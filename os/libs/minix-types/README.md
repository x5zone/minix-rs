# minix-types

> Minix3 核心协议类型库

## 概述

本 crate 提供 Minix3 跨服务通讯必须知道的最小类型集合，相当于 C 语言里的 `include/minix/`。

## 设计原则

### 1. 最小化

只放跨服务通讯必须知道的最小集合，不包含任何服务的私有实现细节。

### 2. 稳定性

这些类型是各服务之间的"协议"，变更需要谨慎。

### 3. 无业务逻辑

不包含任何服务的私有实现细节，只定义数据结构。

## 核心类型

### 进程标识

| 类型 | 说明 |
|------|------|
| `Pid` | 进程 ID（32 位有符号整数） |
| `Endpoint` | 端点标识（用于 IPC） |
| `ProcIndex` | 进程表索引 |

### 用户/组标识

| 类型 | 说明 |
|------|------|
| `Uid` | 用户 ID |
| `Gid` | 组 ID |
| `IdSet<T>` | ID 三元组（real/effective/saved） |

### 时间/地址

| 类型 | 说明 |
|------|------|
| `Clock` | 时钟滴答 |
| `VirBytes` | 虚拟地址 |

### IPC

| 类型 | 说明 |
|------|------|
| `Message` | IPC 消息 |

## 为什么不包含 MProc 等进程表结构？

根据 Minix3 微内核设计，各服务拥有私有的进程表：

| 服务 | 进程表 | 位置 |
|------|--------|------|
| PM | `mproc` | `minix-pm` crate |
| VM | `vmproc` | `minix-vm` crate |
| VFS | `fproc` | `minix-vfs` crate |
| Kernel | `proc` | `minix-kernel` crate |

### 设计原因

1. **职责隔离**: 各服务的进程表包含大量私有逻辑
2. **不变量保护**: 状态转换逻辑绑定了服务内部复杂逻辑
3. **微内核原则**: 遵循"知识最小化"原则

## 使用示例

### 在服务中使用

```rust
// 在 PM crate 中
use minix_types::{Pid, Endpoint, ProcIndex};

// PM 私有的进程结构体
pub struct Process {
    pub pid: Pid,
    pub endpoint: Endpoint,
    // ... PM 私有字段
}
```

### 跨服务通讯

```rust
use minix_types::{Endpoint, Message};

// 发送消息
fn send_message(target: Endpoint, msg: Message) {
    // ...
}
```
