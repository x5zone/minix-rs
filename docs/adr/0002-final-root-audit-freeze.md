# ADR 0002：最终根审计后冻结，目标义务取生命周期并集

- **状态**：已采纳（2026-11-04，I-29 内存图政策第二十五轮）
- **背景**：`R21` 原本按阶段分别验收（S3 用 `Ordinary(S3)`、S4 用 `Ordinary(S4)`），但第一版允许启动对象在 S3 之后释放、其页要到 S4 才进入可用表。S3 构造最终根时必须预映射这些页，否则切到最终根后再补映射就太晚；而「S3 预算」只写在注释里，没有进入公式。

## 决策

1. **目标义务取并集**：`FinalRootRequiredMappings = OrdinaryMemoryMappingRequirements(S3) ∪ OrdinaryMemoryMappingRequirements(S4)`。
2. **两次审计同一目标**：S3 最终根构造完成点与 S4 都按这份并集验收——S4 验的是「仍是那份冻结根、且仍满足同一目标」，不是用更小的 S4 义务集重验。
3. **审计后冻结**：S3 审计通过到 T2 启用完成之间，禁止任何 PTE 修改；S4 额外确认启用的根与已审计根同一。

## 备选与取舍

- **允许中间修改、每次改动后重跑完整验收**：灵活，但要求把「最后一次验收必须发生在启用之前」变成可判定的时序约束，第一版没有这个机制。
- **只靠 S4 遍历**：不可接受——切根后 CPU 已在新根下执行，事后再遍历不能为之前的执行背书。

## 后果

- 最终根的构造与审计必须是一个不可分割的步骤；任何运行时修补最终根的需求都被推到第二版。
- `R21` 的量词域是 `FinalRootAuditPhases = {S3 构造完成点, S4}`，输入恒为并集目标。
