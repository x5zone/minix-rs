# ADR 0001：设备访问按地址域分离（MMIO 与端口 I/O）

- **状态**：已采纳（2026-11-04，I-29 内存图政策第二十五轮）
- **背景**：设备义务模型最初假设所有设备访问都是「物理页 + `VA = PA`」的 MMIO 映射。但本仓 x86 控制台走 COM1 `0x3F8` 的 `in`/`out` 指令，访问的是独立端口地址空间：没有物理页、没有页表叶子、`IdentityVaRepresentableRanges` 不适用。

## 决策

设备访问分成两个地址域，共享**授权关系**的语义，不共享**地址表示与映射机制**：

| 地址域 | 义务载体 | 页表叶子 | 验收键 |
|---|---|---|---|
| MMIO | `DeviceMappingRequirements`（映射）+ `MmioAccessRequirements`（访问） | 有 | `(tree, phase, path)` |
| 端口 I/O | `PortIoAccessRequirements`（仅访问） | **无** | `(caller, phase)` |

- 授权权威分别是 `DeviceWindowPolicy` 与 `PortWindowPolicy`，两者同构但分开存储。
- 每个实际访问点有稳定 `AccessUseId`；一条映射义务可被多个使用点引用，反向不允许孤立映射。
- `R20` 只在物理地址域求交；端口 I/O 不参与。

## 备选与取舍

- **合并成一套「设备窗口 + 地址域字段」**：少一个对象，但两类地址同表，会被再次当成同一种区间去求交——这正是前几轮反复修的错误。
- **让端口 I/O 也伪造一条恒等映射义务**：能让公式统一，但与硬件模型不符，且页表遍历永远证明不了端口访问。

## 后果

- 设备 ABI 只承载 MMIO 映射；端口访问合同留在架构层与引导壳内部审计。
- `LAPIC`/`IO-APIC` 等窗口是否进入第一版设备政策需要单独裁决；当前不在窗口清单内。
