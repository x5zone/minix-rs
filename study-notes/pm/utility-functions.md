# PM 工具函数库模块

> **模块范围**: `servers/pm/utility.c`
> **核心功能**: PID 分配、进程查找、优先级转换、端点验证、VFS 通信、时间统计
> **所属服务**: PM（Process Manager）

---

## 一、模块整体定位

### 1.1 在系统中的作用

本模块实现了 PM 服务中的通用工具函数，为其他 PM 模块提供基础支持：

| 函数 | 功能 | 主要调用者 |
|------|------|-----------|
| `get_free_pid` | 分配唯一 PID | forkexit.c |
| `find_proc` | 通过 PID 查找进程 | 多个模块 |
| `find_param` | 查找引导参数 | main.c |
| `nice_to_priority` | nice 值转调度队列 | misc.c, main.c |
| `pm_isokendpt` | 验证端点有效性 | 多个模块 |
| `tell_vfs` | 异步发送消息给 VFS | 多个模块 |
| `set_rusage_times` | 时间格式转换 | wait.c, misc.c |

### 1.3 核心设计约束

**无状态函数**：大部分函数是无状态的纯函数，易于测试和推理

**异步通信**：`tell_vfs` 使用非阻塞 IPC，避免 PM 阻塞

**静态 PID 分配**：使用静态变量跟踪下一个候选 PID

## 二、核心数据结构

### 2.1 常量定义

```c
// 来自 servers/pm/const.h
#define NR_PIDS       30000    // PID 最大值
#define INIT_PID      1        // init 进程的 PID

// 来自 minix/config.h
#define MAX_USER_Q    0        // 最高优先级用户队列
#define MIN_USER_Q    (NR_SCHED_QUEUES - 1)  // 最低优先级用户队列（15）
#define USER_Q        ((MIN_USER_Q - MAX_USER_Q) / 2 + MAX_USER_Q)  // 默认（7）

// 来自 sys/resource.h
#define PRIO_MIN      -20      // nice 值最小值（最高优先级）
#define PRIO_MAX      20       // nice 值最大值（最低优先级）
```

### 2.2 进程表结构

```c
struct mproc {
    int mp_flags;          // 进程标志位
    pid_t mp_pid;          // 进程 ID
    pid_t mp_procgrp;      // 进程组 ID
    endpoint_t mp_endpoint;// 进程端点号
    // ...
};

extern struct mproc mproc[NR_PROCS];  // 进程表
```

### 2.3 端点号结构

```
端点号（32 位）:
┌─────────────────────────────────┬─────────────────────────────────┐
│       生成号（16 位）            │       进程索引（16 位）          │
└─────────────────────────────────┴─────────────────────────────────┘
         高 16 位                          低 16 位

_ENDPOINT_P(endpoint) 提取低 16 位作为进程索引
```

**设计原因**：生成号用于检测进程是否已退出并被新进程替换

### 2.4 时间结构

```c
struct timeval {
    time_t tv_sec;         // 秒
    suseconds_t tv_usec;   // 微秒（0-999999）
};

struct rusage {
    struct timeval ru_utime;  // 用户态 CPU 时间
    struct timeval ru_stime;  // 内核态 CPU 时间
    // ... 其他字段
};
```

```

│   │  生命周期: 程序启动到结束                                             │  │
│   │  存储位置: 静态数据段                                                 │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │

│   │                          循环开始                                   │    │

│                          ▼                                                  │

│              ▼                       ▼                                     │

│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**算法特点**：

| 特点 | 说明 |
|------|------|
| 循环分配 | PID 从 2 到 29999 循环使用 |
| 双重检查 | 同时检查 PID 和进程组 ID |
| 线性搜索 | O(n) 复杂度，适合进程数量有限的场景 |
| 延迟重用 | 避免短时间内重用 PID |

### 3.5 nice 值到优先级映射

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    nice_to_priority 映射关系                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   公式: new_q = MAX_USER_Q + (nice - PRIO_MIN) * (MIN_USER_Q - MAX_USER_Q + 1)│
│                                              / (PRIO_MAX - PRIO_MIN + 1)    │
│                                                                             │
│   简化: new_q = 0 + (nice + 20) * 16 / 41                                   │
│                                                                             │
│   映射表:                                                                   │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │  nice 值   │   计算结果    │   优先级队列   │   含义                 │  │
│   ├─────────────────────────────────────────────────────────────────────┤  │
│   │    -20     │      0        │   MAX_USER_Q  │   最高优先级           │  │
│   │    -10     │      3-4      │               │   高优先级             │  │
│   │      0     │      7-8      │   USER_Q      │   默认优先级           │  │
│   │     10     │      11-12    │               │   低优先级             │  │
│   │     20     │      15       │   MIN_USER_Q  │   最低优先级           │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   关系: nice 值越大（越"谦让"），优先级越低                                  │
│                                                                             │
│   nice 值范围: -20 到 +20                                                   │
│   优先级队列: 0 到 15                                                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```


## 四、关键机制拆解

### 4.1 PID 唯一性保证

**双重检查机制**：

```c
if (rmp->mp_pid == next_pid || rmp->mp_procgrp == next_pid) {
    t = 1;  // 冲突
    break;
}
```

**原因**：
- PID 可以作为进程 ID 或进程组 ID
- 两者必须唯一，防止信号发送错误

### 4.2 端点号验证

**三层验证**：

| 层次 | 检查内容 | 错误码 |
|------|----------|--------|
| 1 | 索引范围 | EINVAL |
| 2 | 端点号匹配 | EDEADEPT |
| 3 | 进程状态 | EDEADEPT |

**生成号机制**：

```
进程槽位重用场景:
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   时间线:                                                                   │
│                                                                             │
│   T1: 进程 A 占用槽位 5，端点号 = 0x00010005                                │
│       ┌─────────────────────────────────────────────────────────────────┐  │
│       │  槽位 5: endpoint=0x00010005, pid=100, IN_USE                   │  │
│       └─────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   T2: 进程 A 退出                                                          │
│       ┌─────────────────────────────────────────────────────────────────┐  │
│       │  槽位 5: endpoint=0x00010005, pid=0, !IN_USE                    │  │
│       └─────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   T3: 进程 B 分配到槽位 5，端点号 = 0x00020005（生成号递增）                │
│       ┌─────────────────────────────────────────────────────────────────┐  │
│       │  槽位 5: endpoint=0x00020005, pid=200, IN_USE                   │  │
│       └─────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   T4: 收到发给进程 A 的消息（端点号 0x00010005）                            │
│       pm_isokendpt 检测到端点号不匹配，返回 EDEADEPT                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 异步 IPC 机制

**asynsend3 特点**：

| 特点 | 说明 |
|------|------|
| 非阻塞 | 消息放入目标队列后立即返回 |
| 无回复 | AMF_NOREPLY 表示不需要同步等待回复 |
| 可靠 | 内核保证消息传递 |

**VFS_CALL 标志作用**：

```c
// 设置标志
rmp->mp_flags |= VFS_CALL;

// VFS 处理完成后发送回复
// PM 主循环收到回复后清除标志
rmp->mp_flags &= ~VFS_CALL;
```

### 4.4 引导参数查找

**monitor_params 格式**：

```
monitor_params 缓冲区:
┌─────────────────────────────────────────────────────────────────────────────┐
│ rootdev=c0d0p0s0\0bootdev=c0d0p0\0hz=100\0\0                               │
└─────────────────────────────────────────────────────────────────────────────┘
 ↑             ↑              ↑           ↑
 参数1         参数2           参数3       结束标记

格式: name=value\0name2=value2\0...\0\0
```

**查找算法**：

```c
for (envp = monitor_params; *envp != 0;) {
    // 比较参数名
    for (namep = name; *namep != 0 && *namep == *envp; namep++, envp++)
        ;
    // 检查是否完全匹配
    if (*namep == '\0' && *envp == '=')
        return(envp + 1);  // 返回值部分
    // 跳到下一个参数
    while (*envp++ != 0)
        ;
}
```

## 五、边界条件与特殊分支

### 5.1 PID 回绕

```c
next_pid = (next_pid < NR_PIDS ? next_pid + 1 : INIT_PID + 1);
```

**场景**：系统长时间运行，PID 达到 29999 后回绕到 2

### 5.2 nice 值边界保护

```c
// 输入验证
if (nice < PRIO_MIN || nice > PRIO_MAX) return(EINVAL);

// 计算结果保护
if ((signed) *new_q < MAX_USER_Q) *new_q = MAX_USER_Q;
if (*new_q > MIN_USER_Q) *new_q = MIN_USER_Q;
```

**原因**：防止整数溢出或计算误差导致越界

### 5.3 VFS 调用状态检查

```c
if (rmp->mp_flags & (VFS_CALL | EVENT_CALL))
    panic("tell_vfs: not idle: %d", m_ptr->m_type);
```

**场景**：进程已经在等待 VFS 响应时再次调用 tell_vfs

**处理**：触发 panic，因为这是设计错误

### 5.4 时间转换溢出

```c
u64_t usec;  // 使用 64 位整数
usec = user_time * 1000000 / sys_hz();
```

**原因**：`user_time * 1000000` 可能超过 32 位整数范围

## 七、Rust 重构与设计改进建议

### 7.1 类型系统改进

**当前问题**：PID 和端点号使用整数类型

```c
pid_t mp_pid;           // int 类型
endpoint_t mp_endpoint; // int 类型
```

**Rust 改进**：使用强类型

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
struct Pid(i32);

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
struct Endpoint {
    generation: u16,
    index: u16,
}

impl Pid {
    const INIT: Pid = Pid(1);
    const MAX: i32 = 30000;
    
    fn is_valid(&self) -> bool {
        self.0 > 0 && self.0 < Self::MAX
    }
}

impl Endpoint {
    fn index(&self) -> usize {
        self.index as usize
    }
    
    fn matches(&self, other: Endpoint) -> bool {
        self.generation == other.generation && self.index == other.index
    }
}
```

### 7.2 PID 分配器抽象

**当前问题**：静态变量 + 线性搜索

```c
static pid_t next_pid = INIT_PID + 1;
// 遍历整个进程表检查冲突
```

**Rust 改进**：使用专门的分配器

```rust
use core::sync::atomic::{AtomicU32, Ordering};

struct PidAllocator {
    next: AtomicU32,
}

impl PidAllocator {
    const fn new() -> Self {
        Self { next: AtomicU32::new(2) }
    }
    
    fn allocate(&self, table: &ProcessTable) -> Pid {
        loop {
            let pid = self.next.fetch_add(1, Ordering::SeqCst);
            let pid = if pid >= Pid::MAX { 2 } else { pid };
            
            if !table.is_pid_used(pid) {
                return Pid(pid);
            }
        }
    }
}
```

### 7.3 错误处理改进

**当前问题**：整数错误码

```c
return EINVAL;   // 22
return EDEADEPT; // 49
```

**Rust 改进**：使用 Result 和枚举

```rust
#[derive(Debug)]
enum EndpointError {
    InvalidIndex,
    DeadEndpoint,
    ProcessExited,
}

fn pm_isokendpt(table: &ProcessTable, endpoint: Endpoint) -> Result<usize, EndpointError> {
    let index = endpoint.index();
    
    if index >= NR_PROCS {
        return Err(EndpointError::InvalidIndex);
    }
    
    let proc = table.get(index).ok_or(EndpointError::ProcessExited)?;
    
    if proc.endpoint != endpoint {
        return Err(EndpointError::DeadEndpoint);
    }
    
    if !proc.in_use() {
        return Err(EndpointError::ProcessExited);
    }
    
    Ok(index)
}
```

### 7.4 异步通信改进

**当前问题**：标志位 + panic

```c
if (rmp->mp_flags & (VFS_CALL | EVENT_CALL))
    panic("tell_vfs: not idle");

rmp->mp_flags |= VFS_CALL;
```

**Rust 改进**：使用类型状态

```rust
enum ProcessState {
    Idle,
    WaitingVfs,
    WaitingEvent,
}

struct Process {
    state: ProcessState,
    // ...
}

impl Process {
    fn tell_vfs(&mut self, msg: Message) -> Result<(), VfsError> {
        match self.state {
            ProcessState::Idle => {
                self.state = ProcessState::WaitingVfs;
                asynsend(VFS_PROC_NR, msg)?;
                Ok(())
            }
            _ => Err(VfsError::NotIdle),
        }
    }
    
    fn vfs_reply(&mut self) {
        self.state = ProcessState::Idle;
    }
}
```

### 7.5 当前设计问题总结

| 问题 | 代码位置 | 说明 |
|------|----------|------|
| 类型不安全 | PID、端点号 | 使用整数，容易混淆 |
| 静态变量 | get_free_pid | 难以测试，状态隐式 |
| panic 使用 | tell_vfs | 系统崩溃代价高 |
| 错误码 | pm_isokendpt | 无法区分具体错误类型 |
| 线性搜索 | find_proc | O(n) 复杂度 |

### 7.6 改进方向

#### 7.6.1 哈希表查找

```rust
use hashbrown::HashMap;

struct ProcessTable {
    procs: [Option<MProc>; NR_PROCS],
    by_pid: HashMap<Pid, usize>,
}

impl ProcessTable {
    fn find_proc(&self, pid: Pid) -> Option<&MProc> {
        self.by_pid.get(&pid).map(|&idx| self.procs[idx].as_ref())?
    }
}
```

#### 7.6.2 时间转换抽象

```rust
struct CpuTime {
    ticks: u64,
    hz: u64,
}

impl CpuTime {
    fn to_duration(&self) -> Duration {
        let micros = self.ticks * 1_000_000 / self.hz;
        Duration::from_micros(micros)
    }
}

struct RUsage {
    user_time: Duration,
    system_time: Duration,
}
```

#### 7.6.3 配置参数抽象

```rust
struct BootParams {
    params: HashMap<&'static str, &'static str>,
}

impl BootParams {
    fn get(&self, name: &str) -> Option<&str> {
        self.params.get(name).copied()
    }
    
    fn get_parsed<T: FromStr>(&self, name: &str) -> Option<T> {
        self.get(name)?.parse().ok()
    }
}
```

## 八、总结

### 8.1 核心知识点

1. **PID 分配**：静态变量跟踪 + 循环搜索 + 双重检查
2. **端点验证**：三层检查（索引、端点号、状态）
3. **异步通信**：非阻塞 IPC + 标志位状态管理
4. **优先级映射**：nice 值线性映射到调度队列

### 8.2 关键设计决策

| 决策 | 原因 |
|------|------|
| PID 循环分配 | PID 是有限资源，需要重用 |
| 端点生成号 | 检测进程退出和槽位重用 |
| 异步 IPC | PM 不能阻塞等待 VFS |
| panic 机制 | 系统服务器内部错误应立即崩溃 |

### 8.3 设计张力点

1. **简单 vs 效率**：线性搜索简单但效率较低
2. **安全 vs 性能**：端点验证增加开销但提高安全性
3. **异步 vs 一致性**：异步通信难以保证状态一致性
