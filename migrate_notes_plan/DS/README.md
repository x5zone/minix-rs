# DS 侧独立审计产物索引

本目录是独立审计方（DS）对 notes 目录迁移的只读审计产物，与迁移执行方（Qoder 侧）的
交付物 `migrate_notes_plan/` 上层目录分开放置，以保证独立性。

## 怎么读

1. 先读 [`REVIEW-REPORT.md`](REVIEW-REPORT.md)——结论、判定摘要、问题清单、未能核对项都在那一份里。
2. 需要复核某条结论时，按报告里的「证据：`evidence/xxx.txt`」引用直接打开对应文件，
   里面是当时跑的命令与其原始输出。
3. 想自己重跑对账，用下表的脚本（全部只读，不写仓库内任何文件）。

## 文件清单

| 文件 | 用途 |
|---|---|
| `REVIEW-REPORT.md` | 最终审计报告（交回格式：结论 / P0 / P1 / P2 / 未能核对项） |
| `audit_1_content.py` | 按 path-map 逐条比对迁移前后 sha256，并核对映射类型与 git 状态、枚举迁移期新增文件 |
| `audit_1d_classify.py` | 把内容差异分为「合同前缀替换可解释」与「有残差」两组 |
| `audit_1e_lineclass.py` | 对残差文件做行级分类：前缀替换 / 链接重定基 / 结构性编辑 |
| `audit_1h_links.py` | 从旧文本解析链接、按映射表推期望新目标、与现文本解析比对 |
| `audit_4_refs.py` | 必改域旧路径残留的字节级扫描（绕开本机 ugrep 对无效 UTF-8 静默吞输出的问题） |
| `audit_5_links.py` | 断链集合对账（解析坐标口径，纠正了迁移方脚本只映射文件名的口径） |
| `audit_5b_broken_verdict.py` | 现状全部断链的终审判据：逐条回查迁前是否可解析 |
| `evidence/` | 每一步的原始命令输出与控制台记录（文件名以报告里的引用为准） |
