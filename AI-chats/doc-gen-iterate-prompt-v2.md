# 五轮迭代 v2：以"纯学生实读"为闸门，把干巴稿逼回 draft 级教材

> 用途：外层迭代驱动器。目标不是"产出一篇过门的文档"，而是**每轮逼工作流学会"带着读者把机制想一遍"**。
> 用法：整段发给新会话 agent。内层流程见 `AI-chats/doc-gen-prompt.md`；上一轮取证与复盘见 `prompt/REVIEW-TRACE-docgen-01-05-5rounds.md`；教学性诊断的真源见 `prompt/GPT_advice.md`。
> 一句话北极星：**产出好文档是结果，把"读者认知转移"逼进生成器是主线。**
>
> **本篇取代 `AI-chats/doc-gen-iterate-prompt.md`（v1）**：v1 的 C 阶段仍以行数/围栏数为主轴，保留仅作上一轮取证，不再使用。

## 第 0 轮（一次性）· 建立"学生之眼" + 初改工作流 + 清空

1. **先读 `prompt/GPT_advice.md` 全文**——这是 GPT 读过 01、05 新旧两版后的诊断，本迭代的世界观来源。核心结论必须内化：新版退化的根因不是行数/覆盖/§11 放晚，而是 **outline 只有"知识图 + 章节结构"，没有"读者认知状态转移图"**；多 AI review 会共同把"8 次认知跃迁压成 3 句结论"当成"改进"。
2. **纯学生实读（不加载任何 skill，不带 OS 外部知识脑补）**：把 `rewrite-notes/01-stage-kernel/draft/01-*.md`、`draft/05-*.md`（旧版·人工审阅·当作优秀教学样本，暂时忽略其过时/与 Rust 不符）和上一版新稿放在一起读（上一轮生成稿已删，用 `git show a481dfbee^:rewrite-notes/01-stage-kernel/<篇名>.md` **只读恢复**当干巴反例；⛔ 它不是基线、不入库、正式文档不得引用，且**不要读 `.wt/` 下其它工作树里的同名残留旧稿**）。**逐节记录**：旧版在这里让我做了哪些认知动作（看到真实代码→逐条解码→发现一个不明显事实→自己归纳出机制）？读起来是什么"手感"？
3. **把这份体验写成"M 标尺"而不是散文**（本轮产出的关键形状）：固定五列（`M#` | 认知动作名 | draft 正例位置 | 违反形态 | 只看新稿可答 yes/no 的判据）、**5–8 条封顶**（超过即重演"几十条教学质量检查"）。标尺落 `trace` 第 0 轮，**后续每轮 C 阶段只能引用 M# 编号**，不得每轮重新发明一套判据；`M#` 永不重编号，只在"规则缺口"获批后追加。
4. **初改工作流**：据 1–3 校准 `AI-chats/doc-gen-prompt.md` 与本篇。**只做减法与收紧，不再新增机器门**（GPT 明言别再造几十条教学质量检查）。**事实纠偏**：减法只落 `AI-chats/*` 时**不触发四道同步门**（`rules-consistency.yml` 的 paths 与 `lint-review-rules.sh` 的 `LINT_ROOTS` 均不含 `AI-chats/`）；只有真碰 `prompt/review-rules/*` 或 `tools/*` 才需跑四道门——而那类改动本轮默认禁止。反之，**新增/修改已跟踪的 `prompt/` 文件会进入 lint 扫描域**，入库后必须本地复跑 `check-review-rules.sh` + `lint-review-rules.sh`。
5. **清空腾位（已核实为 no-op）**：`git rm` 主树 `rewrite` 上现存的 `01~05` 正式稿（若存在）。**实测本轮开工时主树已无 `0[1-5]-*.md`（提交 `a481dfbee` 已删）**，故此步只做核实与如实记录，不做假动作。`draft/` 人工版是**对照样本**，保留、经 `git ls-files` 确认跟踪、绝不改。旧 `.design/`、`.review/` 不留（工作树本就无，每轮走 Step 0.3 就地现推）。
6. 建 `trace`，把第 0 轮的"学生体验笔记 + M 标尺 + 减法清单"写进去。

## 每轮（k = 1..5）的六个阶段

### A 生成 · 完整跑 doc-gen-prompt 内层（第 -1→7 步）
- **检查点 A2 只验三件事**（按第 1 轮后的契约）：① 每节认知四段（Input/Question/Evidence/Output）与两条约束是否填全；② Question 是不是一个**能被源码回答的真问题**（不是修辞性悬念）；③ **大纲禁则复扫**——大纲里不得出现比喻、正文结论句、写作指示、"兑现落差 D#"标记。四段没填全或禁则命中 = 不许写正文。
- 检查点 A/A2/B1/B2 照常向用户汇报。

### B 轨迹 · 记录全程
原始记录落 `tmp/doc-gen-iterate2/round-k/`（命令/输出/Skill 调用/各门退出码/返工）；提炼进 `trace`。**必须含失败与返工**。

### C ★纯学生实读对比（本轮主闸门，不套 skill、不带外部知识脑补）
拿新稿与 `draft/{num}-*.md` 并排，**以第一次读这个主题的人的身份通读**，回答且只回答这一个问题：
> **旧版在这里让读者做了哪些认知动作，新稿把哪些动作替读者省掉了、压成了一句结论？**
逐节列"认知跃迁丢失清单"（不是数围栏/数行数——那些是 presence 读数，堆一下就能骗过）。再补：Ch1 是否先建心智模型（而非上来"上一章交了空表"）；被整段分析的每个 C 函数是否"摊开真实代码→逐条解码→逼出一个不明显事实→读者自己归纳"。

**清单表头固定（逐轮同构才可比，写进 `trace`）**：

| 节号 | **新稿原话摘录**（必填，≥1 句可定位） | 命中 M# | draft 对应处让读者做的动作（行引） | 丢失类型 | 严重度 |
|---|---|---|---|---|---|

丢失类型五值：压成结论 / 跳过观察 / 观察与归纳同段 / 起手外部承接 / 导览无真码。**"原话摘录"列留空 = 清单不完整 = 本轮直接判不通过**——这是反 presence 化的机关：堆字段打勾填不出原文。

**本轮 PASS 判据**：阻断级条目 = 0 且通读者冷读三处自问"我能自己想到下一步"均为 yes。不达标即不通过，回 D 重做（不降级、不放水）。

**反向一票（第 1 轮加）**：跃迁清单为空**不够**——若通读者同时报出"每节都有人在宣布这里很重要"（元话语、比喻、金句收束、悬念节拍），计 `P1-teaching-formalized`，本轮仍判不通过。**修法不是再补构件，也不是改章级骨架（章骨架由 `prompt/review-rules/review-doc-checklist.md` §1–§4 规定，不得自创），而是：把模型先宣布的结论后移（概念章不提前给出后续章答案）、删元话语、把跨章拼接补成回指（第 3 章每个决策回指第 2 章观察、第 4 章每个实现回指第 3 章决策）。**（Round 1 实例：清单几乎为空、机器门全绿、CodeReview 9/10 事实断言属实，外部读感仍为"教学被形式化"；而本轮把骨架改成"按概念成章"的修法**因违反规范源而被退回**。）
机器门（承载/锚点/文风/引用/关联）此轮**只作底线**：全绿≠合格，只是没犯规。

### D 改进 · 回到生成器，不是回到文档
针对 C 列出的"跃迁丢失"，判它属于（引用 M# 与清单条目号）：
- **生成约束没兑现**（元组填了却没在正文执行）→ 收紧 doc-gen 第 2 步/第 4.6 判据措辞（**改已有句、不新增条**，且只落 `AI-chats/*`）；
- **约束本身缺**（工作流没要求这类认知动作）→ 在 `trace` 记为待裁决，交用户拍板，**不擅自往 review-rules 堆门、不改 `tools/*`**；
- **同类丢失第二次以上**才允许把它升级为生成器硬判据（首轮就动规则 = 为个例改全局）。
- 每轮**除加之外必做一次"减"判定**（`trace` 固定表：上一轮新增/收紧项 | 本轮清单是否真引用过它 | 保留/软化/删除 + 理由）；连续两轮零命中默认列为删除候选。
- 文档侧只修 C 直接暴露的"被压成结论"处——把结论展开回"看代码→观察→推理"，别顺手补覆盖、别为显得厚而堆字段表。
- **但先分消"形式化"与"欠构件"**（Round 1 教训）：如果丢失的根因是"先宣布后证明 + 元话语叙事 + 回指缺失"，那它**不是能逐条修补的缺陷**：重写章内交付顺序与句子（补回指、删元话语、结论后移），**但不改章级骨架**——骨架属规范源（`review-doc-checklist.md` §1–§4：概述/C 源码分析/Rust 设计决策/实现详解/测试/诊断）。就地堆文风修补只会把稿子磨得更漂亮、更不像书；而自创骨架会直接造成与规范源的冲突（两者在本轮都真实踩过）。

### E 提交 · 五道文档门全绿只是底线
`anchor-resolve --check`、`doc-code-map --check`、`doc-style-lint --diff`（0 error）、`doc-ref-check`（`AWK=gawk`）、`doc-code-density --check`；**另加元话语/比喻复扫 grep（命中即未修完，不得提交）**——Round 1–4 实际发生的事是：写了"禁元话语"的规则后仍在三篇里连着违规（"值得 X"、"地基"、"伸手"），说明光有规则不自查不够。sha256 绑定；逐路径点名、一逻辑单元一笔、不跳 hook。文档一笔、工作流改进一笔。

**改文件前的一条硬规则**（Round 2、4 各踩过一次）：先 `git worktree list` 确认目标工作树仍在登记中——**已销账的 `.wt/<id>` 目录可能还留在磁盘上，写进去的改动不会进入任何分支**。

### F 回归复核 · 审自己的 commit（不许自证通过）
- 派 **CodeReview 子代理**（`review_scope=explicit_target` 取本轮 commit）查事实/锚点/代码忠实/测试非虚构/命令可跑；
- **关键补一刀**：CodeReview 查"对不对"，查不出"教不教"；所以 F 必须**再跑一遍 C 的纯学生实读**（或派一个"只能凭本文答题、禁外部知识"的学生子代理）确认 D 的修改真把跃迁补回来了，没补回就回 D 重做，直到"读起来像旧版那样在带我走"才进下一轮。
- **两次学生实读不得同型**（否则退化成复制粘贴）：C = **发现型**（新稿与 draft 并排通读，列丢失清单）；F = **闭卷型**（只给新稿，答 5–8 道由 C 的缺口反向生成的机制题，每题挂在某一节的④上）。两个子代理**互盲**（不得看到对方输出、不得读 `trace`/`GPT_advice`/`review-rules`）。
- **重做上限与顺序锁**：跃迁清单未清空 → **不得先走 E 提交再补做**（先落地再说 = 把未达标的稿写进共享历史）；同一个 num 的 C/F 不通过**最多重做 2 次**，第 3 次同类丢失判为生成器系统性问题 → 停下交用户裁决。重做一律**追加 fix commit**，绝不 `reset`/`revert` 已合回 `rewrite` 的历史。

## 检查点与停止

- 默认串行自主推进，每轮 F 干净后进下一轮，并汇报：**本轮"跃迁丢失清单" + 工作流改了什么 + commit 号 + 学生实读"读起来是否接近旧版手感"的一句话自评**。
- 必须停下回报：任一门 FAIL 修不了；`check-staged-inflight` 拦下；与 todo-fix 撞路径；qemu 占用；出现"规则缺口"需裁决；检查点 A/A2 需用户确认。
- 收敛判定（诚实，不粉饰）：某轮学生实读"跃迁丢失清单"为空、且新读手感明显接近旧版 → 视为该类主题工作流已收敛；连续两轮跃迁清单为空可提前交付，不强凑五轮。

## 第 5 轮收尾必交

1. 01~05 五篇 vs 各自 draft：**逐篇的"认知跃迁是否被替读者做完"定性结论**（不是行数对比表）。
2. 五轮累计的工作流改动清单，标**每轮学生实读是否真因它少丢一次跃迁**（命中）；从未命中的列为删除候选。
3. 仍属"规则缺口、待裁决"的遗留 + 被证伪的假改进（加了却没让任何一轮读起来更像教材的门）——诚实列出。
4. 一句话总判：**当前工作流产出的稿，是否已达到"第一次读的人能顺着它、像旧版一样自己把机制想一遍"的质感？** 没到就明说差在哪，不为收敛背书。
