# 1 最大亮点：CPU 三问终于成为主线

这是整个重构里最成功的一处。

以前：

```text
保护结构
 ├─ GDT
 ├─ IDT
 ├─ TSS
 ├─ 特权级
 ├─ ...
```

读者会觉得：

> 又是一堆名词。

现在：

```text
CPU运行时需要回答：

1 当前什么特权级？
2 异常跳哪？
3 用哪个栈？

↓

prot_init()
就是提前配置答案
```

这已经变成：

```text
问题驱动
    ↓
概念
    ↓
实现
```

而不是：

```text
实现
    ↓
总结概念
```

这是根本性提升。

# 2 我唯一还会改的一处：1.1 例子

你现在写：

```text
*(0xffffffff80000000)=0
```

对于已经学过内核的人很好。

对于第一次看的人：

会有两个额外问题：

```text
为什么这个地址是内核地址？
为什么这个地址不能写？
```

反而分散注意力。

我更倾向：

```c
while (1) {
    *((int*)0) = 0;
}
```

或者：

```c
sys_kill_all_processes();
```

然后说：

> 用户程序不能直接操作内核资源。

随后再引出：

```text
为什么不能？
```

再进入：

```text
特权级
↓
页表权限
↓
异常处理
```

这样认知负担更低。

当然这只是教学风格问题。

不是错误。

# 3 1.2 里 RISC-V 的表述建议再严谨一点

这里：

```text
riscv64
当前特权级存放：
sstatus.SPP
```

严格来说不准确。

SPP 只在 trap 时保存来源特权级。

当前特权级不是靠 SPP 表示。

更准确：

```text
当前运行级别：
CPU 当前状态

trap 来源：
sstatus.SPP
```

或者简单写：

```text
RISC-V 当前运行在 S/U mode
trap 时由 SPP 记录来源
```

否则容易被懂 RISC-V 的人挑刺。

这是全文唯一我觉得属于“概念准确性”的点。

# 4 1.3 的流程图还可以再统一一点

你现在：

```text
切换到可信内核栈

(x86/aarch64 硬件自动
riscv64 软件交换)
```

很好。

但下面：

```text
保存现场
```

其实三架构也不统一。

例如：

x86：

```text
CPU自动压栈一部分
```

RISC-V：

```text
软件保存
```

ARM：

```text
大部分寄存器软件保存
```

所以严格来说：

```text
保存现场
```

也是抽象层。

我建议加一句：

```text
现场保存由硬件、软件或两者协作完成，
具体机制因架构而异。
```

这样你的“统一抽象层”原则贯彻到底。

# 5 1.4a 可能需要一张小图

这是全文最难理解的一节。

你现在已经意识到：

```text
特权级
≠
页表权限
```

但：

```text
特权级
→ 决定权限检查方式
→ 权限位实际执行检查
```

很多人第一次看会混。

我会加：

```text
ring3
  │
  ▼
CPU发起访问
  │
  ▼
检查PTE.U
  │
  ├──允许
  └──拒绝→异常
```

或者：

```text
特权级（为什么不能）
        ↓
页表权限位（如何阻止）
        ↓
异常处理（阻止后的动作）
```

这张图会非常有教学价值。

甚至可能成为整章最重要的图之一。

# 8 我最欣赏的一处修改

其实不是三问。

而是这个：

```text
1.3 加返回闭环
```

以前很多内核教程都是：

```text
用户
 ↓
异常
 ↓
内核
```

结束。

读者潜意识会认为：

```text
保护结构 = 进入内核
```

实际上：

```text
保护结构 =
进入内核
+
返回用户
```

而：

```text
iretq
eret
sret
```

本质上是保护模型的一半。

你把这一半补上之后：

```text
用户 ↔ 内核
```

终于成为完整状态机。

这个改动我认为价值甚至高于 GDT 降权。
