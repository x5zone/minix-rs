### 0.3 学生体验笔记（我作为第一次读这个主题的人，实读后的诚实记录）

**必须纠正 v1 trace 的一处自我描述**：干巴件 01 并不"通篇无码无辨析"——它有 `pre_init` 七步码、有 PWT|PCD 辨析、有 USER 位不对称辨析、有清 PSE 的顺序辨析、还有越界推演。**退化不在"构件缺失"，在构件的交付方式**。所以本轮标尺不能是"有没有"，只能是"读者有没有被带着做那一步"。这是 v1 五轮始终没看清的那一层。

真读出来的三处手感差异：

1. **旧版把我放进一个不确定里，新版把我放进一份摘要里。** 读 `draft/05` §1.0：先给我"同步 vs 异步"的分别、"CPU 只有一根 INT 线但设备有几十个"所以要有转发与仲裁，再给我三条前置条件与"缺第一条会 triple fault"的后果——读完我**已经想知道**代码到底在哪一步把中断打开。读干巴件 `05` §1.1：第一句是"03 文档把保护结构建了起来……05 要做的是把这些活的信号源接上"，我此刻没有任何问题被制造出来，后面所有结论都是通知。
2. **旧版让我在码上停住，新版替我在码上走完。** `draft/05` §2.2 把 `intr_init` 的 12 行 `outb` 全摊开，逐行给了 ICW1~ICW4/OCW1 的解码表；读到"主片 `~(1 << CASCADE_IRQ)`、从片 `~0"` 时，"初始化完成 ≠ 开始接收 IRQ"是我自己冒出来的。干巴件 `05` §2.2 讲同一个主题**一段 C 码都没有**，只有一句"C 版里 tick 频率是运行期从环境变量读的"——我知道结论，我不知道它从哪几行读出来，也打不开文件自己走。
3. **新版会把两个真落差塞进一个长句的从句里。** 干巴件 `01` §2.2："…先 memcpy 一份…（原始结构在引导服务退出后会失效）；从链接期符号读出…；把命令行拆成…；把 user_sp 刻意压低一档，好让内核栈溢出撞进'留白'被发现、也让内核地址与用户地址一眼可辨"。后两条是真金，但它们在从句位置，我的眼睛直接滑过去——**同一件事在 `draft/01` 是独立成段的辨析**（L464、L466、L476 各一段）。这是我这次读出来的最小说法差异，也是最容易被任何"数码/数辨析段"的门漏掉的一种。

一句话手感：旧版像是有人把手电筒打在哪一行上、然后问我"你看到什么"；新版像是把讲完的幻灯片发给我，附录里附了码。

5. **过度断言**："唯一可能的形状""这不是偏好"。应写"存在 X 依赖故 A 不早于 B（不变量）"与"这是当前实现的选择（可不同）"。
