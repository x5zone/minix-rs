# Workflow 全面 review：按「最好的 OS 教程 + 配套代码」目标（2026-11-21）

> **目标锚（用户原话）**：中文社区最好的 OS 教程和配套代码；文档与代码都要「简洁、优美、
> 可读、可理解、教学友好」；用户是第一读者，能容忍一定阅读返工，但 D01 的迭代次数已超出阈值，
> 且仍有很多 todo、仍是半成品。
>
> **本报告只做诊断与重设计，不改规则**。所有数字来自实际轨迹与 `git log`。

---

## 0. 一句话结论

**当前 workflow 是「发现驱动的审查循环」，不是「稿件生产流程」。** 它优化的是「本轮没有更多
发现」，不是「读者能学会」。在 D01 上这两个目标已经背离到不可调和：28 轮、1336 条发现、
216 次文档提交、3 次 CONVERGED，冻结后仍有 109 次关联代码改动、200+ 出版违规、27 条 todo。

继续加轮不会收敛，因为**循环的对象不是稿件，而是不断移动的代码与不断扩张的发现集**。

## 2. 结构性根因（按影响排序）

### R1. 收敛对象错位：发现 vs 稿件

G1–G9（以及后来的 G10–G12）全部是「本轮发现 / 本轮欠账」。**没有任何一条判「这篇稿件是否
达到出版质量」**。当发现集的供给不衰减时，收敛就永远只是「这一轮刚好没找到」。

### R2. 代码与文档同轮演进，文档永远追不上

R34 冻结后仍有 109 次 `os/` 提交。每一次设计批（D-062 wire v10、D-067 fill API、D-074
BootScalars…）都会让文档的 §3/§4/§5 失效，于是下一轮确认轮又产生 76/93 条新发现。
**文档在追一个正在施工的工地，而且施工图还在改。**

### R3. 延期出口把「未完成」合法化

旧规则里 `②`（用户批准的延期）、`⑥`（下一设计批）、`SUGG`（建议级）、`OPEN-DEBT`（下一批）
都是合法出口。实测：`OPEN-DEBT` 的 `[OPEN]` = 0，而 `01-todo.md` 有 14 待实施 + 9 已批准待实施
+ 1 登记不实施。**「已批准待实施」让「收敛」与「todo 还在」可以同时为真**。V3.7 已关闭这些
出口，但 D01 的历史欠账仍在。

### R4. 审查单位过大

每轮审整篇 3616 行 + 54 个关联文件。只要任何一处有问题，整篇就不能收敛；修完 A 处，B 处
又因为代码变化而失效。**没有章节级冻结**，所以同一节可以被反复审 10 次。

### R5. 没有作者 / 编辑阶段

流程是「AI 生成 → AI 审查 → 局部补丁」。没有单一叙事负责人，读者发现的理解问题被逐条打补丁，
而不是重写那一段。结果是文档越来越像工程日志：§3 有 45 处过程痕迹，读者要先读编号图例才能
知道 `D-061` 是什么——而那本来就不该出现在教程里。

### R6. 指标奖励「发现」

头条指标是 `发现总数`；面板产出条数被当作工作量。**没有一个指标衡量「读者是否学会」**：
首次阅读阻塞点、每章概念数、示例可运行率、练习完成率、复述通过率（G4 只覆盖局部）。
供给方（面板）与需求方（读者）的激励不一致。

### R7. 多篇并发 + 跨篇 ②

D01/D02/D03… 同时开轮；D01 的代码改动让 D02/D03/D04 的引文失效（实测 4 处 citation FAIL：
`kern_stack_top` 变方法、`startup_objects` 删除）。跨篇 `②` 转出把这些失效记成「下一轮再修」，
下一轮又因新改动失效。**并发省下的时间，以返工形式加倍付出。**

### R8. 硬预算失效

§7.5 规定同一篇同一 edition 最多 3 个修改轮。D01 实际跑了 8+ 个（V3.1 一个 edition 就 5 个）。
超限靠「用户授权追加轮」合法化；没有「第 N 轮不收敛 → 强制重写」的触发器。

### R9. 教程质量 rubric 缺失

读者角色问的是「你卡在哪」，不是「这一章能不能教会人」。没有检查：学习目标、前置概念、
最小可运行示例、失败对照、练习、小结、术语表。所以一篇文档可以通过六角色面板，却仍然不是
一篇好教程。

### R10. 工具把过程痕迹当正常

`doc-style-lint` 对 D01 报 `error=0`，而文档有 42 处迭代叙事、57 处过程编号。SL-5 的 error
词表不含「旧形态 / 删除前 / 已被删除 / 不再使用」；「最初 / 曾经 / 后来」只是 warning；
模式 64 从未进任何门。**流程自己在生产「合规的工程日志」。**

## 4. 重设计提案（按优先级）

### P0：立即改变循环的对象

1. **停止 D01 的补丁循环。** 按 V3.7 判 `NOT CONVERGED`；不要再开第 29 轮。补丁轮已经证明
   产出的是「新的可发现面」，不是「更接近出版」。
2. **两阶段制：Manuscript → Review。**
   - Manuscript 阶段：一个作者 agent（或人）按教程 rubric 重写指定章节；**不派六角色面板**。
   - Review 阶段：面板只做验收，**不再产生设计批**；发现必须当轮修完。
   - 设计批只能在 Manuscript 阶段之前落地；Review 中途需要改设计 → 中止本轮、重设基线。
3. **代码冻结窗口。** 一篇文档进入 Review 后，其关联代码冻结；任何 `os/` 改动即中止本轮。
   这是把「文档追工地」变成「文档与工地分开验收」的唯一办法。
4. **章节级冻结。** 每一章通过「教程 rubric + 出版门」后冻结；后续轮只审未冻结章与改动行。
   这把「整篇 3616 行 × 28 轮」变成「每章 2–3 轮」。

### P1：让预算与质量可判

5. **硬轮次预算 + 强制重写。** 3 个修改轮；第 4 轮不允许开。未收敛 → 按 `EDITION-RETRO`
   **重写失败章节**，而不是继续补丁。例外需用户 D 行，且必须写明「为什么重写不可行」。
6. **教程质量 rubric（可判）。** 每章必须有：
   - 学习目标（读者读完能做什么，1–3 条）；
   - 前置概念（只引用已学章节）；
   - 最小可运行示例（或最小可验证机制）；
   - **失败对照**（「如果这样做，哪里不好」——唯一允许的历史教学形态）；
   - 练习 / 自检问题（≥2）；
   - 小结（≤5 条）；
   - 术语首次定义；
   - 概念密度上限（每 100 行新概念数）。
   任一项缺失 = P1，不得 CONVERGED。
7. **指标换血。** 头条从「发现总数」改为：读者阻塞点数、每章概念数、示例可运行率、
   练习完成率、返工轮数、出版门命中数、todo open 数。面板 KPI 不再奖励条数。
8. **单线程顺序迭代**（已写进 V3.7）+ **禁止跨篇 ②**：未读篇的改动直接做，不留 ②。

### P2：供给与工具治理

9. **面板按风险启动**：低风险篇只跑 FACT + READER-A + DESIGN-D2；高风险篇才全六角色。
   目标是降低「发现供给」，而不是提高「发现速度」。
10. **同根复发 → 强制重写**：同一根因连续两轮复发，不再打补丁，重写该节。
11. **出版门与 todo 账本接入 CI**（基线机制）；**读者 rubric 的机械项做 detector**
    （学习目标/练习/小结/术语表的存在性、概念密度）。

## 5. 对 D01 的具体建议

1. **先取清单**：`doc-publication-check` 101 处 + `code-publication-check` 126 处 + todo 账本
   13 条。这三张清单是重写的输入，不是补丁的输入。
2. **选节重写**：优先 §3（45 处过程痕迹）与 §4（31 处），按「如果这样做会怎样」的对比写法
   重写；§1/§5/§6 做局部清理。
3. **先冻结代码**：重写期间不再落地设计批；D-107 线程完成后冻结。
4. **验收**：重写 → 出版门零命中 → 一次全量面板（不是每节一轮）→ rubric 验收 → 确认轮。
5. **预期**：从「28 轮补丁」变成「1 次章节重写 + 1 次确认轮」。如果重写后又出现大批发现，
   说明 rubric/冻结仍有漏洞，再改规则，而不是继续补。

## 6. 需要用户裁决的三件事

1. **代码冻结窗口**：Review 期间关联代码不改（设计批前置）。接受吗？
2. **3 轮硬上限 + 强制重写**：第 4 轮不允许开，未收敛就重写失败章节。接受吗？
3. **教程 rubric 的最小项集**：学习目标 / 前置概念 / 最小示例 / 失败对照 / 练习 / 小结 /
   术语定义 / 概念密度——够不够？还要加什么（图、表、章末索引、跨章引用）？

> 这三项决定 P0/P1 能否落地。未裁决前，不建议再对 D01 开任何 review 轮。
