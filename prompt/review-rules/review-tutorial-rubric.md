# 教程质量 rubric（V3.12，2026-11-22 作者裁决）

> **目标**：文档不只是「正确」，还要能被第一读者学会。用户是第一读者。
> **判级**：本章缺 TR-0 / TR-3 / TR-4 / TR-5 任一项 = **P1**；存在任一 P1 的篇目不得 `CONVERGED`。
> **V3.12 的结构修正**：TR-1 学习目标与 TR-2 前置知识是作者组织教学、评审者检查完整性的约束，
> **不再强制在章节开头以独立小节呈现**。机械门只检查 TR-0、TR-3..TR-6；TR-1/TR-2 由
> `structure.md` §11 复述测试与 G18 冷读判定。理由：把技术评审文档的「主题思想 + 不变量 +
> 编号系统」当成教程开头，会把大量内部术语提前塞给读者，造成「信息没错但出现的时机全错」。
> **单元映射**：TR-0..TR-6 仍在父 `##` 章级判定；T2 的 `###` 节负责触发与修复，
> 不把 rubric 拆成节级七项。
> **与出版标准的关系**：`review-publication.md` 管「不能有什么」（标号/历史/中间引用）；
> 本文件管「必须有什么」（教学结构）。两者都过，才叫出版就绪。

---

## 一、认知顺序原则

> 先让读者产生理解问题的需要，再给他理解问题所需的知识。

读者的理解顺序：

1. 知道遇到了什么问题；
2. 理解为什么这个问题值得解决；
3. 遇到解决问题所需的新概念；
4. 作者在概念真正参与推理时解释它；
5. 通过完整机制理解约束、不变量和设计选择。

章节开头只负责第 1–2 步。不要求集中定义术语、列举不变量、解释编号体系或提供全文导航；
只引入理解当前问题所必需的信息。

## 二、每章必答项

| 编号 | 项 | 要求 | 机械判定 |
|---|---|---|---|
| **TR-0** | **问题入口** | 章节开头用自然语言说明本章要解决什么问题、为什么读者需要理解它；不以术语清单、不变量表或编号说明开场 | 章内第一个非空内容必须是散文段落（非列表/表格/围栏代码/引用块），且该段落实义字符 ≥20；若章首直接进入 `N.0`，则由 `#### 问题入口` 子节承担 |
| **TR-1** | **学习目标** | 作者与评审者能说出读者读完本章后应理解什么、能解释什么或能完成什么；用于约束教学内容是否完整，**不强制在章首以列表呈现** | 不作为独立小节检查；由 `structure.md` §11 复述测试与 G18 冷读判定 |
| **TR-2** | **前置知识** | 只包括作者要求读者在本章开始前已经掌握的通用知识或前序章节已建立的概念；**本章准备引入和讲解的概念不得列为前置知识** | 若正文出现「前置/预备/前提」小节，不得把本章才引入的内部术语列为前置；由结构评审与 G18 判定 |
| **TR-3** | **最小可运行示例** | 一个可执行或可观察的最小例子（代码 / 命令 / 状态推演） | 章节内存在标题含「示例 / 最小 / 可运行 / 动手」的小节，且含至少一个围栏代码块或编号步骤 |
| **TR-4** | **失败对照** | 「如果这样做，哪里不好，所以这里这样做」——唯一允许的历史教学形态 | 章节内存在标题含「如果 / 失败 / 反例 / 错误做法 / 常见错误」的小节，且明确指出后果（不是泛泛而谈） |
| **TR-5** | **小结** | ≤5 条本章要点 | 章节内存在标题含「小结 / 总结 / 本章要点 / 要点回顾」的小节，条目数 1–5 |
| **TR-6** | **术语首次定义** | 新术语在首次出现处定义，或篇末有术语表 | 篇内存在「术语 / 名词表」章节，或章节内有「术语」小节 |

### 2.1 `N.0` 导读的结构（L0.9 门）

每章 `N.0 本章导读` 只保留两个子节：`#### 问题入口` 与 `#### 前置概念`。`前置概念` 只列真正的前置知识，本章才引入的概念不得列入。其余教学构件按下列位置放：

- `学习目标`：删除独立小节；V3.12 已明确不强制在章首呈现。
- `最小示例`：移到读者已经具备执行所需概念的位置（章内机制段之后，或章末回顾之前）。
- `失败对照`：移到它所对照的机制之后，不留在导读。
- `小结`：移到本章末尾，位于最后一个非导读、非术语内容小节之后。
- `术语`：移到章末，或改为行内 `**术语**（解释）`；不得留在 `N.0` 内。

机械判定：`tutorial-rubric-check.py` 检查 `N.0` 子节数 ≤2、子节名只允许上述两项、`小结` 后不再有非术语小节、`术语` 不在 `N.0` 内。

**段落负载（报告项，不阻断）**：单个自然段超过 500 实义字符 → WARN，提示可能过载；按“结论先行、锚点次之、边界最后”拆成 2–3 段。

**规则候选（未实施）**：“读者操作指令”检测——正文出现“可跳过”“不要混”“先分清”“第一次读可跳过”等指令时，报 P1 结构缺陷。这些指令说明主线与参考材料没有在结构上自然分开；目标是在后续版本中降为 0。

**概念密度（报告项，不阻断）**：每 100 行新增 `###` 小节数 > 8 → WARN，提示该章可能塞得太满。

**知识与约束的引入时机**：

- 概念在读者需要它理解当前问题时引入；
- 不变量在后续推理依赖它之前建立；
- 编号约定在读者第一次需要解读该编号时说明；
- 不为尚未出现的正文内容提前灌输完整知识体系。

## 三、为什么是这些项

- **问题入口**：读者先要知道「为什么现在要读这一段」，才愿意接受后面的术语和约束。
- **学习目标**：没有目标，作者不知道哪些内容该讲、哪些该删；但它不是给读者的任务清单。
- **前置知识**：教程的失败大多来自「用到还没教的东西」；只列真正的前序知识，不把本章内容提前。
- **最小可运行示例**：OS 教程的核心是「看见它跑起来」；纯叙述无法验证理解。
- **失败对照**：这是唯一允许的历史教学形态——不是「最初…后来删了」，而是「如果这样做，
  哪里不好，所以这里直接这样做」。它同时承担「反模式教学」与「设计理由」两个功能。
- **小结**：读者合上本章时的记忆锚点。
- **术语定义**：同一概念在不同章用不同词，是读者卡住的第一大来源。

## 四、G18 可读性否决（V3.12）

### 4.1 读者画像

读者应具备：

- C 语言阅读能力；
- 操作系统的基本启动过程概念；
- 基本 Rust 语法、所有权和类型知识；
- 物理地址、虚拟地址、页表等基本概念。

读者不被默认具备：

- 本项目 Rust 版本的启动链知识；
- `BootHandoff`、`DirectMapLayout` 等项目内部类型的先验理解；
- 三架构启动路径的具体知识；
- 尚未在前置章节讲授的内部设计契约。

### 4.2 每篇学习范围表

每篇文档在学习范围表（`rewrite-notes/meta/review/scope/<stage>/<doc-stem>.yaml`）中声明：

| 内容 | 本篇要求 |
|---|---|
| 例如：Direct Map 是什么 | 能建立基本概念 |
| 例如：为什么启动阶段需要它 | 能理解基本用途 |
| 例如：在启动流程中何时建立 | 能理解顺序和作用 |
| 例如：三架构完整布局与建立机制 | 不要求本篇掌握，属于独立专题 |

- 表由 `review-units.py init` 建模板，**只能由作者确认**（`scope confirm --by author`）；
- 确认后随 edition 固定；冷读学生按表内「要求」项判断，表外内容不展开不扣分；
- 学习范围表不得由冷读 agent 自行推断或扩张。

### 4.3 硬劝退定义

> 读者无法完成学习范围表内的核心学习任务，并且能够指出具体的文本缺陷及缺失的理解链条。

满足以下任一条：

- 学习范围表内的关键机制从未完整讲解；
- 核心概念出现时没有建立必要的前提；
- 两处章节互相指向，读者找不到真正的解释；
- 关键过程被拆成多个局部描述，读者无法还原完整执行顺序；
- 重要结论没有解释依据，必须依赖学习范围表外的知识才能理解。

以下**不构成硬劝退**：术语不好理解、读起来累、不够有趣、概念密度高（可报 P2 改进项）。

### 4.4 冷读发现格式

> 我读到哪里，已经知道什么，接下来需要理解什么，但正文缺少哪一段解释，因此无法继续推导。

报告必须给出机器可读的硬劝退计数：`HARD-REJECTIONS: <n>` 或 `硬劝退: <n>`。

### 4.5 执行时机

```text
确认轮其他验证完成
    ↓
G18 端到端冷读（新独立 READER-C 运行 + 学生画像 + 学习范围表）
    ↓
硬劝退 = 0 → 才允许 gate --pass / CONVERGED
硬劝退 > 0 → 不记录 CONVERGED，发现进修复清单
```

### 4.6 READER-C 独立性

G18 的 READER-C 是**新的独立冷启动运行**：

- 输入：当前待收敛的整篇文档 + 读者画像 + 学习范围表；
- **不提供**：之前的面板报告、缺陷清单、预期结论、Rust 源码、其他教程文档；
- 角色仍叫 READER-C，但审查上下文是全新的。`review-panel.md` 的材料隔离规则直接适用。

### 4.7 作者抗辩与 Me Agent 判断

- 冷读学生报告阅读障碍；
- me agent 对照学习范围表和既有章节职责，判断是否符合硬劝退定义；
- 作者可提出设计意图、前置知识或其他反证；
- me agent 判断反证：引用已批准范围 → 降级；新教学取舍 → 交还作者。

### 4.8 不反复空转

同一根因导致的多个阅读障碍，合并为一个发现；修复后验证根因是否消除，
不按表面症状数量新开审查轮次。

### 4.9 中文表达审计（不否决收敛）

以中文编辑身份审查，**不否决收敛**，发现转 `style-fix`。不设限定语密度机械阈值；
给出少量代表性原句和改写建议即可。

## 五、检测器

`python3 tools/tutorial-rubric-check.py <doc>`：

- 按 `## ` 切章；跳过 `参见/附录/索引/参考文献` 与 <20 行章节；
- 逐章检查 TR-0、TR-3..TR-6；缺项打印 `[FAIL] <章>: 缺 TR-n（…）`；
- TR-1/TR-2 不做标题关键词检查，避免逼迫作者在章首堆术语；
- `--report` 只打印不退出 1（用于存量文档的 burn-down）；
- `--self-test` 正反例判别；
- 退出码：有缺项 = 1。

**适用范围**：当前篇在 CONVERGED 前必须 `exit 0`；G18 冷读另行通过。非当前篇只跑 `--report`。

## 六、与 G13/G18 的关系

`review-evals.md` §6A：

- **G13 教程 rubric**：当前篇 `tutorial-rubric-check.py` 零缺项（TR-0、TR-3..TR-6）；
- **G18 可读性冷读**：确认轮内完成整篇 `student-cold-read` 事件，学习范围表已由作者确认，
  报告 `HARD-REJECTIONS: 0`；缺一项不得 `CONVERGED`。

G13 与 G10（文档出版）、G11（代码出版）、G12（TODO 账本）、G18 并列；任何一项不满足，
不得 `CONVERGED`。
