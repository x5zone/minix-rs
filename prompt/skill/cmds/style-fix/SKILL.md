# style-fix

## 目标
提升教学性，for 读者。修文风、去开发文档味、章节重组、细节深度归位。

## scope（用户未指定时确认）
`section`（默认）/ `chapter` / `doc`。

## 执行
按 `prompt/review-rules/review-cmds.md` §三：四步审计（章节组织 → 逐节开发文档味 → 细节深度 → **教学构件完备性**）→ 修复。
第四维逐条勾 §六 style-bible 第 9 条“必备构件清单”（贴码/调用图/辨析/三架构对照/诊断），对照 §一 通用门 #9。⚠️ **以"审计通过、无改动"收尾，在现有判据下曾是满分，在新判据下视为未做教学增益作业**——必须逐构件回答“本处已有 / 仍缺为何可不补”。
文风硬约束见 §六 style-bible：技术博客文风、禁黑话/缩写/文言文/压缩简写、禁"旧版/最初/后来"叙事（模式 64）、Ch1 主语是 CPU/OS/机制而非函数名；且§六 第 10 条仲裁：**反膨胀≠砍教学，删减只删重复与越界，不删贴码/图/辨析/对照/诊断。**

## 强制门
锚点纪律门（模式 83）+ 文风门 + **教学构件承载门**（§一 #9：分析/实现章不得纯散文；机器读数 `tools/doc-code-density-check.sh`）。

## 不做
不改代码语义；不做 C 覆盖度判断（发现 → 记录交 full-review）。但“补贴一段真实节选码/补一张调用图/补三架构对照”属本 cmd 职责（是教学承载，不是改语义）。

## 产物
三类审计结果 + 修复稿 + 自检（读者复述测试，H1）+ 进出各跑一次全量 lint（`tools/doc-style-lint.sh`；进入前出存量清单，完成后 `--diff` 零 error）。文档类产物同时附 Rust 代码块四分类表（H3，`tools/doc-snippet-extract.sh`）。
