# style-bible

## 硬裁决：读者体验优先于审查便利（2026-10-07 固化）

正式文档是写给**读者**的，不是写给**审查**方便看的。复刻代码里那些坐标注释、行号提示，本质是
AI 回 `minix3/` 核对时给自己留的锚点；它们占住读者版面，却不增加理解。因此定一条排序原则：
**读者读到什么先决定，审查需要什么后承接**——审查需求一律外移到锚点底账，不与讲解争版面。

判据可执行（按形态分四类，不再笼统说"锚点越少越好"）：

| 形态 | 例子 | 判定 | 处置 |
|---|---|---|---|
| 纯坐标，零讲解 | 代码块行尾 `/* 33 */` | **噪声** | 移出，进锚点底账；`tools/doc-style-lint.sh` 规则 SL-9 对新增行阻断 |
| 坐标与讲解同框 | `unsigned fp_flags;  /* 16: 进程标志 */` | **半噪声** | 讲解留下（`/* 进程标志 */`），数字移出 |
| 工具派生行号提示 | 正文里 `（L123，工具生成）` | **噪声（工具自产）** | 移出；暂列 SL-10 告警级，等底账抽取工具落地后升为阻断（否则工具自己产出违规） |
| 符号锚点、句内区间题注 | `os/kernel/src/lib.rs:fn kmain`、`（本节复刻 rs/main.c:38-131）` | **合法** | 保留：符号锚点不随代码漂移，且是读者可跳的入口；块级区间题注是读者想知道的"这对应哪段 C" |

一句话记忆版：**同一个括号里，有讲解就留，只有坐标就走。**

配套两条不许越界：

- 移出**不等于**删除可追溯性。每条被移走的坐标都要落到锚点底账（格式见下），且移出动作与正文修改
  同一笔提交完成——于是历史里永远留有原始值，底账丢失也能从 git 历史重建。
- 不许为了"读者体验"削弱任何真值校验：符号锚点解析（Sync-5）、覆盖率穷举、测试名对账照旧强制。

### 锚点底账格式（`.review/{tool}/{stage}/{doc-stem}.anchors.md`）

评审中间产物，随 `.review/` 不入库；正式文档**不引用**它（隐藏目录约定）。每篇被降噪的文档一份：

```markdown
# {doc-stem} 锚点底账（审查用，非交付物）
> 来源：本文坐标自正式正文移出。正文与本页同一笔提交落地，历史即备份。
| 正文位置（章节/行首文字片段） | 坐标类型 | 真源锚点 |
|---|---|---|
| §2.3 `EXTERN struct rproc rproc[...]` | C 源行号 | minix3/minix/include/minix/proc.h:34 |
| §4.1 `sef_receive_status` 说明段 | 工具行号提示 | os/libs/minix-sef/src/lib.rs:fn sef_receive_status（L123） |
```


## 定位
所有文档产出的硬约束声明。可单独加载，也是 style-fix/full-review 等文档类任务的前置。

## 八条
1. 文风：技术博客——详细、清晰、透彻、深入浅出；讲本质机制（WHY→WHAT→HOW）。
2. 绝对禁止：黑话/行话简称、压缩简写、文言文、字词缩略——文档和中间结果都适用。历史教训："双校验、十处理函数的纯计算部分、四十五表项、三十九名单"式输出完全不可读，且让人无法相信思维链和代码的正确性。
3. 禁开发文档味：不写"旧版/最初/后来/我们改成"；用"如果 X 设计会有 Y 问题，所以用 Z"假设性推理（模式 64）。
4. Ch1 主语 = CPU/OS/机制/矛盾，不是函数名或结构体名。
5. 中间结果同样清晰详细（scan.md/todo/阶段产物禁止速记黑话）——"换个 AI 能看明白"是可读性标准。
6. 锚点纪律（模式 83）：事实断言必须带符号锚点（`path:fn name`、C `path:func`）或来源锚点；行号只允许工具派生 `（Lnnn，工具生成）`，禁止手工维护；给不出 → 标 [待验证]，禁止静默写成事实。
7. **正式文档只面向读者，过程痕迹禁止入正文**（A1.2/7）：review 编号、review 日期、修复史叙事、写作策略元注释、review 工具术语一律不进正文；机器检查 `tools/doc-style-lint.sh`（存量报告、`--diff` 阻断）。
8. **修复文档用假设性推理或直接正确表述重写，不追加补丁句**（A1.2/8）：修复信息写进 `.review/` 产物，不写进正文。

完整规则：`prompt/review-rules/review-cmds.md` §六。
