# test-audit

## 目标
审查测试本身。测试是正确性的另一支柱——但测试自己也会错、会冗余、会虚构。

## scope
`file` / `module` / `doc`（对账文档 §5 测试描述）。

## 执行
按 `prompt/review-rules/review-cmds.md` §五，5 维全查：
1 完备性（核心分支/边界/错误路径/并发）；
2 自身正确性（断言对应被测行为、mock 正确——本项目发生过"测试代码就是错的，啥都测不出来"的真实事故，重点排查）；
3 冗余（同行为多测、可参数化）；
4 无效（空体/#[ignore] 无理由/assert!(true)）；
5 虚构（文档 §5 声称的测试 fn 必须 grep 命中；双向对账）。

## 强制门
测试名对账门（本 cmd 主门，全量非抽样）+ 锚点纪律门。

## 不做
不修功能代码；不补新功能测试（缺口 → 清单，修复走 todo-fix）。

## 产物
5 维报告 + 文档-代码测试一致性矩阵 + 必修项清单。
