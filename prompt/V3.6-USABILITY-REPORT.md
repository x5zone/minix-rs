### 4.1 为什么判「不收敛」

用户的收敛口径是「无 P0 + 额外一轮确认」。**五轮没有任何一轮是零 P0**，因此不满足。

更重要的观察：**每一轮的 P0 都出在上一轮的修复里**，而不是新领域：

- R2 在 R1 的 `_has_add` / `_debt_row_closed` / 回执解析里找到 3 个 P0；
- R3 在 R2 的修复里找到 5 个（`完成度` 漏网、`_has_add` 无极性、不完整回执、`§7.7` 恒真）；
- R4 在 R3 的修复里找到 2 个（`FAIL 未清零`、否定剥离吃掉真提案）；
- R5 在 R4 的契约里找到 2 个（**照模板写反而被判无提案**、token 全文匹配）。

这不是执行质量问题，是**方法性质**：用文本/正则表达领域判据，表达力天然不足；每次修复
引入新语法面，下一轮就找到绕过。18 轮文本门循环（r10–r27）已经证明过一次；V3.6 的五轮
复现了同一规律。

### 4.2 但严重度在下降

| 轮 | P0 的性质 |
|---|---|
| R1–R2 | **判据本身错**（语义理解错误：C-33 与判例矛盾、`panic!` 与 C-31 打架） |
| R3 | **修复引入的反向激励**（`_has_add` 无极性 → 诚实零报告 FAIL） |
| R4 | **修复实现与自身契约不符**（否定剥离吃掉真提案） |
| R5 | **契约实现细节**（模板括注不匹配、token 匹配位置） |

R4/R5 把关键判据改成 **token / 字段**这类结构化契约后，P0 的类型从「判据错」退化为
「实现没对齐自己刚写下的契约」，影响面从「规则自相矛盾」缩到「某个语法变体漏判」。

## 五、当前可用性判定

### 可用（有证据）

1. **合规轮端到端通过**：合成 V3.6 run（`schema: V3.6 from R1` + 2 行减法表 + `- 减法: 提案 2 / 采纳 1`
   + `- 遗留 P0: 0 / P1: 0`）实跑 `PASS 11 / WARN 0 / FAIL 0`（`tmp/r4/system.md`）。
2. **存量零误伤**：六篇归档审计 FAIL 数与同 HEAD 旧版工具逐篇一致
   （**108/77/84/16/17/0**，D01 的数字随并发会话新增欠账增长，但旧/新工具始终一致）。
3. **六篇最终轮**：02–06 全 PASS；01 R35 的 FAIL 全部是真实欠账（I-36/I-40/I-42/I-43/I-44），
   不是 V3.6 判据噪声。
4. **轨迹修复有效**：b1–b5 全部有前后对照读数（见 §三）。
5. **四道规则同步门 + 七项工具自测全绿**。

### 不可用之处（必须知道）

1. **大部分 V3.6 判据是荣誉制**：C-31 三问、C-33 可混淆面、C-35 教学账、C-37 触发的**内容**
   没有任何工具检查；门只检查「字段在不在」与「计数对不对」。**不要把门绿当作判据被执行的证据。**
2. **`采纳` 数不与台账 ⑥ 对账**：可以写 `采纳 0` 而实际实施了减法。
3. **V3.6 只对 `schema: V3.6 from R<N>` 且带 `--round` 的文档生效**：存量六篇走 V3.4 schema，
   不受新门约束（这是设计，不是缺陷）。
4. **`--round` 之外的归档审计不会跑减法门**。

### 不可修（已登记 V3.7，16 项）

| 类别 | 条目 |
|---|---|
| 门覆盖缺口 | 确认轮 survey 发现量入 metrics；读者档位机械门；六角色显式枚举；D 号唯一性与引用存在性；V3.6 必填字段无门解析 |
| 语义约定 | refute「主张成立」不得写 FP；裸 `superseded` 需目标；`采纳` 与台账 ⑥ 对账 |
| 格式/工具 | OPEN-DEBT 表头别名；空白首格行；减法门 `from R<N>` 作用域；style-lint 对 runs 日期豁免；§7.7 围栏/垃圾行加固 |
| 定义缺失 | 「API 表面倍数」无定义；code-excellence「前置条件」执行歧义 |
| 规则措辞 | 缺 token 仅 WARN 而前言写「必须」 |

## 六、给使用者的建议

1. **把 V3.6 当决策指南用，不要当验证器用。** 它的价值在于给 review agent 一套可执行的
   取舍尺度（威胁模型分层、减法优先、教学成本），而不在于「门绿 = 判据执行了」。
2. **门只信三类读数**：制品链哈希、计数对账（\(提案数 = 表行数\)、\(发现总数 = 处置和\)）、
   结构化 token（`[CLOSED]`/`[OPEN]`、`- 遗留 P0: n / P1: n`）。其余判据靠 review agent 的
   产物质量与 meta-review 抽样。
3. **不要再用「补词表」修文本门。** 五轮与 18 轮循环的共同教训：能改形态（token/字段/计数）
   就不要改正则。这条已写进 `review-panel.md` §4.7 与 `review-evals.md` §4.0f 的判例说明。
4. **继续对抗的边际收益**：预计每轮仍会产出 1–3 个「契约实现细节」级 P0，但不再产出
   「判据自相矛盾」级。若目标是「零 P0」，需要把剩余判据全部改造成结构化契约（V3.7 的
   16 项），而不是继续加对抗轮。
5. **V3.7 的晋升纪律**：按 §7.2 每边界 ≤2 条分批。优先做「门覆盖缺口」类（可机械校验），
   最后做「定义缺失」类（需要用户裁决取舍）。
