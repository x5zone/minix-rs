## 1. 概念：出生证明四联单

### 1.0 章节引言

目标读者是跟完第 11 篇的读者：会找会加会删。前置知识只需要一条：新建文件是"占号、建档、上户口"三件事。

本章建立创建的心智模型：四拍（查空、分配、落盘、进入）加回滚（哪拍失败拆哪拍），以及四种出生（文件、设备、目录、链接）各自的加戏。

### 1.1 四拍：查空、分配、落盘、进入

新建节点分四拍。第一拍查：父目录必须存在且有链接（删过的目录不算），目录建子且父链接到顶报链接上限，名字必须空（有人报已存在，其他失败透传）。第二拍分配：位图占位、表占槽、填模式属主、链接数置一（先占一，户口上了再说）、设备区号落首区。第三拍落盘：脏节点强制写盘——崩溃后孤儿节点（有号无名）远好于悬空名字（有名无号），顺序不能反。第四拍进入：名字写进父目录，失败则拆台（链接数减一、标脏、释放、退位图）。

四拍的顺序是 crash 一致性的果：每拍都让"已持久"的一边比"未持久"的多一点，任何时刻崩溃，检查工具都能收拾。

### 1.2 回滚：哪拍失败拆哪拍

进入失败拆到分配前：链接数减一、标脏、释放槽位、退位图号。四样全退，不留尾巴（占着位图不用的号是泄漏，泄漏是慢性 corrupt）。点点舞失败（见下节）多拆一样：父目录里刚写的名字删掉——删失败报 corrupt（C 在这里宕机"目录消失了"，名字写进去却删不掉一定是盘坏了，报错比崩溃诚实）。

### 1.3 目录的点点舞

建目录在四拍之外加三步：点与点点写进新目录块，成功则子母链接数各加一（点算子的一份，点点算母的一份），失败则删名退链接退位。母链接数加一要标脏母节点——链接数是持久状态，不标脏等于白加。

### 1.4 符号链接：目标住单间

符号链接的目标字符串住在独立的数据块里（新分一区），不是槽位里。流程：建节点、分区、目标加结束零拷入、按真长度定大小（串里有提前结束零报名字过长——注释为这个错误码道歉但保留它：没有更贴切的码）。失败回滚多拆一区（分区也要退）。目标超块直接拒绝，连区都不分——先验后占，不浪费。

### 1.5 设备节点与寻位标记

设备节点是"带设备号的空文件"：创建同文件，首区号填设备号（设备号借住在区号字段，这是 Unix 的传统把戏：字符块设备没有数据区，区号字段空着也是空着）。寻位标记最简单：找到槽位置标记，找不到静默——寻位是提速 hint，hint 永不报错。

### 1.6 本章小结

四拍建文件（查空分配落盘进入），失败拆台（位图槽位名字全退），目录跳点点舞（两进入两加数），链接住单间（目标块加回滚），设备借区号字段，寻位静默。下一章进入 C 源码验证。

父无链接报无此项（`open.c:208-211`）。目录建子且父到顶报链接上限（`open.c:213-217`）。前进找名（`open.c:220`）。 miss 则分配（`open.c:224`，无位返回空）、链接加一、区号落首区、强制落盘（`open.c:233-235`，注释写明 crash 鲁棒性）、进入名字（`open.c:238`），进入失败则链接减一标脏释放返回进入错（`open.c:239-243`）。命中则已存在（`open.c:248-251`），其他失败透传。置错误码返回槽位（`open.c:255-256`）。

### 2.6 寻位 `fs_seek`（`open.c:263-270`）

找槽（`open.c:268`），找到置寻位标记。找不到静默——注释写明抑制预读是目的。

### 2.7 与 Rust 实现的步骤差异说明

| 差异 | C 做法 | Rust 做法 | 分类 |
|------|--------|-----------|------|
| 错误码全局 | `err_code` 全局读写 | 返回值 | 设计决策：错误随调用走 |
| 空槽释放 | 放空无操作 | 内部分支释放 | 无差异（空安全保留） |
| 回滚宕机两处 | 目录消失、链接消失宕机 | 报 corrupt | 设计决策：坏输入不是编程错误 |
| 精确错误透传 | 取父失败一律无效参数 | 表满位图满精确透传 | 设计决策：精确优于粗糙（调用方可决策） |
| 目标拷贝 | 授权复制进块 | 调用方供字节片 | 设计决策：传输边界在适配器（第 02 篇） |

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 上下文束收五件（依据：第 1.1 节四拍的用料）

表、缓存、超级块、位图、设备号加几何与只读态收成一个上下文结构，四 makers 只取上下文。替代方案是每函数七八个参数：签名与 C 一一对应但调用点拼参数拼到眼花。上下文把"同一挂载的共享件"打包，参数剩业务件（目录、名字、模式）。第 07 篇区策略用闭包，本篇用结构——闭包适合一两个回调，结构适合五个以上共享件，分水岭在数量。

### 3.2 完成态分两种（依据：第 2.1 节与第 2.2 节的放与不放）

建文件返回槽位引用（调用方持有，如 C），建设备建目录建链接返回已释放快照（槽位号加号，如 C 的"放完再报"）。两种完成态用两种类型，误用编译不过：拿着快照当引用用？快照没有引用方法。替代方案是统一返回槽位：调用方分不清谁要放，漏放泄漏引用。类型即文档。

### 3.3 回滚宕机改 corrupt（依据：第 1.2 节、第 2.3 节）

删名失败报 corrupt。C 宕机的理由是"刚写进去的名字删不掉一定是 bug"，但 damaged 镜像下块读写失败同样删不掉——那是输入坏，不是程序坏。坏输入报 corrupt，编程错误才断言。区分标准：第 08 篇重复释放同理。

### 3.4 精确错误透传（依据：第 2.1 节取父）

取父失败透传表满位图满精确码，不吞成无效参数。C 吞成的理由是调用方只看成功失败；Rust 调用方（框架适配器）直接转发错误码给虚拟文件系统服务，精确码一路送达应用。信息只增不减，转发链无损。

### 3.5 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 上下文束 | 第 1.1 节 | 七八参数 | 调用点拼参眼花 |
| 完成态两种类型 | 第 2.1、2.2 节 | 统一槽位 | 漏放泄漏，分不清 |
| 回滚报 corrupt | 第 1.2 节 | 保留宕机 | 坏输入不是编程错误 |
| 精确透传 | 第 2.1 节 | 吞成无效 | 转发链无损，信息只增 |

## 4. Rust 实现详解

### 4.2 新节点与四 makers（`open.rs` 实现小节）

### 4.3 取父放槽辅助（`open.rs` 辅助小节）
