## 1. 概念：装好系统之后，软件从哪里来

### 1.0 本章说明

系统装好了，引导进去了，网络通了，服务跑起来了。接下来用户要装软件：编辑器、远程工具、开发工具链、解释器。一个一个手动编译太累，所以需要包管理：有人把软件编好放在仓库里，用户一句话就装上。包管理之外，还有三件供给侧的事：引导块怎么写进磁盘，构建依赖怎么算出来，汇编里的符号地址怎么抽出来给链接器用。

> **本章不讲什么**：
>
> - 编译器与链接器本身（构建链之外）
> - 包下载与解包的执行（待执行层）
> - 完美散列函数的数学实现（本篇只到方法选择）
>
> 本章只讲供给语言：集合怎么选，仓库地址怎么写，引导块怎么选文件，依赖行长什么样，符号行长什么样，构建配置行长什么样。

### 1.1 软件集合：三组包与确认跳过

包集合脚本把常用软件分成三组：核心工具组（远程登录、编辑器、传输工具）、开发工具组（版本控制、两种构建工具、二进制工具、编译器）、附加组（语法生成器、文档工具、解释器）。每组一次安装调用，每组之前打印标题，安装时逐个确认，输入否定就跳过整组。这种分组不是技术必须，是经验沉淀：刚装完系统的用户最可能先要这三类东西，按组给比让他自己一个一个想更快。

包名的形状有规矩：小写字母、数字、减号、加号、点，开头必须是字母或数字。大写、空格、下划线开头都不接受。规矩写进检查函数，坏名字在到达安装器之前就被拦下。

### 1.2 光盘仓库：地址模板与查找顺序

没有网络的机器从光盘装包。仓库地址按模板拼出来：`packages` 加发行版本加体系结构加 `All`。摘要文件名固定，查找顺序固定：先看根目录，再看挂载点，哪个先有摘要文件就用哪个，剩下的参数原样交给包安装器。用户配置文件可以指定光驱名，驱动挂载留给执行层。

为什么先根后挂载点？因为有些机器把光盘内容直接拷进了硬盘，根目录就有仓库，这时候不该再去挂光驱。顺序即优先级，写死在常量里，测试钉死。

### 1.3 引导块安装：按文件系统选阶段文件

引导块安装把第二阶段加载器写进磁盘的保留区。不同文件系统用不同的阶段文件：快速文件系统、第二扩展文件系统、第三代 Minix 文件系统各一个。新安装要求 32 个空闲扇区，因为第二阶段加载器约 8 千字节，地方不够就失败，而不是写一半截断。类型分发、文件选择、空间检查三件事各自独立，类型错了报参数无效，空间不够报空间耗尽，两种错误泾渭分明。

### 1.4 构建辅助：依赖行、符号行、配置行

依赖生成工具读源码里的包含关系，写出 `目标：依赖` 形状的行，缺省写进 `.depend` 文件。长行用末尾反斜杠续行，续行 Zugehörigkeit 在纯层按逻辑行分组。符号抽取工具读汇编输出的符号，写出 `名字 数值` 形状的行，两种输出模式（C 代码模式与 Forth 代码模式）互斥。构建配置文件只有五行：一个缺省赋值加一个条件块，缺省赋值用问号等号，条件行以点开头归构建器，纯层只管赋值行。

## 2. C 源码分析

### 2.1 包集合脚本：三组与确认

集合脚本定义三组变量：核心工具三个包，开发工具五个包，附加三个包。每组打印标题后一次安装调用，确认提示由安装器负责，否定跳过整组。Rust 侧 `sets.rs` 的集合枚举与这三组逐项对应，缺失计算（列出未安装）与跳过语义对应。

### 2.2 光盘脚本：路径模板与查找顺序

仓库路径模板 `packages/$(uname -r)/$(uname -m)/All` 由发行版本与体系结构拼出，摘要文件名 `pkg_summary.bz2` 固定。查找循环先根后挂载点，命中即设置仓库环境变量并移交参数。Rust 侧 `cdrepo.rs` 的路径拼装与模板逐段对应，查找顺序以常量逐项对应。

### 2.3 引导安装：类型分发与空间要求

文件系统类型分发（第 61 行附近）把命令行参数映射到三种实现，阶段文件选择（第 246 行附近）按类型取文件名，空间要求（第 276 行附近）检查 32 个扇区，不足报错而不是截断写。Rust 侧 `bootinst.rs` 的类型解析、文件名表、空间检查与这三处逐项对应。

### 2.4 覆盖率拉取：大缓冲与单参数

覆盖率拉取工具用 4 兆字节静态缓冲一次装下全部元数据与文件数据，命令行只接受一个标签参数，多一个少一个都打印用法。先整块清零再收数据，避免虚拟内存子系统在刷新中途介入分页。Rust 侧本篇到职责级为止（标签解析与缓冲常量），传输执行归执行层。

### 2.5 依赖生成与散列与符号抽取：文件名与方法与模式

依赖生成缺省输出 `.depend`，后缀表决定哪些文件参与，包含树决定行内容。完美散列工具的方法选择（第 139 行到第 144 行附近）在三种方法里选一种，`bdz` 是兼容别名。符号抽取的两个模式标志互斥，剩下的参数组成编译器命令。Rust 侧 `depfile.rs` 的行拆分与续行分组、`symgen.rs` 的模式解析与符号行解析与这三处逐项对应。

### 2.6 构建配置：五行文件

配置文件共 5 行：详细开关的缺省赋值占一行，条件块占剩下四行。Rust 侧 `mkconf.rs` 的赋值解析（三种操作符）与赋值行对应，条件行明确拒绝（归构建器），注释与空行报查无以便调用方跳过。

## 3. Rust 设计决策

### 3.1 为什么集合用枚举而不是字符串透传

字符串透传最省事，但选集输错一个字母（比如把开发集写成 `deev`）会一路传到安装器才报错，报错信息还是安装器的方言。枚举在解析期就把选择收敛到三个变体加全选，错词当场报参数无效。而且枚举让缺失计算有了类型：给一个集合，返回缺的包，集合本身不可能是坏的。如果直接透传字符串，每个下游函数都要重新校验，校验逻辑散得到处都是。

### 3.2 为什么路径拼装用调用方缓冲而不是返回字符串

无标准库环境下没有堆字符串可返回，拼装必须写进调用方给的缓冲。缓冲过小即错，而不是截断，因为截断的路径指向错误的位置，安装器会去错误的地方找包，报错信息牛头不对马嘴。字符白名单在拼装时检查，空格与斜杠进不来，路径穿越攻击在纯层就被挡住。

### 3.3 为什么空间不足与参数无效用不同的错误号

调用方（脚本）要区分这两种失败：参数无效是人的错，重看用法就行；空间不足是盘的错，需要清理或者换盘。用同一个错误号，脚本只能打印同一句话，用户分不清该改命令还是该清磁盘。空间耗尽沿用系统的空间耗尽错误号，脚本里现成的分支就能接住。

### 3.4 为什么续行分组只报告首行而不拼出整行

拼出整行需要分配内存存合并结果，无堆环境下做不到。报告每组首行（去续行符、去尾空）足以让调用方定位：执行层按位置取物理行自己拼，纯层只管分组正确。分组边界是续行符，判断只看行尾最后一个非空字符是不是反斜杠，简单到不可能错。

### 3.5 与同类系统的对照：供给工具只做准备，执行留给专用层

本篇延续全阶段的分层：纯层把话说明白（选哪个集、地址怎么写、空间够不够、行怎么拆），下载、写入、编译这些脏活归执行层。同类现代系统的包管理器也是这个分法，只是传输协议不同，本篇的纯判断层不依赖任何一种传输实现。构建链之外的宿主工具链不在本篇范围，边界在文档头显式声明。

## 4. 实现详解

### 4.1 模块结构

`os/commands/usr-sbin/pkgtools`（库包名 `minix-pkgtools`）共 7 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`PkgError`，22 对应参数无效、2 对应查无、28 对应空间耗尽）与模块组织 |
| `sets.rs` | `pkgin_sets.sh` 三组变量 | 集合解析、包名检查、包数据库接口 |
| `cdrepo.rs` | `pkgin_cd.sh` 路径模板 | 仓库路径拼装、查找顺序 |
| `bootinst.rs` | `installboot.c` 第 61 行与第 246 行与第 276 行附近 | 类型解析、阶段文件名、空间检查 |
| `depfile.rs` | `mkdep.c` 缺省文件名 | 依赖行拆分、续行判断、逻辑行分组 |
| `symgen.rs` | `genassym.sh` 模式标志 | 模式解析、符号行解析、符号表接口 |
| `mkconf.rs` | `mk.conf` 5 行 | 操作符解析、配置行解析 |

### 4.2 关键类型与不变量

- **包集合 `PackageSet`**：核心、开发、附加。不变量：数字与单词两形等价；全选以空表示；未知词即错。
- **包数据库 `PackageDb`**：集合查询加安装判断。不变量：切片实现三集合恒在；空实现一切查无；缺失计算只报未安装。
- **仓库路径**：发行版加体系结构。不变量：两段非空；字符白名单；缓冲过小即错。
- **引导文件系统 `BootFs`**：三种。不变量：未知词即错；文件名表与类型一一对应；空间少于 32 扇区即错。
- **依赖行**：目标加依赖。不变量：冒号必须有；两边非空；续行只看行尾。
- **生成模式 `GenMode`**：普通、C 代码、Forth。不变量：空词即普通；两模式互斥；未知字母即错。
- **符号表 `SymbolTable`**：查询加插入。不变量：同名后写覆盖；满表再插即错；空表查无且拒绝写。
- **配置赋值 `MkAssign`**：名字加操作符加值。不变量：注释空行报查无以便跳过；条件行明确拒绝；名字字符集受限。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `parse_set_selection` | 词 | 集合或全选 | 集合选择语义 |
| `check_package_name` | 名字 | 是否合法 | 包名规则语义 |
| `missing_of` | 库、集合、缓冲 | 缺数 | 跳过语义 |
| `build_repo_path` | 版本、体系、缓冲 | 路径长 | 路径模板语义 |
| `pick_repo_root` | 根表、存在判断 | 首个命中 | 查找顺序语义 |
| `parse_boot_fs` | 词 | 类型 | 类型分发语义 |
| `check_loader_room` | 空闲扇区 | 是否够 | 空间要求语义 |
| `split_dep_line` | 行 | 目标与依赖 | 依赖行语义 |
| `join_continuations` | 物理行、缓冲 | 逻辑行数 | 续行语义 |
| `parse_symbol_line` | 行 | 符号定义 | 符号行语义 |
| `parse_mk_line` | 行 | 配置赋值 | 配置行语义 |
