## 1. C 真序

### 1.1 阶段类型判定

**用户系统交付因果链型**（plan §1.2 裁定，沿 14-stage-runtime 非 server 先例）：commands 层没有 server 启动链，主线是**内核交出控制权之后的交付链**——init → rc → 服务 → 登录 → shell → 功能域命令 → 游戏。附**功能域语义分组**次主线（plan §1.3：06~24 按文件/文本/正则/编辑/文档/归档/进程/终端/存储/网络/系统/游戏分组，POSIX 安装分层只决定权限与 PATH 不决定语义归属）。

**规模特性**（六轮之最）：865 个 .c / 425,130 行 / 328 命令 / 49 项 etc 配置——任何"逐命令精讲"都会失控，plan §3.6 的**命令契约表**（组内共享语义主线 + 全量契约表 + Requires 列）是唯一可行形态，B 相必须坚持。
