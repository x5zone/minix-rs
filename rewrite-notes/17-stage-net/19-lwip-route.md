## 1. 概念：前缀长度是唯一的组织原则

### 1.0 本章的读者与阅读方法

本章假设读者已经理解第 05 篇的掩码连续性规则，知道掩码可以表达为前缀长度。本章不需要读者了解基数树的旋转，只需要带着三个问题来读：为什么所有掩码都要求能表达为前缀长度，位序号与字节序号如何换算，管理层在哪些位置替换了协议栈自带逻辑。读完本章，读者应当能够说出前缀假设的内容，三个位运算公式的含义，以及 4 个覆盖与钩子点的位置，即使遮住所有函数名字也不影响理解。

### 1.1 前缀假设把掩码比较变成整数比较

源文件第 5 行到第 8 行的核心假设是所有掩码都是规范的：前若干位为 1，其余全为 0，可以用前缀长度完整表达。基于该假设，路由条目存放在与其掩码位宽对应的节点上，该节点仍可拥有子节点，子节点是更精细的前缀。不再区分叶与内部节点，只区分数据节点（带条目，零到两个孩子）与链路节点（无条目，恰有两个孩子）。这种存放的意义在于查找即最长匹配：从根按位下行，最后一个遇到的数据节点就是最长匹配。不支持的特例是同一地址全掩码网络条目与主机条目并存，源文件明确说明暂不支持，因为该树不用于邻居表，如需支持只需改精确查找的原型，添加函数已预留差异。

### 1.2 三个位运算公式是树的坐标系

位序号转字节下标为右移 3 位，位序号转字节内偏移为 7 减去低 3 位，位宽转字节数为位宽加 7 后右移 3 位。位 0 是第 0 字节的最高位，这种大端位序与网络字节序一致。举例：位 0 在字节 0 偏移 7，位 7 在字节 0 偏移 0，位 8 在字节 1 偏移 7。位宽 0 占 0 字节，位宽 1 与 8 各占 1 字节，位宽 9 占 2 字节。预计算在节点加入时算好字节下标与偏移，查询时直接使用，避免重复移位。

### 1.3 管理层在 4 个位置替换协议栈逻辑

管理层用弱符号覆盖版本 4 选路与版本 6 选路，协议栈调用选路时实际进入管理实现。网关钩子在地址解析需要网关而管理实现必须兜底时触发，正常情况下不应当触发，触发即表示覆盖有误或协议栈新增了调用点。默认路由与默认网关的关系在源文件第 55 行到第 60 行阐明：默认网关是下一跳地址，默认路由是前缀长度为 0 的条目，两者配合实现全网可达。这种覆盖加钩子的做法在操作系统中很常见：Linux 内核同样允许路由子系统覆盖默认选路，Redox 系统把选路实现为可替换的路由表服务，思路一致：机制可插拔，策略集中管。

### 1.4 本章小结

路由管理解决三件事：前缀假设把掩码变成整数，三个公式提供坐标系，4 个位置完成协议栈替换。下一章进入 C 语言源码的逐项验证，确认每个公式与每个位置都有源码依据。

## 3. Rust 设计决策

> 本章解释每个设计选择的原因，先给出依据，再列出考虑过的替代方案与放弃理由。

### 3.1 位映射采用三个纯函数（依据：第 1.2 节、第 2.2 节）

字节下标、字节内偏移、位宽占字节数各有一个函数。替代方案是调用者手写移位。放弃的理由是手写移位容易写错方向，而函数名表达了语义，测试逐个断言边界。

### 3.2 前缀合法性按版本分开（依据：第 1.1 节、第 2.2 节）

版本 4 上限 32，版本 6 上限 128，各有一个函数。替代方案是共用一个上限 128。放弃的理由是共用会误接受版本 4 的 33 到 128，改变原始语义。

### 3.3 存储与覆盖不建模（依据：第 1.1 节、第 1.3 节、第 2.3 节）

树节点、路由条目、弱符号覆盖需要服务与链接环境。替代方案是完整建模。放弃的理由是脱离服务与链接谈覆盖没有意义，与缓存不建模的理由相同。

### 3.4 设计决策汇总

| 决策 | 依据章节 | 考虑过的替代方案 | 放弃理由 |
|------|----------|------------------|----------|
| 位映射三函数 | 第 1.2 节、第 2.2 节 | 调用者手写移位 | 易写错方向 |
| 前缀按版本分开 | 第 1.1 节、第 2.2 节 | 共用上限 128 | 误接受非法前缀 |
| 存储覆盖不建模 | 第 1.1 节、第 2.3 节 | 完整建模 | 脱离环境无意义 |
