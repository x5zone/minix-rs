## 1. 概念：一次系统调用走主路径，两种错误才回退

### 1.0 本章的读者与阅读方法

本章假设读者知道系统调用是用户态进入内核的唯一方式，不需要了解虚拟文件系统的内部转发。本章只需要带着三个问题来读：15 个调用有哪些，主路径的消息长什么样，回退在什么条件下触发。读完本章，读者应当能够说出 15 个调用的名称，3 个标志位的映射关系，以及回退的两个触发错误，即使遮住所有函数名字也不影响理解。

### 1.1 主路径是构造消息后一次陷入

每个调用先把域、类型、协议等参数装入消息结构，再执行一次到文件系统进程的系统调用，由文件系统转发到对应的套接字驱动。以创建为例：清零消息，填入域类型协议，陷入后直接返回结果，成功即得到文件描述符，失败即设置错误码。这种薄封装的意义在于策略集中：用户库不做任何协议判断，所有判断留给服务端，库只负责搬运参数。Linux 的系统调用封装同样是薄层，Redox 系统把用户库实现为构造消息加一次陷入，思路一致。

### 1.2 类型标志按位映射到打开标志

套接字类型中除去协议类型部分的 3 个标志位逐位映射：关闭时执行映射到打开时关闭执行，非阻塞映射到打开时非阻塞，屏蔽管道破裂信号映射到打开时屏蔽。映射是按位独立的，组合自动成立：三位全置即三位全映射，无位即无映射。这种逐位映射的意义在于正交：三个选项互不干扰，测试只需要覆盖 8 种组合中的代表即可验证。

### 1.3 旧式回退只在两种错误下触发，重写后丢弃

仅当文件系统返回族不支持或功能未实现时，封装才回退到打开旧式设备节点并使用旧设备协议。其它错误直接返回，不回退。旧式协议是上一代网络服务的遗留，设备节点与请求码都属于历史包袱。[ARCH N-2]：重写后丢弃回退，文件系统路径是唯一路径。本模块用一个纯函数记录旧分支条件，恒返回假的反面即新行为：永远不回退。保留该函数的意义在于可审查：后人搜索回退即可找到决策点，确认丢弃是有意的而不是遗漏。

### 1.4 本章小结

用户态封装解决三件事：15 个调用的主路径形状，3 个标志位的逐位映射，两种错误触发回退而重写后丢弃。下一章进入 C 语言源码的逐项验证，确认每个分支都有源码依据。

## 3. Rust 设计决策

> 本章解释每个设计选择的原因，先给出依据，再列出考虑过的替代方案与放弃理由。

### 3.1 调用清单采用十五变体枚举（依据：第 1.1 节、第 2.1 节）

15 个调用各为一个变体，顺序与源码一致。替代方案是用字符串名字。放弃的理由是字符串无法穷举检查，新增调用时编译器不会提醒补分支。

### 3.2 标志映射采用逐位累加（依据：第 1.2 节、第 2.2 节）

三位各自判断后累加。替代方案是查表映射。放弃的理由是三位正交，查表需要 8 行而逐位只需 3 个分支，且组合语义更清晰。

### 3.3 回退条件保留为纯函数（依据：第 1.3 节、第 2.2 节）

失败加两种错误即回退。替代方案是删除该函数。放弃的理由是删除后丢弃决策无处可查，保留函数让 [ARCH N-2] 有明确的审查锚点。

### 3.4 设计决策汇总

| 决策 | 依据章节 | 考虑过的替代方案 | 放弃理由 |
|------|----------|------------------|----------|
| 调用枚举 | 第 1.1 节、第 2.1 节 | 字符串名字 | 无穷举检查 |
| 标志逐位累加 | 第 1.2 节、第 2.2 节 | 查表映射 | 组合语义不清 |
| 回退条件保留 | 第 1.3 节、第 2.2 节 | 删除函数 | 决策无处可查 |

## 4. 错误处理

| 场景 | C 语言行为 | Rust 表达 | 说明 |
|------|------------|-----------|------|
| 主路径成功 | 返回描述符 | 调用者返回结果 | 成功不回退 |
| 主路径失败非两种错误 | 返回错误 | 回退函数返回假 | 不回退 |
| 主路径失败为两种错误 | 旧代码回退，新行为返回错误 | 回退函数返回真，调用者忽略并返回错误 | [ARCH N-2] 丢弃 |
| 类型标志含未知位 | 忽略未知位 | 映射函数只认三位 | 未知位不映射 |
