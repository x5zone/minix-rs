发现与修法：

| ID | 严重度 | 问题 | 修法 |
|---|---|---|---|
| R1-01 | P1 | 只检查最后一个 full 轮的 trajectory；早先确认轮缺复核也能继续 | `begin-confirmation` 检查上一轮；`gate` 检查 `1..round` 全部轮次 |
| R1-02 | P1 | 第二次确认轮可以零逐单元 `confirm-review` 通过 | 要求当前 `confirmation.round` 同时出现在每个单元的 `review_rounds` 与 `post_freeze_rounds` |
| R1-03 | P1 | trajectory 的 FAIL 可被无理由覆盖为 PASS | FAIL→PASS 必须 `--reason`；已有 PASS 拒绝重复；记录 `supersedes` |
| R1-04 | P1 | 证据只绑 `UNIT`，不绑文档账户；D01 的 D-114 可被 D02 引用 | 增加 `DOC <doc>` 绑定；解析 `DECISIONS.md` 的 scope，跨篇引用 doc 级裁决直接拒绝 |
| R1-05 | P2 | `new-edition` 不带 `--unfreeze-all` 会留下“冻结但零 review”的非法状态 | 新 edition 强制 `--unfreeze-all` |
| R1-06 | P1 | 冻结后改正文再 `sync --unfreeze`，旧确认仍有效 | 解冻/正文变化时清空该单元 `review_rounds` 与 `post_freeze_rounds` |
| R1-07 | P1 | 复制状态 YAML 可让 D02 继承 D01 的 full 轮 | `load_state_for` 校验 `doc` 字段，串篇即拒绝 |
| R1-08 | P1 | 同一 full evidence 写两条 `DOC` 可给两篇背书 | evidence 必须恰好一条 `DOC` 且匹配当前篇 |
| R1-09 | P1 | 同一 trajectory evidence 可满足 R1/R2 | 只许点名当前轮；同一 evidence hash 不得复用 |
| R1-10 | P1 | 确认轮 active 时再次 begin 会推进轮次 | active 时直接 FAIL |

- trajectory 先 FAIL 后 PASS 无 `--reason` → 拒绝；
- D-114 用于第二篇账户 → 拒绝；
- 确认轮 active 时重复 begin → 拒绝；
- 正常 2 full + 逐单元 review + 3 次 trajectory → 接受。

## 最终判定

**PASS**。V3.11 的五个硬约束均有机械检测器与负例：

1. 每篇独立账户（`DOC` + 状态文件按 doc 定位；D-114 跨篇拒绝）；
2. 每篇至少 2 个 full 轮（full evidence 覆盖全部单元，重复 evidence 拒绝）；
3. 每单元至少 2 次 review（冻结前 pass + 冻结后 confirm-review；当前确认轮必须逐单元记录）；
4. 每轮 trajectory review（`1..round` 全查；FAIL 改判需 reason）；
5. 历史重置（旧 run/state 归档；新账户 round=0、full=0、review=0）。
