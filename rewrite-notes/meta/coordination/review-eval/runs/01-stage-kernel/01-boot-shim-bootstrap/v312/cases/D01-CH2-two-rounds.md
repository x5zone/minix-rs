## 二、根因判断

1. **体裁与 rubric 的张力**：Ch2 是 953 行 C 走读，含大量判例/源码锚点；六视角（尤其 editor/reference）按“线性教程”判，主线只占约 55%，其余是判例盒。两遍读是本章的实际阅读方式，但六视角 brief 没有“主线 + 判例盒”的输入约定。
2. **结构已修但指针卫生未清**：2.5/2.5.1 顺序已解决 Reader-B 的因果倒置；剩余多为“上表/本节末/见上段”这类可机械修的指针，以及术语两套口径。
3. **重复修复成本高**：每改一轮都换哈希，六视角全部失效；agent 又多次误读旧切片，导致证据链反复。继续无限重写会违反 §12。

## 三、候选方案

### A. 结构拆分：主线章 + 参考伴生篇
- 把 Ch2 拆成 300–400 行主线（C 行为、判据、锚点）与一份参考伴生篇（判例盒、深推演、源码摘录）。
- 优点：主线可线性读，六视角容易过；C 深度保留。
- 成本：新增文档、锚点/单元/摘要全部重做；需作者批准“新增伴生篇”；违反“不先创建 mainline 伴生篇”的旧裁决，需新案件卷授权。

### B. 重写 Ch2 为 400–500 行 C 行为叙述
- 删/移深判例到 Ch3/Ch4 或附录，只留 C 行为表、D1–D5、锚点。
- 优点：一章一读，六视角成本低。
- 成本：丢失当前 C 走读的证据密度；Ch3/Ch4 需接收内容；等于重写一章。

### C. 保留 Ch2 为参考章，给六视角加“主线 + 判例盒”阅读约定
- 在 §2.0 加 5–6 行路线图（主线 2.1→2.3→2.4.1→2.5→2.6→2.8；判例盒 2.4.2.3/2.5.1 第二遍读）；把 2.4.2.3/2.5.1 标为“判例盒”；修完剩余指针/术语后重跑 editor/reference/Reader-B/G18/beginner。
- 优点：不动结构，保留 C 深度；成本最低；符合“Ch2 是 C 源码分析”的章契约。
- 成本：这是对六视角判据的局部调整（reference/editor 接受“两遍读”），需要 workflow 回归与 meta-review 追认；若作者认为六视角必须线性通读，则 C 不成立。
