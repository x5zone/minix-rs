1. L35 "跳转时两个寄存器各放一个魔术值" 与紧随的表格（L39 `MULTIBOOT_HEADER_MAGIC` 由引导器扫镜像前 8KB，方向内核→引导器）及 L86-87 的 `push %ebx /* info struct */` 冲突：跳转时 %eax 是 `MULTIBOOT_INFO_MAGIC`，%ebx 是 `multiboot_info` 地址，镜像头魔术值不在寄存器里。读者在契约入口得到两个互斥的交接模型，必须先自行纠正才能继续读表。

2. L118 "整份拷贝只是第一层，按值交付要三层都完成"（L13 亦作"三层按值复制"）与 L120 的枚举（命令行、模块表、内存图三项）及 L397 "整份拷贝 `mbi`、命令行、模块表与内存图复制" 对不上：加上第一层共四步，正文从未指明"三层"是哪三层；且 L122 把"三层都完成"当作 I1 成立条件，而内存图若不转换，`mbi.mmap_addr` 仍指向引导器内存。读者无法把本章唯一的核心判断落到具体步骤。

3. L342 "同一段引导准备在 x86 与 ARM 两侧各有一份实现" 与 L356 "这一整串不需要第二份实现——差异被挡在入口这一层" 直接冲突；L356 下一句自己引用 `earm/pre_init.c:get_parameters`，L358 又给出 `earm/pre_init.c:overlaps` 的闭区间差异（下游差异，不在入口层）。读者无法确定本节结论是"共用一套"还是"各写一份"，也无法接受"差异只在入口层"。
