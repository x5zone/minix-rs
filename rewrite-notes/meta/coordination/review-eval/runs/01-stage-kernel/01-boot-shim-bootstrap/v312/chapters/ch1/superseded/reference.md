## 方法与边界

本轮是 Ch1 章级参考读者的第三轮、最终切片重跑（切片 82 行、5,869 字节）。输入只有本章切片与章契约 `01-outline.v6.md`；本章是首章，没有上一章一页回顾可依托，冷启动只能靠 1.0 的问题入口与前置概念。契约把 Ch1 限定为五项：问题入口、三类数据、四条通用不变量、接缝、范围；具体载荷类型、协议与字段留给 Ch3；本章也不允许出现项目类型名、协议名、字段表、容量数字、Rust 标识符与围栏代码块。切片实际没有围栏代码块，也没有契约列出的禁用标识符。因此参考读者不应在本章找命令、代码示例或字段速查；本章的可查项是概念、问法与边界。

抽查方法：先随机取节，再在节内随机取行，共 15 个落点；每个落点只带一个查阅问题，只看能否在合理跳转内答出，不判断答案在 Minix3 或实现中是否成立。抽查顺序是随机的，下表按节序排列，便于对照。下文「一跳」指一次定位跳转，可以是同节内、跨节或跳到章契约；全部行号指最终切片。

## 二、必须回读前文的节

本章没有上一章；这里的「前文」指本章更早的小节。

- 1.3（第 48 行）：同一节里有两套四短语。第一句是「数据收集、来源记录、所有权与校验」，接缝句是「数据按值、可追溯、有所有者、先校验后使用」。两套都不带 I 编号，第一套的「数据收集」在四条不变量里没有同名条目；从这节进入的读者要回 1.2 表才能对号。四条不变量在 1.2 表、1.3 的接缝句、最小示例、小结都有转述，只有 1.2 表与最小示例带编号。
- 失败对照（第 44 行）：整段用「只把指向发送侧地址空间的指针交给接收方」暗指 I1，却不写 I1；要挂到编号得回 1.2 表第 35 行。
- 小结（第 69–71 行）：三条分别是 1.1、1.2、1.3 的压缩转述，不带节号；展开任何一条都要回读对应节。第三条「指针不能跨边界，内容可以复制」是 I1 的转述，同样不带编号。
- 术语「消费」（第 80 行）：与 I4「校验先于消费」的从属关系要回 1.2 第 38、40 行才看得出；术语表只给「第一次使用」。
- 1.4（第 52 行）的「镜像篇」「内存管理与服务篇」「各架构启动篇」：这不是回读能解决的，前文没有映射；列入第三节第 1 条。
- 自足的反例：1.3 接缝句（第 48 行）单独看就能知道本篇与镜像篇各保证什么；1.4（第 52 行）单独看也能知道本章不覆盖哪些内容。参考读者从这两处进入是安全的，代价是出站篇名不可解析。

## 三、缺失的速查项

1. 出站篇名不可解析。1.3 与 1.4 的「镜像篇」「内存管理与服务篇」「各架构启动篇」没有文档名与章号；契约的 Ch2–Ch6 标题不能直接映射这三个篇名。同一出口还有命名漂移：1.3 叫「三种目标架构的启动篇」，1.4 叫「各架构启动篇」，读者无法确认是不是同一篇。本章是首章，没有上一章一页回顾可补这个映射。参考读者按「镜像篇」查不到下一站。
2. 术语表没有 I1–I4 条目。契约把「四条通用不变量」列为 Ch1→Ch3 的导出接口，编号是本章最该被索引的键，却只存在于 1.2 表与最小示例；术语表与 1.2 表还是两套说法（「按值交付」对应 I1、「提交」对应 I3、「消费」对应 I4），没有互指，按术语查与按编号查互不对应。
3. 术语表缺正文实际用到的操作名与环境名。操作名：建表（第 10、23、24、38 行）、镜像摆放校验（第 24 行）、物理页分配（第 23 行）、启动服务（第 10 行）、换栈进入（第 52 行）；环境名：固件（第 10、23、48、52 行）、高半（第 14、48 行）。其中「高半」第 14 行有内联解释，「建表」「固件」对十年 OS 工程师是常识，严重度低；「镜像摆放校验」「换栈进入」是项目动作名，章内无定义也无指针，严重度高。
4. 三类数据没有编号或简称。1.1 末段用「前两类」「第三类」，小结用「三类数据」并重列三个名字；读者想引用「第三类」要回 1.1 表逐行数。契约也只说「三类数据」，没有再给编号。
5. 1.1 表的「谁需要它」列答的是动作，不是角色。「建表、物理页分配」「建表、镜像摆放校验」「启动入口、校验」混用动作与位置；读者按表头问「谁需要」时，得到的不是组件名。表仍可用来判断用途，但不能直接回答消费者是谁。
6. 1.2 表的 I4 行不自足。表行只给「三项确认」的内容，不给三项与 I1–I3 的对应；对应关系在第 40 行。按表速查 I4 时，读者知道要检查什么，但不知道 I4 是 I1、I2、I3 的汇总检查。

## 四、结构对查阅的影响

- 标题层级清楚：1.0 导读 → 1.1 数据 → 1.2 不变量 → 1.3 接缝 → 1.4 范围 → 1.5 回顾。参考读者按标题就能落到目标节；1.5 把小节与术语放在章尾，符合手册用法。
- 两张表是速查骨架。1.1 表的列是「数据 / 回答什么问题 / 谁需要它」，1.2 表的列是「编号 / 概念级不变量 / 可检查的问法 / 破坏后的现象」。两张表都不需要回读正文就能用，这是本章最强的部分。1.2 表尤其好：编号列可直接定位，问法列可直接验收。
- 契约的 Ch1 节序是五项（问题入口、三类数据、四条不变量、接缝、范围），切片多出 1.5 本章回顾；1.5 只复述前文，不引入新知识点，对参考读者是加分项，也让本章在章尾有一个集中速查块。
- 最小示例（第 60–63 行）与 1.2 表功能重叠：前者是四问的验收清单，后者是四问的释义表。对参考读者是双入口，不是冗余；但两处需要同步维护，任何一处改动都要检查另一处。
- 1.3 与 1.4 重叠。1.3 给接缝句并列出三个后续篇名；1.4 再说一遍三个篇名并补具体的不覆盖项。两节相邻，读者为同一个「下一站在哪」的问题要看两处，而两处都没有章号。重复没有带来新的可查信息。
- 指针密度失衡。可解析的「见第三章」只有一处（第 31 行），不可解析的三个篇名却在 1.3、1.4 各出现一次；真正需要落地的出口却一个都不可解析。
- 本章没有上一章可依托，1.0 的问题入口与前置概念承担冷启动；这两小节足够让读者知道本章不要求载荷细节，在只有切片与契约的情况下成立。1.0 的问题入口是一整段 173 字的叙述，不是列表；作为「本章讲什么」的入口够用，作为「有哪些可查项」的索引偏弱。
- 当前 82 行的章没有目录也能用；若后续扩到数百行，1.5 的三个四级小节（最小示例、小结、术语）需要进目录，否则「小结/术语」仍要翻到章尾才能发现。当前翻到章尾的成本很小。
- 「失败对照」是 1.2 下的四级标题，不带编号；在目录里会是一个无编号子项。当前长度下不影响发现，但按编号引用「1.2 的失败对照」时没有正式编号，只能描述位置。

## 五、判定

十五个落点里八个直接命中（七个零跳转，一个一跳靠契约补标题），一个半命中，两个需回读，四个查不到。四个查不到集中在两类：术语表覆盖不全（镜像摆放校验、换栈进入、建表、固件；高半有内联解释）与出站篇名不可解析（1.3/1.4 的镜像篇、内存管理与服务篇、各架构启动篇）；术语表另缺 I 编号条目，但 1.2 表的编号列可代偿。本章 82 行，回读 1.2 的实际成本就是回看一段；契约又把本章限定为概念章，具体载荷留给 Ch3，因此载荷细节不在本章不是缺口。两张表加四问清单在零跳转或一跳内可用，单章内当参考手册用成立，判定 READABLE。

会翻成 NOT-READABLE 的条件写明：1.3/1.4 的篇名继续不给文档名与章号，同时章长明显超过当前规模（当前 82 行）；或者 1.2 表被移走或拆散，而术语表仍不收录 I1–I4。那时「镜像篇指什么」「I3 是哪条」会从个别缺口升级为系统性缺口。术语表的操作名缺项单独不足以推翻判定，因为 1.2 表与正文内联解释还能代偿；但「镜像摆放校验」「换栈进入」这类项目动作名如果在下游章节被频繁引用，应在本章补一句定义或指针。

本报告不判断事实：1.1 对 Minix3 引导交接的归类是否准确、1.2 四条不变量是否覆盖真实失败面、1.3 的接缝划分是否符合项目实际，均不在射程。
