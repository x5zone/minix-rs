## 4. 入口导航

强的部分：

- L7 的入口不是抽象定义，而是一个具体坏法：内核按引导器给的地址读内存图，读到的却是自己地址空间里一段无关内容，不报错，只有错的数据。这给读者一个「为什么必须处理交接」的现场。
- L11–L14 的前置概念短而诚实：只要求「引导器交控制权」「固件留下平台数据」、物理/虚拟地址与地址映射、页错误；明确说「本章不要求知道具体载荷类型、协议或字段」。L11 还把「高半」指向 §1.6 术语，这是正确的预告方式。
- L7 的路线句给出了章节顺序：先三类数据（§1.1），再四条不变量（§1.2），再用数值示例检验（§1.5）。读者知道主线在哪。

缺陷：

- N1（中）：L7 的路线句漏掉 §1.3；L63 的「本章的主干」同样只提 §1.1、§1.2、§1.5、小结与术语。scope S1 明确要求「能说出本篇与后续镜像篇的接缝」，而接缝的对手篇直到小结 L106 才点名。按 L7 的路线字面读，读者会 1.1→1.2→1.5→1.6，第一次看到接缝要等到小结。标题 L55 仍然可见，所以不是 NOT-READABLE；但入口路线是读者最先相信的地图，漏掉一个 scope 要求的节，应在冻结前修。
- N1 的次要点：L7 先连问三件（哪些必须带走、哪些只在引导器那边短暂有效、带错了会在哪一步坏掉），紧接着说「本章要回答两个问题」。数量从三跳到二，读者需要自己判断哪两个是正式的。建议写成「两个核心问题」或不写数量。
- O4（可选）：L73 是 §1.5 的首段，内容是区间记法，不是「这一节要示范什么」。目的由标题「四问走两遍」和 L7 路线承担，地图仍成立；若要让首段自报主题，可在 L73 前加一句「这一节用一组区间把 I1–I4 走两遍」。
