## 导航判定

### 1. 标题与首段能否建立本章地图

PASS。章标题“概述”本身不承载信息，但 `1.0` 的问题入口在 L7 先给失败场景（按引导器给的地址读内存图，读到无关内容且不报错），再给两个待答问题，最后给出节序图：“先定三类数据（第 1.1 节），再给四条通用不变量（第 1.2 节），然后用数值示例检验交接是否成立（第 1.5 节）”。读者在第一屏就能拿到“问题 → 概念 → 验证”的主线。

节标题普遍是内容句而非标签，扫一遍目录即可判断各节用途：`1.1 内核接手时拿到什么`、`1.2 四条通用不变量`、`1.5 最小示例：四问走两遍`、`1.6 本章回顾`。`1.2` 的子标题“失败对照：以 I1 为例”（L49）明确限定只展开一条，不会让读者期待四条都展开。

### 2. 节序能否建立依赖、能否跳读

PASS。按首段读出的依赖关系如下：

| 节 | 首段交代的职责 | 依赖 | 可否跳读 |

| 1.0 | 失败场景、两个问题、节序图 | 无 | 否，入口 |
| 1.1 | 定义发送侧/接收方，给出三类数据 | 1.0 | 否，主线起点 |

主线 `1.1 → 1.2 → 1.5 → 1.6` 被 L7 显式标出，跳读 1.3、1.4 不会断链。1.3 与 1.4 都是边界说明，放在主线中段会短暂打断“三类数据 → 四条不变量 → 示例”的节奏，但两节各自首段能自说明，不构成迷路。

### 3. 有没有孤儿概念

基本没有。标题与首段出现的概念都能在章内找到落点：

- `内存图` 在 L24 表内就地解释“区间清单”；`镜像的位置` 同表；`I1–I4` 在 L34 表内定义；`高半` 在 L59 有括号释义并指向 §1.6 术语；`失败面` 在 L32 的句子里已可理解，L131 术语表再定义。
- 两处属于“先用后定义”，但都有章末术语兜底，不构成真正孤儿：`交接` 在 L7 首次出现，定义在 L114；`接缝` 在 L55 标题首次出现，定义在 L133（`承重接缝`）。见发现 Nav-3、Nav-4。

### 4. 章末结论是否清楚

PASS。L102 先给能力句（能对一份交接数据逐条回答四问并说出根因），L104–L108 给五条小结，L108 还给一道带答案的自检题，L110 用一句“下一章从 C 侧看引导器怎样把这些数据交进内核”完成向下交接。读者读完知道本章留下了什么、下一步去哪里。

### 5. 章节入口与接缝是否可导航

PASS，有一处悬空指针。

- 入口：L7 的失败场景 + 两个问题 + 节序图，足够。
- 向后接缝：L59 一句“本篇保证数据按值、可追溯、有唯一所有者、先校验后使用，镜像篇保证这些数据在进入高半后仍可被访问”，是全章唯一承重接缝，L106 小结再次复述，前后一致。
- 向下接缝：L110 指向下一章 C 侧，明确。
- 不写内容的去向：L65–L69 五条中四条指向具体章（第 3 章、第 2 章、镜像篇、设计与实现章节），第五条 `L68` 的“对应的架构启动篇”没有篇名或章号，读者无法从本章跳到那里。见 Nav-2。
