## 一、标题与首段能否建立本章地图

能。章标题「概述」是泛称，单看标题不知道本章讲什么；1.0 的问题入口把场景与路线一次说全：内核从固件和引导器手里接过一小堆数据，本章先讲这次交接的问题形状，即需要哪几类数据、为什么不能直接共享地址，再从数据形状入手，给出四条通用不变量与边界，把「交接成立」变成可以检查的条件（`ch1.md:10`）。六个节标题按「入口、数据、不变量、接缝、范围、回顾」排列，各节开头逐节兑现标题承诺（1.5 由三个子块承担）。

| 节 | 标题承诺 | 首段兑现情况 |
|---|---|---|
| 1.0 本章导读 | 问题入口与前置概念 | 兑现。首段给出交接场景与全章路线；前置概念就地解释「高半」（`ch1.md:10`、`ch1.md:14`） |

两处摩擦影响地图精度，都不致命。

第一处是路线句里的动作名没有落点。`ch1.md:10` 说内核需要数据才能开始「建表、映射和启动服务」，但 1.1 首段只承诺「三类」数据，1.3 与 1.4 首段给的是篇级归属，不是动作到篇的映射。读者按路线句找过去，会在 1.1 只拿到数据分类，在 1.3 和 1.4 只拿到「不归本篇」的清单；「映射」与「启动服务」在标题和首段里始终没有可见归宿。修法二选一：在 1.0 加一个短括注，说明这些动作分别归后续哪一篇；或把「映射」「启动服务」从路线句里删掉，不承诺本章不讲的动作用途。

第二处是 1.3 与 1.4 在目录上像同一件事。两节相邻，标题一个说「接缝」一个说「范围」，首段都在说「不是本篇」。功能上可以区分：1.3 说责任分界在哪，并给出一句「本篇保证……镜像篇保证……」的合同（`ch1.md:48`）；1.4 说本章不写哪些机制，列得更细（`ch1.md:52`）。但标题没有把这层区别说出来，跳读者会以为其中一节是重复。建议让 1.4 标题直接写出「不写什么」，或在 1.4 首段回指 1.3，表明自己是明细而不是重复。

另有一处半拍错位，不构成障碍：路线句先说「为什么不能直接共享地址」，再说「先从数据形状入手，再给出四条不变量与边界」（`ch1.md:10`）；目录上地址问题落在 1.2 的 I1 与失败对照里，不是独立小节。因为句子后半句已经把「先数据、后不变量」的顺序说回来了，读者不会真的走错；若要完全对齐，可把「为什么不能直接共享地址」并进 1.2 的承诺。

## 二、节序是否可跳读

- 1.0 不可跳。它是入口，定义了「高半」，也给出了全章路线（`ch1.md:10`、`ch1.md:14`）。
- 1.1 不可跳。三类数据是后文一切指代的容器，小结第一条就是它们的复述（`ch1.md:69`）。
- 1.2 不可跳。四条不变量是本章主干；小结第二条与最小示例四问都回指这四条（`ch1.md:70`、`ch1.md:60-63`）。
- 1.3 可跳，代价低。跳过它，1.4 首段与术语「接缝」仍能独立读懂；失去的是那句「本篇保证……镜像篇保证……」的接缝合同（`ch1.md:48`），而这是全章边界最凝练的一句。低代价不等于零代价。
- 1.4 可跳，代价几乎为零。它把 1.3 的三个下游归属再列一遍，只是更细；读完 1.3 的读者可以跳过。两节同时跳也不影响主线 1.0 到 1.1 到 1.2 再到 1.5。
- 1.5 不可跳。最小示例是四条不变量的可操作形式，小结是章末结论，术语是回查入口（`ch1.md:56-81`）。

过渡方面，1.2 到 1.3 没有路标句，读者从「不变量」直接落到「本篇覆盖什么」，需要自己意识到章节在收束；因为 1.3 本来就是出口段，这不构成障碍。1.3 到 1.4 的问题不是缺路标，而是两节内容重叠，已在第一节说明。

节序总评：主线四节（1.0、1.1、1.2、1.5）顺序合理；边界两节（1.3、1.4）可以合并，或至少让 1.4 明确自己是 1.3 的「不写什么」明细。

## 三、有没有孤儿概念

按「在标题、首段或小结里出现，却没有可见归宿」的标准，本轮剩三处轻度问题。

- 「建表、映射和启动服务」（`ch1.md:10`）：标题与首段只回答「哪三类数据」，不回答这些动作用在哪；1.3 与 1.4 给的是篇级归属，不是动作到篇的映射。「映射」「启动服务」尤其没有落点。建议同第一节的修法：加短括注，或删掉本章不承诺的动作名。
- 指路体系有两套：「第三章」（`ch1.md:31`）与「镜像篇、内存管理与服务篇、各架构启动篇」（`ch1.md:48`、`ch1.md:52`）。切片里没有一句话说明两套指路的关系。对第一次读这本书的人，「第三章」是不是就是「镜像篇」无法从本章判断。建议在 1.3 或术语表用一行说明「第 N 章指本篇内部，X 篇指同阶段其他文档」。
- 「按值交付」（`ch1.md:78`）与 1.3 首段的「数据按值」（`ch1.md:48`）、小结的「内容可以复制」（`ch1.md:71`）三处措辞不同。概念能对上，但按术语表回查的读者要多做一次映射。建议让 1.1 或 1.2 首段正式用一次「按值交付」，或把术语条目改成与小结一致的措辞。

有明确归宿的概念：

- 「高半」在前置概念里就地解释为「内核运行所在的高地址虚拟区间」（`ch1.md:14`），有定义、有归属。
- 「接缝」在 1.3 标题与术语表之间都有落点（`ch1.md:46`、`ch1.md:81`），归宿完整。
- 「可用内存的图」在小结与术语表两处写法一致（`ch1.md:69`、`ch1.md:75`），没有书写漂移。
- 「三种目标架构」（`ch1.md:48`、`ch1.md:52`）是本章边界声明的一部分，本章不展开架构名，不算孤儿。

一处轻度地图盲区，不计为孤儿：「提交」与「消费」在术语表有定义（`ch1.md:79-80`），但标题与首段没有显示它们落在 1.2；从首段建图的读者要到术语表才知道这两个词属于本章。术语表本身就是归宿，所以不构成孤儿；若希望地图直达，可在 1.2 首段点出这两个词会在本节解释。

## 四、章末结论是否清楚

内容上清楚。小结三条逐条覆盖本章的三件交付物：三类数据（对应 1.1）、四条不变量防范的四类失败（对应 1.2）、指针与内容的取舍以及「载荷细节不在本章展开」（对应 1.2 的失败对照与 1.3、1.4 的边界）。三条都没有引入新概念，也没有把正文没说过的话塞进结论。只读小结的人能说出本章立住了什么。

结构上，`1.5 本章回顾` 现在是独立的 `###`，三个子块（最小示例、小结、术语）都服务于章末回顾；失败对照已归入 1.2 的 `####`（`ch1.md:42`），不再由「回顾」承载第一次解释，标题与内容相符。

剩下两点是位置与自足性。第一，小结最后一条说「载荷细节不在本章展开」（`ch1.md:71`），但没有说去哪里找；「见第三章」只出现在 1.2 首段（`ch1.md:31`）。若希望小结自足，可在第三条补「见第三章」。第二，小结是 1.5 的第二个 `####`，后面还有术语；读者跳到章末最后一块会落在术语而不是结论。术语收尾符合惯例，不算缺陷；若希望结论是读者最后看到的东西，可以把小结移到术语之后。

## 五、结论

判 READABLE。三件事成立：从标题与首段能搭出完整的六节地图；主线四节不可跳、边界两节可跳且代价明确；章末小结能独立复述本章交付物。本章是全书入口，由 1.0 承担入口职能，没有上一章回顾也不构成缺口。

建议在冻结前处理的三条，按优先级：

1. 路线句里的动作名没有落点（`ch1.md:10`）。加一个短括注说明「建表、映射、启动服务」各归哪篇，或删掉本章不承诺的动作名。成本最低。
2. 1.3 与 1.4 的边界声明重叠（`ch1.md:48`、`ch1.md:52`）。合并成一节，或让 1.4 明确是 1.3 的「不写什么」明细表。
3. 小结最后一条不指向下一章（`ch1.md:71`）。补「见第三章」，或把小结移到术语之后，让结论收尾。

以上三条都不构成重读级障碍，所以不改变 READABLE 判定。
