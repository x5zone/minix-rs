## 结构重建（读者 B 的独立读法）

我把全文读成一条单轴、六段式的论证：

1. **问题与判据（§1）**：内核接手时要带走三份数据（可用内存清单、内核位置记录、交接结构）；I1–I4 是四个失败面；D1–D5 是五条次序约束。
2. **C 基线（§2）**：multiboot 契约 → `head.S` 入口 → `get_parameters` → `add_memmap`/`cut_memmap` → `overlaps`/`kern_mod` → 模块检查 → ARM32 对照 → 交付物形状。
3. **Rust 设计（§3）**：协议换代 → `KernelInfo`/wire → 两张表与 `SourceRecord` → bootstrap 区间与分配器换手 → 取件抽象与依赖方向 → 五条生产腿 → 所有权与门链。
4. **实现（§4）**：UEFI 入口与九动作 → 描述符分类 → 共用取件 → `BootReport`/`KernelInfo` 构造 → 六个落地区 → allocator/arena 落地 → C 函数对照 → Direct Map 概念入口。
5. **证据与诊断（§5–§6）**：I1–I4 证据矩阵 → 宿主边界 → 机制证明 → 真机门链 → 未闭环项；EBS 分界/路标 → panic 路径 → 失败模式 → 命令。
6. **参见（§7）**：前置后续、C/Rust 源码清单、构建入口、符号速查。

**结构强度**：每章都有问题入口（章首段）与导读；关键计数都有"唯一权威"表（§3.1.1 接线、§3.6 计数、§4.4.1 门链、§4.5 容量、§5.1 证据）；对不确定结论普遍加了"观测常态/未证明"限定；I1–I4 在 §1、§3、§5 形成"定义—设计—证据"的闭环。

**结构风险**：同一事实有多个完整入口（S01）；导读的术语块放在小结/失败对照之后（S02）；编号体系多且局部口径冲突（S08/S09）；设计章与实现章的边界在多处互相渗透（S04）；设计史叙事混入正文（S13）。
