## 我重建的结构

按本章自己的依赖声明重建（不是按 outline 的编号重排），依赖链是：

1. **交接面（2.1）**：引导器与内核靠识别头、寄存器约定、`mbi`、`boot.cfg` 指令次序对接。没有这一层，后面不知道“谁给了什么”。
2. **入口（2.2）**：`head.S` 设临时栈、清帧指针、按 i386 调用约定把魔术值与 `mbi` 地址交给 `pre_init`。设栈是进入 C 的前提，所以必须先于任何收集。
3. **收集（2.3）**：`get_parameters` 整份拷贝 `mbi`；命令行逐词扫描 → `mb_set_param` → `param_buf`；模块表拷贝；链接期常量填 `bootstrap_*`/`vir_kern_start`。到这里“引导器的数据”变成“内核的记录”，但内存账还只有原材料。
4. **建账（2.4.1）**：细表/粗档 → `add_memmap`；`add_memmap`/`cut_memmap` 的取整、空槽与 `mmap_size` 语义。这里只建立“可用区间”的原材料。
5. **完成账（2.5）**：`overlaps` 逐条 sanity check；内核把自己登记为第 M+1 个模块；对每条记录 `cut_memmap` 切掉内核与模块占用。2.4.1 结算（494 行）说“到这里尚未切，框 1 要到 §2.5 的 `cut_memmap` 之后才完成”，2.5 末（698 行）说“框 1 才真正完成”——两处都要求把第 5 步放在任何“消费这份账”的内容之前。
6. **消费（2.4.2.1–2.4.2.3）**：`pg_alloc_page` 从最高下标取页、`alloc_lowest` 从最低处扫、两条取整规则、`alloc_lowest` 把长度当结束地址的判决。这些消费者运行在 `pre_init` 之后（612 行：“往后从这份账里取页的，是 `pre_init()` 之后的 4KB 细粒度映射路径与 VM 接手后的所有分配”），因此必须拿第 5 步完成后的账；2.4.2.3 前提一（599 行）还需要 `kmain → cstart → arch_init → smp_init` 的调用序。
7. **生命周期（2.4.2.4 + 2.5.1）**：切占用（`pre_init` 内）→ `arch_init` 两条 BIOS 切除 → `alloc_lowest` 跳板 → 还 VM 镜像（`arch_boot_proc`）→ 还引导段（`kmain` 后段）→ VM 接手时 16 条截断。这是同一份账的时间线，按时间应排成“切占用 → 加回 → 移交截断”。
8. **检查与对照（2.6、2.7）**：模块三层检查（次序、条数、区间）；ARM32 的同名入口与 `setup_mbi`。
9. **归纳与收尾（2.8 + 四个 `####`）**：`pre_init` 调用树、D1–D5 锚点、I1–I4 对回；失败对照、最小示例、小结、术语。
