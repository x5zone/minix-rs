# 01 引导交接 · P-DESIGN 第一遍（round38）

## DESIGN-SUMMARY

C 侧真正要保证的语义是：引导器在跳转那一刻拥有它填的 `mbi`、模块表与命令行字节；内核一进 `pre_init` 就把 `mbi` 整份拷进自己的 unpaged 全局 `kinfo`，把模块表与命令行复制/解析成自己的记录，此后不再读引导器内存（`head.S:77` 调用、`main.c:128` 高半再深拷一次）。内存账的唯一所有者是 `kinfo.memmap` 加 `mem_high_phys`：`add_memmap` 只追加不排序，`cut_memmap` 只做页粒度减法，`pg_alloc_page` 与 `alloc_lowest` 是仅有的两个发放点，每一次改账都被全局布尔 `kernel_may_alloc` 挡着。账的改写只有三类入口：`pre_init` 建账并切掉内核与模块、`kmain` 在 VM 启动前把 bootstrap 段加回（`main.c:301`）、`bsp_finish_booting` 关闸（`main.c:105`）；模块字节的加回发生在装载启动进程时（§2.4.2），不在交接窗口内。失败路径没有恢复：魔术值、槽位上限、重叠、耗尽都在现场 assert/panic 停住，参数缓冲溢出则静默丢弃；绝不会带着半张账继续消费。并发边界很干净：构建期单 CPU、IF=0（`head.S:71-72` 的 `popf`），没有锁；SMP 起来后到 VM 接手前的改账都在 BKL 下、不许睡眠。

设计主张：把 C 的一次性全局副作用改成一条单向管线——借用的事实、字节 wire、自有的 `KernelInfo` 三种身份；跨度集合取代槽位数组；两个发放策略按地址而非下标定义；所有结构校验集中在建模之前；失败一律 `Result`，入口只停一次；并发窗口用所有权表达，不用全局布尔。

## DECISION 01

**决策问题**：交接数据有几种身份，下游可以消费哪一种？
**候选**：A 三种（借用事实 `BootFacts<'a>` / wire 字节 / 自有 `KernelInfo`）；B 两种（发送侧直接产自有结构，wire 只是其字节视图）；C 一种（全程同一结构，指针字段靠约定）。
**选择与理由**：A，且下游只认 `KernelInfo`。wire 只携带事实：内存条目与来源、模块名与物理区间、命令行字节、内核摆放声明；最终跨度表由接收侧推导。跨镜像只能传值，而把发送侧算好的账当输入会让接收侧校验变成装饰，还会让五条腿各写一遍推导。
**代价与边界**：接收侧多一次推导；wire 需要版本、总长、逐段边界与校验和；两个直核腿可跳过字节编码，但不能跳过同一个 `assemble` 与校验（统一消费次序）。
**与 C 语义对应**：`mbi` 整份深拷与 `module_list[]` 复制；`main.c:128` 的第二次拷贝是一个所有者的搬家。
**可测试性**：encode/decode 是 `&[u8]` 上的纯函数；截断、超长、坏校验和、声明长度与真实长度不符各有向量。

## DECISION 02

**决策问题**：谁拥有载荷，什么时候换手，如何保证只填一次？
**候选**：A 单一所有者线性换手（`BootFacts` → `assemble` → `KernelInfo` + `EarlyMemory`）；B 全局 statics 加 filled 标志，第二次填 panic；C `Arc<Mutex<...>>` 共享可写。
**选择与理由**：A。中间的账是 `assemble` 的私有局部量，失败即 drop，成功才构造输出；没有运行时 filled 标志。C 的 `BootStorage` 只是发送侧 arena，是实现细节，不配单独的类型身份。
**代价与边界**：部分构造不可观察，调试只能看最终快照；这正是要的。构造失败不能依赖堆分配的错误消息。
**与 C 语义对应**：`kinfo` 从 `.unpaged_bss` 副本换手到高半副本，旧副本此后只被读或回收。
**可测试性**：「半填状态不可构造」由类型保证，用编译失败用例固化；运行时测试只看 `Ok` 的完整快照与 `Err` 的无产出。

## DECISION 03

**决策问题**：内存账用什么数据形状，来源记录挂在哪？
**候选**：A 定长槽位数组，复刻空洞与扫描顺序；B 按地址有序的 `[Span; N]`，不合并；C `Vec`/`BTreeMap`（需要分配器）。
**选择与理由**：B。`Span { start, len, source: SourceId }`，恒有序、两两不交、允许相邻；来源随跨度走，切割只分裂不新建来源。C 的下标序不是地址序，把一个回收副产物当语义会把偶然变成不变量；有序集合让相交、包含、发放都退化成一次扫描。
**代价与边界**：插入要 O(N) 搬移（N 很小）；不合并会让相邻跨度保持多条，VM 交接按条数限额时会比 C 更早暴露——这是想要的。容量耗尽返回 `Err`，不 panic。
**与 C 语义对应**：`add_memmap` 的只追加、`cut_memmap` 的「清空后补左右余量」在这里变成一次跨度替换；`mem_high_phys` 改为从集合推导，不再单独维护。
**可测试性**：「总字节数守恒」「跨度两两不交」「切割后每字节来源不变」都是集合上的纯函数性质测试。

## DECISION 04

**决策问题**：非页对齐的来源区间怎么准入，切除往哪边取整？
**候选**：A 照 C：起点向上、长度向下，终点可外移一页；B 向内夹取 `[roundup(start), rounddown(end))`；C 直接拒绝非对齐输入。
**选择与理由**：B。准入的职责是「只声明来源真正给过的字节」，C 的外移会让账比固件承诺多一页，与来源可追溯直接冲突；切除沿用 C 的向外取整（起点向下、终点向上），因为消费侧要保证「用过的页不留在账上」，保守方向正确。4 GiB 截断保留为显式策略参数，并记入来源账的 `above_limit`。
**代价与边界**：与 C 在非页对齐条目上最多差一页；退化切除（`start == end` 且未对齐）仍会切掉一页，必须在文档与测试里写明；`LIMIT` 是架构策略，不是散落在算法里的常量。
**与 C 语义对应**：`pg_utils.c:add_memmap` 的 `roundup/rounddown`、`:cut_memmap` 的反向取整、`LIMIT 0xFFFFF000`。
**可测试性**：四种对齐组合、跨 `LIMIT`、零长、退化切除、内外夹取的手算向量。

## DECISION 05

**决策问题**：两个发放点如何定义，「从最高处取页」是什么意思？
**候选**：A 复刻 C 的下标序扫描；B 按地址：`take_lowest(len)` 取最小基址的够用跨度（前端切走），`take_page_top()` 取最大地址跨度的最后一页；C 一个通用分配器加策略参数。
**选择与理由**：B。C 的「最高下标」只是槽位回收的副产物，`pg_alloc_page` 的意图是「从高处取、给低处留连续」，只有写成地址序才可证明。`alloc_lowest` 在 C 里把长度当结束地址传给 `cut_memmap`（`pg_utils.c:81`），在已核对调用序与四前提下切除常态不发生（§2.4.1.3）；Rust 必须真的切除，并把「分配后该段不在账上」写成后置条件。
**代价与边界**：某些切割形态下具体物理页与 C 不同，但不可由用户态观察；跳板低于 1 MiB 从「观测常态」变成显式检查，失败返回 `Err`。
**与 C 语义对应**：`arch_smp.c:76-81` 的 `alloc_lowest` 加 `< 1 MiB` 断言；`pg_utils.c:138` 的 `pg_alloc_page` 从最高条目取页。
**可测试性**：空集合、单跨度、多跨度、相邻跨度、取整后长度不足、低地址约束失败各一例。

## DECISION 06

**决策问题**：谁参与重叠检查，用什么区间代数？
**候选**：A 照 C 把内核塞进模块数组第 M 槽；B 内核范围单列，检查接收 `&[Range]`；C 只查模块不查内核。
**选择与理由**：B。判据只有一条 `a.start < b.end && b.start < a.end`，相切放行。C 的 `-1` 端点判据是在半开区间上手工翻译「最后一个字节」，正是相切误报的来源；内核不占模块槽，模块容量也就不必为它留一格。
**代价与边界**：位置耦合消失后，模块到启动程序的绑定要另有依据（见 DECISION 09）；重叠错误在建模之前报出，不进入切除阶段。
**与 C 语义对应**：`pre_init.c:overlaps` 的端点检查与「内核当第 M+1 个模块」，`panic` 变成 `Err(Overlap)`。
**可测试性**：相切、单字节相交、包含、完全相同、三区间链、内核恰好包住模块。

## DECISION 07

**决策问题**：命令行与内核派生键如何共存，用户态拿到的旧 blob 怎么产出？
**候选**：A 原样保存 C 的 NUL 串并复刻「只删首条」的扫描；B 有序记录表加显式优先级（外部键与内核派生键），渲染成旧 blob；C 只存原始字节，每次查找重扫。
**选择与理由**：B。外部同名键后者覆盖前者并保持首次出现的位置；内核派生的 `arch`/`board` 权威，不可被外部遮蔽；容量不足时丢弃新记录并计数，启动继续；查找返回首个匹配。C 的删除只对首条生效，使 `board` 是否被遮蔽取决于它在缓冲区的位置，这不是可保留的语义。
**代价与边界**：命令行不再能改写 `machine.board_id`（有意的收紧）；blob 里不再出现重复键；丢弃计数可见，但启动结果与 C 一样不失败。
**与 C 语义对应**：`mb_set_param` 的专用键、去重、双 NUL 格式与 `get_value` 的首匹配；`GET_MONPARAMS` 整块拷贝的字节格式（§2.3 落链）。
**可测试性**：重复键在首条/非首条、容量边界、双 NUL 结尾、缺键、专用键覆盖。

## DECISION 08

**决策问题**：校验失败如何收场，检查放在哪里？
**候选**：A 每个算法内部 assert/panic；B 全链路 `Result<_, BootError>`，入口一次性 `boot_fail`；C 尽力而为继续启动。
**选择与理由**：B。`BootError` 覆盖 `BadWire/BadMagic/Truncated/Overlap/NoSpan/SpanExhausted/BadGeometry/BadModuleSet`，并给出 errno 映射（`EINVAL/ENOMEM/ENOEXEC`）供跨边界复用；所有结构校验在建模之前完成，消费函数的入参已是不变量成立的类型。
**代价与边界**：错误路径不能用堆分配；调用点必须显式处理，入口只有一处分派。C 的「立即停、绝不半消费」保留，改变的是停点不再散落在算法里。
**与 C 语义对应**：魔术值断言、`mmap_size` 上限、no slot/no memory 的 panic；`exec_elf.c:160-167` 在清进程、分配之前先检查全部 program header 的做法，就是 I4 的现成范例。
**可测试性**：每个错误变体一个最小向量；失败后没有 `KernelInfo` 可观察由类型保证。

## DECISION 09

**决策问题**：模块是谁，容量满了怎么办？
**候选**：A 位置索引（C 的 `module_list[i-NR_TASKS]` 对 `image[i]`）；B 名字加显式启动程序表，数量必须精确相等；C 名字只用于诊断，绑定仍靠顺序。
**选择与理由**：B。`ModuleDesc { name, phys: Range, state: Present | Reclaimed }`，`Reclaimed` 代替把 start/end 清零；容量固定，超出返回 `Err`，不静默截断。跨镜像 wire 必须自带名字；C 的顺序耦合只在发送与接收共用一张表时成立，而五条腿的来源不同（UEFI 文件系统、U-Boot/DTB）。
**代价与边界**：启动期多做一次名字比对；静态表与模块名单要在编译期对账。VM 若只能吃固定条数，交接时明确失败，而不是静默丢。
**与 C 语义对应**：`module_list[]` 与 `table.c:44` 的顺序约定、用 0 表示「已回收」、`NR_MEMS = 16` 的静默截断（§2.4.1.4）。
**可测试性**：数量不等、重名、缺名、多余名、回收状态迁移、超过 VM 容量的交接。

## DECISION 10

**决策问题**：这份账什么时候可以被谁改，并发窗口怎么表达？
**候选**：A 全局 `kernel_may_alloc` 布尔加约定；B 所有权表达窗口：`EarlyMemory` 是线性值，`&mut` 只在 BKL 持有者手里，交接后只剩 `&KernelInfo`；C 每跨度一把锁。
**选择与理由**：B。构建期单 CPU、IF=0，没有并发；SMP 起来后任何改账都在 BKL 内、不许睡眠；`EarlyMemory` 不是 `Sync`，跨 CPU 共享必须先经过 Mutex/BKL 守卫。把「能不能改」从运行时布尔变成类型与借用。
**代价与边界**：`kmain` 的「还 bootstrap 段」必须在关闭窗口之前完成，窗口关闭点成为显式代码位置，不能中途 reopen；`EarlyMemory` 与 `KernelInfo` 拆成两个值，交接函数返回二元组。
**与 C 语义对应**：`main.c:142` 置 1、`main.c:105` 置 0、`main.c:301` 在窗口内改账；`kernel_may_alloc` 被两个编译单元各自定义（§2.4）是全局布尔会分身的证据。
**可测试性**：host 侧两个互不共享的 `EarlyMemory` 证明无全局状态；借用检查器固化「`KernelInfo` 交接后不可改」。

## MINIMAL-DESIGN

公开面只有四个名字：`BootFacts<'a>`（借用事实）、`BootError`、`KernelInfo`（自有只读事实：模块、参数、内核范围、用户栈顶）、`EarlyMemory`（跨度集合与两个发放方法），加一个 `assemble(facts, geometry) -> Result<(KernelInfo, EarlyMemory), BootError>`。更少概念的实现方式：

- 不要 trait：五条腿各是一个返回 `BootFacts` 的普通函数，平台在编译期选定；`BootFacts` 这层中立结构已经给了测试接缝，`dyn` 只增加间接层。
- 不要 builder 类型与 typestate：中间账是 `assemble` 的局部变量，失败即 drop；「只填一次」由「没有第二个人拿到它」保证，而不是状态机。
- 不要 `BootStorage`/`BootReport` 两个名字：发送侧借用视图就是 `BootFacts`；接收侧落地区是一个对齐 arena 的实现细节，不是协议概念。
- 不要槽位、空洞、零长哨兵、`mmap_size` 高水位：`[Span; N]` 加一个 len 就够。
- 不要「内核当模块」：重叠检查接收 `&[Range]`，模块表只装模块。
- 不要单独的审计遍历：`Span` 的类型强制带 `source`，另存每来源的收支表（reported/admitted/carved/rounded/above_limit），`audit()` 只对表做加法。
- 不可再删的四样：借用事实、自有结果、线性早期内存、错误枚举；删任何一个都会把不变量退回运行时约定。
- 代价：`assemble` 一个函数承担校验、建账、切除、产出，函数比 C 的分散函数长；收益是公开状态为零，测试仍可按私有纯函数拆。

## NOT-COPIED-FROM-C

- 40 槽数组、零长度当空位、`mmap_size` 高水位、按下标扫描：都是槽位回收的副产物，不是分配语义。
- 内核占模块第 M+1 槽与 `kern_mod`/`mods_with_kernel`：内核范围本来就是链接期事实，不需要伪装成模块。
- 参数去重只对首条生效、`board` 可被位置决定的遮蔽：结果依赖记录位置，不是可保留的契约。
- `add_memmap` 终点外移一页的取整：会让账比来源承诺多，破坏来源可追溯。
- `alloc_lowest` 把长度当结束地址传给 `cut_memmap`：常态不切除，是缺陷不是语义；Rust 改为真切除并加后置条件。
- 全局 `kernel_may_alloc` 布尔及其两份定义：窗口应由所有权表达。
- `kinfo` 里的 `mbi` 整份副本、`kmess` 指针、`bootstrap_start/len`、`freepde_start`、占位后被覆盖的 `user_sp`/`vir_kern_start`、可写的 `mem_high_phys`：前三个是同一地址空间的便利，指针与占位符跨镜像即失效；后两个是可推导量。
- VM 侧 16 条静默截断：容量不足应当明确失败，不能丢条目后继续。
- 以 assert 表达式文本作唯一诊断、检查与切除逐条交错：校验要聚成前置阶段，诊断要带错误码。
- `MULTIBOOT_MAX_MODS` 减一给内核留槽：模块容量不应被内核记账方式吃掉一格。
- 六个具名 `.bss` 落地区的具体形态：协议只约定字节布局，接收侧用一个 arena 即可。
