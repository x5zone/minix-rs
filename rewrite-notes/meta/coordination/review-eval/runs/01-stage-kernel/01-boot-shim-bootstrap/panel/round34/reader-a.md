读法：按读者画像的前置知识逐节读全文；不使用源码、其他文档或操作系统常识补全作者没有写出的内容。以下只记我读文档时的实际卡点与改进机会。

全文已逐节读完。除下面一条 FINDING 外，没有其它让我卡住无法继续阅读的问题；其余是读得慢或需要多回看一次的改进机会，按 SUGGESTION 记。

## FINDING RD34-READER-A-01（P2）

### FINDING RD34-READER-A-01（P2）

- 位置：§3.8 "分配器换手的落地" 的扣除表说明段——"表头把两份清单分开陈述：扣除记录含 VM 自己，交接模块清单（`VmBootHandoff.modules`）才按 C 的 `kinfo.module_list[]` 排除 VM。"
- 严重度：P2
- 问题：这里说"按 C 的 `kinfo.module_list[]` 排除 VM"，但同一篇文档的 §4.3 给出的 `MODULE_NAMES` 十二项里明确有 `"vm"`，并说"12 不是随手定的数：它等于 C `boot_image` 表的用户态段长度"；§2.5 又说内核把自己追加到 `module_list[k]`；§2.4.2 说 VM 模块回收后"任何遍历 `module_list[]` 的代码都会看到一条'空模块'"。这三处合起来说明 C 的 `kinfo.module_list[]` **含** VM（只是回收后条目被置零），没有"排除 VM"的性质。我读到这里无法判断：C 的 `module_list[]` 到底含不含 VM？Rust 的 `VmBootHandoff.modules` 排除 VM，是照 C 的哪份清单？
- 影响：我会把 C 的 `module_list[]` 误当成"不含 VM 的交接清单"，于是读错 §2.4.2 的"还 VM 镜像"（C 是回收 VM 的模块字节并置零条目，不是从清单里删掉 VM），也读错 §3.8 扣除表"扣除记录含 VM / 交接清单不含 VM"的 C 对应关系。要继续读，我必须自己猜"作者想指的可能是另一份 C 清单（比如 `boot_procs` 或 boot image 表）"，而文档没有给出这个名字。
- 证据或推理：只引文档内的句子——§3.8 上引；§4.3 `MODULE_NAMES` 列表含 `"vm"`，且"12 不是随手定的数：它等于 C `boot_image` 表的用户态段长度"；§2.5 "内核自己不带 `multiboot_module_t`……把它塞进模块数组的第一个空槽"（`cbi->module_list[k]`）；§2.4.2 "置零发生在加回之后，且两个字段一起置 0。此后任何遍历 `module_list[]` 的代码都会看到一条'空模块'"。这三处是"C 的 `module_list[]` 含 VM"，与 §3.8 的"排除 VM"直接冲突。
- 最小修复：把 §3.8 那句改成一句可判定的说法，二选一——(a) "C 的 `kinfo.module_list[]` 本身含 VM，VM 的条目在 `arch_boot_proc` 回收后被置零（§2.4.2）；Rust 的 `VmBootHandoff.modules` 排除 VM 是 Rust 侧的选择"；或 (b) 若确实另有一份不含 VM 的 C 清单，写出它的名字（不要写 `kinfo.module_list[]`）。同时把同一段引用的源码注释 "excludes VM — C: `kinfo.module_list[]`" 按同一口径修正，避免读者把注释放进正文后再次冲突。
- 置信度：高
- 是否需源码核实：否
- 若我错了：我可能把"按 C 的 `kinfo.module_list[]` 排除 VM"读成"C 的清单不含 VM"，而作者的原意可能是"交接清单按 C 的 `kinfo.module_list[]` 的顺序排列，但 Rust 侧额外排除 VM"；即便如此，这句话的语法仍把"排除"挂在 C 的符号上，读者无法从字面排除这种读法。作者若在 §3.4.2 或 §4.3 某处已经说明"C 的 `module_list[]` 含 VM、Rust 交接清单是另一份"，我没有找到那句；那正是需要补的回指。
- 命中清单：2（每个因果主张能在同节或回指节找到证据）、5（指针不落空、不反向、不自指）
