## FINDINGS

## FINDING RA-F1 §1.0「高半切换后读到零」与 §3.2.4/§5.3 的证据强度冲突

- **节号 + 原文摘录**
  - §1.0 失败对照：「接收侧会在自己的地址空间里读到发送侧的内存；**高半切换后读到零，正是 I1 判据里的第一现场**。」
  - §3.2.4：「两条候选各带可检验的推论……本篇没有归档的探针读数可重放……候选①只按源码注释与人工观察保留为“未排除”，候选②同样未排除」；「把'值必须在入口尽早深拷'写成已证设计会高估证据强度」。
  - §5.3：「两条候选……都**未排除**……因此“入口尽早深拷”是预防性不变量，不是已证机制。」
- **严重度**：P1（认识论口径冲突，影响初学者建立因果模型）
- **问题**：开篇把「高半切换 → 读到零」当作 I1 的第一现场陈述为事实；§3.2.4 与 §5.3 明确说零化机制未定、两个候选都未排除。同一现象在 §1 是「已证现场」，在 §3/§5 是「未证候选」。
- **影响**：初学者会把「高半切换清零指针」当成机制记住；读到 §3.2.4 必须反向拆掉这个模型。更实际的影响是：读者无法判断 I1 的「可观测判据」到底要求多强的证据——是结构论证（指针跨镜像必失效），还是观测（真机见过零化）。
- **证据**：全文第 34 行 vs 第 1321 行、第 2649 行（本次只读文档，未读源码/规则）。
- **最小修复**：§1.0 该句改为「接收侧读到的地址在自己的地址空间里没有意义——结构上必然失效；真机上还观测到整段归零（机制未定，见 §3.2.4）」；或加一句前向指针「此处的'读到零'是观测，不是已证机制」。
- **置信度**：高（两处口径确实一强一弱）；中（作者可能认为 §1.0 只在讲「结构必失效」，但原文点名了「读到零」这个具体观测）。
- **若我错了**：若「高半切换后读到零」指的是「切片指针本身指向的页在接收侧页表里未映射，读取即 fault/零」这一纯结构推论，而非 §3.2.4 的真机零化观测，则两处不冲突；但 §3.2.4 的 `res=127 zeroed=127` 读数与 §1.0 的措辞几乎同形，读者无法自行区分。

## FINDING RA-F2 §5.5「没有未闭环缺口」与 §5.1/§5.2/§3.1.1 的覆盖口径冲突

- **节号 + 原文摘录**
  - §5.5：「**当前没有未闭环的测试缺口。**」
  - §5.2：「aarch64 直核由 `test-smp-aps-aarch64` 到 boot/SMP 标记（**其后的用户链 Data Abort 是已登记的 A2 遗留，不作为本表的通过证据**）」。
  - §5.1 I3 行：「**五条腿都有门覆盖**」。
  - §3.1.1：「aarch64 直核面……判据是 SMP 交付（`ap-arrived`/`ap-irq-ready`），**不是启动路标门**」。
- **严重度**：P1（证据矩阵的可信度；初学者会把「没有缺口」当成交付结论）
- **问题**：一边说没有未闭环测试缺口，一边登记了 aarch64 用户链 Data Abort 这个遗留；同时把「SMP 交付门」算成「五条腿都有门覆盖」，而 §3.1.1 自己说那不是启动路标门。三处合起来，读者无法判断 aarch64 直核的**交接**是否被证明。
- **影响**：I3 行的「五条腿都有门覆盖」会被初学者读成「五条腿都证明交接成立」；实际 aarch64 直核只到 `ap-irq-ready`，且其后的用户链已知会 Data Abort。证据强度和结论不匹配。
- **证据**：第 2634、2639、2661、2665、1123 行。
- **最小修复**：§5.5 改为「引导交接范围内没有未闭环缺口；aarch64 直核的证据止于 SMP 交付，其后用户链 Data Abort 作为 A2 遗留单列」，并在 §5.1 I3 行把 aarch64 标成「部分覆盖（仅 SMP 交付）」。
- **置信度**：中高（文字冲突明确；「A2 遗留」是否算测试缺口取决于台账口径，我无法读台账确认）。
- **若我错了**：若 A2 遗留已在别处关闭、只是本表仍引用旧注记，则 §5.5 成立；但 §5.1 的「五条腿都有门」与 §3.1.1「不是启动路标门」的措辞冲突仍在。

## SUGGESTIONS（换一种讲法）

### S1 §2.3 `mb_set_param`：把「三条边缘分支」挪到主结论之后

现状：先讲「已存在先删」的 off-by-one 字节图（下标 0–8 表），再讲「重写 `A=3` 首条生效」，再讲「`xboard=2` 中段命中产生 `xarch=i386`」，最后讲「首条提升分支」。我在第一遍读完后只记得「删除只对首条可靠」，但四条推演混在一起，主结论被埋。建议在字节图前先给三行 take-away：「同名键删除只对首条记录可靠；非首条会留下双记录，读取取第一条；中段前缀匹配可能造出伪记录」，再展开推演；`xboard=2` 这类 adversarial 例子可标「边角，可跳过」。

### S2 §2.4.2.1「下标序 ≠ 地址序」表加一个两刀手算

现状：表格用「数组此前状态 / 左余量落点 / 右余量落点 / 序是否断开」四列描述切割形态，但没有像 §2.4 那样给一次具体数字 trace。建议照 §2.4 的 `0x400123` 例子补一次「先切 A 再切 B，右余量落到 m+2，下标 3 的地址低于下标 1」的两刀手算，读者才能把「按下标取 ≠ 按地址取」落到具体槽位。

### S3 §1.0 术语「五条生产腿」补一句「未接线的 riscv64 UEFI shim 不计入」

§1.0 把「五条生产腿」定义为两条 UEFI + U-Boot shim + 两个直核面；但 §3.1.1 的接线状态表列了第六行「riscv64 UEFI shim：未接线」。初学者在 §3.1.1 会重新数腿并怀疑 §1.0 漏了一条。建议在 §1.0 术语条目末尾加「未接线的 riscv64 UEFI shim 路径不计入这五条，见 §3.1.1」。

### S4 §1.2 I2 的「第一现场」用 Rust 错误名，初学者不知道去哪看

I2 行的第一现场写 `FreeSpanWithoutMemorySource` 或 `ReservedSpanWithoutSource`——这是 Rust 侧错误变体，但 §1.2 尚未引入 Rust（第 3 章才讲）。建议改为「账上有字节但说不出谁给的（Rust 侧表现为 `FreeSpanWithoutMemorySource`，§3.3）」，或把错误名放进括号并标章号。

## 正面记录（不是客套，是给作者的可复用做法）

- §2.4 的 `0x400123` 手算 + 长度守恒校验（`0x300000 + 0xBFE000 + 0x2000 = 0xF00000`）：初学者能自己复算，建议其他「区间推演」段照此办。
- §2.5 的 `overlaps` 去掉 `-1` 的反例（A/B 相切）：把「半开区间」这个抽象变成了可执行的两行算术，是本篇最有效的一处失败对照。
- §2.2 的栈对齐逐字节推演与「call 前 ≡4、入口 ≡0，仍不满足 SysV」的结论：敢说 C 原作违反 ABI，并给出「没有反汇编证据，只能当风险提示」的边界，证据强度标得诚实。
- §5.1 的「不证明什么」列：这是我读过的启动链文档里少见的自觉，建议保留并在 §6 失败模式表里也加同列。
