## SUGGESTION A-06

## SUGGESTION A-14

- 位置：§1.4（切根）、§2.6.3/§2.6.4（切根/换根）、§4.4/§2.4（收口）、§4.1/§3.7（直核）。原文：“**切根**（从自举根切到运行期根……）”、“切根后那张 `pagedir[]`（paged 副本 B，§2.6.4）”、“这次**换根**”、“2 MiB 对齐收口”、“以 32 位的 `phys_bytes` 收口”、“测试内核直核调用”。
- 问题：四个词各被用作两个概念：“切根”既是 Rust 的 bootstrap→runtime 切换，又被用来指 C 的 A→B 切换（§2.6.3 的“切根后那张 pagedir[]”），“换根”也指同一个 C 切换；“收口”既是链接脚本的 2 MiB 对齐填充，又是 32 位地址截断；“直核”既是生产启动形态，又是测试内核的直接调用。读者每遇到一次都要从上下文重新消歧。
- 影响（若采纳）：减少在 §2.6.3/§2.6.4 与 §4.4/§4.6 之间的术语回读，尤其“切根”在两章指不同机器的切换时。
- 最小修复：每个概念固定一个词——“切根”只用于 Rust 自举根→运行期根，“换根”只用于 C 的 A→B；“收口”分成“对齐收口”与“32 位截断”；“直核”分成“直核形态”与“测试直调”。
- 依据：§1.4 给“切根”的定义是“从自举根切到运行期根”；§2.6.3 却用“切根后那张 pagedir[]（paged 副本 B）”指 C 的 `prot_init` 切 A→B；§2.6.4 又把同一动作叫“换根”；§2.4 的“以 32 位的 phys_bytes 收口”与 §4.4 的“2 MiB 对齐收口”是两种“收口”；§4.1 的“测试内核直核调用”与 §3.7 的“直核自引导”是两种“直核”。
- 置信度：高
- 命中：1、6
