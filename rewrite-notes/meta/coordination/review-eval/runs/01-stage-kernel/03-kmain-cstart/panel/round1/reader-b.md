## 一、全文论证结构重建

作者要读者接受的是一条五步链：

1. 02 篇交出的状态是"能跑，但规则仍借自引导方"：GDTR/IDTR 指向引导方的表，TSS 没有内核自己的版本；三张表分别回答特权级与段可访问性、异常入口、ring3 进 ring0 用哪根栈（§1.1）。
2. 因此 `kmain` 阶段 B 的第一件事必须是 `init_protection`。所谓"第一次行使特权"不指第一次执行 ring0 指令，而指把表的控制权从引导方换到内核的那串装载动作（§1.2、§1.3）。
3. C 侧证据链按函数顺序展开：`kmain` 五步准备（§2.1）→ `cstart` 四调用与次序（§2.2）→ `prot_init` 五类动作（§2.3）→ `tss_init` 一条描述符、一个结构体、两条系统调用路径（§2.4）→ `prot_load_selectors` 六步装载（§2.5）→ 重建页表（§2.6）→ earm 是独立实现而非条件编译分支（§2.7）→ 三类归纳（§2.8）。
4. Rust 侧把 C 留下的问题重新回答成七个决策：64 位下各表的去留（§3.1）、两个 trait 的切分（§3.2）、地址稳定契约（§3.3）、系统调用单路径（§3.4）、页表重建淘汰（§3.5）、`cstart` 拆 Phase（§3.6）、门先装后 `load`（§3.7）；第 4 章按同一顺序落地。
5. 证据边界：宿主测试证明位与字段，`test-protection` 证明三架构的装载面，缺口表登记未覆盖项（§5）；诊断章给症状到确认命令的映射（§6）。

这条链的承重点只有三处：

- 承重点甲：阶段 B 第一件事为什么是 `init_protection`。文档在 §1.1 用 02 篇的状态表与 `lib.rs` 文档注释的转引建立它，§3.6 再用 `init_clock_and_interrupts` 的反事实加固。
- 承重点乙：门以 GDT 已装载为前提，所以两个 trait 的调用次序不可交换（§3.2）。
- 承重点丙：表装载后地址不能再变，所以必须先搬进全局再 `load`，并重建 TSS 描述符（§3.3）。

结构问题集中在三处：承重点甲从未在本篇内正面论证；承重点乙与丙的结论被设计章、实现章、测试章各说一遍，其中两处互相矛盾。下面先列阻断阅读的两条，再列建议。

### S13 §2.8 归纳的分类轴与读者陈述不自洽

- **位置**：§2.8 表与末段。
- **严重度**：中。
- **问题**：三类轴是"改内存还是改 CPU 状态"，但第三类"接管后的收尾（改内存与 CR3）"同时含两样，正文自认"第三类的 `pg_clear` 也改内存（与第一类重叠，按目的归此）"；`prot_init_done` 的读者先说在 AP 启动路径的 `assert(prot_init_done)`，随后说"唯一读者 `copy_trampoline`"，两个读者名。

- **证据**：表头与第三类行；"`prot_init_done` 的读者在 `i386/arch_smp.c` 的 AP 启动路径里（`assert(prot_init_done)`）"；"`prot_init_done` 的唯一读者 `copy_trampoline`"。

- **置信度**：0.85。
- **若我错了**：若 `copy_trampoline` 就是 assert 所在函数，两句可合并为"唯一读者是 `copy_trampoline` 里的 assert"，但需点名函数关系。

## 四、总体判断

1. 全文的骨架是清楚的：三张表 → C 侧三函数 → Rust 七个决策 → 落地 → 证据边界 → 诊断。读者能顺着这条线读完，没有迷路。
2. 最大的结构病是"结论前置"：六个导读块把小结与失败对照放在证据之前，读者先被告知该相信什么，再去读为什么。这不是局部措辞，是六章共用的模板。
3. 第二大的病是"同一件事说三遍"：设计章（§3）、实现章（§4）、测试章（§5）各自复述同一结论，且复述之间已经出现两处相反（F1、F2）。重复不是冗余问题，而是矛盾温床。
4. 承重点甲（阶段 B 第一件事为什么是 `init_protection`）在本篇内没有正面论证，只转引 02 篇与 `lib.rs` 注释；这是全文唯一一处"前提从篇外借来"的地方，建议补一段本篇自己的论证。
5. 修订优先级：先修 F1、F2（它们让读者无法判断机制真相），再处理 S1、S5、S6、S7（它们影响全文框架与学习目标的可达成性），最后做 S2、S3、S4、S8–S14 的收束与去重。
