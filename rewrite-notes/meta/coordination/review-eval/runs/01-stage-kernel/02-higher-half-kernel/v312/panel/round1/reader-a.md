## FINDING READER-A-01（P1）

- 位置：§1.0 最小示例，"# 链接脚本给出一对基址；两者之差就是平移量（§1.1）"，命令对象是 `os/kernel-image/x86_64.ld`。
- 严重度：P1
- 问题：对 x86_64 脚本，两个基址常量之差不是 `vaddr − paddr` 平移量。我按注释算出 `0xFFFF800000000000 − 0x200000 = 0xFFFF7FFFFFE00000`，与 §6.2 给出的 x86_64 平移量 `0xffff800000000000` 对不上。命中清单第 3 条（把单形态结论写成普遍结论）与第 4 条（同一口径跨节不一致）。
- 影响：我会带着错误的平移量去读 J1 与 L4，进而怀疑 §6.2 的读数；在 x86_64 上会把 `KERNEL_HIGH_BASE` 与"两个常量之差"混为一谈，后面读 `AT` 表达式时无法判断减去的到底是哪一个量。
- 证据或推理：§3.1 原文："x86_64 的位置计数器起点是 `KERNEL_HIGH_BASE + KERNEL_PHYS_BASE`（首段的虚拟地址里直接含有物理基址，`AT` 表达式减去 `KERNEL_HIGH_BASE` 就得到物理地址）"；§3.1 的脚本摘录给出 `KERNEL_HIGH_BASE = 0xFFFF800000000000;` 与 `KERNEL_PHYS_BASE = 0x200000;`；§6.2 原文："L4 的平移量按架构不同：x86_64 是 `0xffff800000000000`，aarch64 是 `0xffff7fffbfe00000`，riscv64 是 `0xffffffbf7fe00000`"。
- 最小修复：把注释改成"x86_64 的平移量是 `KERNEL_HIGH_BASE`（首段 VMA 已含 `KERNEL_PHYS_BASE`）；aarch64/riscv64 的平移量才是两个常量之差"，或者在示例里同时打印首段 VMA 与 LMA 再相减。
- 置信度：高
- 是否需源码核实：否
- 若我错了：我可能把"两者之差"理解成"首段 VMA 与首段 LMA 之差"，而不是"两个常量之差"；但紧接着的命令只读两个常量，§1.1 也没有给出 x86_64 的首段 VMA，读者只能按常量差理解。

## FINDING READER-A-02（P2）

- 位置：§1.0 术语，"**VMA / LMA**：段的执行地址与装载地址；`p_vaddr` 与 `p_paddr` 分别描述它们。"；同节"**高半 / 低半**：内核执行地址所在的高地址区间，与物理内存所在的低地址区间相对。"
- 严重度：P2
- 问题：术语把 VMA 与高半都定义成"执行地址"，但 §1.1 与 §1.0 失败对照反复强调"符号值已经是高半 VMA，但 CPU 还不能从那里取指"。如果 VMA 是"执行地址"，这句话在术语上自相矛盾；§2.1 又把 VMA 定义成"链接器解析符号时用的地址"。命中清单第 1 条（术语首次定义）与第 3 条（前提与结论不一致）。
- 影响：我会按"执行地址"理解 VMA，正好落入 §1.0 失败对照警告的"把符号值当成可执行地址"的错误；必须自己把"执行"改读成"链接期虚拟地址"才能继续，读到 §3.3 的"在物理视图下取到低物理地址"时还会再卡一次。
- 证据或推理：§1.0 术语原句；§1.1 原文："分页开启之前，`kmain` 的符号值已经是高半 VMA，但 CPU 还不能从那里取指；分页开启之后，符号值没变，可访问性才成立。"；§2.1 原文："VMA（virtual memory address，链接器解析符号时用的地址）与 LMA（load memory address，装载器写段体时用的地址）"。
- 最小修复：把术语改成"VMA：链接期虚拟地址（符号解析用），不等于运行期可访问地址；高半：以 `kern_virt_base` 起始的内核虚拟区间；低半：恒等映射覆盖的物理地址区间（VA = PA）"，并在 VMA 定义后保留一句"可访问性要等映射建立"。
- 置信度：高
- 是否需源码核实：否
- 若我错了：作者可能用"执行地址"指"链接时假定代码将执行的地址"，并在 §1.1 立即修正；但术语表本身没有这个限定，初学者会按字面读。
