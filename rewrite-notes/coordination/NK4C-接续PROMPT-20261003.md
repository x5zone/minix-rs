## 一、这个项目在做什么，你要达成什么（三终目标，`/goal` active 直至全部完成）

`minix-rs` 是把 Minix3 微内核用 Rust（x86_64 / aarch64 / riscv64 三架构，`#![no_std]`）做的**语义重写**：
保持对外行为一致，内部用 Rust 类型系统。三条最终目标与**当前精确状态**：

1. **三架构启动标记**：各自从串口打印 `minix-rs rc: minimal boot script marker`。
   现状：x86_64 ✅、aarch64 ✅、**riscv64 ❌——只差缺陷 (A)**。
2. **18-stage 命令面**：echo / ls / cat 走真实 VFS 的 IPC 全跑通。
   现状：x86_64 ✅、**aarch64 ✅（本会话新增 `os/qemu-tests/test-cmd-smoke-aarch64.sh` 实测 PASS，过 CodeReview 修 P1/P2 重跑仍 PASS）**、riscv64 ❌（受 (A) 门控）。
3. **586 个 minix3 的 C 测试上机跑通**。
   现状：**构建/链接面已 18/18 可链成 riscv64 静态 ET_EXEC ELF**（本会话补 md5 / bm / errno(`sys_nerr`) 三个 BSD 兼容件）；但**「上机真跑」仍受 (A) 门控**（riscv），aarch64 上机另需 freestanding aarch64 C 工具链。

**(A) 同时门控目标① riscv 段、目标② riscv 段、目标③ riscv 上机段**，是贯穿三条目标的共同关键路径，最高优先。

## 三、(A) 现在的确切认知状态（最重要，别把它当已解决、也别重走死路）

**当前定性（有证据）：(A) 是一个「fork 路径上的 timing-sensitive 竞态」，不是「某枚固定 PTE 槽被写坏」。**

支撑证据链（见 §续-266~272）：
- **同-build 裸启动秒级可复现**（`bash tmp/nk4a/riscv_fingerprint.sh <tag> <port>`，无 `-S`、无插件，~4–6s 到 `pagefault in VM`）。
- **跨 boot 非确定，≥3 种形态**（各来自内核 trap 帧**同一行**打印，(sepc,stval) 同源同 build）：
  | 形态 | sepc | stval | 性质 |
  | --- | --- | --- | --- |
  | A | `0x3ffffe26e4` | ==sepc | 取指页故障（VM 在用户地址空间顶附近取指）；崩前紧接 `sas-fork ep=32780 root=0x9dc37000`→`setaddr nr=0xc` |
  | B | `0x3ac1a` | `0x409d28bb20` | query L0 槽读（合法对齐基 0x9d28b000+idx×8，再 \|bit38 非规范） |
  | C | `0x3abec` | `0x10bd28cb2c` | query L1 槽读；**低 12 = 0xB2C 非 8 对齐**（§3.5 矛盾） |
- **插件零扰动实测（§续-269）**：可观测的 1078 条 query 读**全部 8 对齐**（`pc=0x3abec` 观测 215 次永远读对齐 `0x109d2adff8`=子根 `0x9dc37000` i2=511→L1 `0x9d2ad000` 槽 511）；崩点 `stval=0x10bd28cb2c` 在**所有 mem-cb 记录里出现 0 次**。⇒ **QEMU 8.2.2 的 `mem-cb` 不为「故障那一次访问」触发**，且本机头文件**无寄存器/内存读 API** ⇒ 形态 C 的真实故障地址无法由当前零扰动手段直读。
- **插件拖慢使 race 消失（§续-270，硬旁证）**：加全窗 store 插件（零改 guest 码、只拖慢）后，fork 崩**不再发生**（guest 困在 `sa-call` 循环 ≥180s）。耐久脏槽型缺陷被均匀拖慢仍会崩；只有跨 race 才因拖慢改变窗口交错而不再触发。⇒ 插件对该 race **不是中立观测者**（速度扰动型 Heisenbug）。
- **fork 处理器排序审计（§续-272）**：`os/servers/vm/src/fork.rs` 五步（建子页表→父 CoW 降写→`sys_fork(PFF_VMINHIBIT)`→`setaddrspace`清 inhibit→msg 预页）与 C `minix3/minix/servers/vm/fork.c` **逐字同序** ⇒ 偏离**不在 VM 事件循环顺序**，若为 race 则在**内核侧**（`sys_fork`/`complete_fork_setup`/`VMINHIBIT` 清除→重调度语义）或**共享页表帧分配器 × 并发**（minix-rs 是 SMP+BKL，与 C 结构不同的层）。

### 已定论 / 已下调（别当结论用、别重走）
- **旧靶 `0x9DC377F8`（子根 i2=255 L2 中间项）彻底作废**：崩 walk 实为子根 `0x9dc37000` 的 **i2=511**（栈 `0x7fffffffe000`），计划里 §续-240 的「硬件写 watchpoint 唯一靶」前提不成立。
- **§续-265「root 身份错配（VM PageTable 根 ≠ 子 live satp 根）」下调为未证**：它是拿 stval 当 walk 输出算「故障物理」推出来的；而 §续-266 反汇 + §续-269 插件都证明崩 stval 非任何 query 槽读输出 ⇒ 推导作废，「比对三 root」不作为下一步。
- **§3.8「读法乙子型（query 返回后调用者加 0xB2C 游标）」被驳**：query 每条 `ld` 立即数恒 0、地址=4KiB 对齐基址+索引×8 ⇒ 崩点区没有「query 之后加偏移」的指令。

### 死路清单（禁止重走 / 投机修）
