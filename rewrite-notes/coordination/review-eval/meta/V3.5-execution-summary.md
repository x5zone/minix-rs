## 四、流程发现（这批执行验证到的问题）

1. **裸发现 ID 跨轮重名是硬缺陷**：D01 R35 与 R31、D02 R3 与 R1 都用 `FACT-01`/`CLAIM-01` 这类裸 ID，而台账是全局 `ID → 行` 的映射，后写的行会覆盖先写的行，导致历史轮的根因数从分档聚合里消失。本批的处置是「R35/R3 行同时列 `RD35-`/`RD3-` 前缀形与裸形，并把 R35 节排在 R31 节之前让历史行最后生效」。**建议下一版工具强制轮次前缀**（R32–R34 当年用 `RD32-` 前缀正是为此）。
2. **确认轮的 §3.6 修复权限有系统性张力**：设计 P1/P2 只能延期（D-060/D-063），两次都把「看起来像 P1」的设计项推入下一个 design batch。若 meta 认为它们应按事实缺陷在轮内修，则确认轮的定义需要收紧。
3. **独立 certify 的价值被两篇实证**：D01 的冷读推翻了主 agent 对 20 条 R31 遗留的分诊（原判多数已闭合，实为 20 条仍存活）；D02 的 certify 推翻主 agent 四处错误。**「回执必须给命令与读数」这条设计有效**，应保留。
4. **并发会话会造成判决账撞号**：本批执行期间另一会话提交了 D-061（D01 ARCH 提案裁决）与 D-062（D01 wire 字段删除裁决），与本批原定的 D-061 冲突，已顺延为 D-063。**建议判决账编号在提交前重读文件取下一个空号**。
5. **归档审计的 100 项 FAIL 是历史债**：R17–R30 的旧格式（V3 之前的证据标准）在 `--round` 模式下不阻断，但全档审计会一直红。本批按 §3.4「单独记账、不追溯、不删证据」处理。
