# BLIND-SPOTS —— review 工作流历史盲区账本

> 每条盲区都必须有历史证据、为什么当时没发现、期望由哪个装置接住。工作流改版后，OPEN 项必须重新出现；否则改版不算进步。
> 状态只允许三种：`OPEN`（仍未稳定发现）、`DETECTED`（当前版本已能稳定发现，且最近两次回归复现）、`CLOSED`（已不可能再犯，例如规则或工具已经机械封堵）。

## B-01 翻译残留：Rust 只是 C 结构的改名

- **类别**：代码设计 / 翻译残留
- **历史证据**：项目所有者多次记录“写出来的 Rust 是 Minix3 代码的 translate 而非 rewrite”，见 `prompt/code-review-subagent.md:113`；外部审查把这类残留命名为单实现依赖注入 trait、无状态 Manager 结构体、布尔或字符串状态机、哨兵返回值、clone 到能编译、`Rc<RefCell>` 对象图，见同文件 `124-131`。
- **为什么当时没发现**：既有规则反复强调“不要直译”，但审查动作停在“意图声明”，没有从 C 语义出发独立提出 Rust 方案；翻译残留表现为“看起来合理的架构”，不是语法错误。
- **期望探测器**：P-DESIGN 的第一遍（只看 C 语义与文档 Ch1/Ch2，不看现有 Rust）与第二遍（对照差异）；对抗样本 `T01`。
- **状态**：DETECTED
- **检测证据**：D01 DESIGN-01..15 报出 C 形状状态/身份；D2 逐条复核；见 `tmp/review-eval/01-stage-kernel/01-boot-shim-bootstrap/panel/design-d2.md`
