## 我重建的论证结构

这篇文档的主轴是镜像这个二进制从 ELF 文件变成高半 `kmain` 的四段：

1. 链接。`kernel.lds` 用位置计数器造出两套地址；`AT()` 只改程序头里的 `p_paddr`；低侧 `.unpaged_*` 段与高侧普通段各自保持平移一致。
2. 摆放。Makefile 的 `objcopy --prefix-symbols` 与输出文件名前缀决定哪些对象进低侧；`mpx.o` 不在改名名单里，所以 `k_initial_stktop` 落在高侧 `.bss`。
3. 映射。`pre_init` 的五步建表：`pg_identity` 全铺 4 GiB，`pg_mapkernel` 从 961 号页目录项起映射内核，`pg_load` 与 `vm_enable_paging` 的次序由 PSE 与 PG 的依赖决定。
4. 进入。`head.S` 用绝对立即数设栈、用相对 `call` 跳转；两件事必须成对且不返回；栈符号必须已在页表中可访问。

文档把这条链在两套实现上各走一遍：C 侧按源码对象（`kernel.lds`、`Makefile.inc`、`head.S`、`pg_utils.c`、`mpx.S`）展开，Rust 侧按设计决策（三形态脚本、自建解析器、派生栈顶、`HugePages` trait、2MiB 收口、四步自举根、`HigherHalf` trait）展开，再用实现章与测试章落地。第四个层次是证据：宿主解析与装载测试、`L0` 到 `L10` 的布局断言、真机 `test-higher-half`、`M1` 到 `M13` 的反转核对表。

主张层面这条链是闭合的。断点集中在分类的适用范围、章节之间的边界，以及证据归属；下面按四类列出。

## SUGGESTION

下面这些不改变论证是否成立，只影响阅读顺序与措辞。

**S-01（§2 的节序与四时刻不一致）**：§1.1 宣布“前一个时刻的产物是后一个时刻的输入”，但 §2 的顺序是链接（2.1）、低侧对象（2.2）、进入（2.3）、映射（2.4）、栈落段（2.5）。2.3 在 2.4 之前，读者要在还不知道五步建表的情况下读“恒等映射移除之后”。建议在 §2 开头声明“本章按 C 源码对象组织，四时刻的对应见 §2.6”，或者把 2.3 移到 2.4 之后。

**S-02（§2.6 的归纳表引入新证据）**：§2.6 第 4 行在“结论”单元格里写“ARM 侧同一判据也已静态核实：`earm/Makefile.inc` 的改名名单不含 `mpx.o`、`earm/mpx.S` 在 `.bss` 后切回 `.data`、`earm/kernel.lds` 的 `.unpaged_data` 只收 `unpaged_*.o`”（第 517 行）。这是新论证，不是归纳。建议移到 §2.5 的 ARM 对照段，§2.6 只留一句“ARM 侧同判据已核实，见 §2.5”。

**S-03（§1.1 与 §1.3 重复“符号值与可访问地址”）**：§1.1 第三段完整解释了“符号值在链接期确定、可访问性要等页表”，§1.3 末段又用四行重复同一区分。建议保留 §1.1 的完整解释，§1.3 改成一句“符号值与可访问地址的区分见 §1.1”。

**S-04（§3.7 的表把“不返回”放在前置条件列）**：表头是“前置条件”，第 3 行却写“不返回”，紧接着的正文又说“第 3 行记的是返回类型，不是前置条件”。建议把 `-> !` 单独列成一行“返回类型”，或者移出前置条件表，避免读者把签名当成调用者要保证的条件。

**S-05（§3.3 的自相矛盾句）**：“两个值不一样：`kernel_boot_stack_top` 是预留区的顶……`kern_stack_top` 是收口后的镜像尾，等于前者加上收口填充量（填充为零时两者相等）”（第 736 行）。前半句说不一样，括号里说可能相等。建议改成“两个符号的定义不同；填充为零时数值相等”。

**S-06（§6.1 第一行的时刻与小节对不上）**：第 1743 行说“三个时刻……见 §2.1、§2.3、§4.1 与 §4.4 的反向推演”，三个时刻对应四个小节，没有给出配对。建议逐对点名，例如“分页开启后立刻见 §4.3 其一；恒等映射被移除见 §2.3 其二与 §2.5；首次切地址空间见 §4.4 其一”。

**S-08（§4.4 的十六进制错位复算打断论证）**：第 1437 行用半段篇幅纠正源码注释里 `7ffe` 与 `7fe0` 的错位，并复算故障地址。这属于诊断注记，建议移到 §6.1 的“诊断注记”，§4.4 只留“源码注释的读数有一位错位，按 `delta` 复算得到故障地址”一句。

**S-09（§5.4 的 M12 状态自相矛盾）**：M12 写“已覆盖（手工复跑）”，证据列又写“这是一次性复跑，不是常驻 CI 断言”。建议把“覆盖状态”拆成两列或写成“已手工验证；未常驻”，不要让“已覆盖”与“不是常驻”并置。

**S-10（§3.1 的“三套分类”没有枚举）**：第 558 行说“三套分类不是同一件事”，但没有点名是哪三套。建议写成“链接脚本形态、装载路径、执行视图这三套分类不是同一件事”，让读者不必从下面的四列表反推。

**S-11（§3.2 与 §4.2 的设计与实现边界）**：§3.2 摘了 `impl Iterator for SegmentIter` 的完整 `next()`、字段偏移表和 `e_phentsize` 的反向推演；§4.2 又重新摘 `parse_ehdr` 的五道校验与 `compute_kernel_layout`。建议把迭代器实现、字段偏移表与 `e_phentsize` 反推移到 §4.2，§3.2 只保留“自建、零分配、错误分层”三条设计取舍与 12 个变体的分类，使“§3 设计决策、§4 实现详解”的分工真正成立。

## 小结

这篇文档的主张链是完整的：四时刻、J1 到 J4、C 侧的双地址与五步建表、Rust 侧的派生栈顶与 `HigherHalf` 契约，都能在正文里找到支撑。问题集中在三处：第一，J1 与 J2 的适用范围没有标注，C 侧的实例与表里的普适措辞冲突；第二，路径分类与断言清单的“权威”被 §1.3、§3.1、§3.4、§3.6、§3.8、§4.5、§4.5.1、§5.2 反复声明又反复复制，读者要自己判断哪一张表算数；第三，第 5 章的证据组织没有兑现第 1 章的承诺，M3 与 M9 还把不同侧的证据混在一起。上面 16 条 FINDING 里，READER-B-01 到 READER-B-06 是必须先解决的骨架问题，其余是骨架修好后会自然消失或变得可核对的问题。
