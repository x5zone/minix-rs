## 结构重建（读者 B 的独立骨架）

本文的骨架是「三件事」：链接期决定符号值、装载期决定段体字节落在哪个物理地址、运行期决定 CPU 从哪个地址取指和用哪个栈。

- 第 1 章立三件事，并给出一张「链接期 / 装载期 / 运行期」三列图（§1.1、§1.2）。
- 第 2 章在 C 侧把三件事各走一遍：§2.1 链接脚本的双地址与 `AT()`；§2.2 对象改名与两段式布局；§2.3 `head.S` 的设栈与跳转；§2.4 `k_initial_stktop` 的落段判据；§2.5 归纳入表。
- 第 3 章按五条 Rust 设计决策对应：§3.1 链接脚本三形态；§3.2 ELF 解析器自建；§3.3 栈顶从链接符号改为派生值；§3.4 换栈与跳转收进 `HigherHalf` trait；§3.5 镜像跨距收口到映射粒度。
- 第 4 章逐条落地：§4.1 链接脚本；§4.2 解析与按 `p_paddr` 摆放；§4.3 三架构的成对跳转；§4.4 从装载到 `kmain` 的全路径；§4.5 与 Minix3 C 的对照。
- 第 5、6 章是验证与诊断，第 7 章是参见。

这个骨架与文档的章节顺序基本一致。结构上的偏差集中在三处：§3.1 在后半段换成了第二套分类（装载路径 × 执行视图），而这套分类的主体在 §4.4；§2.2 末尾插入的 961 页目录下标属于 §3.5 的 C 侧负担；§4.4 的 `store_kernel_info` 历史叙述与临时打印偏离了「从装载到 `kmain` 的路径」这一主题。偏差本身不一定阻断阅读，但 §3.1 的「下表第 5 行」因此指错行（FINDING 1），而 §3.2 与 §4.2 对「畸形程序头」的处置说法相反（FINDING 3）。
