## 论证结构重建（独立复得）

全篇主张：`cstart` 的三行调用（`init_clock` → `intr_init` → `arch_init`）各补齐一样缺失物（软件时钟状态 / 处于已知屏蔽态的中断控制器 / 架构杂项），三者中只有 `arch_init` 读前两者的产物，故唯一不可交换的次序在 `arch_init`；持久的 tick 源刻意不在这三行里，而在启动末端（C `boot_cpu_init_timer` / Rust `boot_init_timer`）；Rust 侧以新的内部组织保持同一外部行为（Rewrite/Refactor），三架构差异以 `[ARCH: K-1/K-2/K-3]` 标注。

论证链（按章节复得）：

1. §1 建立框架：缺的三样东西与三行调用图、读/写状态表（§1.1）；控制器在链上的位置与"全屏蔽"结束态的意义、空钩子链后果（§1.2）；三架构硬件落点与"C 只覆盖两架构"关键前提（§1.3）；范围边界与可跳过项（§1.4，末尾挂"章末复述"）。
2. §2 用 C 源码证明：三行调用之间的准备段只读参数写 `kinfo`，`init_clock` 与 `intr_init` 无共享状态故可交换（§2.1）；`init_clock` 纯软件 + 范围回退（§2.2）；`intr_init` 十次写不可交换（ICW 计数状态机）与三条"看码才知"结论（§2.3）；`arch_init` 不可前置的两条依据——读 `system_hz`（§1.1 污染清单 + §2.4 调用链）与门表重建需控制器处于已定义屏蔽态（§2.4）；ARM 侧同一格的不同答法（§2.5）；持久 tick 源的三段（编程/注册/放行）在启动末端及其两条真实依赖（§2.6）；归纳两条次序原则（§2.7）。
3. §3 八条 Rust 决策：ClockArch 两层拆分（§3.1）、DEFAULT_HZ 编译期常量 + 构造器守卫（§3.2）、控制器拆 Router/PerCpuUnit（§3.3）、IRQ_MANAGER 全局（§3.4）、ArchInit 阶段 trait（§3.5）、cut_memmap 不进 ArchInit（§3.6）、三段分离 + TimerIrqGate（§3.7）、ARCH 标注落点（§3.8）。
4. §4 逐函数走查：`init_clock_and_interrupts`（§4.1，含 Step 2 条件子步与 Step2/3 对调推演）、`ClockState` 形状（§4.2）、三架构 ClockArch/InterruptRouter/PerCpuUnit/ArchInit（§4.3–4.6）、`boot_init_timer` 四件事与多级门（§4.7 + 4.7.1/4.7.2）、`register_hook` 注册路径（§4.8）、`TIMER_IRQ` 取值（§4.9）、四全局访问契约（§4.10）。
5. §5 证据：宿主读数口径（§5.1）、真机载体（§5.2）、机制→断言反转核对表 M1–M18（§5.3）、缺口披露（§5.4）。
