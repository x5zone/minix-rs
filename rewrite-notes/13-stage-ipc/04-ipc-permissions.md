# 04 — System V 权限模型：谁能碰这个对象，一次讲清

> **状态**: 已改写（2026-09-05，依据 plan.md 阶段 2 权限面边界从零写作）
> **定位**: 阶段 2 权限面（05 到 08 每个处理函数的前置原语）
> **源码**: `minix3/minix/servers/ipc/utility.c`（49 行，本篇全覆盖）；`minix3/sys/sys/ipc.h` 第 54 行到第 92 行（权限结构与标志）
> **Rust 模块**: `os/servers/ipc-server/src/perms.rs`（权限判断与掩码决策纯函数）
> **说明**: 每个处理函数在动手之前都要先问一句话：调用者有没有资格碰这个对象。本篇讲这句话的完整语义：超级用户直接放行，其他人按同用户、同组、其他人三档比对权限位。处理函数怎么用结论是 05 到 08 的事情，本篇只讲判断本身与每个调用点传什么掩码。

## 1 概念

### 1.1 目标读者与前置知识

面向已经读过 02 篇的读者。前置知识：02 篇的读权限位、写权限位、管理权限位三个常量。Unix 文件权限（所有者、组、其他人三档）如果学过则直接对应，没学过也没关系——本篇从零讲起，只需要知道"每个对象记着创建者是谁、每档允许做什么"这个想法。

### 1.2 本篇不讲什么

- 七种消息的字段含义——那是 02 的事情。
- 每个处理函数内部的流程——那是 05 到 08 的事情。
- 清单查询为什么不查权限——那是 03 讲过的事情（任何用户都能列清单，只暴露元信息）。
- 共享内存段的创建与挂接——在 07 与 08，本篇只登记它们传什么掩码。

### 1.3 为什么权限判断值得单独成篇

一个刚接触 System V 的读者最容易犯的错误，是把"权限"理解成一句话"检查一下有没有权限"。其实这里有三层意思叠在一起：第一，判断规则本身（同用户看高三位、同组看中三位、其他人看低三位，调用者要的位必须全中）；第二，每个调用点要什么（读操作要读位、写操作要写位、删除与改属性要所有者身份）；第三，两种失败长得不一样（权限位不够回访问拒绝，身份不对回操作不许可）。

把判断规则单独抽出来有两个好处。第一，八个调用点共用同一个函数，规则一次讲清，05 到 08 的每一篇都不用再解释"为什么这里传读掩码"，只引用本篇的掩码表。第二，判断函数是纯逻辑（输入四个值，输出真假），天然可单测——本篇的 Rust 代码把"查身份"与"比权限"分开，前者是跨服务查询（进程管理器才知道某端点的用户标识），后者是纯函数。Redox 操作系统的权限检查也是这个分层：身份来自可信的调用上下文，判断是纯逻辑。

### 1.4 一次权限检查的完整旅程（以读取信号量值为例）

```
1. 用户进程：发起信号量取值请求（05 篇），信里带集合标识符与序号
  → 2. 处理函数：先按标识符找到集合，再问本篇的判断函数：
     "这个调用者有没有这个集合的读权限"
  → 3. 判断函数：先问进程管理器"这个端点的用户标识与组标识是什么"，
     再按三档规则比对（本篇第 2.2 节）
  → 4. 回到处理函数：有权限则继续取值，无权限则回访问拒绝（EACCES，数值 13）
```

注意第 3 步里面的分工：身份查询走进程管理器（`getnuid`/`getngid`，库函数，向进程管理器发查询），权限比对是本地纯计算。这个分工在 Rust 侧变成显式的函数签名：判断函数接收"调用者身份"作为参数，不自己发查询——调用者（处理函数）负责把身份查好传进来。测试因此不需要模拟进程管理器，直接传身份值即可。

### 1.5 小结

权限判断由四部分组成：判断函数（三档比对）、身份来源（进程管理器查询）、掩码表（八个调用点各自要什么）、管理信息库输出拷贝（字段原样搬运）。记住这四部分，后文 05 到 08 的每一篇在动手前都会引用本篇的掩码表，不再重复解释。

## 2 C 源码分析

### 2.1 权限结构（`ipc.h` 第 54 行到第 81 行）

| 字段 | C 类型 | 含义 |
|------|--------|------|
| `uid` | 用户标识 | 当前所有者的用户标识 |
| `gid` | 组标识 | 当前所有者的组标识 |
| `cuid` | 用户标识 | 创建者的用户标识（创建后一般不变） |
| `cgid` | 组标识 | 创建者的组标识 |
| `mode` | 模式 | 九个权限位加分配标志等（低九位是权限，`SEM_ALLOC` 等是状态） |
| `_seq` | 无符号短整数 | 序号（标识符编码用，见 99） |
| `_key` | 键 | 创建时用的键 |

所有者与创建者是两套字段：`IPC_SET` 命令可以改所有者（见 05 篇），但创建者保持创建时的值。判断函数认两套（同用户看所有者或创建者任一相符），删除命令只认两套中的所有者身份（见 2.4 节）。

管理信息库输出用的结构（`ipc_perm_sysctl`，第 72 行到第 81 行）字段与上表一一对应，只是键扩成 64 位、序号带符号——给 `ipcs` 命令看的快照格式，语义与内部结构一致。

### 2.2 判断函数逐项核对（`utility.c` 第 4 行到第 32 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 取身份 | 第 10 行到第 11 行 | 查调用者端点的用户标识与组标识（进程管理器查询） |
| 截断掩码 | 第 12 行（`mode &= 0700`） | 只要高三位：调用者"想要的"永远落在高三位，后面靠移位对齐 |
| 超级用户 | 第 15 行到第 16 行（用户标识为零） | 直接放行，不看任何权限位 |
| 同用户 | 第 18 行到第 20 行（调用者等于所有者或创建者） | 取对象的低九位中的高三位，不移位 |
| 同组 | 第 21 行到第 24 行（组等于所有者组或创建者组） | 取中三位，想要的位右移三位对齐 |
| 其他人 | 第 25 行到第 29 行 | 取低三位，想要的位右移六位对齐 |
| 收尾 | 第 31 行（`mode && ((mode & req_mode) == mode)`） | 想要的位非空且全中才放行 |

收尾的两个条件值得停一下：第一，想要的位不能为空（掩码为零时直接拒绝——"什么都不要"不算有权限）；第二，想要的每一位都必须在对象档位里出现（部分命中不算）。顺序也有讲究：同用户优先于同组，同组优先于其他人——一个既是同用户又是同组的人走同用户档，不叠加。

八进制 `0700` 是"只要高三位"的意思： Unix 权限九位分三档，每档三位（读、写、执行；信号量与共享内存借用读、写两位的含义，执行位无意义）。`ACCESSPERMS`（八进制 `0777`，`stat.h` 第 189 行）是创建时从标志里取权限位的掩码（05 与 07 篇）。

### 2.3 输出拷贝逐项核对（`utility.c` 第 38 行到第 49 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 清零 | 第 41 行 | 输出结构先整体清零（无残留） |
| 搬运 | 第 42 行到第 48 行 | 键、用户、组、创建用户、创建组、模式、序号七个字段原样拷贝 |

纯搬运，无判断。给管理信息库组装函数（05 的 `get_sem_mib_info`、08 的 `get_shm_mib_info`）用的。

### 2.4 掩码调用点矩阵（八个调用点）

| 调用点 | C 位置 | 传什么 | 失败回什么 |
|--------|------|--------|-----------|
| 信号量创建（已存在集合） | `sem.c:107` | 创建标志原样（标志里含权限位，见 05 篇） | 访问拒绝 |
| 信号量取值类（SETVAL/SETALL） | `sem.c:520` | 写位 | 访问拒绝 |
| 信号量取值类（其余） | `sem.c:536` | 读位 | 访问拒绝 |
| 信号量删除与改属性 | `sem.c:524-529` | 不走判断函数：比所有者身份（创建者或所有者或超级用户），否则回操作不许可 | 操作不许可（数值 1） |
| 信号量操作 | `sem.c:705` | 按操作内容组装：全是零操作则读位，否则写位 | 访问拒绝 |
| 共享内存创建（已存在段） | `shm.c:65` | 创建标志原样 | 访问拒绝 |
| 共享内存挂接 | `shm.c:156` | 只读挂接则读位，否则读加写两位 | 访问拒绝 |
| 共享内存状态查询 | `shm.c:305` | 读位 | 访问拒绝 |
| 共享内存删除与改属性 | `shm.c`（与信号量同款） | 比所有者身份，否则回操作不许可 | 操作不许可 |

两处"不走判断函数"值得记住：删除与改属性要的是"身份"（你是所有者吗），不是"权限位"（你的档位里有写位吗）——超级用户照样放行，但普通用户即使档位里有写位也不是所有者就拒绝。失败码也不同：权限位不够是访问拒绝，身份不对是操作不许可。这是 05 与 08 两篇都要引用的差异。

## 3 Rust 设计决策

| 编号 | 决策 | C 做法 | Rust 做法 | 为什么这样做 |
|---|------|--------|-----------|--------|
| D1 | 身份与判断分离 | 判断函数内部查身份（第 10 行） | `check_perm(perm, caller: Identity, mode) -> bool` 纯函数；身份查询留给调用者（`perms.rs`） | 查身份要跨服务发消息，纯判断不需要；分开后判断可单测，不用模拟进程管理器；与 Redox 的"上下文给身份、逻辑做判断"同款分层 |
| D2 | 权限结构去指针化 | 结构体尾部带私有指针（`_sem_base`，`sem.h:65`） | `IpcPerm` 只含七个值字段，无指针（`perms.rs`） | 私有指针是 C 实现细节（plan 已记排除）；Rust 侧集合数据由所有者持有，去掉指针后结构可拷贝可比较 |
| D3 | 掩码表变函数 | 八个调用点各写各的掩码表达式 | `resolve_*_mask` 四个纯函数（信号量控制、信号量操作、共享内存挂接、共享内存控制）加 `is_owner_or_root`（`perms.rs`） | 掩码规则集中一处可审查；05 到 08 调用函数不写表达式；测试枚举全部命令不断言遗漏 |
| D4 | 失败码随判决走 | 调用点各自写返回码 | 判决枚举 `AccessVerdict::{Allow, DenyAccess, DenyOwnership}` 加 `to_errno()`（`perms.rs`） | 访问拒绝与操作不许可的差异变成类型（2.4 节的差异 solicit 显式）；调用点只转码不决策 |
| D5 | 输出拷贝变构造 | 清零加逐字段赋值（第 41 行到第 48 行） | `IpcPermSysctl::from_perm(&IpcPerm)`（`perms.rs`） | 构造即完整，无"忘了清零"一说；字段增减时编译器逼迫同步 |

微内核对照（类比，不是移植依据）：Redox 的方案服务在打开文件时同样先问"调用者身份有没有这个路径的权限"，身份来自内核给的调用上下文，判断是纯逻辑——与本篇 D1 同构。seL4 的能力系统更进一步（权限跟着令牌走，不用查表），但 Minix3 保持经典的三档位模式，本篇不发明新语义，只把 C 的隐含分工变成显式签名。

替代方案及否决：把身份查询也包进判断函数（签名里收端点，内部调进程管理器）——否决，因为跨服务查询在测试与无内核环境下不可用，会把八个纯逻辑测试变成集成测试；身份作为参数传入后，判断函数在任何环境可测。

## 4 实现详解

### 4.1 模块结构

```
os/servers/ipc-server/src/
  perms.rs        — 权限结构、身份、判断函数、掩码决策、输出构造（本篇 D1 到 D5 的落地）
```

### 4.2 关键类型与函数

**结构与身份**（`perms.rs`）：

- `IpcPerm { key, uid, gid, creator_uid, creator_gid, mode, seq }`：对应 C 的 `ipc_perm`（去指针后）。
- `Identity { uid, gid }`：调用者身份，调用者负责查好传进来。
- `IpcPermSysctl`：管理信息库输出快照，`from_perm` 构造。

**判断与判决**（`perms.rs`）：

- `check_perm(perm: &IpcPerm, caller: Identity, mode: u32) -> bool`：第 12 行到第 31 行的逐行对应（截断、超级用户、三档、收尾双条件）。
- `AccessVerdict` 枚举：`Allow`（零）、`DenyAccess`（访问拒绝）、`DenyOwnership`（操作不许可），`to_errno() -> i32`。
- `is_owner_or_root(perm: &IpcPerm, uid: u32) -> bool`：删除与改属性的身份规则（所有者或创建者或超级用户）。

**掩码决策**（`perms.rs`）：

- `resolve_semctl_mask(cmd: u32) -> SemctlAccess`：取值设值类回写位检查、删除改属性回身份检查、信息查询回放行、其余回读位检查。
- `resolve_semop_mask(has_nonzero: bool) -> u32`：有非零操作则写位，否则读位。
- `resolve_shmat_mask(flag: u32) -> u32`：只读标志则读位，否则读加写。
- `resolve_shmctl_stat_needs / identity cmds`：状态查询读位、删除改属性身份检查。

### 4.3 关键不变量

- 掩码截断先行：任何判断先取高三位，测试用超限掩码验证。
- 空掩码拒绝：想要零位时返回假（收尾第一条件），测试钉住。
- 身份检查与权限检查不混用：删除路径只认身份，测试用"有写位但非所有者"验证拒绝。

## 6 过渡
