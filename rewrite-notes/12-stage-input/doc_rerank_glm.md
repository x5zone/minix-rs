## 1. C 真序

### 1.0 阶段类型判定

**服务事件循环型**（主骨架：RS 加载 → SEF → input_init 四步 → chardriver_task 主循环 → 双类消息分发）+ **事件旅程型与驱动生命周期型**（双次主线：一次输入事件从驱动到读者/终端的三级跳板；驱动从宣告到断开的布告栏生命周期；外加 LED 状态流这条反向支线——三线并行是本 stage 区别于姊妹 stage 的结构特征，plan §1.3 已定，正文 00§1.4-1.5 已落实）。判定理由：input 的主循环由框架提供（02），业务 handler 是纯判决（06~11），全部复杂性在"消息怎么分类、事件怎么路由、挂起怎么唤醒"——典型的服务事件循环型，但外部消费者（TTY/pckbd）契约占比高，故次主线用旅程而非协议表。
