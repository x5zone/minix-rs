## 1. C 真序

### 1.1 阶段类型判定

判定为**服务事件循环型**（最小服务器：658 行 C）。SCHED 由 RS 启动，`main()`（`main.c:22`）进入无限循环；启动段只有 `sys_getmachine` 与 `init_scheduling` 两个动作；全部业务在"收消息—通知优先—五路分发—回复"循环内。与其它服务器不同：SCHED 的稳态产品是"内核参数下发"与"队列平衡"两个异步机制，而非请求处理。

### 1.2 真序表

**启动段**：

| 步 | 动作 | C 锚点 | 说明 |
|----|------|--------|------|
| S01 | RS 从 boot image 启动 SCHED（`SRV_F` 系统服务） | `rs/table.c` 私有表；交叉引用 03-stage-rs | 阶段入口 |
| S02 | `main()` → `sef_local_startup()` | `main.c:22,111` | `main.c:111-121` |
| S03 | SEF 二注册：`sef_cb_init_fresh` + `SEF_CB_INIT_RESTART_STATEFUL` | `main.c:114-115` | 无信号回调 |
| S04 | `sef_startup()` → `sef_cb_init_fresh` | `main.c:120,126` | boot 锚点 |
| S05 | `sys_getmachine(&machine)`（processors_count/bsp_id）；失败 panic | `main.c:130-131` | 机器拓扑 |
| S06 | `init_scheduling()`：`balance_timeout=5×sys_hz()` + `sys_setalarm`；失败 panic | `main.c:133`、`schedule.c:334-342` | 队列平衡定时器 |

**结论：保留 00-14 + 99 的 16 篇编号与顺序；不新增、不合并、不拆分；全部原地重建。** 理由：① 顺序与启动/消息/模型/服务/机制/契约的分层一致，无前向引用（§9.1）；② 缺陷是版本漂移（测试数、Rust 锚、接线现状）与三处事实错误（错误码偏离、终止性论证、队列范围），重编排无收益；③ 唯一候选"把 12/13/14 拆/合"均不成立：12（内核双向）与 13/14（PM/RS 客户端）读者不同，且各自有独立 wire 面；④ 新增长点（ARCH 状态、偏离台账、接线现状、测试基线）统一进 99 与对应篇。

- 归哪一篇：99 篇的 ARCH 状态表（K-156，新增节）。
- 验收标准：A-1…A-8 逐项一条状态（已落地／待接线），每项带 Rust 符号锚，与各篇 D 系列不冲突。

### 7.7 G-07 PM/RS 侧接线 DEFERRED 未披露

- 主题是什么：PM 侧的 `sched_start` 调用点与退出路径仍是 DEFERRED 占位（`os/servers/pm/src/init.rs:677,708,721-726`、`os/servers/pm/src/exit.rs:481`）；RS 侧的纯决策模块把生产接线交给 19 层，模块头写着"fail-closed until then — ARCH A-12"（`os/servers/rs/src/sched.rs:9-10`，另有 `awaiting-wiring` 注释在 172、209 行）。旧 13／14 篇按"已有实现／已接线"写。

### 7.8 G-08 05 队列范围笔误（0..16）

- 主题是什么：旧 05 篇把队列编号写成 `0..16`（真值是 `NR_SCHED_QUEUES` 给出的 `0..15`）。C 侧真值在 `minix3/minix/include/minix/config.h:66-72`：`NR_SCHED_QUEUES` 为 16、`MIN_USER_Q` 为 `NR_SCHED_QUEUES - 1`（即 15）、`USER_Q` 由 `(MIN_USER_Q - MAX_USER_Q) / 2` 派生。
- 为什么重要：队列编号是优先级模型的坐标系，差一格的坐标系会让后面全部"降一级／到底停／恢复"的边界描述跟着错（08 篇的 `< MIN_USER_Q` 与 11 篇的恢复条件都依赖它）。
- 原料在哪里：`config.h:66-72`；旧文笔误位置是 05 篇的 §1.2（§2 池 K-050 的"旧位置"列）。以命令核验（命令：`rg -n '0\.\.16' 06-stage-sched/05-priority-timeslice-model.md`，实测命中第 27 行）。
- 归哪一篇：05 篇的"队列与优先级"一节（K-050，纠错点）。
- 验收标准：05 篇写 `0..15` 且与 `config.h:66-72` 对得上；同一核验命令无残留。
