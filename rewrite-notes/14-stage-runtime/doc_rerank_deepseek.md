## 1. C 真序

### 1.1 阶段类型判定

判定为**库与框架型 + 诞生链**的混合阶段：runtime 不是服务器，而是所有用户态服务共享的运行时层（`minix-rt` + `minix-sys` + `minix-types`）。真序分两条：① **诞生链**（内核交付 → crt0 → 运行时初始化 → 构造器 → main）；② **机制分层**（陷入原语 → syscall 协议 → 按服务分组的调用封装 → 分配器/诊断/常量）。

### 7.2 非 C 主题逐项落实（§3.6 的十项）

**T-01 链接与加载**
- 主题：程序为什么是静态链接、没有动态加载器，构造段怎样进入程序。

**T-02 镜像与内存布局**
- 主题：进程映像里栈与参数区怎么摆、堆从哪里长起。
- 为什么重要：初始栈与堆边界是所有内存判断的两个端点，摆错位置，后面的分配器章节全部失据。

- 为什么重要：这两段是用户态与内核之间唯一的机械接口，寄存器约定写错，后面所有协议都无从谈起。

- 原料：`os/Cargo.toml`（workspace 清单）与 `os/libs/minix-rt/Cargo.toml`、`os/libs/minix-sys/Cargo.toml`；C 侧基线 `minix3/minix/lib/libminc/Makefile`。
- 归属：99 篇（工具链与依赖一节），00 篇一句指路。
- 验收：依赖图与 Cargo 清单一致；"no_std 加 core/alloc"的表述在 00 与 99 两处一致。

**T-06 跨模块接口与线格式**
- 主题：消息体、状态字、批量槽这三类线格式。
- 为什么重要：线格式是跨进程边界的唯一契约，布局错一个字段，两端就永远对不上话。
- 原料：`minix3/minix/include/minix/ipcconst.h:6-35`（调用号与状态编码）；`minix3/minix/include/minix/ipc.h:795-803`（读写）、`:726-734`（定位）、`:2745-2762`（批量槽 `asynmsg`）、`:1887-1896`（服务查询）与同文件里的 `_ASSERT_MSG_SIZE` 断言；Rust 侧布局单源是 `minix-types` crate。
- 归属：04 篇（状态字与批量槽）、05 篇（路径双路径）、13 篇（常量）、99 篇（五十六字节负载与 `_ASSERT_MSG_SIZE`）。
- 验收：每类线格式都有一处主家给全量布局，其他篇只引用不重画。

**T-07 错误路径**
- 主题：错误号从内核到调用者要经过哪些手，失败在每一层怎么表达。
- 为什么重要：错误路径是微内核里最常见也最容易被文档省略的一段；漏掉它，读者在第一次失败时就无据可查。
- 原料：`minix3/sys/sys/errno.h:42,175,196-213`（通用错误号与 Minix 私有段）；`minix3/minix/lib/libsys/kernel_call.c:7-21`（`ENOTREADY` 退避）；`os/libs/minix-rt/src/init.rs` 的 `errno_to_negative` 与 `negative_to_errno`（正负转换单点）。
- 归属：03 篇（转换单点）、05 篇（重试）、06 篇（分配失败）、07 篇（恐慌梯子）、13 篇（全表）。
- 验收：每篇的错误分支都能对应到一个错误号来源，13 篇的表覆盖各篇用到的编号。

**T-08 关闭与退出**
- 主题：进程怎样结束，退出失败时还剩哪些兜底。
- 为什么重要：退出是每个程序的必经路径，兜底链写不清，读者会以为退出只有一条路。
- 原料：`minix3/lib/csu/common/crt0-common.c:144-192`（入口尾部的 exit 调用）；`minix3/minix/lib/libc/sys/_exit.c:12-30`（系统调用失败后发自杀信号、再失败原地挂起）。
- 归属：02 篇（尾部 exit）与 08 篇（三级兜底）。
- 验收：两篇的退出路径相互衔接，08 篇给出三级兜底的行号。

**T-09 并发与同步**
- 主题：用户态运行时的单线程假设与两处例外（批量异步发送、同步闹钟）。
- 为什么重要：单线程假设是全部共享状态用法的前提；两个例外是仅有的异步面，漏讲会让读者以为运行时到处可并发。
- 原料：`minix3/minix/lib/libsys/asynsend.c:25-139`（批量队列五步）；`minix3/minix/lib/libsys/tickdelay.c:7-19`（同步闹钟，非正参数直接返回成功）。
- 归属：99 篇（单线程假设一节）、04 篇（批量发送）与 05 篇（延迟）各讲机制。
- 验收：99 篇明确写出"单线程、无锁"的前提，两处例外都能指到具体函数。

**T-10 测试基建**
- 主题：测试分两层，crate 内的 `#[test]` 与真机脚本。
- 为什么重要：读者需要知道"跑一遍"意味着什么，也要知道真机断言只有五条、覆盖的是诞生链而不是全部行为。
- 原料：`os/qemu-tests/test-rt-birth.sh:123-127`（五条 grep 断言，分别检查描述符解析行、内核信息校验、用户栈指针、进入 main、恐慌渲染）；各篇 §5 的 `#[test]` 检索命令与 `cargo test -p minix-sys --manifest-path os/Cargo.toml`。
- 归属：各篇 §5 分别列模块测试，99 篇的测试基线一节汇总三个 crate 与真机脚本。
- 验收：各篇 §5 的计数与检索结果一致；99 篇同时给出 crate 级总数与真机断言数，并注明计数以重建当日实测为准。
