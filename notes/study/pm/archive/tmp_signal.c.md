# servers/pm/signal.c 逐行讲解

> **文件路径**: `minix3/minix/servers/pm/signal.c`
> **核心功能**: 信号处理实现——Unix 信号机制在用户态进程管理器中的实现

---

## 文件概述

### 是什么（功能说明）

这个文件实现了 **Unix 信号机制**，信号是一种**异步通知机制**，用于进程间通信和异常处理。当信号发生时，内核会中断进程的正常执行流程，转而执行信号处理函数。

**生活类比**：信号就像手机推送通知——你正在做一件事（运行程序），突然收到一条通知（信号），你需要停下来处理它（执行信号处理函数），处理完后继续原来的工作。

### 为什么（设计原因）

**为什么信号是"混乱和不愉快的事情"？**

信号设计者自己也承认（见文件头注释）：
1. **异步性**：信号可以在任何时刻到达，打乱程序执行
2. **复杂性**：信号可以被捕获、忽略、阻塞、默认处理
3. **竞争条件**：信号到达时机不确定，容易产生竞态
4. **可移植性**：不同系统的信号行为有细微差异

**为什么在用户态实现信号？**

Minix3 是微内核架构，内核只负责最基本的调度和 IPC。信号处理涉及：
- 进程表管理（PM 负责）
- 文件系统操作（VFS 负责，如 coredump）
- 用户空间信号处理函数执行

这些都不应该在内核中实现。

### 什么情景使用（应用场景）

1. **用户按 Ctrl+C**：终端发送 SIGINT 给前台进程组
2. **程序错误**：非法内存访问触发 SIGSEGV
3. **定时器**：alarm() 设置的定时器到期发送 SIGALRM
4. **进程控制**：kill 命令发送信号给指定进程
5. **调试**：gdb 使用 SIGTRAP 实现断点

## 逐行讲解

### 文件头注释

```c
/* This file handles signals, which are asynchronous events and are generally
 * a messy and unpleasant business.  Signals can be generated by the KILL
 * system call, or from the keyboard (SIGINT) or from the clock (SIGALRM).
 * In all cases control eventually passes to check_sig() to see which processes
 * can be signaled.  The actual signaling is done by sig_proc().
```

**翻译**：
> 这个文件处理信号，信号是异步事件，通常是一件混乱和不愉快的事情。信号可以由 KILL 系统调用产生，也可以来自键盘（SIGINT）或时钟（SIGALRM）。在所有情况下，控制最终传递给 check_sig() 来查看哪些进程可以被信号通知。实际的信号通知由 sig_proc() 完成。

**设计思路**：

信号处理的核心流程：
```
信号源 → check_sig() → sig_proc() → 目标进程
```

- `check_sig()`：决定"发给谁"（进程选择）
- `sig_proc()`：决定"怎么发"（信号投递）

```c
 * The entry points into this file are:
 *   do_sigaction:	perform the SIGACTION system call
 *   do_sigpending:	perform the SIGPENDING system call
 *   do_sigprocmask:	perform the SIGPROCMASK system call
 *   do_sigreturn:	perform the SIGRETURN system call
 *   do_sigsuspend:	perform the SIGSUSPEND system call
 *   do_kill:		perform the KILL system call
 *   process_ksig:	process a signal an behalf of the kernel
 *   sig_proc:		interrupt or terminate a signaled process
 *   check_sig:		check which processes to signal with sig_proc()
 *   check_pending:	check if a pending signal can now be delivered
 *   restart_sigs: 	restart signal work after finishing a VFS call
 */
```

**入口点说明**：

| 函数 | 功能 | 调用者 |
|------|------|--------|
| `do_sigaction` | 设置信号处理方式 | 用户进程 |
| `do_sigpending` | 获取待处理信号集 | 用户进程 |
| `do_sigprocmask` | 设置信号屏蔽字 | 用户进程 |
| `do_sigreturn` | 从信号处理函数返回 | 用户进程 |
| `do_sigsuspend` | 挂起进程等待信号 | 用户进程 |
| `do_kill` | 发送信号给进程 | 用户进程 |
| `process_ksig` | 处理内核产生的信号 | 内核 |
| `sig_proc` | 投递信号给进程 | PM 内部 |
| `check_sig` | 选择目标进程 | PM 内部 |
| `check_pending` | 检查待处理信号 | PM 内部 |
| `restart_sigs` | VFS 回复后恢复信号处理 | PM 内部 |

```c
{
```

**第 21-27 行**：读取新的信号处理设置
- **`act == 0`**：用户只想获取旧设置，不修改

```c
	sigaddset(&mp->mp_ignore, sig_nr);

	sigdelset(&mp->mp_ksigpending, sig_nr);

	sigdelset(&mp->mp_ignore, sig_nr);
```

**三种处理方式**：

| sa_handler | 含义 | 操作 |
|------------|------|------|
| `SIG_IGN` | 忽略信号 | 加入 ignore 集合，清除 pending |
| `SIG_DFL` | 默认处理 | 从 ignore/catch 集合移除 |
| 其他地址 | 捕获信号 | 加入 catch 集合 |

**信号掩码集合**：
```

┌──────────────────────────────────────────────────────────────┐
│ mp_ignore:    被忽略的信号                                     │
│ mp_catch:     被捕获的信号                                     │
│ mp_sigmask:   被阻塞的信号（暂时不投递）                         │
│ mp_sigpending: 待处理的信号（已发送但被阻塞）                    │
│ mp_ksigpending: 来自内核的待处理信号                           │
└──────────────────────────────────────────────────────────────┘
```

```c

  sigdelset(&svec.sa_mask, SIGKILL);
  sigdelset(&svec.sa_mask, SIGSTOP);
  mp->mp_sigact[sig_nr].sa_mask = svec.sa_mask;

  mp->mp_sigreturn = m_in.m_lc_pm_sig.ret;
  return(OK);
}
```

**第 41-48 行**：保存信号处理设置

**关键点**：
- **SIGKILL 和 SIGSTOP 不能被阻塞**：从 sa_mask 中强制移除
- **`mp_sigreturn`**：信号处理函数返回后的清理函数地址

### do_sigprocmask 函数

```c
/*===========================================================================*
 *				do_sigprocmask                               *
 *===========================================================================*/
int do_sigprocmask(void)
{
/* Note that the library interface passes the actual mask in sigmask_set,
 * not a pointer to the mask, in order to save a copy.  Similarly,
 * the old mask is placed in the return message which the library
 * interface copies (if requested) to the user specified address.
 *
 * The library interface must set SIG_INQUIRE if the 'act' argument
 * is NULL.
 *
 * KILL and STOP can't be masked.
 */
  sigset_t set;
  int i;

  assert(!(mp->mp_flags & (PROC_STOPPED | VFS_CALL | UNPAUSED | EVENT_CALL)));

  set = m_in.m_lc_pm_sigset.set;
  mp->mp_reply.m_pm_lc_sigset.set = mp->mp_sigmask;
```

**功能**：设置或获取信号屏蔽字

**翻译注释**：
> 注意库接口直接传递实际的掩码，而不是指针，以节省一次复制。类似地，旧掩码放在返回消息中，库接口会（如果请求）复制到用户指定的地址。
> 库接口必须在 'act' 参数为 NULL 时设置 SIG_INQUIRE。
> KILL 和 STOP 不能被屏蔽。

```c
  switch (m_in.m_lc_pm_sigset.how) {
      case SIG_BLOCK:
	sigdelset(&set, SIGKILL);
	sigdelset(&set, SIGSTOP);
	for (i = 1; i < _NSIG; i++) {
		if (sigismember(&set, i))
			sigaddset(&mp->mp_sigmask, i);
	}
	break;

      case SIG_UNBLOCK:
	for (i = 1; i < _NSIG; i++) {
		if (sigismember(&set, i))
			sigdelset(&mp->mp_sigmask, i);
	}
	check_pending(mp);
	break;

      case SIG_SETMASK:
	sigdelset(&set, SIGKILL);
	sigdelset(&set, SIGSTOP);
	mp->mp_sigmask = set;
	check_pending(mp);
	break;

      case SIG_INQUIRE:
	break;

      default:
	return(EINVAL);
	break;
  }
  return OK;
}
```

**四种操作模式**：

| 模式 | 操作 | 说明 |
|------|------|------|
| `SIG_BLOCK` | 阻塞信号 | 将 set 中的信号加入屏蔽字 |
| `SIG_UNBLOCK` | 解除阻塞 | 将 set 中的信号从屏蔽字移除，并检查待处理信号 |
| `SIG_SETMASK` | 设置屏蔽字 | 完全替换屏蔽字，并检查待处理信号 |
| `SIG_INQUIRE` | 查询 | 只返回当前屏蔽字，不修改 |

**关键点**：
- **解除阻塞后必须调用 `check_pending`**：可能有信号在等待
- **SIGKILL 和 SIGSTOP 不能被阻塞**：强制从 set 中移除

### do_sigsuspend 函数

```c
/*===========================================================================*
 *				do_sigsuspend                                *
 *===========================================================================*/
int do_sigsuspend(void)
{
  assert(!(mp->mp_flags & (PROC_STOPPED | VFS_CALL | UNPAUSED | EVENT_CALL)));

  mp->mp_sigmask2 = mp->mp_sigmask;	/* save the old mask */
  mp->mp_sigmask = m_in.m_lc_pm_sigset.set;
  sigdelset(&mp->mp_sigmask, SIGKILL);
  sigdelset(&mp->mp_sigmask, SIGSTOP);
  mp->mp_flags |= SIGSUSPENDED;
  check_pending(mp);
  return(SUSPEND);
}
```

**功能**：原子地替换信号屏蔽字并挂起进程

**为什么需要原子操作？**

如果分两步（先设置屏蔽字，再挂起），中间可能收到信号：
```
错误方式：
1. 设置屏蔽字
2. [信号到达，但被新屏蔽字阻塞] ← 信号丢失！
3. 挂起进程

正确方式（sigsuspend）：
1. 原子地：设置屏蔽字 + 挂起
2. [信号到达，可以投递]
3. 进程被唤醒
```

**内存模型**：
```
调用前:
mp_sigmask = 旧屏蔽字
mp_sigmask2 = 未使用

调用后:
mp_sigmask = 新屏蔽字（临时）
mp_sigmask2 = 旧屏蔽字（保存，用于恢复）
mp_flags |= SIGSUSPENDED
```

### do_sigreturn 函数

```c
/*===========================================================================*
 *				do_sigreturn				     *
 *===========================================================================*/
int do_sigreturn(void)
{
/* A user signal handler is done.  Restore context and check for
 * pending unblocked signals.
 */
  int r;

  assert(!(mp->mp_flags & (PROC_STOPPED | VFS_CALL | UNPAUSED | EVENT_CALL)));

  mp->mp_sigmask = m_in.m_lc_pm_sigset.set;
  sigdelset(&mp->mp_sigmask, SIGKILL);
  sigdelset(&mp->mp_sigmask, SIGSTOP);

  r = sys_sigreturn(who_e, (struct sigmsg *)m_in.m_lc_pm_sigset.ctx);
  check_pending(mp);
  return(r);
}
```

**翻译注释**：
> 用户信号处理函数完成。恢复上下文并检查待处理的未阻塞信号。

**功能**：从信号处理函数返回，恢复进程上下文

**流程**：
```
信号处理流程:
1. 信号到达 → 内核保存上下文到栈
2. 执行用户信号处理函数
3. 信号处理函数返回 → 调用 sigreturn
4. do_sigreturn:
   a. 恢复信号屏蔽字
   b. 调用 sys_sigreturn 恢复寄存器
   c. 检查待处理信号
5. 进程从中断点继续执行
```

### do_srv_kill 函数

```c
/*===========================================================================*
 *			      do_srv_kill				     *
 *===========================================================================*/
int do_srv_kill(void)
{
/* Perform the srv_kill(pid, signo) system call. */

  /* Only RS is allowed to use srv_kill. */
  if (mp->mp_endpoint != RS_PROC_NR)
	return EPERM;

  /* Pretend the signal comes from the kernel when RS wants to deliver a signal
   * to a system process. RS sends a SIGKILL when it wants to perform cleanup.
   * In that case, ksig == TRUE forces PM to exit the process immediately.
   */
  return check_sig(m_in.m_rs_pm_srv_kill.pid, m_in.m_rs_pm_srv_kill.nr,
	  TRUE /* ksig */);
}
```

**功能**：系统服务专用的 kill 接口

**为什么需要单独接口？**

RS（重启服务）需要强制终止系统进程：
1. 普通用户不能杀死系统进程（权限检查）
2. RS 发送的信号伪装成来自内核（`ksig = TRUE`）
3. 内核信号可以绕过某些检查

### stop_proc 函数

```c
/*===========================================================================*
 *				stop_proc				     *
 *===========================================================================*/
static int stop_proc(struct mproc *rmp, int may_delay)
{
/* Try to stop the given process in the kernel. If successful, mark the process
 * as stopped and return TRUE.  If the process is still busy sending a message,
 * the behavior depends on the 'may_delay' parameter. If set, the process will
 * be marked as having a delay call pending, and the function returns FALSE. If
 * not set, the caller already knows that the process has no delay call, and PM
 * will panic.
 */
  int r;

  assert(!(rmp->mp_flags & (PROC_STOPPED | DELAY_CALL | UNPAUSED)));

  r = sys_delay_stop(rmp->mp_endpoint);

  /* If the process is still busy sending a message, the kernel will give us
   * EBUSY now and send a SIGSNDELAY to the process as soon as sending is done.
   */
  switch (r) {
  case OK:
	rmp->mp_flags |= PROC_STOPPED;

	return TRUE;

  case EBUSY:
	if (!may_delay)
		panic("stop_proc: unexpected delay call");

	rmp->mp_flags |= DELAY_CALL;

	return FALSE;

  default:
	panic("sys_delay_stop failed: %d", r);
  }
}
```

**功能**：在内核中停止进程

**翻译注释**：
> 尝试在内核中停止给定进程。如果成功，标记进程为已停止并返回 TRUE。如果进程仍在忙于发送消息，行为取决于 'may_delay' 参数。如果设置，进程将被标记为有延迟调用待处理，函数返回 FALSE。如果未设置，调用者已经知道进程没有延迟调用，PM 将 panic。

**为什么进程可能"忙于发送消息"？**

Minix 的 IPC 是同步的：
```
进程 A 发送消息给进程 B:
1. A 调用 send(B, msg)
2. 如果 B 没在等待，A 被阻塞
3. 此时 A 无法被停止（正在发送消息）
```

**解决方案**：
- 内核返回 `EBUSY`
- 设置 `DELAY_CALL` 标志
- 等待内核发送 `SIGSNDELAY` 信号

### try_resume_proc 函数

```c
/*===========================================================================*
 *				try_resume_proc				     *
 *===========================================================================*/
static void try_resume_proc(struct mproc *rmp)
{
/* Resume the given process if possible. */
  int r;

  assert(rmp->mp_flags & PROC_STOPPED);

  /* If the process is blocked on a VFS call or a process event notification,
   * do not resume it now.  Most likely it will be unpausing, in which case the
   * process must remain stopped.  Otherwise, it will still be resumed once the
   * VFS or event call is replied to.  If the process has died, do not resume
   * it either.
   */
  if (rmp->mp_flags & (VFS_CALL | EVENT_CALL | EXITING))
	return;

   * need only be unpaused once, but once it is resumed, all bets are off.
   */
  rmp->mp_flags &= ~(PROC_STOPPED | UNPAUSED);
}
```

### sig_proc 函数（核心函数）

```c
/*===========================================================================*
 *				sig_proc				     *
 *===========================================================================*/
void
sig_proc(
	register struct mproc *rmp,	/* pointer to the process to be signaled */
	int signo,			/* signal to send to process (1 to _NSIG-1) */
	int trace,			/* pass signal to tracer first? */
	int ksig			/* non-zero means signal comes from kernel  */
)
{
/* Send a signal to a process.  Check to see if the signal is to be caught,
 * ignored, tranformed into a message (for system processes) or blocked.
 *  - If the signal is to be transformed into a message, request the KERNEL to
 * send the target process a system notification with the pending signal as an
 * argument.
 *  - If the signal is to be caught, request the KERNEL to push a sigcontext
 * structure and a sigframe structure onto the catcher's stack.  Also, KERNEL
 * will reset the program counter and stack pointer, so that when the process
 * next runs, it will be executing the signal handler. When the signal handler
 * returns,  sigreturn(2) will be called.  Then KERNEL will restore the signal
 * context from the sigcontext structure.
 * If there is insufficient stack space, kill the process.
 */
  int slot, badignore;

  slot = (int) (rmp - mproc);
  if ((rmp->mp_flags & (IN_USE | EXITING)) != IN_USE) {
	panic("PM: signal %d sent to exiting process %d\n", signo, slot);
  }
```

**翻译注释**：
> 发送信号给进程。检查信号是否要被捕获、忽略、转换为消息（对于系统进程）或阻塞。
> - 如果信号要转换为消息，请求内核发送系统通知给目标进程。
> - 如果信号要被捕获，请求内核将 sigcontext 和 sigframe 结构压入捕获者的栈。内核还会重置程序计数器和栈指针，这样进程下次运行时将执行信号处理函数。当信号处理函数返回时，将调用 sigreturn(2)。然后内核将从 sigcontext 结构恢复信号上下文。
> 如果栈空间不足，杀死进程。

**信号处理决策树**：
```
信号到达
    │
    ├─→ 进程被调试？ → 通知调试器
    │
    ├─→ 进程在 VFS 调用中？ → 挂起信号，等待 VFS 回复
    │
    ├─→ 系统进程？ → 转换为消息或终止
    │
    ├─→ 信号被忽略？ → 丢弃
    │
    ├─→ 信号被阻塞？ → 加入待处理队列
    │
    ├─→ 信号被捕获？ → 设置信号处理函数
    │
    └─→ 默认处理 → 终止/忽略/停止
```

### check_sig 函数

```c
/*===========================================================================*
 *				check_sig				     *
 *===========================================================================*/
int check_sig(proc_id, signo, ksig)
pid_t proc_id;			/* pid of proc to sig, or 0 or -1, or -pgrp */
int signo;			/* signal to send to process (0 to _NSIG-1) */
int ksig;			/* non-zero means signal comes from kernel  */
{
/* Check to see if it is possible to send a signal.  The signal may have to be
 * sent to a group of processes.  This routine is invoked by the KILL system
 * call, and also when the kernel catches a DEL or other signal.
 */

  register struct mproc *rmp;
  int count;			/* count # of signals sent */
  int error_code;

  if (signo < 0 || signo >= _NSIG) return(EINVAL);

  /* Return EINVAL for attempts to send SIGKILL to INIT alone. */
  if (proc_id == INIT_PID && signo == SIGKILL) return(EINVAL);

  /* Signal RS first when broadcasting SIGTERM. */
  if (proc_id == -1 && signo == SIGTERM)
      sys_kill(RS_PROC_NR, signo);
```

**功能**：选择目标进程并发送信号

**pid 参数含义**：

| pid 值 | 含义 |
|--------|------|
| > 0 | 发送给指定 PID 的进程 |
| 0 | 发送给调用者进程组的所有进程 |
| -1 | 发送给所有进程（广播） |
| < -1 | 发送给指定进程组的所有进程 |

**特殊处理**：
- **不能杀死 INIT**：INIT 是系统关键进程
- **广播 SIGTERM 时先通知 RS**：让 RS 有机会清理

```c
  /* Search the proc table for processes to signal. Start from the end of the
   * table to analyze core system processes at the end when broadcasting.
   * (See forkexit.c about pid magic.)
   */
  count = 0;
  error_code = ESRCH;
  for (rmp = &mproc[NR_PROCS-1]; rmp >= &mproc[0]; rmp--) {
	if (!(rmp->mp_flags & IN_USE)) continue;

	/* Check for selection. */
	if (proc_id > 0 && proc_id != rmp->mp_pid) continue;
	if (proc_id == 0 && mp->mp_procgrp != rmp->mp_procgrp) continue;
	if (proc_id == -1 && rmp->mp_pid <= INIT_PID) continue;
	if (proc_id < -1 && rmp->mp_procgrp != -proc_id) continue;

	/* Do not kill servers and drivers when broadcasting SIGKILL. */
	if (proc_id == -1 && signo == SIGKILL &&
		(rmp->mp_flags & PRIV_PROC)) continue;

	/* Skip VM entirely as it might lead to a deadlock with its signal
	 * manager if the manager page faults at the same time.
	 */
	if (rmp->mp_endpoint == VM_PROC_NR) continue;

	/* Disallow lethal signals sent by user processes to sys processes. */
	if (!ksig && SIGS_IS_LETHAL(signo) && (rmp->mp_flags & PRIV_PROC)) {
	    error_code = EPERM;
	    continue;
	}

	/* Check for permission. */
	if (mp->mp_effuid != SUPER_USER
	    && mp->mp_realuid != rmp->mp_realuid
	    && mp->mp_effuid != rmp->mp_realuid
	    && mp->mp_realuid != rmp->mp_effuid
	    && mp->mp_effuid != rmp->mp_effuid) {
		error_code = EPERM;
		continue;
	}

	count++;
	if (signo == 0 || (rmp->mp_flags & EXITING)) continue;

	/* 'sig_proc' will handle the disposition of the signal.  The
	 * signal may be caught, blocked, ignored, or cause process
	 * termination, possibly with core dump.
	 */
	sig_proc(rmp, signo, TRUE /*trace*/, ksig);

	if (proc_id > 0) break;	/* only one process being signaled */
  }

  /* If the calling process has killed itself, don't reply. */
  if ((mp->mp_flags & (IN_USE | EXITING)) != IN_USE) return(SUSPEND);
  return(count > 0 ? OK : error_code);
}
```

**进程选择逻辑**：

1. **遍历进程表**：从后向前（系统进程在后面）
2. **选择匹配的进程**：根据 pid 参数
3. **跳过特殊进程**：
   - 广播 SIGKILL 时跳过系统进程
   - 跳过 VM（避免死锁）
4. **权限检查**：
   - 超级用户可以发信号给任何进程
   - 普通用户只能发给自己的进程
5. **调用 sig_proc**：实际发送信号

### check_pending 函数

```c
/*===========================================================================*
 *				check_pending				     *
 *===========================================================================*/
void
check_pending(register struct mproc *rmp)
{
  /* Check to see if any pending signals have been unblocked. Deliver as many
   * of them as we can, until we have to wait for a reply from VFS first.
   *
   * There are several places in this file where the signal mask is
   * changed.  At each such place, check_pending() should be called to
   * check for newly unblocked signals.
   */
  int i;
  int ksig;

  for (i = 1; i < _NSIG; i++) {
	if (sigismember(&rmp->mp_sigpending, i) &&
		!sigismember(&rmp->mp_sigmask, i)) {
		ksig = sigismember(&rmp->mp_ksigpending, i);
		sigdelset(&rmp->mp_sigpending, i);
		sigdelset(&rmp->mp_ksigpending, i);
		sig_proc(rmp, i, FALSE /*trace*/, ksig);

		if (rmp->mp_flags & (VFS_CALL | EVENT_CALL)) {
			/* Signals must be rechecked upon return from the new
			 * VFS call, unless the process was killed. In both
			 * cases, the process is stopped.
			 */
			assert(rmp->mp_flags & PROC_STOPPED);
			break;
		}
	}
  }
}
```

**功能**：检查并投递待处理的信号

**调用时机**：
- 解除信号阻塞后（SIG_UNBLOCK, SIG_SETMASK）
- 从信号处理函数返回后（do_sigreturn）
- 从 sigsuspend 返回后

**投递逻辑**：
1. 遍历所有信号
2. 如果信号待处理且未阻塞
3. 调用 `sig_proc` 投递
4. 如果需要等待 VFS，停止遍历

### unpause 函数

```c
/*===========================================================================*
 *				unpause					     *
 *===========================================================================*/
static int
unpause(
	struct mproc *rmp		/* which process */
)
{
/* A signal is to be sent to a process.  If that process is hanging on a
 * system call, the system call must be terminated with EINTR.  First check if
 * the process is hanging on an PM call.  If not, tell VFS, so it can check for
 * interruptible calls such as READs and WRITEs from pipes, ttys and the like.
 */
  message m;

  assert(!(rmp->mp_flags & (VFS_CALL | EVENT_CALL)));

  /* If the UNPAUSED flag is set, VFS replied to an earlier unpause request. */
  if (rmp->mp_flags & UNPAUSED) {
	assert((rmp->mp_flags & (DELAY_CALL | PROC_STOPPED)) == PROC_STOPPED);

	return TRUE;
  }

  /* If the process is already stopping, don't do anything now. */
  if (rmp->mp_flags & DELAY_CALL)
	return FALSE;

  /* Check to see if process is hanging on a WAIT or SIGSUSPEND call. */
  if (rmp->mp_flags & (WAITING | SIGSUSPENDED)) {
	/* Stop the process from running. Do not interrupt the actual call yet.
	 * sig_send() will interrupt the call and resume the process afterward.
	 * No delay calls: we know for a fact that the process called us.
	 */
	stop_proc(rmp, FALSE /*may_delay*/);

	return TRUE;
  }

  /* Not paused in PM. Let VFS, and after that any matching process event
   * subscribers, try to unpause the process. The process needs to be stopped
   * for this. If it is not already stopped, try to stop it now. If that does
   * not succeed immediately, postpone signal delivery.
   */
  if (!(rmp->mp_flags & PROC_STOPPED) && !stop_proc(rmp, TRUE /*may_delay*/))
	return FALSE;

  memset(&m, 0, sizeof(m));
  m.m_type = VFS_PM_UNPAUSE;
  m.VFS_PM_ENDPT = rmp->mp_endpoint;

  tell_vfs(rmp, &m);

  return FALSE;
}
```

**功能**：中断进程的阻塞调用

**POSIX 要求**：信号必须中断某些阻塞调用（如 read、wait），返回 EINTR

**处理流程**：
1. 如果进程在 PM 中阻塞（WAITING, SIGSUSPENDED）：直接停止
2. 如果进程可能在 VFS 中阻塞：通知 VFS 检查
3. 返回 FALSE 表示需要等待 VFS 回复

### sig_send 函数

```c
/*===========================================================================*
 *				sig_send				     *
 *===========================================================================*/
static int
sig_send(
	struct mproc *rmp,		/* what process to spawn a signal handler in */
	int signo			/* signal to send to process (1 to _NSIG-1) */
)
{
/* The process is supposed to catch this signal. Spawn a signal handler.
 * Return TRUE if this succeeded, FALSE otherwise.
 */
  struct sigmsg sigmsg;
  int i, r, sigflags, slot;

  assert(rmp->mp_flags & PROC_STOPPED);

  sigflags = rmp->mp_sigact[signo].sa_flags;
  slot = (int) (rmp - mproc);

  if (rmp->mp_flags & SIGSUSPENDED)
	sigmsg.sm_mask = rmp->mp_sigmask2;
  else
	sigmsg.sm_mask = rmp->mp_sigmask;
  sigmsg.sm_signo = signo;
  sigmsg.sm_sighandler =
	(vir_bytes) rmp->mp_sigact[signo].sa_handler;
  sigmsg.sm_sigreturn = rmp->mp_sigreturn;
```

**功能**：设置信号处理函数

**sigmsg 结构**：
```c
struct sigmsg {
    sigset_t sm_mask;        // 信号屏蔽字
    int sm_signo;            // 信号编号
    vir_bytes sm_sighandler; // 信号处理函数地址
    vir_bytes sm_sigreturn;  // sigreturn 函数地址
};
```

```c
  for (i = 1; i < _NSIG; i++) {
	if (sigismember(&rmp->mp_sigact[signo].sa_mask, i))
		sigaddset(&rmp->mp_sigmask, i);
  }

  if (sigflags & SA_NODEFER)
	sigdelset(&rmp->mp_sigmask, signo);
  else
	sigaddset(&rmp->mp_sigmask, signo);

  if (sigflags & SA_RESETHAND) {
	sigdelset(&rmp->mp_catch, signo);
	rmp->mp_sigact[signo].sa_handler = SIG_DFL;
  }
  sigdelset(&rmp->mp_sigpending, signo);
  sigdelset(&rmp->mp_ksigpending, signo);

  /* Ask the kernel to deliver the signal */
  r = sys_sigsend(rmp->mp_endpoint, &sigmsg);
  /* sys_sigsend can fail legitimately with EFAULT or ENOMEM if the process
   * memory can't accommodate the signal handler.  The target process will be
   * killed in that case, so do not bother interrupting or resuming it.
   */
  if(r == EFAULT || r == ENOMEM) {
	return(FALSE);
  }
  /* Other errors are unexpected pm/kernel discrepancies. */
  if (r != OK) {
	panic("sys_sigsend failed: %d", r);
  }
```

**信号处理标志**：

| 标志 | 含义 |
|------|------|
| `SA_NODEFER` | 执行信号处理函数时不阻塞该信号 |
| `SA_RESETHAND` | 信号处理后恢复为默认处理 |

**sys_sigsend 失败原因**：
- `EFAULT`：用户栈空间不足
- `ENOMEM`：内存不足

### 为什么这样设计？

1. **分层处理**：
   - `check_sig`：进程选择
   - `sig_proc`：信号投递决策
   - `sig_send`：实际设置信号处理函数

2. **异步安全**：
   - 进程可能在任何状态收到信号
   - 使用 `PROC_STOPPED` 标志确保一致性

3. **VFS 协作**：
   - 进程可能在 VFS 调用中阻塞
   - 需要通知 VFS 中断阻塞调用

```rust
#![no_std]

pub const _NSIG: usize = 64;

#[derive(Clone, Copy, Default, PartialEq, Eq)]
pub struct SigSet(pub u64);

impl SigSet {
    pub const fn empty() -> Self {
        Self(0)
    }
    
    pub fn add(&mut self, signo: usize) {
        if signo > 0 && signo < _NSIG {
            self.0 |= 1u64 << (signo - 1);
        }
    }
    
    pub fn del(&mut self, signo: usize) {
        if signo > 0 && signo < _NSIG {
            self.0 &= !(1u64 << (signo - 1));
        }
    }
    
    pub fn is_member(&self, signo: usize) -> bool {
        if signo > 0 && signo < _NSIG {
            (self.0 & (1u64 << (signo - 1))) != 0
        } else {
            false
        }
    }
}

bitflags::bitflags! {
    #[derive(Clone, Copy, Default)]
    pub struct ProcFlags: u32 {
        const IN_USE = 0x001;
        const ZOMBIE = 0x002;

        const EVENT_CALL = 0x008;
        const PROC_STOPPED = 0x010;

        const UNPAUSED = 0x040;
```

### do_sigaction Rust 实现

```rust
#[derive(Debug)]
pub enum SigError {
    InvalidSignal,
    DataCopyFailed(i32),
}

pub fn do_sigaction(
    mp: &mut MProc,
    m_in: &Message,
    who_e: i32,
) -> Result<(), SigError> {
    assert!(!mp.mp_flags.intersects(
        ProcFlags::PROC_STOPPED | ProcFlags::VFS_CALL | 
        ProcFlags::UNPAUSED | ProcFlags::EVENT_CALL
    ));
    
    let sig_nr = m_in.get_lc_pm_sig_nr() as usize;
    
    if sig_nr == SIGKILL {
        return Ok(());
    }
    if sig_nr < 1 || sig_nr >= _NSIG {
        return Err(SigError::InvalidSignal);
    }
    
    let oact_ptr = m_in.get_lc_pm_sig_oact();
    if oact_ptr != 0 {
        let old_action = mp.mp_sigact[sig_nr];
        sys_datacopy_to_user(who_e, oact_ptr, &old_action)?;
    }
    
    let act_ptr = m_in.get_lc_pm_sig_act();
    if act_ptr == 0 {
        return Ok(());
    }
    
    let svec: SigAction = sys_datacopy_from_user(who_e, act_ptr)?;
    
    match svec.sa_handler {
        SIG_IGN => {
            mp.mp_ignore.add(sig_nr);
            mp.mp_sigpending.del(sig_nr);
            mp.mp_ksigpending.del(sig_nr);
            mp.mp_catch.del(sig_nr);
        }
        SIG_DFL => {
            mp.mp_ignore.del(sig_nr);
            mp.mp_catch.del(sig_nr);
        }
        _ => {
            mp.mp_ignore.del(sig_nr);
            mp.mp_catch.add(sig_nr);
        }
    }
    
    mp.mp_sigact[sig_nr].sa_handler = svec.sa_handler;
    let mut mask = svec.sa_mask;
    mask.del(SIGKILL);
    mask.del(SIGSTOP);
    mp.mp_sigact[sig_nr].sa_mask = mask;
    mp.mp_sigact[sig_nr].sa_flags = svec.sa_flags;
    mp.mp_sigreturn = m_in.get_lc_pm_sig_ret();
    
    Ok(())
}
```

### sig_proc Rust 实现

```rust
pub fn sig_proc(
    rmp: &mut MProc,
    signo: usize,
    trace: bool,
    ksig: bool,
) -> Result<(), SigError> {
    let slot = rmp.slot();
    
    if rmp.mp_flags.intersects(ProcFlags::EXITING) {
        panic!("signal sent to exiting process");
    }
    
    if trace && rmp.mp_tracer != NO_TRACER && signo != SIGKILL {
        rmp.mp_sigtrace.add(signo);
        if !rmp.mp_flags.contains(ProcFlags::TRACE_STOPPED) {
            trace_stop(rmp, signo);
        }
        return Ok(());
    }
    
    if rmp.mp_flags.intersects(ProcFlags::VFS_CALL | ProcFlags::EVENT_CALL) {
        rmp.mp_sigpending.add(signo);
        if ksig {
            rmp.mp_ksigpending.add(signo);
        }
        if !rmp.mp_flags.intersects(ProcFlags::PROC_STOPPED | ProcFlags::DELAY_CALL) {
            stop_proc(rmp, false)?;
        }
        return Ok(());
    }
    
    if rmp.mp_flags.contains(ProcFlags::PRIV_PROC) {
        return handle_system_signal(rmp, signo, ksig);
    }
    
    let badignore = ksig && 
        noign_sset.is_member(signo) && 
        (rmp.mp_ignore.is_member(signo) || rmp.mp_sigmask.is_member(signo));
    
    if !badignore && rmp.mp_ignore.is_member(signo) {
        return Ok(());
    }
    
    if !badignore && rmp.mp_sigmask.is_member(signo) {
        rmp.mp_sigpending.add(signo);
        if ksig {
            rmp.mp_ksigpending.add(signo);
        }
        return Ok(());
    }
    
    if !badignore && rmp.mp_catch.is_member(signo) {
        if !unpause(rmp)? {
            rmp.mp_sigpending.add(signo);
            if ksig {
                rmp.mp_ksigpending.add(signo);
            }
            return Ok(());
        }
        
        if sig_send(rmp, signo)? {
            return Ok(());
        }
    } else if !badignore && ign_sset.is_member(signo) {
        return Ok(());
    }
    
    sig_proc_exit(rmp, signo);
    Ok(())
}
```

## 要点总结

1. **信号是异步事件**：可以在任何时刻到达，需要仔细处理竞态条件
2. **分层处理**：`check_sig` 选择进程，`sig_proc` 决定处理方式，`sig_send` 实际投递
3. **VFS 协作**：信号可能需要中断 VFS 中的阻塞调用

## 灾难预演

**如果删除 `sigdelset(&svec.sa_mask, SIGKILL);` 会怎样？**

场景：用户尝试阻塞 SIGKILL
1. 用户调用 `sigaction(SIGTERM, &act, NULL)`，其中 `act.sa_mask` 包含 SIGKILL
2. 没有删除 SIGKILL，进程的 `mp_sigmask` 包含 SIGKILL
3. 某人发送 SIGKILL 给进程
4. `sig_proc` 检查 `mp_sigmask`，发现 SIGKILL 被阻塞
5. **灾难**：SIGKILL 被加入待处理队列，进程无法被杀死！

**如果删除 `check_pending(mp);` 调用会怎样？**

场景：进程阻塞了 SIGUSR1，然后解除阻塞
1. 进程调用 `sigprocmask(SIG_BLOCK, SIGUSR1)` 阻塞信号
2. 某人发送 SIGUSR1，信号被加入待处理队列
3. 进程调用 `sigprocmask(SIG_UNBLOCK, SIGUSR1)` 解除阻塞
4. 没有调用 `check_pending`
5. **灾难**：SIGUSR1 永远留在待处理队列，永远不会被投递！

## 互动自测

1. **问题**：为什么 SIGKILL 和 SIGSTOP 不能被阻塞或忽略？
   **答案**：这是系统设计的最后手段。如果进程可以阻塞 SIGKILL，系统就无法强制终止失控的进程。

2. **问题**：`mp_sigpending` 和 `mp_ksigpending` 有什么区别？
   **答案**：`mp_sigpending` 记录所有待处理信号，`mp_ksigpending` 只记录来自内核的信号。内核信号有特殊处理（如不能被安全忽略）。

3. **问题**：为什么信号处理函数执行时要阻塞该信号？
   **答案**：防止信号处理函数被递归调用。如果信号处理函数执行中又收到同一信号，会导致栈溢出。
