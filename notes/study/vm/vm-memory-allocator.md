# VM 内存分配器

## 模块整体定位

### 在系统中的作用

内存分配器模块是 VM 服务器的内存管理基础设施，负责：

1. **物理内存分配**: 分配和释放物理页框
2. **Slab 分配器**: 高效的小对象分配
3. **内存缓存**: 文件系统缓存管理
4. **备用页管理**: 为 VM 自身提供备用内存

## 核心数据结构

### 1. 物理页位图

**定义位置**: `servers/vm/alloc.c`

```c
#define NUMBER_PHYSICAL_PAGES (int)(0x100000000ULL/VM_PAGE_SIZE)
#define PAGE_BITMAP_CHUNKS BITMAP_CHUNKS(NUMBER_PHYSICAL_PAGES)

static bitchunk_t free_pages_bitmap[PAGE_BITMAP_CHUNKS];
```

**字段说明**:

| 字段 | 类型 | 大小 | 说明 |
|------|------|------|------|
| `free_pages_bitmap` | `bitchunk_t[]` | ~128KB | 物理页空闲位图，每位表示一页 |

**内存布局**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          物理页位图布局                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   32 位地址空间: 4GB / 4KB = 1,048,576 页                                   │
│   位图大小: 1,048,576 位 = 131,072 字节 ≈ 128KB                             │
│                                                                             │
│   位图结构:                                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 位图[0]: 页 0-31    (物理地址 0x00000000-0x0001F000)                │   │
│   │ 位图[1]: 页 32-63   (物理地址 0x00020000-0x0003F000)                │   │
│   │ ...                                                                 │   │
│   │ 位图[N]: 页 N*32 到 N*32+31                                         │   │
│   │ ...                                                                 │   │
│   │ 位图[32767]: 页 1048544-1048575                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   位值含义:                                                                 │
│   - 0: 页已分配                                                             │
│   - 1: 页空闲                                                               │
│                                                                             │
│   示例:                                                                     │
│   位图[0] = 0b...00001111  表示页 0-3 已分配，页 4-31 空闲                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**设计原因**:
- **位图管理**: 每位表示一页，节省内存
- **快速查找**: 使用位操作快速找到空闲页
- **全局视图**: 可以看到整个物理内存状态

### 2. 页缓存

**定义位置**: `servers/vm/alloc.c`

```c
#define PAGE_CACHE_MAX 10000
static int free_page_cache[PAGE_CACHE_MAX];
static int free_page_cache_size = 0;
```

**字段说明**:

| 字段 | 类型 | 大小 | 说明 |
|------|------|------|------|
| `free_page_cache` | `int[]` | 40KB | 最近释放的页号缓存 |
| `free_page_cache_size` | `int` | 4 字节 | 缓存中页的数量 |

**设计原因**:
- **快速分配**: 优先从缓存分配，避免位图查找
- **局部性**: 最近释放的页可能很快再次分配
- **性能优化**: 减少位图操作

### 3. 备用页队列

**定义位置**: `servers/vm/alloc.c`

```c
#define MAXRESERVEDPAGES 300
#define MAXRESERVEDQUEUES 15

static struct reserved_pages {
    struct reserved_pages *next;
    int max_available;
    int npages;
    int mappedin;
    int n_available;
    int allocflags;
    struct reserved_pageslot {
        phys_bytes phys;
        void *vir;
    } slots[MAXRESERVEDPAGES];
    u32_t magic;
} reservedqueues[MAXRESERVEDQUEUES];
```

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `next` | `reserved_pages*` | 下一个使用的队列 |
| `max_available` | `int` | 队列最大深度 |
| `npages` | `int` | 每个槽位的页数 |
| `mappedin` | `int` | 是否映射到 VM 地址空间 |
| `n_available` | `int` | 当前可用槽位数 |
| `allocflags` | `int` | 分配标志 |
| `slots` | `reserved_pageslot[]` | 槽位数组 |
| `magic` | `u32_t` | 魔数（用于健全性检查） |

**设计原因**:
- **避免循环依赖**: VM 分配内存时可能需要更新自己的页表
- **预分配**: 提前分配备用页，确保紧急情况可用
- **类型区分**: 不同用途的备用页使用不同队列

### 4. Slab 分配器

**定义位置**: `servers/vm/slaballoc.c`

```c
#define SLABSIZES 200
#define MINSIZE 8
#define MAXSIZE (SLABSIZES-1+MINSIZE)

struct sdh {
    int freeguess;
    struct slabdata *next, *prev;
    elements_t usebits;
    phys_bytes phys;
    u16_t nused;
};

struct slabdata {
    u8_t data[DATABYTES];
    struct sdh sdh;
};

static struct slabheader {
    struct slabdata *list_head;
} slabs[SLABSIZES];
```

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `slabs` | `slabheader[]` | 200 个大小类别的 slab 链表 |
| `list_head` | `slabdata*` | slab 链表头 |
| `data` | `u8_t[]` | 数据区域（约 4KB） |
| `sdh` | `sdh` | slab 头部 |
| `usebits` | `elements_t` | 使用位图 |
| `nused` | `u16_t` | 已使用对象数 |

**内存布局**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Slab 分配器布局                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   Slab 大小类别: 8, 9, 10, ..., 207 字节（共 200 个）                        │
│                                                                             │
│   每个 slab（一页）:                                                         │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 数据区域 (DATABYTES ≈ 4072 字节)                                    │   │
│   │ ┌─────────┬─────────┬─────────┬─────────┬─────────┐                │   │
│   │ │ 对象 0  │ 对象 1  │ 对象 2  │ ...     │ 对象 N  │                │   │
│   │ │ (8字节) │ (8字节) │ (8字节) │         │ (8字节) │                │   │
│   │ └─────────┴─────────┴─────────┴─────────┴─────────┘                │   │
│   │                                                                     │   │
│   │ Slab 头部 (sdh, 24 字节)                                            │   │
│   │ ┌─────────────────────────────────────────────────────────────┐    │   │
│   │ │ freeguess | next | prev | usebits | phys | nused            │    │   │
│   │ └─────────────────────────────────────────────────────────────┘    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   Slab 链表:                                                                │
│   slabs[0] (8 字节)  ─→ slab1 ─→ slab2 ─→ ... ─→ NULL                      │
│   slabs[1] (9 字节)  ─→ slab1 ─→ slab2 ─→ ... ─→ NULL                      │
│   ...                                                                       │
│   slabs[199] (207 字节) ─→ slab1 ─→ ... ─→ NULL                            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**设计原因**:
- **小对象优化**: 避免为小对象分配整页
- **减少碎片**: 相同大小的对象放在一起
- **快速分配**: 从链表头分配，O(1) 时间

### 5. 缓存页结构

**定义位置**: `servers/vm/cache.h`

```c
struct cached_page {
    dev_t dev;
    u64_t dev_offset;
    ino_t ino;
    u64_t ino_offset;
    int flags;
    struct phys_block *page;
    struct cached_page *older;
    struct cached_page *newer;
    struct cached_page *hash_next_dev;
    struct cached_page *hash_next_ino;

```

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `dev` | `dev_t` | 设备号 |
| `dev_offset` | `u64_t` | 设备偏移 |
| `ino` | `ino_t` | inode 号 |
| `ino_offset` | `u64_t` | inode 偏移 |
| `flags` | `int` | 标志位 |
| `page` | `phys_block*` | 物理块指针 |
| `older` | `cached_page*` | LRU 链表（更旧） |
| `newer` | `cached_page*` | LRU 链表（更新） |
| `hash_next_dev` | `cached_page*` | 设备哈希链 |

**设计原因**:
- **双重索引**: 可以按设备或 inode 查找
- **LRU 淘汰**: 使用 LRU 链表管理缓存
- **快速查找**: 哈希表加速查找

## 核心流程

### 1. 物理内存分配流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      物理内存分配流程 (alloc_mem)                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   输入: pages (页数), flags (分配标志)                                       │
│                                                                             │
│   步骤 1: 检查页缓存                                                         │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ if (free_page_cache_size > 0 && pages == 1) {                        │   │
│   │     cl = free_page_cache[--free_page_cache_size];                    │   │
│   │     return cl;  // 从缓存分配                                        │   │
│   │ }                                                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   步骤 2: 查找位图                                                           │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ for (i = 0; i < NUMBER_PHYSICAL_PAGES; i++) {                        │   │
│   │     if (page_isfree(i)) {                                            │   │
│   │         // 检查是否有连续 pages 个空闲页                             │   │
│   │         for (j = 0; j < pages; j++) {                                │   │
│   │             if (!page_isfree(i + j)) break;                          │   │
│   │         }                                                            │   │
│   │         if (j == pages) {                                            │   │
│   │             // 找到连续空闲页                                        │   │
│   │             for (j = 0; j < pages; j++)                              │   │
│   │                 SET_BIT(free_pages_bitmap, i + j, 0);                │   │
│   │             return i;  // 返回起始页号                               │   │
│   │         }                                                            │   │
│   │     }                                                                │   │
│   │ }                                                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   返回 NO_MEM                                                               │
│   return NO_MEM;  // 内存不足                                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```c
void free_mem(phys_bytes cl, int pages)
{
    // 步骤 1: 检查页缓存
    if (free_page_cache_size < PAGE_CACHE_MAX && pages == 1) {
        free_page_cache[free_page_cache_size++] = cl;
        return;
    }

    // 步骤 2: 更新位图
    for (i = 0; i < pages; i++) {
        SET_BIT(free_pages_bitmap, cl + i, 1);
    }
}
```

### 3. Slab 分配流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Slab 分配流程 (slaballoc)                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   输入: size (对象大小)                                                      │
│                                                                             │
│   步骤 1: 确定大小类别                                                       │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ if (size < MINSIZE) size = MINSIZE;                                  │   │
│   │ if (size > MAXSIZE) return NULL;  // 太大，不能用 slab               │   │
│   │ slab_index = size - MINSIZE;                                         │   │
│   │ s = &slabs[slab_index];                                              │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   步骤 2: 查找空闲对象                                                       │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ for (sd = s->list_head; sd; sd = sd->sdh.next) {                     │   │
│   │     if (sd->sdh.nused < ITEMSPERPAGE(size)) {                        │   │
│   │         // 这个 slab 还有空闲对象                                    │   │
│   │         // 使用 freeguess 作为提示                                   │   │
│   │         for (i = sd->sdh.freeguess; i < ITEMSPERPAGE(size); i++) {   │   │
│   │             if (!GETBIT(sd, i)) {                                    │   │
│   │                 // 找到空闲对象                                      │   │
│   │                 SETBIT(sd, i);  // 标记为已使用                      │   │
│   │                 return &sd->data[i * size];                          │   │
│   │             }                                                        │   │
│   │         }                                                            │   │
│   │     }                                                                │   │
│   │ }                                                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   步骤 3: 创建新 slab                                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ sd = newslabdata();  // 分配一页                                     │   │
│   │ ADDHEAD(sd, s);      // 加入链表头                                   │   │
│   │ SETBIT(sd, 0);       // 标记第一个对象为已使用                       │   │
│   │ return &sd->data[0]; // 返回第一个对象                               │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   返回对象指针                                                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**关键代码**:

```c
void *slaballoc(size_t size)
{
    struct slabheader *s;
    struct slabdata *sd;
    int i;

    // 步骤 1: 确定大小类别
    if (size < MINSIZE) size = MINSIZE;
    if (size > MAXSIZE) return NULL;
    GETSLAB(size, s);

    // 步骤 2: 查找空闲对象
    for (sd = s->list_head; sd; sd = sd->sdh.next) {
        if (sd->sdh.nused < ITEMSPERPAGE(size)) {
            for (i = sd->sdh.freeguess; i < ITEMSPERPAGE(size); i++) {
                if (!GETBIT(sd, i)) {
                    SETBIT(sd, i);
                    return &sd->data[i * size];
                }
            }
        }
    }

    // 步骤 3: 创建新 slab
    if (!(sd = newslabdata())) return NULL;
    ADDHEAD(sd, s);
    SETBIT(sd, 0);
    return &sd->data[0];
}
```

**关键代码**:

```c
struct cached_page *find_cached_page_bydev(dev_t dev, u64_t dev_offset,
    ino_t ino, u64_t ino_offset)
{
    u32_t hash = makehash(dev, dev_offset);
    struct cached_page *cp;

    for (cp = cache_hash_bydev[hash]; cp; cp = cp->hash_next_dev) {
        if (cp->dev == dev && cp->dev_offset == dev_offset) {
            cache_lru_touch(cp);
            return cp;
        }
    }

    return NULL;
}
```

```
│                                                                             │
│   优势:                                                                     │
│   - 快速分配：避免位图查找                                                  │
```

### 3. Slab 分配器

**原理**: 为小对象提供高效分配

```

├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   大小类别:                                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ slabs[0]: 8 字节对象   (每页约 508 个对象)                           │   │

│                                                                             │
│   Slab 结构:                                                                │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 一页 (4KB)                                                           │   │
│   │ ┌───────────────────────────────────────────────────────────────┐   │   │
│   │ │ 数据区域 (对象数组)                                            │   │   │
│   │ │ [对象0][对象1][对象2]...[对象N]                                │   │   │
│   │ └───────────────────────────────────────────────────────────────┘   │   │
│   │ ┌───────────────────────────────────────────────────────────────┐   │   │
│   │ │ Slab 头部 (sdh)                                                │   │   │
│   │ │ - freeguess: 下一个可能空闲的对象索引                          │   │   │
│   │ │ - next/prev: 链表指针                                          │   │   │
│   │ │ - usebits: 使用位图                                            │   │   │
│   │ │ - nused: 已使用对象数                                          │   │   │
│   │ └───────────────────────────────────────────────────────────────┘   │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   分配策略:                                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 1. 从链表头开始查找                                                  │   │
│   │ 2. 找到有空闲对象的 slab                                             │   │
│   │ 3. 使用 freeguess 作为提示                                           │   │
│   │ 4. 如果没有空闲 slab，分配新页                                       │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   优势:                                                                     │
│   - 小对象优化：避免为小对象分配整页                                        │
│   - 减少碎片：相同大小的对象放在一起                                        │
│   - 快速分配：O(1) 时间复杂度                                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4. LRU 缓存淘汰

**原理**: 使用 LRU 链表管理缓存

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          LRU 缓存淘汰                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   LRU 链表结构:                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ lru_newest (最新使用)                                                │   │
│   │     ↓                                                                │   │
│   │ [页A] ←→ [页B] ←→ [页C] ←→ ... ←→ [页Z]                             │   │
│   │                                           ↑                          │   │
│   │                                     lru_oldest (最久未用)            │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   访问缓存页:                                                               │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 1. 从 LRU 链表移除该页                                               │   │
│   │ 2. 将该页插入链表头（lru_newest）                                    │   │
│   │                                                                     │   │
│   │ // 访问前: [页A] ←→ [页B] ←→ [页C]                                   │   │
│   │ // 访问页B后: [页B] ←→ [页A] ←→ [页C]                                │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   淘汰缓存页:                                                               │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 1. 从 LRU 链表尾移除页（lru_oldest）                                 │   │
│   │ 2. 从哈希表移除                                                      │   │
│   │ 3. 释放物理页                                                        │   │
│   │                                                                     │   │
│   │ // 淘汰前: [页A] ←→ [页B] ←→ [页C]                                   │   │
│   │ // 淘汰页C后: [页A] ←→ [页B]                                         │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   优势:                                                                     │
│   - 自动淘汰：最久未用的页先被淘汰                                          │
│   - 简单高效：链表操作 O(1)                                                 │
│   - 局部性：保留常用页                                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```c
// 检查是否有连续 pages 个空闲页
for (j = 0; j < pages; j++) {

if (j == pages) {
    // 找到连续空闲页
```

**注意**: 需要检查连续性，不能分配不连续的页。

### 3. Slab 大小限制

**代码位置**: `slaballoc.c`

```c
#define MINSIZE 8
#define MAXSIZE (SLABSIZES-1+MINSIZE)  // 207

if (size > MAXSIZE) return NULL;  // 太大，不能用 slab
```

**设计原因**: 大对象应该直接分配整页，不使用 slab。

### 4. 缓存哈希冲突

**代码位置**: `cache.c`

```c

for (cp = cache_hash_bydev[hash]; cp; cp = cp->hash_next_dev) {
```

**设计原因**: 使用链表法处理哈希冲突。

## 灾难预演

**场景 1: 内存耗尽**

如果物理内存耗尽：
```c
if (cl == NO_MEM) {
    // 无法分配内存
}
```
- 新进程无法创建
- 页错误无法处理
- 系统性能下降

**预防**: 设置内存使用上限，提前预警

**场景 2: 位图损坏**

如果位图数据损坏：
```c
// 位图显示页空闲，但实际已分配
SET_BIT(free_pages_bitmap, i, 1);  // 错误地标记为空闲
```
- 同一页被分配两次
- 数据损坏
- 系统崩溃

**预防**: 健全性检查，验证位图一致性

**场景 3: Slab 内存泄漏**

如果 slab 对象未释放：
```c
void *obj = slaballoc(16);
// 忘记调用 slabfree(obj)
```
- Slab 页无法回收
- 内存泄漏
- 性能下降

**预防**: 使用 RAII 或智能指针

**场景 4: 缓存淘汰失败**

如果缓存无法淘汰：
```c
// 所有缓存页都在使用，无法淘汰
```
- 无法插入新缓存
- 文件系统性能下降

**预防**: 设置缓存上限，强制淘汰
