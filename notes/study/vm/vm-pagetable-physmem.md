# VM 页表与物理内存管理

## 模块整体定位

### 在系统中的作用

页表与物理内存管理模块是 VM 服务器的核心基础设施，负责：

1. **页表管理**: 管理进程的虚拟地址空间映射
2. **物理页框分配**: 分配和释放物理内存页
3. **地址转换**: 虚拟地址到物理地址的映射
4. **权限控制**: 设置页的读写执行权限
5. **VM 自身内存管理**: 为 VM 服务器分配内存

## 核心数据结构

### 1. 页表结构 (pt_t)

**定义位置**: `servers/vm/pt.h`

```c
typedef struct {
    u32_t *pt_dir;              /* 页目录指针（VM 地址空间） */
    u32_t pt_dir_phys;          /* 页目录物理地址 */
    u32_t *pt_pt[ARCH_VM_DIR_ENTRIES];  /* 页表指针数组 */
    u32_t pt_virtop;            /* 查找空洞的提示地址 */
} pt_t;
```

**字段说明**:

| 字段 | 类型 | 大小 | 说明 |
|------|------|------|------|
| `pt_dir` | `u32_t*` | 4 字节 | 页目录虚拟地址，包含 ARCH_VM_DIR_ENTRIES 个条目 |
| `pt_dir_phys` | `u32_t` | 4 字节 | 页目录物理地址，用于加载 CR3 |
| `pt_pt` | `u32_t**` | 4 × 1024 字节 | 页表指针数组，每个 PDE 对应一个页表 |
| `pt_virtop` | `u32_t` | 4 字节 | 查找虚拟地址空洞的提示 |

**内存布局**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          页表结构内存布局                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   pt_t 结构                                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ pt_dir ──────────────────┐                                          │   │
│   │ pt_dir_phys: 0x1234000   │                                          │   │
│   │ pt_pt[0..1023] ─────────┐│                                          │   │
│   │ pt_virtop: 0x400000     ││                                          │   │
│   └──────────────────────────│───────────────────────────────────────────┘   │
│                              │                                               │
│   页目录（4KB）              │                                               │
│   ┌──────────────────────────│───────────────────────────────────────────┐   │
│   │ PDE[0]    PDE[1]    ... │ PDE[1023]                                 │   │
│   │  ├─→ pt_pt[0]           │                                            │   │
│   │  ├─→ pt_pt[1]           │                                            │   │
│   │  ...                    │                                            │   │
│   │  └─→ pt_pt[1023]        │                                            │   │
│   └──────────────────────────│───────────────────────────────────────────┘   │
│                              │                                               │
│   页表（每个 4KB）           │                                               │
│   ┌──────────────────────────┘                                            │   │
│   │ pt_pt[0] ──→ 页表 0: PTE[0] PTE[1] ... PTE[1023]                      │   │
│   │ pt_pt[1] ──→ 页表 1: PTE[0] PTE[1] ... PTE[1023]                      │   │
│   │ ...                                                                    │   │
│   │ pt_pt[1023] ──→ 页表 1023: PTE[0] PTE[1] ... PTE[1023]                │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   总大小: 约 4KB (pt_t) + 4KB (页目录) + 4KB × N (页表)                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**设计原因**:
- **二级页表**: x86 使用二级页表结构（页目录 + 页表）
- **按需分配**: 页表按需分配，节省内存
- **物理地址缓存**: `pt_dir_phys` 用于快速加载 CR3
- **虚拟地址提示**: `pt_virtop` 加速空洞查找

**架构相关定义**:

### 3. 物理块结构 (phys_block)

**定义位置**: `servers/vm/phys_region.h`

```c
struct phys_block {
    phys_bytes phys;            /* 物理地址 */
    u8_t refcount;              /* 引用计数 */
    struct phys_region *firstregion;  /* 引用链头 */
    u16_t flags;                /* 标志位 */
};
```

**字段说明**:

| 字段 | 类型 | 大小 | 说明 |
|------|------|------|------|
| `phys` | `phys_bytes` | 4 字节 | 物理地址，MAP_NONE 表示未分配 |
| `refcount` | `u8_t` | 1 字节 | 引用计数，最大 255 |
| `firstregion` | `phys_region*` | 4 字节 | 引用链头，指向第一个 phys_region |
| `flags` | `u16_t` | 2 字节 | 标志位 |

**设计原因**:
- **引用计数**: 支持写时复制和共享内存
- **引用链**: 快速遍历所有引用者
- **按需分配**: `phys` 可以是 MAP_NONE

### 4. VM 自身内存管理

**备用页机制**:

```c
#define SPAREPAGES 20          /* 备用页数量 */
#define STATIC_SPAREPAGES 15   /* 静态备用页数量 */

static char static_sparepages[VM_PAGE_SIZE*STATIC_SPAREPAGES] 
    __aligned(VM_PAGE_SIZE);   /* 静态分配的备用页 */

static void *spare_pagequeue;  /* 备用页队列 */
```

**设计原因**:
- **避免循环依赖**: VM 分配内存时可能需要更新自己的页表，需要备用页
- **静态分配**: 部分备用页静态分配，确保初始化时可用
- **动态补充**: 使用后从 alloc.c 补充

**关键代码**:

```c
int pt_new(pt_t *pt)
{
    int i, r;

    // 步骤 1: 分配页目录
    if (!(pt->pt_dir = vm_allocpage(&pt->pt_dir_phys, VMP_PAGEDIR)))
        return ENOMEM;

    // 步骤 2: 清空页目录
    for (i = 0; i < ARCH_VM_DIR_ENTRIES; i++)
        pt->pt_dir[i] = 0;

    // 步骤 3: 初始化页表指针数组
    for (i = 0; i < ARCH_VM_DIR_ENTRIES; i++)
        pt->pt_pt[i] = NULL;

    // 步骤 4: 映射内核区域
    for (i = 0; i < kernmappings; i++) {
        kern_mapping_t *km = &kern_mappings[i];
        if ((r = pt_writemap(NULL, pt, km->vir_addr, km->phys_addr,
                             km->len, km->flags, 0)) != OK)
            return r;
    }

    return OK;
}
```

### 2. 页表映射写入流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    页表映射写入流程 (pt_writemap)                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   输入: vmp (进程), pt (页表), v (虚拟地址), physaddr (物理地址),            │

│                                                                             │
│   步骤 1: 参数检查                                                           │
│   ┌─────────────────────────────────────────────────────────────────────┐   │

│                                    │                                        │
│                                    ↓                                        │

│   ┌─────────────────────────────────────────────────────────────────────┐   │

│   │                            flags, verify);                           │   │
│   │                                                                     │   │
│   │ // 遍历所有涉及的 PDE                                               │   │
│   │ // 如果 PDE 不存在，分配新的页表                                     │   │
│   │ // 调用 pt_ptalloc() 分配页表                                       │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   步骤 3: 写入页表项                                                         │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ for(p = 0; p < pages; p++) {                                         │   │
│   │     int pde = ARCH_VM_PDE(v);                                        │   │
│   │     int pte = ARCH_VM_PTE(v);                                        │   │
│   │                                                                     │   │
│   │     // 构造 PTE                                                      │   │
│   │     entry = (physaddr & ARCH_VM_ADDR_MASK) | flags;                  │   │
│   │                                                                     │   │
│   │     if (verify) {                                                    │   │
│   │         // 验证模式：检查 PTE 是否匹配                               │   │
│   │         if (maskedentry != entry) return EFAULT;                     │   │

│   │     v += VM_PAGE_SIZE;                                               │   │
│   │ }                                                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   返回 OK                                                                    │
│   return ret;                                                               │
```

**关键代码**:

```c
int pt_writemap(struct vmproc *vmp, pt_t *pt, vir_bytes v,
                phys_bytes physaddr, size_t bytes, u32_t flags,
                u32_t writemapflags)
{
    int p, pages;
    int verify = 0;
    int ret = OK;

    if (writemapflags & WMF_VERIFY)
        verify = 1;

    assert(!(bytes % VM_PAGE_SIZE));
    assert(!(flags & ~(PTF_ALLFLAGS)));

    pages = bytes / VM_PAGE_SIZE;

    // 步骤 2: 分配页表
    ret = pt_ptalloc_in_range(pt, v, v + VM_PAGE_SIZE*pages, flags, verify);
    if (ret != OK) {
        printf("VM: writemap: pt_ptalloc_in_range failed\n");
        goto resume_exit;
    }

    // 步骤 3: 写入页表项
    for (p = 0; p < pages; p++) {
        u32_t entry;
        int pde = ARCH_VM_PDE(v);
        int pte = ARCH_VM_PTE(v);

        // 构造 PTE
        entry = (physaddr & ARCH_VM_ADDR_MASK) | flags;

        if (verify) {
            // 验证模式
            u32_t maskedentry = pt->pt_pt[pde][pte];
            maskedentry &= ~(I386_VM_ACC|I386_VM_DIRTY);
            if (entry & ARCH_VM_PTE_RW)
                maskedentry |= ARCH_VM_PTE_RW;
            if (maskedentry != entry) {
                ret = EFAULT;
                goto resume_exit;
            }
        } else {
            // 写入模式
            pt->pt_pt[pde][pte] = entry;
        }

        physaddr += VM_PAGE_SIZE;
        v += VM_PAGE_SIZE;
    }

resume_exit:
    return ret;
}
```

```
│   │ // 注意: 可能递归分配 PDE（如果 VM 自身的页表不足）                  │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   步骤 3: 清空页表                                                           │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ pt->pt_pt[pde] = p;                                                  │   │
│   │                                                                     │   │
│   │ for(i = 0; i < ARCH_VM_PT_ENTRIES; i++)                              │   │
│   │     pt->pt_pt[pde][i] = 0;  // 所有 PTE 初始化为 0                  │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   步骤 4: 设置页目录项                                                       │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ pt->pt_dir[pde] = (pt_phys & ARCH_VM_ADDR_MASK) | flags              │   │
│   │                 | ARCH_VM_PDE_PRESENT | ARCH_VM_PTE_USER             │   │
│   │                 | ARCH_VM_PTE_RW;                                    │   │
│   │                                                                     │   │
│   │ // PDE 总是可写、用户可访问                                         │   │
│   │ // 权限由 PTE 控制                                                  │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ↓                                        │
│   返回 OK                                                                    │
│   return OK;                                                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**关键代码**:

```c
static int pt_ptalloc(pt_t *pt, int pde, u32_t flags)
{
    int i;
    phys_bytes pt_phys;
    u32_t *p;

    // 步骤 1: 检查参数
    assert(pde >= 0 && pde < ARCH_VM_DIR_ENTRIES);
    assert(!(flags & ~(PTF_ALLFLAGS)));
    assert(!(pt->pt_dir[pde] & ARCH_VM_PDE_PRESENT));
    assert(!pt->pt_pt[pde]);

    // 步骤 2: 分配页表内存
    if (!(p = vm_allocpage(&pt_phys, VMP_PAGETABLE)))
        return ENOMEM;

    // 处理递归分配
    if (pt->pt_pt[pde]) {
        vm_freepages((vir_bytes) p, 1);
        assert(pt->pt_pt[pde]);
        return OK;
    }
    pt->pt_pt[pde] = p;

    // 步骤 3: 清空页表
    for (i = 0; i < ARCH_VM_PT_ENTRIES; i++)
        pt->pt_pt[pde][i] = 0;

    // 步骤 4: 设置页目录项
    pt->pt_dir[pde] = (pt_phys & ARCH_VM_ADDR_MASK) | flags
                    | ARCH_VM_PDE_PRESENT | ARCH_VM_PTE_USER | ARCH_VM_PTE_RW;

    return OK;
}
```

```c
struct phys_block *pb_new(phys_bytes phys)
{
    struct phys_block *newpb;

    if (!SLABALLOC(newpb)) {
        printf("vm: pb_new: couldn't allocate phys block\n");
        return NULL;
    }

    if (phys != MAP_NONE)
        assert(!(phys % VM_PAGE_SIZE));

    newpb->phys = phys;
    newpb->refcount = 0;
    newpb->firstregion = NULL;
```

```c
struct phys_region *pb_reference(struct phys_block *newpb,
    vir_bytes offset, struct vir_region *region, mem_type_t *memtype)
{
    struct phys_region *newphysr;

    if (!SLABALLOC(newphysr)) {
        printf("vm: pb_reference: couldn't allocate phys region\n");
        return NULL;
    }

    newphysr->memtype = memtype;

    // 建立链接
    pb_link(newphysr, newpb, offset, region);

    // 设置到虚拟区域
    physblock_set(region, offset, newphysr);

    return newphysr;
}

void pb_link(struct phys_region *newphysr, struct phys_block *newpb,
    vir_bytes offset, struct vir_region *parent)
{
    newphysr->offset = offset;
    newphysr->ph = newpb;
    newphysr->parent = parent;
    newphysr->next_ph_list = newpb->firstregion;
    newpb->firstregion = newphysr;
    newpb->refcount++;
}
```

### 6. 写时复制流程

```

│   步骤 4: 更新引用                                                           │

│   │ pb_unreferenced(region, ph, 0);  // 减少旧引用                       │   │
│   │ pb_link(ph, pb, ph->offset, region);  // 建立新引用                  │   │
│   │ ph->memtype = &mem_type_anon;  // 设置为匿名内存                     │   │
│   │                                                                     │   │
│   │ // 注意: pb_unreferenced 不释放 phys_region (参数 0)                │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
```

**关键代码**:

```c
int mem_cow(struct vir_region *region,
    struct phys_region *ph, phys_bytes new_page_cl, phys_bytes new_page)
{
    struct phys_block *pb;

    // 步骤 1: 分配新物理页
    if (new_page == MAP_NONE) {
        u32_t allocflags;
        allocflags = vrallocflags(region->flags);

        if ((new_page_cl = alloc_mem(1, allocflags)) == NO_MEM)
            return ENOMEM;

        new_page = CLICK2ABS(new_page_cl);
    }

    assert(ph->ph->phys != MAP_NONE);

    // 步骤 2: 复制内容
    if (sys_abscopy(ph->ph->phys, new_page, VM_PAGE_SIZE) != OK) {
        panic("VM: abscopy failed\n");
        return EFAULT;
    }

    // 步骤 3: 创建新物理块
    if (!(pb = pb_new(new_page))) {
        free_mem(new_page_cl, 1);
        return ENOMEM;
    }

    // 步骤 4: 更新引用
    pb_unreferenced(region, ph, 0);
    pb_link(ph, pb, ph->offset, region);
    ph->memtype = &mem_type_anon;

    return OK;
}
```

## 关键机制拆解

### 1. 二级页表结构

**原理**: x86 使用二级页表将 32 位虚拟地址转换为物理地址

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          二级页表地址转换                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   虚拟地址（32 位）:                                                        │
│   ┌─────────────┬─────────────┬─────────────┐                             │
│   │  位 31-22   │  位 21-12   │  位 11-0    │                             │
│   │  PDE 索引   │  PTE 索引   │  页内偏移   │                             │
│   │  (10 位)    │  (10 位)    │  (12 位)    │                             │
│   └─────────────┴─────────────┴─────────────┘                             │
│         │               │               │                                   │
│         │               │               │                                   │
│         ↓               ↓               ↓                                   │
│   ┌─────────┐     ┌─────────┐     ┌─────────┐                             │
│   │ 页目录  │ ──→ │ 页表    │ ──→ │ 物理页  │                             │
│   │ (PDE)   │     │ (PTE)   │     │ (4KB)   │                             │
│   └─────────┘     └─────────┘     └─────────┘                             │
│                                                                             │
│   地址转换过程:                                                             │
│   1. 从 CR3 寄存器获取页目录物理地址                                        │
│   2. 使用 PDE 索引（位 31-22）查找页目录项                                  │
│   3. 从 PDE 获取页表物理地址                                                │
│   4. 使用 PTE 索引（位 21-12）查找页表项                                    │
│   5. 从 PTE 获取物理页地址                                                  │
│   6. 加上页内偏移（位 11-0）得到最终物理地址                                │
│                                                                             │
│   地址范围:                                                                 │
│   - PDE 索引: 0-1023，每个 PDE 覆盖 4MB 虚拟地址                            │
│   - PTE 索引: 0-1023，每个 PTE 覆盖 4KB 物理页                              │
│   - 总虚拟地址空间: 4GB                                                     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**关键宏定义**:

```c
#define ARCH_VM_DIR_ENTRIES  1024   /* 页目录条目数 */
#define ARCH_VM_PT_ENTRIES   1024   /* 页表条目数 */
#define VM_PAGE_SIZE         4096   /* 页大小 */

/* 提取 PDE 和 PTE 索引 */
#define ARCH_VM_PDE(v)    (((v) >> 22) & 0x3FF)  /* 位 31-22 */
#define ARCH_VM_PTE(v)    (((v) >> 12) & 0x3FF)  /* 位 21-12 */
```

### 4. VM 自身内存管理

**原理**: VM 需要管理自己的内存，避免循环依赖

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        VM 自身内存管理                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   问题:                                                                     │
│   - VM 分配内存时需要更新自己的页表                                         │
│   - 更新页表需要分配页表内存                                                │
│   - 形成循环依赖                                                            │
│                                                                             │
│   解决方案: 备用页机制                                                       │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 1. 静态备用页: 编译时分配，确保初始化时可用                          │   │
│   │    static char static_sparepages[VM_PAGE_SIZE*15];                   │   │
│   │                                                                     │   │
│   │ 2. 动态备用页: 运行时从 alloc.c 分配                                 │   │
│   │    spare_pagequeue = reservedqueue_new(SPAREPAGES);                  │   │
│   │                                                                     │   │
│   │ 3. 分配策略:                                                         │   │
│   │    - 优先使用静态备用页                                              │   │
│   │    - 然后使用动态备用页                                              │   │
│   │    - 最后从 alloc.c 分配                                             │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   分配流程:                                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ vm_allocpage() {                                                     │   │
│   │     if (level > 1 || !pt_init_done) {                                │   │
│   │         // 递归调用或初始化阶段，使用备用页                           │   │
│   │         return vm_getsparepage();                                    │   │
│   │     }                                                                │   │
│   │                                                                      │   │
│   │     // 正常分配                                                      │   │
```

## 边界条件与特殊分支

### 1. 地址对齐检查

**代码位置**: 多处

```c
// 虚拟地址必须页对齐
assert(!(v % VM_PAGE_SIZE));

// 字节数必须页对齐
assert(!(bytes % VM_PAGE_SIZE));

// 物理地址必须页对齐
assert(!(phys % VM_PAGE_SIZE));
```

**设计原因**: 页表以页为单位管理，所有地址和大小必须页对齐。

### 2. 页表存在性检查

**代码位置**: `pt_writemap()`

```c
// 检查 PDE 是否存在
if (!(pt->pt_dir[pde] & ARCH_VM_PDE_PRESENT))
    return EFAULT;

// 检查 PTE 是否存在
if (!(pt->pt_pt[pde][pte] & ARCH_VM_PTE_PRESENT))
    return EFAULT;
```

**注意**: 必须先检查 PDE，再检查 PTE。

### 3. 权限检查

**代码位置**: `pt_checkrange()`

```c
// 检查写权限
if (write && !(pt->pt_pt[pde][pte] & ARCH_VM_PTE_RW))
    return EFAULT;
```

**注意**: x86 和 ARM 的权限位不同：
- x86: `ARCH_VM_PTE_RW` 表示可写
- ARM: `ARCH_VM_PTE_RO` 表示只读

### 4. 大页处理

**代码位置**: `pt_ptalloc()`

```c
// 不允许覆盖大页
assert(!(pt->pt_dir[pde] & ARCH_VM_BIGPAGE));
```

**设计原因**: 大页（4MB）和普通页（4KB）不能混用。

### 5. 递归分配处理

**代码位置**: `pt_ptalloc()`

```c
// 处理递归分配
if (!(p = vm_allocpage(&pt_phys, VMP_PAGETABLE)))
    return ENOMEM;

if (pt->pt_pt[pde]) {
    // 递归分配已经创建了页表
    vm_freepages((vir_bytes) p, 1);
    return OK;
}
```

**设计原因**: `vm_allocpage()` 可能触发页表分配，导致递归。

## Rust 重构与设计改进建议

### 1. 类型系统改进

**当前问题**: 使用原始整数表示地址和标志位

```c
u32_t *pt_dir;      // 页目录指针
u32_t pt_dir_phys;  // 物理地址
u32_t flags;        // 标志位
```

**Rust 改进**:

```rust
use core::ops::{BitOr, BitAnd};

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct PhysAddr(pub usize);

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct VirtAddr(pub usize);

bitflags::bitflags! {
    #[derive(Clone, Copy, Debug)]
    pub struct PageFlags: u32 {
        const PRESENT = 0x001;
        const WRITABLE = 0x002;
        const USER = 0x004;
        const ACCESSED = 0x020;
        const DIRTY = 0x040;
        const GLOBAL = 0x100;
    }
}

impl PhysAddr {
    pub fn is_aligned(&self) -> bool {
        self.0 % PAGE_SIZE == 0
    }
    
    pub fn align_down(&self) -> Self {
        PhysAddr(self.0 & !(PAGE_SIZE - 1))
    }
    
    pub fn pde_index(&self) -> usize {
        (self.0 >> 22) & 0x3FF
    }
    
    pub fn pte_index(&self) -> usize {
        (self.0 >> 12) & 0x3FF
    }
}
```

**优势**:
- 编译时类型检查
- 防止混淆物理地址和虚拟地址
- 标志位类型安全

### 2. 页表结构改进

**当前问题**: 使用原始数组和指针

```c
u32_t *pt_dir;
u32_t *pt_pt[ARCH_VM_DIR_ENTRIES];
```

**Rust 改进**:

```rust
const PAGE_SIZE: usize = 4096;
const DIR_ENTRIES: usize = 1024;
const PT_ENTRIES: usize = 1024;

struct PageTable {
    dir: Box<PageDirectory>,
    dir_phys: PhysAddr,
    tables: [Option<Box<PageTableEntries>>; DIR_ENTRIES],
    virtop: VirtAddr,
}

struct PageDirectory {
    entries: [PageDirEntry; DIR_ENTRIES],
}

struct PageTableEntries {
    entries: [PageTableEntry; PT_ENTRIES],
}

#[derive(Clone, Copy)]
struct PageDirEntry {
    value: u32,
}

impl PageDirEntry {
    fn is_present(&self) -> bool {
        self.value & 0x001 != 0
    }
    
    fn phys_addr(&self) -> PhysAddr {
        PhysAddr((self.value & 0xFFFFF000) as usize)
    }
    
    fn set(&mut self, phys: PhysAddr, flags: PageFlags) {
        self.value = (phys.0 as u32 & 0xFFFFF000) | flags.bits();
    }
}

#[derive(Clone, Copy)]
struct PageTableEntry {
    value: u32,
}

impl PageTableEntry {
    fn is_present(&self) -> bool {
        self.value & 0x001 != 0
    }
    
    fn is_writable(&self) -> bool {
        self.value & 0x002 != 0
    }
    
    fn phys_addr(&self) -> PhysAddr {
        PhysAddr((self.value & 0xFFFFF000) as usize)
    }
    
    fn set(&mut self, phys: PhysAddr, flags: PageFlags) {
        self.value = (phys.0 as u32 & 0xFFFFF000) | flags.bits();
    }
}
```

**优势**:
- 类型安全的页表项
- 封装访问方法
- 使用 Option 表示可能不存在的页表

## 要点总结

1. **二级页表结构**
   - 页目录（PDE）+ 页表（PTE）
   - 32 位虚拟地址 → 物理地址
   - 每个进程一个页表

2. **按需分配页表**
   - 页表按需分配，节省内存
   - 4GB 地址空间只需 4KB 页目录
   - 每个页表覆盖 4MB 虚拟地址

3. **引用计数与共享**
   - 多个虚拟区域可共享物理页
   - 支持写时复制
   - 引用链管理所有引用者

4. **VM 自身内存管理**
   - 备用页机制避免循环依赖
   - 静态备用页确保初始化可用
   - 动态补充备用页

## 灾难预演

**场景 1: 页表项权限错误**

如果页表项权限设置错误：
```c
// 应该设置 WRITABLE 但忘记了
pt->pt_pt[pde][pte] = phys | PRESENT | USER;  // 缺少 WRITABLE
```
- 进程写入时触发页错误
- 如果错误处理不当 → 进程崩溃

**预防**: 使用宏或函数封装页表项设置

**场景 2: 引用计数溢出**

如果 `refcount` 超过 255：
```c
u8_t refcount;  // 最大 255
```
- 引用计数回绕到 0
- 物理页被错误释放
- 其他进程访问已释放的内存 → 数据损坏

**预防**: 使用更大的类型或检测溢出

**场景 3: TLB 未刷新**

如果修改页表后未刷新 TLB：
```c
pt->pt_pt[pde][pte] = new_entry;
// 忘记调用 sys_vmctl(VMCTL_FLUSHTLB)
```
- CPU 使用旧的 TLB 条目
- 访问错误的物理地址 → 数据损坏

**预防**: 每次修改页表后刷新 TLB

**场景 4: 备用页耗尽**

如果备用页耗尽：
```c
// VM 初始化时需要分配页表
// 但备用页已用完
```
- 无法分配页表
- VM 初始化失败 → 系统无法启动

**预防**: 增加备用页数量或优化分配策略
