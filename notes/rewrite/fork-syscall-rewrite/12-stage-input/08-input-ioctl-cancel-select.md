## 1. 概念：三个"顺带"的功能

### 1.1 控制：正常通道之外的绿色通道

打开、读、关闭是字符设备的"正常通道"，控制是"绿色通道"：那些不好塞进读写模型的零碎需求（调灯、查状态、特殊操作）走这里。控制请求带一个编号说明"办哪件事"，本服务只认识一件事：调灯（编号 `KIOCSLEDS`，构造见第 05 篇 2.6 节）。不认识的一律回答"不是打字机控制"——这个错误号的名字是历史遗留（终端时代控制命令的统称），意思是"我不懂这个编号"，不是字面意思。绿色通道的设计哲学是"宁缺毋滥"：只开一个口，别的口子需要时再开，不开不需要的口（每个口子都是未来的维护负担）。

调灯请求自带灯状态（调用者内存里的三位：数字锁、大写锁、滚动锁开还是关），服务把它翻译成自己的掩码语言（第几位亮，见 1.2 节），然后转交置灯逻辑（第 10 篇）。翻译与发送分开：翻译是本篇的事（纯位运算），发送是第 10 篇的事（要发消息）。控制函数本身在翻译完就回答"好"——发送成没成功，调用者不关心（灯晚亮一会，用户感知不到；且发送失败只记日志，见第 10 篇）。

### 1.2 两套灯语言：调用者的三位与服务的掩码

调用者说灯用三位（位 0、1、2 分别是数字锁、大写锁、滚动锁），服务记灯用掩码（位 1、2、3 分别是三盏灯，位号等于灯的事件码）。为什么两套？调用者的三位是键盘驱动的传统（从个人电脑时代沿用），服务的掩码是"码即位号"的统一规则（第 04 篇灯码 1、2、3，第 05 篇置灯载荷）。翻译是三行"如果调用者某位亮，就点亮服务掩码对应位"，未知位忽略（调用者可能知道服务不认识的灯，忽略是最安全的：不认识的灯不乱点）。

### 1.3 取消：凭三件套认领，把"等"叫醒

取消请求说"把那个等待叫醒，别等了"。服务凭三件套认领：调用者身份、请求编号（挂起时记下的两项，授权号不需要——授权是内存许可证，和"叫醒谁"无关）。三件套全对上才叫醒，叫醒的方式是"让原来的读回答被打断"——注意 subtle 之处：取消请求本身没有特殊回答（前台正常回它），是被叫醒的那个读报告"被打断了"。一封取消，两个回答：取消者得到"收到"，等待者得到"打断"。对不上（没人等、身份不对、编号不对）就沉默——原来的读可能已经结束了（事件刚把它叫醒），对空气喊话不如闭嘴。沉默 Agree 前台的赊账纪律（第 02 篇）：取消是四种可赊账的信之一，"不回"在这里是合法答案。

### 1.4 查询：不承诺的打听，分两种"是"

查询请求说"我不读，我就打听一下：读会不会成功"。服务看一眼状态，回答"行"或"不行"，绝不等待——查询是"即问即答"的反面（读是"可以等"，查询是"绝不等"）。"行"有两种意思，需要读者仔细区分：

- 真有货（队列里有事件）：行，读吧。
- 读了也是白读（设备没营业、或已有挂起）：也回答"行"——意思是"别等了，现在读，立刻拿错误"。注释写明"立即报错"（`/* immediate error */`）：这个"行"不是"有数据"，是"问完了，去读吧，答案马上到（是个错误）"。

为什么把"报错"也叫"就绪"？因为查询的契约是"读会不会立刻有答案"，而不是"读有没有数据"。报错也是答案，而且是立刻的答案——调用者收到"行"去读，立刻拿到错误，不用等。把"等"从调用者的选项里删掉，是查询存在的全部意义（调用者想等就直接读，不用查询）。

写方向永远回答"行"（同样的"立即报错"：输入设备不接受写，写了立刻错）。错误方向（"有没有异常"）永远回答"不行"——服务没有异常可报，诚实地说没有。

### 1.5 查询的预约：没货又想被叫，留个名字

查询还有第二种用法："现在没货，但有货了叫我"。调用者在查询里加"事后通知"位，服务没货可报时不回答"不行"，而是记下调用者的名字（选择者），有货时（事件到来，第 09 篇）通过另一封信通知他（第 02 篇的事后通知）。注意和挂起读的区别：挂起是"我要读，有货直接把货送来"（推数据），预约是"有货告诉我，我自己再来读"（推通知）。推数据省一次往返，推通知省一次内存授权——调用者按需选择。预约只记一个名字（后来者顶掉前者，和挂起"一设备一等待"是同一政策，第 07 篇 1.2 节）。

### 1.6 本章小结：三个配角，一场重头戏的配角

读完本章，读者应该能不假思索地回答：控制只认识哪个编号、两套灯语言怎么翻译；取消凭哪三件套认领、为什么对不上就沉默；查询的两种"行"各是什么意思、写为什么永远行、预约和挂起的区别。下一阶段（第 09、第 10 篇）讲事件与灯光的正戏：本章的翻译结果（掩码）由第 10 篇发出，本章的取消与查询由第 09 篇的事件唤醒配合。

## 2. C 源码分析

> 本章逐段对照原始 C 代码。所有行号以工作区当前 `minix3/` 为准。

### 2.1 控制：只认识调灯（input_ioctl，input.c:241-277）

```c
static int
input_ioctl(devminor_t minor, unsigned long request, endpoint_t endpt,
        cp_grant_id_t grant, int flags, endpoint_t user_endpt, cdev_id_t id)
{
        struct input_dev *input_dev;
        kio_leds_t leds;
        unsigned int mask;
        int r;

        if ((input_dev = input_map(minor)) == NULL)
                return ENXIO;

        if (!input_dev_active(input_dev))
                return EIO;

        switch (request) {
        case KIOCSLEDS:
                if ((r = sys_safecopyfrom(endpt, grant, 0, (vir_bytes) &leds,
                    sizeof(leds))) != OK)
                        return r;

                mask = 0;
                if (leds.kl_bits & KBD_LEDS_NUM)
                        mask |= (1 << INPUT_LED_NUMLOCK);
                if (leds.kl_bits & KBD_LEDS_CAPS)
                        mask |= (1 << INPUT_LED_CAPSLOCK);
                if (leds.kl_bits & KBD_LEDS_SCROLL)
                        mask |= (1 << INPUT_LED_SCROLLLOCK);

                input_set_leds(minor, mask);

                return OK;

        default:
                return ENOTTY;
        }
}
```

换算查不到与不营业的拒绝和读函数逐字相同（`ENXIO`、`EIO`，第 07 篇 2.1 节）——入口两问是各处理函数的统一开场，只有打开多一问（独占，第 06 篇）。`switch` 只有一个 `case` 加 `default`：认识调灯，不认识的全报"不是打字机控制"。调灯分支先从调用者内存把灯状态拷出来（拷贝失败直接返回拷贝的错误——传输失败的错误号由传输定，服务不翻译传输错误）；三行位翻译（`1 << 灯码`，灯码 1、2、3 来自第 04 篇，位定义来自 `kbdio.h`，第 05 篇 2.6 节）；调置灯函数（第 10 篇）；回答好。注意函数签名里用不上的参数（标志、用户身份、编号）：控制不需要它们（调灯不需要知道调用者是谁、不需要编号认领），留着是因为前台统一传参（和第 06 篇打开不用的两个参数同理）。

### 2.2 取消：三重匹配或沉默（input_cancel，input.c:282-298）

```c
static int
input_cancel(devminor_t minor, endpoint_t endpt, cdev_id_t id)
{
        struct input_dev *input_dev;

        if ((input_dev = input_map(minor)) == NULL)
                return ENXIO;

        if (input_dev->suspended && input_dev->caller == endpt &&
            input_dev->req_id == id) {
                input_dev->suspended = FALSE;

                return EINTR;
        }

        return EDONTREPLY;
}
```

换算查不到照例 `ENXIO`。注意取消**不查营业**——不营业的设备也可能挂着等待（营业判断看的是"现在有没有驱动"，等待是"以前挂上的"，驱动走了等待还在，第 11 篇断开连接会处理，处理之前取消照样工作）。三重匹配（挂着、调用者对、编号对）全中才叫醒，叫醒就是把标志复位，返回"被打断"（这个错误号是给**原来的读**的，不是给取消请求的——取消请求本身的回答由前台正常发送，见 1.3 节）。任一对不上就赊账（沉默）：注释在搬运函数处写明"原来的请求可能已经结束了，这时不该回信"（第 02 篇 2.6 节取消的默认行为与此处一致， framework 允许取消赊账）。

### 2.3 查询：即问即答与预约（input_select，input.c:303-326）

```c
static int
input_select(devminor_t minor, unsigned int ops, endpoint_t endpt)
{
        struct input_dev *input_dev;
        int ready_ops;

        if ((input_dev = input_map(minor)) == NULL)
                return ENXIO;

        ready_ops = 0;

        if (ops & CDEV_OP_RD) {
                if (!input_dev_active(input_dev) || input_dev->suspended)
                        ready_ops |= CDEV_OP_RD;        /* immediate error */
                else if (!input_dev_buf_empty(input_dev))
                        ready_ops |= CDEV_OP_RD;        /* data available */
                else if (ops & CDEV_NOTIFY)
                        input_dev->selector = endpt;   /* report later */
        }

        if (ops & CDEV_OP_WR) ready_ops |= CDEV_OP_WR;  /* immediate error */

        return ready_ops;
}
```

换算查不到照例 `ENXIO`（查询也要先找对门）。读方向三分支与 1.4 节逐行对应：不营业或有挂起→就绪（注释"立即报错"），有货→就绪（注释"有数据"），没货加事后通知位→记下选择者（注释"稍后报告"）。注意记选择者时**覆盖**旧选择者（直接赋值，不是追加）——一设备一选择者，和一设备一挂起是同一政策（1.5 节）。写方向无条件就绪（注释"立即报错"：写必错，错得立刻）。错误方向没有分支——返回值里永远没有错误位（1.4 节）。返回就绪掩码（当场回信，第 02 篇查询的当场回信）。

## 3. Rust 设计决策

> 本章解释"为什么这样设计"。每个决策先说备选方案，再说选择的理由。

### 3.1 控制拆成路由与翻译：编号归路由，位归翻译

`decide_ioctl` 只看编号（调灯去置灯、别的拒绝），`led_mask_from_kio_bits` 只看位（三位到掩码）。理由：编号的集合会变（将来加新控制命令，路由加分支），位的含义不变（灯还是那三盏）；变的东西和不变的东西住一起，改的时候互相打扰。分开后，加新命令只动路由，灯码变了（几乎不可能）只动翻译。调用者内存拷贝（传输层）在两者之间：路由通过才值得拷贝（不认识的编号连内存都不碰——碰了也白碰，还多一次跨进程拷贝的失败面），翻译用拷出来的位。这是"先问办不办，再问怎么办"的顺序，和读的"先判断再拷贝"是同一条纪律（第 07 篇 3.1 节）。

备选方案是路由翻译一体（查到编号直接读位）。拒绝的理由：一体函数需要调用者位做参数，测试路由（认不认识编号）时必须伪造位——无关参数污染测试意图，和第 06 篇论证过的问题一样。

### 3.2 取消的 verdict 只有两种：叫醒或沉默

`CancelVerdict` 枚举只有 `InterruptReader` 与 `Ignore` 两个变体，没有第三种"拒绝"。理由：取消没有"拒绝"的概念——对不上不是"错"，是"没什么可做的"。枚举只有两种，调用者（分发层）用 `match` 穷举，不可能漏掉"沉默"这条路（一体函数返回错误号时，调用者容易把"忽略"误读成"失败"，进而记下满篇的错误日志——枚举让"忽略"成为一等公民，不是错误号的伪装）。

备选方案是返回错误枚举（匹配上返 `EINTR`，对不上返 `EDONTREPLY` 伪码）。拒绝的理由：`EDONTREPLY` 不是错误，是"别回信"的指令（第 02 篇）；把它和真正的错误号放在同一个返回位置，调用者必须记得"这个变体不是错"——用类型把"指令"和"错误"分开（verdict 枚举 vs 错误枚举），记得住的东西让编译器记住。

### 3.3 查询的值与效应分开：掩码归值，记名归效应

`SelectOutcome` 把"哪些就绪"（值）与"要不要记名"（效应）装在一个结构体里返回。理由：C 把两者混在一个函数里（返回值加副作用），测试"记名了没"必须读返回值之外的状态；分开后，测试断言值断言值、断言效应断言效应（`test_select_reports_ready_data_and_errors` 逐项对照）。结构体（不是元组）是因为两个字段类型不同（整数掩码与布尔），元组会让人分不清哪个是哪个——具名字段是文档。

### 3.4 读就绪两分支合并：同位不同义，注释存义

C 的读就绪有两个分支（立即报错与有数据），都置同一个位。Rust 合并成一个条件（`!active || suspended || !empty`），把两个注释的意思写进一条注释（"立即有答案：数据或错误，跟进的读负责区分"）。理由：代码检查工具会指出"两个分支做同样的事"（`if_same_then_else`），而工具是对的——分支的区分只存在于注释里，不存在于行为里。行为相同的分支合并，注释保留区分——注释是给人看的，分支是给机器走的，两者各归其位。合并前后真值表逐项相同（review 验证，见 scan Gate B），不是"差不多"，是"完全一样"。

### 3.5 错误方向无分支：缺席即设计

错误查询永远没回答（返回掩码里没有错误位）。Rust 没有 `if ops & SELECT_ERROR` 分支，只有一行 `let _` 加注释，说明"看过，没有分支是故意的"。理由：缺席的代码最容易被后人"补上"（"这里漏了错误方向吧？"），`let _` 是留给后人的纸条："没漏，故意的，C 也没有"。这条纸条的成本是一行，收益是阻止一次错误的"补全"。

## 4. 实现详解

> 完整代码在 `os/servers/input/src/handlers.rs`（控制取消查询三节）。本章按"控制、取消、查询"的顺序展开，每个小节标注对应的第 3 章决策。

### 4.1 控制：`IoctlVerdict`、`decide_ioctl`、`led_mask_from_kio_bits`（对应决策 3.1）

```rust
pub enum IoctlVerdict {
    SetLeds,              // 去置灯（掩码由翻译函数另算）
    Refuse(InputError),   // 不认识的编号
}
```

路由只认 `KIOCSLEDS`（`minix-types` 的常量，第 05 篇），营业检查先行（与读同序）。翻译函数三行位映射，未知位忽略（1.2 节）。注意 `SetLeds` 变体不带掩码字段——掩码是翻译函数的产物，不是路由的产物：路由的结论只回答"去哪"，不携带"用什么去"，携带尚未算出的数据会让调用者误以为数据有效。单元变体加独立翻译函数，数据只在算出来的地方出现。

### 4.2 取消：`CancelVerdict`、`decide_cancel`、`apply_cancel`（对应决策 3.2）

判断三重匹配（挂着、调用者等、编号等，端点比较用内部整数，不比较结构体——端点相等就是整数相等，语义透明），执行只复位标志（注释写明与关闭修正的不对称原则，第 06 篇 3.3 节：联系方式不可达，不清）。

### 4.3 查询：`SelectOutcome`、`decide_select`、`apply_select_record`（对应决策 3.3、3.4、3.5）

判断返回结构体（掩码加是否记名），执行覆盖式记名（后来者顶掉前者，注释写明一设备一选择者政策）。合并后的读就绪条件（决策 3.4）与错误方向纸条（决策 3.5）如代码所示。
