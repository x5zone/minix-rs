## 1. 概念：终端是事件的终点站，也是灯光的起点

### 1.1 终点站与起点：一进一出两条线

终端和输入服务之间有两条线，方向相反。进来的一条是事件流：没人要的事件被服务转交给终端（第 09 篇三级跳板的最后一级），终端收下、过滤、存进自己的小缓冲，等上层来读。出去的一条是灯光流：终端维护着每台控制台的锁定键状态（大写锁定开着还是关着），状态变了（或服务刚宣告起来），终端把掩码发给服务，服务再广播到键盘（第 10 篇）。一进一出，终端既是消费者（吃事件），又是生产者（产灯光）——"消费者"这个篇名只取了一半，完整标题应该是"消费与回授"，迟到的诚实比漂亮的名字重要。

```
输入服务                                    终端驱动
   | ---- 转交事件 (TTY_INPUT_EVENT) ------> | 存进缓冲，等上层读（本章 1.2 节）
   | <---- 调灯掩码 (INPUT_SETLEDS) -------- | 状态变了就发（本章 1.4 节）
   | ---- 宣告起来 (TTY_INPUT_UP) --------> | 记下服务端点，回授当前灯光（本章 1.3 节）
```

### 1.2 终端的过滤器：只要键盘页，只要认识的码

终端不是什么事件都要。转交来的事件先过两道筛子：第一道看页——只要键盘页（`INPUT_PAGE_KEY`），鼠标移动、媒体键、灯光事件全部丢掉（终端是打字的地方，指针与媒体键归窗口系统，不是终端的菜）；第二道看码——码号必须小于扫描码总数（`0xE8`，即第 04 篇键盘码表上沿的保留空隙起点），超出的丢掉。两道筛子之后，按下与松开合并编码（松开的码或上释放位 `0x8000`），存进 32 项的环形小缓冲，满了就丢新的（注意：丢新不等盖旧——和第 09 篇服务侧"覆盖最旧"相反，1.5 节专门讲这对反义词）。

为什么终端只吃键盘页？因为终端的上层（shell、编辑器）只认字符：按键变成字符需要键盘映射（扫描码到字符的本地化过程，驱动阶段），鼠标位移变成不了字符——喂给终端也没用。过滤器是"按需索取"的形状：要什么拿什么，不要的不碰。

### 1.3 握手：记下谁，再把灯的现状告诉它

服务宣告"我起来了"，终端做两件事：先验明正身（查布告栏"input"标签的端点，和发信人比对——和第 12 篇驱动验配置、第 05 篇服务验置灯是同一套"信权威不信自称"，三处互相印证）；再把当前灯光推过去（调 `set_leds`，见 1.4 节）。顺序不能反：先记端点（`set_leds` 发消息需要知道发给谁），后推灯光——"记谁"与"告诉它"，两步缺一不可。验明失败（查不到、对不上）直接返回：宣告是广播，广播听不清就当没听见，下次服务重起还会再宣告（第 01 篇 2.4 节：握手失败只记日志，不崩溃——两边的失败哲学一致：握手丢了可以重来）。

### 1.4 回授：状态变了就推，推送前先抹掉私房位

终端维护每台控制台的锁定键状态（数字锁、大写锁、滚动锁，外加一个终端私有的 Alt 锁定）。状态变化时（用户按了锁定键），终端把掩码发给服务。发送前做两件事：去掉私房位（Alt 锁定是终端内部状态，服务不认识——`& ~ALT_LOCK` 把第 4 位抹掉再发，掩码卫生）；确认服务端点已知（刚启动还没收到宣告时不发——`NONE` 检查，早发了也没人收）。发送用异步（单向纪律，第 05 篇），失败记日志。注意调用时机有两处：状态变化时（按键处理中切换锁定位），与收到宣告时（1.3 节的回推）——"变了就推"与"起来就推"，推送的两个触发器。

### 1.5 一对反义词：终端丢新，服务盖旧

终端小缓冲满了丢**新**事件，服务环形缓冲满了盖**旧**事件——同一场景（缓冲满了又来新的），两处行为相反。先摆事实（两处代码各有各的写法，无注释解释），再划边界：本文档记录差异，不断言动机——"为什么不同"头文件没写、注释没写，编造动机违反因果链诚实（模式 48）。从可观察行为能说的是：终端保证已入队的按键不丢（上层按序读，打字不能丢字），服务保证最新 32 个总在（批量读最新优先）；两种保证各有各的读者，不必统一。差异登记在此，动机留白——留白是诚实，不是偷懒。

### 1.6 本章小结：终点与起点各就各位

读完本章，读者应该能不假思索地回答：终端吃事件过哪两道筛子、松开怎么编码、小缓冲满了怎么办（以及和服务侧有何不同）、握手时先记谁后推什么、回授何时触发、私房位为什么抹掉。输入阶段至此只剩一篇（第 14 篇）：客户端库的第一个真实用户。

## 2. C 源码分析

> 本章逐段对照原始 C 代码。所有行号以工作区当前 `minix3/` 为准。

### 2.1 缓冲与位定义：32 项、释放位、私房位（keyboard.c:30-61，keymap.h:163）

```c
#define KB_IN_BYTES   32      /* size of keyboard input buffer */   /* :30 */
#define RELEASE_BIT 0x8000                                          /* :35 */
static unsigned short inbuf[KB_IN_BYTES];                           /* :37 */
static unsigned short *inhead = inbuf;                              /* :38 */
static int incount;                                                 /* :40 */
static endpoint_t input_endpt = NONE;                               /* :75 */
```

小缓冲 32 项（和服务侧 32 项同数——同数是巧合还是约定？头文件两边各写各的 `32`，无共享常量、无注释互指，按"巧合"处理：本文档不断言两者有关联。诚实注记：若将来一侧改 32 而另一侧没改，没有任何机制会响——这是两个独立的 32，不是同一个 32）。

释放位 `0x8000`（第 35 行）：扫描码是 16 位，低 15 位装码，高位装"松开"——按下与松开共用一个通道（和输入协议"值字段分装按松"是两种编码，第 04 篇值字段 0/1 是协议语言，释放位是终端内部语言，翻译发生在 2.2 节）。私房位在第 58-61 行：

```c
#define SCROLL_LOCK (1 << INPUT_LED_SCROLLLOCK)   /* :58, 即位 3 */
#define NUM_LOCK    (1 << INPUT_LED_NUMLOCK)      /* :59, 即位 1 */
#define CAPS_LOCK   (1 << INPUT_LED_CAPSLOCK)     /* :60, 即位 2 */
#define ALT_LOCK    0x10                          /* :61, 终端私有 */
```

三盏灯的位定义复用输入协议的灯码（`1 << 码`，和第 08 篇服务侧翻译、第 10 篇掩码语义三方一致——"码即位号"贯穿服务与终端，不断就是对的）；`ALT_LOCK`（`0x10`）是终端私有的第四位，发送前抹掉（1.4 节）。

扫描码总数 `NR_SCAN_CODES 0xE8`（`keymap.h:163`，注释"键盘映射的行数"）：232。`0xE8` 恰好是第 04 篇键盘码保留空隙的起点（`0xE8` 以上保留）——两处数字相同不是巧合：键盘映射表有多少行，合法码就有多少个，保留区从表尾开始。跨文件数字互锁，本文档登记（第 04 篇 1.4 节的空隙在此兑现）。

### 2.2 消费：验明、过滤、编码、入队（do_input，keyboard.c:124-176）

```c
void do_input(message *msg)
{
  ...
  switch (msg->m_type) {
  case TTY_INPUT_UP:
        if ((r = ds_retrieve_label_endpt("input", &endpt)) != OK) { ... return; }
        if (endpt != msg->m_source) { ... return; }

        input_endpt = msg->m_source;

        /* Pass the current state of the LEDs to INPUT. */
        set_leds();

        break;

  case TTY_INPUT_EVENT:
        if (msg->m_source != input_endpt) { ... return; }

        /* Only handle keyboard keys. */
        if (msg->m_input_tty_event.page != INPUT_PAGE_KEY)
                return;

        /* Only handle known USB HID keyboard codes (the 00h-E7h range). */
        scode = msg->m_input_tty_event.code;
        if (scode >= NR_SCAN_CODES)
                return;

        /* Is it a KEY RELEASE? */
        if (msg->m_input_tty_event.value == INPUT_RELEASE)
                scode |= RELEASE_BIT;

        if (incount < KB_IN_BYTES) {
                *inhead++ = scode;
                if (inhead == inbuf + KB_IN_BYTES) inhead = inbuf;
                incount++;
                tty_table[ccurrent].tty_events = 1;
        }

        break;

  default:
        panic("do_input called for unknown message type %x", msg->m_type);
  }
}
```

宣告分支（1.3 节）：查标签、比端点、记端点、推灯光——四步缺一不可，任一步失败返回（不崩溃：宣告会再来）。事件分支：验发送者（不是服务就记日志返回——陌生人的事件不能吃，吃了就是命令注入）；过滤页（非键盘页静默丢弃——注意这里**不记日志**：鼠标事件被转交来是正常的（服务三级跳板的终端兜底什么都往这送，第 09 篇），记日志等于拿正常流量刷屏。验发送者记日志、过滤页不记日志——"陌生要喊，无关要忍"，日志政策按频率与性质区分，第 12 篇 1.3 节的隐藏规则在此第三次兑现）；过滤码（超 `0xE8` 静默丢弃，同样不记日志，同理）；松开编码（值字段松开则码或释放位——协议语言转内部语言，翻译点）；入队（满则丢新，1.5 节；置事件标志，叫醒上层）。

末尾 `default` 崩溃：未知消息类型进 `do_input` 是框架 bug（分发层 `tty.c` 只把两个已知类型送进来，2.4 节），崩溃暴露分发错误——"不该发生"的分支崩溃，与"可能发生"的分支容忍（验明失败返回），是本函数两种失败哲学的分界线（对照第 01 篇订阅失败崩溃：都是"不可能/不该"，都是崩溃）。

### 2.3 回授：私房位抹掉再发（set_leds，keyboard.c:369-384）

```c
static void set_leds(void)
{
/* Make INPUT set the LEDs on the caps, num, and scroll lock keys. */
  message m;
  int r;

  if (input_endpt == NONE)
        return;

  memset(&m, 0, sizeof(m));

  m.m_type = INPUT_SETLEDS;
  m.m_input_linputdriver_setleds.led_mask = locks[ccurrent] & ~ALT_LOCK;

  if ((r = asynsend3(input_endpt, &m, AMF_NOREPLY)) != OK)
        printf("TTY: asynsend to INPUT %u failed (%d)\n", input_endpt, r);
}
```

无端点就回（没宣告不推，1.4 节）；掩码取当前控制台锁定位去私房位（`& ~ALT_LOCK`——掩码卫生，1.4 节）；异步发送（单向纪律）；失败记日志（灯同步失败不算失败，第 10 篇 1.5 节的终端侧实例）。注释开宗明义（"让输入服务置三盏灯"）——函数只做这一件事，无隐藏行为。

### 2.4 消息接入：两个类型进同一扇门（tty.c:205-214）

## 3. 契约设计决策（本篇无 Rust 实现，所有权归驱动阶段）

> 本章解释"为什么这样定契约"。 drive 阶段实现终端时，这些决策是它的输入；每条先说备选方案，再说选择的理由。本篇零新增 Rust 代码——号码、载荷、事件含义已有权威定义（第 04、05 篇），终端内部结构（映射、缓冲、锁定位）归驱动阶段所有，现在定义等于从未来偷东西（所有权规则）。

### 3.1 双向验明正身：三处互相印证，不统一成一次

服务验置灯（05/10：只认终端），终端验宣告与事件（本篇 2.2：查标签、比端点），驱动验配置（12：查标签）。三处验法不统一（查标签、比端点、双保险各一），各按自己的消息频率与风险定——统一成"一律查标签"会让高频事件路径每次查一次布告栏（性能灾难），统一成"一律记端点"会让首次配置无据可查（先有鸡问题）。"同原则（信权威）、异做法（按频率）"是三处差异的统一解释。

### 3.2 页过滤与码过滤：两道筛子缺一不可

只滤页不滤码：保留区码（`0xE8` 以上）进入映射表越界（映射表 232 行，超了读越界——内存安全事故）；只滤码不滤页：鼠标位移值（可达 `0xFFFF` 量级）MOD 进键盘映射，指针一动满屏乱字。两道筛子各拦一类灾难，顺序页先码后（页不对连码都不看——便宜的先行，第 12 篇 2.3 节的顺序纪律跨篇兑现）。

### 3.3 满缓冲丢新：与覆盖旧共存，不统一

1.5 节已述。补充实现建议（给驱动阶段，非命令）：两处策略各有读者契约在身（终端上层按序消费、服务批量读新），统一任一方向都会破坏一方的读者——"看起来不一致"是"读者不同"的诚实反映。驱动阶段重写终端时，原样保留丢新，并引用本节（防"顺手统一"的重构）。

### 3.4 私房位掩码卫生：内部位不出境

`ALT_LOCK` 是终端内部状态位，出境掩码必须抹掉。推广为跨服务掩码纪律：任何掩码出境前，发送方负责清除接收方不认识的位（接收方忽略未知位是兜底，第 08 篇灯位翻译"未知位忽略"——发送方卫生加接收方兜底，双保险）。本篇是发送方卫生的实例，第 08 篇是接收方兜底的实例，两处互相印证。

### 3.5 未知类型崩溃：分发错误的哨兵

`default` 崩溃不是"严格"，是"哨兵"：正常流程永远走不到（接入层只送两个号），走到了说明接入层坏了——崩溃把"接入层出问题"变成人人能听见的崩溃，而不是悄无声息的错乱。对照验证：第 01 篇订阅失败崩溃（"不可能发生"则崩溃）、第 06 篇关闭修正（"可能发生但错了"则改）——三处同一标尺：不可能的事崩溃，可能的错事容忍或修正。
