## 1. 概念：翻译官的三份工作与硬件的尊严

### 1.1 驱动是翻译官，不是搬运工

键盘鼠标驱动处在硬件与库之间，干三份工作：出生时宣告（查硬件、定类型、贴条子）；有动静时翻译（硬件字节变成统一事件，调库上报）；被点名时回写（库调灯光钩子，驱动写硬件端口）。翻译是灵魂：硬件说"扫描码 `0x1E` 抬起"，驱动说"键盘页 A 键松开"——两种语言，一张对照表（扫描映射表）。搬运工只管把字节从端口搬到库，翻译官要懂两边的语法。本章讲翻译官的三份工作，硬件端口的时序与电气细节留在驱动阶段（边界先行声明，2.8 节有裁剪清单）。

### 1.2 宣告顺序：先摸硬件，再报名

驱动启动先初始化硬件（探控制器、测自检、挂中断——失败直接返回错误码，连宣告都不做），再按探测结果定类型（辅助口存在就是键鼠双类型，否则纯键盘），最后宣告。顺序即诚实："我能干什么"必须先验明（硬件探测），再宣告——宣告"我是鼠标驱动"之前，先确认鼠标口真的存在。顺序反过来（先宣告后探测、探测失败再撤回）需要"撤回"协议，而协议里没有撤回（布告栏条子只能覆盖不能删除吗？能删，但服务侧把删理解为"驱动死了"，见第 11 篇 1.1 节——"诈尸式宣告"会引发一次完整的连接再断开，白白惊动服务）。和第 01 篇"先摆桌子再请客人"、第 11 篇"先验明再分配"是同一个顺序纪律：承诺之前先验货。

### 1.3 键盘翻译：状态机吃前缀，查表出事件

个人电脑键盘的扫描码不是"一键一码"：普通键一个字节，扩展键两个字节（`0xE0` 开头），暂停键一串特殊字节。驱动用四态小状态机吃前缀：0 态吃到 `0xE0` 转 1 态（扩展），吃到 `0xE1` 转 2 态（暂停前奏），2 态吃到 Ctrl 码转 3 态，3 态吃到 NumLock 码就是暂停键——前缀字节自己不产生事件，只决定"下一个字节怎么解释"。状态机是"前缀的记忆"，记忆清空在每次产出事件之后（`kbd_state = 0` 收尾）。查表在状态定之后：普通态查普通表，扩展态查扩展表，表项直接给出（页，码）——翻译是"状态加查表"，无计算。查表无结果（页为零）吞掉：硬件会发出表里没有的码（多媒体键盘的怪键），吞掉是最安全的（发一个"页零"事件，服务侧页过滤迟早丢掉它，还不如不发——在源头省一次消息）。

按下松开的判定只看最高位（`0x80`）：亮了就是松开，灭了就是按下——硬件把"按松"编码进扫描码的最高位，驱动把它翻译成统一事件的值字段（按下 1、松开 0）。"位"变"值"，翻译的最小单位。

### 1.4 鼠标翻译：三字节包拆成按钮加位移

鼠标说话是三字节一组：首字节带按钮状态与符号位，后两字节是横纵位移。驱动攒够三字节才动手：先对三个按钮逐个比变化（上次状态异或这次状态，变的位才发事件——"变化才上报"，没变的按钮不刷屏），按钮事件用按键页（第几个按钮就是第几个码：主按键码加序号——第 04 篇"未命名的大码"在此兑现：二三号按钮的码 2、3 正是这么来的）；再看位移（零就不发——静止的鼠标不说话），非零拼符号位（首字节的符号位或到高位，补成有符号数），用桌面页横纵轴码、相对标志发出。"变化才上报"与"静止不说话"是同一原则：线上只走增量，不走状态——增量协议省带宽，状态同步靠"上次值"记忆（驱动记 `aux_state`，和第 10 篇服务记灯光记忆是同一思想，不同方向）。

### 1.5 灯光回写：掩码到位字节的逆翻译

库调灯光钩子给掩码（`1 << 码` 的位，见 1.6 节对照），驱动把它翻回端口字节（三盏灯各一位：滚动锁 `0x01`、数字锁 `0x02`、大写锁 `0x04`），排进输出队列等硬件吃。这是第 08 篇位翻译的逆过程（服务：调用者位→掩码；驱动：掩码→端口位）——正反两次翻译，中间语言是掩码（掩码是服务与驱动的合同语言，第 05 篇载荷）。输出队列满了就丢本次命令（不排队——灯命令是状态同步，排队会让旧状态覆盖新状态，见第 10 篇 1.5 节"同步非事务"的驱动侧实例：队列满时丢，最新状态下次再来）。

### 1.6 主循环镜像：同形第三例

驱动主函数三行（登记出生回调、启动框架、进库主循环）和输入服务主函数（第 01 篇 2.1 节）逐行同形：启动框架都是"登记第一次回调再启动"，主循环都是"等信分发不返回"。阶段内第三次同形（服务、字符框架用户、驱动库用户）——"事件循环"是 Minix3 系统进程的统一心跳，plan 主线"启动顺序"的注脚：每个进程都这么出生、这么活、这么等信。回调表三钩子（灯、中断、闹钟）无"其他"——其他消息库默认吸收（第 12 篇 2.6 节），驱动连表都不用填（NULL 即默认，不填即正确）。

### 1.7 本章小结：接口盖住了真实用户

读完本章，读者应该能不假思索地回答：驱动三份工作是什么、为什么先探测后宣告、键盘前缀状态机怎么吃、鼠标三字节怎么拆、灯光掩码怎么翻回端口、主循环与服务 side 有何异同，以及最重要的——第 12 篇的接口盖不盖得住这一切（盖得住，见第 4 章对照表：驱动调的每个库函数、填的每个钩子，在库里都有位置）。输入阶段至此只剩收尾（第 99 篇全局概念）。

## 2. C 源码分析

> 本章逐段对照原始 C 代码。行号以工作区 `minix3/` 为准。硬件端口时序、看门狗、应答协议、输出队列机制归驱动阶段（2.8 节裁剪清单），本章只讲库使用面与翻译决策。

### 2.1 出生：硬件先行，宣告殿后（pckbd_init/startup/main，pckbd.c:464-507）


### 2.2 回调表：三钩子，无其他（pckbd_tab，pckbd.c:37-41）

```c
static struct inputdriver pckbd_tab = {
        .idr_leds       = pckbd_leds,
        .idr_intr       = pckbd_intr,
        .idr_alarm      = pckbd_alarm

```

灯、中断、闹钟三钩子有主，"其他"空着——库对空钩子的默认是吸收（第 12 篇 2.6 节），驱动不需要的通知种类连表都不填。三个钩子的分工：灯（回写，2.5 节）、中断（分流，2.6 节）、闹钟（看门狗到期处理，硬件机制归驱动阶段——闹钟钩子的存在只证明"驱动用了定时器"，定时器干什么（看门狗）是硬件可靠性话题，出本阶段范围）。

### 2.3 键盘翻译：状态机加查表（kbd_process，pckbd.c:327-368）

```c

        index = scode & ~SCAN_RELEASE;
        ...
        if (page)
                inputdriver_send_event(FALSE /*mouse*/, page, code, press, 0);
```

最高位判定按松（`SCAN_RELEASE 0x80`，`pckbd.h`），去最高位取索引。状态机四态吃前缀（1.3 节），暂停键是状态 3 加 NumLock 码的特例（注释 `FALLTHROUGH` 穿透，和服务 side 两处穿透同作者手笔：第 02 篇回信函数、第 05 篇消息入口——穿透注释是这位作者的签名式写法）。查表分普通扩展两张（`table.c`，同目录，声明在 `pckbd.h:46-47`）。`if (page)` 守卫吞掉无映射（1.3 节）。上报调库，种类传"非鼠标"（布尔参数，第 12 篇 1.5 节"驱动不记号"的实例：驱动说种类，库填槽位），标志传零（按键是绝对语义的离散事件，相对标志只属于位移）。


首字节第 3 位（`0x08`，协议规定首字节该位恒亮）是同步锚：包头对不上就扔（重同步，1.4 节）。攒满三字节开工：按钮逐位异或比变化（`aux_state` 记上次，1.4 节增量记忆），码用主按键码加序号（`INPUT_BUTTON_1 + i`——第 04 篇"二三号按钮无名"的出处：头文件只命名了 1 号，2、3 号靠加法）；值用当前状态的布尔化（按下 1 松开 0——按钮事件的值语义和按键一致，第 04 篇）；标志传零（按钮是离散量，绝对默认）。位移非零才发（静止不说话），符号位拼高位（首字节 `0x10/0x20` 分管横纵符号），桌面页横纵轴码，相对标志（1.4 节）。两次上报的种类都传"鼠标"（布尔真）。

### 2.5 灯光回写：掩码翻端口位（pckbd_leds，pckbd.c:417-428）

```c
static void
pckbd_leds(unsigned int leds)
{
        unsigned char b;

        b = 0;
        if (leds & (1 << INPUT_LED_NUMLOCK)) b |= LED_NUM_LOCK;
        if (leds & (1 << INPUT_LED_CAPSLOCK)) b |= LED_CAPS_LOCK;
        if (leds & (1 << INPUT_LED_SCROLLLOCK)) b |= LED_SCROLL_LOCK;

        set_leds(b);
}
```

掩码位（`1 << 灯码`，第 08 篇生产）翻回端口位（`LED_NUM_LOCK 0x02` 等，`pckbd.h`）——第 08 篇翻译的严格逆函数（`f(g(x)) = x`：服务把调用者位翻成掩码，驱动把掩码翻成端口位，端口位恰好等于调用者位—— round trip 回到起点，附带证明两处翻译互逆，见 scan Gate B）。翻完进输出队列（`set_leds`，队列机制归驱动阶段；满了丢本次，1.5 节）。端口位定义在驱动头文件（`pckbd.h`），不在共享库——端口是硬件语言，硬件语言不出驱动门（所有权规则：共享库只讲合同语言，端口字节是驱动私事）。

## 3. 契约设计决策（本篇无 Rust 实现，所有权归驱动阶段）

> 本章解释"为什么接口长这样"。驱动阶段实现时，这些决策是它的输入；每条先说备选方案，再说选择的理由。本篇零新增 Rust 代码——库接口（第 12 篇）已覆盖驱动全部调用（第 4 章对照表），硬件语言（端口、时序）归驱动所有，现在定义等于从未来偷东西。

### 3.1 库覆盖完备：驱动调的每个函数库里都有位置

对照表（第 4 章）逐项验证：第 12 篇的六组接口（键拼写、掩码组装、判决、核对、回调、分类）覆盖驱动的四次调用（三库函数加三钩子注册）与全部常量（类型位、页码、按钮码、标志位经由 04/05 含义覆盖）。覆盖完备是本篇存在的第一理由（plan §2.1："13/14 结尾验证 09/10 的外部可观察行为"——14 验证 12 的接口盖得住真实用户）。

### 3.2 翻译决策归驱动，不归库

扫描码到事件的映射（状态机、查表、按钮拆分、位移符号扩展）全在驱动，不在库。备选方案是库提供"标准翻译"（传扫描码，库出事件）。拒绝的理由：扫描码是硬件语言（每种键盘、每种鼠标各说各的，USB 键盘另有一套），库若接翻译，库就要懂所有硬件——库从"协议助手"膨胀成"硬件抽象层"，和字符框架（第 02 篇"前台不管业务"）的哲学相悖。库只懂协议（第 12 篇 1.1 节手脚脑袋分工），翻译是手脚的事。plan 把翻译放在 14（外部契约）而非 12（库），正是这条分界。

### 3.3 端口语言不出驱动门

端口号、命令字节、端口位定义全在驱动头文件（`pckbd.h`），共享库零端口知识。备选方案是端口常量进共享库（"大家都用键盘端口"）。拒绝的理由：USB 键盘不用端口（用总线事务），蓝牙键盘不用端口——端口是"个人电脑键盘"这种具体硬件的语言，不是"输入驱动"的语言。共享库讲所有驱动的合同语言（第 12 篇），具体硬件语言留在具体驱动门内。pckbd.h 的存在本身就是分界示范。

### 3.4 满队列丢命令：同步语义的驱动侧实例

输出队列满丢本次命令（不排队），和第 10 篇服务侧"失败只记日志"同构：灯命令是状态同步，排队让旧状态覆盖新状态。两处同一原则（同步非事务），一处在服务（记日志等恢复），一处在驱动（丢等下次）——实现不同（服务有记忆可恢复，驱动无记忆只能等下次调灯），原则相同。驱动阶段重写输出队列时，原样保留满丢（并引用本节，防"改成排队"的重构）。
