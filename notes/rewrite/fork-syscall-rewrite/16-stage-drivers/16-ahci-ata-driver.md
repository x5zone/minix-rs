> **源码**：`minix3/minix/drivers/storage/ahci/ahci.c`（二千七百三十四行，端口、命令表、散集表、中断、超时）、`minix3/minix/drivers/storage/ahci/ahci.h`（帧布局与端口寄存器）、`minix3/minix/drivers/storage/at_wini/at_wini.c`（二千二百四十三行，控制器、直接存取、复位）、`minix3/minix/drivers/storage/at_wini/at_wini.h`（端口号与状态位）、`minix3/minix/drivers/storage/at_wini/liveupdate.c`（七十六行，热升级钩子）

> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/02-blockdriver-framework.md`（块框架，两驱动都挂靠）、`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/15-virtio-blk-driver.md`（编链思想对照）
> **说明**：高级主控接口与并行接口是真盘的两兄弟：一个新（串行，端口命令表），一个老（并行，控制器命令）。本篇讲两兄弟的共同点（命令槽、超时复位、识别容量）与不同点（帧结构对端口命令、散集表对直接存取）。寄存器细节在服务层，本库只定顺序与算法。

> **本篇不讲什么**：
> - 虚拟块设备（见 `15-virtio-blk-driver.md`，编链思想对照用）
> - 其余存储杂项（见 `17-storage-misc-driver.md`）

> 本篇只回答一个问题：**真盘的命令如何上发，如何等，如何超时，如何复位**。

## 1. 概念：机场塔台与火车站

### 1.0 章节引言

目标读者是读完虚拟块的读者。前置知识只需要一条：链怎么编。本章解释真盘为什么比虚拟盘多三件事：等、超时、复位。

### 1.1 高级主控是机场塔台

想象机场塔台：三十二条跑道（命令槽），飞机起降要先申请跑道（发命令占槽），落地交回跑道（完成清槽），飞机失联（超时）封锁全场（全部失败），封锁后重启塔台（复位重编）。塔台不开（端口没启动）不受理申请，先开塔再申请是铁律。

高级主控的端口就是这座塔台。三十二槽位图（`COMMAND_SLOTS`）管理在飞命令，占槽常数时间（找第一个空位），完成清槽，超时清全部并转超时态（发命令直接拒：先复位再说）。复位回停止态（重编表后再启动）。停机清槽是关键：停端口时在飞命令全作废，不留半截状态给下次启动。

### 1.2 并行接口是火车站

并行接口是老火车站：四个站台（驱动器，`MAX_DRIVES`），一列车最多二百五十六节（扇区，`MAX_SECS`）。站长室四态：新生、复位中、探明、就绪、待复位。复位后探站台（哪个站台有车），认车（识别容量，有一辆能认出就开张，全认不出待复位），开张后按站台接车。出错锁存待复位（下次动作必须是复位，不许带病接车）。

大单拆小单：超二百五十六扇区分整单加零头（整单数加余数，无整单余数即全单）。拆单是纯算术，与硬件无关，放库里测得最全。

### 1.3 直接存取：专车道

小单走编程道（中央处理器一字节一字节搬），大单走专车道（直接存取）。专车道三态：闲、已武装（方向加扇区数）、已到（等验错）。武装时闲才能武装（重武装拒），零扇区拒（空车不上路）。到了验车：设备错位清说明货没到（调用方复位），无错位清说明货到了。提前停车（复位路径）回闲。

### 1.4 识别：查身份证

识别数据二百五十六字，容量在第一百与第一百零一字（低高拼六十四位）。零容量等于没车（端口后没盘，认了也白认）。写缓存位随身带（性能策略用）。块太短（不足二百五十六字）直接拒（残缺身份证不认）。容量乘五百一十二是字节数（与虚拟块同一乘法，块大小通用）。

### 1.5 超时复位：封锁与重开

超时是全端口最重的事件：在飞命令全失败，状态转超时，后续发命令全拒。复位是唯一的出路：清槽回停止，重编表，重启动。并行接口的出错锁存同理：待复位态下接车请求一律不受理（先复位）。两兄弟的复位哲学一致：坏了就停，停了重编，编完重开，不带病。

### 1.6 本章小结

真盘两兄弟：高级主控三十二槽塔台，并行接口四站台火车站，直接存取三态专车道，识别查身份证，超时封锁复位重开。下一章进入 C 语言源码验证。

### 2.2 端口命令槽（`ahci.c` 第九百行到第九百八十五 行，第一千八百一十行到第一千八百七十七行）

完成清槽（成功失败都清），失败全清（超时分支），找空槽（线性找第一个空），发命令（占槽设表响铃），执行（发完等完成或超时）。槽位图是全端口最热的数据，找空必须常数级（线性三十二项即常数）。

### 2.3 超时复位（`ahci.c` 第一千二百二十行到第一千三百三十五 行，第一千七百一十五行到第一千七百九十三行）

硬复位（端口物理复位），重写（改配置），启动（开命令开收帧），停止（关命令清槽），重启（停复位启三连），等待（忙等状态位），超时（定时器到转失败）。停止清槽是铁律：停机不留半截命令。

### 2.4 识别与缓存（`ahci.c` 第四百零二行到第七百七十五 行）

介质检查（有盘无盘），识别检查（并行与串行各一版），通用识别（发识别命令），刷缓存（掉电前落盘），缓存读写（读策略写策略）。容量零等于无盘（认了白认）。

### 2.5 控制器与等待（`at_wini.c` 第三百一十四行到第四百五十三行，第一千六百二十六行到第一千七百二十七行）

探测（扫四站台），初始化（认车布中断），复位（控制器复位），等待（忙等状态掩码），中断等待（睡等中断），直接存取等待（忙等直接存取位）。等待分两种：忙等（短，有 bound）与睡等（长，让出），混用是功夫：该忙等时睡等丢性能，该睡等时忙等烧中央处理器。

### 2.6 直接存取（`at_wini.c` 第五百六十四行到第九百六十一行）

查直接存取能力（控制器支不支持），启停直接存取（编程启动位），错检查（传完看错位）。编程道与专车道的分界在服务层调参，本库只管武装检查完成四步。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 端口做成槽位图（依据：第 1.1 节、第 2.2 节）

三十二布尔数组，占槽找空，完成清槽，超时全清复位态。启停只认停起顺序（没停就启不动，没启就发不出）。替代方案是链表管槽，不选的理由是：槽数固定三十二，数组下标即槽号，链表多一次跳转。

### 3.2 识别做成纯解析（依据：第 1.4 节、第 2.4 节）

字数组进容量缓存出，短块零容量拒。缓存位随身带（性能策略在服务层用）。替代方案是解析里直接读寄存器，不选的理由是：读寄存器要端口，端口在服务层，解析只认字数组。

### 3.3 控制器做成阶段机（依据：第 1.2 节、第 2.5 节）

新生复位探明就绪待复位五态，乱序调用拒绝（没探明不认车）。站台存在数组，进谁家门认谁的车。出错锁存待复位（带病不接车）。替代方案是布尔三元组，不选的理由同终端篇：阶段机让非法转移不可能。

### 3.4 直接存取做成武装机（依据：第 1.3 节、第 2.6 节）

闲武装到验错四步，零扇区拒，重武装拒，早停回闲。验错清状态（查完即闲，下次重武装）。替代方案是布尔一枚（开关联动），不选的理由是：布尔分不清武装了没验错和验完没武装，四态才够。

### 3.5 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 端口槽位图 | 第 1.1、2.2 节 | 链表管槽 | 下标即槽号 |
| 识别纯解析 | 第 1.4、2.4 节 | 解析读寄存器 | 端口在服务层 |
| 控制器阶段机 | 第 1.2、2.5 节 | 布尔三元组 | 非法转移可能 |
| 存取武装机 | 第 1.3、2.6 节 | 布尔一枚 | 状态不够分 |

## 4. 错误处理

| 场景 | C 行为 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 未启动发命令 | 不受理 | `NotStarted` | 先开塔再申请 |
| 槽满 | 稍后重试 | `NoSlot` | 跑道全占 |
| 完成空槽 | 无此槽 | `finish` 假 | 重复完成 |
| 超时 | 全失败转态 | `note_timeout` | 封锁全场 |
| 空识别块 | 拒 | `parse` 空 | 残缺不认 |
| 零容量 | 无盘 | `parse` 空 | 认了白认 |
| 控制器空探 | 待复位 | `NeedsReset` | 无车开张不了 |
| 出错接车 | 锁存 | `drive_ready` 假 | 带病不接车 |
| 零扇区武装 | 拒 | `start` 假 | 空车不上路 |
| 验错前查 | 拒 | `check` 假 | 没到先查白查 |
