## 1. 概念：小区的门牌与户籍科

### 1.0 章节引言

目标读者是理解字符驱动与注册思想的读者。前置知识只需要两条：读文件即读设备，名单管可见。本章解释引脚与注册的两套户籍：一套管脚，一套管设备。

### 1.1 引脚驱动是门牌科

想象新建小区的门牌科：每栋楼认领门牌号（认领引脚），住户按门牌收信（读文件看电平），电工按门牌开关灯（读特制文件驱动电平）。门牌号不能重（认领过的脚再认领被拒），灯开关要看户型（输入脚拒绝驱动）。

Minix3 的引脚驱动就是门牌科。启动钩子按板型认领一批引脚（两款开发板各一批，外加演示用的大红按钮），每个引脚挂一到三个文件：读文件（`GPIO_CB_READ`）看电平，输出脚再挂开关灯两文件（`GPIO_CB_ON`、`GPIO_CB_OFF`），输入脚再挂中断文件（`GPIO_CB_INTR_READ`）。读开关文件即开关（读完答零字节：动作做了，内容没有），读中断文件取锁存的中断标记（取完清零，下次再取是新的）。

### 1.2 读渲染：一位数加换行

电平渲染是 `"%d\n"`：一加换行两位，偏移零全取，偏移一取换行，偏移二到头。这是全驱动最短的规则，却是最容易错的：偏移二必须答零（到头），不能答换行；偏移一必须答一字节，不能答两字节。渲染函数返回三元组（首字节、次字节有无、长度），调用方照抄进回复，没有第二种解释。

### 1.3 认领规则：先到先得

认领三查：脚号有没有人（有人拒），模式记下来（输入输出），属主记下来（文件系统导出者）。读写两查：没认领的脚读写全拒（无此脚），输入脚拒绝驱动（方向错）。中断读查认领不查方向（中断标记与方向无关，输入脚才有中断可读，输出脚读中断永远假）。

先到先得是全部公平性的来源：没有优先级，没有抢占，认领即持有，持有至进程结束。简单，但够用：板上引脚是静态分配的，启动时一次认领完，运行时几乎不再变。

### 1.4 设备注册是户籍科

通用设备上户口三件套：父设备号、名字、属性表。序列化是传输形状：固定头（属性数、父号、名字偏移）加每属性一条（名偏移数据偏移）加尾部字符串区。长度可算：头十六加条目十六乘数加全部字符串长。注册表按柄管理：增发新柄（空槽复用最小号），删清空槽（删空槽假），查柄借记录，列活柄。

通用串行总线设备多一层：设备下挂最多三十二接口，接口逐个绑定（绑定回调接受记端点，拒绝记空）。未绑定计数是就绪度：全绑好零，剩几个未绑就是几。跟踪表的增删与通用表同形（空槽复用，删空假）。

### 1.5 两表对照：引脚认领对设备挂名

引脚认领与总线预留是同一类操作：先登记后使用，重复登记被拒，释放后可再登记。设备注册与总线建档也是同一类：增发柄，删清槽，查借记录。三个阶段的三套登记（总线名单、引脚认领、设备注册）形状不同，灵魂相同：资源有主，用前先问。这是驱动子系统的登记三部曲，本篇是第三部。

### 1.6 本章小结

引脚驱动是门牌科：认领、读写、导出三件事，渲染两位两规则。设备注册是户籍科：通用记录三件套，总线接口三十二。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单

| 文件 | 行数 | 内容 |
|------|------|------|
| `minix3/minix/drivers/system/gpio/gpio.c` | 二百九十行 | 引脚认领、文件导出、读渲染、消息钩子 |
| `minix3/minix/lib/libdevman/generic.c` | 二百七十五 行 | 通用增删、序列化 |
| `minix3/minix/lib/libdevman/usb.c` | 三百零一行 | 总线设备接口跟踪与绑定 |
| `minix3/minix/include/minix/devman.h` | 约七十行 | 注册接口声明 |

### 2.2 引脚导出（`gpio.c` 第六十行到第一百六十行）

认领（失败报输入输出错误），设模式（失败报输入输出错误），分配回调结构（失败报内存不足），挂读文件（名），输出脚加挂开关灯两文件（名加 `On`、`Off`），输入脚加挂中断文件（名加 `Intr`）。文件名缓冲二百字节，读缓冲二十六字节（`DATA_SIZE`）。板型分支：两款开发板各认领一批（输出使能液晶、输入接按键），演示按钮两对。焊盘配置调复用与上下拉（板级细节，模式值在服务层）。

### 2.3 读渲染（`gpio.c` 第二百一十行到第二百六十行）

开关文件：置位清零，失败输入输出错误，成功答零字节。中断文件读锁存标记，普通文件读电平，失败输入输出错误。渲染 `"%d\n"`，偏移到头答零，正偏移移窗，返回剩余长度。消息钩子转交中断消息（中断到来靠消息，不靠轮询）。主函数填三钩子（初始化、读、消息）跑虚拟树，根目录只读。

### 2.4 通用注册（`generic.c` 全文）

字符串存入缓冲记偏移（名加数据挨个存），序列化算头加条目加字符串（三段相加），分配失败返回空（调用方转内存不足）。增设备进表，删设备清项。端点静态存（服务地址缓存在库里，重启重查在服务层）。

### 2.5 总线跟踪（`usb.c` 全文）

设备新建（编号）、设备增加（进表）、设备移除（清项）、设备删除（释放）、初始化（绑回调注册）。接口数组三十二，绑定回调逐接口跑，接受记端点拒绝记空。描述符全透明（库不解释描述符，只数接口）。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 引脚硬件做成行为定义（依据：第 1.3 节、第 2.2 节）

驱动、采样、采中断三方法。内存板与空板两个行为不同的实现满足门禁：内存板测电平锁存，空板测缺硬件路径。寄存器永不进库。替代方案是寄存器地址进库，不选的理由是硬件抽象原则。

### 3.2 认领做成查表（依据：第 1.3 节、第 2.2 节）

脚号查有人即拒，模式属主记下。读写先查认领再调硬件，方向错拦在调硬件之前。替代方案是认领放硬件里，不选的理由是：认领是策略（谁先谁得），硬件只管电平，策略与力学分离。

### 3.3 导出做成命名加规划（依据：第 1.1 节、第 1.2 节、第 2.2 节、第 2.3 节）

后缀四常量，文件名拼接函数，读规划四变体，渲染三元组。偏移规则收进渲染函数（零全取、一取换行、二到头）。替代方案是渲染放服务层手写，不选的理由是：偏移规则错一位就多给少给，一处实现四组测试锁死。

### 3.4 注册做成柄表（依据：第 1.4 节、第 2.4 节）

通用记录三件套（父号、名长、属性表），序列化三段相加，柄表空槽复用最小号。替代方案是链表，不选的理由是：柄即下标，数组最直接，链表找柄多一次遍历。

### 3.5 总线跟踪做成设备加接口（依据：第 1.4 节、第 2.5 节）

设备三十二接口上限，绑定接受记端点拒绝记空，未绑定计数即就绪度。替代方案是描述符进库解释，不选的理由是：库不解释描述符是 C 语言的既定分工，改了等于揽不该揽的活。

### 3.6 库名加客户端后缀（依据：第 2.7 节）

计划短名已被设备管理服务占用（包名与库名双撞）。改名客户端后缀，文档与代码注释双记理由。替代方案是合进服务包，不选的理由是：驱动侧客户端与服务侧是两层，合包等于把楼上楼下砌一间房。

### 3.7 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 硬件行为定义 | 第 1.3、2.2 节 | 寄存器进库 | 硬件泄漏 |
| 认领查表 | 第 1.3、2.2 节 | 放硬件里 | 策略力学混淆 |
| 导出命名规划 | 第 1.1、1.2、2.2、2.3 节 | 服务层手写 | 偏移错一位 |
| 注册柄表 | 第 1.4、2.4 节 | 链表 | 找柄多遍历 |
| 跟踪设备接口 | 第 1.4、2.5 节 | 解释描述符 | 揽不该揽的活 |
| 库名加后缀 | 第 2.7 节 | 合进服务包 | 楼上楼下砌一间 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 认领有人 | 输入输出错误 | `claim` 返回该错 | 先到先得 |
| 模式失败 | 输入输出错误 | 服务层透传 | 板级拒绝 |
| 分配失败 | 内存不足 | 服务层透传 | 回调结构建不出 |
| 读写未认领 | 无此脚 | `read` 等返回该错 | 没上户口不接待 |
| 输入脚驱动 | 板故障 | `drive` 返回该错 | 方向错 |
| 板卡拒绝 | 板故障 | 透传板错 | 硬件说不 |
| 注册表满 | 空柄 | `add` 返回空 | 生产按拓扑 sizing |
| 接口超三十二 | 假 | `add_interface` 返回假 | 描述符谎报长度时拦 |
| 未知接口绑定 | 假 | `bind` 返回假 | 对不上号不记 |
