## 1. C 真序（运行时真序重建）

**阶段类型判定**：本 stage 同时具备"集合型"（57 个并行驱动）与"服务事件循环型"（每个驱动的骨架）双重特征。按提示词第九部分规则处理：**以驱动骨架的运行时序为主线（启动→宣告→收包→分派→回复→中断/通知），57 个驱动按设备族并行分组，组内参考成员讲透 + 差异矩阵收束**。理由：每个驱动的进程生命周期完全同构（SEF 启动 → 回调表进主循环），差异只在硬件协议与回调实现；强行给 57 个驱动排线性序是伪序，同构骨架讲一次、并行体按族组织才是真序。

### 1.2 并行体（57 驱动的族序）

族内成员互相并行，族间只有弱依赖（pci 先于 PCI 设备驱动、devman 绑定于全部字符/块驱动）。现有目录的九个分组（框架/boot 关键/系统服务/输入/存储/USB/显示音频/网络/杂项）与族的依赖偏序一致——这是**从 C 结构独立核对后的确认**，不是对 `plan.md` 结论的转述：框架库目录（`lib/lib*driver*` 11 个）先于 server 目录（`drivers/`）成立；boot 因果链由 T1 锚点决定；其余各族之间无调用依赖，仅共享 99 的协议簿。
