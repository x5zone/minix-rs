# 11-pci-driver：总线驱动

> **分类**：系统服务第 3 篇（设备枚举、配置空间、访问名单）
> **源码**：`minix3/minix/drivers/bus/pci/main.c`（七百四十行，查询协议与控制码）、`minix3/minix/drivers/bus/pci/pci.c`（二千五百五十九行，枚举、桥、中断路由）、`minix3/minix/drivers/bus/pci/pci_table.c`（三十七行，桥标识表）、`minix3/minix/include/minix/com.h`（第九十五 行到第一百六十行，总线查询号段）
> **Rust 模块**：`os/drivers/bus/pci/src/protocol.rs`（查询号与控制码）、`os/drivers/bus/pci/src/config.rs`（配置空间抽象）、`os/drivers/bus/pci/src/database.rs`（设备库与访问名单）
> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/01-chardriver-framework.md`（字符框架，本篇挂靠其通用挂钩）、`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/10-readclock-driver.md`（权限门思想）
> **说明**：总线驱动是全系统设备的户籍警：哪条总线上有几张卡、每张卡是谁（厂商设备号）、中断走哪根线、地址窗口怎么开，全归它管。设备驱动加载前先问它：我要找的卡在吗，在哪，我能碰吗。本篇讲户籍管理的三件套：枚举建档、配置读写、名单门禁。桥窗口与寄存器探测的力学细节在服务层实现，本库只定策略。

> **本篇不讲什么**：
> - 各设备驱动如何用总线信息（见 `14-virtio-framework.md`、`16-ahci-ata-driver.md`、`22-net-driver-reference.md`，本篇只讲提供方）
> - 桥窗口的力学与中断路由的芯片细节（本篇只讲记录与规则，探测在服务层）
> - 输入输出控制总线（见 `24-misc-drivers.md`）
>
> 本篇只回答一个问题：**一张新卡插上系统，驱动如何知道它是谁、能不能碰、怎么说话**。

## 1. 概念：车管所

### 1.0 章节引言

目标读者是理解字符框架与权限门的读者。前置知识只需要两条：通用挂钩收杂项消息，权限门先验后做。本章解释总线驱动的三件套：建档、说话、门禁。

### 1.1 总线驱动是车管所

想象车管所：新车上牌（枚举建档：厂商、型号、车架号），车主查档（查询：首辆、下一辆、按牌找、看证），过户设限（访问名单：这辆车谁能开）。车管所不管开车（设备驱动开），只管档。档不全，车不许上路。

Minix3 的总线驱动就是车管所。启动时扫全部总线建档（枚举），设备驱动来查档（查询协议十八问），驱动要碰卡先挂名（预留与名单）。中断路由是牌照续签：卡说自己用几号线，车管所记下来告诉内核。

### 1.2 查询十八问：查档手册

查询协议十八个操作，基址 `0x300` 加索引（注意五号六号空着：历史删号留空，解码时跳过）。分四组：建档组（握手 `BUSC_PCI_INIT`、首设备 `BUSC_PCI_FIRST_DEV`、下设备、找设备 `BUSC_PCI_FIND_DEV`、看证），读写组（八字节十六三十二读写共六问，如 `BUSC_PCI_ATTR_R32`），管理组（预留、重扫、设备名、槽名、设名单 `BUSC_PCI_SET_ACL`、删名单、地址窗口 `BUSC_PCI_GET_BAR`），保留组（输入输出内存映射号归别的驱动）。

查档的规矩是游标制：首设备（`do_first_dev`）从零开始，下设备（`do_next_dev`）接着上次的索引往后，找设备（`do_find_dev`）按总线设备功能直达，看证按索引取厂商设备号。游标在调用方手里（消息里带索引），驱动无状态：同一次遍历中途换调用方不影响，因为位置信息全在消息里。这是无状态游标的经典形状：服务端不记你走到哪，你自己说。

### 1.3 配置空间：每卡二百五十六格

每张卡（严格说是每个功能）有二百五十六字节配置空间，读写按八十六三十二三种宽度。宽度与对齐是绑死的：三十二位访问必须四对齐，十六位二对齐，八字节任意。错位访问没有定义，驱动直接拒绝（无效），不猜调用方想干什么。

端口号永不进操作系统层：行为定义只谈总线设备功能偏移宽度值，端口周期在板侧实现。这是硬件抽象的老规矩，本篇的落点是配置空间。

### 1.4 名单门禁：谁的卡谁开

可见性规则一句话：没上名单的卡人人可见，上了名单的卡只有名单上的人可见。一张卡一旦有人预留（挂名），没挂名的人立刻看不见它（遍历跳过）。预留与设名单是两个入口同一张表：预留（`do_reserve`）是驱动给自己挂名，设名单是管理方给别人挂名，删名单与释放是摘名（释放摘自己的全部，删名单摘指定调用方的）。

这条规则防止两家驱动抢一张卡：网卡驱动预留了自己的卡，磁盘驱动遍历时根本看不见它，抢都没处抢。门禁在遍历层做，不在读写层做：看不见就不会去读，比读时再拦早一步。

### 1.5 枚举建档：扫街

启动扫描（`probe_bus`）从零号总线起，逐设备逐功能读厂商号（全一说明没卡），有卡建档（厂商、设备、中断针），桥设备递归进下级总线（桥后面还有街），中断线路由（针号换线号），地址窗口记录（桥的窗口、卡的地址寄存器）。重复位置（`is_duplicate`）拒绝建档（同一位置两条记录说明探测重了，宁可丢后者）。

桥标识表是作弊小抄：已知桥芯片的厂商设备号对照表（三十七行，十几座桥），命中直接用已知行为，不命中走通用桥流程。小抄的好处是启动快，代价是新桥要加表，这是用维护换时间的典型交易。

### 1.6 控制码：字符控制的七件事

字符控制分支（`pci_ioctl`）管七件事：按总线设备功能读写配置寄存器（先找索引，找不到无效参数），总线信息（占位接受，无载荷），映射物理内存（先加特权再映射，失败带错出），解映射，预留（找索引授访问），释放（摘名），其余（老式总线读写）一律不合适操作。映射是敏感操作：先给调用方加内存特权，成了才映射，不成连映射都不碰。

### 1.7 本章小结

总线驱动是车管所：枚举建档，查询十八问，无状态游标，配置三宽度，名单门禁，控制七件事。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单

| 文件 | 行数 | 内容 |
|------|------|------|
| `minix3/minix/drivers/bus/pci/main.c` | 七百四十行 | 查询协议十八问、控制七件事、字符表、主循环 |
| `minix3/minix/drivers/bus/pci/pci.c` | 二千五百五十九行 | 枚举、桥、地址窗口、中断路由、可见性 |
| `minix3/minix/drivers/bus/pci/pci_table.c` | 三十七行 | 桥标识对照表 |
| `minix3/minix/include/minix/com.h`（第九十五 行到第一百六十行） | 约六十五行 | 总线查询号段 |

### 2.2 查询协议（`main.c` 第四十六行到第五百二十四行）

握手回空消息（新手报到，驱动记一下）。首设备查调用方名单，从零找第一可见（索引加厂商设备号三件套回填，回复号即结果码）。下设备从消息索引续找。找设备按总线设备功能直达（找不到结果码非一）。看证按索引取号。设备名槽名按厂商号或索引取名字符串，超长截断，复制失败带错出。设名单删名单改表。预留挂名。地址窗口取属性。重扫重走枚举。每个处理函数尾都是填回复发非阻塞发送，发送失败打印日志（查询答复丢了调用方会重问，不重试）。

### 2.3 控制七件事（`main.c` 第五百三十八行到第六百六十八 行）

按总线设备功能读写：先复制入参（失败带错出），找索引（找不到无效参数），读调三十二位读回填复制回，写直接写。配置读写只实现三十二位版（八字节十六位版走查询协议，控制分支不管）。总线信息占位接受。映射：复制入参，加内存特权（失败带错出），映射物理内存，回填复制回。解映射：复制入参，解映射。预留：复制入参，找索引，授访问。释放：复制入参，摘名，成功。老式读写默认不合适操作。

### 2.4 通用挂钩与字符表（`main.c` 第六百七十行到第七百六十行）

通用挂钩按消息号分发十八问（对不上打印未处理，不回复：打日志就是答复，调用方看日志自查）。字符表四挂钩（打开关闭全接受，控制七件事，通用十八问）。注意没有读写真挂钩：总线驱动不搬字节，读写走默认（输入输出错误）。主循环是字符框架主循环（初始化回调在枚举文件里）。

### 2.5 枚举与路由（`pci.c` 选读）

端口级读写三宽度六函数，索引级包装六函数，状态读写，重复位置拒绝，空闲总线分配，厂商名表，桥能力打印，桥窗口更新，四种南桥初始化，桥识别，中断推导，中断记录，地址寄存器记录（三类：普通、桥、卡总线），桥补全，桥遍历，桥中断读写（三实现），桥完成，英特尔初始化，显卡上报，可见性，启动初始化。二千五百五十九行里本篇只定策略（记录形状、遍历顺序、可见性规则），力学（端口周期、窗口算法）全在服务层。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 查询号做成枚举（依据：第 1.2 节、第 2.1 节）

十八变体，空号跳过（五六号无变体，解码直接空）。索引与消息号互转常量函数。替代方案是整数常量，不选的理由同框架篇。空号跳过是易错点：枚举里没有五六号，调用方传 `0x305` 解码为空，映射为无效参数，与通用挂钩的未处理分支一致。

### 3.2 配置空间做成行为定义（依据：第 1.3 节、第 2.5 节）

读写两方法，宽度枚举，对齐谓词。空空间与内存空间两个行为不同的实现满足门禁：空空间专测缺硬件路径，内存空间测三宽度读写与错位拒绝。内存空间三十二位槽加掩码拼拆十六八字节，与硬件小端布局一致（注释写明）。替代方案是端口号进库，不选的理由是硬件抽象原则：操作系统层不见端口。

### 3.3 设备库做成向量加名单（依据：第 1.4 节、第 1.5 节、第 2.2 节、第 2.5 节）

记录向量（上限六十四，生产按拓扑来，测试够用），名单向量，重复位置拒绝，可见性一函数，游标查询一起始一续查。预留即挂名，释放摘名。替代方案是哈希表加锁，不选的理由是：单线程事件循环下向量线性扫足够快（六十四项），哈希是多余依赖。

### 3.4 控制码做成枚举（依据：第 1.6 节、第 2.3 节）

七变体，老式读写不在其中（解码空转不合适操作）。数值（输入输出控制编码平台相关）在服务层比对，本库只认种类。替代方案是数值进库，不选的理由是：平台相关编码进库等于把移植性卖了。

### 3.5 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 查询号用枚举 | 第 1.2、2.1 节 | 整数常量 | 空号漏判 |
| 配置行为定义 | 第 1.3、2.5 节 | 端口号进库 | 硬件泄漏 |
| 库向量加名单 | 第 1.4、1.5、2.2、2.5 节 | 哈希加锁 | 单线程用不上 |
| 控制码用枚举 | 第 1.6、2.3 节 | 数值进库 | 卖移植性 |

## 4. 错误处理

| 场景 | C 行为 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 空号查询 | 未处理分支 | `decode` 空 | 五六号无变体 |
| 找不到索引 | 结果码非一 | `find` 空 | 直达失败 |
| 错位访问 | 无定义 | `is_valid` 假转无效 | 不猜调用方意图 |
| 板卡拒绝 | 错码 | `ConfigError::BoardFault` | 板侧故障 |
| 重复建档 | 拒绝后者 | `add` 返回假 | 探测重了丢后者 |
| 库满 | 拒绝 | `add` 返回假 | 生产按拓扑 sizing |
| 未授权遍历 | 跳过 | `is_visible` 假 | 看不见不读写 |
| 老式控制 | 不合适操作 | `BusControl` 无变体 | 解码空转该码 |
| 复制失败 | 带错出 | 服务层透传 | 复制在服务层 |

## 6. 过渡：从总线到引脚

总线驱动管的是插卡的户籍，下一篇引脚驱动管的是板上引脚的户籍：引脚认领、模式、读写、文件导出，外加设备注册库（驱动侧的增删）。两篇对照看：总线的名单管谁能看卡，引脚的认领管谁能用脚，都是先登记后使用。读引脚之前，建议重温本篇的可见性规则：引脚认领失败与总线授权失败是同一类错误（资源有主了）。
