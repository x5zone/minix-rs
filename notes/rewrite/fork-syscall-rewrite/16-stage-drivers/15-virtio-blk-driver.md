## 1. 概念：外卖三件套

### 1.0 章节引言

目标读者是读完框架篇的读者。前置知识只需要一条：描述符链怎么串。本章解释块请求的三段形状，以及扇区对齐为什么是铁律。

### 1.1 虚拟块请求是外卖三件套

想象点外卖：订单小票（头：读写类型、扇区号）、饭菜（数据段）、评价卡（状态字节，宿主机写）。三件缺一不可：没小票宿主机不知道读哪，没饭菜没东西搬，没评价卡客户机不知道咸淡。顺序固定：小票在前，饭菜居中，评价卡殿后。评价卡永远是宿主机写（客户机读），方向错了整单作废。

Minix3 的虚拟块请求就是这三件套。方向定类型（读 `VIRTIO_BLK_T_IN` 进，写 `VIRTIO_BLK_T_OUT` 出），位置除以五百一十二定扇区号，向量定数据段数，状态段恒一位。宿主机吃完在状态段写一字节：零成功（`VIRTIO_BLK_S_OK`），一输入输出错，二不支持，其他值一律按输入输出错处理（未知状态永不按成功放行，这是状态翻译的铁律）。

### 1.2 扇区对齐：铁律两条

位置与长度必须五百一十二对齐，不对齐直接无效参数。两条铁律的理由不同：位置不对齐，扇区号算出来带小数，没法要；长度不对齐，尾巴凑不够一块，宿主机没法收。这是虚拟块与内存盘的分水岭：内存盘按字节算，虚拟块按扇区算，跨界必须先对齐。

### 1.3 截断：分区是天花板

请求跨过分区尾按剩余截短，截到块边界（截完再对五百一十二取整，保证还是整块数）。向量随之修：超长的末段截短，截空的段丢掉。到头（位置过分区尾）答零字节（读到头了，不是错）。只读盘的写在编链前就拒（特性里有只读位，写请求到此为止，不进队列）。

### 1.4 单盘单分区：抄近道

全驱动只认一块盘一个分区，分区表就是容量乘块大小。几何上报与分区查询全返回这一套数。这不是偷懒，是虚拟硬件的形状就这样：一台虚拟机一块虚拟盘，分区在客户机文件系统里分，不在驱动里分。抄近道抄得理直气壮：形状简单，代码就简单。

### 1.5 控制两问：数人头与冲水

控制分支两问：数人头（打开计数拷回），冲水（刷写缓存）。其余控制码一律不合适操作。数人头是调试用的：谁没关盘一目了然。冲水走刷新请求（类型冲刷），宿主机落盘后才算完。

### 1.6 本章小结

虚拟块是三件套：头定类型，扇区定位置，向量定段数，状态定错码，对齐是铁律，分区是天花板，单盘抄近道。下一章进入 C 语言源码验证。

### 2.2 请求组装（`virtio_blk.c` 第二百八十行到第三百七十九行）

位置不对齐、长度不对齐直接无效参数。到头答零。向量修整（超长截末段，截空丢段）。块数不对齐无效参数。虚实映射（失败带错出）。填头（方向定类型，优先级零，扇区号），头段、数据段、状态段三段进链（状态段恒置写位），发链，等完成。完成看状态：成功返字节数，失败进状态翻译。

### 2.3 状态翻译（`virtio_blk.c` 第五百四十九行到第五百六十三行）

### 2.4 分区几何控制探测

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 链规划做成纯函数（依据：第 1.1 节到第 1.3 节、第 2.2 节）

位置长度分区进，类型扇区段数字节出。到头答零字节（不是错），截断向下取整块。替代方案是规划里直接发链，不选的理由是：发链要队列，队列在服务层，规划只算形状。

### 3.2 状态翻译做成全匹配（依据：第 1.1 节、第 2.3 节）

成功输入输出错不支持各归位，通配全按输入输出错。替代方案是通配透传原值，不选的理由是：未知状态透传等于把宿主机的 bug 当成功报，错杀比放过安全。

### 3.3 几何做成值类型（依据：第 1.4 节、第 2.4 节）

容量扇区数乘块大小，只读位前置拒写。打开计数饱和减（关超开不清零，调用方糊涂不连累计数）。替代方案是裸整数到处算，不选的理由是：容量乘块大小散出去，总有一处忘乘。

### 3.4 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 链规划纯函数 | 第 1.1-1.3、2.2 节 | 规划发链 | 队列在服务层 |
| 状态全匹配 | 第 1.1、2.3 节 | 通配透传 | 错杀比放过安全 |
| 几何值类型 | 第 1.4、2.4 节 | 裸整数 | 忘乘块大小 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 位置不对齐 | 无效参数 | `plan_transfer` 错 | 扇区号算不出 |
| 长度不对齐 | 无效参数 | `plan_transfer` 错 | 尾巴凑不够块 |
| 到头 | 答零 | 零字节规划 | 读到头不是错 |
| 只读盘写 | 拒绝 | `refuses_write` 真 | 编链前拦 |
| 状态成功 | 成功 | 零码 | 全绿 |
| 状态输入输出错 | 输入输出错误 | 透传 | 宿主机说坏了 |
| 状态不支持 | 不支持 | 透传 | 宿主机说不会 |
| 未知状态 | 输入输出错误 | 通配错 | 错杀不放过 |

## 6. 过渡：从虚拟盘到真盘

虚拟块是最好写的块驱动：宿主机全包，驱动只编链。下一篇高级主控接口是真硬件：端口、命令表、散集表、中断、超时、复位，全自己来。两篇对照看：虚拟块的链在内存里编，真盘的链在硬件表里编，编链思想相通，等待形状不同（虚拟块睡等，真盘中断加超时）。读真盘之前，建议重温本篇的截断规则：真盘也有分区天花板，算法同一套。
