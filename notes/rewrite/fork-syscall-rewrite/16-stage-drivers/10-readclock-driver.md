# 10-readclock-driver：实时时钟驱动

> **分类**：系统服务第 2 篇（硬件时钟三操作，转发模式）
> **源码**：`minix3/minix/drivers/clock/readclock/readclock.c`（一百九十一行，协议循环与十进制换算）、`minix3/minix/drivers/clock/readclock/forward.c`（一百二十行，转发到芯片驱动）、`minix3/minix/drivers/clock/readclock/readclock.h`（时钟操作表）、`minix3/minix/drivers/clock/readclock/arch/`（两种架构时钟，见第 2.7 节）、`minix3/minix/include/minix/com.h`（第九百九十五 行到第一千零十二行，实时钟协议常量）
> **Rust 模块**：`os/drivers/clock/readclock/src/protocol.rs`（协议编号与时间形状）、`os/drivers/clock/readclock/src/clock.rs`（十进制换算与时钟抽象）、`os/drivers/clock/readclock/src/device.rs`（权限分诊）
> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/01-chardriver-framework.md`（本篇不走字符框架，走专有协议，见第 1.2 节）
> **说明**：实时时钟是断电也走的硬件钟，开机对时、定时关机全靠它。本篇讲它的三操作协议：读、写、断电，外加转发模式（时钟嵌在多功能芯片里时转交芯片驱动）。权限门是本篇的重点：读人人可读，写要超级用户，断电只要电源管理。

> **本篇不讲什么**：
> - 时钟服务与定时器（见 `../01-stage-kernel/` 的时钟定时篇，本篇只讲硬件钟）
> - 两种架构时钟的寄存器细节（见第 2.7 节分工，逐寄存器展开留给架构文档）
> - 芯片驱动本身（本篇只讲转发，芯片驱动各归其类）
>
> 本篇只回答一个问题：**三个时钟操作各自验谁的资格，时钟嵌在别的芯片里时怎么办**。

## 1. 概念：传达室的挂钟

### 1.0 章节引言

目标读者是理解请求分诊的读者。前置知识只需要一条：消息类型认家族。本章解释时钟协议为什么自立门户，以及三操作的资格门。

### 1.1 实时时钟是传达室的挂钟

想象单位传达室墙上的挂钟：谁路过都能看（读时间），只有后勤能调（写时间），拉闸断电只有电工说了算（断电）。挂钟停电也走（电池），所以开机第一件事是对表：系统时间从它来。

Minix3 的实时时钟驱动就是这块挂钟。读操作（`RTCDEV_GET_TIME`）人人可读（时间是公开信息），写操作（`RTCDEV_SET_TIME`）验超级用户（`SUPER_USER`，调时间影响全系统），断电操作（`RTCDEV_PWR_OFF`）验电源管理端点（`PM_PROC_NR`，只有它知道关机流程走完没走完）。三道门，门门在碰芯片与碰调用方缓冲之前：资格不够，连读调用方的时间结构那一步都省了。

### 1.2 为什么不走字符框架

字符框架的七种请求（打开关闭读写控制取消轮询）没有一个是读时间的形状：读时间要带回一个时间结构，写时间要从调用方取一个时间结构，断电没有数据只有资格。实时钟协议是专为这三件事定的：请求号五个（读、写、断电，外加授权版的读写 `RTCDEV_GET_TIME_G` 与 `RTCDEV_SET_TIME_G`），回复号一个（`RTCDEV_REPLY`）。协议号段独立（基址 `0x1400`），判定宏同形（高位比对）。框架是手段，协议是目的：形状对不上就另起协议，不削足适履。

### 1.3 转发模式：挂钟挂在别人墙上

有些实时钟嵌在多功能芯片里，芯片驱动已经会读写它。这时时钟驱动不当家，只当二传手：收到的请求原样转给芯片驱动，芯片驱动的答复原样带回。转发的三条规矩：目标标签（`fwd_set_label` 设、`fwd_exit` 清）没配拒绝初始化（`fwd_init`，不知道往哪转就不开张），断电请求（`fwd_pwr_off`）无数据直转（断电消息不带时间结构），读写（`fwd_get_time`、`fwd_set_time`）走授权（给芯片驱动开临时授权，用完即销，授权泄漏等于把时钟送人）。

二传手的价值是隔离变化：全系统的服务只认时钟驱动一家，芯片换了只改转发目标，调用方一行不用动。这是外观模式的教科书用例：一个固定门面，后面随便换。

### 1.4 十进制换算：芯片说方言

硬件钟存的是二六十进制（一字节两位十进制数），操作系统用二进制。读出来要译（高半字节乘十加低半），写进去要编（十除十进高半，余数进低半）。两个函数互逆，零到九十九往返无损。这是全驱动最纯的函数：无状态，无副作用，测试一次全覆盖。

### 1.5 通知丢弃：敲门没下文的不理

通知消息一律丢弃不回复（主循环收到通知直接下一轮）。时钟驱动没有定时器、没有中断、没有事件灯，通知对它没有意义。字符框架的通知旁路在这里退化成一句话：与我无关，下一位。

### 1.6 本章小结

时钟驱动是挂钟：读放行、写验超级用户、断电验电源管理，协议自立门户，嵌在别家转交，十进制换算两种，通知丢弃。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单

| 文件 | 行数 | 内容 |
|------|------|------|
| `minix3/minix/drivers/clock/readclock/readclock.c` | 一百九十一行 | 协议循环、权限门、十进制换算、调用方缓冲搬运 |
| `minix3/minix/drivers/clock/readclock/forward.c` | 一百二十行 | 转发目标、授权版读写、断电直转 |
| `minix3/minix/drivers/clock/readclock/readclock.h` | 约二十行 | 时钟操作表与架构装配声明 |
| `minix3/minix/drivers/clock/readclock/arch/` | 两种架构时钟 | 芯片寄存器读写（见第 2.7 节） |
| `minix3/minix/include/minix/com.h`（第九百九十五 行到第一千零十二行） | 约十八行 | 请求基址、五个请求号、一个回复号 |

### 2.2 协议循环（`readclock.c` 第五十行到第一百三十一行）

阻塞收任意消息，接收失败记日志继续（注意不是停下：时钟驱动的接收失败被视为可恢复，与字符框架的停下哲学不同，原因是时钟无状态，重收一条就是）。通知丢弃。读：调芯片读，失败带错出；成功把时间结构拷回调用方，拷失败带错出。写：验超级用户（不是拒绝访问），取调用方时间结构（取失败带错出），调芯片写。断电：验电源管理端点，否则拒绝访问。未知请求无效参数。回复一律通用回复号加状态码，非阻塞发送（发送失败记日志继续）。

接收失败继续而不是停下，是本篇与框架篇最大的行为差异：时钟驱动不记任何跨请求状态（时间在芯片里，不在驱动里），一条坏了下一条照做。有状态才怕坏状态，无状态怕什么。这是故障处理与状态持有量的正比关系，值得停留。

### 2.3 权限门（`readclock.c` 第七十一行到第一百零八行）

读无门（注释明示任何用户可读）。写验超级用户（调用方用户号比对）。断电验端点等于电源管理（端点比对，比用户号更严：连超级用户冒充都不行，必须是那个进程）。门全在搬运与芯片之前，顺序见第 1.1 节。

### 2.4 十进制换算与缓冲搬运（`readclock.c` 第一百六十七行到第一百九十一行）

译码 `bcd_to_dec`：高半与十五取十乘加低半。编码 `dec_to_bcd`：十除十进高半，余数进低半。取时间结构：调用方拷进（数据复制）。存时间结构：拷回调用方。四个函数全纯（除搬运外），换算两函数无状态。

### 2.5 转发（`forward.c` 全文一百二十行）

目标标签设取清三函数（设标签、清标签、无标签初始化拒绝）。发消息：查标签端点（查不到返回负一），断电直发（无数据无授权），读写开临时授权（读授权写方向，写授权读方向，方向别搞反：授权方向是对方视角），发系统调用，销授权，验回复号与状态（不对记日志返回负一）。授权版读写各一行（方向不同），断电一行动力全无。退出清标签。

授权方向是新人的第二个陷阱：读时间是对方写我方缓冲，所以开写授权；写时间是对方读我方缓冲，所以开读授权。方向是对方的动作，不是我的动作。

### 2.6 初始化（`readclock.c` 第一百三十三行到第一百六十五 行）

架构装配 `arch_setup`（填操作表 `struct rtc`）失败记日志返回错，芯片初始化失败记日志返回错。新旧重启热升级全走同一函数（无状态可丢，全场景重装配即可）。退出调芯片退出（主循环永不退出，这行是给静态分析看的）。

### 2.7 架构时钟分工（不展开寄存器）

两种架构时钟各实现操作表（初始化、读写、断电、退出）。本篇只记录分工与文件名，逐寄存器行为留给架构文档。时钟操作表是硬件抽象的实例：操作系统层只认表，寄存器在表后面。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 请求编号做成枚举（依据：第 1.2 节、第 2.1 节）

五变体，授权版各占一变体（授权是传输细节，但请求号不同，路由必须分得清）。解码失败返回空，调用方映射为无效参数。替代方案是整数常量，不选的理由同框架篇。

### 3.2 时间形状做成值类型（依据：第 1.4 节、第 2.4 节）

六字段（时分秒日月年），周日与年日随身不解释。合理性谓词收进类型（秒容闰秒，年下限一九七零）。内存时钟的写入口先验合理性再存，不合理报无效参数：早拦比存了再错强。替代方案是透传 C 结构，不选的理由是：合理性检查散出去，每个写入口写一遍，迟早漏一处。

### 3.3 时钟硬件做成行为定义（依据：第 2.7 节）

初始化读写断电退出五方法，退出默认空体（主循环永不退出，退出只为完整）。空时钟与内存时钟两个行为不同的实现满足门禁：空时钟专测缺硬件路径，内存时钟测读写存取。替代方案是函数指针表，不选的理由同框架篇。

### 3.4 权限门做成纯分诊（依据：第 1.1 节、第 2.3 节）

调用方身份收成两布尔（超级用户、电源管理），分诊是纯函数：通知丢、未知错、读放、写验、断电验。拒绝带错码（拒绝访问），不带悬念。分诊在复制与芯片之前，顺序由类型保证（分诊输出是枚举，芯片调用在服务层按枚举走，跳过分诊拿不到放行变体）。替代方案是门散在各入口，不选的理由是：门散出去，新增操作（比如未来加闹钟）容易忘验。

### 3.5 转发目标做成值类型（依据：第 1.3 节、第 2.5 节）

标签有无一布尔（字符串在服务层），无标签初始化拒绝。授权方向规则写进文档（读开写授权，写开读授权），实现时由服务层的授权类型保证。替代方案是字符串进库，不选的理由是：标签比较与端点查找全是传输相关，库里放字符串只是摆设。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 请求编号用枚举 | 第 1.2、2.1 节 | 整数常量 | 漏检查即漏洞 |
| 时间值类型 | 第 1.4、2.4 节 | 透传 C 结构 | 合理性检查散落 |
| 时钟行为定义 | 第 2.7 节 | 函数指针表 | 空检查分散 |
| 权限纯分诊 | 第 1.1、2.3 节 | 门散各入口 | 新增操作忘验 |
| 转发值类型 | 第 1.3、2.5 节 | 字符串进库 | 传输相关摆设 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 通知 | 丢弃不回复 | `Dispatch::Drop` | 与我无关 |
| 未知请求 | 无效参数 | `Dispatch::Unknown` | 认不出就报 |
| 写无超级用户 | 拒绝访问 | `Set(Err)` | 调时间影响全系统 |
| 断电非电源管理 | 拒绝访问 | `PowerOff(Err)` | 端点比对更严 |
| 芯片读失败 | 带错出 | 服务层透传芯片错 | 读失败不伪造时间 |
| 调用方缓冲失败 | 带错出 | 服务层透传复制错 | 资格够了搬运跪了照报 |
| 无标签初始化 | 无效参数 | `ForwardTarget::init` 错 | 不知道往哪转不开张 |
| 转发失败 | 负一 | 服务层转错 | 对方拒收或状态错 |
| 不合理时间 | 无效参数 | `set_time` 先验 | 早拦比存错强 |

## 6. 过渡：从时间到总线

时钟驱动是不碰字符框架的第一个驱动：协议自立门户，权限门前置。下一篇总线驱动走回字符框架（打开关闭控制通用挂钩），但控制命令与查询消息两套并行：控制走字符控制，查询走通用消息。这是字符框架的另一种用法：框架只管收发，语义全在控制码与消息号里。读总线之前，建议重温本篇的权限门：总线的访问控制表是同一类思想（先验资格再碰硬件），只是资格从身份变成了名单。
