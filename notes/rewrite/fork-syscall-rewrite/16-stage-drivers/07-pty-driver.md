## 1. 概念：对讲机

### 1.0 章节引言

目标读者是已经读完终端驱动的读者。前置知识只需要一条：终端的行规则与挂起选择。本章解释伪终端多出来的东西：对、主从分工、克隆分配、包模式。

### 1.1 伪终端是一对对讲机

想象一对对讲机：甲按住说话，乙听见；乙按住说话，甲听见。主端与从端就是这对机器：主端写的字节出现在从端的输入队列（当作键盘敲的），从端写的字节进主端的输出环（当作屏幕显示的）。方向只有两条：主到从，从到主，不存在第三条。

远程登录会话是标准的对讲场景：键盘敲的字进主端，主端递给从端，壳读到执行；壳的输出进从端，从端递给主端，服务发往网络。终端驱动管的是真线，伪终端管的是假线，行规则两边同一套。

### 1.2 三十二对：一对一状态机

全系统 `NR_PTYS` 三十二对，每对一台状态机。状态六个位：终端端开、主端开、终端端关、主端关、Unix98 种、包模式。经典对的规矩是：从端可以先开（用户态靠这个找空对），主端只开一次（开过的主端再开是错误）。Unix98 对的规矩反过来：主端只能从克隆设备领，直接开主端号走后门一律拒绝。

两端都关了整对复位：状态清零，Unix98 对还请文件系统删从节点（删了也可能本来就没有，失败一律忽略）。复位是配对语义的核心：半开的对不留垃圾状态，下一位用户拿到的是干净的对。

### 1.3 克隆设备：领号机

克隆设备是发号机：打开它，驱动找第一对空对，打上 Unix98 标记，回答克隆成功加新主端号。找不着空对回答再试（这是 POSIX 规定的错误码，不是驱动自创）。打开前先请文件系统清掉该对可能残留的旧从节点：不清会有两个问题，一是旧节点指向已死的对，二是重启后残留节点是安全洞。清不掉直接拒绝克隆，让调用方换别的分配办法。

### 1.4 输出环：从端到主端的传送带

从端写的字节先进二千零四十八字节的环，主端读时再从环里取。环满了只进能进的部分（终端输出从不等人）。主端读挂起时，环里一有货就泵：先泵包模式零字节（包模式开且本次读还没交过货），再泵环里字节，直到环空或读够。泵完货数大于零才答复，否则继续等。

主端读取消按挂起配对：调用方加标识对上才取消，有货答货数，无货答中断，对不上静默吞。这是终端取消的翻版，只是路数少（主端只有读写两路挂起，没有排空挂起）。

### 1.5 包模式：最小可用的信封

包模式是给远程登录服务的状态信封：从端状态变了，主端读时先拿到一个零字节，知道有状态事发生。实现是极简的：只在包模式开且本次读还没交货时塞一个零，后续完整支持标注了待办。这是一种诚实的最小实现：够跑通服务，不够全功能，差的部分写在注释里不藏着。

### 1.6 选择语义：主端版的两条规则

主端轮询的就绪规则与终端同形，数据源不同：写就绪 `CDEV_OP_WR` 看从端关（关了必就绪，报错也是就绪）、主写挂起（挂着必不阻塞）、从队列有空；读就绪 `CDEV_OP_RD` 看从端关、主读挂起、输出环有货。从端关了一切就绪（与终端挂断规则同理）。

### 1.7 文件系统侧车：从节点的户籍警

Unix98 从节点住在伪终端文件系统里，驱动管增删，文件系统管树。通信是同步的：发请求等到对方确认才返回，避免驱动与用户态之间的竞态。端点不缓存：每次现查，文件系统重启重挂后不拿旧端点。查不到文件系统，增删全失败，克隆走不通，用户态回退别的分配办法。

### 1.8 本章小结

伪终端是对讲机：三十二对状态机，主端挂钩，输出环二千零四十八字节，包模式塞零信封，选择看环与挂起，文件系统管户籍。下一章进入 C 语言源码验证。

### 2.2 对表与分配（`pty.c` 第四十六行到第一百三十六行）

对结构含终端指针、状态字节、主读写挂起、输出环、选择登记。状态六位见第 1.2 节。对表三十二项。找空对线性扫，扫不到返回空（克隆调用方答再试）。主端回调表 `pty_master_tab` 七挂钩（打开、关闭、读、写、控制、取消、选择），注意没有中断与定时：伪终端没有硬件，不会来中断。

### 2.3 主端打开（`pty.c` 第一百三十八行到第二百二十三行）

克隆分支：找空对（没有答再试），清文件系统旧节点（不清掉答再试），打 Unix98 标记，算新主端号，回答克隆成功。经典分支：号段之外输入输出错误，映射失败没有此设备，主端已开输入输出错误（从端先开不拦）。分支末统一打主端开标记，清读写货数。经典主端拒绝 Unix98 种（防后门），Unix98 主端拒绝直接开（只能克隆领）。

### 2.4 复位与关闭（`pty.c` 第一百九十三行到第二百六十行）

复位清状态（Unix98 对先请文件系统删节点，失败忽略）。主端关闭：映射失败没有此设备，标主端关，从输出环唤醒挂起的从端写（关闭是最强的就绪），两端全关走复位。从端关闭在从端文件里，对端关闭唤醒主端读。

### 2.5 主端取消与选择（`pty.c` 第四百一十五行到第五百一十六行）

取消按读写两路配对调用方加标识，有货答货数、无货答中断、对不上不回复。选择探测 `select_try_pty`：写看从端关、主写挂起货数、从队列空位；读看从端关、主读挂起货数、输出环货数。选择注册与终端同形。重试 `select_retry_pty` 测登记的操作，有就绪发迟通知清位。主端请求入口 `do_pty` 是字符框架的直接调用（一行）。

### 2.6 输出泵与完成（`pty.c` 第六百二十一行到第六百八十一行）

泵循环：环空或读够停；包模式且本次未交货先塞零（复制失败停泵）；环货按需搬（复制失败停泵）；记账（环减、读增）。完成函数：货数大于零才答复并清挂起，否则继续等。从端读函数 `pty_slave_read`：对端关了唤醒挂起的终端读，否则按试探或挂起返回。从端写函数：字节进输出环，环满截断，唤醒主端读。

### 2.7 文件系统侧车（`ptyfs.c` 全文一百一十二行）

同步通信：现查端点（不缓存），查不到报死端点，查到发收等确认。增节点：填索引、模式、属主、设备号，发增请求，返回对方的答复码。删节点：发删请求。模式是字符设备加六二零权限。驱动重启后残留节点靠克隆时的预清除扫掉，见第 1.3 节。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 对状态做成标志字节（依据：第 1.2 节、第 2.2 节）

六个位一字节，开关用位操作。挂起槽与缓冲不在状态里，各归各的类型。对表三十二项定长，找空对线性扫。替代方案是六个布尔字段，不选的理由是：C 语言的状态判断全是位与，标志字节让 Rust 的判断与 C 逐位对得上，审阅时一眼可比。

### 3.2 开关规则做成状态方法（依据：第 1.2 节、第 1.3 节、第 2.3 节、第 2.4 节）

经典主端单开、克隆领号、从端先行、双关复位，四条规则收成四个方法。文件系统清理由服务层在调克隆方法前后做（行为抽象见第 3.5 节），状态机只管位。替代方案是开关逻辑散在服务层，不选的理由是：规则是驱动的，散出去服务层各自为政，迟早有一处忘了复位。

### 3.3 输出环做成计数泵（依据：第 1.4 节、第 2.6 节）

环存字节，泵动计数，复制在服务层。包模式零字节是计数（占读名额），不是环里真有个零。完成函数货零不开口。取消按配对答货数或中断。替代方案是环里真塞零字节，不选的理由是：真塞零会污染环，读名额与环货数两本账对不上。

### 3.4 选择探测做成纯函数（依据：第 1.6 节、第 2.5 节）

输入全是事实快照，输出是就绪位，无副作用。调用方拼事实，探测只算位。替代方案是探测直接读对结构，不选的理由是：对结构含挂起槽与缓冲，探测函数签名会拖进整个对，纯事实快照让测试一次测一条规则。

### 3.5 文件系统做成行为定义（依据：第 1.7 节、第 2.7 节）

增删两方法，缺席与内存两实现。克隆门是自由函数：清成功才放行。缺席实现专测克隆失败路径（文件系统没跑时用户态回退）。替代方案是直接调数据存储查端点，不选的理由是：那样克隆失败路径测不了，只能等文件系统挂了测。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 状态标志字节 | 第 1.2、2.2 节 | 六布尔字段 | 位判断与 C 对不上 |
| 开关状态方法 | 第 1.2、1.3、2.3、2.4 节 | 散在服务层 | 迟早忘复位 |
| 输出计数泵 | 第 1.4、2.6 节 | 环里真塞零 | 两本账对不上 |
| 探测纯函数 | 第 1.6、2.5 节 | 直读对结构 | 签名拖进整个对 |
| 文件系统行为定义 | 第 1.7、2.7 节 | 直调查端点 | 失败路径测不了 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 无空对克隆 | 再试 | `first_free` 空转该码 | POSIX 规定码 |
| 文件系统不清旧节点 | 再试 | `clone_gate` 假转该码 | 安全洞不将就 |
| 经典主端双开 | 输入输出错误 | `open_master` 返回该码 | 一对一主端 |
| 号段外主端 | 输入输出错误 | 服务层号段检查 | 经典分支守卫 |
| 映射失败 | 没有此设备 | 服务层映射检查 | 通用守卫 |
| 取消 miss | 不回复 | `cancel` 返回空 | 陈旧取消静默吞 |
| 取消命中空读 | 中断 | `cancel` 返回该码 | 等读被信号打断 |
| 从端关后读写 | 就绪（报错也是就绪） | `probe` 置位 | 等下去无意义 |

## 6. 过渡：从假线到日志

伪终端证明字符框架能挂无硬件设备：主端七挂钩没有中断定时，照样跑。下一篇日志驱动是另一个无硬件字符设备：环形缓冲加挂起读加诊断捕获。两篇对照看：伪终端的环在主从之间传字节，日志的环在写读之间传字节，环的写法（写指针追读指针、满了盖旧货）是同一套。读日志之前，建议重温本篇的输出泵：日志的挂起读唤醒是同一套泵思想。
