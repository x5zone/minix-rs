# 23-net-driver-variants：十二网卡变体差异

> **分类**：网络第 2 篇（十二家环不同，中轴不变，差异只列不同）
> **源码**：`minix3/minix/drivers/net/e1000/e1000.c`（九百一十八行）与 `e1000.h`（环数量）与 `e1000_hw.h`（描述符布局）、`minix3/minix/drivers/net/rtl8139/rtl8139.c`（一千五百三十行）与 `rtl8139.h`（槽数与环游标）、`minix3/minix/drivers/net/lance/lance.c`（八百九十五 行）与其余九目录（见第 2.6 节矩阵）
> **Rust 模块**：`os/drivers/net/e1000/src/desc.rs`（描述符环）、`os/drivers/net/rtl8139/src/txrx.rs`（发送槽与接收绕回）、`os/drivers/net/lance/src/ring.rs`（小环与芯片身份）
> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/22-net-driver-reference.md`（参考实现，十三成员对照基准）、`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/03-netdriver-framework.md`（网络框架）
> **说明**：十二变体是同一中轴的十二种环：初始化收发的中轴不变，环大小、槽数、探测方式各不同。本篇讲三家详例加九家矩阵，不重复讲参考语义。寄存器读写在服务层，本库只定环与身份。

> **本篇不讲什么**：
> - 参考实现语义（见 `22-net-driver-reference.md`，页游标与队列分工已讲透）
> - 协议栈上层（见第十七阶段网络面）
> - 板级寄存器时序（本篇只讲环几何与探测方式，时序在服务层）
>
> 本篇只回答一个问题：**十二家网卡的环各长什么样，靠什么认出自己面对的是哪块卡**。

## 1. 概念：同一考卷的十二种答卷

### 1.0 章节引言

目标读者是读完网卡参考的读者。前置知识只需要一条：驱动表十三成员是满分考卷。本章解释十二变体为什么值得单列一篇：考卷相同，答卷各写各的环。

### 1.1 描述符环是整齐的答题卡

千兆网卡用整齐的答题卡：收发各二百五十六格，每格配二千零四十八 字节草稿纸。用到哪格尾指针就跟到哪格，到顶绕回。空环就是尾追上头：一格没剩。环几何是纯数数，与网速无关。

### 1.2 四槽加环形缓冲是偏科的答卷

百兆网卡偏科：发送只有四格（轮流用，用完一格换下一格），接收却是一整块六万五千五百三十六字节的大草稿纸，读游标在里面绕圈（读多少走多少，到顶绕回）。偏科是硬件定的：发少收多，驱动照单全收。

### 1.3 小环加认卡是最老的答卷

最老的网卡最省：收发各十六格，初始化块写明模式地址与过滤器。认卡靠查户口本（芯片版本表八项，读寄存器版本号对上哪项就是哪块卡）。对不上户口本不开张：陌生卡拒绝服务。

### 1.4 探测是不看身份证只数人头

十二家探测有个共同怪癖：不按厂商标识过滤，按第几块卡跳过（跳过前几块同类设备，用第几块）。标识表只打日志与分支，不拦路。认卡方式有三：读版本号、读芯片版本寄存器、从网卡只读存储器直读地址。

### 1.5 本章小结

十二变体三件事：环几何纯数数，认卡对户口本，探测数人头。下一章进入 C 语言源码验证。

### 2.2 三家回调对照（十三成员满分卷）

| 驱动 | 回调表位置 | 填几项 | 缺哪几项 |
|------|-----------|--------|---------|
| 千兆 | `e1000.c` 第三十八行到第四十九行（`e1000_table`） | 十项 | 设能力、设标志、设介质、其他 |
| 百兆 | `rtl8139.c` 第一百零一行到第一百一十三行（`rl_table`） | 十一项 | 设能力、设标志、设介质 |
| 老卡 | `lance.c` 第一百五十八行到第一百六十七行（`lance_table`） | 八项 | 设能力、设标志、设介质、设硬件地址、取链路、时钟 |

三家都不填设能力设标志设介质：三项是框架预留，当代网卡用不上。老卡另缺硬件地址（地址从只读存储器直读）、链路与时钟。

### 2.3 千兆环几何（`e1000.h` 第二十九行到第三十五 行）

收发描述符各二百五十六（第二十九行与第三十二行），缓冲二千零四十八 字节（第三十五 行）。收描述符含缓冲地址长度校验和状态错位（`e1000_hw.h` 第三十一行），发描述符含缓冲地址长度校验和偏移命令状态（第四十六行）。

### 2.4 百兆四槽大环（`rtl8139.h` 第十九行到第四十八行）

发送槽四格（第十九行），状态寄存器四连号（第二十行到第三十四行，发送时编程对应槽）。接收整块六万五千五百三十六字节（第四百三十五行），两游标（第四十六行到第四十八行），取包绕回在第六百一十九行到第六百八十八行，发送编程对应槽在第七百一十一行。

### 2.5 老卡小环认卡（`lance.c` 第六十三行到第一百七十七行）

收发环各十六格（第九十七行到第一百零六行），初始化块含模式物理地址过滤器与环地址（第一百零九行）。芯片版本表八项（第六十三行到第八十七行），读寄存器版本号掩码对表（第七百零七行到第七百一十四行），地址从只读存储器端口直读（第七百八十二行到第七百八十四行），直接存取内存需低十六兆（第七百五十九行）。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 环做成计数器（依据：第 1.1 节、第 2.3 节）

总数写死（二百五十六），尾指针加一取模，对上头顶即空。替代方案是裸下标散算，不选的理由是：计数器把总数与绕回收敛到一处。

### 3.2 槽做成轮转器（依据：第 1.2 节、第 2.4 节）

四槽轮流，头指针加一取模四。替代方案是位图管槽，不选的理由是：四槽固定且顺序使用，位图多一次查表。

### 3.3 绕回做成纯函数（依据：第 1.2 节、第 2.4 节）

游标加消费量对六万五千五百三十六取模，一测就是全部边界。替代方案是绕回散落在取包里，不选的理由同过滤篇：纯函数边界测得全。

### 3.4 认卡做成查表（依据：第 1.3 节、第 2.5 节）

版本号掩码后查八项表，对上是卡对不上是空。替代方案是 if  else 链，不选的理由是：查表与户口本心智一致，加新型号只加一行。

### 3.5 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 环计数器 | 第 1.1、2.3 节 | 裸下标散算 | 总数绕回两处 |
| 槽轮转器 | 第 1.2、2.4 节 | 位图管槽 | 多一次查表 |
| 绕回纯函数 | 第 1.2、2.4 节 | 绕回散落取包 | 边界测不全 |
| 认卡查表 | 第 1.3、2.5 节 | 条件分支链 | 加型号多处 |

## 4. 错误处理

| 场景 | C 行为 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 尾追上头顶 | 环空 | 为空返回真 | 没格不硬读 |
| 陌生版本号 | 拒绝服务 | 查表返回空 | 对不上不开张 |
| 槽用完 | 轮转复用 | 头指针绕回 | 四槽循环用 |
