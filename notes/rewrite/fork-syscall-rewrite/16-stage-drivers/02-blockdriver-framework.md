## 1. 概念：带仓库分区的厨房

### 1.0 章节引言

目标读者是已经读完上一篇的读者。前置知识只需要上一篇的三条：单线程事件循环、请求编号加标识的路由、重启门。本章假设你已经接受那三条，只解释块框架多出来的东西。

### 1.1 同一间厨房，多了一本仓库账

字符驱动的后厨模型照搬过来就能用：虚拟文件系统服务与文件服务器当前台，块驱动当后厨，一次只做一张小票，做完连编号送回。连重启门都一模一样：宣告上线时清空已打开设备表，陈旧请求静默丢弃。

多出来的第一样东西是分区。一块磁盘在操作系统眼里不是一整块蛋糕，而是切好的若干小块，每块有自己的起始位置与长度。分区表就写在磁盘的固定位置上，驱动第一次打开设备时把它读进来，后面每次读写先查表换算：分区内的偏移加上分区的起始位置，才是磁盘上的真正位置。没有这张表，读写分区三的数据可能落到分区一的地盘上。

多出来的第二样东西是向量读写。普通读写一次搬一段连续内存，向量读写一次搬多段不连续内存（ scatter 收集与 gather 分散）。文件系统写文件时经常遇到这种形状：文件内容在内存里分几处放，但落在磁盘上是连续的。向量读写让这种搬运一次完成，不用来回跑四趟。

多出来的第三样东西是等待队列。多线程的块驱动让多个工作线程同时干活，一张小票进来先按设备排队，哪个线程空了领哪张。单线程驱动不需要这个，但框架把队列做成独立模块，两边共用同一套排队逻辑。

多出来的第四样东西是追踪与热升级钩子。追踪记录每个块操作的开始与结束，调性能时看；热升级钩子让驱动在系统不重启的情况下换新版本，准备与状态切换两个回调管这个。

### 1.2 七种请求：字符七种加向量一对

块请求也是基址加小索引，一共七种：打开、关闭、读、写、收集读、分散写、设备控制。基址是 `0x500`，索引零到六。判定宏同样看除了低七位之外的部分等不等于基址。

和字符请求对比，打开关闭读写控制四种完全对应，多出来的一对是收集与分散（索引四与五）。回复比字符简单：只有一种通用回复（状态码加标识），没有轮询那两种特殊形状，因为块设备不做轮询。

请求材料也和字符对称：打开带次设备号与访问方式，读写带次设备号、字节数、授权、标志、标识、位置，收集分散把字节数换成元素个数，控制带授权与请求码。位置字段是六十四位的，因为磁盘动不动就几百吉字节，三十二位装不下。

### 1.3 十一个回调：字符十个加分区几何

块回调表有十一个成员。字符的十个里面，读与写合并成一个传输回调（用方向参数区分），向量一对也进这个回调（用向量标志区分），于是七个数据回调变成一个，加上打开、关闭、控制、清理、中断、定时、通用，一共十一个，再加分区查询、几何上报、设备号映射三个纯查询回调。

默认行为和字符对称：空的打开关闭视为成功，空的传输视为输入输出错误，空的控制视为不合适操作。分区查询空着表示没有分区信息，几何上报空着表示不报告几何形状。驱动种类字段决定要不要处理分区请求：磁盘类处理，非磁盘类拒绝。

### 1.4 分区解析：第一次打开时读表

分区解析只在第一次打开设备时跑一次。流程是：问驱动要设备范围，分配一块光盘扇区大小的临时缓冲，读分区表，逐项检查每项落在设备范围内，排序主分区（主分区与其他操作系统共享，必须排好序），递归处理扩展分区里的子分区，最后释放临时缓冲。

多线程驱动里多个设备可能同时做分区解析，所以临时缓冲是每次调用单独分配的，不共用。临时缓冲分配失败直接让进程停下：连一张表都读不进来，后面所有读写都没有意义，故障即停。

### 1.5 单线程、队列式、多线程：三套循环，一套策略

C 语言有三套主循环：单线程循环（收一条做一条）、队列式循环（收到的先排队再做）、多线程循环（多个工作线程从每设备队列领活干）。三套循环的准入策略是同一套：重启门、通知旁路、未知类型走通用挂钩。区别只在等待的形状：单线程在接收处等，多线程在队列处等。

Rust 实现只保留单线程事件循环，多线程的线程拓扑不复刻。这是设计期确认的架构演进：多线程解决的是机械硬盘时代的排队问题，现代块层用异步队列而非线程池；保留有界队列的准入策略，丢掉线程管理。这是 `[ARCH A-5]`，文档、设计快照、代码注释三处一致标注。

### 1.6 追踪：给每个块操作记考勤

追踪模块记录每个块请求的开始时间、结束时间与结果，存在环形缓冲里。开关、缓冲大小、目标设备三个控制项走设备控制请求进来。平时关着，调性能时打开，读完再关。追踪本身不改变任何请求的结果，它只是看，这是它和热升级的本质区别。

### 1.7 热升级：换轮胎不停车

热升级让驱动在系统运行中换新版本。准备回调在旧版本退出前跑，把状态倒出来；状态切换回调在新版本启动后跑，把状态接过去。块驱动的热升级与虚拟内存的热升级走同一套失败关闭哲学：准备失败就拒绝升级，老版本继续跑，不带病上岗。

### 1.8 本章小结

块框架等于字符框架加四样东西：分区（仓库账）、向量读写（一次搬多处）、等待队列（多线程排队）、追踪与热升级（观察与换版）。路由、重启门、故障即停三条与字符完全一致。下一章进入 C 语言源码，验证每一样东西的真实形状。

### 2.2 消息布局与请求常量

文件头注释（`driver.c` 第一行到第四十行）画出消息布局：七种请求各占哪些字段，一种通用回复。请求编号是基址 `0x500` 加零到六（`com.h` 第九百七十行到第九百七十六行），判定宏看高位等不等于基址（`com.h` 第九百六十六行）。访问位读与写各一比特（`com.h` 第九百八十二行到第九百八十三行），直写标志一比特（`com.h` 第九百八十七行）。

扇区常量在 `blockdriver.h` 第五十行到第六十行：物理扇区五百一十二字节，除法用移九位，取余用掩码五百一十一，光盘扇区二千零四十八字节，直接内存缓冲是一扇区乘一（配置头里直接内存扇区数默认一）。

### 2.3 宣告与打开集合（`driver.c`）

与字符框架同形：文件内静态运行标志与打开表，二百五十六上限，清空查找登记三个小函数，满了停下。上线宣告发块前缀的驱动上线事件，重启时请内核解除卡住的调用方，然后清空打开表。块宣告多一个参数：驱动种类（磁盘类才走分区路径），字符宣告没有这个参数。

### 2.4 适配器：传输四合一

打开关闭控制三个适配器与字符同形。传输适配器把读、写、收集、分散四种请求 funnel 进一个传输回调：方向参数区分读写，向量标志区分连续与向量，计数参数在连续模式是字节数，在向量模式是元素个数。挂钩空着返回输入输出错误。

分区门：磁盘类驱动在第一次打开时调分区解析，非磁盘类跳过。几何上报走设备控制请求里的专用控制码，驱动种类不是磁盘时拒绝。

### 2.5 三套主循环

单线程循环（`driver.c`）与字符主循环同形：运行标志置真，阻塞接收，中断且已终止就退出，其他接收错误停下，否则路由。队列式循环（`driver_st.c` 第二十五行到第八十九行）多一步：收到的消息先按设备号进队列，处理完再从队列取下一条，对外暴露队列入队函数供特殊驱动自己写循环。多线程循环（`driver_mt.c` 第七十行到第二百行）是每设备一队加工作线程池：入队函数把消息连同传输状态推进设备队，出队函数阻塞等活，传输请求识别函数决定哪些请求走队列（读写收集分散走队列，打开关闭控制直达）。

### 2.6 消息队列模块（`mq.c`）

一百二十八个消息格预先分配，空闲链管分配，每设备一条队。入队在空闲链空时返回假（调用方视为暂时拒绝），出队按先进先出，判空函数供工作线程看活。初始化函数把所有队与空闲链复位。全模块无锁：单线程用时天然安全，多线程用时由调用方的工作线程协议保证一次一队一主。

### 2.7 分区解析（`drvlib.c`）

入口 `partition` 先问驱动要设备范围，拿不到直接返回；分配光盘扇区大小的临时缓冲，拿不到停下；调表解析；释放缓冲。表解析读分区表，检查每项不越界，按风格处理（软盘整盘一段，主分区排序，子分区递归进扩展分区），扩展分区递归有深度上限意识（表项数量封顶，天然终止）。

### 2.8 追踪与热升级（`trace.c`、`liveupdate.c`）

追踪：开关标志、目标设备、环形缓冲、读写指针、起始时间戳五个静态量；控制函数处理开关与改大小；开始函数记请求与时间；结束函数记结果。时间用时间戳计数器转微秒。热升级：准备回调倒状态，状态切换回调接状态，支持声明函数把两个回调注册进系统事件框架。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 请求编号做成枚举（依据：第 1.2 节、第 2.2 节）

与字符篇同理：七个变体，索引零到六，解码失败返回空。向量一对各占一个变体，不合并，因为消息里的计数含义不同（字节数对元素个数），合并会丢掉这个区别。替代方案是整数常量加检查函数，不选的理由同上一篇：漏检查即漏洞。

### 3.2 传输四合一（依据：第 1.3 节、第 2.4 节）

C 语言四个数据请求 funnel 进一个传输回调，Rust 用一个方法加两个标志（读写方向、是否向量）完整保留这个形状。替代方案是拆成四个方法，不选的理由是：拆开后驱动要写四遍同样的位置换算与范围检查，而真正的差异（连续对向量）只在授权组装层，不在驱动逻辑层。Redox 的块层同样是一个读写对加向量变体，形状一致。

### 3.3 分区范围做成值类型（依据：第 1.4 节、第 2.7 节）

起始加长度的结构体，配包含判断（含溢出保护）。C 语言用裸结构体加散落各处的比较，Rust 把比较收进方法，溢出用检查加法处理（起始加长度可能回绕，回绕时直接判越界）。替代方案是裸二元组，不选的理由是：裸元组看不出哪个是起始哪个是长度，传反了编译器不吭声。

### 3.4 等待队列只保留准入策略（依据：第 1.5 节、第 2.6 节）

一百二十八上限、先进先出、满了返回假，三条保留，消息缓冲与线程拓扑不保留。队列里存的是请求标识整数，不是消息本身：消息归服务层，策略归本库。替代方案是完整复刻消息格，不选的理由是：消息类型是传输相关，本库不该碰传输。

### 3.5 驱动行为做成整体行为定义（依据：第 1.3 节、第 2.4 节）

十一个方法，全部默认体，默认体复刻 C 语言空挂钩行为。第二个实现（内存盘模型）证明行为定义可被不同行为实现：静默盘全默认，内存盘重写传输与分区。门禁要求行为定义至少有两个行为不同的实现，本库用这两个满足。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 请求编号用枚举 | 第 1.2、2.2 节 | 整数常量 | 漏检查即漏洞 |
| 传输四合一 | 第 1.3、2.4 节 | 拆四个方法 | 重复的位置换算写四遍 |
| 分区范围值类型 | 第 1.4、2.7 节 | 裸二元组 | 起始长度传反无检查 |
| 队列只留策略 | 第 1.5、2.6 节 | 复刻消息格 | 消息是传输相关 |
| 整体行为定义 | 第 1.3、2.4 节 | 拆小行为定义 | 路由只认编号，拆分掩盖缺实现 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 无传输挂钩 | 输入输出错误 | `NO_TRANSFER_HOOK` | 设备不能搬块 |
| 无控制挂钩 | 不合适操作 | `NO_IOCTL_HOOK` | 同字符框架 |
| 非磁盘的分区请求 | 拒绝 | `NOT_DISK` | 非磁盘类不处理分区 |
| 无可用次设备号 | 无效参数 | `BAD_MINOR` | 取不出设备的消息 |
| 队列满 | 暂时拒绝 | `PendingQueue::push` 返回假 | 调用方稍后重试，不算错误 |
| 未知请求 | 进程停下（回复构造） | `unknown_request_error` 报无效参数 | 不停进程，报错代替 |
