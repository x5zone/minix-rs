# 09-random-driver：随机数驱动

> **分类**：系统服务第 1 篇（熵池加密钥流，单次设备）
> **源码**：`minix3/minix/drivers/system/random/main.c`（二百六十八行，设备挂钩与采集定时）、`minix3/minix/drivers/system/random/random.c`（二百三十七行，熵池与密钥流）、`minix3/minix/drivers/system/random/random.h`（熵源定义）、`minix3/minix/drivers/system/random/aes/`（分组密码实现，见第 2.8 节）、`minix3/minix/include/minix/type.h`（第一百八十二行到第一百九十三行，熵源数量与样本结构）
> **Rust 模块**：`os/drivers/system/random/src/pool.rs`（熵池与重播计划）、`os/drivers/system/random/src/core.rs`（密钥流核心）、`os/drivers/system/random/src/device.rs`（单设备与轮询）
> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/01-chardriver-framework.md`（字符框架）
> **说明**：随机数驱动是全系统唯一的熵源：密钥、会话标识、地址随机化全找它要。本篇讲它的三层结构：熵池层收噪声，密钥流层产字节，设备层定阻塞语义。注意一个事实核查结论：本驱动只有一个次设备（随机设备零号），没有独立的不阻塞设备（调用方要不等就先轮询），计划 stub 里的双设备写法以源码为准纠正。

> **本篇不讲什么**：
> - 内核侧的噪声采集（见 `../01-stage-kernel/` 目录，本篇只消费内核递来的样本）
> - 密码学原语的选型（见第 2.8 节，分组密码与杂凑在服务层装配，本库只定形状）
> - 其他系统服务的用量（本篇只讲产生与分发）
>
> 本篇只回答一个问题：**噪声如何变成用不完的随机字节，没攒够噪声时读操作怎么办**。

## 1. 概念：酒窖

### 1.0 章节引言

目标读者是理解字符框架的读者。前置知识只需要一条：字符读写的七种形状。本章解释随机数驱动的三层：收汁、发酵、取酒。

### 1.1 随机数驱动是一座酒窖

想象一座酒窖。葡萄汁（噪声样本）从十六个果园（内核熵源）加一个自家小院（定时器）源源不断送进来，倒进三十二个大橡木桶（熵池）按轮发酵。攒够第一桶的量就开一次新酒（重播种）：各桶按规矩舀几勺进调配罐（杂凑），调出新的酵母（密钥）。客人要酒时（读），从酵母取一瓢，加计数器搅一搅（分组密码加密计数器），倒出来；倒完换新酵母（密钥更新），保证偷了今天的酵母也算不出昨天的酒（前向保密）。

这个比喻对应全部机制：三十二池（`NR_POOLS`）轮收、十六阶（`N_DERIV`）导数过滤（太平淡的汁不要）、第一池二百五十六样本（`MIN_SAMPLES`）开播、播种计数定参与池、计数器加密产流、产后换新密钥。

### 1.2 三十二池：分级发酵

为什么三十二池而不是一池？因为噪声源有快慢之分：键盘中断一秒几次，定时器一刻不停。全倒一池，快源的汁会淹没慢源的味。轮收规则是：第几个源的第几次汁进第几池（源内轮转），第一池人人有份（每源第一勺都进零池），播种时零池必参与，其余池按播种计数轮流参与（计数二进制里第一个一的位置决定带几池）。慢池难得参与一次，参与时陈酿已久，慢源的味保得住。这是 Fortuna 论文的池思想，名字可以不知道，道理要明白。

### 1.3 导数过滤：太平的汁不要

恒定不变的样本没有熵（永远报同一个数的传感器是坏了，不是稳了）。过滤算法是十六阶差分：新样本与链里十六个旧值逐级做差，十六个差里最小的那个小于二就扔掉。全零链里第一个样本必收（差全是样本本身），链填满后恒定流被拒，抖动流长收。这是熵的看门人：只让带变化的汁进桶。

### 1.4 播种：攒够开罐

零池攒够二百五十六样本就播种：播种计数加一，已播种过则旧密钥先进罐，零池摘要进罐，按计数选的池摘要挨个进罐，罐口封成新密钥（杂凑终结），样本计数清零，播种标记立起。调用方写的字节是信任汁：直接进零池，一字节算八样本（信任所以给满分），写完也试播种。

### 1.5 密钥流：计数器加密

产流是计数器加密：计数器（六十四位，高低各三十二）排进块头，其余补零，分组密码加密，出一块。计数器每次加一（低字回绕进高字）。读请求分一千零二十四字节大块产，尾巴不够一块单独加一块再截。产完换密钥：连产两块，前块当新密钥前半，后块当后半。从此旧密钥作废，偷密钥的人只能算未来算不出过去。

### 1.6 设备语义：没酒就请回

全驱动只有一个次设备（零号）。读的规矩三条：号错报输入输出错误，没播种过答再试（不等不等自己选，驱动不替你等），播种过当场给足。写的规矩两条：号错拒，余下全收（写即播种）。打开只认零号。轮询永远全就绪（读不阻塞：没酒答再试也是立即答；写永远收）。采集定时没播种一拍一次，播种后五百拍一次（开源节流：够喝了少折腾内核）。

没有独立的不阻塞设备是本篇的事实核查结论：源码里 `NR_DEVS` 为一，只有零号。需要不阻塞语义的调用方先轮询（永远就绪）再决定读不读，读到再试就是没酒。这与计划 stub 的双设备写法不同，以源码为准。

### 1.7 与其他系统的对照

Linux 的随机池是一大池加紧急池，播种按时间与估计熵触发；Minix3 是三十二池加计数轮转，播种按样本数触发。Linux 的估计器曾因估计不准引发阻塞争议，Minix3 不估计（信任汁给满分，内核汁全收），用池轮转代替估计：简单，不吵架，够用。

Redox 的随机方案是直接读内核随机源，没有用户态熵池层。Minix3 把池放在用户态驱动里，原因是噪声源在内核（中断时序），池策略在用户态好改：换过滤算法不用动内核。这是微内核的常规分工：机制在内核，策略在服务。

### 1.8 本章小结

随机数驱动是酒窖：三十二池轮收，十六阶导数看门，二百五十六样本开播，计数器加密产流，产后换密钥，没酒答再试，单设备，轮询永真。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单

| 文件 | 行数 | 内容 |
|------|------|------|
| `minix3/minix/drivers/system/random/main.c` | 二百六十八行 | 设备挂钩、采集定时、样本分箱、轮询 |
| `minix3/minix/drivers/system/random/random.c` | 二百三十七行 | 熵池、密钥流、播种 |
| `minix3/minix/drivers/system/random/random.h` | 十六行 | 熵源定义与公开接口 |
| `minix3/minix/drivers/system/random/aes/` | 分组密码实现 | 计数器加密的原语（本库不管实现） |
| `minix3/minix/include/minix/type.h`（第一百八十二行到第一百九十三行） | 约十二行 | 熵源十六、每源六十四样本、样本分箱结构 |

### 2.2 熵源与样本分箱（`type.h` 第一百八十二行到第一百九十三行，`main.c` 第一百八十七行到第二百二十六行）

熵源十六（`RANDOM_SOURCES`），每源六十四样本（`RANDOM_ELEMENTS`），分箱结构含下一起始、有效长度、六十四样本槽。驱动内部源一定时源零号。分箱读取处理环绕：读写指针加长度不出界一次取，跨界拆两段（前段到尾，后段从头）。断言守着指针合法性（越界直接停下：内核递来的分箱若非法，说明内核侧坏了，停下比瞎吃强）。

### 2.3 采集定时（`main.c` 第二百三十一行到第二百五十四行）

每次闹钟到：轮换取一源的分箱（源号加一对十六取模），取到了喂池；再取自家定时器值喂零号源；按播种状态定下次闹钟（一拍 `KRANDOM_PERIOD` 对五百拍）。初始化调一次（顺手布定时器），再取整批初始样本（十六源全喂），参数核对发现源数对不上直接退出（驱动拒绝在参数错配的内核上跑）。

### 2.4 熵池（`random.c` 第十八行到第一百七十九行）

池数三十二（`NR_POOLS`），导数深十六（`N_DERIV`），阈值二百五十六（`MIN_SAMPLES`），样本计数与播种标记。初始化清导数链与游标、初始化三十二池上下文、计数清零。样本入口验源号（非法停下），逐样本过导数链，接受的进轮转池（零池加样本计数，游标加一到顶回零）。信任汁入口：字节进零池，一字节八样本，试播种。播种守卫：样本不够直接回。

### 2.5 播种（`random.c` 第二百零六行到第二百三十六行）

计数加一，已播种旧密钥先进罐，零池终结摘要进罐，零池上下文重置，按计数选池（第一个一比特定带几池）逐个终结进罐重置，终总结成新密钥（密钥长等于摘要长，断言锁死），样本清零，播种标记立起。选池循环的位运算见第 1.2 节，代码与模型逐位一致。

### 2.6 密钥流（`random.c` 第八十一行到第二百零四行）

取流：块密钥表一次，分整块直产、尾块侧产截取，产完连取两块换密钥。数据块：计数器排块头（低字在前），加密，低字加一（回绕进高字）。密钥表断言与加密长度断言锁死（失败停下：密码学原语失败没有带病跑的选项）。

### 2.7 设备挂钩（`main.c` 第一百二十行到第一百八十五行，第二百五十九行到第二百六十八行）

读：号错输入输出错误，没播种再试，分一千零二十四字节（`RANDOM_BUF_SIZE`）大块产，复制失败返回复制错（打印日志），返回全长。写：号错拒，分块收，喂信任池，返回全长。打开：零号外没有此设备。轮询：号错输入输出错误，余下读写位全置（错位忽略）。回调表五挂钩（打开、读、写、选择、闹钟），注意没有关闭与取消：随机设备无状态可关，无挂起可取消。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 池拓扑做成纯类型（依据：第 1.2 节到第 1.4 节、第 2.4 节、第 2.5 节）

导数链、轮转游标、样本计数、选池位运算全是纯函数与值类型，杂凑在行为定义后面。播种的混合顺序（旧密钥、零池、选中池）收成一个方法，摘要数组进、密钥出。替代方案是池与杂凑写死在一起，不选的理由是：写死了播种顺序测不了，只能等攒够二百五十六样本测。

### 3.2 密码原语做成行为定义（依据：第 2.6 节、第 2.8 节）

杂凑两方法（吸入、快照重置），分组密码一方法（块加密）。折叠实现与空实现（杂凑）行为不同，折叠密码与常量密码（分组）行为不同，门禁满足。生产装配平台原语，这是架构演进（密码学在服务层选型，计划边界本来就不覆盖选型）。替代方案是自带实现，不选的理由是：密码学实现进驱动库等于背审计责任，库只定形状。

### 3.3 密钥流做成计数器状态机（依据：第 1.5 节、第 2.6 节）

计数器六十四位分高低字，回绕进位，块头排布小端在前（与 C 的内存拷贝顺序一致）。产流分块、尾块侧产、产后换密钥三步一字不差。替代方案是调外部流密码，不选的理由是：计数器加密就是流密码的构造，另调一种等于把已验证的构造换成没验证的。

### 3.4 设备语义做成纯检查（依据：第 1.6 节、第 2.7 节）

读三条、写两条、打开一条、轮询全置，收成常量函数。分块计划收成纯函数（一千零二十四分块）。采集周期收成纯函数（一拍对五百拍）。替代方案是检查里直接调复制，不选的理由同框架篇：复制在服务层。

### 3.5 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 池拓扑纯类型 | 第 1.2-1.4、2.4、2.5 节 | 池杂凑写死 | 播种顺序测不了 |
| 原语行为定义 | 第 2.6、2.8 节 | 自带实现 | 背审计责任 |
| 计数器状态机 | 第 1.5、2.6 节 | 外调流密码 | 换掉已验证构造 |
| 设备纯检查 | 第 1.6、2.7 节 | 检查调复制 | 复制在服务层 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 非法熵源号 | 进程停下 | `feed` 返回假 | 库不停进程，服务层转错 |
| 未播种读 | 再试 | `check_read` 返回该码 | 没酒请回 |
| 错号读写 | 输入输出错误 | `check` 系列返回该码 | 号段内唯一设备 |
| 错号打开 | 没有此设备 | `check_open` 返回该码 | 打开路径写法 |
| 错号轮询 | 输入输出错误 | 服务层按该码 | 轮询路径写法，原样保留 |
| 复制失败 | 复制错 | 服务层返回复制错 | 复制在服务层 |
| 映射失败（密钥表） | 停下 | 服务层装配保证 | 原语失败无带病跑选项 |

## 6. 过渡：从熵到时间

随机数驱动解决不可预测，下一篇时钟驱动解决可读时间：两篇都是单设备小驱动，都是用户态字符面之外走专有协议（随机走字符框架，时钟走自己的实时钟协议）。读时钟之前，建议重温本篇的播种守卫：时钟驱动的权限门（读放行、写验超级用户、断电验电源管理）是同一类思想（先验资格再干活）。
