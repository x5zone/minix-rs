## 1. 概念：小区的黑板报

### 1.0 章节引言

目标读者是已经读完终端与伪终端的读者。前置知识只需要一条：挂起读（没货就等，有货就答）。本章解释日志驱动为什么是第三只环，以及它与前两只环的不同。

### 1.1 日志驱动是小区的黑板报

想象小区门口的黑板报：物业有事就写上去，居民路过就看。黑板只有那么大，写满了就擦掉最早的接着写。居民来晚了，早的字没了，但总有最新的字可看。没人规定居民什么时候来看，报也不等人。

Minix3 的日志驱动就是这块黑板。内核与服务是物业（只写不看），管理员与日志命令是居民（只看，有时等）。环是五万字节，写满盖旧货，读走不留档。来晚了旧消息没了，这是设计不是缺陷：诊断总线的职责是让最新状态可查，不是当档案馆。

### 1.2 写盖旧货：黑板写满擦前面

写操作永远成功（除非法号）：环里有空位往空位写，没空位把读指针往前推，腾出地方写新的。一次写超长（超过整环）只留最后五万字节，前面的来不及进环就扔了。写完两件事：环里有货了，挂起的读者该醒了，选择了读的人该通知了。

先唤醒挂起读再通知选择者，顺序不能反：挂起读把货读走一部分，选择者看到的才是读剩下的。如果先通知选择者，它来读时货可能已经被挂起读拿走，白跑一趟。顺序是语义的一部分，不是性能细节。

### 1.3 读挂起：居民等新字

读操作分三种情形。环里有货，直接答（能给多少给多少，不凑整）。环里没货且调用方说不等（`CDEV_NONBLOCK` 非阻塞标志，见字符框架篇），答再试。环里没货且调用方愿意等，挂起（记下调用方、标识、要多少）。挂起只许一路：已经有人等着，新来的读直接答零（不是错误，是请回：一次只伺候一位，排队在驱动门外）。

一路挂起是全驱动最有争议的设计：为什么不排队？因为日志读者的典型用法是一个守护进程独占读，多路挂起只会出现在程序写错的时候。答零让写错的程序立刻发现（读到零知道没轮到自己），排队反而让它傻等。把错误暴露给调用方，不替它排队，这是驱动 retained 的一贯态度。

### 1.4 取消配对：等累了先走

等着的读者可以取消：调用方加标识对上，撤挂起，原读答中断；对不上，取消本身不回复（陈旧取消静默吞）。非法号的取消答无效参数（号都不对，谈不上配对）。取消命中后事件灯意义上的唤醒在服务层做，本库只负责配对与清挂起。

### 1.5 选择三位：读要货写永真

轮询三位 `CDEV_OP_RD`、`CDEV_OP_WR`、`CDEV_OP_ERR` 加迟通知位 `CDEV_NOTIFY`（`com.h` 第九百四十九行到第九百五十二行）：读就绪要求环里有货，写永远就绪（写从不阻塞，盖旧货保证），错位永远不就绪（本驱动无错条件，位留着但永不置）。剩余操作在要求迟通知时登记，登记记下调用方。迟通知在下次写后发出（写指针动了就可能有新货），发出后清相应位。

### 1.6 内核消息增量：只抄新增的

内核的环形消息缓冲与日志环是两只不同的环：内核环是写源，日志环是读者之一。信号只报信（写指针动了），不带货。驱动用新旧指针的差对长度取模算出新增字节数，拷走，记下新指针。取模保证环绕正确：新指针绕回零时差依然是对的。新增零字节说明缓冲被并发清空了：指针照样推进（C 语言无条件存），拷零字节（白跑一趟，但正确）。

终端驱动是同一块内核缓冲的另一个读者，各记各的指针，互不干扰。两个读者都用同一套增量算法，本库的增量游标是纯函数，两边各实例化一个，宽度按各自缓冲来。

### 1.7 热升级三钩子：准备、验态、倒态

日志的热升级注册三个钩子：准备（倒状态前）、验态（新状态合法性）、倒态（状态导出）。与块驱动的热升级同哲学：准备失败拒绝升级，老版本继续跑。日志的状态就是环加挂起加登记，倒出去接回来，读者不断线。

### 1.8 本章小结

日志驱动是黑板报：五万字节环，写盖旧货，读一路挂起，取消精确配对，选择读要货写永真，内核增量取模算，热升级三钩子。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单

| 文件 | 行数 | 内容 |
|------|------|------|

| `minix3/minix/drivers/system/log/log.h` | 约三十行 | 环定义、五万容量、函数声明 |
| `minix3/minix/drivers/system/log/diag.c` | 五十四行 | 内核消息增量捕获 |

| `minix3/minix/include/minix/com.h`（第九百四十九行到第九百五十二行） | 四行 | 选择位与迟通知位 |

### 2.2 环定义与容量（`log.h` 全文）

环 `LOG_SIZE` 五万字节（一行宏），设备结构 `logdevice` 含缓冲、货数、读写指针、挂起四件套（调用方、标识、要多少、授权）、选择登记（位加调用方）。函数声明：内核消息处理 `do_new_kmess`、追记入口 `log_append`。容量五万是经验值：够存一次启动风暴的诊断，又不至于太占内存。

初始化函数 `sef_cb_init_fresh`（`log.c` 第八十七行到第一百零七行）把环的货数读写指针全清零、挂起调用方清零、登记诊断通知、宣告上线。信号回调 `sef_cb_signal_handler` 只认内核消息信号（到货走增量捕获），其他信号忽略。

### 2.3 写循环 `subwrite` 与追记 `log_append`（`log.c` 第一百二十三行到第二百零八行）

逐段写：每段按写指针到环尾截断，本地缓冲直接拷，授权走安全复制（失败按已搬数算部分成功），推进写指针累货数（环指针推进宏 `LOGINC` 即取模加），超容盖旧货（货数减溢出，读指针前推）。写完唤醒挂起读（有货：读出货数，迟答复，清挂起）再通知选择者（有货且登记了读：发迟通知，清读位）。追记入口是写的本地版（内核消息直接进环）：超长跳过前部，只留末窗，调写循环。

### 2.4 读循环 `subread` 与读挂钩 `log_read`（`log.c` 第二百一十三行到第二百七十三行）

读循环 `subread` 逐段搬：按剩余货数与环尾截断，安全复制出，推进读指针减货数，返回搬数。读挂钩 `log_read`：非法号报输入输出错误（注意不是没有此设备：号段内唯一设备 `MINOR_KLOG` 零号，`NR_DEVS` 为一，错号是参数错）；有人挂着直接答零；有货当场答；空环非阻塞答再试；空环阻塞挂起（记四件套，答不回复）。

非法号用输入输出错误而不用没有此设备，是全驱动唯一与直觉不符的地方：打开用没有此设备，读写用输入输出错误。历史原因（读写路径的号检查写在数据面），Rust 实现原样保留并注释，不擅自统一。

### 2.5 取消 `log_cancel` 与选择 `log_select`（`log.c` 第三百零六行到第三百六十行）

取消 `log_cancel`：非法号无效参数；调用方标识双对上才撤（撤后原读答中断）；对不上不回复。选择 `log_select`：非法号没有此设备（选择路径用没有此设备，与读写不同，原样保留）；读位看货数，写位恒置；剩余在要求迟通知时登记。写恒就绪是环语义的直接推论：写从不阻塞，所以永远可写。写挂钩 `log_write` 是写循环的薄包装（调 `subwrite` 传空本地缓冲），打开挂钩 `log_open` 只认零号。

### 2.6 诊断捕获 `do_new_kmess`（`diag.c` 全文五十四行）

静态读指针记上次位置。取内核信息块的消息缓冲，新旧指针差取模算新增，逐字节拷到本地行缓冲（行缓冲防并发改：指针只取一次，取模防环绕，拷完推进）。新增零直接推进指针（缓冲被清空，白跑）。追记进环。信号处理只认内核消息信号，其他信号忽略；终止信号在终端驱动停控制台，日志驱动无此分支。

### 2.7 热升级钩子（`liveupdate.c` 九十九行）

准备 `sef_cb_lu_prepare`、验态 `sef_cb_lu_state_isvalid`、倒态 `sef_cb_lu_state_dump` 三回调注册进系统事件框架。状态是环加挂起加登记。准备失败拒绝升级。与虚拟内存热升级同失败关闭哲学。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 环做成计数器（依据：第 1.2 节、第 2.3 节）

读写指针加货数三数走天下，字节数组不在库里。盖旧货是三数运算：写指针推、货数加、超容读指针推。超长写先跳前部（只留末窗），与追记入口同规则。替代方案是五万字节数组进库，不选的理由是：字节的进出全经授权复制，数组进库了复制还是要在服务层做，数组只是占地方。

### 3.2 挂起做成单槽（依据：第 1.3 节、第 2.4 节）

二路挂起直接答零，不排队。单槽是类型：有就是有，没有就是没有，不存在第二个。替代方案是挂起队列，不选的理由见第 1.3 节：排队替写错的程序兜底，不如答零让它立刻发现。

### 3.3 取消做成精确配对（依据：第 1.4 节、第 2.5 节）

调用方加标识双对上才撤，撤后原读答中断。非法号先拦（无效参数），对不上静默吞。替代方案是只对调用方不对标识，不选的理由是：同一调用方可能先后挂起两次（读完又读），只对调用方会撤错路。

### 3.4 选择做成三位常量（依据：第 1.5 节、第 2.5 节）

读写错三位加迟通知一位，掩码常量。写恒就绪是环语义的推论，错位恒不就绪是驱动语义（无错条件）。替代方案是布尔三元组，不选的理由是：位运算与 C 语言逐位对得上，且迟通知的登记清除就是位操作。

### 3.5 增量做成泛型游标（依据：第 1.6 节、第 2.6 节）

宽度泛型（内核环与日志环宽度未必同），新旧指针差取模，零新增照样推进。终端驱动的黑板报读者与本篇共用这个游标：各实例化一个，各记各的指针。替代方案是两处手写取模，不选的理由是：取模公式错一位就丢消息，一处实现两处用，公式只错得了一次。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 环计数器 | 第 1.2、2.3 节 | 字节数组进库 | 复制还在服务层，数组占地方 |
| 挂起单槽 | 第 1.3、2.4 节 | 挂起队列 | 替错程序兜底不如报错 |
| 取消精确配对 | 第 1.4、2.5 节 | 只对调用方 | 先后两挂起撤错路 |
| 选择三位常量 | 第 1.5、2.5 节 | 布尔三元组 | 位运算与 C 对得上 |
| 增量泛型游标 | 第 1.6、2.6 节 | 两处手写 | 公式错一位丢消息 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 非法打开号 | 没有此设备 | `open` 返回该码 | 唯一设备零号 |
| 非法读写号 | 输入输出错误 | `read` 返回该码 | 历史写法，原样保留 |
| 非法选择号 | 没有此设备 | `select` 返回该码 | 选择路径写法，原样保留 |
| 空环阻塞读 | 挂起 | `ReadVerdict::Park` | 居民等新字 |
| 空环非阻塞读 | 再试 | 返回该码 | 调用方说不等 |
| 二路挂起读 | 答零 | `Answer(0)` | 请回，不排队 |
| 取消 miss | 不回复 | `cancel` 返回空 | 陈旧取消静默吞 |
| 取消命中 | 原读答中断 | `Cancelled::Read` | 等累了先走 |
| 非法取消号 | 无效参数 | 返回该码 | 号不对谈不上配对 |

| 选择读要货写永真 | 空环只写、有货读写、非法号错 | 选择挂钩 |
| 登记剩余 | 迟通知登记位与人、清除归零 | 选择登记分支 |
