# 20-fb-driver：帧缓冲驱动

> **分类**：显示第 1 篇（字符设备看显存，开机关logo，显示器信息另读）
> **源码**：`minix3/minix/drivers/video/fb/fb.c`（四百零四行的通用层）、`minix3/minix/drivers/video/fb/fb_edid.c`（一百八十七行的显示器信息读取）与 `fb_edid.h`（十二行的两个函数声明）、`minix3/minix/drivers/video/fb/arch/earm/fb_arch.c`（四百零八行的硬件层，唯一的后端）、`minix3/minix/drivers/video/fb/logos.h`（三千零五十四行的开机标识位图）、`minix3/minix/include/sys/ioc_fb.h`（第十一行到第十四行的四个输入输出控制请求）
> **Rust 模块**：`os/drivers/video/fb/src/mode.rs`（模式选择）、`os/drivers/video/fb/src/display.rs`（打开计数与截断）
> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/01-chardriver-framework.md`（字符框架，本驱动挂靠的框架）、虚拟内存阶段的映射机制（物理映射接口的语义来源）
> **说明**：帧缓冲是字符设备，不是内存映射设备：用户进程靠读写与四个输入输出控制请求看显存，没有映射回调。本篇讲五个回调怎么做、显示器信息怎么读、模式怎么选。寄存器写入与拷贝流量在服务层，本库只定选择与计数。

> **本篇不讲什么**：
> - 控制台渲染（见 `06-tty-driver.md`，终端行规则另讲）
> - 虚拟内存映射机制本身（映射接口只消费，机制见虚拟内存阶段）
> - 高清桥芯片（见 `24-misc-drivers.md`，桥差异另讲）
>
> 本篇只回答一个问题：**屏幕这块内存怎么打开、怎么读写、模式谁说了算**。

> **计划勘误**：`plan.md` 第 2 章把帧缓冲记成映射到用户，这是写错了。实证是：字符驱动回调表没有映射成员（`chardriver.h` 第九行到第二十三行十个成员无映射），帧缓冲只实现其中五个（`fb.c` 第四十四行到第五十一行）。用户侧靠读写直达显存（第一百一十五 行与第二百三十行的安全拷贝），不是靠映射。本篇按源码实证写作。

## 1. 概念：显存是挂在墙上的黑板

### 1.0 章节引言

目标读者是读完通用串行总线批的读者。前置知识只需要一条：字符驱动靠打开关闭读写与输入输出控制服务。本章解释帧缓冲为什么特殊：它的读写不经过磁盘，直达屏幕这块内存。

### 1.1 黑板读写是直达显存

想象教室墙上的黑板：老师写字（写请求）直接落在黑板上，同学抄（读请求）直接从黑板上抄，没有中间商。帧缓冲驱动就是黑板管理员：打开设备数人数（打开计数加一），第一次有人来先通电摆黑板（硬件初始化），没人了关灯（计数归零），读写按黑板大小截断（超出的不读不写）。

### 1.2 四个输入输出控制请求是黑板的遥控器

黑板有四个遥控按钮：查当前显示参数、改当前显示参数、查固定显示参数、平移显示。改参数只许改垂直偏移（别的不许动，越界拒绝），陌生按钮一律回答不支持。遥控器只调姿势，不搬黑板：搬黑板（寄存器写入）在服务层。

### 1.3 显示器信息是学生的体检表

显示器自带体检表（扩展显示标识数据，一百二十八字节）：写着它会哪些分辨率。驱动开机先找体检表（经块设备协议向提供者读，第一百二十八 字节，读完校验解析），有体检表按体检表选模式（取交集最高分辨率），没体检表用默认（一千零二十四乘六百，三十二位色，双缓冲）。体检表缺省合法：没有也不报错，直接默认。

### 1.4 模式选择是体检表与支持表的相亲

硬件只会四种分辨率（一千零二十四乘七百六十八、一千二百八十乘八百、一千四百乘一千零五十、一千二百八十乘七百二十）。相亲规则：体检表上的模式与支持表求交集，取像素最多的那个。交集为空回默认，不空谈恋爱。帧缓冲大小纯算术（宽乘高乘色深除八），连续物理内存不够就启动失败。

### 1.5 重启窗口是黑板的保护期

机器刚重启一秒内，黑板上还画着重启标识，不许擦（写、改参数、平移一律回答稍后重试）。保护期是给人看标识的，不是给程序用的：一秒过后照常服务。打开计数与保护期是配对思想（见第十九篇标签配对）：开加一，关减一，计数归零才算无人用。

### 1.6 本章小结

帧缓冲五件事：开数人，读写截断，四个遥控按钮，体检表相亲选模式，重启一秒保护期。下一章进入 C 语言源码验证。

### 2.2 主循环与五个回调（`fb.c` 第四十四行到第五十一行，第三百零七行到第三百一十六行）

回调表 `fb_tab` 十个成员只实现五个（第四十四行到第五十一行）：`fb_open` 打开、`fb_close` 关闭、`fb_read` 读、`fb_write` 写、`fb_ioctl` 输入输出控制，取消、选择、中断、闹钟、其他留空。主函数按序做四件事：取启动参数、`fb_edid_args_parse` 解析显示器信息参数、本地启动、进字符驱动主循环 `chardriver_task`（第三百零七行到第三百一十六行）。初始化回调 `sef_cb_init` 区分三种启动（第二百五十七行到第二百九十行）：新生打印进程号，热升级恢复状态不宣布，重启置标记后 `chardriver_announce` 宣布。

### 2.3 打开关闭读写（`fb.c` 第五十九行到第九十七行，第九十九行到第二百三十四行）

`fb_open` 打开先查设备号越界（超界回答无设备），首次打开 `fb_edid_read` 读显示器信息（第七十行，失败则空信息）、`arch_fb_init` 初始化硬件（第七十四行），成功 `open_counter` 计数加一并画开机或重启标识。`fb_close` 关闭断言计数为正后递减（第九十行到第九十七行）。`fb_read` 读与 `fb_write` 写先 `arch_get_device` 取设备（第九十九行到第二百三十四行），按设备大小截断位置与长度，分别经 `sys_safecopyto` 安全拷贝到用户（第一百一十五 行）与 `sys_safecopyfrom` 安全拷贝自用户（第二百三十行）直写物理映射虚地址。写另受重启窗口 `keep_displaying_restarted` 门控（第二百二十一行返回稍后重试）。

### 2.4 四个输入输出控制请求（`ioc_fb.h` 第十一行到第十四行，`fb.c` 第一百二十一行到第一百九十八行）

`FBIOGET_VSCREENINFO` 查可变参数、`FBIOPUT_VSCREENINFO` 改可变参数、`FBIOGET_FSCREENINFO` 查固定参数、`FBIOPAN_DISPLAY` 平移显示各一请求（第十行到第十三行，头文件第九行是注释）。分发在第一百二十一行到第一百四十七行，陌生请求回答 `ENOTTY` 不支持（第一百四十六行）。改可变参数 `arch_put_varscreeninfo` 只许改垂直偏移（`fb_arch.c` 第二百七十四行到第二百九十六行，越界回答非法参数），平移显示 `arch_pan_display` 直接转调改参数（第三百零八行到第三百一十二行），读类请求是结构体拷贝。

### 2.5 显示器信息读取（`fb_edid.c` 第五十四行到第一百八十六行）

参数解析 `fb_edid_args_parse` 在第五十四行到第八十行（按显示器信息加编号经环境取参数填提供者数组，缺省合法）。单次读取 `do_read` 在第八十五 行到第一百四十三行：经块设备协议发 `BDEV_OPEN` 打开（第九十四行）、授权（第一百零五行）、`BDEV_READ` 读一百二十八字节（第一百一十行）、收权（第一百一十九行）、`BDEV_CLOSE` 关闭（第一百三十三行），全经进程间发送接收。对外读取 `fb_edid_read` 在第一百四十五 行到第一百八十六行：空提供者或非法设备号回答非法参数（第一百五十三行到第一百五十五 行），`ds_retrieve_label_endpt` 经设备目录服务查端点（第一百六十二行），读后 `edid_parse` 校验解析（第一百七十七行）。

### 2.6 硬件层（`fb_arch.c`，唯一的后端）

全局状态含寄存器基址、帧缓冲虚实地址、大小、初始化标记与三套配置（第四十八行到第一百二十三行）。模式选择 `choose_mode` 取体检表与支持表 `omap_supported_modes` 交集最高分辨率（第一百四十四行到第一百六十四行），`configure_with_edid` 先套默认再覆写（第一百六十六行到第二百一十九行），无体检表 `configure_with_defaults` 直接默认（第二百二十一行到第二百三十三行）。初始化 `arch_fb_init` 在第三百一十四行到第四百零七行（单设备号、已初始化直接成功、无体检表回退默认、`vm_map_phys` 映射寄存器、`alloc_contig` 分配连续内存、按面板配置写时序寄存器、配置显示）。运行时显示 `arch_configure_display` 按垂直偏移写基址寄存器并置使能位（第二百三十五行到第二百五十二行）。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 模式做成交集选择（依据：第 1.4 节、第 2.6 节）

支持表四模式写死，体检表模式数组进交集最高出，无交集返回空（调用方回默认）。替代方案是选择里直接读体检表，不选的理由是：读体检表要块协议，块协议在服务层，选择只认数组。

### 3.2 大小做成纯算术（依据：第 1.4 节、第 2.6 节）

宽乘高乘色深除八，六十四位防溢出，测试一算就是全部。替代方案是大小散落在初始化里，不选的理由是：纯算术让分配前的 dry-run 可能（不够就早报）。

### 3.3 计数做成加减器（依据：第 1.1 节、第 2.3 节）

开加一关减一，零下关拒绝（对应 C 的断言），首次开标记需初始化。替代方案是布尔是否有人用，不选的理由是：布尔数不清两个人同时用，关早了黑板灭了。

### 3.4 截断做成纯函数（依据：第 1.1 节、第 2.3 节）

位置超设备零回报，长度按剩余取小，测试不用起拷贝。替代方案是截断散落在读写入口，不选的理由同过滤篇：纯函数一测就是全部边界。

### 3.5 输入输出控制做成枚举（依据：第 1.2 节、第 2.4 节）

四请求各一值，陌生号返回空（调用方回答不支持）。替代方案是裸数字比对，不选的理由同通用串行总线篇：枚举让漏分支编译不过。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 模式交集选择 | 第 1.4、2.6 节 | 选择读体检表 | 块协议在服务层 |
| 大小纯算术 | 第 1.4、2.6 节 | 大小散落初始化 | 早报不可能 |
| 计数加减器 | 第 1.1、2.3 节 | 布尔有人用 | 数不清两人 |
| 截断纯函数 | 第 1.1、2.3 节 | 截断散落入口 | 边界测不全 |
| 请求枚举 | 第 1.2、2.4 节 | 裸数字比对 | 漏分支不响 |

## 4. 错误处理

| 场景 | C 行为 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 设备号越界 | 回答无设备 | 调用方拒绝 | 单设备是顶 |
| 陌生请求号 | 回答不支持 | 解码返回空 | 按钮只有四个 |
| 零下关闭 | 断言失败 | 关闭返回假 | 没人不能关 |
| 位置超设备 | 零字节 | 截断返回零 | 黑板外不读 |
| 长度超剩余 | 截断 | 取小 | 黑板边截断 |
| 偏移越界 | 回答非法参数 | 更新返回假 | 姿势不出界 |
| 无交集模式 | 回默认 | 选择返回空 | 相亲不成默认 |
| 重启一秒内写 | 回答稍后重试 | 调用方门控 | 保护期不擦 |
