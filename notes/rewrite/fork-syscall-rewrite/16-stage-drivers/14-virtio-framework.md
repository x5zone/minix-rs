# 14-virtio-framework：虚拟队列框架

> **分类**：存储第 1 篇（虚拟机与宿主机的环形契约）
> **源码**：`minix3/minix/lib/libvirtio/virtio.c`（九百一十三行，建设备、协商、队列、踢与中断）、`minix3/minix/lib/libvirtio/virtio_ring.h`（环布局，源自 Linux 头）、`minix3/minix/include/minix/virtio.h`（约一百二十行，操作表与状态字节）
> **Rust 模块**：`os/libs/minix-virtio/src/ring.rs`（环索引算法）、`os/libs/minix-virtio/src/features.rs`（特性协商）、`os/libs/minix-virtio/src/device.rs`（生命周期与踢策略）
> **前置**：`notes/rewrite/fork-syscall-rewrite/16-stage-drivers/02-blockdriver-framework.md`（块框架，虚拟块是其消费者之一）
> **说明**：虚拟队列是虚拟机与宿主机之间的传菜口：客户机把请求链进环，踢一脚门铃，宿主机做完把完成链进另一环，中断通知客户机。本篇讲这套契约的三件套：环布局、特性协商、设备生命周期。端口读写、内存映射、中断注册全在服务层，本库只定顺序与算法。

> **本篇不讲什么**：
> - 虚拟块设备的请求语义（见 `15-virtio-blk-driver.md`，本篇只讲环）
> - 虚拟网卡的请求语义（见 `22-net-driver-reference.md`）
> - 间接描述符的线程池优化（见第 2.8 节，本库只走直接描述符路）
>
> 本篇只回答一个问题：**客户机与宿主机不共享内存管理权时，如何交接一块块的输入输出**。

## 1. 概念：旋转寿司

### 1.0 章节引言

目标读者是理解环形队列的读者。前置知识只需要一条：生产者消费者模型。本章解释虚拟队列为什么是三环而不是一环，以及特性协商为什么是取交集。

### 1.1 虚拟队列是旋转寿司

想象旋转寿司店：厨师（客户机）把菜放上传送带（可用环），按铃（踢门铃），客人（宿主机）取走吃掉，把空碟放回回收带（已用环），厨师看回收带知道哪碟吃完了。三条带各司其职：菜单（描述符表）写菜名，传送带写单号，回收带写空碟号。

Minix3 的虚拟队列就是这家店。描述符表是菜单（地址、长度、标志、下一道），可用环是传送带（标志、序号、单号数组），已用环是回收带（标志、序号、完成数组）。客户机只写传送带，宿主机只写回收带，菜单两边只读：写权限分离，并发不用锁（各写各的，读对方的）。

### 1.2 描述符链：拼单

一个请求经常要多块缓冲（读请求：头一块、数据 N 块、状态一块）。描述符的下一标志把多块串成链：头块指第二块，第二块指第三块，末块不置下一位。写标志管方向：宿主机写客户机读的块置写位（状态块永远置写位），反之清零。间接标志是整单外包：描述符指向的不是数据，而是一整张小菜单（间接表），宿主机按小菜单取。间接表预先分配（分配要进内核，慢，启动时一次备好）。

空闲链是菜单背面的草稿纸：空描述符用下一字段串起来，取链从头取，用完从头还。取空与还空是队列最热的路径，必须常数时间：头指针加减，计数加减，无搜索。

### 1.3 可用与已用：两本账

可用序号是客户机发的单号：每上一道菜加一（回绕是自然的，十六位）。已用序号是宿主机吃的进度：吃完一批写当前值。未吃数等于可用减已用（回绕减法，结果恒对）。客户机收菜看已用：已用追上可用说明全吃完，已用落后说明有新空碟。

中断抑制是省铃钱：宿主机说别响（已用标志置不通知），客户机照吃不误，只是多看两眼；客户机说别吵（可用标志置不中断），宿主机照做，只是多踢两脚。抑制全是优化建议，不是正确性依赖：铃响不响，菜照吃，这是契约里最实在的一条（不可靠，所以只是优化）。

### 1.4 特性协商：点菜只点有的

宿主机报菜单（特性位），客户机勾自己要的，回写交集。宿主机多出的位直接忽略（老客户机跑在新宿主机上，新菜看不见，就当没有）。协商失败（要的宿主机没有）不拦路：对应功能不用就是了，设备照开。这是前后兼容的经典形状：交集工作，差集沉默。

### 1.5 生命周期：认亲上岗下岗

建设备（`virtio_setup_device`）五步：验参数（空名负数零线程全拒），找卡（厂商对、子设备对），认亲（写确认 `VIRTIO_STATUS_ACK` 加驱动 `VIRTIO_STATUS_DRV` 两字节），开队列（按数分配），备间接表。就绪（`VIRTIO_STATUS_DRV_OK`）三步：队列内存就位，中断挂号，开机字节。复位一键：状态清零，中断注销，设备重置。释放两步：先放队列内存，再放设备（顺序反了悬空指针：队列内存先走，设备结构随后）。

踢门铃的规矩：宿主机说别踢就不踢（不通知位），除非队列满了（满了宿主机可能等着腾地方，不踢死锁）。中断的规矩对称：客户机说别吵就不吵。两条规矩都是省开销的：铃越少越快，但正确性不靠铃（靠轮询序号），所以省铃大胆省。

### 1.6 本章小结

虚拟队列是旋转寿司：菜单描述符，可用传送带，已用回收带，特性取交集，生命周期五步，踢与中断各有省铃规矩。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单

| 文件 | 行数 | 内容 |

### 2.2 环布局（`virtio_ring.h` 全文）

描述符 `vring_desc` 十六字节（地址八字节、长度四字节、标志两字节、下一两字节）。标志三位：下一（`VRING_DESC_F_NEXT`）、写、间接。可用环（标志、序号、单号数组），已用环（标志、序号、完成数组），完成项八字节（单号四字节、长度四字节）。抑制两标志：已用不通知、可用不中断。协商两特性位：间接二十八（`VIRTIO_RING_F_INDIRECT_DESC`）、事件索引二十九。头文件禁改声明写在注释里：改了宿主机客户机两边全断。

### 2.3 建设备与协商（`virtio.c` 第一百二十行到第二百七十五 行）

验参数（空名、负数、零线程全拒，返回空），找卡（厂商对子设备对，不对空），认亲（写确认加驱动），协商（`exchange_features`：读宿主位，掩码客户请求，回写交集），开队列（按数分配内存，失败释放设备），备间接表（按线程数预分配，分配要进内核所以一次备好）。队列内存是连续物理页（客户机与宿主机共享的唯一内存，地址双方可见）。

### 2.4 队列与索引（`virtio.c` 第二百七十六行到第五百零六行）

物理队列初始化（虚实地址、页号、环大小、空闲链串好、已收序号清零）。空闲表管理（取链还链）。间接表管理（占用标记，描述符用完清表）。发链（链描述符进环，踢按规矩），收链（已用序号推进，数据指针带回，长度带回，无货返回负一）。

### 2.5 踢与中断（`virtio.c` 第七百三十六行到第八百三十一行）

中断归属读状态寄存器（是本设备中断才认）。复位（注销中断，重置设备）。开关中断（使能失能各一行）。踢规矩（不通知位清或队列满才踢）。匹配设备（厂商子设备双对）。中断注册注销。特性查询（宿主位读，客户位读）。读三宽度（八字节十六三十二各一函数）。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 环索引做成状态机（依据：第 1.2 节、第 1.3 节、第 2.2 节、第 2.4 节）

空闲链、可用序号、已用序号、已收序号四数一结构。取链还链常数时间，发菜收碟各一方法。回绕用回绕加减（序号自然回绕，结果恒对）。替代方案是裸数组加散落计数，不选的理由是：四数恒等式（空闲数加已用数恒等）散出去没人守得住。

### 3.2 协商做成交集函数（依据：第 1.4 节、第 2.3 节）

宿主位进，表内位掩码，交集出。未知宿主位忽略（前向兼容）。替代方案是要求全等，不选的理由是：全等等于拒绝升级，老客户机新宿主机开不了机。

### 3.3 生命周期做成阶段机（依据：第 1.5 节、第 2.3 节、第 2.5 节）

新认亲列队就绪失败五态，乱序调用拒绝（没列队就就绪等于没买票上车，直接拒）。状态字节累积写（确认加驱动加就绪或失败）。替代方案是布尔三元组，不选的理由是：阶段机把非法转移变成不可能（类型层面走不到），布尔要靠调用方记得查。

### 3.4 端口做成行为定义（依据：第 2.5 节）

读写字节两方法，空端口与向量端口两个行为不同的实现满足门禁：空端口测缺硬件路径，向量端口测读写记录。替代方案是端口号进库，不选的理由同总线篇。

### 3.5 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 环索引状态机 | 第 1.2、1.3、2.2、2.4 节 | 裸数组散计数 | 恒等式没人守 |
| 协商交集函数 | 第 1.4、2.3 节 | 要求全等 | 拒绝升级 |
| 生命周期阶段机 | 第 1.5、2.3、2.5 节 | 布尔三元组 | 非法转移可能 |
| 端口行为定义 | 第 2.5 节 | 端口号进库 | 硬件泄漏 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 参数非法 | 返回空 | 服务层拒绝建设备 | 空名负数零线程 |
| 找卡失败 | 返回空 | 服务层拒绝建设备 | 厂商子设备不对 |
| 队列内存失败 | 释放设备 | 服务层回滚 | 先建后开，开败拆建 |
| 无空描述符 | 等待或间接表 | `take_free` 空 | 调用方切间接路 |
| 未知宿主位 | 忽略 | 协商跳过 | 前向兼容 |
| 乱序就绪 | 不可能 | 阶段机拒绝 | 没列队不就绪 |

## 6. 过渡：从契约到首个房客

虚拟队列是空架子：环转得再溜，没有房客住也是空转。下一篇虚拟块设备是第一个房客：读请求三段链（头、数据、状态），扇区对齐，状态码翻译。框架与房客的分工是：框架管环怎么转，房客管链怎么编。读虚拟块之前，建议重温本篇的链式：头数据状态三段是下一章的主角。
