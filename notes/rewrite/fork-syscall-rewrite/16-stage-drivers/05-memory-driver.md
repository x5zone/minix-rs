> **说明**：内存驱动是启动映像里仅有的两个驱动之一（另一个是终端驱动），也是全系统唯一同时服务字符与块两种请求的驱动。它管七个固定设备加六个内存盘：绝对内存、内核内存、空洞、零源、启动设备、映像盘，外加六个可扩容的内存盘。本篇讲这个双面驱动的全部语义：两张回调表、主循环如何分诊、每个设备的读写行为、内存盘扩容控制。

> 本篇只回答一个问题：**一个驱动如何同时当字符设备与块设备，十三个次设备各自是什么行为**。

## 1. 概念：身兼两职的馆员

### 1.0 章节引言

目标读者是已经读完框架批四篇的读者。前置知识只需要一条：字符请求走字符框架，块请求走块框架。本章解释一个驱动如何同时挂两边，以及十三个次设备各自的脾气。

### 1.1 内存驱动是身兼两职的馆员

想象图书馆里一位馆员，白天在借书台回答读者（字符面：读零、写空洞），晚上在库房盘点书架（块面：读写内存盘）。同一位馆员，两套工服，读者按窗口排队，馆员看窗口决定穿哪套。

Minix3 的内存驱动就是这位馆员。主循环收到消息先看类型：块请求进块框架，字符请求进字符框架（`memory.c` 第一百零一行到第一百零四行）。两边各有一张回调表，字符四挂钩（打开、关闭、读、写），块六挂钩（类型、打开、关闭、传输、控制、分区查询）。分诊规则只有一条：看编号认家族，与框架的家族判定是同一条。

### 1.2 十三个次设备：七固定加六盘

次设备号零到十二。前七个固定：零号兼容内存盘（一号以前的老名字），一号绝对内存（整台机器的物理内存），二号内核内存（内核虚拟内存的映射窗口），三号空洞（黑洞，读永远到头，写全吞掉），四号启动设备（启动映像载入的设备），五号零源（读全是零，写全吞掉），六号映像盘（链进驱动的启动映像）。七到十二是六个内存盘，初始没有后备存储，靠控制命令逐个扩容。

字符面只认一、二、三、五（绝对内存、内核内存、空洞、零源），其余九个走块面。面的归属函数是全驱动共享的一条规则：字符请求落在块设备上（或反过来）一律回答没有此设备。这条规则防止调用方拿错窗口：用字符语义打开内存盘是调用方的错误，越早报错越好。

### 1.3 读写的三板斧：到头、截短、搬运

所有传输共享同一套截断语义：位置超出设备长度回答零字节（到头），请求跨过结尾按剩余长度截短（截短），剩下的才搬运（搬运）。字符读、字符写、绝对内存页窗口、块向量循环，四处各写一遍同样的三行，这是 C 语言里典型的复制粘贴，Rust 实现把它收成一个 clamp 函数，四处共用。

空洞读永远回答零（永远到头），零源读保留全部长度（由内核代填零），空洞与零源写全吞（回答全部长度，什么都不存）。内核内存从映射窗口搬，绝对内存按页窗口搬，内存盘与映像盘从后备存储搬。六种行为一张表，见第 2.5 节。

### 1.4 页窗口：一次只看一页

绝对内存有四吉字节，不可能一次全映射。驱动只映射当前需要的那一页：要读的字节在哪页就映射哪页，下一个字节还在同一页就继续用，跨页了先解除旧映射再建新映射。缓存恰好一页，多一页都不留，这是内存受限时代的典型写法。

页窗口算法有三条状态：有没有映射、映射的是哪页、窗口地址。选择函数先算目标页，命中直接返回，未命中先解旧映射再建新映射，建失败报内存不足。刷新函数解映射清状态。这个算法与具体映射原语无关，Rust 实现把它做成泛型策略，映射原语收进行为定义，测试用内存后备，生产用真实映射。

### 1.5 内存盘扩容：先问三件事

内存盘扩容控制只接受一种控制码，其他一律无效参数。通过之后问三件事：是不是内存盘（兼容号、六个盘号、映像盘算数，其他算错），尺寸是不是已经对了（对了直接成功，映像盘强制按零算），是不是只有控制自己在用（打开计数必须是一，控制自己占一次，有别人也开着就报忙）。三问全过才拆旧后备建新后备：旧后备按页对齐解除映射，新尺寸零不分配，非零分配匿名映射，失败报内存不足。

忙检查是三问里最重要的一问：有人正在用盘时换后备，正在飞的读写会落到释放掉的内存上。所以扩容要求独占，不独占宁可报错。这是典型的先验证后动手，验证不过一律不动原状。

### 1.6 启动顺序：映像盘先行

驱动初始化时先登记映像盘（基址零、长度为链入映像的大小、地址为映像符号），再把打开计数全清零，再把绝对内存登记为四吉字节，最后宣告字符与块两边上线。映像盘登记在前是因为根文件系统马上就要从它读启动文件，它是开机后第一个被读的块设备。

内核内存的映射代码在源码里被预处理开关关掉了（`memory.c` 第一百三十行到第一百四十五行的 `#if 0` 块），原因是内核内存布局改由虚拟内存服务统一管理，驱动不再自己映射。这段死代码是理解职责边界的活化石：驱动消费映射，不拥有映射。

### 1.7 与其他系统的对照

Linux 把同样的设备拆成多个驱动：空洞零源一个，内存一个，内存盘一个（brd），映像盘是启动流程的一部分。Minix3 把十三个设备塞进一个驱动，原因是启动映像要求驱动尽量少：多一个驱动就多一个进程、多一次宣告、多一份依赖。理解了启动映像的约束，就理解了双面驱动不是炫技，是省钱。

Redox 没有直接对应的驱动：它的零源与空洞是方案（scheme）的一个分支，内存盘是另一个方案。路由键不同（路径对编号），但面的思想相通：同一个实现可以同时回答多种请求，路由只认键。

### 1.8 本章小结

内存驱动是双面馆员：主循环看编号分诊，两张回调表各管一面，十三个次设备各有脾气，传输共享到头截短搬运三板斧，绝对内存用单页窗口，内存盘扩容先问三件事，映像盘登记在先。下一章进入 C 语言源码验证。

## 2. C 语言源码分析

### 2.1 文件清单与设备号

| 文件 | 行数 | 内容 |
|------|------|------|
| `minix3/minix/drivers/storage/memory/memory.c` | 五百九十九行 | 双面主循环、两张回调表、字符四函数、块五函数、页窗口、扩容控制 |
| `minix3/minix/include/minix/dmap.h`（第八十五行到第九十二行） | 八行 | 八个设备号定义 |
| `minix3/minix/include/sys/ioc_memory.h` | 约十行 | 内存盘扩容控制码定义 |

设备号：兼容内存盘零、绝对内存一、内核内存二、空洞三、启动设备四、零源五、映像盘六、内存盘首七（`dmap.h` 第八十五行到第九十二行）。内存盘数六（`memory.c` 第三十七行），设备总数十三（`memory.c` 第四十一行）。

### 2.2 两张回调表与主循环（`memory.c` 第六十三行到第一百零八行）

字符表四挂钩（打开、关闭、读、写），块表六成员（磁盘类、打开、关闭、传输、控制、分区查询）。主循环是死循环：阻塞接收任意消息，接收失败停下，块请求进块框架，其余进字符框架。注意分诊用块判定宏肯定式，字符侧是兜底：未来新增家族的消息会掉进字符框架再被通用挂钩处理，不会卡死。

### 2.3 初始化（`memory.c` 第一百一十三行到第一百六十五行）

注册新启动与重启回调（重启走有状态分支，内存盘内容要保留），启动框架接管。初始化函数登记映像盘（基址零、长度为映像尺寸、地址为映像符号），清零全部打开计数，登记绝对内存四吉字节，宣告两边上线。内核内存映射块被 `#if 0` 关掉，见第 1.6 节。

### 2.4 面的归属（`memory.c` 第一百七十行到第一百八十四行）

面的函数对一、二、三、五回答假（字符面），其余回答真（块面）。字符三函数与块四函数入口全调它，错面一律没有此设备。数一数分支：一共十三个次设备，四个字符面，九个块面，一个不多一个不少。

### 2.5 六种读写行为

| 次设备 | 字符读 | 字符写 | 块读写 |
|--------|--------|--------|--------|
| 空洞（三） | 零字节（永远到头） | 全吞 | 不服务（错面拒绝） |
| 零源（五） | 全长（内核代填零） | 全吞 | 不服务（错面拒绝） |
| 内核内存（二） | 映射窗口搬运（截短） | 映射窗口搬运（截短） | 不服务（错面拒绝） |
| 绝对内存（一） | 页窗口搬运（截短） | 页窗口搬运（截短） | 不服务（错面拒绝） |
| 内存盘（零、七到十二） | 不服务（错面拒绝） | 不服务（错面拒绝） | 后备存储搬运（截短） |
| 映像盘（六）、启动设备（四） | 不服务 | 不服务 | 后备存储搬运（截短） |

内核内存传输（第一百八十九行到第二百一十三行）：窗口未初始化报输入输出错误，到头截短，读调安全复制出，写调安全复制入，复制失败返回复制错误码。绝对内存传输（第二百一十八行到第二百八十二行）：页对齐算目标页，命中复用、未命中先解后建，建失败先报内存不足再无内存，页内分段搬运，位置与偏移双推进，返回搬运总数。

### 2.6 打开关闭计数（`memory.c` 第三百六十行到第四百零一行，第四百八十二行到第五百零七行）

字符打开与块打开都先过面的门，再计数加一。字符打开在三十二位兼容构建下给绝对内存的出资进程开输入输出特权（`memory.c` 第三百六十七行到第三百七十八行的条件编译），六十四位构建没有这段。字符关闭与块关闭都先过面的门，计数为零报无效参数，否则减一。关未打开的设备是调用方的错误，大声报错，不静默。

### 2.7 块传输向量循环（`memory.c` 第四百一十七行到第四百七十七行）

先查分区（查不到没有此设备），高半部位非零直接成功零字节（超大位置视为到头之外），逐向量元素搬运：元素长度按剩余截短，未初始化后备报输入输出错误，到头返回已搬总数，复制失败停下（此处是全驱动唯一的复制失败停下，因为块复制失败意味着后备损坏，无恢复意义）。元素耗尽进下一格，偏移清零，总数累加，返回总数。

### 2.8 扩容控制（`memory.c` 第五百一十二行到第五百九十九行）

控制码不对直接无效参数。映像盘强制按零算。只有兼容号、盘号段、老号、映像盘能进，其余无效参数。取请求结构失败返回取数错误。尺寸已对直接成功。打开计数不是一报忙。旧后备按页对齐解除映射（失败只告警不报错，因为旧盘本来就要扔）。新尺寸零不分配，非零匿名映射，失败报内存不足。登记地址与长度，成功。（控制码 `MIOCRAMSIZE` 的数值是平台相关的输入输出控制编码，本库只认策略不认数值，数值在服务层比对。）

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 设备号做成枚举（依据：第 1.2 节、第 2.1 节）

十三个次设备八个变体（六个盘共用一变体加索引）。解码失败返回空，调用方映射为无此设备或输入输出错误。替代方案是整数常量，不选的理由同框架篇：漏检查即漏洞。面的归属做成枚举方法，字符读写的守卫与块传输的守卫共用一条，不存在两边口径不一致。

### 3.2 几何表做成定长数组（依据：第 1.6 节、第 2.3 节）

十三槽几何加十三槽计数，初始化只填绝对内存，其余由服务层在启动与扩容时填。打开计数饱和加（C 语言不设防溢出，Rust 用饱和加保留不崩溃，计数本身无语义上限含义）。替代方案是动态表，不选的理由是：槽位数是协议常量，编译期定死。

### 3.3 截断做成一处函数（依据：第 1.3 节、第 2.5 节）

四处手写的到头截短收成 `clamp` 一个常量函数。替代方案是各处手写，不选的理由是：四处手写必然有一处写错（历史上这类截断是越界读的高发区），一处实现加四组测试锁死。

### 3.4 规划与复制分离（依据：第 1.3 节、第 2.5 节）

读写函数只算规划（搬多少、从哪种后备、要不要过页窗口），不碰复制。复制是传输相关，只能在服务层做（需要授权与端点）。替代方案是规划函数直接调复制，不选的理由是：那样全部测试都要进内核环境，策略测不起。这与客户端库的传输抽象是同一个思想：策略可测，机制可换。

### 3.5 页窗口做成泛型策略（依据：第 1.4 节、第 2.5 节）

缓存一页的算法收成泛型，映射原语收进行为定义。空映射与内存映射两个行为不同的实现满足门禁：空映射专测内存不足路径，内存映射测命中复用与跨页切换。替代方案是窗口与映射写死在一起，不选的理由是：写死了就测不了跨页逻辑，只能进真机测。

### 3.6 扩容做成纯策略函数（依据：第 1.5 节、第 2.8 节）

六个分支（非盘、已对、忙中、可扩，外加未知号与映像强制零）收成一个纯函数，输入全是数值，输出是四种裁决。后备的拆建在服务层。替代方案是策略里直接调映射分配，不选的理由同上：分配失败路径在纯函数里测得更全（忙中分支不分配也能测）。

### 3.7 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 设备号用枚举 | 第 1.2、2.1 节 | 整数常量 | 漏检查即漏洞 |
| 几何表定长数组 | 第 1.6、2.3 节 | 动态表 | 槽位是协议常量 |
| 截断一处函数 | 第 1.3、2.5 节 | 各处手写 | 手写必有一处错 |
| 规划复制分离 | 第 1.3、2.5 节 | 混写 | 策略测不起 |
| 页窗口泛型策略 | 第 1.4、2.5 节 | 写死 | 跨页测不了 |
| 扩容纯策略函数 | 第 1.5、2.8 节 | 混写分配 | 失败路径测不全 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 错面请求 | 没有此设备 | `open` 等返回该码 | 面的守卫 |
| 未知次设备号 | 没有此设备 | `decode` 空转该码 | 十三之外全拒 |
| 关未打开设备 | 无效参数 | `close` 返回该码 | 调用方错误，大声报 |
| 窗口未初始化 | 输入输出错误 | 服务层按规划报该码 | 后备没准备好 |
| 映射失败 | 内存不足 | `MapperError::NoMemory` 转该码 | 页建不出来 |
| 非盘扩容 | 无效参数 | `ResizeVerdict::NotRamdisk` | 面的守卫的控制版 |
| 盘忙扩容 | 忙 | `ResizeVerdict::Busy` | 独占要求 |
| 复制失败（块） | 停下 | 服务层按规划处理 | 块复制失败无恢复意义，文档记录 |

## 6. 过渡：从双面驱动到终端驱动

内存驱动证明框架能挂双面：分诊看编号，两边各一张表，面的守卫管串门。下一篇终端驱动是字符面的重用户：挂起、取消、轮询、行规则、多个终端共享一张表，框架的每条旁路都有人走。读终端驱动之前，建议重温本篇的面的守卫：终端驱动的视频次设备号走特殊分支，与面的守卫是同一类思想（认出不是自己的信，立即分流）。
