## 1. 概念：八条线的总机房

### 1.0 章节引言

目标读者是已经读完字符框架与内存驱动的读者。前置知识只需要两条：字符请求的七种形状，面的守卫的思想。本章解释终端驱动为什么比内存驱动复杂一个数量级：状态多（每条线几十个字段）、挂起多（读挂起写挂起控制挂起三路）、旁路多（时钟、硬件、内核消息、功能键、输入事件、视频）。

### 1.1 终端驱动是八条线的总机房

想象老式电话局的总机房：八条外线进来，话务员逐条应答。每条线有自己的状态卡：谁在通话（打开计数）、谁是主人（控制进程）、有没有人等着（挂起的读写）、留言了什么（输入队列）。话务员一次只处理一条线，但眼睛扫着八张卡，哪张卡亮灯处理哪张。

Minix3 的终端驱动就是这间机房。八条线是四个控制台加四条串口，每条线一张状态卡（终端结构，五十多个字段）。主循环每次先扫八张卡的事件灯（有灯先处理），再收一条新消息。事件灯是去耦的关键：硬件中断只负责点灯，真正干活的是主循环里的事件处理，灯与活分离，中断处理可以很短。

### 1.2 次设备号到终端表：三段加两特例

次设备号到终端表的映射分三段：控制台段（零到三）进表的前四槽，串口段（十六到十九）进表的后四槽，视频号（一百二十五）不进表走视频分支。两个特例：控制台别名（零号）与日志号（十五号）都重写成配置的控制台行，日志读还被额外拒绝（日志是只写诊断设备）。

映射失败（号段之外）或命中的线没激活，一律回答没有此设备。这是面的守卫的终端版：认不出是哪条线，立即退回。视频分支单独处理显示控制消息，不占用终端表槽位。

### 1.3 行规则：按键到字节的厨房

行规则是终端的灵魂：用户敲的键与程序读到的字节之间隔着一整套加工。加工按顺序走：七位截断、转义字符、重印请求、回车换行互转、正规模式的擦除与杀行、文件尾标记。每个加工受一个开关管：开关关了，对应加工跳过，字节原样进队列。

正规模式（`ICANON` 开关）与非正规模式是分水岭：正规模式一次一行（程序读到换行才返回），非正规模式按最小字节与超时返回。擦除删一个字符，杀行删整行（保留前面的换行），文件尾字符进队列但永不返回给程序（只起断行作用）。转义字符保护下一个字符：被保护的字符跳过一切解释，原样进队列并打保护标记。

输入队列是二百五十六格的环，附带换行计数。计数让正规读不用扫描：有换行才可能返回，没有换行直接挂起。队列满了新字符丢掉（C 语言响铃），这是有损但正确的选择：终端输入是人敲的，丢一个字符人会重敲，卡死整个驱动不可接受。

### 1.4 挂起三路：读挂起、写挂起、排空挂起

终端的读写不像内存驱动那样当场完成：读要等用户敲够一行，写要等设备慢慢吐。挂起信息存在状态卡上：读挂起记调用方、标识、授权、还差多少、已到多少；写挂起同样；排空挂起记控制码。三路各记各的，取消时按调用方加标识精确匹配， match 哪路答哪路：读有货答货数，无货答再试；写同理；排空答中断。

重复挂起是调用方的错误：已经有一路读挂着又来一路读，回答输入输出错误。长度零也是错误：读零个字节没有意义，回答无效参数。这两条守卫把糊涂的调用方挡在门外，不让它把状态卡搞乱。

### 1.5 轮询两条特殊规则

轮询就绪判断有两条终端特有的规则。第一条：挂断速度下什么都就绪。线路挂断意味着对端永远不会再有数据，等下去没有意义，不如立即返回让程序自己处理挂断。第二条：正规模式下读就绪要求见过换行。队列里有字符但全是半行，正规读去了也白去，不如说没就绪。

轮询注册还有一条跨次设备号规则：同一对象通过两个不同次设备号注册，被拒绝。因为日志号与控制台号指向同一条线，迟到的就绪通知只带一个次设备号，带错了虚拟文件系统服务配不上对。所以注册时记下次设备号，迟到通知原样带回，注册冲突直接拒绝。

### 1.6 内核消息重定向：黑板报

内核想打印消息时不自己画屏，它把消息放进共享的环形缓冲，发信号通知终端驱动。驱动算出新增了多少字节（用新旧写指针的差对缓冲长度取模，取模保证环绕正确），拷出来，发往当前控制台的写路径（走非阻塞写，不抢占正在打印的内容：正在打印先备份，写完恢复）。日志驱动的诊断捕获是同一块缓冲的另一个读者，两边各记各的读指针，互不干扰。

### 1.7 主循环：先扫灯再收信

主循环是死循环：先扫八张卡的事件灯（亮灯就处理），再阻塞收一条消息。通知分支：时钟走定时器到期处理，硬件走串口中断加定时器，其他不管。特殊消息分支：功能键控制、输入服务上线、输入事件各走各的。视频号走视频分支。剩下的字符请求先取次设备号（取不出丢弃），再进字符框架。字符框架之外的消息也进字符框架，由通用挂钩处理。

这个先扫灯再收信的顺序保证事件不饿死：如果只收信不扫灯，密集的消息流会让事件灯一直亮着没人处理。先扫灯的那一轮不收信，最多延迟一条消息的时间，换来事件的及时性。

### 1.8 与其他系统的对照

Linux 的行规则住在内核的行规程层，终端驱动只管硬件，层次分明。Minix3 把行规则与硬件驱动放在一个进程里，原因是进程间消息太贵：每个按键都发两次消息（键盘到行规则，行规则到程序），延迟受不了。合在一起后，按键进队列与程序读队列之间只隔一次函数调用。这是微内核的经典取舍：层次纯洁性让位于按键延迟。

Redox 的终端也是用户态进程，行编辑 approach 接近：输入先攒行再交付。但 Redox 用路径路由（终端路径），Minix3 用次设备号路由，数字路由更快，路径路由更灵活，各有利弊。

### 1.9 本章小结

终端驱动是八线总机房：事件灯去耦中断与处理，次设备号三段加两特例映射，行规则七步加工，挂起三路精确配对，轮询两条特殊规则，内核消息走黑板报，主循环先扫灯再收信。下一章进入 C 语言源码验证。

### 2.2 主循环（`tty.c` 第一百四十六行到第二百三十九行）

先扫灯（八张卡的事件标志），再收信。通知分时钟（定时器到期）、硬件（串口中断加定时器）、其他（不管）。特殊消息分功能键控制、输入上线、输入事件。视频号走视频分支。字符请求取次设备号后进字符框架，非字符请求直接进字符框架。接收失败停下，与框架同哲学。

### 2.3 映射（`tty.c` 第二百六十四行到第二百九十二行）

控制台别名与日志号重写成配置行，视频号返回空（调用方走视频分支），控制台段与串口段按段进槽，段外返回空，命中未激活返回空。三段两特例一激活检查，数一数分支：七个出口，一个不多。

### 2.4 打开关闭（`tty.c` 第七百二十一行到第七百七十七行）

打开：映射失败没有此设备，日志读拒绝访问，否则按访问字决定是否收编控制终端（不禁才收编，收编返回控制标记），计数加一，首次打开调设备打开。关闭：映射失败没有此设备，日志跳过计数（日志不计数），末次关闭清控制、取消输入输出、调设备关闭、恢复默认终端属性与窗口尺寸、重设行参。末次关闭恢复默认是关键：上一个程序改的行参不能漏给下一个程序。

### 2.5 取消（`tty.c` 第七百七十八行到第八百一十四行）

映射失败没有此设备。按读、写、排空的顺序 match 调用方加标识：读命中按有货无货答货数或再试，清读挂起；写命中同理；排空命中答中断，清排空挂起。命中任一路置事件灯（唤醒事件泵）。全 miss 回答不回复（陈旧取消，静默吞掉）。

### 2.6 轮询（`tty.c` 第八百一十六行到第八百九十九行）

就绪探测：挂断速度全就绪；读就绪要求挂起中（必不阻塞）或队列有货加正规换行规则；写就绪要求正在排空或设备能吃。注册：立即就绪的子集直接返回，剩余在要求迟通知时登记，登记记下次设备号，双次设备号冲突拒绝。重试：重测登记的操作，有就绪发迟通知并清相应位。

### 2.7 读写挂起（`tty.c` 第四百七十行起读，写分支随后）

读：映射失败没有此设备，双挂起报输入输出错误，零长度报无效参数，登记挂起四件套，非正规定时按最小与超时布定时器，先灌队列再泵事件，灌完挂起清零说明当场做完（回答不回复，由事件泵稍后补答），队列空且非阻塞则撤挂起按有货无货回答，否则挂起（阻塞等）。写：同形，方向相反，设备慢慢吐，吐完事件泵补答。

### 2.8 设备相关分工（不展开寄存器）

控制台：屏幕初始化、字符输出、滚屏、铃声、字体加载、控制台切换、视频分支消息。串口：初始化、中断处理、收发。键盘：一次性初始化、扫描码映射、功能键控制、输入事件入口。本篇只记录分工与入口函数名（见 `tty.h` 末尾的声明段），逐寄存器行为是架构相关，留给后续文档。行规则与设备之间通过七个设备函数指针接线（读、写、取消输入输出、开关中断、控制、开关），指针为空用空操作代替。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 线路解码做成枚举（依据：第 1.2 节、第 2.3 节）

控制台、串口、视频三变体，日志别名在解码时重写。槽位计算收成方法（控制台低槽，串口随后）。激活检查留给调用方（激活表在服务层，知道哪条线插着电）。替代方案是整数加减，不选的理由是：段界算错一位就串线，枚举让串线在类型层面不可能。

### 3.2 行配置做成值类型（依据：第 1.3 节、第 2.4 节）

八个开关加八个控制字符加速度。末次关闭恢复默认收成常量函数，默认值一眼可查。挂断速度做成谓词，轮询探测直接调。替代方案是透传 C 结构，不选的理由是：C 结构几十个字段，大部分本驱动不解释，透传等于把不理解的东西背进类型。

### 3.3 输入队列做成环加计数（依据：第 1.3 节、第 2.7 节）

二百五十六格环，换行计数附带。擦除删尾，杀行删到换行，满了返回假（调用方响铃或丢弃，策略在服务层）。替代方案是动态数组，不选的理由是：容量是协议常量，定长环最简单，且 C 语言的环形语义（满了丢）必须保留。

### 3.4 行加工做成逐字节状态机（依据：第 1.3 节、第 2.7 节）

一次一字节，状态只有转义 pending 一位。回显不在状态机里（回显要画屏，是传输相关）。每个字节的结局是六种之一：存、擦、杀、丢、忽略、重印。替代方案是整块处理，不选的理由是：转义与擦除都是跨字节状态，整块处理要回头看，逐字节最直接。

### 3.5 会话做成一线一状态（依据：第 1.4 节、第 1.5 节、第 2.4 节到第 2.6 节）

打开计数、控制端点、三路挂起、轮询登记全收进一个结构。取消按三路顺序精确匹配，轮询探测与注册分离（探测纯读，注册写登记）。双次设备号冲突拒绝收进注册函数。替代方案是散落的全局数组（C 做法），不选的理由是：一线一状态让测试一次测一条线，互不干扰。

### 3.6 后端做成行为定义（依据：第 2.8 节）

七个设备函数收成七个方法，全默认空操作。空后端与回环后端两个行为不同的实现满足门禁：空后端测无设备，回复环测有来有回。控制台串口伪终端的真实后端在服务层与后续文档实现。替代方案是函数指针表（C 做法），不选的理由同框架篇：空检查分散不如默认体集中。

### 3.7 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 线路解码用枚举 | 第 1.2、2.3 节 | 整数加减 | 段界算错串线 |
| 行配置值类型 | 第 1.3、2.4 节 | 透传 C 结构 | 背进不理解的字段 |
| 输入环加计数 | 第 1.3、2.7 节 | 动态数组 | 容量是协议常量 |
| 加工逐字节状态机 | 第 1.3、2.7 节 | 整块处理 | 跨字节状态回头看 |
| 一线一状态 | 第 1.4、1.5、2.4-2.6 节 | 全局数组 | 测试互相干扰 |
| 后端行为定义 | 第 2.8 节 | 函数指针表 | 空检查分散 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 未知线路 | 没有此设备 | `decode` 空 | 段外全拒 |
| 未激活线路 | 没有此设备 | 服务层激活表拒绝 | 解码后第二道门 |
| 日志读 | 拒绝访问 | `open` 返回该码 | 日志只写 |
| 双挂起读 | 输入输出错误 | `park_read` 返回该码 | 调用方糊涂，大声报 |
| 零长度读写 | 无效参数 | `park` 系列返回该码 | 读零字节无意义 |
| 取消 miss | 不回复 | `cancel` 返回空 | 陈旧取消静默吞 |
| 取消命中读 | 货数或再试 | `Cancelled::Read` | 有货答货，无货答再试 |
| 取消命中排空 | 中断 | `Cancelled::Drain` | 等排空被信号打断 |
| 双次设备号注册 | 坏文件 | `select` 返回该码 | 迟通知配对要求 |
| 挂断速度 | 全就绪 | `probe` 返回全部 | 等下去无意义 |

## 6. 过渡：从物理终端到伪终端

终端驱动管的是真线：控制台、串口，键盘在那头。下一篇伪终端管的是假线：主从对，没有硬件，主端是程序，从端跑着壳。两篇共用行规则与挂起选择：伪终端的从端就是一台终端机，只是它的键盘与屏幕是主端的程序。读伪终端之前，建议重温本篇的行加工与取消配对：主端取消与从端取消是两套挂起，容易搞混。
