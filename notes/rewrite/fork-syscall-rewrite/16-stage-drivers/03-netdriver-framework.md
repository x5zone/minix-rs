## 1. 概念：机场塔台

### 1.0 章节引言

目标读者是已经读完前两篇的读者。前置知识只需要一条：单线程事件循环（一次处理一条消息）。本章解释网络框架与前两篇不同的地方：对话对方、队列的形状、状态上报。

### 1.1 网卡驱动是一座机场塔台

想象一座小型机场的塔台。塔台平时不生产任何东西，它只做三件事：飞机要降落时给它安排跑道（收包），飞机要起飞时放行（发包），跑道状况变了广播通知（链路与统计上报）。塔台一次只处理一架飞机，但脑子里记着等待的队列：起飞排一条队，降落排一条队。

Minix3 的网络框架就是这座塔台。协议栈是航空公司：它把要发的包递给塔台，把收包的空缓冲也递给塔台。网卡是跑道：真正的起降发生在那里，驱动负责在塔台与跑道之间搬运。框架本身不碰网线，它管队列、管状态、管组播名单。

这个比喻对应四处真实机制：发送队列最多记八个待发的包，接收队列最多记两个待收的缓冲，链路状态变化时主动推给协议栈，统计计数变化时也推。队列满了新的请求直接拒绝，不排无限长的队。

### 1.2 六种请求：初始化、配置、发送、接收、保留、状态确认

协议栈与网卡驱动之间只说六种话：初始化、配置、发送、接收、保留控制、状态确认。编号是基址 `0x1A00` 加零到五的索引，判定宏同样看高位等不等于基址。

初始化最特殊：它是协议栈重启后说的第一句话，意思是之前欠的账一笔勾销，发送队列接收队列全部清空，状态确认也重来。框架收到初始化时先忘掉一切，再把网卡名字、硬件地址、能力位、链路状态、收发队列上限打包回复过去。这就是为什么服务器状态里有一个初始化期待标志：没收到初始化之前，其他请求一律拒绝。

配置一句话里塞五种子类型：设模式与组播名单、开关能力、设专用标志、设介质类型、改硬件地址。模式位决定收哪些包：只收自己的单播，只收广播，收名单上的组播，收全部组播，全部都收（混杂模式），或者全关。组播名单最多一次带十六个，多了就让网卡收全部组播，不再点名。

发送与接收是数据的两条路：发送是协议栈把包递下来，框架排进发送队列，网卡取走发掉；接收是协议栈把空缓冲递下来，框架排进接收队列，网卡把收到的包填进去。保留控制槽一直空着，留给未来。状态确认是协议栈对状态上报的回执。

### 1.3 十二个回调：网卡要会的事

框架定义十二个挂钩：名字、初始化、停止、设模式、设能力、设标志、设介质、改地址、接收、发送、取链路、中断、定时、通用消息。数据只走接收与发送两个：接收是网卡把包交出来，发送是网卡把包拿走。复制包内容的授权向量操作留在服务层，行为定义只谈长度，不谈授权与端口。

默认值全部是安静忽略：不停的卡不用实现停止，不换地址的卡不用实现改地址。初始化默认报零地址零能力零轮询，收发默认不动（接收报零表示没有包，发送报成功但没发，测试时一眼看出没实现）。

### 1.4 收发队列：八与二的讲究

发送队列记八个，接收队列记两个。为什么不对称？因为发送是协议栈主动推，突发时一次来好几个，队列短了吞吐上不去；接收是网卡被动填，缓冲由协议栈提前给，给两个周转就够，多了占内存。这个八与二是从协议栈的对应模块里抄过来的，两边必须对上，否则一方说能排八个另一方只准备两个槽。

### 1.5 状态上报：链路与统计主动推

链路变了（网线插拔）与统计涨了（错包、碰撞、丢包）不走请求回复，走框架主动推。网卡调四个统计函数之一，框架记下数字，置起待发送标志，发状态报告给协议栈。计数为零的上报直接忽略，不脏化待发送标志。协议栈回状态确认表示收到。

### 1.6 端口辅助：搬包的姿势

老网卡用输入输出端口搬包，新网卡用内存映射。端口搬运的算法是：从包内扁平偏移找到起始的向量元素，然后逐元素搬，一段一段来。框架把这个走格子的算法收进共享的默认方法，板卡侧只实现搬一个连续小块。这样老网卡的驱动只需要写几十行端口读写，不用重写走格子逻辑。端口号永远不进操作系统层：行为定义的方法参数里没有端口，端口只出现在板卡实现内部。这是 `[ARCH A-2]`（输入输出端口与内存映射的硬件抽象）在本框架的落点。

### 1.7 初始化门：先报到再干活

服务器状态里有一个初始化期待标志，初始为真。没收到初始化之前，发送接收配置一律拒绝并报无效参数。这个门与字符块的重启门是同一个思想：状态没对齐之前不干活。但网络没有已打开设备表，因为网卡没有次设备的概念：一张卡就是一个整体，不存在打开这个分区的概念。

### 1.8 本章小结

网络框架等于塔台三件事：排队（发送八接收二）、推状态（链路与统计）、看门（初始化期待）。对话对方是协议栈，数据只谈长度不谈授权，端口只出现在板卡侧。下一章进入 C 语言源码验证。

### 2.2 请求常量与尺寸
请求编号是基址 `0x1A00` 加零到五（`com.h` 第一千零九十六行到第一千一百零一行），回复编号是回复基址 `0x1A80` 加零到五（第一千一百零三行到第一千一百零八行）。配置子类型五个（第一千一百一十一行到第一千一百一十五行）：设模式、设能力、设标志、设介质、改地址。模式位六个（第一千一百一十八行到第一千一百二十三行）：关闭、单播、广播、组播名单、组播全收、混杂。能力位九个（第一千一百二十六行到第一千一百三十四行）：六个校验和分项加组播、广播、改地址三个初始化能力。专用标志四个（第一千一百三十七行到第一千一百四十行）：调试加三条链路线。链路状态两个（第一千一百四十三行到第一千一百四十四行）：未知与上线。

尺寸三行在 `config.h` 第一百零二行到第一百零四行：名字上限十六（含结尾零）、硬件地址上限六、向量上限八。队列界限在 `netdriver.c` 第三十四行到第四十六行：发送八、接收二、组播名单十六。

### 2.3 框架状态与宣告（`netdriver.c` 第二十五行到第九十行）

文件静态量一览：回调表指针、运行标志、初始化期待、在线标志、轮询节拍、发送队列与计数、接收队列与计数、待确认状态与端点、链路与统计待推标志、四个统计计数、设备名字、硬件地址、能力位、链路、介质。宣告函数只干发布一件事：取本进程标签，拼网前缀，发驱动上线事件。失败停下，与字符块同哲学。

### 2.4 初始化处理（`netdriver.c` 第七百零六行到第七百六十行）

初始化请求先清账：发送计数接收计数归零，待确认状态清掉，状态端点换成新来的协议栈。然后刷新链路，组装初始化回复（标识、链路、介质、能力、名字、硬件地址与长度、收发队列上限），发回去。如果有攒着没发的统计，顺手推一份新的状态报告，让新协议栈一上来就有数。

这个先清账再回复的顺序是关键：协议栈重启意味着它手里的旧请求全作废了，框架这边不清账，后面来的发送请求会和旧账搅在一起。初始化就是双方对表的时刻。

### 2.5 端口辅助（`portio.c` 全文一百九十三行）

字节搬运函数是模板：从扁平偏移算出起始向量元素（调拷贝准备函数，越界直接停下），然后逐元素搬，每段调一次系统安全端口输入输出，失败停下。输入输出各有字节与字四个入口，全调这个模板。拷贝准备函数先拒绝超界（偏移加长度超出包长就停下），再线性找起始元素（注释说如果慢了可以缓存上次的位置，实际没做，因为向量最多八段，线性足够快）。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 请求编号做成枚举（依据：第 1.2 节、第 2.2 节）

六个变体，索引零到五，解码失败返回空。初始化期待门在分类函数里实现：期待初始化时非初始化请求直接报无效参数，不路由。替代方案是整数常量，不选的理由同前两篇。

### 3.2 硬件地址与统计做成值类型（依据：第 1.5 节、第 2.2 节）

地址是六字节数组加有效长度，零地址判断收进方法。统计是四个计数器，累加函数保留零忽略规则（零不上报，不脏化待发送标志），饱和加法防回绕。替代方案是裸数组与裸整数，不选的理由是：裸数组看不出有效长度，裸整数的零忽略规则会散落各处。

### 3.3 端口访问做成行为定义（依据：第 1.6 节、第 2.5 节）

走格子算法收进默认方法，板卡只实现搬一个连续小块。超界在走之前检查，一段没搬就失败，不存在搬一半。端口号只出现在板卡实现的参数里，行为定义的方法签名里没有端口之外的硬件概念，操作系统层只谈方向、宽度、偏移、长度。替代方案是自由函数加端口参数到处传，不选的理由是：自由函数无法约束板卡必须实现什么，行为定义让缺实现在编译期暴露。两个行为不同的实现（录制板，丢弃板）满足门禁：录制板记日志供检查，丢弃板不记供生产用。

### 3.4 驱动行为做成整体行为定义（依据：第 1.3 节、第 2.6 节）

十二个方法全部默认体。收发只谈长度：接收返回搬了多少字节，发送返回成功与否，授权向量一律不出现。第二个实现（回环卡）证明行为定义可被不同行为实现：静默卡全默认，回环卡重写收发链路中断。门禁要求行为定义至少有两个行为不同的实现，这两个满足。

### 3.5 队列做成常量泛型（依据：第 1.4 节、第 2.2 节）

发送八与接收二是同一类型的两个实例，容量是编译期常量。后备数组按最大界限分配，小队列用不完，换的是零运行时开销与类型层面的区分：发送队列传不到要接收队列的地方。替代方案是动态数组加运行时界限，不选的理由是：界限是协议常量，编译期定死最可靠。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 请求编号用枚举 | 第 1.2、2.2 节 | 整数常量 | 漏检查即漏洞 |
| 地址与统计值类型 | 第 1.5、2.2 节 | 裸数组与裸整数 | 长度与零规则散落 |
| 端口行为定义 | 第 1.6、2.5 节 | 自由函数 | 缺实现编译期不暴露 |
| 整体行为定义 | 第 1.3、2.6 节 | 拆小行为定义 | 路由只认编号 |
| 队列常量泛型 | 第 1.4、2.2 节 | 动态数组 | 界限编译期定死最可靠 |

## 4. 错误处理

| 场景 | C 行为 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 期待初始化时来其他请求 | 拒绝 | `classify` 报无效参数 | 先报到再干活 |
| 未知请求 | 走通用挂钩 | `Route::Other` | 不回复 |
| 队列满 | 拒绝新请求 | `push` 返回假 | 调用方稍后重试 |
| 包越界 | 进程停下 | `PortError::OutOfRange` | 走之前检查，不搬一半 |
| 板卡拒绝 | 进程停下 | `PortError::BoardFault` | 不停进程，报错代替 |
| 零统计上报 | 忽略 | `add` 返回假 | 不脏化待发送标志 |

## 6. 过渡：从框架到网卡

本篇讲完了网络语义的框架侧：初始化对表、配置下发、收发排队、状态上报、端口抽象。网卡的具体实现（参考网卡、虚拟网卡、其余十二种变体）在第二十二篇与第二十三篇：第二十二篇讲参考网卡如何把本篇的十二个回调填满，虚拟网卡如何把端口访问换成内存队列；第二十三篇是十二种真实网卡的差异矩阵。

协议栈本身（传输控制协议与网际协议服务）在第十七阶段。读那部分之前，建议先读本篇的初始化与状态上报：协议栈重启时重发初始化，框架清账，这个握手是理解协议栈恢复逻辑的关键。
