## 1. 概念：同声传译

### 1.0 章节引言

目标读者是理解状态机与单行道的读者。前置知识只需要两条：字符框架的通知旁路思想，翻译即查表。本章解释键盘翻译为什么需要状态，以及事件为什么只朝一个方向流。

### 1.1 键盘驱动是同声传译

想象联合国会场的同声传译：代表说话（按键），译员实时翻成六种语言（事件），耳机只朝一个方向送（单行道）。译员听不懂的不翻（填充表项吞掉），语气词要等下文（转义前缀等下一字节），最长的词要听完六个音节（暂停键六字节前奏）。

Minix3 的键盘部分就是这位译员。扫描码是源语言（硬件方言），通用输入事件是目标语言（系统普通话）。翻译分两步：状态机认出是哪个键（普通、转义、暂停三态），查表翻成页码加键码。页码为零的表项是填充（硬件预留位），直接吞掉不产生事件。

### 1.2 状态机：三个前缀

普通键一字节：最高位是松开标志（`SCAN_RELEASE`），其余七位查普通表（`kbd_process` 按松分家）。转义键两字节：扩展零前缀（`SCAN_EXT0`）加一字节，查转义表。暂停键六字节：扩展一（`SCAN_EXT1`）、控制（`SCAN_CTRL`）、数字锁定（`SCAN_NUMLOCK`）的按下松开各一对，状态机走二态再三态，集齐才发一个暂停事件，中途断了（比如扩展一后面跟了别的键）直接回零态，后续字节按普通键处理。

状态机只有四态（零一二三），简单却完备：转义只嵌一层，暂停前奏固定，错位自愈（错了回零，不卡死）。这是硬件协议的形状决定的：键盘只会发这几种前缀，没有更长的。

### 1.3 鼠标：三字经

鼠标说话是三字节一组（`kbdaux_process`）：首字节是按钮加符号位加同步位，后两字节是位移。同步规则一句话：首字节第三位置一才是包头，否则当噪声扔掉（掉字节后自愈）。按钮三位逐位比：变了就发事件（`INPUT_PAGE_BUTTON` 页，按下 `INPUT_PRESS` 松开各一），没变不吭声。位移非零就发：符号位展成三十二位有符号数，相对标志位（`INPUT_FLAG_REL`）置一（位移是相对的，不是绝对坐标）。

三字节组的妙处是自定界：丢一字节最多坏一组，下一包头一到自动对齐。不像流协议丢字节后面全错，包协议错一组好一组。这是硬件协议设计的常识：短包加同步位，宁可丢包不错位。

### 1.4 发光二极管：两字节命令

键盘的灯听指挥：命令字节（`LED_CODE`）加掩码字节，两字节一组排队发。队列十六字节（`KBD_OUT_BUFSZ`），满了新命令丢掉并清确认标志（旧命令可能卡住了，清标志让发送逻辑重来）。发送规则：有货且无未确认才发一字节，键回复确认（`KB_ACK`）才发下一字节。确认字节是固定值，对不上不算确认（串口噪声不背锅）。

掩码翻译是位对位：输入服务的三位（数字、大写、滚动）翻成键盘的三位（位置不同，值不同）。翻译函数是纯函数，一行一位，无分支。

### 1.5 事件桥：单行道

事件桥（`inputdriver_send_event`）是通往输入服务的单行道：事件只朝服务流，从不回头。桥的状态三件套：服务地址（没配不发货）、键盘号、鼠标号（无效号 `INVALID_INPUT_ID` 的那种不发货）。配置消息（`INPUT_CONF`）要验发送方（必须是输入服务本人，端点查对不上直接忽略）。发送用阻塞发：一次只发一件，发崩了（服务死了）立即解绑（地址清零，后续事件全拦下，直到重新配置）。设灯消息（`INPUT_SETLEDS`）同样验发送方。

阻塞发的两条理由写在源码注释里，值得全文背诵：一是防攒太多异步消息淹了服务，二是崩了立刻知道（阻塞发失败就是服务没了）。单行道加阻塞发，等于带背压的管道：服务慢了驱动跟着慢，不丢件。

### 1.6 初始化：认亲

驱动启动认两门亲：键盘（`INPUT_DEV_KBD` 必有，认不到报错），鼠标（`INPUT_DEV_MOUSE` 可选，有就多报鼠标标志）。认亲失败分两等：键盘认不到返回错（没键盘开什么机），鼠标认不到只少报标志（没鼠标照样开机）。上报标志是键盘位恒置加鼠标位可选，输入服务按标志配号（只配有的那种）。

### 1.7 本章小结

键盘驱动是同声传译：扫描码三态机，鼠标三字节包，发光二极管两字节命令，事件桥单行道阻塞发，初始化认亲。下一章进入 C 语言源码验证。

### 2.2 扫描与翻译（`pckbd.c` 第三百二十七行到第四百一十二行）

键盘处理 `kbd_process`：松开位分按松，索引去松开位，按状态机查普通表或转义表（`INPUT_PAGE_KEY` 页为主），页码零吞掉，否则发键盘事件（松紧原样带）。暂停走二三态：扩展一进二，控制键进三（按松皆可，索引比对去松开位），数字锁定出暂停事件，其余吞掉。鼠标处理 `kbdaux_process`：首字节第三位清零且包空直接回（重同步），攒三字节（不够回），清计数，三按钮逐位比（变了发事件，松紧看新态），两轴非零发相对位移（符号位展三十二位）。

### 2.3 发光二极管（`pckbd.c` 第一百七十五 行到第一百九十二行，第四百一十七行到第四百二十八行）

设灯 `set_leds`：空队从头起，超长丢并清确认（两字节装不下），否则追加命令加掩码。有未确认不发（发送函数首查）。灯映射 `pckbd_leds`：输入服务三位翻键盘三位（位对位）。确认分支：确认为固定值且有未确认才清（串口噪声不算数），清完发下一字节。

### 2.4 事件桥（`inputdriver.c` 全文二百零六行）

宣告：取本标签拼输入前缀，发驱动上线事件（类型即设备标志，覆盖写）。发送：地址空或号无效静默拦，填五字段发阻塞送，发送失败解绑（地址清零）。配置：验发送方是输入服务（端点查对不上忽略），存地址与双号，双号全无效打印诊断（驱动歇菜明示）。设灯：验发送方是桥地址（防冒名），调灯回调（空回调跳过）。路由：通知分硬件时钟通用三路，消息分配置设灯通用三路，全不回复（输入协议无回复，单行道）。

### 2.5 初始化（`pckbd.c` 第四百六十四行到第四百八十三行）

定时器初始化，键盘初始化（失败返回错），鼠标有无定标志（辅助口存在加鼠标位），宣告上线。键盘初始化本体内含自检、中断挂钩、控制器命令（端口体操在服务层，本库不管）。

## 3. Rust 设计决策

> 本章解释为什么这样设计。每个决策先给依据，再给替代方案与取舍。

### 3.1 扫描码做成状态机（依据：第 1.2 节、第 2.2 节）

四态一字节状态，一次一字节，结局三变体（等下文、出事件、吞掉）。暂停前奏收进状态转移（扩展一进二，控制进三，数字锁定出事件）。替代方案是正则式匹配整串，不选的理由是：输入是逐字节到的，等整串凑齐再匹配要另设缓冲，状态机天然逐字节。

### 3.2 对照表做成行为定义（依据：第 1.1 节、第 2.2 节）

普通转义两方法，示例表与空表两个行为不同的实现满足门禁：示例表测翻译路径，空表测吞掉路径。全表是数据（随服务数据走），逻辑是状态机（进库）。替代方案是全表进库，不选的理由是：一百六十九行数据进库，库的测试负担全是查表，逻辑一行测不到。

### 3.3 鼠标做成三字节组装器（依据：第 1.3 节、第 2.2 节）

包头同步位守门，按钮记忆逐位比，位移符号展，相对标志恒置。事件是枚举（按钮三元组、位移三元组），调用方 match 穷尽。替代方案是回调式（每事件调函数），不选的理由是：回调把组装与消费焊死，枚举让消费方可存可转可测。

### 3.4 发光二极管做成 outbox（依据：第 1.4 节、第 2.3 节）

排队、取字节、确认三方法，掩码翻译纯函数。满队丢并清确认（与 C 一字不差）。替代方案是发送放库里，不选的理由是：发送要端口，端口在服务层，库里放发送等于把端口请进库。

### 3.5 事件桥做成门禁状态（依据：第 1.5 节、第 2.4 节）

绑定、解绑、路由三方法，配置验发送方。发送本身在服务层（阻塞发的崩溃感知在服务层实现，本库只出门禁 verdict）。替代方案是发送放库里，不选的理由同上：发送要传输，传输在服务层。

### 3.6 设计决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 扫描状态机 | 第 1.2、2.2 节 | 正则整串匹配 | 另设缓冲多余 |
| 对照行为定义 | 第 1.1、2.2 节 | 全表进库 | 逻辑测不到 |
| 鼠标组装器 | 第 1.3、2.2 节 | 回调式 | 焊死消费方 |
| 灯 outbox | 第 1.4、2.3 节 | 发送放库 | 端口进库 |
| 桥门禁状态 | 第 1.5、2.4 节 | 发送放库 | 传输进库 |

## 4. 错误处理

| 场景 | C 返回 | Rust 表达 | 说明 |
|------|--------|-----------|------|
| 填充表项 | 吞掉无事件 | `Swallowed` | 硬件预留位 |
| 错位前奏 | 回零态 | 后续按普通键 | 自愈不卡死 |
| 包头失同步 | 扔字节 | `feed` 返回空 | 噪声字节丢掉 |
| 队满灯命令 | 丢并清确认 | `queue` 满分支 | 旧命令卡住重来 |
| 确认不对 | 不算数 | `note_ack` 假 | 串口噪声不背锅 |
| 桥未配 | 静默拦 | `route` 空 | 没地址不发货 |
| 号无效 | 静默拦 | `route` 空 | 没号不发货 |
| 配置冒名 | 忽略 | `configure` 假 | 端点对不上不认 |
| 发送崩溃 | 解绑 | `note_send_failure` | 服务没了全拦 |

## 6. 过渡：从按键到队列

键盘驱动把人手变成事件，事件进了输入服务才有下文。下一篇虚拟队列框架换了个世界：没有人手，只有虚拟机与宿主机之间的环形队列。但两篇对照看：键盘的状态机认前缀，队列的可用环认索引，都是认标记推进；鼠标的包头同步，队列的可用标志，都是对齐了再动手。读队列之前，建议重温本篇的门禁思想：队列的踢与中断抑制是同一类门（什么时候值得打扰对方）。
