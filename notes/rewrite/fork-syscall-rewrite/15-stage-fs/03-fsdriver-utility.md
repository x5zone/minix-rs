## 1. 概念：跨越边界的四样工具

### 1.0 章节引言

目标读者是跟完前两篇的读者：知道请求按编号分发，知道适配器先检查再调用。前置知识只需要一条：用户态进程各有各的内存，一个进程不能直接读写另一个进程的内存，跨进程拿数据必须经过内核允许的通道。

本章的四个工具解决四个问题：字节怎么搬（数据通道），名字怎么验（名字获取），目录列表怎么装（目录项编码器），长路径怎么走（查找漫步）。四个工具彼此独立，但有一个共同主题：**调用者给的东西一律先验后用**。

### 1.1 数据通道：两种门后的同一条走廊

文件服务器经常要读写调用者的内存：把读到的数据送过去，把要写的数据取过来，把文件空洞对应的区域清零。调用者的缓冲有两种形态：远端授权（调用者把自家内存的一块区域授权给服务器碰），本地指针（服务器操作自己的内存，比如解析符号链接时的临时缓冲）。

C 代码在这两条路上用分支区分：端点是自己就直接内存复制，否则走授权内核调用。Rust 把分支变成类型：数据通道枚举有两个变体（缺席与在场），在场时携带一个传输后端 trait。生产用授权后端，测试用内存后端，符号链接解析用本地缓冲后端。三处调用点（复制进、复制出、清零）的形状完全一致：先验边界，再按变体行事。

缺席变体对应窥视请求：窥视不经过调用者缓冲，三个操作全部静默成功。这个"什么都不做但报告成功"的语义是故意的：服务器代码不需要为窥视写分支，同一套读写逻辑直通。

### 1.2 边界检查：走廊的护栏

每个搬运操作都检查偏移加长度不超过声明的总长度。这个检查是完整性护栏：声明长度是调用者承诺的缓冲大小，超了就是越界。检查用带进位判断的加法，防止恶意偏移回绕骗过检查（偏移取最大值加一，回绕成零，不设防的检查会放行）。

护栏的错误码是无效参数。注意 C 代码在这里用的是宕机（断言越界即崩溃），Rust 改成返回错误。这个改动是深思熟虑的，理由在第 3 章。

### 1.3 名字获取：四道关卡

名字是调用者递进来的字节，变成可用字符串要过四道关卡：长度零一律拒绝；要求非空时长度一（只有结束零）也拒绝；长度超过输出缓冲报名字过长；复制进来后末字节必须是零，否则报无效参数。

长度含结束零这个约定是第一道关卡存在的原因：调用者报的长度是"含零的总字节"，服务器按这个约定检查。查找路径的名字可以空（空路径另有含义），其他位置的名字必须非空，调用方用一个布尔参数区分这两种场景。

### 1.4 目录项编码器：先在 staging 区摆盘再上桌

读目录操作一次返回很多条目，每条含节点号、记录长度、名字长度、类型、名字。直接一条一条写给调用者，每次都要经过内核调用，太贵。于是框架用 staging 区：服务器的小缓冲，先把条目摆进去，摆满了就整体搬给调用者，清空继续摆，最后把尾巴搬完，报告总字节数。

编码器有三种回答：摆进去了（返回记录长度），摆不下了但之前摆过东西（返回零，调用者知道列表到此为止），第一条就摆不下（报无效参数——调用者给的容量连一条都装不下，一定是调用者算错了）。名字过长在 Rust 侧是类型化错误（C 侧是宕机，见第 3 章）。

记录格式有个细节：名字后必须补零到对齐边界，末尾的填充字节全部清零。这是为了不把服务器内存的残留泄漏给调用者。安全不在远方，就在这种填充字节里。

### 1.5 路径查找：一步一查的漫步

虚拟文件系统服务一次发来整条路径，框架一次只走一步：取下一个分量，问服务器这个分量是谁，拿到新节点，继续。走的过程中处理四种岔路：点（原地踏步）、点点（向上走，有 as 根与文件系统根的特殊处理）、挂载点（停下，把路权交给另一个文件服务器）、符号链接（读出目标，拼上没走完的尾巴，重走；绝对路径的链接把改写后的路径交还给虚拟文件系统服务）。

权限检查编织在每一步：经过的每个中间节点都必须是目录，且调用者必须有搜索权限。超级用户跳过检查，属主、属组（含附加组）、其他人各看自己的执行位。这是文件系统安全的第一道门：没有搜索权限的目录，里面的名字一个都看不见。

符号链接的深度计数器防循环：链接套链接超过八层就报循环错误。绝对路径链接交还上游，是因为绝对路径的起点是全局根，只有虚拟文件系统服务知道全局根在哪里，文件服务器只认识自己的地盘。

### 1.6 引用计数：借一本还一本

查找过程中每拿到一个节点，就欠一次释放：从旧节点挪到新节点时释放旧节点，失败时释放当前节点，成功时最终节点留给调用者（调用者以后用释放节点请求归还）。这个"借还平衡"是 C 代码里最容易漏的地方，Rust 实现把每次释放都写在返回之前，测试用释放记录清单验证"走过的都还了，拿到的没还"。

### 1.7 本章小结

四个工具：通道搬字节（先验边界），名字过四关，目录项摆盘再上（填充清零防泄漏），路径一步一查（权限、挂载、链接、借还平衡）。下一章进入 C 源码验证每个细节。

## 2. C 源码分析

### 2.1 复制三姐妹 `fsdriver_copyin`、`fsdriver_copyout`、`fsdriver_zero`（`utility.c:4-78`）

复制进 `fsdriver_copyin`（`utility.c:7-28`）、复制出 `fsdriver_copyout`（`utility.c:33-54`）、清零 `fsdriver_zero`（`utility.c:59-78`）结构完全相同：通道空指针直接成功返回；偏移加长度超总长度则宕机；端点是自己则内存操作，否则调对应的授权内核调用（取、送、置零）。

三个函数的注释都写了同一句话：数据长度字段只用于这个完整性检查。也就是说总长度字段平时没人读，它的存在就是为了这三处检查。这是防御性设计的典型：多带一个字段，只为检查。

### 2.2 名字获取 `fsdriver_getname`（`utility.c:83-105`）

按顺序四步：长度零或（要求非空时的）长度一，报无效参数；长度超输出缓冲，报名字过长；授权复制；末字节非零则打印一行日志并报无效参数。注意长度一的判断只在要求非空时生效：查找路径允许空名字（空路径表示当前目录），其他路径不允许。

### 2.3 目录项三件套 `fsdriver_dentry_init`、`fsdriver_dentry_add`、`fsdriver_dentry_finish`（`dentry.c:1-99`）

初始化 `fsdriver_dentry_init`（`dentry.c:9-20`）记下通道、总容量、已刷字节（零）、staging 缓冲区与大小、已摆字节（零）。添加 `fsdriver_dentry_add`（`dentry.c:27-79`）步骤：名字超长宕机；算记录长度（名字偏移加名字长度加一再对齐）；总容量装不下且之前什么都没装，报无效参数；总容量装不下但装过，返回零；staging 区装不下但 staging 为空，宕机（调用者给的 staging 连一条都装不下）；staging 区装不下但有货，先刷 staging 再摆；填节点号、记录长度、名字长度、类型、名字；名字后补零到记录末尾；已摆计数推进，返回记录长度。收尾 `fsdriver_dentry_finish`（`dentry.c:85-99`）把 staging 余货刷完，返回总字节数。

记录长度宏（`sys/sys/dirent.h:105-107`）：名字偏移加名字长度加一（结束零），再按对齐向上取整。对齐值是节点号大小减一（`dirent.h:88`），节点号八字节所以按八字节对齐。名字偏移是十三（八字节节点号加两字节记录长度加两字节名字长度加一字节类型，`dirent.h:94-99`）。

### 2.4 查找：权限 `access_as_dir`、切分 `next_name`、解链接 `resolve_link`（`lookup.c:1-112`）

目录搜索检查 `access_as_dir`（`lookup.c:8-37`）：不是目录报非目录；超级用户直接过；属主看属主执行位，属组（含附加组遍历）看属组执行位，其他人看其他执行位；没位报拒绝访问。

取下一分量 `next_name`（`lookup.c:43-76`）：跳过前导斜杠；复制到斜杠或结尾，超长报名字过长；空剩余得当前目录标记。返回指针指向分量后的第一个字符（通常是斜杠或结束零）。

解链接 `resolve_link`（`lookup.c:83-112`）：本地数据通道指向路径缓冲，调服务器的读链接回调（结果不保证结尾零），拼上没走完的尾巴，超长报错，拷回原缓冲。

### 2.5 查找主循环 `fsdriver_lookup`（`lookup.c:117-333`）

取请求六件套：起始目录、进程根、路径授权、路径容量、路径长度、标志（`lookup.c:134-139`）。取路径名字（允许空，`lookup.c:142-144`）。取凭证：置了凭证标志就校验结构大小并授权复制（`lookup.c:147-157`），否则只用用户标识与组标识（`lookup.c:158-162`）。

起点获取：用当前目录标记调一次服务器查找，同时知道起点是不是挂载点（`lookup.c:167-169`）。主循环每轮：取下一分量；挂载点起点要求分量必须是点点（`lookup.c:182-192`），否则报无效参数；非挂载点做目录搜索检查（`lookup.c:198-200`）；点跳过；点点在进程根原地踏步（`lookup.c:216-217`），在文件系统根则回指针并报离开挂载点（`lookup.c:224-229`）；调服务器单步查找（`lookup.c:238-240`）；向上走进非目录则宕机（`lookup.c:243-244`）；符号链接按规则解（计数超八报循环，`lookup.c:256-260`），绝对路径交还（`lookup.c:270-274`）；释放旧节点（`lookup.c:280-281`）；新节点是挂载点则报进入挂载点（`lookup.c:289-292`）。

收尾三岔（`lookup.c:296-316`）：三个重定向码需要回额外信息（偏移、链接计数，符号链接还要拷回改写后的路径）；成功填节点六字段；失败释放当前节点（`lookup.c:329-330`）。

### 2.6 与 Rust 实现的步骤差异说明

| 差异 | C 做法 | Rust 做法 | 分类 |
|------|--------|-----------|------|
| 越界处理 | 三个复制函数宕机 | 返回无效参数 | 设计决策：库不崩服务器，见第 3.2 节 |
| 名字超长（目录项） | 宕机 | 报名字过长 | 设计决策：同上 |
| staging 过小 | 宕机 | 报无效参数 | 设计决策：同上 |
| 上行非目录 | 宕机 | 报无效参数 | 设计决策：服务器实现糊涂时保命 |
| 读链接失败的清理 | 释放链接节点与当前节点后跳出 | 同样释放两个节点后返回 | 无差异 |

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 传输后端做成 trait（依据：第 1.1 节、第 2.1 节）

C 用端点分支区分本地与远端。Rust 用 `DataBackend` trait：复制进、复制出、清零三个方法。内存后端是生产代码（符号链接解析与窥视模拟走本地缓冲），不是测试替身；测试复用它，外加故障注入开关（固定失败码）。

替代方案是枚举两种形态（本地切片与远端授权标识）。那样生产必须实现授权内核调用才能编译，而授权调用属于服务进程层，不属于框架。trait 把"怎么碰调用者内存"的知识推迟到服务进程，框架只管"碰之前先验边界"。

### 3.2 宕机改返回错误（依据：第 1.2 节、第 2.6 节）

C 的四处宕机（三次越界、一次名字超长、一次 staging 过小、一次上行非目录）在 Rust 里全部变成错误返回。理由：框架是库，库崩掉整个服务器进程是最坏的选择；调用者（虚拟文件系统服务）本来就能处理错误码，返回错误码是协议内的正常沟通，宕机是掀桌子。

有人会问：越界是不是说明服务器有漏洞，崩了反而安全？答案是错误码同样阻止了越界（数据没搬），区别只是服务器活着还是死了。活着的服务器可以继续服务其他请求，死了的服务器要整个重启，重启期间所有挂载它的应用都卡住。可用性也是安全的一部分。

### 3.3 记录长度逐字对照（依据：第 2.3 节）

记录长度函数是 C 宏的逐字翻译：名字偏移（十三）加名字长度加一（结束零）加对齐减一，按位取反掩码对齐。对齐值八来自八字节节点号，注释写明推导链（类型头文件行号、宏行号），将来节点号变了，对齐值跟着变，不会静默错位。

### 3.4 查找分两相（依据：第 1.5 节、第 2.5 节）

Rust 的查找循环分成只读的解析相与行动相：解析相从工作缓冲读出分量位置、是否上行、是否末尾、尾巴起点，然后借用结束；行动相按解析结果调服务器、改缓冲。两相之间只传偏移数字，不传借用。这个结构是被借用检查器逼出来的，但结果比 C 更清晰：C 的指针在循环里既读又写，Rust 强迫把读与写分开，反而让"哪一步在读、哪一步在写"一目了然。

### 3.5 引用释放写在每个返回之前（依据：第 1.6 节、第 2.5 节）

五个释放点：挂载点违规、搜索失败、单步失败、上行非目录、链接读失败，外加成功路径的旧节点释放与最终保留。每个返回错误的分支先释放再返回，测试用释放记录清单锁定"走过的都还了"。这是把 C 末尾的统一清理（成功留、失败放）展开成显式释放，啰嗦但不会漏。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 后端用 trait | 第 1.1 节 | 枚举本地与远端 | 授权调用属服务进程层，框架不应依赖 |
| 宕机改错误 | 第 1.2 节 | 保留宕机 | 库崩进程是最坏选择，错误码同样阻止越界 |
| 记录长度逐字译 | 第 2.3 节 | 简化公式 | 对齐推导链必须留痕，否则静默错位 |
| 查找分两相 | 第 2.5 节 | 单循环指针 | 借用检查器不允许；分开后读写更清晰 |
| 释放显式化 | 第 1.6 节 | 统一清理 | 分支多，统一清理易漏，显式释放可测 |

## 4. Rust 实现详解

### 4.1 数据通道（`os/libs/minix-fs/src/data.rs`）

`DataBackend` trait 三个方法，`DataChannel` 枚举两个变体（缺席、在场）。边界检查用带进位判断的加法，注释写明防回绕。三个搬运方法先检查再按变体行事，缺席直接成功。名字获取按 C 的四步实现，返回去零后的长度。内存后端是公开生产代码，故障注入字段供测试。

### 4.2 目录项编码器（`os/libs/minix-fs/src/dentry.rs`）

`DirentType` 枚举七个具名类型加兜底（未知值归其他）。`DentryError` 三个变体各有错误码映射。记录长度与名字偏移是公开常量。编码器结构五个字段与 C 结构一一对应，staging 缓冲区从调用方借（服务器多大就借多大，不用堆）。添加方法按 C 的分支顺序实现，填充清零覆盖名字结束零之后到记录末尾的全部字节。收尾方法消费自身（列表结束后编码器无用，消费掉防止复用）。

### 4.3 路径查找（`os/libs/minix-fs/src/lookup.rs`）

凭证结构固定十六个附加组槽位加有效计数（与 C 数组对应，避免变长分配）。搜索检查按 C 的四步实现，附加组成员判断是独立方法。分量切分处理前导斜杠、空剩余、超长三条。查找结果枚举四个变体：找到、进入挂载点、离开挂载点、绝对符号链接；绝对符号链接的路径装箱（枚举常见变体保持小体积，罕见大变体走堆）。

主循环两相机的落点：解析相用内部动作枚举（完成、原地、违规、搜索失败、单步），行动相匹配执行。偏移语义的微差在注释与第 2.6 节差异表中如实记录：进入挂载点与 C 一致（分量末尾），离开与绝对链接指向分量开头（含前导斜杠），C 指向分量开头（不含斜杠）。虚拟文件系统服务只用偏移配路径拷回，斜杠之差不影响正确性，文档注明以便将来对齐。

### 4.4 内存文件服务器（`os/libs/minix-fs/src/memfs.rs`，第 01 到 03 篇共用例证）

内存服务器是框架的完整例证：目录树、文件字节、符号链接全在内存里，命名空间、数据、元数操作全实现，只有块操作未实现（没有设备）。读目录操作内部复用目录项编码器（staging 本地缓冲，走完编码再一次性交付），证明编码器可被真实服务器使用。改名失败回滚（删了旧名但新目录非法时把旧名种回去），删目录拒绝时恢复名字——"拒绝不能丢数据"是贯穿实现的原则。

## 6. 过渡：从行走到存盘

本篇的四个工具让服务器能搬运字节、验证名字、列出目录、走完路径。但所有数据还在内存里打转：读上来的块没有地方放，写下去的块没有地方攒，重复读同一块每次都要碰存储。

下一篇 `04-block-cache.md` 讲块缓存：哈希索引加最近最少使用淘汰加引用计数 pin 住的三件套，脏块写回，预读，二级缓存挂钩，容量启发式。读完下一篇，框架层（第 01 到 05 篇）的前四块就齐了，只剩块输入输出（第 05 篇）把缓存与驱动连起来。

阅读建议：先读哈希与淘汰（缓存的心脏），再读脏块与刷盘（正确性的命门），预读与启发式可以后读。
