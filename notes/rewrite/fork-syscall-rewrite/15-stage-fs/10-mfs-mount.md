## 1. 概念：开店、打烊与门口挂牌

### 1.0 章节引言

目标读者是跟完第 09 篇的读者：手里有超级块解析、位图、索引节点表。前置知识只需要一条：挂载是把存储设备接到目录树上的动作。

本章三个概念：开店（挂载七步）、打烊（卸载六步）、门口挂牌（挂载点检查）。外加一节设计优选：实现前比较了三种挂载形态，为什么选中"一个值拥有全部"。

### 1.1 开店七步

挂载分七步，顺序即依赖：记住设备、读身份证（不行就散伙，设备号复位）、脏盘降级（读写变只读，体面比性能重要）、认块大小（缓存与镜像必须一致）、数已用区（给缓存启发式交数）、领根节点（没有根或根是空壳就散伙）、脏标记落盘（读写挂载把干净位清掉，崩溃后后来者知道）。

散伙有个讲究：每一步失败都要把前面占的收拾干净（设备复位），不能留半挂载状态。这是"构造要么全成、要么全无"的原子性，不彻底的一半比失败更糟。

### 1.2 脏盘降级：体面比性能重要

镜像说上次没干净卸载，而调用者要求读写挂载，服务器不硬上：自动降成只读，并记下"降过级"。只读挂载不写盘，不会扩大不一致，检查工具以后慢慢修。性能让路给安全，这是文件系统的第一美德。

降级要记录：卸载报告里写不写干净位，取决于最初是不是只读——降级来的只读同样不写（它本来就是脏的，写干净等于撒谎）。

### 1.3 打烊六步

卸载分六步：数在用引用（根被引用一次是干净，多了就嚷嚷但不停）、放根（根丢了是内存 corrupt，停）、调同步（注入的回调，刷脏）、读写则标干净落盘、作废设备缓存、设备号复位。嚷嚷不停是原则：卸载必须成功，虚拟文件系统服务指着它继续流程；问题记下来，不拦路。

### 1.4 门口挂牌：三问

挂载点检查三问：号在吗（打开，失败报无效），挂过牌吗（挂过报忙），是设备节点吗（块字符报非目录）。三问全过才挂牌（置标记）。打开的槽位每条路都释放——检查函数借来即还，不留引用。

### 1.5 设计优选：三种挂载形态的比较

实现前比较了三种形态。

形态一：全局静态（C 原样）。设备号、超级块、表全是全局。优点是与 C 逐行对应，缺点是测试互斥（两个挂载互相踩），多挂载无路，多线程无路。否决：测试是正确性的命脉，互斥测试等于半盲。

形态二：各部件分散参数传递（挂载函数取缓存、表、超级块一堆参数，每个调用点传一遍）。优点是无全局，缺点是参数表爆炸（七八个参数起步），调用者拼参数比干活还累，且"同一挂载的部件"关系只存在于程序员脑子里，类型看不见。否决：关系应该写进类型，不是写进记忆。

形态三：一个值拥有全部（选中）。`MountedFs` 值装设备号、超级块、缓存、表、读写态、降级标记、根槽位。优点有三：测试可建两个挂载并行跑；部件关系类型可见（值的方法只能碰自己的部件）；生命周期清晰（值 Drop 即散伙，无需复位函数）。

对照 Linux：超级块对象（`struct super_block`）也是一值装全部（设备、标志、根目录项、文件系统私有数据），挂载即实例化超级块对象。选中形态与 Linux 同构，差异只在语言表达。

对照 Redox：挂载是命名空间里的一句柄，获取与释放成对，句柄失效后操作全拒。选中形态的 `mount` 返回值加 `unmount` 消费值（`unmount` 取走所有权）正是句柄语义：用完的值不存在了，误用编译不过。

对照操作系统理论：这是资源获取即初始化（构造成功即就绪，失败即无残留）加会话类型（挂载会话的状态机由类型保证：未挂载的值构造不出来）。理论、Linux、Redox 三方会师，形态三全票当选。

### 1.6 本章小结

开店七步散伙干净，脏盘降级记录在案，打烊六步嚷嚷不停，挂牌三问借还配对，形态三（值拥有全部）经三方对照当选。下一章进入 C 源码验证。

## 2. C 源码分析

### 2.1 挂载 `fs_mount`（`mount.c:10-98`）

记设备、读只读标志（`mount.c:19-20`）。打开设备（读写或只读，失败报无效参数，`mount.c:23-26`）。填设备号读超级块（`mount.c:29-30`），失败则复位设备号、关设备、报原因（`mount.c:33-37`）。脏加读写则关设备、重开只读、警告（`mount.c:40-50`，重开失败宕机）。认块大小（`mount.c:52`）。数已用区交缓存（`mount.c:58-60`，注释写明区即块）。领根节点（`mount.c:63-68`，失败复位关设备报无效参数）。根零模式则放根复位关设备报无效参数（`mount.c:70-76`）。记只读（`mount.c:78`）。填根六字段（设备号填空，`mount.c:81-86`）。能力无标志（`mount.c:88`）。读写则清干净位写回（失败宕机，`mount.c:91-95`）。返回读超级块的结果（成功即成功，`mount.c:97`）。

### 2.2 挂载点 `fs_mountpt`（`mount.c:104-128`）

临时打开（`mount.c:114-115`，失败报无效参数）。已挂牌报忙（`mount.c:117`）。块字符报非目录（`mount.c:119-121`，类型掩码判断）。放回（`mount.c:123`）。成功则挂牌（`mount.c:125`），返回结果。

### 2.3 卸载 `fs_unmount`（`mount.c:134-172`）

数在用引用（`mount.c:144-148`，非一则打印）。找根（找不到宕机，`mount.c:150-151`）。放根（`mount.c:153`）。同步（`mount.c:156`）。读写则标干净写回（`mount.c:159-162`）。关设备（`mount.c:165`）。作废缓存（`mount.c:168`，注释写明防 virtual memory 缓存 corrupt）。设备号复位（`mount.c:171`）。

### 2.4 与 Rust 实现的步骤差异说明

| 差异 | C 做法 | Rust 做法 | 分类 |
|------|--------|-----------|------|
| 设备打开关闭 | 打开读写或只读、关闭 | 跳过（内存盘不需要，驱动阶段接） | 已知缺口：归属明确 |
| 重开只读 | 关了重开 | 直接降级标记 | 设计决策：无驱动可重开，标记等价 |
| 失败宕机四处 | 重开失败、写回失败、根丢失 | 报错误（根丢失报 corrupt） | 设计决策：库不崩 |
| 全局状态 | 三全局 | 值拥有全部 | 架构演进：见第 1.5 节 |
| 打印警告 | 忙打印、脏打印 | 报告计数、降级标记 | 设计决策：库不打印 |
| 位数统计函数 | `stats.c`（第 17 篇） | 挂载本地实现，第 17 篇 canonicalize | 已知缺口：单定义加前向声明 |

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 值拥有全部（依据：第 1.5 节）

三方对照（理论、Linux、Redox）全票。`unmount` 取走所有权：用完的值不存在，误用编译不过，这是会话类型最廉价的实现。

### 3.2 错误细分（依据：第 2.1 节散伙点）

六错误变体：超级块（内因透传）、内部错误（透传）、根丢失、根空壳、块大小不对、挂载点忙或非目录。每个散伙点对号入座，调用者知道哪步散的伙。C 用打印加统一码区分，Rust 用变体区分。

### 3.3 降级记录（依据：第 1.2 节）

降级标记存在值里，卸载报告可查。C 用打印记录降级（重启后无处查），Rust 用字段记录（值在标记就在）。信息从日志搬进类型，与第 08 篇错误变体同一思想。

### 3.4 位数统计本地实现（依据：第 2.1 节、第 2.4 节）

挂载要用的区用量现在就要，第 17 篇的 canonical 版本还没到。本地实现一遍，第 17 篇到来时 canonicalize（复用或替换，届时以第 17 篇为准，本篇注明）。替代方案是挂载跳过用量统计：缓存启发式缺输入，退化成固定池——功能可用但性能语义丢了。不跳过，本地实现加前向声明。

### 3.5 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 值拥有 | 第 1.5 节 | 全局静态、散参数 | 测试互斥、关系不可见 |
| 错误细分 | 第 2.1 节 | 统一无效 | 散伙点不可区分 |
| 降级记录 | 第 1.2 节 | 打印了事 | 重启后无处查 |
| 统计本地 | 第 2.1 节 | 跳过统计 | 启发式缺输入 |

## 4. Rust 实现详解

### 4.1 类型与挂载（`os/fs/mfs/src/mount.rs` 前三百行）

错误六变体加错误码映射（三透传三定值）。挂载值七字段（设备、超级块、缓存、表、读写、降级、根槽位）加六个访问器。挂载七步按 C 顺序：建池、读零号块解析、脏降级、块大小认领、用量统计、领根验空壳、脏标记落盘。根描述六字段（设备填空）。散伙无残留（返回值，无半值）。

### 4.2 统计、写回、卸载、挂载点（`mount.rs` 后段）

位数统计（位图区定位、逐字数空位、界内裁剪）。超级块写回（守卫、重建十三字段、偏移拷贝、标脏刷盘）。卸载六步（计数、找根放根、同步回调、标干净写回、作废、报告）。挂载点三问（打开、判断、释放、挂牌）。区空间视图（超级块三字段子集）。

### 4.3 接线表翻通（`os/fs/mfs/src/table.rs` 增量）

状态加第三变体（本 crate 已通），挂载三行翻通，存活计数五变八，待建二十六变二十三。第 07 篇文档同步（八通二十三待）。
