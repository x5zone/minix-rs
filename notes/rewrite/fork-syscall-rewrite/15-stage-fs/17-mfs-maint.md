## 1. 概念：落盘顺序、数空位与脏标记的红线

### 1.0 章节引言

目标读者是跟完数据与元数据两组的读者：已经知道索引节点如何写回单个，也知道卷状态需要空闲数。前置知识只需要一条：内存比磁盘快，所以修改先攒在内存里，攒脏了才批量写回，批量写回时顺序决定正确性。

本章建立维护面的心智模型。维护面做三件事：同步时按先索引节点后数据块的顺序刷脏，统计时按位图实际内容数空位而不越界，标记时在只读盘上划红线。三件事都不碰文件内容，只保证持久状态的完整与可查。

### 1.1 同步顺序：先索引节点，后数据块

同步的意思是把内存里全部脏东西写回磁盘。脏东西有两类：脏索引节点，脏数据块。原始实现规定先刷全部脏索引节点，再刷全部脏块，注释写明顺序至关重要，原因是写回索引节点会把结果留在块缓存里面。

这句话值得展开。索引节点的写回是把内存结构编码进索引节点区所在的缓存块，编码完块变脏了。如果先刷数据块再刷索引节点，索引节点编码产生的新脏块就没人管了，同步结束磁盘上躺着旧索引节点，崩溃后文件长度与块指向对不上。先刷索引节点再刷数据块，编码产生的新脏块被后面的整缓存刷盘带走，落盘顺序与依赖顺序一致，任何时刻崩溃，磁盘上的索引节点与数据块互相印证。

对照 Linux：Linux 的同步同样分索引节点回写与块设备刷盘两阶段，块设备刷盘在后，理由相同。对照 Redox：Redox 的方案同步是句柄刷盘语义，顺序由底层驱动保证，思想同构。

### 1.2 数空位：按图索骥，不数到图外

空闲统计的意思是数位图里面有多少个零位。位图分两种：索引节点位图，存储区位图。两种位图的起点、总位数、块数各不相同：索引节点位图从第二块开始，总位数是索引节点数加一（含零号保留位），块数是超级块记录的索引节点位图块数；存储区位图紧跟其后，总位数是存储区总数减去数据区起点再加一，块数是超级块记录的存储区位图块数。

数的过程从搜索提示位开始，绕位图一整圈，每个机器字先整体判断全一则跳过，否则逐位检查。逐位时算全局位号，位号超出总位数就停，不数图外的填充位。图外的填充位恒零，不停就会把填充当空闲，空闲数虚大，卷状态撒谎。搜索提示位越界时归零，这是鲁棒性处理：提示位是优化用的，错了只影响起点，不影响总数。

字节序细节：位图字从磁盘读上来要按本机是否同序转换，第 16 篇的转换函数在这里被调用。转换错了零一位错位，数的全错。所以数空位的正确性依赖字节序转换的正确性，两篇在此衔接。

### 1.3 脏标记红线：只读盘上不许有脏东西

脏标记宏的意思是给缓存块标脏之前先看挂载是否只读。读写挂载直接标脏，只读挂载打印文件名行号并输出调用栈。只读盘上出现脏标记是逻辑错误：只读意味着从挂载起就不该有任何写，走到标脏这一步说明前面的只读检查漏了，大声嚷出来是为了让开发者找到漏检的位置。

索引节点篇的标脏宏是同一思想在索引节点上的应用：标脏在只读盘上打印加堆栈。本篇的宏管块，那篇的宏管索引节点，两处红线互相补充，读写路径上的任何漏检都会触发其中一处。

库不打印原则在这里同样适用：原始实现用打印加堆栈，Rust 实现用返回值。守卫函数在只读时报告只读错误，调用方把错误转成自己的诊断。信息从标准输出搬进类型，与第 10 篇降级标记同一思想。

### 1.4 常量目录：六十八行头文件的权威位置

常量头文件定义五组常量。表大小组：直接区数七，总区数十，内存表五百一十二槽，哈希一百二十八桶。魔数组：第一版、第二版、第三版及其字节序反转版，版本号二与三。目录操作组：查找、进入、删除、查空四个模式。写映射组：释放标志一位。脏与时间组：干净、脏、访问、状态变化、数据修改五标记。位置组：根号一，引导块零，超级块偏移一千零二十四，文件系统起点第二块。派生尺寸组：目录项大小、每块目录项数、每块位图字数、每块位数、间接块容量、每块索引节点数。

每组常量的权威 Rust 位置在本篇统一登记：魔数、版本、位置、派生尺寸归超级块篇，表大小与哈希归索引节点篇，目录操作模式归目录篇，脏与时间标记归索引节点篇，释放标志归写路径篇。本篇不重复定义任何常量，重复定义是跨模块漂移的源头，第 16 篇的权威位置检查已经讲过这个教训。

### 1.5 全局状态：五个名字的去向

全局头文件声明五个名字：临时错误码、校验数组、服务设备号、已用存储区数、回调表。临时错误码在 Rust 实现里面消失了，错误跟随调用返回，不需要全局暂存。校验数组是调试期核对引用计数的工具，生产关闭，文档记录即可。服务设备号收进挂载值里面，第 10 篇的值拥有全部已经覆盖。已用存储区数收进区空间视图，挂载时统计，分配释放时维护。回调表收进接线表常量数组，第 07 篇已经覆盖。五个名字个个有归宿，没有悬空的全局，这是重写对全局状态的交代。

### 1.6 本章小结

维护面三件事：同步先索引节点后数据块，因为写回会留结果在缓存里；数空位按图索骥不越界，填充位不数，提示位越界归零；只读盘上标脏是逻辑错误，库用返回值代替打印。常量不重复定义，只登记权威位置。全局五个名字个个有归宿。下一章进入原始代码验证，逐个函数核对行号和行为。

## 2. 原始代码分析

### 2.1 同步 `fs_sync`（`misc.c:8-23`）

遍历全部五百一十二个内存槽位（`misc.c:18`），引用计数为正且脏就写回（`misc.c:19`）。引用计数为零的槽位跳过：没人用的槽位即使脏也是旧主人的残留，释放时已经处理过。全部写完刷整缓存（`misc.c:22`），顺序即第 1.1 节的契约。

### 2.2 空闲统计 `count_free_bits`（`stats.c:13-89`）

断言超级块非空（`stats.c:30`）。按位图种类取起点、总位数、块数、搜索起点（`stats.c:32-42`）。搜索起点越界归零（`stats.c:45`）。算起始块与块内字号（`stats.c:49-50`）。循环块数次，每次拿块（`stats.c:54-55`），逐字跳全一（`stats.c:63`），转换字节序（`stats.c:65`），逐位算全局位号（`stats.c:69-71`），超总位数停（`stats.c:74-76`），零位计数（`stats.c:77-79`），超界跳出本块（`stats.c:82`）。放回块，下一块，字号清零（`stats.c:84-86`）。返回总数（`stats.c:88`）。

函数名与注释不符：注释写分配一位并返回位号，实际是数空位总数。这是注释年久失修，行为以代码为准，文档在这里写明，避免读者被注释误导。

### 2.3 脏标记宏（`clean.h:5-12`）

只读打印文件名行号并输出调用栈（`clean.h:6-8`），否则标脏（`clean.h:10`）。宏用循环包裹，保证分号语义正确，这是 C 宏的通用写法。

### 2.4 全局声明（`glo.h:10-20`）

临时错误码、校验数组、服务设备号、已用存储区数四变量加回调表声明（`glo.h:11-20`）。条件编译保证表文件是定义而其他文件是声明，这是 C 全局变量的通用组织。

### 2.5 常量表（`const.h:5-65`）

表大小（`const.h:5-15`）、名字上限（`const.h:18`）、魔数与版本（`const.h:22-29`）、位失败信号（`const.h:32`）、目录四模式（`const.h:34-37`）、释放标志（`const.h:40`）、脏与时间五标记（`const.h:42-46`）、位置四常量（`const.h:48-51`）、派生尺寸（`const.h:53-59`）、磁盘区与索引节点尺寸（`const.h:62-65`）。

### 2.6 与 Rust 实现的步骤差异说明

| 差异 | 原始做法 | Rust 做法 | 分类 |
|------|----------|-----------|------|
| 错误传递 | 无错误码（同步无失败，统计断言） | 函数返回值 | 设计决策：错误跟随调用返回 |
| 拿块失败 | 断言块非空 | 返回输入输出错误 | 设计决策：库不崩进程 |
| 只读标脏 | 打印加堆栈 | 报告只读错误 | 设计决策：库不打印 |
| 统计存储 | 边读边数 | 调用方供位图镜像，纯计数 | 设计决策：判断与存储分离 |
| 全局变量 | 五个全局 | 值与参数，无全局 | 架构演进：值拥有全部 |
| 注释失修 | 数空位注释写分配 | 文档写明以代码为准 | 文档决策：注释不算依据 |

## 3. Rust 设计决策

> 每个决策先给出依据，再给出替代方案与取舍。对照 Linux 与 Redox 的同类设计。

### 3.1 同步执行器闭包注入：顺序在篇内，机制在实现方（依据：第 1.1 节、第 2.1 节）

同步函数取脏索引节点号清单与两个执行闭包：按号写回单个索引节点，刷整块缓存。顺序硬编码先清单后刷盘，调用方不能调换。替代方案是同步函数直调索引节点表与块缓存：同步篇依赖两大模块，测试要搭整套存储。闭包注入后测试用数组替身记录顺序，三行覆盖全部顺序语义。

对照 Linux：Linux 的同步回调同样是上层定顺序、下层给出接口，顺序写在调用方。两者同构。

### 3.2 失败停住并上报已做工作量（依据：第 2.1 节）

原始同步没有失败概念，Rust 执行闭包可能失败。第一个失败停住整趟，已写回的计数保留在报告里面。替代方案是失败跳过继续：坏块后面的好块继续刷，成功率更高。选择停住的理由是同步的调用场景是关机与信号处理，失败意味着存储已经不可信，继续刷可能扩大不一致，停住并上报让上层决定，比闷头继续诚实。

### 3.3 统计纯计数不碰存储（依据：第 1.2 节、第 2.2 节）

空闲统计取位图镜像字节片与总位数，纯计数返回。拿块、字节序转换、起点定位都在调用方。替代方案是统计函数直调缓存拿块：统计篇依赖缓存与超级块，位图起点换算重复一份。纯计数让第 16 篇的卷状态与挂载时的用量统计共用同一函数，一处实现两处调用。

### 3.4 脏标记守卫返回错误（依据：第 1.3 节、第 2.3 节）

守卫是常量函数：只读报告只读错误，否则成功。调用方在标脏前调用，失败不标。替代方案是保留打印：库在服务器进程里面打印，日志归属混乱，测试无法断言。返回值让测试锁定只读拒绝。

### 3.5 常量零重复（依据：第 1.4 节）

本篇不定义任何常量，只登记权威位置。替代方案是本篇复刻一份常量方便引用：两份常量值迟早漂移，漂移后编译器不报错，测试不覆盖，错误静默。零重复是跨模块常量的唯一安全策略。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 执行闭包注入 | 第 1.1 节 | 直调表与缓存 | 测试要搭整套存储 |
| 失败停住上报 | 第 2.1 节 | 跳过继续 | 存储不可信时继续扩大不一致 |
| 统计纯计数 | 第 1.2 节 | 直调缓存拿块 | 换算重复，调用方已备好镜像 |
| 守卫返回错误 | 第 1.3 节 | 保留打印 | 库不打印，测试可断言 |
| 常量零重复 | 第 1.4 节 | 复刻一份 | 静默漂移，无人发现 |

## 4. Rust 实现详解

### 4.1 同步执行（`os/fs/mfs/src/maint.rs` 同步小节）

报告结构两字段：已写回数，块刷盘标记。同步函数遍历清单逐个调写回闭包，失败透传，已写回数停在失败处。清单为空也调刷盘闭包，空清单不代表块缓存干净。刷盘成功置标记并返回报告。

### 4.2 空闲统计与脏守卫（`os/fs/mfs/src/maint.rs` 统计小节）

空闲统计逐字节逐位，位号到达总位数立即返回，短镜像只贡献持有位，总位数零直接返回零。脏守卫是常量函数，只读错否则对。错误枚举三变体加错误码映射。

## 5. 测试

### 5.1 同步测试（三个）

顺序锁定：两脏号加刷盘，记录顺序是两号在前、刷盘标记在后，报告计数二。空清单仍刷盘：无脏号也调刷盘，报告计数零。失败停住：第二个写回失败，刷盘没跑，错误透传。

### 5.2 统计与守卫测试（三个）

填充裁剪：两字节全零配十位总数只数十。置位扣除：全一字节零空闲，低两位 置位扣二。短镜像与零总数：短镜像只贡献持有位，零总数直接零，六十五位两置位得六十三。脏守卫：读写过，只读拒绝。错误码映射：三变体对照原始错误码。
