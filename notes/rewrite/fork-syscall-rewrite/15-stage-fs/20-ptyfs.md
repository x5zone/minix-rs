## 1. 概念：数字名字、位图与标签鉴权

### 1.0 章节引言

目标读者是跟完进程篇的读者：见过框架加内容的服务，现在看直连驱动框架的服务。前置知识只需要一条：伪终端是一对主从设备，主设备在驱动里，从设备以文件的形式出现在从设备目录下，应用打开从设备文件就拿到了终端。

本章建立终端树的心智模型。服务做三件事：用位图加数组管固定个节点，数字与名字双向转换保证一一对应，控制消息先验服务标签再执行。查找枚举状态三操作读表，增删改三操作写表，读写操作不存在（终端内容走驱动，不走文件系统）。

### 1.1 固定表：三十二个节点预分配

节点数在系统配置里定死三十二个，编译期已知，数组与位图静态分配，不长不大。注释写明未来配置不再是全局定义时重写本模块，这是已知局限，文档如实记录。固定表的代价是终端数封顶，好处是无分配失败（除越界外）、无碎片、枚举上限恒定。

对照 Linux：Linux 的开发终端目录同样动态展示已分配的终端，数量上限由配置定。固定上限是终端子系统的通用做法，不是本实现的偷懒。

### 1.2 名字双向转换：数字与串一一对应

从设备名是索引的十进制串：零号节点叫零，一号叫一。转换分两向。数字到串：逐位取余倒填，零特判，缓冲装不下报名字过长。串到数字：空串拒绝，非数字拒绝，前导零拒绝（零本身除外），上溢拒绝。有效名的定义是能被正向转换生产出来的串，反向只认正向能生产的，两向互逆，没有例外。空串在原始实现里解析成零，但查找断言名字非空且先处理点，空串到不了解析，Rust 实现直接拒绝空串，行为等价且接口更诚实。

前导零拒绝的原因是规范性：零一与一是同一个索引，允许两种写法，枚举输出一种，查找认两种，同一节点两个名字，缓存与审计都麻烦。一名一节点是名字空间的基本卫生。

### 1.3 查找：只认根目录与点

查找只认根目录号，非根目录号报找不到。点回根，数字名先解析再查表，解析失败或表未分配都报找不到。查找断言名字非空，空名字是调用方 bug，不是用户错误。命中填六字段：号、模式、属主、属组、大小零、设备号，挂载标记恒否。

### 1.4 枚举：位置计数器走满三十二格

枚举位置计数器从零走：零号点，一号点点，二号起是索引，索引等于位置减二。空闲索引跳过但耗位置，满缓冲回绕，走到上限停。非根节点枚举拒绝。名字生成失败跳过（理论上不应发生，防御性跳过）。类型按模式换算，目录点点报目录，从设备报字符设备。位置到顶报输入输出错误，与框架枚举同式。

位置语义与框架枚举同构：空闲耗位置、满回绕、越顶报错。三十二格走完必停，无死循环，这是固定上限的另一个好处。

### 1.5 状态与修改：目录两链接，文件一链接

状态查询按号找记录，根返回根记录，链接数目录二文件一，三时间全填创建时间。改属主换标识清特权位，与磁盘服务器同式。改模式只换权限九位，类型位保留。根的修改落根记录，从设备的修改落数组。未知号三操作全报无效参数。

### 1.6 控制消息：先验标签，再办事，再回话

控制消息分授权与执行两半。授权看发送方服务标签：标签不是终端驱动报无效，请求码不明报未实现。执行分三种：增改存记录并记创建时间，删除清位图（幂等，空删也成功），查名渲染数字串。回话区分阻塞与异步：阻塞调用同步回，异步通知发无回执发送。回话失败打印，这是服务边界日志，不是库打印，保留在服务层。

创建必须是阻塞的，注释写明原因：驱动建完节点应用马上打开，异步建有竞态，应用打开时节点还没建好。阻塞语义把竞态关在门外，这是接口设计对并发的回答。

增改语义是存在即更新：节点已分配也存新数据，不报错。驱动重建终端复用索引，更新语义让重建不需要先删，这与进程目录的先删后建相反，原因是终端索引由驱动分配而进程号由内核分配，分配权不同，语义不同。

### 1.7 挂载与信号：拒绝当根，终止下班

挂载拒绝根挂载标记，与框架挂载同式，报根六字段，能力无标志。初始化清位图并记根创建时间。信号只响应终止，其他忽略。回调表八项：挂载、查找、枚举、状态、改属主、改模式、查卷、其他消息。无读写截断建删，终端内容不走文件系统，这是回调表最短的服务。

### 1.8 本章小结

固定表三十二，名字数字互逆，查找只认根与点，枚举三十二格耗位跳空，状态目录二文件一，控制先验标签后办事，创建阻塞防竞态，存在即更新，挂载拒根，信号只应终止。下一章进入原始代码验证，逐个函数核对行号和行为。

## 2. 原始代码分析

### 2.1 节点管理 `node.c`（`node.c:20-83`）

初始化清位图（`node.c:20-25`）。存节点（`node.c:32-44`）：越界报无内存，置位，拷贝记录，存在即更新。删节点（`node.c:51-55`）：清位，恒成功。读节点（`node.c:61-69`）：越界或未置位报空，否则交指针。取上限（`node.c:75-83`）：恒返配置数，注释写明配置够小所以不跟踪实际水位。

### 2.2 名字转换（`ptyfs.c:54-100`）

正向（`ptyfs.c:54-66`）：格式化数字，失败报无效，装不下报名字过长。注意格式化目标写错缓冲（`sizeof(name)` 套在指针参数上恒为指针大小，名字恒装下），这是原始实现的瑕疵，Rust 实现用显式 bound 重写，行为收紧。反向（`ptyfs.c:75-100`）：逐字符数字校验，前导零拒绝，上溢用乘后变小判断（无 checked 乘的年代写法），空串得零。

### 2.3 挂载查找枚举（`ptyfs.c:27-199`）

挂载（`ptyfs.c:27-47`）：根标记拒绝，填根六字段，能力无标志。查找（`ptyfs.c:107-147`）：断言非空，非根报找不到，点回根，数字解析查表，命中填六字段，挂载恒否。枚举（`ptyfs.c:152-199`）：非根报无效，初始化组装器，循环三段，空闲跳过耗位置，名失败跳过，满回绕，收尾。

### 2.4 状态修改组（`ptyfs.c:205-293`）

取记录（`ptyfs.c:205-219`）：根交根记录，号越界报空，索引换算查表。改属主（`ptyfs.c:225-239`）：取记录，换标识清特权位，报回。改模式（`ptyfs.c:246-257`）：取记录，换权限九位，报回。查状态（`ptyfs.c:263-280`）：取记录，填模式属主链接设备三时间，目录二文件一。查卷（`ptyfs.c:286-293`）：不截断标记，名字上限。

### 2.5 控制消息（`ptyfs.c:299-372`）

取发送方标签（`ptyfs.c:311-315`），失败打印返回。标签非终端驱动打印返回（`ptyfs.c:317-321`，注释写明更细的鉴权是未来工作）。增改（`ptyfs.c:327-337`）：填设备模式属主时间，存记录。删除（`ptyfs.c:339-343`）：清位。查名（`ptyfs.c:345-350`）：渲染。未知请求打印并报未实现（`ptyfs.c:352-355`）。回话（`ptyfs.c:363-371`）：阻塞同步回，异步无回执发，失败打印。

### 2.6 初始化信号与主循环（`ptyfs.c:377-434`）

初始化（`ptyfs.c:377-386`）：清位图，记根时间。信号（`ptyfs.c:391-397`）：终止下班。启动注册两回调（`ptyfs.c:403-409`）。回调表八项（`ptyfs.c:411-420`）。主函数进框架主循环（`ptyfs.c:425-434`）。

### 2.7 与 Rust 实现的步骤差异说明

| 差异 | 原始做法 | Rust 做法 | 分类 |
|------|----------|-----------|------|
| 错误传递 | 返回错误码加打印 | 函数返回值加错误枚举 | 设计决策：错误跟随调用返回 |
| 正向缓冲 | 指针大小误作缓冲大小 | 显式 bound 检查 | 修正性：原始瑕疵收紧 |
| 空串解析 | 空串得零 | 空串拒绝 | 设计决策：接口诚实（到不了的分支） |
| 上溢判断 | 乘后变小判断 | checked 乘加 | 设计决策：等价但可读 |
| 表存储 | 静态数组加位图 | 值拥有数组加位图 | 架构演进：值拥有全部 |
| 回话发送 | 服务层直发 | 授权解码与执行分离 | 设计决策：传输边界上移 |
| 越界存 | 报无内存 | 报无空间（同码） | 无差异：错误码相同 |

## 3. Rust 设计决策

> 每个决策先给出依据，再给出替代方案与取舍。对照 Linux 与 Redox 的同类设计。

### 3.1 表做成值：测试可建多个（依据：第 1.1 节、第 2.1 节）

数组加位图收成结构体值，测试建多个互不干扰。原始实现静态全局，单进程单表。替代方案是全局静态：测试互斥。值类型零成本，与框架篇同一思想。

### 3.2 正向缓冲瑕疵收紧（依据：第 2.2 节）

原始正向用指针参数的字节大小当缓冲大小，恒为指针宽度，名字恒装下，超长检查失效。Rust 实现用十二字节显式 bound（三十二位最大十位加结束零，绰绰有余），装不下报名字过长。这是修正性不对齐：行为收紧，注释与文档写明位置与原因，测试锁定十位边界与上溢。

### 3.3 空串拒绝（依据：第 1.2 节、第 2.2 节）

空串解析在原始实现得零，但查找断言非空，空串到不了。Rust 解析直接拒绝空串。替代方案是复刻得零：调用方多一个到不了的分支，测试要覆盖无意义行为。拒绝让接口诚实：无效输入在入口拦，不进表。

### 3.4 授权与执行分离（依据：第 1.6 节、第 2.5 节）

控制消息先授权解码（验标签、认请求码、备执行参数），再执行表更新。传输（标签查询、回话发送）在服务层，表更新在库。替代方案是一锅烩：库依赖数据存储服务与进程间通信原语，测试要搭全套。分离后授权表四个分支全覆盖，执行三操作各测。

### 3.5 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 表值 | 第 1.1 节 | 全局静态 | 测试互斥 |
| 缓冲收紧 | 第 2.2 节 | 复刻瑕疵 | 超长检查失效 |
| 空串拒绝 | 第 1.2 节 | 复刻得零 | 到不了的分支 |
| 授权执行分离 | 第 1.6 节 | 一锅烩 | 测试要搭全套 |

## 4. Rust 实现详解

### 4.1 表与名字（`os/fs/ptyfs/src/table.rs`、`os/fs/ptyfs/src/names.rs`）

表结构三字段：一位图字，三十二记录。新建常量函数，存越界报无空间，删恒成功，读空闲或越界报空，上限恒三十二。名字渲染十二字节 bound，十进制倒填，零特判。解析空拒绝、非数字拒绝、前导零拒绝、checked 上溢拒绝。

### 4.2 查找枚举状态与控制（`os/fs/ptyfs/src/lib.rs`）

根号一，从设备基号二，控制三请求码，标签终端，权限九位掩码，特权两清位。错误六变体加错误码映射。查找：非根报找不到，点回根，解析查表。枚举：三段位置，空闲耗位，满回绕，越顶错。改属主改模式：根落根记录，从设备落数组，未知号报无效。状态：目录二文件一，三时间取创建。控制授权：验标签认请求码备参数。卷状态：不截断加名字上限。

## 5. 测试

### 5.1 名字测试（三个）

渲染零与边界：零、个位、上限三十二位最大值。往返：七值渲染解析互逆。拒绝：空串、字母、前导零、上溢两值。

### 5.2 表与操作测试（五个）

查找点与从设备：点回根，数字命中，外目录未分配坏名全找不到。枚举跳空与回绕：两容量停从设备处回绕，续枚举走完停界外，异节点拒绝。属主模式：从设备换标识清特权，改模式保类型，根落根记录，未知号拒绝。状态链接时间：根二从设备一，时间取创建，未知号拒绝。控制授权：异标签拒收，三请求码认，未知码未实现。表边界：上限三十二，越界存无空间，空删恒成功。常量锁定：根基号请求码标签。错误码六映射。
