## 1. 概念：翻译官与边境检查站

### 1.0 章节引言

目标读者是读完第 01 篇的读者：已经知道消息按编号查表分发，知道挂载门禁。前置知识只需要一条：函数调用需要合法的参数，而消息里的字段是不可信的外部输入。

本章建立三个概念：适配器是翻译官（消息字段与服务器调用之间的翻译），校验是边境检查（非法输入在边境被拦下，进不了内陆），点名字符规则是全网统一的国境法（所有文件系统对点和点点的处理完全一致）。

### 1.1 适配器是翻译官

分发表把请求送到适配函数门口，适配函数做三件事：从消息里取出字段并检查合法性，调用服务器的对应回调，把回调的结果装进回复消息。这三步的顺序是固定的：先检查，再调用，最后装回复。检查失败时直接返回错误码，服务器回调一次都不会被调用。

为什么翻译官这一层必须存在？因为消息是扁平的整数与字节数组，而服务器回调要的是有类型的参数（索引节点号、位置、长度、名字字符串）。翻译官把" wire 格式"变成"类型化参数"，服务器作者永远只处理合法输入。这是纵深防御思想：每一层都只信任经过上一层检查的东西。

### 1.2 三十一个适配器按五组编队

三十一个适配器不是三十一个孤立函数，它们按操作对象分成五组。分组不是文档作者的发明，而是代码本身的形状：同组适配器取同一批字段、做同一类检查、调同一族回调。

1. **挂载组（五个）**：挂载、卸载、挂载点检查、新节点、释放节点。管的是文件系统整体与节点的生死簿。
2. **数据组（八个）**：读、写、窥视、读目录、截断、抑制预读，外加读写共用的内部帮手与窥视模拟。管的是字节流。
3. **命名空间组（九个）**：创建、建目录、建设备节点、硬链接、删除、删目录、改名、符号链接、读符号链接。管的是名字与目录树。
4. **元数组（五个）**：状态、改属主、改模式、改时间、文件系统统计，外加同步。管的是描述信息。
5. **块组（四个）**：块读、块写、块窥视、刷块，外加块读写共用的内部帮手与新驱动绑定。管的是裸设备。

记住这个分组，后文的 C 分析与 Rust 设计都按它展开。

### 1.3 校验规则：位置、长度、计数

数据类请求共享一条校验规则：位置不能是负数，长度不能超过有符号结果的最大值。位置是文件偏移，负偏移没有意义；长度最终要装进有符号返回值，超了装不下。这条规则在读、写、窥视、读目录、块读、块写、块窥视七处重复出现，Rust 侧收成一个函数，七处共用。

释放节点的计数校验是另一条：零与超大计数都被拒绝。零引用没有意义，超大计数（超过三十二位整数上限）一定是发送方算错了。截断请求校验区间两端非负。新建类请求的名字规则见下一节。

### 1.4 点名字符：全网统一的国境法

创建、建目录、建设备节点、硬链接、符号链接五个操作拒绝点和点点，理由是"已经存在"；删除文件拒绝点和点点，理由是"不允许"；删除目录对点报"无效参数"、对点点报"目录非空"；改名的旧名与新名拒绝点和点点，理由是"无效参数"。

这些规则不在任何一个文件系统里实现，而是在适配层统一执行。好处是全网一致：不管挂载的是磁盘文件系统还是虚拟文件系统，点和点点的行为永远相同。坏处是服务器想自定义也没门——但这正是设计意图：点的语义是协议的一部分，不是文件系统的自由。

### 1.5 窥视模拟：没枪没炮，拿读来造

窥视请求希望文件服务器把文件页直接暴露给虚拟内存，不经过复制。有后端设备的服务器必须自己实现窥视；没有后端设备的服务器（纯内存的虚拟文件系统）可以不实现，框架用读来模拟：分配临时缓冲，用服务器的读回调填满，把缓冲页交给虚拟内存，并告诉虚拟内存用完即弃，避免缓存过期数据。

这个模拟是"有限支持"的诚实写法：性能不如真窥视，但正确性有保证。Rust 侧用路径选择函数表达这个决策：有窥视实现就直调，有后端设备但没实现就报未实现，无后端设备就走模拟。

### 1.6 回复的形状：位置推进与字节计数

读类操作成功时，回复带两个数：传输后的新位置（原位置加上实际传输字节），以及实际传输字节数。实际传输可能少于请求长度（读到文件尾），所以这两个数都要回。窥视与读链接只回字节数，不回新位置——窥视不移动文件偏移，这是容易写错的细节，C 注释里专门写了一句"不返回新位置"。

### 1.7 本章小结

适配器是翻译加检查：取字段，验合法，调回调，装回复。三十一个适配器按五组编队，校验规则三条（位置长度、释放计数、点名），窥视有模拟退路，回复分推进位置与只报字节两种形状。下一章进入 C 源码，逐个验证。

## 2. C 源码分析

### 2.1 挂载组（五个）

**挂载 `fsdriver_readsuper`**（`call.c:11-68`）是最长的适配器，步骤如下：取设备号、标签授权、标签长度、挂载标志；回调空则报未实现；已挂载则打印一行日志并报忙；取标签名字（允许空）；通知驱动绑定（如果服务器提供了绑定回调）；调挂载回调；成功时填根节点五字段与能力标志，更新库内挂载状态（已挂载、设备、根节点），清虚拟内存缓存使用标记。

能力标志的两条框架规则（`call.c:48-51`）：文件窥视与块窥视同时有，或者设备没有主设备号（无盘），就点亮有窥视位。注意这个判断用的是"服务器有没有提供回调"，不是"挂载回调报了什么"，框架在服务器的回答之外又加了一笔。

**卸载 `fsdriver_unmount`**（`call.c:74-90`）调卸载回调（可空），清虚拟内存缓存（如果用过内存映射模拟），清挂载标志，永远报成功。卸载没有失败的概念：虚拟文件系统服务说卸，服务器必须卸。

**挂载点检查 `fsdriver_mountpoint`**（`call.c:818-829`）取索引节点号，回调空则报未实现，否则透传回调结果。

**新节点 `fsdriver_newnode`**（`call.c:120-148`）取模式、属主、属组、设备号，回调空则报未实现，成功时填新节点六字段（含设备号）。

**释放节点 `fsdriver_putnode`**（`call.c:96-114`）取节点号与计数，计数零或超大先报无效参数，回调空则直接报成功（注意：不是未实现，是成功——释放通知丢了也无妨，这是五个组里唯一的"空回调即成功"的释放语义）。

### 2.2 数据组（八个）

**读写共用帮手 `read_write`**（`call.c:153-188`）取节点号、位置、长度，位置负或长度超限报无效参数，拼数据抽象（端点是发送方，授权与长度来自消息），按调用标识调写或调读回调。回调返回非负表示传输字节数：位置推进，回复填新位置与字节数，结果转成功；返回负数表示错误码，直接透传。

**读 `fsdriver_read`**（`call.c:194-202`）与**写 `fsdriver_write`**（`call.c:205-216`）只是空检查加转调：回调空报未实现，否则进共用帮手。

**窥视模拟**（`call.c:226-273`）分配匿名内存映射，用读回调填充，读不满的尾巴补零，通过虚拟内存调用把页交给虚拟内存（一次性标记），用不断增长的假设备偏移避免复用假设，解映射，返回长度。两个静态变量（标志存贮与假偏移）是函数私有的，注释解释了为什么假偏移必须递增：依赖"虚拟内存串行处理窥视请求"的协议假设有风险，递增偏移更保险。

**窥视 `fsdriver_peek`**（`call.c:280-315`）取节点号、位置、长度并校验；有窥视回调就直调（数据参数固定空）；没有回调时，有后端设备报未实现，无后端设备走模拟。成功只回字节数，不回新位置。

**读目录 `fsdriver_getdents`**（`call.c:320-353`）取节点号、位置、容量，回调空报未实现，位置与容量同样校验，拼数据抽象，调回调，成功时回新位置与字节数。位置在这里是输入兼输出：从哪里续读由它定，停在哪里也由它报。

**截断 `fsdriver_trunc`**（`call.c:360-376`）取节点号与区间两端，两端非负校验，回调空报未实现，否则透传。

**抑制预读 `fsdriver_inhibread`**（`call.c:381-393`）取节点号，有寻位回调就通知一声，永远报成功。它的作用是告诉服务器"调用者刚移动了文件偏移，之前的预读作废"。

### 2.3 命名空间组（九个）

**创建 `fsdriver_create`**（`call.c:399-438`）取授权、长度、目录节点、模式、属主、属组；回调空报未实现；取名字（要求非空）；拒绝点和点点（报已存在）；调回调；成功填新节点五字段。

**建目录 `fsdriver_mkdir`**（`call.c:443-474`）、**建设备节点 `fsdriver_mknod`**（`call.c:479-512`）、**硬链接 `fsdriver_link`**（`call.c:517-543`）结构与创建相同，只是字段与回调不同，点名规则相同（报已存在）。

**删除文件 `fsdriver_unlink`**（`call.c:548-573`）点名规则变为拒绝点和点点报不允许，其余同上。**删除目录 `fsdriver_rmdir`**（`call.c:578-606`）点报无效参数、点点报目录非空——点点不是空目录，删它相当于删父目录，框架直接挡掉。

**改名 `fsdriver_rename`**（`call.c:611-646`）取新旧两套授权、长度、目录；回调空报未实现；旧名非空校验加点的无效检查；新名同样；调回调。注意新旧名字各做一次完整的取名字流程，两次都可能失败。

**符号链接 `fsdriver_slink`**（`call.c:651-685`）取路径授权、长度、目录、属主、属组，点名检查，拼目标数据抽象（授权与长度来自消息的目标字段），调回调。**读符号链接 `fsdriver_rdlink`**（`call.c:690-712`）拼数据抽象，调回调，成功只回字节数（与窥视同理，不推进位置）。

### 2.4 元数组（五个）

**状态 `fsdriver_stat`**（`call.c:717-741`）取节点号与授权，回调空报未实现，本地清零状态结构，预填设备号与节点号（框架帮填的两项），调回调，成功后把整个状态结构复制给调用者。

**改属主 `fsdriver_chown`**（`call.c:746-767`）取节点号与新属主属组，回调空报未实现，成功回新模式。**改模式 `fsdriver_chmod`**（`call.c:772-790`）同理。**改时间 `fsdriver_utime`**（`call.c:795-812`）取节点号与访问、修改时间的秒加纳秒四项，组装成两个时间结构，回调空报未实现。

**文件系统统计 `fsdriver_statvfs`**（`call.c:834-851`）回调空报未实现，本地清零统计结构，调回调，成功复制给调用者。**同步 `fsdriver_sync`**（`call.c:856-866`）有回调就通知，永远报成功。

### 2.5 块组（四个）

**块读写共用帮手 `bread_bwrite`**（`call.c:900-935`）取设备号、位置、长度并校验，拼数据抽象，按标识调块写或块读，成功回新位置与字节数。**块读 `fsdriver_bread`**（`call.c:940-949`）与**块写 `fsdriver_bwrite`**（`call.c:954-963`）做空检查后转调。

**块窥视 `fsdriver_bpeek`**（`call.c:968-996`）与文件窥视的关键区别：没有模拟退路。回调空直接报未实现，因为块窥视面对的是设备页，读文件那套模拟不适用。位置长度照样先验，成功只回字节数。

**刷块 `fsdriver_flush`**（`call.c:1001-1013`）取设备号，有回调就通知，永远报成功。**新驱动 `fsdriver_newdriver`**（`call.c:871-895`）取设备号、授权、长度；回调空直接报成功（注意：不是未实现——没有绑定回调的服务器不需要知道驱动标签）；否则取标签（允许空）并通知绑定。

### 2.6 与 Rust 实现的步骤差异说明

| 差异 | C 做法 | Rust 做法 | 分类 |
|------|--------|-----------|------|
| 授权搬运 | 每个适配器从消息字段拼数据抽象 | 数据抽象的拼装留给服务进程的收发层，适配器只收验证后的标量 | 设计决策：适配器与传输解耦，见第 3.2 节 |
| 窥视模拟的内存映射 | 适配器内部分配映射并调虚拟内存 | 模拟路径由调用方注入（测试替身可替换） | 设计决策：副作用注入，见第 3.4 节 |
| 状态与统计结构的预填 | 适配器预填设备号与节点号 | 调用方预填，适配器只透传 | 设计决策：职责归位，见第 3.5 节 |
| 新驱动的空回调 | 空回调报成功 | 空默认体，效果相同 | 无差异（默认体即成功） |
| 释放节点的空回调 | 空回调报成功 | 默认体即成功 | 无差异 |

## 3. Rust 设计决策

> 每个决策先给依据（第 1 章的概念或第 2 章的源码位置），再给替代方案与取舍。

### 3.1 校验函数独立成章（依据：第 1.3 节、第 2.2 节、第 2.5 节）

位置长度检查在七个适配器里重复，点名规则在九个适配器里重复。Rust 把它们收成六个自由函数：位置长度、截断区间、释放计数、创建点名、删除点名、删目录点名、改名点名。适配器只管调用，规则只实现一次。

替代方案是每个适配器内联自己的检查。那样九处点名规则各自写一遍，将来协议变了要改九处，漏一处就是全网不一致。独立函数的代价是多一层调用，收益是规则单点定义。点名规则的四种错误码差异（已存在、不允许、无效参数、目录非空）是最容易抄错的，单点定义消除整类错误。

### 3.2 适配器与传输解耦（依据：第 1.1 节、第 2.6 节差异表）

C 适配器从消息字段里抠授权标识，拼出数据抽象。Rust 适配器不碰消息：调用方（服务进程的收发层）已经把授权翻译成数据通道，适配器只收验证后的标量（节点号、位置、长度）与通道。读写的字节流用闭包传递：读是"来一块交一块"的推送闭包，写是整片字节切片。

这样分层的理由是测试：适配器测试不需要伪造消息与授权，只需要内存通道。传输细节（授权、端点、内核调用）全部沉到数据通道模块，第 03 篇展开。

### 3.3 输入与回复做成结构（依据：第 1.6 节、第 2.2 节）

传输输入（节点、位置、长度）与块传输输入（设备、位置、长度）是带校验构造函数的结构：构造时即验证，拿在手里的值一定合法。挂载输入与新节点输入是普通结构。回复分两种形状：推进型（新位置加字节数）与计数型（只有字节数），各用一个结构，窥视与读链接只能拿到计数型——"窥视不推进位置"的规则在类型层面可查，而不是靠注释提醒。

### 3.4 副作用注入（依据：第 2.2 节窥视模拟）

窥视模拟需要分配内存、调用读、通知虚拟内存。Rust 把"模拟怎么读"做成调用方注入的闭包参数，适配器只决定走哪条路。测试注入内存替身，生产注入真实读路径。这是依赖注入思想的常规应用：决策（选哪条路）与能力（路怎么走）分开，决策可测，能力可换。

### 3.5 预填职责归位（依据：第 2.4 节状态适配器）

C 的状态适配器预填设备号与节点号，因为它手里有库内全局变量。Rust 没有全局变量（状态在服务器值里），预填自然归调用方：调用方知道设备号，顺手填好再调适配器。职责跟着数据走，数据在哪里，活就在哪里。

### 3.6 错误透传用问号（依据：第 1.1 节翻译官模型）

适配器三步中的任何一步失败，整个适配器失败，错误码原样返回。Rust 用问号操作符表达这个"一步失败全盘失败"，三十一个函数读起来都是"验、调、装"的直线，没有嵌套的错误处理。这是翻译官模型的直接映射：翻译错一个词，整句作废。

### 3.7 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 校验函数独立 | 第 1.3 节、第 2.2 节 | 各适配器内联 | 九处点名规则各自写，必有人抄错 |
| 适配器不碰消息 | 第 1.1 节 | 从消息抠字段 | 测试需伪造消息与授权，笨重且脆弱 |
| 输入回复结构化 | 第 1.6 节 | 散参数加注释 | 窥视不推进位置的规则靠注释，易忘 |
| 模拟闭包注入 | 第 2.2 节 | 适配器内部分配 | 测试要进内核内存映射，不可测 |
| 预填归调用方 | 第 2.4 节 | 适配器预填 | Rust 无全局变量，数据在哪里活在哪里 |
| 问号透传 | 第 1.1 节 | 嵌套匹配 | 三步直线变圣诞树，可读性差 |

## 4. Rust 实现详解

### 4.1 校验函数（`os/libs/minix-fs/src/call.rs` 前一百一十行）

最大传输量是与目标平台相关的有符号上限，注释写明来源。位置长度检查与截断区间检查、释放计数检查是常量函数（纯整数比较）；四个点名检查是普通函数（字符串比较在当前编译器下还不能进常量函数，注释里如实说明限制，没有硬拗）。

### 4.2 挂载组（`call.rs` 挂载小节）

挂载输入结构带设备与标志。挂载适配器按 C 的顺序执行：已挂载判忙，绑定驱动标签，调挂载回调，协商窥视位。窥视协商是独立的常量函数，四个布尔输入决定是否点亮能力位，测试可以直接调用它验证四种组合（有实现、无设备等），不需要搭服务器。

卸载适配器只有一行：通知服务器。挂载点、新节点、释放节点三个适配器各调一个回调，释放节点先验计数。

### 4.3 数据组（`call.rs` 数据小节）

传输输入的构造函数即校验。读适配器调服务器读闭包，把返回字节数换算成推进回复；写适配器先检查"给的字节不能比说的长度多"（调用方可能把整片缓冲递进来，长度字段才是准的），再调写。窥视路径选择是独立常量函数，三种输入对应直调、模拟、未实现。读目录适配器把位置的可变借用直接递给服务器（输入兼输出），返回字节数。

### 4.4 命名空间组（`call.rs` 命名空间小节）

名字输入结构只含目录与名字（长度与终止符的检查在数据通道的名字获取里做，第 03 篇）。九个适配器各先调对应的点名规则，再调回调。改名调两次规则（旧名新名各一次），与 C 的两次取名字流程对应。

### 4.5 元数与块组（`call.rs` 元数与块组小节）

状态、改属主、改模式、改时间、文件系统统计五个适配器透传，同步永远成功。块传输输入与文件传输输入形状相同但设备字段代替节点字段，各自独立定义（不共用），因为"文件偏移"与"设备偏移"是不同概念，共用结构会制造混淆。块窥视只有检查函数（无模拟），刷块与新驱动永远成功。

## 6. 过渡：从翻译到搬运

本篇讲完了"说什么"：三十一个请求各自的字段、检查、回调、回复。但还有一个问题没碰：字节与名字到底是怎么从调用者的内存搬到服务器的内存的？授权标识是什么？本地指针与远端授权的两条路怎么统一？读目录的条目又是什么格式？

这些"怎么搬"的机制是下一篇 `03-fsdriver-utility.md` 的内容：数据通道（复制进、复制出、清零）、名字获取（长度、终止符、非空三条规则）、目录项编码器（暂存加刷新的两级流水）、路径查找（一步一查、挂载点与符号链接的三岔路）。

阅读建议：先读数据通道，它是所有读写与名字操作的地基；再读名字获取（只有一百行 C 代码，却是九个命名空间适配器的共同前置）；目录项与查找可以按需深入。
