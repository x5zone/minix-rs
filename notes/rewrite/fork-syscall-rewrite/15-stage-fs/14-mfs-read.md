## 1. 概念：从文件偏移到磁盘块的数据旅程

### 1.0 章节引言

目标读者是跟完命名空间四篇的读者：已经知道名字如何变成文件编号，也知道文件长度如何变化，但还没有读过一个字节的文件内容。前置知识只需要一条：文件是按字节编号的连续逻辑空间，磁盘是按块编号的离散物理空间，中间需要一张翻译表。

本章建立读取路径的心智模型。读取分三层：顶层按请求长度切分，保证每次只处理一个块内部的一段；中层按文件偏移查翻译表，找到磁盘块号或者确认是空洞；底层按块号拿数据或者返回零。预读是顶层的加速器，目录枚举是同一套块读取在目录文件上的应用。

### 1.1 块号翻译：直接、单重间接与双重间接

内存索引节点里面保存十个存储区号，前七个是直接存储区，第八个是单重间接块，第九个是双重间接块。直接存储区的名字就是数据本身，间接块里面保存的是存储区号清单。单重间接块里面存一整块存储区号，双重间接块里面存一整块单重间接块的区号。

翻译时先算文件块号，即文件偏移除以块大小。再把文件块号换算成存储区号，需要考虑一个存储区可能包含多个块。文件块号落在前七个直接区覆盖的范围，直接返回对应的存储区号加块内偏移。落在单重间接范围，先拿单重间接块，按索引取出存储区号再返回。落在双重间接范围，先拿双重间接块取出单重间接块的区号，再拿单重间接块取出数据存储区号。任何一级遇到空区号就报告空洞，不继续往下走。

双重间接的索引上限有保护：算出来的双重间接索引超过单块能容纳的区号个数，直接报告空洞，不去拿磁盘块。这个保护让超大偏移的读取快速返回，而不是逐级拿块之后才发现越界。

### 1.2 空洞读零：没有分配的块读出来全是零

空洞的意思是文件逻辑上有这个位置，但磁盘上没有给它分配存储区。空洞的来源有两种：文件中间跳着写留下的缝隙，截断扩大留下的尾巴。原始实现规定空洞读出来全是零，写入时遇到空洞则分配新块。这个规定让稀疏文件成为可能：一个很大的文件如果中间大片是零，磁盘上可以只保存非零部分，读零的部分不需要存储空间。

读取遇到空洞时不碰磁盘，直接向调用方输出同样长度的零。这个分支是读取与写入的根本区别：读取把缺席当正常，写入把缺席当需要分配的信号。第 15 篇的写入遇到同样的缺席会走分配路径，两篇在此分叉。

### 1.3 分块循环：每次只处理一个块内部的一段

一次读取请求可能横跨多个块，原始实现用循环切分，每次只处理当前块里面从当前偏移开始的一段。切分长度取块剩余长度和剩余请求长度的较小值。读取时还要考虑文件长度：如果当前位置已经到达文件末尾就停止，如果当前块会超出文件末尾就按剩余文件长度截断。写入时不截断，因为写入可以扩大文件，但写入前要检查扩大之后是否超过文件系统允许的最大长度，超过就拒绝。

循环的计数器有三个：还剩多少没读，已读了多少，文件内位置走到哪里。每次处理完一段，三个计数器同步推进。返回值是实际搬运的字节数，不是请求长度，因为可能提前遇到文件末尾或者中途出错。调用方靠返回值知道读到哪里停。

### 1.4 窥视模式：只看缓存里面有没有，不去磁盘拿

除了读取和写入，块处理函数还有第三种模式，叫窥视。窥视的意思是问缓存里面有没有这个块，有就用，没有就报告缺席，不去磁盘拿。窥视服务于虚拟内存的页面缓存协同：虚拟内存想知道文件系统的缓存里面有没有某页，有就直接用，没有就自己想办法，不强迫文件系统去读盘。

空洞在窥视模式下的回答是通知虚拟内存把对应页清零，而不是返回零数据。这个细节保证两级缓存看到的空洞语义一致：文件系统缓存和虚拟内存缓存都认为空洞是零，不会有一边有旧数据另一边是零。

### 1.5 预读：顺序读越读越快的原因

预读的意思是当前这次读了第几个块，顺手把后面几个块也从磁盘拿进缓存。顺序读文件时，下一次读的位置恰好是这次的下一个块，数据已经在缓存里面，直接命中，不需要等磁盘。随机跳读时预读帮助不大，所以寻位标记置位之后预读量会减少。

原始实现的预读量计算考虑四个上限：请求后面还剩多少字节，文件还剩多少块，单次预取队列的最大长度，以及顺序读的最小预取量。最小预取量是三十二个块，寻位之后不保证这个最小量。预读时逐个翻译后面块的块号，翻译出空洞就停止，因为空洞不需要预取。翻译出来的块号如果已经在缓存里面就停止，因为后面的块很可能也在缓存里面，不需要继续预取。收集到的块号交给块层的批量预取接口，一次下发。

### 1.6 目录内容枚举：按位置分批输出

目录在磁盘上也是文件，内容是定长目录项数组。枚举的意思是按调用方给的位置开始，把后面的目录项逐个翻译成通用的目录输出格式，分批拷贝给调用方。位置必须是目录项大小的整数倍，否则说明调用方的位置已经错乱，报告找不到。每次枚举结束时更新位置：如果调用方缓冲区满了，位置停在没来得及输出的那一项，下次从这一项继续；如果全部输出完，位置停在文件末尾，下次从末尾开始返回空。

每个目录项输出时需要知道目标文件的类型，因为通用目录格式里面有文件类型字段。类型通过按编号查找内存索引节点得到，找不到就按未知类型输出。注释写明这种查找代价很高，调用方要随时准备收到未知类型。这是性能与准确性的权衡：目录项里面不存类型省空间，枚举时现查类型费时间，折中方案是查不到就报未知，不硬等。

### 1.7 本章小结

读取路径是三层结构：分块循环保证每次只处理块内一段，块号翻译把文件偏移变成磁盘块号或者空洞，块处理按读取、写入、窥视三种模式分支。空洞读零让稀疏文件成为可能，预读让顺序读越读越快，目录枚举是块读取在目录文件上的应用，位置对齐和类型降级是它的两个特殊规则。下一章进入原始代码验证，逐个函数核对行号和行为。

## 2. 原始代码分析

### 2.1 读写主函数 `fs_readwrite`（`read.c:23-111`）

### 2.2 块处理 `rw_chunk`（`read.c:117-204`）

位置超过地址上限就终止进程（`read.c:141-142`），因为文件偏移不可能这么大，到了就是编程错误。翻译文件偏移到磁盘块号，翻译只用缓存里面的元数据（`read.c:143`）。记录设备号和文件编号（`read.c:144-145`），断言编号有效（`read.c:146`）。

块号为空分三路：读取就向调用方输出零（`read.c:149-155`），窥视就通知虚拟内存清零对应页（`read.c:156-159`），写入就分配新块（`read.c:160-165`）。块号非空且非写入，走预读路径拿块（`read.c:167-169`）。块号非空且写入，按整块覆盖与否决定是否需要先读盘：整块覆盖不需要读，块对齐且位置在文件末尾之后也不需要读，否则正常拿块（`read.c:170-181`），拿不到就终止进程。

块对齐的写入且位置在原文件末尾之后且非整块，先把整块清零再拷贝，避免旧尾巴残留（`read.c:187-190`）。读取就从块缓冲拷贝给调用方（`read.c:192-194`），写入就从调用方拷贝进块缓冲并标脏（`read.c:195-199`）。放回块并返回（`read.c:201-203`）。

### 2.7 与 Rust 实现的步骤差异说明

| 差异 | 原始做法 | Rust 做法 | 分类 |
|------|----------|-----------|------|
| 错误传递 | 全局错误码加返回值混合 | 函数返回值 | 设计决策：错误跟随调用返回 |
| 终止进程 | 位置超限、拿块失败、间接块损坏时终止 | 返回输入输出错误 | 设计决策：库不终止进程 |
| 窥视元数据 | 间接块按窥视只用缓存 | 间接块一律正常拿取 | 设计决策：块层已覆盖批量预取，窥视无收益 |
| 预读队列 | 自建静态队列加批量下发 | 收集映射块号后调块层预取 | 无差异：机制相同，接口换层 |
| 类型查找 | 按编号打开目标，失败终止 | 表命中则用真实类型，否则按未知 | 设计决策：枚举不为类型去读盘 |
| 传输边界 | 框架拷贝函数直接读写用户缓冲 | 调用方提供字节回调 | 设计决策：传输边界上移到适配器 |

## 3. Rust 设计决策

> 每个决策先给出依据，再给出替代方案与取舍。对比 Linux 与 Redox 的同类设计，说明为什么当前选择更适合无标准库的单线程文件服务器。

### 3.1 翻译参数与合法区号范围收成两个小结构（依据：第 1.1 节、第 2.3 节）

块号翻译需要的几何参数只有两个：直接存储区个数，每间接块容纳的区号个数。合法性校验需要的范围只有两个：首个数据存储区号，存储区总数。这四个数收成两个小结构，调用方在挂载时从超级块一次性算好，之后每次翻译只传这两个小结构。

替代方案是每次翻译传超级块引用。坏处是翻译函数依赖超级块类型，超级块加字段翻译函数跟着重新编译，防腐层破了。小结构是防腐层，字段变化隔离在挂载时的一次换算。

对照 Linux：Linux 的地址空间操作把块大小和间接层级收成文件系统的私有数据，翻译函数只看私有数据，不看超级块整体。两者同构。

### 3.2 间接块损坏报输入输出错误（依据：第 1.1 节、第 2.4 节）

间接块里面的区号超出数据区范围，说明磁盘镜像被人写坏或者位图与间接块不一致。原始实现打印并终止整个文件服务器，Rust 实现返回输入输出错误。文件服务器是多用户共享的服务，一个坏文件不应该拖死所有用户，报错让调用方按错误码处理，比终止更符合服务的可用性要求。

替代方案是保留终止。坏处是测试无法覆盖这条分支，覆盖了进程就没了。返回错误让测试可以用伪造的间接块锁定这条分支。

### 3.3 窥视模式不下沉到间接块（依据：第 1.4 节、第 2.2 节）

原始实现的翻译函数有一个机会主义参数，窥视时间接块只用缓存。Rust 实现的翻译一律正常拿间接块，窥视语义只保留在数据块的按需分配与批量预取层面。理由是块层的批量预取已经覆盖了机会主义的收益：预读时翻译后面块的块号，命中缓存就停止，这个停止逻辑与窥视等价，单独为间接块保留窥视模式省不下一次磁盘访问，反而让翻译函数多一个分支。

对照 Linux：Linux 的预读只管数据页，间接块的缓存由通用块缓存自然覆盖，不单独为间接块做预读。两者同构。

### 3.4 预读有界且寻位后衰减（依据：第 1.5 节、第 2.5 节）

预读最小量三十二个块做成具名常量，寻位标记置位时跳过最小量保证。预读收集到的块号按块层允许的最大预取长度截断，空洞截断收集，缓存命中截断收集。三个截断保证预读不会无限制下发，不会为稀疏区域预取，不会重复预取已缓存的块。

替代方案是不做最小量保证，每次只预取请求后面紧跟着的几块。坏处是顺序读小请求时预读量太小，加速效果不明显。三十二这个数是原始实现的选择，保留它是对顺序读性能特征的忠实复刻，测试锁定这个常量。

对照 Linux：Linux 的预读窗口从小到大自适应，顺序读越大窗口越大，随机读窗口收缩。寻位后衰减是同一思想的简化版：不用自适应算法，用一个标记区分顺序与随机，实现简单但效果方向一致。

### 3.5 目录枚举类型降级为未知（依据：第 1.6 节、第 2.6 节）

枚举时目标类型按内存表命中获取，表里面没有就不去读盘，直接按未知类型输出。原始实现按编号打开目标，失败就终止进程。打开目标可能触发读盘，枚举一个大目录时为每个名字读一次盘，性能不可接受。注释写明这个代价很高，调用方要准备收到未知类型，Rust 实现把这个注释变成行为：查不到就报未知，不硬等。

对照 Redox：Redox 的目录枚举同样只保证名字和编号，类型字段允许为未知，调用方需要类型时自己再查。两者同构。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 参数收成小结构 | 第 1.1 节 | 传超级块引用 | 字段变化扩散，防腐层破裂 |
| 损坏报输入输出错 | 第 2.4 节 | 保留终止 | 一个坏文件拖死全服务 |
| 间接块不窥视 | 第 1.4 节 | 保留机会主义参数 | 省不下访问，多一个分支 |
| 预读有界衰减 | 第 1.5 节 | 无最小量 | 顺序小读加速不明显 |
| 类型降级未知 | 第 1.6 节 | 失败终止 | 大目录枚举为类型读盘太贵 |

## 4. Rust 实现详解

### 4.1 翻译与校验（`os/fs/mfs/src/read.rs` 翻译小节）

文件块号到设备块号的映射按直接、单重间接、双重间接三段分支。直接段空区号返回空，单重间接段空单重块返回空，双重间接段空双重块返回空，双重索引超限返回空。间接块读取按四字节小端解析并逐项校验范围，越界返回输入输出错误。单项解析按索引取数，缺项按空处理，与原始实现的数组越界语义对齐。

### 4.2 读取与预读（`os/fs/mfs/src/read.rs` 读取小节）

文件读取先校验位置非负和块大小非零，按编号查找槽位但不增加引用。位置到达文件末尾直接返回零并清除寻位标记。剩余长度按文件剩余截断。循环内按块大小切分，翻译命中则预读一次并正常拿块拷贝，翻译为空则输出零。结束清除寻位标记，非只读标记访问时间并标脏。预读只在第一次命中时触发，寻位时返回零，收集后面三十二个块以内的映射块号并按块层上限截断后下发。

### 4.3 目录枚举（`os/fs/mfs/src/read.rs` 枚举小节）

位置不对齐直接拒绝。按编号查找目录槽位，非目录拒绝。调用方缓冲与暂存缓冲分离，编码器拥有两块缓冲，循环只碰缓存和表，借用不冲突。逐块拿镜像，空洞报输入输出错误，因为目录不应该有空洞。逐项跳过空槽，按首个零字节算名字长度，表命中取真实类型否则取未知，缓冲区满则位置回绕到当前项。结束更新位置，非只读标记访问时间。
