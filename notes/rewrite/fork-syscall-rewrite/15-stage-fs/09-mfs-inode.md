## 1. 概念：图书馆的借书卡系统

### 1.0 章节引言

目标读者是跟完第 08 篇的读者：认识磁盘身份证与账本，但还没见过文件的内存形态。前置知识只需要一条：磁盘慢内存快，常用的元数据要驻留内存。

本章建立索引节点表的心智模型：它是图书馆的借书卡系统——卡片目录（哈希）找书，借书卡（引用计数）记谁在看，还书车（空闲队列）收没人看的，书库（磁盘）只在缺书时跑一趟。

### 1.1 为什么内存索引节点与磁盘格式长得不一样

磁盘格式是六十四字节的紧凑记录：模式、链接数、属主、属组、大小、三时间、十个区号，一字不多。内存形态则多了十几项：所在设备、本机号、引用计数、脏标记、搜索 hint、挂载标记、寻位标记、更新标记。多的全是"工作状态"，不是"文件属性"——磁盘不需要知道谁在看这本书，内存必须知道。

两边用显式转换函数来回倒：读上来逐字段拓宽（十六位变三十二位，三十二位变六十四位），写回去逐字段收窄。这种"存储窄、工作宽"的分离是通用原则：磁盘格式求稳（几十年不变），内存形态求好用（随实现演进）。

### 1.2 哈希：一百二十八个抽屉

五百一十二个槽位按号查太慢，哈希表把槽位按号的低七位分进一百二十八个抽屉。找文件先算抽屉，再在抽屉里比号加设备。哈希冲突用链解决（同抽屉串起来），这是教科书做法，没有花样。

哈希只管"找到"，不管"能不能用"：找到但引用计数为零的槽位正在还书车上，拿走前要先从车上摘下来。这个"摘车"动作是引用计数与空闲队列的交接点，也是最容易漏的地方。

### 1.3 引用计数：几个人在看这本书

每个槽位记引用计数：打开一次加一，释放一次减一。减到零时看链接数：还有链接的是"没人看但书还在"，写回脏内容，推到还书车尾（下次还可能借，缓存）；零链接的是"书不要了"，上报待回收区号，清掉号牌，推到还书车头（下次优先重用）。

车头与车尾的区别是淘汰策略：刚释放的无主槽位最可能马上被重用（新建文件紧接着到来），放车头；缓存的旧槽位放车尾，慢慢沉底。这是用队列位置表达访问热度，不花一个字节额外状态。

### 1.4 获取的三条路：命中、冷命中、缺席

获取分三种：引用中命中（计数加一，计数器不动——只有冷命中才算命中，这是性能统计的诚实定义），冷命中（计数为零，从车上摘下，计数加一），缺席（车头取空槽，旧号解绑，读磁盘，计数置一，挂进哈希）。车空了报文件表满——五百一十二个全被钉住，爱莫能助。

缺席时设备为空则跳过读盘：这是分配新节点的路径，槽位是全新的，没有磁盘内容可读。设备为空的获取只发生在分配内部，不对外——对外接口永远带真设备。

### 1.5 分配与释放：账本与表的两步舞

分配分两步：先在位图账上占一位（从搜索 hint 起找），再在表里占一槽。表满了则退位（把刚占的位还回去），不能占着账不办事。槽位填模式、零链接、属主属组、设备，大小清零，区号清空，时间全标待更新，脏标记置位。

释放是分配的逆过程：号码越界或零号静默忽略（陈旧号码不值得报错），清位图位，搜索 hint 回拨（下次从更小处找，提高复用）。位图操作本身在超级块篇，表只调接口——第 07 篇闭包注入的同一思想在这里是跨模块调用。

### 1.6 懒时间：记账迟做

时间更新不直接写时钟：置待更新位，状态查询或释放写回时一次性结清。读-only 挂载跳过（只读盘上不写时间，这是只读的语义）。一次时钟读服务三个字段——管道服务器同理（第 06 篇），两种服务器在此同构。

### 1.7 本章小结

内存索引节点是磁盘格式加工作状态：哈希找、计数借、队列收、转换倒、时间懒。下一章进入 C 源码验证。

## 2. C 源码分析

### 2.1 内存结构 `struct inode`（`inode.h:20-50`）

磁盘部分九项（`inode.h:21-29`）：模式、链接数、属主、属组、大小、三时间、十区号。内存部分十三项（`inode.h:32-48`）：设备、号、计数、直接数、间接数、超级块指针、脏标记、区搜索位、目录扫描位、挂载标记、寻位标记、更新标记、哈希链、空闲链。表是五百一十二槽全局数组（`inode.h:50`），空闲队与哈希表 extern（`inode.h:53-56`），命中计数两全局（`inode.h:58-59`）。

脏标记宏（`inode.h:67-70`）：标脏在只读盘上打印加堆栈（只读盘出现脏节点是逻辑错误，值得大声嚷），标干净无声。寻位两常量（`inode.h:63-64`）。

### 2.2 磁盘格式 `d2_inode`（`type.h:8-17`）

六十四字节：模式、链接数、属主、属组各两字节，大小三时间各四字节，十区号各四字节（`2+2+2+2+4+4+4+4+40=64`）。注释写明"磁盘上的样子，非内存"（`type.h:7`）。

### 2.3 释放请求 `fs_putnode`（`inode.c:38-64`）

按号找表（`inode.c:44`），找不到宕机（`inode.c:46-50`，请求引用了不存在的槽位是协议违反）。计数超限宕机（`inode.c:52-56`）。计数减请求数加一（留一给释放函数，`inode.c:58-61`），调释放，报成功。

### 2.4 缓存初始化 `init_inode_cache`（`inode.c:70-90`）

命中计数清零，空闲队初始化，一百二十八哈希链初始化，全槽标未用号并头插入空闲队（`inode.c:86-89`）。初装两步中的另两步归属本篇（第 07 篇已移交）。

### 2.5 哈希挂摘 `addhash_inode`、`unhash_inode`（`inode.c:96-112`）

挂号：号与一百二十七，头插入对应桶（`inode.c:98-101`）。摘号：从链移除（`inode.c:111`）。桶算法是掩码不是取模——桶数是二的幂，掩码等价且更快。

### 2.6 获取 `get_inode`（`inode.c:118-174`）

算桶，链上找号加设备：命中且计数零则摘车加记命中（`inode.c:132-141`），计数加一返回。未命中记缺席（`inode.c:144`），车空报文件表满（`inode.c:147-150`，错误码走全局），取车头，非未用号则解绑（`inode.c:154-155`），摘车，填设备号计数一（`inode.c:161-163`），非空设备读盘（`inode.c:164`），清更新区搜挂载扫描四项（`inode.c:165-168`），挂哈希返回。

### 2.7 纯找 `find_inode`（`inode.c:180-200`）

链上找计数正且号设备吻合（`inode.c:193-197`），找不到返回空。`fs_lookup` 与 `fs_seek` 用它：只看不借，计数不动。

### 2.8 释放 `put_inode`（`inode.c:206-246`）

空指针直接回（调用方省心，`inode.c:214`）。计数已零宕机（`inode.c:216-217`）。减一归零则：零链接先截断（块设备文件错误忽略，`inode.c:224-227`）、清类型、标脏、释放号（`inode.c:228-230`）；清挂载标记；脏则写回（`inode.c:233-234`）；零链接解绑标未用压车头（`inode.c:236-240`），否则压车尾缓存（`inode.c:241-244`）。

### 2.9 分配 `alloc_inode`（`inode.c:252-303`）

只读报只读文件系统（`inode.c:262-265`）。位图按搜索位找位（`inode.c:268`），无位报无空间加打印（`inode.c:269-275`）。搜索位推进（`inode.c:276`）。无盘获取表槽（`inode.c:280`），失败则退位（`inode.c:282`）。填模式、零链接、属主属组、设备、直接间接数、超级块指针（`inode.c:285-292`），擦大小区号时间（`inode.c:299`，与截断共用擦除函数，注释写明省代码，`inode.c:294-298`）。

### 2.10 擦除 `wipe_inode`（`inode.c:309-323`）

大小零、时间全标待更新、标脏、十区号清零（`inode.c:319-322`）。分配与截断共用——同一组字段两种场景都要清，合一处。

### 2.11 回收号 `free_inode`（`inode.c:328-343`）

未用号与超界静默返回（`inode.c:339`）。清位图位（`inode.c:341`），搜索位回拨（`inode.c:342`）。

### 2.12  stamp 时间 `update_times`（`inode.c:349-370`）

只读直接回（`inode.c:363`）。读一次时钟，按位刷三时间（`inode.c:365-368`），清标记（`inode.c:369`）。注释解释懒更新的动机：时钟消息贵，标记便宜（`inode.c:352-357`）。

### 2.13 读写转换 `rw_inode`、`new_icopy`（`inode.c:375-449`）

定位：区起始加位图块数，块号等于号减一除每块节点数加起点（`inode.c:389-390`），槽内偏移号减一取余（`inode.c:392-393`）。拿缓存块（`inode.c:391`）。写则先结时间（`inode.c:397`）、非只读标脏块（`inode.c:398`）。断言三版（`inode.c:404`）。逐字段拷（`inode.c:424-447`），读定直接数为七、间接数按块大小算（`inode.c:432-433`）。放回，清脏标记（`inode.c:407-408`）。

### 2.14 加引用 `dup_inode`（`inode.c:455-463`）

计数加一。简化版获取：指针已知，跳过查找。

### 2.15 与 Rust 实现的步骤差异说明

| 差异 | C 做法 | Rust 做法 | 分类 |
|------|--------|-----------|------|
| 全局表 | 全局数组加全局链 | 表值（可多实例） | 设计决策：测试可并行 |
| 释放截断 | 内联调截断 | 上报待回收区号 | 设计决策：截断归第 13 篇，见第 3.4 节 |
| 找不到宕机 | 请求层宕机 | 返回错误 | 设计决策：库不崩 |
| 计数超限宕机 | 宕机 | 返回错误 | 设计决策：库不崩 |
| 错误码全局 | `err_code` 全局 | 返回值 | 设计决策：错误随调用走 |
| 打印 | 缺空间打印 | 无打印 | 设计决策：库不打印 |

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 表做成值（依据：第 1.1 节、第 2.1 节）

五百一十二槽加一百二十八桶加空闲队收成一个结构体值，测试可建两个并行跑。C 用全局是因为单进程单表；Rust 保留单表语义（构造一个用一个），但不禁止多实例。替代方案是全局静态：测试互斥，未来多挂载无路。值类型零成本，多实例免费。

### 3.2 释放上报区号（依据：第 1.3 节、第 2.8 节）

零链接释放不内联截断，返回待回收区号列表，调用方（第 13 篇）清位图放缓存。理由是依赖方向：截断要写映射（第 14、15 篇）与区释放（第 07 篇策略加第 08 篇位图），索引节点篇直调它们等于依赖半个文件系统。返回区号把"发现"与"执行"分开：发现归本篇（谁的链接清零本篇知道），执行归链接篇。替代方案是本篇直调：第 09 篇依赖第 13、14、15 篇，阶段倒挂。

### 3.3 宕机改报错（依据：第 2.3 节、第 2.8 节）

找不到、计数超限、计数下溢三处宕机改返回错误。理由与第 03 篇相同。释放空槽是调用方传错槽位，报无效参数；测试锁定"放两次第二次错"。

### 3.4 错误细分（依据：第 2.6 节、第 2.9 节）

五错误变体：表满、只读、无空间、 corrupt、无效。表满与无空间分开（槽位满与位图满是两种满，调用者对策不同：前者放槽，后者删文件）。 corrupt 专收磁盘自相矛盾（负大小、短缓冲）。

### 3.5 几何参数子视图（依据：第 2.13 节）

读写定位要的四个数（节点区起点、每块节点数、间接密度）收成小结构，挂载时从超级块一次性算好。表不碰超级块整体——第 07 篇区空间子视图同一思想。替代方案是每次传超级块引用：表依赖超级块类型，超级块篇改字段表跟着改。子视图是防腐层。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 表值 | 第 1.1 节 | 全局静态 | 测试互斥，多挂载无路 |
| 上报区号 | 第 1.3 节 | 内联截断 | 依赖倒挂半个文件系统 |
| 宕机改错 | 第 2.3 节 | 保留宕机 | 库不崩，测试可断言 |
| 错误细分 | 第 2.6 节 | 统一无效 | 两种满对策不同 |
| 几何子视图 | 第 2.13 节 | 传超级块 | 防腐，字段变化隔离 |

## 4. Rust 实现详解

### 4.1 常量与磁盘格式（`os/fs/mfs/src/inode.rs` 前两百行）

未用零、零链接、未分配、表五百一十二、桶一百二十八、类型掩码与六类型、寻位两值、更新三位、目录项六十四、名六十、链接上限、直接七、总槽十。错误五变体加错误码映射。磁盘结构十三字段加六十四字节编解码（显式小端）。

### 4.2 表与槽位（`inode.rs` 表小节）

槽位内存十三字段（磁盘九拓宽加设备号计数几何脏 hint 扫描挂载寻位更新）。表三结构加命中计数。构造全空闲头插（与 C 同序）。桶算法掩码。挂摘桶。查找（计数正）、加引用、获取（三路）、摘队、释放（三岔：持有、释放、回收区号）、分配（两步舞）、无盘快道、回收号、 stamp 时间、磁盘读写、槽位访问器。几何定位纯函数。

### 4.3 与 C 一千零一十三步的差异说明（实现侧）

第 2.15 节六项在实现侧的落点：表值在构造，区号在释放枚举，错误在返回值，几何在子视图。命中计数语义与 C 一致（仅冷命中计数），测试锁定。

## 5. 测试

## 6. 过渡：从住户名册到开门营业

本篇的住户名册记下了每个文件的内存形态与借还规则。但服务器还缺开门三件事：挂载（读身份证、领根节点）、查路（目录里找名字）、开张（建新文件）。

第 10 篇讲挂载纵贯（本轮完整实现：真镜像挂载、干净卸载、挂载点检查）。第 11 篇讲查路（单步查找、目录漫步）。第 12 篇讲开张（创建四件套）。三篇消费本篇的表：获取、释放、分配、回收号，一个不少。
