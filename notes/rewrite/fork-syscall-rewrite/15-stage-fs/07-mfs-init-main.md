## 1. 概念：开店前的四件事与墙上的电路图

### 1.0 章节引言

目标读者是跟完框架与管道服务器的读者：见过完整小店（管道），现在看大店（磁盘）开业。前置知识只需要一条：磁盘文件系统把元数据放在磁盘固定位置，读写前必须先知道这些位置。

本章两个概念：初装是开店前的准备顺序（先通电再摆货），接线表是墙上的电路图（哪路电通向哪个车间，哪些车间还没建）。

### 1.1 初装四步：顺序即依赖

空进程变成文件服务器分四步，每步只依赖前步已建好的东西：打开二级缓存开关（允许以后用虚拟内存缓存），索引节点表清零（引用计数与校验数组归零），初始化索引节点缓存（空闲链与哈希链，细节归索引节点篇），建缓冲池（一千零二十四块，磁盘服务器的起步容量）。

顺序不能换：建池之前开开关（池建好才能决定开关生效条件），清表在初始化缓存之前（缓存初始化假设表是干净的）。这种"顺序即依赖"是启动代码的通用形状，第 01 篇虚拟内存启动链也是同一形状——启动无非是把依赖拓扑摊平成序列。

### 1.2 信号语义：先结账再关门

终止信号到来时，磁盘服务器不能直接下班：内存里有脏块与脏索引节点，直接退出等于丢数据。所以信号处理是"同步再下班"：调文件同步（刷脏），再请求框架终止。管道服务器无盘可刷，直接下班——两种下班方式的差异来自有没有持久状态，这是理解所有服务器信号处理的一把钥匙。

非终止信号一律忽略。信号处理函数不做第二件事：它只做决定（同步加终止），同步本身是别的模块的函数。这种"决定与执行分离"让信号逻辑可测——测试调决定函数，不用发真信号。

### 1.3 接线表：通八路，待二十三路

三十一回调的接线现状：块组五路已通（驱动绑定、块读、块写、块窥视、刷块，全部走第 05 篇块传输），挂载三路已通（挂载、卸载、挂载点检查，见第 10 篇纵贯实现），其余二十三路待建（分属第 09、11 到 17 篇）。新节点请求两边都没有（管道服务器专属，磁盘服务器不建无名节点，框架默认回答未实现）。

接线表是显式的：每行写清 C 处理器名、服务的请求、归属文档、当前状态。随着后续文档落地，行的状态从待建翻成已通，表永远反映真实进度。这种"显式部分接线"优于两种常见做法：静默桩（调了才知道没实现）与大包大揽（假装全通）。诚实的状态表是可维护性的地基。

三个处理器被复用：读写窥视共用读写函数，删除文件与删除目录共用删除函数，块读写窥视共用块传输函数。复用发生在签名相同处，调用标识参数区分具体请求——第 01 篇回调表结构已讲过机理。

### 1.4 拿块包装：缓存之上加一条行规

缓存的拿块返回三种结果：拿到、缺席、失败。文件系统的行规是：失败（缺席除外）即腐败级，直接报错——磁盘块读不上来，往下走只会错上加错。缺席只允许出现在窥视模式，其他模式的缺席是断言级错误（正常拿取不可能缺席，缺席说明契约破了），同样报错。

这条行规的语气比缓存严厉得多：缓存说"缺席是正常情况之一"，文件系统说"除了窥视，缺席就是事故"。层与层的严格度不同是正常的：越靠近应用，越要把异常翻译成事故或正常二选一，不留中间态。

### 1.5 区分配策略： hint、换算、断粮

分配区（磁盘大块）分三步：定起点（要首区则用记录的搜索位，否则把目标区号换算成位号），请位图找位（位图实现归超级块篇），找不着报无空间。位号与区号换算公式是区号等于首区减一加位号，位零保留为失败信号。

释放是分配的逆过程加两笔：位号小于搜索位则搜索位回拨（下次分配从更小处找，提高复用），缓存中同名块作废（防过期）。范围之外的区号静默忽略——陈旧的释放请求没有东西可释放，报错反而添乱。

### 1.6 本章小结

启动四步（开关、清表、建缓存、建池），信号先同步再下班，接线表八通二十三待，拿块行规严于缓存，区分配 hint 加换算加断粮。下一章进入 C 源码验证。

## 2. C 源码分析

### 2.1 入口 `main` 与启动 `sef_local_startup` `main`、`sef_local_startup`（`main.c:14-42`）

入口（`main.c:14-26`）：存参数、本地启动、进框架主循环、返回零。三行有效代码，启动的戏全在回调里。本地启动（`main.c:31-42`）：注册新装回调、注册重启回调（有状态重启）、注册信号回调，交启动框架。这是所有服务器同一套起手式（管道服务器 `pfs_startup` 同构）。

### 2.2 初装 `sef_cb_init_fresh` `sef_cb_init_fresh`（`main.c:47-65`）

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 初装只做两步（依据：第 1.1 节、第 2.2 节）

C 初装四步，Rust 初装两步（开关、建池），索引表清零与缓存初始化归索引节点篇。理由是所有权：表是索引节点篇的结构，初始化函数也在那篇，启动篇越俎代庖只会制造跨篇耦合。替代方案是照抄四步：启动 crate 依赖索引节点 crate，方向反了（索引节点是被启动的，不是启动的前提）。依赖方向必须从启动指向被启动物，不能反过来。

### 3.2 位图闭包注入（依据：第 1.5 节、第 2.6 节）

区分配的位图操作（找位、清位）以闭包注入，超级块篇提供存储实现。这与第 05 篇设备信息 trait、第 03 篇后端 trait 同一思想：策略（起点、换算、断粮、回拨）在本篇，机制（位操作、存储读写）在实现方。替代方案是启动篇直接依赖超级块篇：分配策略与位图存储绑死，测试要搭整块位图。闭包注入后测试用三行数组替身，策略全覆盖。

### 3.3 宕机改报错（依据：第 1.4 节、第 2.8 节）

拿块失败、缺席断言、缺空间打印三处，C 靠宕机、断言、打印，Rust 统一报错误。理由与第 03 篇相同：库不崩进程、不打印，错误随调用走。全局错误码改返回值：调用链上每个函数签名诚实表达失败可能，漏处理在编译期（未使用的结果警告）而不在运行时。

### 3.4 接线表做成常量数组（依据：第 1.3 节、第 2.4 节）

三十一接线行做成编译期常量数组，每行四字段（C 处理器名、请求、归属文档、状态）。测试可以遍历数组断言完整性（三十一行、请求全覆盖、复用关系），这是"表驱动"的彻底形态：表既是文档又是可执行断言。替代方案是注释列表：注释会过期，数组配测试不会——测试每天跑，注释没人看。

### 3.5 信号只做决定（依据：第 1.2 节、第 2.3 节）

信号处理提炼为纯函数：信号号进，决定出（忽略或先同步再下班）。同步执行由事件循环按决定调用，测试调纯函数覆盖两种信号，不用发真信号。这是"决定与执行分离"的又一次应用（第 02 篇窥视选路同理）。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 初装两步 | 第 1.1 节 | 照抄四步 | 依赖方向反了，表归表的主人 |
| 位图闭包 | 第 1.5 节 | 直调超级块 | 测试要搭整块位图，策略机制绑死 |
| 宕机改错 | 第 1.4 节 | 保留宕机 | 库不崩进程，错误随调用走 |
| 常量接线表 | 第 1.3 节 | 注释列表 | 注释过期，数组配测试不过期 |
| 信号纯函数 | 第 1.2 节 | 处理器直调同步 | 测试要发真信号，不可测 |

## 4. Rust 实现详解

### 4.1 启动模块（`os/fs/mfs/src/startup.rs`）

池默认值一千零二十四（Makefile 行号为证）、终止信号十五、启动配置两旋钮（池大小、缓存开关）、服务器核心（缓存加开关、读写访问器）、初装函数（验池下限、建池、存开关）、信号决定纯函数（终止则先同步再下班，否则忽略）。

### 4.2 缓存包装（`os/fs/mfs/src/mfs_cache.rs`）

空区零、区空间三字段（首区、总数、搜索位，超级块字段的子集视图）。拿块包装三分支（成功交槽、窥视缺席交空、其他失败报错）。区分配 hint 分支（首区用搜索位、否则换算，饱和防下溢）、位零防线、断粮报无空间、首区更新搜索位。区释放范围静默、清位、搜索位回拨、缓存作废。范围判断纯函数。

### 4.3 接线表（`os/fs/mfs/src/table.rs`）

状态三变体（块传输已通、本 crate 已通、待归属文档）、表行四字段、三十一常量行（C 初始化顺序）、已通与待建两迭代器。测试锁四事：请求全覆盖（除保留与新节点）、三十一加八加二十三、三处复用同 C、无新节点行。

### 4.4 入口（`os/fs/mfs/src/main.rs`、`lib.rs`）

库根声明三模块加单线程注释。入口停放，注释写明运行时接线归属（无裸待办标记）。

## 6. 过渡：从接线到磁盘格式

本篇搭好磁盘服务器的架子：能启动（两步初装）、能决定下班（信号纯函数）、知道哪路通哪路待（三十一接线）、能拿块分區（包装加策略）。但服务器还不认识磁盘：超级块长什么样、位图在哪、版本号怎么验，全不知道。

下一篇 `08-mfs-super.md` 讲超级块：三十一字节磁盘格式、版本门卫、块大小五连验、首区计算、几何 sanity、强制标志、位图分配释放。读完下一篇，挂载流程（第 10 篇）要用的地基就齐了。

阅读建议：先看版本门卫（三魔数两命运），再看块大小五连验（层层加码），位图分配释放收尾。
