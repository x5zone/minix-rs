## 1. 概念：图书馆的取书单

### 1.0 章节引言

目标读者是读完第 04 篇的读者：知道缓存里有槽位、有脏位、有引用计数。前置知识只需要一条：块设备是按块编号寻址的字节数组，分区是其中一段连续范围。

本章建立传输的心智模型：调用者下一张取书单（设备、位置、长度、方向），传输员先核对单据（设备存在、范围合法、分区裁剪），再逐块行走（拿块、搬运、放回），读单顺路预取后面几块，写单整块覆写跳过读盘，最后报告实际搬了多少字节。

### 1.1 取书单的四个要素

一张取书单有四个要素：哪台设备、从哪里开始、搬多少、方向（读出来还是写进去）。窥视不是第五个方向：窥视就是一张读单，只是收货地址空着——走完全程，暖了缓存，但什么都不交货。把窥视表达为"收货地址缺席的读"，而不是独立方向，是本篇最关键的概念统一，C 代码里 `data` 为空指针的分支正是这个意思。

### 1.2 核对单据：三道关卡

传输开始前先过三道关卡。第一道：设备号不能为空设备，空设备没有存储，谈传输没有意义。第二道：位置不能为负，长度不能超过有符号上限，位置加长度不能溢出——溢出检查用带进位判断的加法，与第 03 篇数据通道的护栏是同一个思想。第三道：问分区要实际大小，把范围裁剪到分区末尾；起点已经在分区之外，报告零字节而不是错误——读到文件尾是正常情况，不是故障。

长度为零的单子直接报告零，连分区都不问。这是早退优化，也是语义：什么都不搬，就什么错都不可能有。

### 1.3 逐块行走：首尾不满、中间整块

字节范围落在块上通常是首尾不满、中间整块：第一块从中间开始，最后一块到中间结束，中间的都是整块。行走时每块算出本块要搬多少（块尾减块内偏移，再与剩余量取小），最后一块还要与分区尾巴取小（三取小，缺一不可）。

每块内部四步：拿块（读预取先行，整块覆写免读），搬运（读是缓存到调用者，写是调用者到缓存），标脏（写必标，即使搬运失败也标——部分复制可能已经落地，不标脏就会丢），放回（引用计数减一，块回队列）。四步在循环里重复，直到剩余量为零或出错。

### 1.4 读预取：顺路多拿几本

顺序读时，读完当前块，接下来很可能要后面几块。预取在拿当前块之前先探路：用窥视模式逐个问后面几块在不在，遇到已缓存的就停（后面的更可能也在，犯不着全问），把探到的未缓存连续段读进来。上限是缓存的预读上限与剩余块数取小。预取纯属优化：失败了静默忽略，正常流程会再读一次，正确性不受影响。

### 1.5 整块覆写免读：旧页无用不取

写操作覆盖整块时，块里旧内容马上作废，读上来是浪费。传输用免读模式拿块：给空槽位，不碰存储，写完标脏。这个优化要求调用者真的写满整块——部分写必须先读，因为没写的部分还要保留。判断条件是"本次搬运量等于整块大小"，一字不多一字不少。

### 1.6 刷后失效：关门前清场

设备关闭后的刷操作分两步：先把脏块写回，再把该设备所有缓存拷贝作废。顺序不能反：先作废再刷，脏数据就没了；只刷不作废，关闭后重开会读到过期缓存。两步连做，保证"关闭的设备不留任何痕迹"。

### 1.7 驱动绑定：给设备挂牌子

挂载与新驱动请求到来时，文件系统把设备号与驱动标签（如设备名）登记到驱动表。当前实现是薄薄一层透传，但它是未来的接缝：块设备层成型后，所有驱动细节藏在这层后面，文件系统只认设备号与标签。这个"今天透传、明天藏实现"的接缝思想，也是第 03 篇后端 trait 的思想。

### 1.8 本章小结

传输是核对单据（三关）加逐块行走（四步）：裁剪分区、预取读、免读整块写、标脏不含糊、刷后失效、挂牌绑定。下一章进入 C 源码，逐段验证二百六十三行。

## 2. C 源码分析

### 2.1 文件头契约（`bio.c:1-40`）

文件头注释是使用契约：用本库的文件系统必须初始化缓冲池（非磁盘 backed 建议预取上限个数，磁盘 backed 用更多），必须启用虚拟内存缓存（支持块设备内存映射），必须用全刷或调全刷实现同步回调。磁盘 backed 文件系统还应考虑三点：限制挂载分区首部一千零二十四字节的写（只读挂载也不拦首部，为分区工具留路），块大小可自定（默认即可），首部注释即文档。

### 2.2 驱动绑定 `lmfs_driver` `lmfs_driver`（`bio.c:48-53`）

取设备主设备号对应的驱动项，登记标签。注释写明这是薄封装，目标是把块设备库藏到文件系统视线之外。当前六行，将来接缝。

### 2.3 块预取 `block_prefetch` `block_prefetch`（`bio.c:64-99`）

取预读上限，超限则截断并视末块为整块。逐块窥视拿：命中则放回并跳出（`bio.c:88-94`，注释写明命中常见，因为每次读前都预取），收集未命中计数。计数大于零则调预读（`bio.c:97-98`）。末块不满时用部分块窥视。注释留了一个待办：按可用缓冲数限流（`bio.c:62`）。

### 2.4 传输主函数 `lmfs_bio` `lmfs_bio`（`bio.c:116-246`）

空设备拒绝（`bio.c:127-128`）。取块大小，定读写方向，断言块大小为正。零长度早退（`bio.c:135-136`）。位置负、长度超限、位置加长度溢出，三者任一拒绝（`bio.c:138-139`，溢出用 `pos > INT64_MAX - bytes + 1` 表达）。

问分区大小（`bio.c:146-147`，注释抱怨不能缓存结果，因为看不见分区变更通知，`bio.c:141-144`）。起点超分区报零（文件尾，`bio.c:149-150`）。长度裁到分区末尾（`bio.c:152-153`）。算起始块、块内偏移、剩余块数（`bio.c:156-158`）。末块是设备末块则算尾巴长度（`bio.c:166-169`）。

主循环（`bio.c:173-236`）：本块搬运量取三者最小（块剩、请求剩）；读则预取（`bio.c:186-188`）；整块覆写用免读（`bio.c:194`）；末块不满用部分块拿；拿块失败打印设备号块号错误码并跳出（`bio.c:202-206`）；读则复制出，写则复制进加标脏（复制失败也标脏，注释解释接口问题但为防缓存与磁盘脱节必须标，`bio.c:210-222`）；放回；失败跳出；块号推进，偏移清零，剩余块减一。

收尾（`bio.c:242-245`）：一次没搬成就报错误，否则报搬运量。短搬加后续错误报短计数——调用者能区分"全失败"与"搬了一半"。

### 2.5 刷后失效 `lmfs_bflush` `lmfs_bflush`（`bio.c:255-263`）

先刷本设备脏块，再作废本设备全部缓存。注释写明目的：设备关闭后不留过期拷贝（`bio.c:249-254`）。

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 设备信息做成 trait（依据：第 1.7 节、第 2.2 节）

分区大小查询与标签绑定收成 `DeviceInfo` trait 两个方法。传输只认 trait，不认驱动。内存盘实现它（分区大小即块数乘块大小，标签存在表里），真实驱动以后实现它。替代方案是传输直接调驱动函数：测试要搭驱动，驱动要搭设备，金字塔倒置。与第 04 篇存储 trait 同一理由，不再展开。

### 3.2 槽位统整块、搬运做裁剪（依据：第 1.3 节、第 2.6 节）

C 的部分块拿取让槽位有大有小，命中比较要核对字节数（大小不对报输入输出错）。Rust 槽位永远整块，末块不满只在搬运时裁剪。代价是末块多占一点内存，收益是槽位尺寸统一、命中比较只比键。权衡成立的条件是块设备按整块寻址——块设备本来就按整块寻址，末块不满是分区概念，不是存储概念。分层对了，复杂度自然消失。

### 3.3 窥视即缺席通道的读（依据：第 1.1 节、第 2.4 节）

传输方向只有读与写两个变体，窥视不占变体：调用方传缺席通道即窥视。C 用空指针表达同一意思，Rust 用枚举变体表达，类型更明确。测试可以用缺席通道走完全程，验证"暖缓存但不交货"。

### 3.4 预取独立成函数（依据：第 1.4 节、第 2.3 节）

预取是纯优化，与主循环的正确性无关，独立成 `prefetch_run` 函数：探路收集、读入连续段、失败全吞。主循环只在读分支调它一行。独立后测试可以直接调预取，验证"预取后读不碰存储"，正确性测试与优化测试分离。

### 3.5 内存盘是生产代码（依据：第 2.1 节契约）

内存盘 `RamDisk` 不是测试替身：它是启动内存盘的占位实现，块数乘块大小即分区，标签表即绑定。测试复用它，启动流程以后也用它。一物两用，符合"测试替身与生产实现统一"的思想——第 03 篇内存后端同理。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 设备信息 trait | 第 1.7 节 | 直调驱动 | 测试金字塔倒置 |
| 槽位统整块 | 第 1.3 节 | 部分槽位 | 命中比较复杂化，收益为零 |
| 窥视无变体 | 第 1.1 节 | 第三方向 | 空指针语义已有，枚举更明确 |
| 预取独立 | 第 1.4 节 | 内联主循环 | 正确性测试与优化测试混杂 |
| 内存盘生产化 | 第 2.1 节 | 纯测试替身 | 启动内存盘本来就需要它 |

## 4. Rust 实现详解

### 4.1 类型与 trait（`os/libs/minix-fs/src/bio.rs` 前一百行）

标签上限八十（含结束零，与数据服务头文件一致）。设备信息 trait 两方法。传输方向两变体。传输函数七参数：缓存、设备信息、设备、位置、长度、方向、通道。泛型三元：存储源、二级缓存、后端。

### 4.2 传输主流程（`bio.rs` 传输小节）

三关卡按 C 顺序：空设备、零早退、位置长度溢出。问分区、裁剪、起点超限报零。算块、偏移、剩余块数、末块尾巴。主循环：三取小、读预取、整块覆写免读、拿块失败跳出、搬运裁剪、读写分支、失败标脏（写）、放回、失败跳出、推进。收尾：零搬运则报错误，否则报计数。

写分支先把通道内容读进临时缓冲，成功才拼进槽位（失败不污染缓存），再调写槽。读分支直接从槽位切片复制出。临时缓冲按块分配在栈外堆上（变长），无固定上限问题（块大小即上限）。

### 4.3 预取与绑定、刷后失效（`bio.rs` 辅助小节）

预取按上限探路，命中停步，读入连续段，全吞失败。绑定验标签长度（含结束零）再登记。刷后失效先刷后作废，顺序注释写明不可反。

### 4.4 内存盘与计数器（`bio.rs` 设备小节）

内存盘构造验非零，读写验下标与长度，标签登记覆盖旧值。计数器用格子包装计数（读路径共享借用不断），只供测试。
