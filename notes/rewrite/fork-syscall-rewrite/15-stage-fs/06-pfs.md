## 1. 概念：只卖两种货的小店

### 1.0 章节引言

目标读者是跟完框架五篇的读者：知道请求如何分发、翻译、搬运。前置知识只需要一条：管道是单向字节流，一头写一头读，先进先出。

本章讲第一个完整服务器。完整的意思是：九个回调全实现，挂载卸载全走通，不依赖任何磁盘。最小的意思是：只卖两种货（管道与设备节点），没有目录，没有名字，没有路径查找。

### 1.1 为什么启动时先挂载它

系统启动时，虚拟文件系统服务第一个挂载的就是管道服务器。原因是管道不需要磁盘：进程间通信的管道必须在根文件系统就绪之前就能用，否则启动初期的进程连管道都建不了。磁盘文件系统还在等驱动就绪，管道服务器只用内存，永远就绪。

所以管道服务器的挂载不读任何设备：挂载就是初始化内存表。设备号与标志位直接忽略，返回的根节点全零——调用者本来也不会用它。这种"挂载但无根"的设计是故意的：保持与其他文件系统的对称，让驱动框架没有特例，而不是因为管道真有个根。

### 1.2 五百一十二张货架

服务器维护固定五百一十二个节点槽位。节点号从一开始，零号保留（查找时零号直接拒绝）。空闲槽位串在栈上，挂载时倒序压栈，于是弹出的顺序从一开始递增——注释里承认这是为了好看（数字从小往大用），美学也是价值。

上限五百一十二与虚拟文件系统服务的索引节点上限保持大体同步，这是全系统能同时打开的管道与克隆设备数的天花板。注释里写了将来可以动态分配，但那需要额外设施——固定表是深思熟虑的简化，不是偷懒：启动初期的内存分配器还没法依赖，固定表零依赖。

### 1.3 借还的最小闭环

节点只有一条出生路（新节点请求）与一条死亡路（释放节点请求）。出生时检查类型（管道或三类设备，其他一律拒绝并注明"调用者行为失常"），检查空位（满了报文件表满），管道则分配三万多字节缓冲（分配失败报无空间）。死亡时检查计数必须恰为一（计数长不大，因为没有增加引用的路），归还缓冲，槽位压回栈顶。

释放后压回栈顶意味着刚释放的号最先被重用。这是栈的自然行为，也是测试锁定的行为：分配、释放、再分配，拿回同一个号。

### 1.4 管道读写：流、压缩、 limits

管道是流，不是文件：读写忽略位置参数，读推进读指针，写追加到尾部。读按三取小（请求量、管内存量、缓冲上限），超缓冲上限直接拒绝；写先验总量（存量加增量超缓冲拒绝），再把残留数据搬到缓冲头（写时压缩，不是读时压缩——小读多的时候省搬运，直线缓冲省内核调用），再复制进，最后更新大小与时间。

截断只支持全清（起止都得零），其他一律拒绝。管道没有"截中间"的概念，全清就是倒空。

### 1.5 懒时间：记账迟做，报账时结

每个节点记三个待更新标记（访问、修改、变更）。读置访问，写置修改加变更，改模式置修改加变更，出生三置全置。状态查询时一次性结清：读一次时钟，三个字段一起刷，标记清零。下次查询无挂起则时钟都不读——上一节测试失败恰恰证明了这条：多读一次时钟，时间就对不上。

改模式只动权限位，类型位原样保留，回写新模式。这是 Unix 语义：改模式改的是"谁能干什么"，不是"这是什么"。

### 1.6 退出：先同步再下班

终止信号到来时，磁盘文件系统要先刷盘再下班，管道服务器无盘可刷，直接下班。信号处理只认终止信号，其他一律忽略。启动时丢弃特权（切到服务用户），失败只警告——启动不能因为降权失败而停，警告加继续是可用性选择。

### 1.7 本章小结

管道服务器是框架的最小完整消费：无根挂载、五百一十二槽位、借还闭环、流式读写、懒时间、信号下班。下一章进入 C 源码，逐段验证四百五十一行。

## 2. C 源码分析

### 2.1 常量与节点结构（`pfs.c:16-44`）

节点上限五百一十二（`pfs.c:16`，注释要求与虚拟文件系统服务上限大体同步）。时间更新三位（`pfs.c:19-21`）。节点结构十三字段（`pfs.c:23-42`）：号、模式、属主、属组、大小、设备号、三时间、数据指针（仅管道）、起始偏移、更新标记、空闲哨兵、空闲链指针。空闲链是表头插入的链表（`pfs.c:44`）。

### 2.2 挂载 `pfs_mount`（`pfs.c:49-82`）

初始化空闲链，倒序建表（一号槽位号为一，空闲哨兵置真，`pfs.c:63-71`）。根节点清零（`pfs.c:78`），能力位置六十四位（`pfs.c:79`），报成功。设备号与标志位两个参数显式标注未用。

### 2.3 卸载 `pfs_unmount`（`pfs.c:87-99`）

扫表找在用节点，找到就打印忙警告。做不了别的——内存表没有持久状态，卸载就是放行。

### 2.4 查找与出生 `pfs_findnode`、`pfs_newnode`（`pfs.c:104-178`）

查找（`pfs.c:104-120`）：号界一到五百一十二，断言槽位号自洽，空闲返回空（调用者转无效参数）。出生（`pfs.c:125-178`）：类型检查（管道或块字符套接字，否则无效参数，`pfs.c:134-138`）；空栈报文件表满（`pfs.c:141-142`）；管道分配缓冲，失败报无空间（`pfs.c:146-147`）；弹栈顶，断言空闲，置忙；填模式属主属组、大小零、三更新全置；设备节点记设备号，管道记空设备；数据指针与起始清零；填回复六字段。

### 2.5 死亡 `pfs_putnode`（`pfs.c:183-212`）

查不到报无效参数。计数非一报无效参数（注释解释计数长不大，`pfs.c:191-198`）。管道释放缓冲。置空闲，压回栈顶，报成功。

### 2.6 管道读写 `pfs_read`、`pfs_write`（`pfs.c:217-293`）

读（`pfs.c:217-248`）：非管道报无效参数；超缓冲上限报文件过大（`pfs.c:229-230`）；裁到存量；复制出，失败透传；大小减、起始加、置访问；报传输量。写（`pfs.c:253-293`）：非管道报无效参数；存量加增量超缓冲报文件过大（`pfs.c:265-266`，先验后搬）；起始非零则残留前移（`pfs.c:274-280`，注释解释写时压缩的理由）；复制进，失败透传；大小加、置变更加修改；报传输量。

### 2.7 截断 `pfs_trunc`、状态 `pfs_stat`、改模式 `pfs_chmod`（`pfs.c:298-375`）

截断 `pfs_trunc`（`pfs.c:298-316`）：非管道报无效参数；非全零区间报无效参数；大小清零，置变更加修改。状态 `pfs_stat`（`pfs.c:321-356`）：查不到报无效参数；有挂起则读一次时钟全刷（`pfs.c:331-339`）；填状态十三字段（设备字段填设备号是旧套接字缺陷的变通，`pfs.c:342`；块大小填管道缓冲；块数按五百一十二字节向上取整，`pfs.c:352-353`）。改模式 `pfs_chmod`（`pfs.c:361-375`）：查不到报无效参数；类型位保留、权限位替换（`pfs.c:370`）；置修改加变更；回写新模式。

### 2.8 信号 `pfs_signal`、启动 `pfs_init` 与 `pfs_startup`、回调表 `pfs_table`、入口 `main`（`pfs.c:380-451`）

信号 `pfs_signal`（`pfs.c:380-388`）：非终止返回，终止则请求框架下班。初始化 `pfs_init`（`pfs.c:393-402`）：丢弃特权到服务用户（`rs.h:22`，九百九十九），失败警告。启动 `pfs_startup`（`pfs.c:407-420`）：注册新装回调、重启回调（有状态重启）、信号回调，交启动框架。回调表 `pfs_table`（`pfs.c:425-435`）：九项——挂载、卸载、新节点、释放节点、读、写、截断、状态、改模式。入口 `main`（`pfs.c:440-451`）：本地启动，进框架主循环，返回成功退出码。

## 3. Rust 设计决策

> 每个决策先给依据，再给替代方案与取舍。

### 3.1 编号栈代替侵入链表（依据：第 2.1 节、第 2.2 节）

C 的空闲链是侵入式链表（指针存在节点里）。Rust 用编号栈：空闲号压栈，分配弹栈。等价性在于后进先出与表头插入同序——倒序压栈保证低号先出，与 C 的"低号先用"一致。替代方案是链表加指针：Rust 里侵入链表要么不安全代码，要么索引，一旦用索引就等价于栈。多余的指针操作没有收益。

### 3.2 缓冲用变长数组（依据：第 2.4 节）

C 用分配的三万多字节堆缓冲。Rust 用变长数组，分配时预留（`try_reserve` 失败转无空间，保留 C 的错误语义）。压缩用区间复制（`copy_within`），语义与内存移动一致。零号设备表示"管道无设备"，与 C 的空设备一致（空设备即零，见第 05 篇）。

### 3.3 时钟做成 trait（依据：第 1.5 节、第 2.7 节）

状态查询的懒更新依赖"读一次时钟"。直接读系统时钟则测试不可控：断言具体秒数 impossible。时钟 trait 加固定时钟（永远报同一秒）加步进时钟（每次读前进一步），测试用步进时钟证明"干净时不读表、脏时读一次"。替代方案是注入固定时间参数：每次调状态都传时间，签名污染，所有调用方跟着改。trait 把时间知识封装在服务器构造时，调用签名干净。

### 3.4 忙警告改计数（依据：第 2.3 节）

库不打印：打印是进程行为，不是逻辑行为。卸载时统计在用数存在公开字段，服务进程愿意警告就警告，愿意上报就上报。测试直接断言计数，不用截获标准输出。这是"逻辑与表现分离"：逻辑产出事实，表现消费事实。

### 3.5 状态布局本地化（依据：第 2.7 节）

系统状态结构的完整布局属于系统调用接口阶段（跨服务共识），管道服务器现阶段用八十字本地布局（字段顺序与 C 一致：设备、模式、链接数、属主、属组、设备、大小、三时间、块大小、块数）。测试锁定布局，接口阶段统一时整体迁移。提前定义全局布局会越权——那是另一篇文档的职责。

### 3.6 决策汇总

| 决策 | 依据 | 替代方案 | 为何不选 |
|------|------|----------|----------|
| 编号栈 | 第 2.1 节 | 侵入链表 | 索引即栈，多余指针无收益 |
| 变长缓冲 | 第 2.4 节 | 定长数组 | 三万字节乘五百一十二常驻太贵 |
| 时钟 trait | 第 2.7 节 | 传参时间 | 签名污染，构造时封装更干净 |
| 忙计数 | 第 2.3 节 | 库内打印 | 逻辑与表现分离，测试可断言 |
| 布局本地 | 第 2.7 节 | 全局布局 | 越权，归属接口阶段 |

## 4. Rust 实现详解

### 4.1 常量与类型（`os/fs/pfs/src/lib.rs` 前一百五十行）

节点上限五百一十二、管道缓冲三万二千七百六十八（目标平台值，有头文件行号为证）、状态块大小五百一十二、类型掩码与四类型、权限掩码七七七七、三更新位、状态缓冲八十。时钟 trait 两方法一契约，固定时钟与步进时钟各有构造与用途注释。节点结构十三字段与 C 一一对应（链指针由栈承担）。

### 4.2 服务器与查找（`lib.rs` 服务器小节）

构造建五百一十二槽位（号自洽）、空栈、时钟、忙计数零。查找分只读与可变两版（借用检查器要求：读字段与改字段不能同借），界外与空闲统一报无效参数，槽位自洽用调试断言（发布无成本）。描述函数拼框架节点。类型判断两常量函数。

### 4.3 九回调（`lib.rs` 回调小节）

挂载重建全表（空闲、数据、大小、偏移、挂起全清）、倒序压栈、忙计数清零、零节点加六十四位能力。卸载计数在用。出生验类型、验空栈、管道预留缓冲（失败无空间）、弹栈填字段、回描述。死亡验计数一、放缓冲、压栈。读写验管道、验上限、裁剪压缩复制、置位。截断验全零。状态验长度、结时间、填八十字节。改模式保类型换权限、回写。

### 4.4 入口（`lib.rs` 尾与 `main.rs`）

`server` 构造冻结时钟服务器，`init` 同义（入口调用点语义清晰）。进程入口构造后停放，注释写明运行时接线归属（无裸待办标记，接线点明确）。

## 5. 测试

### 5.1 挂载与借还测试（四个）

挂载复位加低号先出；出生拒常规文件、纳三类设备；表满报文件表满（循环五百一十二次）；释放重用栈顶、未知号与非一计数拒绝。

### 5.2 管道语义测试（四个）
