# 17 — 轻量线程快照：状态怎么定，睡在哪里怎么写

> **分类**: 进程信息 / 按 NetBSD 格式填写
> **源码**: `minix3/minix/servers/mib/proc.c:224-595`（判断状态的函数 `get_lwp_stat` 加三个填写函数函数加查询入口 `mib_kern_lwp`）
> **说明**: 进程信息五篇的第二篇，回答进程现在是什么状态、睡在哪里。表怎么拿归 16，本篇只管表拿回来之后，怎么把每一行写成 ps 命令能读的格式。

---

## 1 概念

### 1.1 目标读者与前置知识

面向要实现本篇功能的人。前置知识：16（按进程号查槽、写等待原因的文字、滴答换算时间、多留八个位置）、06（范围检查和拷贝出去）、10（查询函数在分发里的位置）。"轻量线程"是 NetBSD 的叫法，指一个能被调度的执行单位。系统信息服务借这套结构，把 Minix 的进程表翻译成 ps 和 top 命令能直接解释的字节。

### 1.2 本章不讲什么

- 三张表怎么拿、索引怎么建——16。
- 拷贝出去和长度截断——06。
- 第二套进程格式、进程参数、Minix 进程快照三种格式——18、19、20。
- 输出结构的字节排布最后怎么定——架构演进 A-4 延续 02 和 11 的立场（对外交换的格式不变，内部怎么写都行），本篇只引用编号值表。

### 1.3 先定状态，再找等待原因，最后填表

用户态的 ps 命令想知道的就三件事：进程是活是死，睡在哪里（等待地址加一句人能看懂的文字），时间、优先级、处理器用量这些数字。服务的回答分三步：

```
进程的三行（内核行、进程管理行、文件轻量行已经拿回来了，见 16）
  │  第一步：状态能直接定的，直接返回
  ├─ 僵死相关 → 等收尸 / 正在退出（连等待原因都不用看）
  ├─ 被停住 → 停止
  ├─ 能运行 → 可运行
  │  第二步：睡着的要找出在等什么
  ├─ 进程管理表说在等 → 等待 / 文件服务表说被卡 → 管道、锁、管道打开、复用等待、驱动名
  ├─ 内核说在跟谁通信 → 服务自身 / 某个内核标志 / 某个端点
  │  第三步：填输出结构
  └─ 状态加等待地址加文字加时间 → 输出结构的一行
```

关键的一点：**三张表说的可能互相矛盾**（进程管理表说在等，内核说在通信）。C 代码的注释直接说了，每张表内部自己是一致的，表和表之间不一定一致。所以判断的先后顺序是固定的：进程管理和文件服务先说，进程间通信和运行标志后说，后算出的能覆盖先算出的等待地址，但"能被信号叫醒"这个标记是添上去的，两边都要，不是二选一。

能报出的状态一共五种（`sys/sys/lwp.h:278-285`）：

| 状态 | 值 | 含义 | 怎么定的 |
|------|-----|------|------|
| 等收尸 | 5 | 死了，等父亲来收 | 不用看等待原因，直接返回 |
| 正在退出 | 6 | 正在退出，约等于僵死 | 不用看等待原因，直接返回 |
| 停止 | 4 | 被调试或者被停住 | 不用看等待原因，直接返回 |
| 可运行 | 2 | 能运行，在队列上排队，还没轮到 | 不用看等待原因，直接返回 |
| 睡着 | 3 | 睡着了，下面一定跟等待原因 | 执行完第二步才返回 |

正在被创建（值 1）和正在某个处理器上跑（值 7）永远不会从服务里出来：前者是每个处理器自己的事，后者一律报可运行（`os/libs/minix-types/src/types/sysctl.rs` 的注释明确写了这条）。

### 1.4 等待地址的低八位是类别号

等待地址是一个六十四位数，服务自己规定：**低八位是类别**，高位是类里面的具体信息（`proc.c:264-274`）。类别表是固定的：

| 低八位 | 类别 | 高位内容 |
|---------|------|---------|
| 0x00 | 内核任务 | 进程号 |
| 0x01 | 被内核运行标志挡住 | 运行标志字 |
| 0x02 | 进程管理调用 | 固定值（等待是 0x102，暂停是 0x202） |
| 0x03 | 文件服务调用 | 阻塞原因编号左移八位。字符设备和套接字再加上驱动端点 |
| 0x04 | 系统信息调用 | 无（纯粹为了输出完整，见 §2.2） |
| 0xff | 卡在某个端点上 | 端点号左移八位 |

注释原话："具体值无所谓，只要非零而且互不重叠"（`:272-274`）。这是服务内部的约定，不是 NetBSD 的标准，ps 命令只显示它，不解析它。

### 1.5 小结

先定状态（能直接定的五种直接返回），再找等待原因（进程管理和文件服务先说，通信和运行标志后说，后算的覆盖地址、先添的标记保留），最后填输出结构（三个填写函数）。表和表之间说的可能矛盾，所以顺序是固定的，§2 看 C 代码是怎么执行这个顺序的。

## 2 C 源码分析

### 2.1 常量和输出结构（`proc.c:224-237` 之外）

| 符号 | 位置 | 值和形状 | 说明 |
|------|------|------|------|
| 五种状态 | `sys/sys/lwp.h:279-284` | 2、3、4、5、6 | 本篇能报出的全部状态 |
| 正在运行 | `sys/sys/lwp.h:285` | 7 | 永不报出，能运行一律报可运行 |
| 三个标志 | `sys/sys/sysctl.h:607-617` | 0x4、0x80、0x200 | 常驻内存、能被信号叫醒的睡眠、内核任务 |
| 文件服务阻塞原因 | `servers/vfs/const.h:19-25` | 0 是无，1 到 6 是管道、锁等 | 原因编号的值归文件服务管，见 §3 的第二个决策 |
| 输出结构 | `sys/sys/sysctl.h:647-673` | 26 个字段 | 对外交换的结构：线程号、标志、状态、两个时间、优先级、处理器号、运行时间、文字、等待地址等 |
| 文字栏宽度 | `sys/sys/sysctl.h:466/469` | 8 和 20 | 等待原因文字栏和名字栏的宽度 |
| 查询号 | `sys/sys/sysctl.h:257` | 64 | 内核表 64 号位置挂着本篇的查询函数（`kern.c:462`） |

输出结构的全字段（按声明顺序）：四个指针（服务填零）、线程号（拿端点号当线程号）、标志、两个时间、两个调度字段（服务填零）、两个优先级、状态、两个填充、等待原因文字、等待地址、处理器号、运行时间秒和微秒、两个处理器用量、进程号、名字。

### 2.2 判断状态的函数（`proc.c:224-390`）

函数输入是槽号，输出是四样东西：等待地址、等待原因的文字、文字长度上限、标志字（按位或进去）。返回值是状态。除了睡着之外的四种直接返回，只有睡着的才执行完全程。

| 段 | 位置 | 行为 |
|----|------|------|
| 取三行 | `:235-237` | 三张表用同一个槽号各取一行（16 已经拿回来了） |
| 状态能直接定的 | `:243-253` | 僵死标志 → 等收尸。正在退出 → 正在退出。被跟踪停住或者内核停住标志 → 停止。内核说能运行（`kernel/proc.h:170` 的函数）→ 可运行。顺序就是优先级：又僵死又能运行，先报僵死 |
| 进程管理和文件服务这一段 | `:287-329` | 在等待 → 类别 0x02 加文字"等待"。被信号挂起 → 类别加文字"暂停"。文件服务阻塞原因不是无 → 按原因编号组成地址加原因文字（管道、锁、管道打开、复用等待。字符设备和套接字再加上驱动端点并调 16 的函数取驱动名。未知的原因回三个问号）。命中任何一个就添上能被信号叫醒的标记（`:328`） |
| 通信和运行标志这一段 | `:335-373` | 从内核行算出在等谁（`kernel/proc.h:187` 的宏）。是在等系统信息服务自己 → 类别 0x04 加文字（注释直说这个分支只是为了输出完整，`:339`）。谁也没等 → 按运行标志组成地址，按标志选等待原因的词（六个词，`:350-363`）。等任意谁 → 只添能被信号叫醒的标记（`:371`），地址不动 |
| 最后一步 | `:380-389` | 地址还是零 → 按端点号组成地址，调 16 的函数写进程名（带括号）。否则写回这段算出的地址。最后统一返回睡着（`:389`） |

两处如实记下来（不是本篇的缺口，是 C 代码的现状）：

- 待办一（`:352-353`）：同一个条件写了两遍，第二遍永远执行不到。不影响结果（该报的词照报），像是复制代码时写错了。Rust 侧按"或一次"实现，结果一样。
- 覆盖的规则：通信这一段的两个分支会**覆盖**上一段算出的地址（直接赋值，`:340` 和 `:349`），但能被信号叫醒的标记不清零（`:328` 已经添上了）。等任意谁的分支不动地址。所以"后算的覆盖地址、先添的标记保留"，§1.3 的顺序结论的证据在这里。

### 2.3 三个填写函数（`proc.c:398-504`）

| 函数 | 位置 | 行为 |
|------|------|------|
| 公共填写 | `:398-455` | 线程号填端点号（注释说拿端点号当线程号，ps 命令能用它，`:411-416`）。挂起时间和睡眠时间：内核任务用开机时间，普通进程用开机时间减去启动时间（`pm/mproc.h:64`）再除以频率。睡眠时间：内核任务固定填零（内核任务不记睡眠时间，`:435-436`），普通进程用出队时间差除以频率（`kernel/proc.h:57`）。优先级写两处（`kernel/proc.h:30`）。处理器号照着填（`:35`）。运行时间调 16 的换算函数，用用户态时间加内核态时间算。三个处理器用量调平均负载接口算（`libsys/cpuavg.c:250`，注释直说和 NetBSD 算法不一样，但够用，`:447-454`） |
| 内核任务填写 | `:461-482` | 清零。标志填常驻内存加能叫醒加内核任务。状态固定填睡着。进程号填槽号减任务数（输出字段是无符号三十二位，负数先回绕成大整数）。等待地址用回绕值左移八位再或上类别零（高位补零，不是符号扩展）。等待原因写任务真名，名字栏写死"内核"（ps 显示名字时任务统一显示这个，`:471-476`）。再调公共填写 |
| 普通进程填写 | `:487-504` | 清零。标志填常驻内存。状态函数的结果按位或进标志字（`:498-499`）。进程号和名字从进程管理行复制（`pm/mproc.h:28` 和 `:80`）。再调公共填写（槽号是任务数加槽位） |

时钟从哪里来（`:408-409` 的读滴答和读频率）归要数据的代码管，本篇只规定拿到滴答数之后怎么算出秒，不规定滴答从哪来。

### 2.4 查询入口（`proc.c:509-593`）

| 步骤 | 位置 | 行为 |
|------|------|------|
| 参数检查 | `:520-528` | 名字长度必须是 3（进程号、每行字节数、最多行数）。进程号小于负一、每行字节数小于等于零、最多行数小于零 → 参数错 |
| 拿表 | `:530-531` | 拿表失败 → 参数错（连拿表失败都报参数错，这是 16 的规矩定完之后的事） |
| 每行字节数 | `:534` | 取每行字节数和结构体大小的小者。调用的人可以报比实际大的步长（向前兼容），只拷贝结构体那么多 |
| 内核任务段 | `:542-557` | 进程号小于等于零时先过一遍全部内核任务槽。在范围内且还有名额才填写拷贝（`:544`）。偏移量无条件按步长前进。进程号等于零过完任务段直接返回（注释解释：内核任务算成零号进程的线程，因为负一已经表示全部进程了，`:536-541`） |
| 普通进程段 | `:563-587` | 进程号大于零精确查槽（查不到或者已经僵死 → 找不到进程，`:564-566`）。进程号小于零全扫一遍（跳过不在用的）。同样的"在范围内且有名额才拷贝、偏移量无条件前进" |
| 预留 | `:589-590` | 只要是只估计长度的那次调用，而且问的是全部进程，再多留八个步长的位置（两次调用之间可能有新进程出生，见 16 §2.1） |

"在范围内且有名额才拷贝、偏移量无条件前进"（`:544` 和 `:580` 的范围检查加名额检查，`:551` 和 `:586` 的无条件前进）的意思是：调用的人传超大步长时，输出是稀疏数组，偏移量是逻辑位置，不是拷了多少。这是 06 拷贝出去语义在进程信息上的实例，18 的第二套格式也一样。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 清醒的四个条件变成四个是非值 | 直接读进程标志位和内核停止标志（`:243-253`） | 四个是非值做参数的判断函数（`os/servers/mib/src/proc/lwp.rs`） | 标志*值*归进程管理和内核管，判断的先后顺序才是本篇的语义。是非值加顺序判断把顺序固定死，具体的值不固定 |
| D2 | 文件服务的阻塞原因变成枚举 | 按没起名的数字分支（`:295-322`） | 阻塞原因枚举加映射函数（`lwp.rs`，值旁边注明出处 `vfs/const.h:19-25`） | 原因编号的值是文件服务的契约，本篇只拥有"编号到文字"的映射。单独一个函数做映射，未知的值回三个问号，和源码同行为 |
| D3 | 等谁分三种情况 | 按端点值直接分支（`:337-373`） | 三种目标情况的枚举（`lwp.rs`） | 三个特殊端点的值是相对端点算出来的，16 已经论证过不固定值。调用的人先把端点值翻译好，本模块只分情况 |
| D4 | 时间换算用 16 的函数，频率为零时回零 | 直接除以频率（`:429` 和 `:438`，频率为零会崩溃） | 时间判断函数用 16 的换算思路，频率为零回零（`lwp.rs`） | 系统频率永不为零是要数据的代码保证的。Rust 里要先检查（和 16 一样，多出来的检查） |
| D5 | 参数检查返回成功或错误码 | 直接返回错误码（`:520-528` 和 `:564-566`） | 两个检查函数返回成功或错误码（`lwp.rs`，错误码还是 C 的码） | 和 02、10 一样，错误码不变，包装换成成功或失败两种结果 |

替代方案及否决：输出结构的 C 语言内存排布直接复制——否决。字节怎么排归架构演进 A-4 管（对外交换的格式不变就行），本模块只算出值，字节排布由要数据的代码组装。三张表布局复刻——否决（16 已经否决过，越界）。

和 Redox、NetBSD 对照着看（对照不是依据）：NetBSD 查轻量线程信息同样先估计长度再填写。Redox 的进程方案用路径字符串，不用固定步长。Minix 选固定步长加取小者截断，本模块保留这个约定（§2.4 每行字节数那行）。

## 4 实现详解

### 4.1 模块结构

```
os/servers/mib/src/proc/
├── mod.rs    — 重导出（本篇加了轻量线程模块的一行）
├── tables.rs — 16（查槽、写等待文字、滴答换算、余量，本篇拿来用）
└── lwp.rs    — 本篇：清醒判断、阻塞解码、睡眠判断、等待地址类别、
                 内核任务判断、用户标志、时间判断、参数检查、预留
```

### 4.2 核心符号表

| 符号 | 来源 | Rust 位置 | 行为 |
|------|------|-----------|------|
| 清醒的四种情况 | `:243-253` | 清醒判断函数 | 僵死、退出、停止、能运行、睡着五选一，顺序就是优先级 |
| 进程管理和文件服务的三个分支 | `:287-322` | 阻塞解码加睡眠判断前半 | 等待、暂停、原因文字加能叫醒标记 |
| 通信和运行标志的三个分支 | `:337-373` | 目标枚举加睡眠判断后半 | 装饰分支、内核标志分支、端点分支 |
| 最后一步 | `:380-387` | 睡眠判断尾段 | 没有前面算出的地址才按端点号组成地址加进程名 |
| 内核任务填写 | `:461-482` | 内核任务判断函数 | 负进程号、全睡、内核名 |
| 普通进程的标志 | `:497-499` | 用户标志函数 | 先填常驻内存加状态函数带出的标记 |
| 时间 | `:425-438` | 时间判断函数 | 任务和进程两路加零频率检查 |
| 参数检查 | `:520-528` 和 `:564-566` | 两个检查函数 | 参数三项检查加找不到进程 |
| 预留 | `:589-590` | 预留函数 | 全量估计才多留八步 |

### 4.3 不变量

| 不变量 | 谁保证 | 证据 |
|--------|------|------|
| 清醒的判断顺序不能换 | 判断函数的分支顺序和 C 一致 | `:243-253` |
| 后面算出的地址覆盖前面的 | 睡眠判断里两个分支无条件赋值 | `:340` 和 `:349` |
| 标记只添不减 | 能叫醒标记全程做或运算 | `:328` 加 `:371` |
| 未知的原因不崩溃 | 解码函数未知走空，文字回三个问号 | `:318-321` |
| 偏移量由调用的人按步长算 | 本模块不拥有偏移量，只给预留的数学 | `:544`、`:580`、`:589-590` |
| 重复的条件只算一次 | 运行原因用单个是非值（C 写重一遍不影响结果，本模块合并成一个） | `:352-353` 的待办 |

### 4.4 和 C 不一样的地方

§2 有四节，§4 是一个模块：拿表和拷贝的执行动作、读时钟和读平均负载全部归要数据的代码管。频率为零的检查和未知原因的单独处理是 Rust 建模顺带的好处（C 里分别是没定义的行为和默认分支，合法输入下两边结果一样）。类别：边界移交出去的加建模顺带的好处，都声明了。
