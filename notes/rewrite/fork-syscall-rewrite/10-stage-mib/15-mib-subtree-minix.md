# 15 — Minix 扩展子树：测试用的子树、显示计数的节点和指向进程信息的节点

> **分类**: 子系统子树 / Minix 扩展

## 1 概念

### 1.1 目标读者与前置知识

面向要跑测试八十七（C 一侧的行为约定，plan §3.5）与实现进程文件系统那一端（20）的人。前置知识：02（Minix 扩展编号）、03（实时变化的计数值）、08（节点的创建和删除，测试用的那几个删除销毁节点就是它的消费者）。

### 1.2 本章不讲什么

- 测试八十七怎么跑——那是 C 一侧的约定（plan §3.5），本篇只讲测试用的子树长什么样。
- 进程本体——那是 16 到 20 的事（本篇只登记两个指向进程信息的节点）。
- 显示计数的节点的读取执行——向别的服务要数据的代码的事（值是实时变化的计数器，形状在 03）。

### 1.3 测试用的子树：十二个节点，每个都是一道断言

测试子树是 Minix 的测试八十七给自己留的。十二个节点，每个对应测试里的一个或几个断言：十六进制字节序（`0x01020304`，大小端一读便知）、布尔可写翻转、六十四位读写、字符串与结构体的短写长写与截断、私有读写拒绝（初值负五千三百七十五，非特权写了必须拒）、任意写放行、三个用来删除的节点、私有子树、永久保留（初值一，无描述）、空描述对齐。

空描述对齐值得停一下：源码注释说"连描述数组的对齐本身都被测，轻动既有字段"（`minix.c:14-18`）。意思是测试不仅查值，还查"枚举描述时返回的描述数组在内存里对不对齐"。加新字段永远可以，改旧字段（哪怕改个描述字符串的长度）都可能让对齐测试变红。这是考题的自我约束：题目本身也是被测对象。

测试用的子树默认包含（测试子树开关等于一，生产可关，关掉之后测试八十七通不过。头文件注释原话，`mib.h:23` 附近）。开关是编译期的：关掉则整棵测试子树不存在，不是"存在但拒绝访问"。这里容易按字面理解错：开关不在运行时，在构建时，关掉之后不存在，开着才存在。

秘密子表是测试子树里唯一的嵌套：`secret` 节点下挂一张只有一个儿子的表，儿子叫 `value`，值一万两千三百四十五，描述是句玩笑话（"我行李箱的密码"，`minix.c:9-12`）。玩笑归玩笑，测的是"私有子树"的查找与权限：整棵子表标私有，非特权连 `secret` 这一层都进不去，更别说读里面的值。07 的权限位在这里第一次有了完整的真实例子。

三个用来删除的节点（`deleteme`、`destroy1`、`destroy2`）是 08 的消费者：测试创建、删除、销毁走一遍，这三个节点就是给删除测试准备的。`destroy1` 初值一百二十三无描述，`destroy2` 初值四百五十六有描述，有没有描述本身也是考项（对齐测试的一部分）。`permanent` 永久保留：永久标志加只读，初值一，无描述，谁也删不掉，删它必须失败。

### 1.4 显示计数的节点：树自报家门

统计子树只有三个节点，全是指向实时变化的全局变量的指针叶子：节点总数、动态对象数、已挂载远端数（03 的三个计数值）。树每答一次查询就数一遍自己。这是 C 惯例里"指针叶子"在此唯一的三个例子（03 讲过指针叶恒为指针）：读到的不是快照，是读那一刻的真值。

为什么是三十二位无符号指针而不是快照值？因为计数器每时每刻都在变，快照一存就旧。指针叶子把"读"推迟到真正拷贝的那一微秒，值永远新鲜。代价是连读三次，两次读到的数可能已经不一样了。调用的人如果连读三次做一致性检查，本身就不成立。新鲜和一致不可兼得，树选了新鲜。

### 1.5 指向进程信息的两个节点：门后的本体在二十篇

进程子树只有两个函数节点：`list`（结构形，整表快照）、`data`（节点形，单进程快照）。函数体全在 20（进程文件系统的消费者约定：负进程号表示内核任务）。本篇只登记这两个节点，不讲节点后面的事。节点在这里，本体在 20，枚举是两篇的握手点。

### 1.6 表里没给网络栈留位置，是设计不是遗漏

顶层表只有三个位置：测试用的子树、显示计数的节点、指向进程信息的节点。网络栈那条注释写着"经远端挂载，不在此"（`minix.c:78`）。没留位置是设计：网络栈启动后用远端注册把自己的子树挂载进来（12、22），静态表不留位置。留位置反而是错：静态位置和运行时挂载会冲突，"谁覆盖谁"说不清。不留位置，挂载逻辑就干净。

### 1.7 和别的操作系统对照着看

Linux 内核自测和内核调试文件系统是"测试子树"思想的相近的两种做法：自测是用户态程序跑断言，调试文件系统是内核主动暴露内部状态给测试读。Minix 把测试用的子树直接做进正式的系统信息树（构建开关控制），比两者都激进：测试读的和用户读的是同一棵树、同一套代码路径，测到的就是用户拿到的。代价是生产构建必须记得关掉，开关注释把"关掉之后测试通不过"直白地写着，就是怕有人悄悄关掉还指望测试过。

Redox 的对照点在方案测试：每个方案带一套测试，跑的是方案接口的约定（打开、读、写、关闭的往返），而不是方案内部的数据。Minix 的测试子树反过来：测的恰恰是内部数据（字面量、权限位、删除），因为系统信息树的"正确"就是"值对"，接口形状在 02 早已固定。两者的分工正好互补：接口约定归协议篇，数据正确归测试子树这篇。

### 1.8 小结

测试用的子树十二个字面量精确到改一个数测试就变红，显示计数的节点照的是三个实时计数值，指向进程信息的节点本体在二十篇，而网络栈的位置故意空着等运行时挂载。抓住这四样，15 就通了。

秘密子表（`minix.c:9-12`）：编号零，名 `value`，值一万两千三百四十五，描述是那句行李箱玩笑。字符串与结构体缓冲是文件级静态数组（十六字节与十二字节，`:7`），测的是"短写进、长写截断"的完整语义，不是零拷贝。

"生（删它）"和"死（删它）"的意思：这三个节点生下来就是给删除测试用的，测试会把它们删掉，再检查删干净没有。

### 2.2 显示计数的表（`minix.c:47-57`，三指针叶）

三指针无符号整型：节点数、对象数、远端数（名副其实）。指针目标就是 03 的三个计数值，"显示谁"在类型层面能查到。

### 2.3 指向进程信息的表（`minix.c:59-66`）加密顶层表（`minix.c:68-79`）

指向进程信息的表：`list`（结构函数）与 `data`（节点函数）。顶层：测试用的子树（隐藏加可写，编译开关控制）与显示计数的节点（只读）与指向进程信息的节点（只读），加网络栈没留位置的注释（`:78`）。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 字面量写进类型 | 表字面量 | 带值的枚举变体（十六进制整数带 `0x0102_0304` 等，`os/servers/mib/src/subtree/minix.rs:24`）加十二行常量表（`:69`） | 测试用的数字改一个测试变红。字面量进类型，不是注释 |
| D2 | 没留位置变成断言 | 注释（`:78`） | 没留位置的常量（`minix.rs:225`）加测试断言顶层表无此编号 | "没留位置是设计"值得测试：后人"补全"网络栈进静态表，测试即变红 |
| D3 | 显示计数变成枚举 | 三指针叶 | 三种情况的枚举（`minix.rs:171`）加编号表 | 指针目标就是 03 三个计数值。枚举让"显示谁"能按名字搜索 |
| D4 | 指向进程信息变成枚举 | 两函数节点 | 两种情况的枚举（`minix.rs:191`） | 本体在 20，节点在这里。枚举是两篇的握手点 |
