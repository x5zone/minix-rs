# 19 — 进程参数：读另一个进程的命令行和环境

> **分类**: 进程信息 / 跨地址空间逐页读
> **源码**: `minix3/minix/servers/mib/proc.c:918-1176`（查询入口 `mib_kern_proc_args`）
> **说明**: 进程信息五篇的第四篇。ps 命令想显示进程的命令行和环境变量，数据在目标进程自己的地址空间里。本篇讲怎么一页一页走过去、页数预算怎么定、超了怎么截断。

---

## 1 概念

### 1.1 目标读者与前置知识

面向要实现本篇功能的人。前置知识：16（按进程号查槽、拿表、多留八个位置、旧缓冲区长度）、06（范围检查和拷出）、10（查询函数在分发里的位置）。"启动信息结构"指进程启动时内核放在它地址空间顶上的那一小块信息，里面记着命令行和环境变量的指针和个数。"启动帧"指 exec 调用时搭的整块内存，命令行和环境变量的字符串都住在里面。

### 1.2 本章不讲什么

- 状态和第二套格式——17、18。
- 整表快照——20。
- 拷出——06。

### 1.3 读别人家的内存，要有预算

读自己家的内存直接读，读别的进程的内存要请内核代劳，一页一页拷过来（`sys_datacopy`）。麻烦在于：目标进程的命令行可能被捣乱。注释把攻击算得很清楚（`proc.c:1023-1029`）：捣乱的进程可以摆一串两字节的字符串，每个都跨两页，按 256K 的上限算，能骗服务拷 1G 数据。所以走之前先定预算：字符串页最多拷"上限除以页长"的两倍（`:1051`），向量页不计（向量是线性走的，没法捣乱，`:1027-1029`）。预算花完就停，返回已经拷到的，不报错。

四个查询分两类。查个数（几个命令行参数、几个环境变量）只读启动信息结构里的两个数字，不碰字符串，最轻。查内容（命令行、环境变量）要走三步：先读启动信息结构拿指针和个数，再顺着指针数组逐个找字符串，最后把字符串拼进输出。估计长度的那次调用（旧缓冲区是空）直接报上限，不走（`:991-998`）。

### 1.4 和别的操作系统对照着看

Linux 读 `/proc/进程号/cmdline`，是内核直接拼好返回的，进程捣乱顶多让内容难看，不会让内核多干活。NetBSD 和 Minix 是调用的人自己走：NetBSD 问长度 blindly 返回上限（注释原话，`:978`），Minix 算个更准的上限（帧长和上限取小再按页取整，`:981`）。Redox 没有对等物：它的进程方案不暴露命令行，走的是启动时传参的路子。三者的账不一样：Linux 把复杂度放在内核拼字符串，NetBSD 把复杂度推给调用的人重试，Minix 把复杂度放在预算和截断。本篇保留 Minix 的预算，因为捣乱的进程是真实存在的威胁模型，不是假想。

### 1.5 小结

四个查询两种走法：查个数只读两个数字，查内容要逐页走。逐页走有三道关：向量页复用、字符串页预算、输出截断。预算的数和截断的规矩是本篇的全部内容，§2 看 C 代码怎么走这三道关。

## 2 C 源码分析

### 2.1 参数检查和查槽（`proc.c:933-960`）

名字长度必须是 2（进程号、查什么），否则参数错（`:933-934`）。查什么必须是四个之一，否则不支持（`:939-947`，注意这里是不支持不是参数错：形状对，操作不对）。拿表失败报参数错。查不到槽或者僵死报找不到进程（`:949-956`，和 18 同样的语义）。查个数且是估计长度的那次调用，直接报四个字节，不碰目标进程（`:959-960`）。

### 2.2 启动信息结构和上限（`proc.c:962-1002`）

从目标进程地址空间顶上拷启动信息结构（`:962-965`），拷不到报参数错。上限取帧长和 exec 大小上限的小者，再按页取整（`:981`）。长注释（`:967-980`）解释为什么这样算：帧本来应该够大（字符串全在里面，不能重叠），但调过改名函数的进程指针可能指到帧外面，不过那部分数据不超过两页，取整吸收掉了。NetBSD  blindly 报上限，我们报得更准一些。

查个数直接拷数字（`:984-989`）。查内容且是估计长度报上限（`:991-998`）。否则记下指针和个数，进逐页走。

### 2.3 逐页走（`proc.c:1004-1171`）

长注释先把七个停下来的条件列全（`:1014-1021`）：目标进程拷失败、向量读完、遇到空指针、输出满了、到上限了、预算花完了、拷出失败。然后是三块缓冲：一页放向量、一页放字符串、一页攒输出（`:1009-1012`），短字符串不值得每次都调拷出。

向量地址在零页或者没按指针大小对齐，直接返回零（`:1040-1041`，空答案不是错）。调用的人给的长度先截到上限（`:1048-1049`）。预算按公式算（`:1051`）。主循环：向量换页才拷（`:1065-1070`），读指针，目标零页就停（`:1076-1077`）。字符串页命中向量页或已存的字符串页就复用，否则花预算拷新页，预算没了或者拷失败就停（`:1086-1102`）。页内找零字节（`:1114`），没找到整页都是字符串的一部分，翻到下一页继续（`:1118-1121`）。每段先截到剩余长度（`:1124-1125`），攒输出满一页就拷出（`:1132-1144`）。向量地址加一个指针，个数减一（`:1159-1160`）。最后把攒的尾巴拷出去（`:1164-1168`），断言没超（`:1170`），返回实际长度（`:1171`）。

和别的系统调用不一样的地方：输出超了截断返回实际长度，不报缓冲区太小（`:1031-1034`）。库函数靠这个行为，改了会断。截断的数据结尾不一定有零字节，调用的人自己处理（`:1036-1038`）。

源码里有一处待办（`:1062-1063`）：字符串应该跟在向量后面，可以从向量开头拷。如实记下，不是本篇缺口。

### 2.4 常量

四个查询号住值表（`sysctl.h:677-680`：命令行 1、个数 2、环境 3、环境个数 4）。页长和 exec 上限归构建头文件，本篇取参，不固定（和 16 同一个道理）。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 四个查询变成枚举 | 按数字分支（`:939-947`） | 四种情况的枚举加解码函数（`os/servers/mib/src/proc/proc_args.rs`），未知回不支持 | 数字的值进值表。本模块只认是哪种 |
| D2 | 参数和槽位检查沿用 | 各写一遍 | 名字长度自己查，槽位检查复用 18 的函数（`proc_args.rs`） | 18 已经写过同样的"查不到或僵死报找不到"，再写一遍是重复。复用写进注释 |
| D3 | 上限和预算变成函数 | 内联公式（`:981`、`:1051`） | 上限函数加预算函数，帧长、上限、页长取参（`proc_args.rs`） | 三个输入有两个归构建头文件，固定数字是编造可移植性。公式值得测，值不值得固定 |
| D4 | 页定位变成三种情况 | 三分支散写（`:1086-1102`） | 向量页、已存页、拷新页三变体加定位函数（`proc_args.rs`） | 复用规则是本篇最容易错的地方，变体名让三条路一目了然 |
| D5 | 分段和截断变成函数 | 内联（`:1114-1125`） | 找零分段函数加剩余截断函数（`proc_args.rs`） | 含零和不含零是两条路，截断数学值得独立测 |

替代方案及否决：三块缓冲直接建模——否决。缓冲是拷出循环的实现细节，归要数据的代码。向量地址零页就报错——否决，C 明确返回零（`:1041`），改成报错是改语义。预算花完报错——否决，C 明确停下返回已拷到的（`:1091-1094`），这是预算的语义。

## 4 实现详解

### 4.1 模块结构

```
os/servers/mib/src/proc/
├── mod.rs      — 重导出（本篇加了两行）
├── tables.rs   — 16（拿表，本篇拿来用）
├── proc2.rs    — 18（槽位检查，本篇复用）
└── proc_args.rs — 本篇：查询枚举加解码、名字检查、个数估计判断、
                   上限、预算、起步检查、旧长度截断、页定位、
                   分段、段截断
```

### 4.2 核心符号表

| 符号 | 来源 | Rust 位置 | 行为 |
|------|------|-----------|------|
| 四个查询 | `:939-947` | 解码函数 | 未知回不支持 |
| 名字检查 | `:933-934` | 名字检查函数 | 长度必须是 2 |
| 槽位检查 | `:952-956` | 复用 18 的函数 | 查不到或僵死报找不到 |
| 个数估计 | `:958-960` | 估计判断函数 | 查个数加空缓冲才走 |
| 上限 | `:981` | 上限函数 | 取小再按页取整 |
| 预算 | `:1051` | 预算函数 | 上限除页长乘二 |
| 起步检查 | `:1040-1041` | 起步函数 | 零页或不对齐回空 |
| 旧长度截断 | `:1048-1049` | 截断函数 | 取小者 |
| 页定位 | `:1086-1102` | 定位函数加三变体 | 复用两页，花预算拷新页 |
| 分段 | `:1114-1121` | 分段函数 | 含零截断，不含整页 |
| 段截断 | `:1124-1125` | 段截断函数 | 截到剩余长度 |

### 4.3 不变量

| 不变量 | 谁保证 | 证据 |
|--------|------|------|
| 未知查询进不来 | 解码函数回不支持 | `:945-946` |
| 僵死读不到 | 槽位检查 | `:955-956` |
| 预算只花在字符串页 | 定位函数只在拷新页分支花 | `:1091` |
| 输出不超调用的人给的长度 | 段截断加旧长度截断 | `:1048-1049,1124-1125` |
| 超了截断返回，不报错 | 调用约定（文档声明，代码不管） | `:1031-1034` |

### 4.4 和 C 不一样的地方

§2 有四节，§4 是一个模块：逐页拷、输出攒批、拷出循环按 §1.2 移交出去。页长和上限取参（D3），合法输入下两边结果一样。类别：边界移交出去的，已经声明。
