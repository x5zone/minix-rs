# 14 — 虚拟内存与硬件子树：两棵小表和三个要算清楚的数

> **分类**: 子系统子树 / 虚拟内存加硬件
> **源码**: `minix3/minix/servers/mib/vm.c`（全文 154 行）、`minix3/minix/servers/mib/hw.c`（全文 140 行）
> **说明**: 两棵小表（虚拟内存十三个位置填四个、硬件十六个位置填十个）和三个纯计算（一分钟占几个槽、页长是二的几次方、宽数变窄数在哪里截断）。13 的写法第二次用。

## 1 概念

### 1.1 目标读者与前置知识

面向照 13 的写法实现小子树的人。前置知识：09（普通读写复用，本篇的函数节点同样调它把算好的整包拷贝出去去）、13（表加清单加构建值只记名字的老实做法）。"负载均值"指一分钟、五分钟、十五分钟三个窗口的平均负载，"内存统计"是 `top` 命令看的那组数字。

### 1.2 本章不讲什么

- 虚拟内存统计的读取执行（向内核要负载历史、要内存统计、要机器信息）——向别的服务要数据的代码的事，16 也读同一批数据，执行代码跨篇复用。
- 其余子树——13 已过，15 下站。

### 1.3 第一个数：一分钟占几个槽

内核每六秒记一个槽，存一百五十个槽，也就是十五分钟的历史（十五乘六十除以六，一百五。对外接口定死的数字，改了会断消费端，`minix/type.h:88-95`）。一分钟就是十个槽，五分钟五十个槽，十五分钟一百五十个槽（分钟数乘六十除以六，`vm.c:43`）。

平均值怎么算？把窗口内所有槽的进程滴答加起来，除以窗口的总滴答数，再乘一百。分母要扣掉最新那个槽还没填满的部分（`vm.c:38-39` 先算欠填，`:65` 再扣）。举个具体数：时钟频率一百，每槽六百滴答，一分钟窗口十个槽共六千滴答，最新槽欠一百，窗口内进程滴答三千，平均值就是一百乘三千除以五千九百，约五十。刻度固定一百（`:70`）。公式从老 Minix 的 C 库继承下来（`:32-34` 注释），服务只负责算对，不管显示效果。

历史槽按取模绕回取（`:55`）：最新槽往前数，编号减到零下就绕到一百四十九。这是环形缓冲区的标准写法，槽数必须是历史深度（一百五），改了就和内核的记录对不上。

### 1.4 第二个数：页长是二的几次方

内存统计要报"页位移"给 `top` 命令：页长四千零九十六，就是二的十二次方，位移填十二。算法是从零往上试，一左移若干位等于页长就中（`vm.c:100-104`），试多少位取决于指针宽度（三十二位系统试三十二次）。全试完没中就留零（结构体先整体清零，`:90`，没中就是零）。不是二的幂的页长报位移零，调用的人看到零就知道没有命中。

顺带说一句诚实话：这个结构体的绝大多数字段都没填对，头顶注释直说"先保证 `top` 够用"（`vm.c:93-97`）。部分填充是声明过的现状，不是缺陷。七个填了的字段是：页长、页掩码（页长减一）、位移、总页数、空闲页数、文件缓存页数（借了没用的字段位，注释写明了借用），再加一个 Minix 自创的最大连续物理内存（同样借空位，注释警告 NetBSD 如果征用这个位置就得搬家，`:108-114`）。字段借用的注释写得越直白，后人搬家越不容易出错。

### 1.5 第三个数：宽数变窄数在哪里截断

物理内存和用户内存各有两个版本：三十二位版本和六十四位版本，同一个函数按节点大小分流（`hw.c:31,67`）。三步走：先按六十四位算全（总页数乘页长，**先转成六十四位再乘**，不然页数多了先溢出，`:29,57`），用户内存再减去内核占用（宁可得零也不回绕，`:62-65`），三十二位版本超出上限就截到上限（`:32-35`）。

拿数字走一遍：一百万页，每页四千零九十六字节，总字节数约四十亿。如果先按三十二位乘再转成六十四位，页再多一倍就溢出了。所以顺序不能错：先转六十四位，再乘。用户内存同理先算全，再减内核占用：内核账目比总量还大，说明数据坏了，返回零，不返回负数（无符号数没有负数，回绕会变成天文数字）。三十二位版本最后截断：超上限报上限，不直接丢掉高位。这样三十二位程序拿不到真值，但能拿到上限这个可用的数，而不是溢出后的错数。

在线处理器数最简单：问内核要机器信息，把处理器个数拷贝出来（`hw.c:81-95`）。配置数（构建期宏，编译时定了几个）和在线数（运行时测了几个）是两个事实，两个节点，不要合并且不要互推。

机器字符串是 C 的条件编译：i386 分支写 `i386`，arm 分支写 `evbarm`，别的架构直接编译失败（`hw.c:5-13`）。Rust 侧是六十四位新行（架构演进，§3 的第五个决策），不是 i386 分支的修改。新架构加一行，旧行不动。

### 1.6 和别的操作系统对照着看

Linux 把内存信息做成文本：`/proc/meminfo` 一行一个冒号分隔的键值对，人能直接读，程序用字符串解析。代价是每次读都要格式化数字，解析也要容错。NetBSD 和 Minix 走二进制结构路线：负载结构、内存统计结构都是定长结构，一次拷贝，调用的人按偏移解释。好处是快且精确，代价是布局就是接口，改一个字段的偏移就断了所有消费者。所以页掩码、刻度、历史深度这些数字在注释里都被标成"不能改"。

Redox 选了第三条路：系统方案下按路径读，文本和二进制混用，简单信息给文本（人能读），批量统计给结构。它的取舍对本篇有直接启发：**交换格式保守（布局一个字节都不许动），内部实现自由（怎么算都行）**。本篇的 Rust 设计正是这个取舍：常量和公式名字可以起得清楚，但历史深度一百五、刻度填一百、欠填公式的形状必须和 C 逐行对齐，测试把每个数字固定死。

### 1.7 小结

虚拟内存这边是两个函数，负载平均整个算，内存统计填上够用的七个字段，外加两个常数：最大睡眠二十是有出处的，零是因为 Minix 进程没有内核栈。九个空着的位置和 13 一样是约定。硬件那边是三个函数，物理内存和用户内存各管两个版本，在线处理器数单独一个，外加四个架构相关的字符串和三个常数，六个空着的位置同样是约定。下一棵子树的读法和这两棵一样：先看计算，再看表。

## 2 C 源码分析

### 2.1 负载均值（`vm.c:12-73`）

读内核负载信息（失败返回参数错误，`:27-28`）。每槽滴答等于六乘频率（`:37`）。算最新槽欠填多少（`:38-39`）。三个窗口各累加历史槽（`:41-57`，取模防绕回，`:55`）。按平均公式算（`:65-67`）。刻度填一百（`:70`）。整包拷贝出去（`:72`）。断言三窗口数组和分钟数组等长（`:25`）：分钟表改了，结构体的数组必须同步改，断言把两者绑在一起。

### 2.2 内存统计（`vm.c:79-117`）

读虚拟内存统计（失败返回参数错误，`:87-88`）。清零。填七个字段（页长、掩码、位移、总页、空闲、文件缓存借空位，`:98-114`）。拷贝出去。头顶待办（`:93-97`）："绝大多数字段没填对，`top` 够用先"。部分填充是声明过的现状，不是缺陷。

### 2.3 虚拟内存表（`vm.c:120-144`，四填九空）

负载函数、内存统计函数、最大睡眠（和 13 的等待上限同源的二十）、无内核栈（零，"Minix 进程没有内核栈"，`:138-140`。有理由的零，不是缺省值）。空着的九个位置（仪表、旧统计、内核内存页、匿名配额上下限、执行配额上下限、文件配额上下限）。

### 2.4 硬件三个函数（`hw.c:18-95`）

物理内存（`:18-40`）：读统计数据。用六十四位乘。三十二位版本截断，六十四位版本直出。用户内存（`:45-76`）：同上一步再减内核占用（再读用量，失败返回参数错误，`:59-60`）。减法饱和。两个版本分流。在线数（`:81-95`）：问机器信息，处理器个数直接拷贝。

### 2.5 硬件表（`hw.c:98-130`，十填六空）

机器（字符串，架构相关）、配置数（构建宏）、字节序（小端四千一百二十三）、物理内存与用户内存（函数，三十二位版本）、页长（四千零九十六）、机器架构（字符串）、六十四位两个版本（函数）、在线数（函数）。空着的六个位置（型号、磁盘名、输入输出统计、对齐、控制台魔数、统计名）。架构字符串：C 只认识两种，第三种编译失败（`:5-13`）。六十四位是新增行（架构演进，§3 第五个决策）。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 窗口数学变成常量加函数 | 六、一百五、一百散写 | 三个常量加四个函数（`os/servers/mib/src/subtree/vm.rs`） | 对外接口定死的数字（改了断消费端）值得起名字。除零（停走的钟）回空值，不崩溃 |
| D2 | 位移搜索变成函数 | 循环内联五行 | 搜索函数，指针宽度做参数（`vm.rs`） | 三十二位 `1U` 上限是 C 的坑（搜到三十二封顶）。指针宽度参数化让六十四位搜索合法化（架构演进加宽只延长搜索，不改变命中） |
| D3 | 两个版本分流变成判断函数加计算函数 | 按节点大小等于整型大小分支，两处 | 版本判断函数加截断函数（`os/servers/mib/src/subtree/hw.rs`）加总字节函数（先转成六十四位再乘）加减内核占用函数（饱和） | "先转成六十四位再乘"和"减法饱和"是两个独立的不变量，值得独立测试 |
| D4 | 构建期值延续 13 的老实做法 | 构建宏 | 只记宏名字的变体（`hw.rs`） | 和 13 第二个决策一样：值归构建，名字归表 |
| D5 | 架构字符串新增行 | 未知架构编译失败（`:12`） | 机器字符串常量等于 `x86_64`（`hw.rs`） | 六十四位是新架构行，不是 i386 分支。架构演进三处标注（本文档本行、设计快照、代码注释） |

替代方案及否决：负载整包建模（负载结构和负载信息结构对等复刻）——否决。结构布局是向别的服务要数据的代码的事（和 16 同源）。本篇只写数学。
