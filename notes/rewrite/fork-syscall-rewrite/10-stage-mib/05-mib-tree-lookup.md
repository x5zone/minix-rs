# 05 — 系统信息库树查找：静态数组直接索引，动态链表有序走查

> **分类**: 查找算法 / 双通道 verdict
> **源码**: `minix3/minix/servers/mib/tree.c:12,34-81`（`IS_STATIC_ID` + `mib_find` 全段）
> **说明**: 按 id 找结点：静态数组 O(1)，动态有序链表 O(n) 带提前收工；落空时顺手报出插入点（08 复用）。分发（10）每走一步名字调一次它，理解成本要对得起调用频率。

---

## 1 概念

### 1.1 目标读者与前置知识

面向要读分发（10）和动态节点（08）的读者。前置知识：03（静态 id 判定语义、dynode 形状）、04（`csize/clen` 是点名数出来的）。复杂度符号 O(1)/O(n) 按常规理解。

### 1.2 本章不讲什么

- 名字分量怎么一层层走下来——那是 10 的事（本篇只讲**一层**的查找）。
- 动态结点怎么插/删——那是 08 的事（本篇只报插入点，不管插入）。
- 静态表的内容——那是 04/13/14/15 的事。

### 1.3 为什么两条路

静态编号是编译期排好的连续编号（0 到表长减一），查该编号直接用数组下标即可，时间复杂度为常数。动态编号是用户运行时自选的号（从 1024 起，但用户可以指定编号，08 细讲）——编号分散无法建稠密数组，只能串成链表。链表按编号排好序，好处是查到"编号更大"就可以提前结束（提前结束）：要找 1030，看到 1041 就不用往后看了。10 的分发循环每消耗一个名字分量就调一次查找——这是热路径，所以"静态数组先行、动态链表有序"这个形状值得一篇讲透。

三条检查按顺序执行需牢记：**负数编号直接视为未找到**（连数组都不看）→ 静态数组命中则直接返回（不再走链表）→ 数组空位或编号超出静态范围才走动态链表。空静态槽（标志为零）**不终止搜索**——它只是"这个位置无人占用"，不能证明"该编号无人使用"，动态链表里可能有。

### 1.4 小结

负数编号直接未找到 → 静态数组以常数时间命中则返回 → 有序链表线性走查但可提前结束。查找未找到时会附带告知适合插入的位置，08 创建时可直接使用。

## 2 C 源码分析

### 2.1 `mib_find` 全段（`tree.c:34-81`）

| 步骤 | C 位置 | 行为 |
|------|--------|------|
| 负数守卫 | `:40-41` | `id < 0` 直接 NULL（元标识符 QUERY/CREATE 那些负数**不走这里**——10 在调查找前先截获，见 10） |
| 静态路 | `:48-57` | `IS_STATIC_ID`（`id < size`，无符号）+ `flags != 0` → 返回结点；`prevpp` 置 NULL（静态不可删） |
| 动态路 | `:69-78` | 有序链表走查；相等返回（`prevpp` 置链环，供删除）；`dynode_id > id` 提前跳出 |
| 落空 | `:81` | NULL |

注释（`:59-67`）把设计理由写全了：用户自选号 → 稠密数组不可能 → 链表是最简下一选项 → 排序换提前收工。**约束推导设计**的范本：不是"链表很好"，是"数组不可能之后链表最不坏"。

### 2.2 `prevpp`：为删除埋的钩子

第三个参数是"指向 dynode 指针的指针的指针"——删除时要改前驱的 `next`，得拿到前驱手里那个指针槽（08 的 `mib_remove` 消费）。静态命中置 NULL（删不动）；调用者传 NULL 表示"我只找不删"。本篇 Rust 侧把"删链环"编码进 `Lookup::FoundDynamic{pos}`（§4），08 取用。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 三 outcome 变枚举 | 返回指针 + `prevpp` 输出参数（NULL 兼"落空"与"不删"） | `Lookup::{FoundStatic{index}, FoundDynamic{pos}, Missing{insert_at}}`（`lookup.rs`） | NULL 在 C 里身兼两职（没找到 / 找到了但删不动）；枚举让"删链环"只存在于动态命中——静态命中的删除是类型级不可能 |
| D2 | 落空附赠插入点 | 落空只回 NULL（`mib_add` 重走一遍找插入位，08） | `Missing{insert_at}`（走查天然知道） | 一次走查同时回答"有没有"和"该放哪"；C 重走是历史实现，顺序不变、次数减一（A-2 允许的内部演进，行为等价：插入位置相同） |
| D3 | 双通道 verdict 分函数 | 一个函数两段 | `find_static`（`lookup.rs`）+ `scan_dynamic` + `find` 总装 | 10 调总装，08 调 `scan_dynamic` 复用插入点；分函数可独立测试（空位穿透、提前收工各有专测） |

替代方案及否决：动态通道换二分查找——否决，链表不是数组（08 的容器未定，BTree/Vec 二选一在 08 定）；本篇 verdict 镜像 C 的线性提前收工，容器升级时 verdict 语义不变（"有序+提前停"），08 可直接换引擎。

## 4 实现详解

### 4.1 模块结构

```
os/servers/mib/src/tree/
└── lookup.rs — 本篇：Lookup / find_static / scan_dynamic / find
```

### 4.2 核心符号表

| 符号 | 来源 | Rust 位置 | 行为 |
|------|------|-----------|------|
| 负数守卫 | `tree.c:40-41` | `lookup.rs`（`find` 首行） | 负数落空（`insert_at: 0`，无意义占位） |
| 静态路 | `tree.c:48-57` | `find_static` | 范围+活槽；空位穿透（回 `None` 继续链表） |
| 动态路 | `tree.c:69-78` | `scan_dynamic` | 相等命中；更大跳出；报插入点 |
| 总装 | `tree.c:34-81` | `find` | 守卫→静态→动态 |

### 4.3 不变量

| 不变量 | 守卫 | 证据 |
|--------|------|------|
| 静态优先 | `find` 先调静态 | `:48-56` 在 `:69` 前 |
| 空位不终止 | `find_static` 回 `None` 继续 | `:57` 落出 if，非 return |
| 有序则早停 | `scan_dynamic` break | `:76-77` |
| 负数不进数组 | 首行守卫 | `:40-41`（无符号包装风险，03） |

### 4.4 与 C 的差异说明（模式 72 CSSCM）

§2 两节 vs §4 一模块：`prevpp` 输出参数 → 枚举携带（D1），落空 → 附赠插入点（D2）。category：设计决策（行为等价：命中集合、顺序、提前停条件逐一同 C；插入点是 C 重走能算出的同一值）。
