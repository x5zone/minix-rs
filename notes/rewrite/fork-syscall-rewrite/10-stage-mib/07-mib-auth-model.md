# 07 — 系统信息库鉴权模型：每个请求最多向进程管理器查询一次，处处复用结果

> **分类**: 权限模型 / 门禁 verdict
> **源码**: `minix3/minix/servers/mib/main.c:259-275`（`mib_authed`）、`minix3/minix/servers/mib/tree.c:115,500-511,848-852,934,995-1004,1228,1389,1447-1456`（九处门）、`minix3/minix/include/minix/const.h:44`（`SUPER_USER`）
> **说明**: 决定谁可查看、私有节点是否可见、谁可写入、谁可改变树结构：每个系统控制请求最多向进程管理器查询一次是否为超级用户，结果在本次请求内缓存，后续九处检查只读缓存。读检查管可见性，写检查含两道权限杠，结构变更检查先验证身份再验证父节点可写性。

---

## 1 概念

### 1.1 目标读者与前置知识

面向要读创建/销毁/读写/分发（08/09/10）的读者。前置知识：02（标志位值）、03（谓词）。"superuser"即 uid 0，`mib_authed` 问的是"这次调用的人是不是 uid 0"。

### 1.2 本章不讲什么

- PM 怎么答（`getnuid` 跨服务查询）——transport（A-12），本篇只判答案。
- 各 handler 调门的具体上下文——那是 08/09/10/11 的事（本篇只给门的形状）。
- 拷贝/grant 语义——那是 06 的事。

### 1.3 问一次，到处用

`mib_authed` 的全部聪明才智在这三行：两个标志位（`AUTH`/`NOAUTH`）都空着才问 PM（`getnuid(endpt)==SUPER_USER`），问完置一位，以后同调用内直接读（`main.c:263-271`）。PM 查询是跨服务 IPC——一次调用里九处门，要是每处问一遍，sysctl 的延迟有一半花在问"我是谁"上。缓存把 O(门数) 次 IPC 变成最多 1 次。Rust 侧 `CallAuth::{Unknown, Yes, No}`（§4）让"问一次"变成结构：`resolve` 对已决缓存是恒等函数，想问第二次都问不成。

### 1.4 三种门

**看的门**（`visible = !PRIVATE || authed`，`:115` 查询、`:934` 描述、`:1389` 分发下钻）：公开结点人人可看，私有结点仅 superuser。私有结点的描述也是私有的（`:934` 同谓词，无第二规则）——名字可以枚举到，描述不行（11 细讲这个不对称）。

**写的门**（分发 `:1447-1456`）：只判"落叶/函数 + 带新数据"的情形，父母结点永不接受写。两道杠按序：先 `READWRITE`（只读结点连 root 都拒），再 `ANYWRITE`-或-superuser。`ANYWRITE` 不覆盖缺失的 `READWRITE`——它豁免的是"谁"，不是"能不能"。

**改结构的门**（创建 `:500-511`、销毁 `:848-852`）：先认人（非 superuser 直接 `EPERM`），再看拓扑（父亲须 `READWRITE`）。顺序是信息论：先认人，普通用户连"父亲是否可写"都学不到。

### 1.5 小结

一问（PM，最多一次）→ 三门（看/写/改结构）→ 全 `EPERM`（MIB 的拒绝词典里没有第二词：`EACCES` 从未出现，见 §2.5）。

## 2 C 源码分析

### 2.1 `mib_authed`（`main.c:259-275`）

| 行 | 行为 |
|----|------|
| `:263` | 双位皆空才问（`!(AUTH\|NOAUTH)`） |
| `:265-268` | `getnuid(call_endpt)==SUPER_USER(0，const.h:44)` → 置 `AUTH`，否则 `NOAUTH` |
| `:271` | 回 `AUTH` 位（非零即是） |

`call_flags` 还装别的吗？`mib.h:49-50` 只定义这两位——`call_flags` 就是鉴权缓存，别无他用。

### 2.2 九处权限检查全表

| 序号 | 位置 | 场景 | 触发条件 | 拒绝方式 |
|---|------|--------|------|------|
| 1 | `tree.c:115` | 枚举查询时的可见性检查 | 节点标记为私有且调用者非超级用户 → 不可见（返回值域留空） | 静默隐藏（不返回错误码） |
| 2 | `:500` | 创建节点时的超级用户检查 | 调用者非超级用户 | 权限不足（EPERM） |
| 3 | `:511` | 创建节点时父节点可写性检查 | 父节点未标记为可读写 | 权限不足（EPERM） |
| 4 | `:848` | 删除节点时的超级用户检查 | 调用者非超级用户 | 权限不足（EPERM） |
| 5 | `:852` | 删除节点时父节点可写性检查 | 父节点未标记为可读写 | 权限不足（EPERM） |
| 6 | `:934` | 读取描述时的私有检查 | 节点私有且调用者非超级用户 → 描述长度置零 | 返回长度零（不报错） |
| 7 | `:1228` | 写入大数据时非特权用户的内存分配限制 | 非超级用户且需分配超过暂存区大小 | 权限不足（EPERM，对应架构演进三） |
| 8 | `:1389` | 分发下钻时的可见性检查 | 节点私有且调用者非超级用户 | 权限不足（EPERM） |
| 9 | `:1447-1456` | 分发阶段的写入权限两道检查 | 一、节点不可写则拒绝；二、无任意用户可写标记且非超级用户则拒绝 | 权限不足（EPERM） |

（`:995/:1004` 是描述设置路径的同谓词复用，11 归属；`:1585/:1632` 是挂载点的位过滤，12 归属。）

### 2.3 拒绝词典：只有 `EPERM`

九处门包含静默隐藏（1、6，返回"无"而非错误——枚举攻击学不到私有结点的存在）和七处 `EPERM`。`EACCES` 在 MIB 全树零出现（`rg EACCES servers/mib/` 无命中，见 VERIFY）——NetBSD 用 `EPERM` 统管特权拒绝，MIB 照抄。**见到 `EACCES` 的移植代码可以直接判定为外来户**。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 缓存变枚举 | `call_flags` 两位 + 手工"双空才问" | `CallAuth::{Unknown, Yes, No}` + `resolve`（`auth.rs`） | "问一次"是 C 用惯例保证的（忘了查位就多问）；枚举让已决 `resolve` 恒等——惯例变结构 |
| D2 | 三类权限检查分别独立为函数 | 九处手写条件判断（条件各写一遍） | `can_see`（可见性检查）/ `check_write`（写入权限的两道检查：先检查可读写标志，再检查任意用户可写或超级用户）/ `check_mutate`（结构变更检查：先验证调用者身份再验证父节点可写性） | 同一谓词在九处手写是第九处写错的温床（`:934` 与 `:115` 同形不同函数已是证据）；一类检查对应一个函数 + 九处调用 |
| D3 | `EACCES` 缺席变知识 | 无（C 只是不用） | doc §2.3 明示 + VERIFY-CHECK 重放 `rg EACCES` 零命中 | "不用某错误码"是跨篇移植时的判定依据，值得钉成 review 证据而不是注释 |

替代方案及否决：把 `getnuid` PM 查询包进 `resolve`（`async` 或 trait）——否决，查询是 transport 效果（A-12），`resolve` 只判 bool 答案；等 PM 客户端落地，调用方 `resolve(getnuid(..)==0)` 一行接上，无需改本模块。

## 4 实现详解

### 4.1 模块结构

```
os/servers/mib/src/
└── auth.rs — 本篇：SUPER_USER / CallAuth+resolve/is_authed /
               can_see / check_write+node_writable_by / check_mutate / is_private
```

### 4.2 核心符号表

| 符号 | 来源 | Rust 位置 | 行为 |
|------|------|-----------|------|
| 问一次 | `main.c:259-272` | `auth.rs`（`CallAuth/resolve`） | 未问才判；已决恒等 |
| 回答 | `main.c:271` | `is_authed` | Yes 即真 |
| 看门 | `:115,934,1389` | `can_see` | 公开全见；私有仅 Yes |
| 写门 | `:1447-1456` | `check_write` | 无新免判；RW 杠；ANYWRITE-或-Yes 杠 |
| 改结构 | `:500-511,848-852` | `check_mutate` | 先人后拓扑 |
| 私有位 | `CTLFLAG_PRIVATE` | `is_private` | 单谓词 |

### 4.3 不变量

| 不变量 | 守卫 | 证据 |
|--------|------|------|
| PM 至多问一次 | `resolve` 已决恒等 | `:263` 双空条件 |
| ANYWRITE 不代 RW | 两杠顺序 | `:1447` 先于 `:1455` |
| 改结构先认人 | `check_mutate` 顺序 | `:500` 先于 `:511` |
| 无 EACCES | rg 零命中 | 全树 |

### 4.4 与 C 的差异说明（模式 72 CSSCM）

§2 三节 vs §4 一模块：`getnuid` 调用点（`:265`）移交 transport（D-否决）；`:995/:1004` 移交 11，`:1585/:1632` 移交 12（§2.2 括号声明）。category：边界移交 + 设计决策（D1 惯例变结构，行为等价）。
