# 08 — 系统信息库动态节点：创建时多重校验，销毁时多重守卫

> **分类**: 生命周期 / 创建销毁 verdict
> **源码**: `minix3/minix/servers/mib/tree.c:242-266`（`mib_check_name`）、`:277-359`（`mib_scan`）、`:426-481`（`mib_upgrade`/`mib_add`）、`:486-775`（`mib_create`）、`:784-916`（`mib_remove`/`mib_destroy`）
> **说明**: 运行时节点的完整生命周期：名字合法性校验、扫描是否与现有节点冲突、标志位合法性检查、创建与删除的多重守卫、版本号递增、内存归属。实际的内存分配、链表链接与数据拷贝是后续竞技场与传输层的效果，本篇只负责所有判决逻辑。

## 1 概念

### 1.1 目标读者与前置知识

面向要实现创建/销毁的人。 前置知识：03（dynode 形状/版本乐观锁）、05（查找双通道/插入点）、07（`check_mutate` 改结构门）。"特权操作"即 superuser 专属（07）。

### 1.2 本章不讲什么

- 插入/删除的指针手术——arena 效果（后续，`mib_add/remove` 本体），本篇只判"插哪/删 quoi"的依据与计数差量。
- 数据拷贝进新结点——那是 06（`copyin_aux/str`）的事。
- 建成/撞车后拷给用户的节点快照——那是 11（`mib_copyout_node`）的事。
- 枚举/描述——11。

### 1.3 创建时的多重校验按成本由低到高排序

`mib_create` 的校验链按"先做开销小的检查"排序：是否为超级用户 → 父节点是否为远端挂载（断言保证已排除）→ 父节点是否可写 → 孩子总数是否溢出（理论上限为 32 位整数最大，注释说明 32 位下实际上到不了）→ 是否提供了新数据 → 请求中版本号是否与父或根匹配 → 版本号是否为 VERS_1 → 标志位是否在白名单内 → 是否为立即值与拥有数据的合法组合 → 读写位消毒 → 节点类型与大小是否匹配 → 处理函数与父指针必须为空 → 名字是否合法 → 扫描是否与现有节点冲突。**在分配内存之前能检查的全部检查完**（`:529-535` 注释），因为分配后失败要走内存释放路径——前置校验是为了减少释放路径，不是为了节省时间。

若与现有节点冲突则不静默：返回已存在错误时把**已存在的节点内容复制给调用者**并暂存长度（`:657-664`，01 §2.4 的暂存长度唯一产生处）——相当于告知调用者"你要建的已存在，内容是这样，自己查看"。

### 1.4 名字需符合 C 语言符号规则，编号则分散

名字规则（`mib_check_name`，`:253-263`）：非空、在给定缓冲区内以空字符结尾、仅含字母/下划线/数字（数字不能出现在首字符）。编号规则（`mib_scan`，`:285-303` 注释）：调用者显式指定编号则校验该编号是否已被占用；未指定则从 1024 与父节点静态大小的较大值起顺延寻找空位——**故意避开静态编号区间**（若应用用静态编号误取到动态节点会引发事故，注释原话），排序保证寻找空位的时间与动态节点数成正比。名字冲突会扫描全部两个存储区（静态全表与动态全表，包括插入点之后的所有节点——提前结束仅节省编号搜索，不节省名字搜索，`:345-354`）。

### 1.5 销毁时的多重守卫

`mib_destroy` 的守卫链：是否为超级用户 → 父节点是否可写 → 是否提供了新数据以指明要删哪个 → 版本号是否为 VERS_1 → 节点是否存在（否则未找到）→ 是否为永久节点 → 若为目录类型则三项额外检查：是否为远端挂载点（忙，需先到 12 卸载）、是否为函数接管节点、是否有孩子节点 → 请求版本号是否与节点当前版本一致 → 请求名字是否与节点名字一致。**先复制旧节点内容，再执行删除**（`:906-913`）——删除后再复制已无源可拷；即使复制失败也照样删除（与 NetBSD 行为一致，`:901-905` 注释）。

`mib_remove` 的内存处理原则（`:793-804`）：仅当描述字符串被标记为拥有时才释放；**数据区永远不单独释放**（静态节点的数据是静态内存，动态节点的数据嵌在节点块内）——所以此处**禁止**检查拥有数据标志（注释用 must not，担心后人误加上）。动态节点需摘链并释放、静态节点原地清零；统一将有效孩子数与总节点数各减一，并沿父链递增版本号。

版本号递增（`mib_upgrade`，`:439-448`）：根版本号加一（跳过零），沿父链一路写到根。零永远不作为有效版本号（表示"不关心版本"标记，03 §1.6）——即使 32 位整数回绕也跳过零。

### 1.6 小结

创建流程：权限与父节点检查 → 版本与标志检查 → 类型与大小 → 名字与冲突扫描 → 分配一块连续内存（含节点头、名字与数据）→ 链入树 → 递增版本 → 回显结果。销毁流程：权限与父节点检查 → 定位与多重守卫 → 先复制后删除 → 按动态或静态分别处理内存差量 → 递增版本。

## 2 C 源码分析

### 2.1 名字校验（`mib_check_name`，`:247-266`）

空/界内无 `\0`/非法字符 → 0（失败）；否则回长度（不含终结符）。首字符数字禁（`namelen>0` 条件，`:259`）。

### 2.2 扫描（`mib_scan`，`:277-359`）

| 阶段 | 位置 | 行为 |
|------|------|------|
| 静态撞车 | `:306-315` | id 等或名等 → `EEXIST`（带静态 id + 结点） |
| 起点 | `:321-324` | 显式号直用；否则 `max(1024, size)` |
| 动态边走边判 | `:326-343` | 过大停（插入点）；等号：显式→撞车，自动→+1；名等→撞车（带动态 id） |
| 尾部名查 | `:346-353` | 插入点之后继续查名（断言 id 递增，`:347`） |
| 成功 | `:356-358` | 回 id + 插入链环 |

### 2.3 创建链（`mib_create`，`:486-775`）

安检 `:499-665`（§1.3 顺序，含版本 `:544-546`、标志 `:552-576`、类型 `:579-634`、func/parent 空 `:633-634`、名字 `:637-640`、扫描 `:647-665`）；分配 `:679-685`（一块：头+名+数据，失败 `EINVAL` 非 `ENOMEM`）；初始化 `:690-749`（标志去版本位 `:695`、NODE 补 PARENT `:696-697`、立即值/外存数据/零填、bool 消毒 `:745-748`）；描述暂不支持（`:751-754`，NetBSD 都没有）；失败释放 `:757-762`；链接 `:768`（`mib_add`：摘链+`csize/clen/nodes++`+升级，`:464-480`）；回显 `:774`（拷失败不撤销）。

### 2.4 销毁链（`mib_remove`/`mib_destroy`，`:784-916`）

守卫 `:847-899`（§1.5）；先拷 `:906`；删除 `:913`（差量 §1.5）；回拷结果 `:915`。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 名字校验变 `Option` | 回 0 表失败 | `check_name → Option<usize>`（`dynamic.rs:26`） | 0 在 C 里既是"失败"又是"长度零"歧义（空名失败回 0，长度不可能是 0——歧义无害但难读）；`None` 即失败 |
| D2 | 扫描变纯函数 | 指针输出参数（idp/prevpp/nodep） | `scan(...) → ScanOutcome::{StaticClash,DynClash,Free{id,insert_at}}`（`dynamic.rs:50,81`） | 三个输出参数是 C 惯例；枚举一次说清"撞哪/空哪/插哪"；05 `Missing{insert_at}` 在此复用为插入点 |
| D3 | 拒绝变枚举+码 | 裸 errno（`EPERM/EBUSY/ENOTEMPTY/EINVAL` 散落） | `DestroyRefusal` 六变体 + `(Refusal, i32)`（`dynamic.rs:219,235`） | 销毁有六种死法，裸码分不清"永久"与"函数结点"（都是 `EPERM`）；变体是原因，码是传输——原因值得名字 |
| D4 | 差量变结构 | 全局 `--` 散写 | `RemoveDelta{free_desc,free_dynode,csize_dec,objects_dec}`（`dynamic.rs:274,287`） | `clen/nodes--` 恒成立不值得建模（调用者照做）；**条件成立**的四项才值得（动态/描述拥有与否四组合，测试全覆盖） |
| D5 | 版本递增变函数 | `+1` + 跳零散写 | `next_root_ver`（`version.rs:15`，wrapping+跳零）+ `create_ver_ok`（`:26`） | u32 回绕跳零是"写一次忘一次"的典型（`:440-441` 两行）；函数+回绕测试钉死 |

替代方案及否决：arena 一步到位（Vec/BTree 真表 + 指针手术）——否决，静态 arena 在 13 首表落地，本篇 verdict 先行（verdict-first 延续；`scan` 的切片签名在 arena 落地时换容器不换语义）。
