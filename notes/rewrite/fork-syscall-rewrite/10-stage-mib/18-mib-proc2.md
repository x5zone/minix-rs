# 18 — 第二套进程格式：同样的状态，另一套输出结构

> **分类**: 进程信息 / 按 NetBSD 格式填写
> **源码**: `minix3/minix/servers/mib/proc.c:600-652`（公共填写 `fill_proc2_common`）、`:657-682`（内核任务填写 `fill_proc2_kern`）、`:687-786`（普通进程填写 `fill_proc2_user`）、`:791-913`（查询入口 `mib_kern_proc2`）
> **说明**: 进程信息五篇的第三篇。ps 命令看进程有两套格式，17 讲完第一套（轻量线程），本篇讲第二套。状态判断和时间换算直接用 17 和 16 算好的，本篇只做三件事：换输出结构、按条件过滤行、定查询参数的规矩。

---

## 1 概念

### 1.1 目标读者与前置知识

面向要实现本篇功能的人。前置知识：16（按进程号查槽、拿表、多留八个位置、滴答换算时间）、17（状态怎么定，特别是"睡着"之外的四种直接返回）、06（范围检查和拷贝出去，输出是稀疏数组的约定）、10（查询函数在分发里的位置）。"第二套格式"指 NetBSD 传下来的进程信息结构，和 17 的轻量线程结构是同一份数据的两种摆法。

### 1.2 本章不讲什么

- 状态具体怎么定的——17。
- 表怎么拿、时间怎么换算——16。
- 内存用量从哪里来——虚拟内存服务，要数据的代码去要，本篇只规定拿到之后怎么填。
- 进程参数、Minix 进程快照——19、20。

### 1.3 同一份数据，两种摆法

C 代码的注释把设计意图直接写出来了（`proc.c:610-618`）：轻量线程结构里的很多信息直接进了第二套格式。为了不写两遍重要代码，先按 17 的办法算出轻量线程的值，再复制进第二套格式。这个"先算一份，再复制一份"的顺序是本篇最关键的设计：凡是两边都有的字段（运行时间、处理器用量、挂起时间、睡眠时间、优先级、处理器号），以 17 算出的为准，本篇不另算一遍。

第二套格式比第一套多的东西有三样。第一，内存用量：常驻集大小、虚拟内存大小、映射内存大小、历史最大驻留、两种缺页计数，从虚拟内存服务要，用页长折成页数。拿不到就填零，不报错（`:619-621`，失败直接忽略）。第二，身份信息：进程号、父亲进程号、会话号、进程组号、终端、四个用户组号、十数组补充组（最多十六个，多的截掉）、信号的三张表、好心值、名字。第三，内核伪进程：内核本身没有进程号，单独填一行，进程号写零，状态固定填睡着，线程数填任务总数，时间按内核任务的槽位算（`:677-681`，注释说这样处理器平均用量才对）。

查询入口支持九种过滤（`proc.c:815-833`）：全部、按进程号、按进程组、按会话、按终端、按有效用户、按实际用户、按有效用户组、按实际用户组。会话和进程组用的是同一个字段（作业控制还没做，这是 C 代码里的待办，`:865`）。终端过滤有两条特殊规则：问"被收回的终端"直接一行都不出（收回系统调用还没做，待办，`:871-872`）；僵死的进程不读它的文件槽，终端按"无设备"算（`:873-875`）。

### 1.4 小结

本篇是 17 的下游：状态和时间拿现成的，只做输出结构、行过滤、参数规矩三件事。顺序是先按 17 的办法算出轻量线程的值，再复制进第二套格式，§2 看 C 代码是怎么复制的。

## 2 C 源码分析

### 2.1 公共填写（`proc.c:600-652`）

先调 17 的公共填写函数算出轻量线程的值（`:617`），再复制：运行时间秒和微秒、处理器滴答和用量、挂起和睡眠时间、优先级两处、处理器号。然后问虚拟内存服务要内存用量（失败忽略，`:621`），折算：常驻集、虚拟内存、映射内存都用"总量除以页长向上取整"，历史最大驻留和两种缺页计数直接照填。用户态时间和内核态时间各调 16 的换算函数算一遍。还有一处待办：中断时间字段没填（`:632`）。

### 2.2 内核任务填写（`proc.c:657-682`）

清零。标志填常驻内存加内核任务加能叫醒。进程号填零。状态固定填睡着。好心值填默认值。等待地址填内核任务类别。等待原因和名字都写"内核"。真实标志照着填。真实状态填运行中。线程数填任务总数。再调公共填写，槽位用内核任务的槽（`:681`）。

### 2.3 普通进程填写（`proc.c:687-786`）

先问开机时间，问不到直接崩溃（`:699-700`，C 代码里调 panic：没有开机时间，后面的启动时间全算不出来）。槽号是任务数加槽位。从三张表各取一行。

僵死的进程终端按无设备算（`:707`）。扩展标志：有终端加一项，是组长（进程号等于进程组号）加一项，作业控制的待办记在这里（`:712`）。退出信号填子进程退出，待办（`:715`）。标志：先填常驻内存，被污染过（跑过提权程序）加一项，被调试器盯着加一项，有终端加一项（`:717-723`）。进程号、父亲（父亲槽位合法才查）、会话、进程组、终端组（有终端才填）、四个用户组号、补充组（截到十六个，`:734-736`）、信号三张表直接复制、好心值加默认值、名字、启动时间（开机时间加已换算的启动滴答，`:745-747`）、子进程时间、真实标志照着填、线程数（僵死填零，否则填一，`:753`）、两个保存的用户组号。

再调 17 的状态函数定状态、等待地址、等待原因和标志（`:757-759`），按状态定真实状态：能运行填运行中，睡着填运行中（能叫醒的再把真实标志添上，`:767-768`），停止填停止，等收尸填等收尸，正在退出填"等收尸"但真实状态填"快死了"（ps 命令不认识正在退出，只能这么显示，`:777`）。不是僵死再调公共填写（`:784-785`，僵死的内核行已经没了，公共填写要读内核行，所以跳过）。

### 2.4 查询入口（`proc.c:791-913`）

| 步骤 | 位置 | 行为 |
|------|------|------|
| 参数检查 | `:802-808,835-836` | 名字长度必须是 4（过滤条件、过滤值、每行字节数、最多行数，最後一个和旧缓冲区长度重复，注释说了）。每行字节数小于等于零、最多行数小于零 → 参数错 |
| 内核匹配 | `:815-833` | 九种过滤各定内核伪进程出不出：全部出。按号、按组、按会话、按用户、按用户组六种，过滤值是零才出。按终端，过滤值是"无终端"才出。未知过滤 → 参数错 |
| 拿表 | `:838-839` | 拿表失败 → 参数错 |
| 每行字节数 | `:842` | 取每行字节数和结构体大小的小者，和 17 一样 |
| 内核段 | `:844-852` | 该出才走：在范围内且有名额才填写拷贝，偏移量无条件按步长前进 |
| 进程段 | `:854-907` | 全部扫一遍，跳过不在用的。九种过滤各筛一遍（会话和进程组都比进程组号，终端三条规则见 §1.3）。同样的"在范围内且有名额才拷贝、偏移量无条件前进" |
| 预留 | `:909-910` | 只要是只估计长度的那次调用，而且问的不是单个进程号，再多留八个步长（两次调用之间可能有新进程出生。问单个进程号不留：最多一行，不会变多） |

返回偏移量。和 17 的查询入口是同一个形状：参数检查、拿表、内核段、进程段、预留，区别只在过滤条件从"进程号三种"变成"九种"，输出结构从轻量线程换成第二套。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 过滤条件变成枚举 | 按数字分支（`:815-833`、`:860-898`） | 九种情况的枚举加解码函数（`os/servers/mib/src/proc/proc2.rs`），未知数字回空 | 数字的值是 NetBSD 的契约，固定在值表里。本模块只认"是哪种"，不认数字 |
| D2 | 内核匹配和行匹配分开 | 内核匹配和行内过滤写在一个大函数里 | 两个函数：一个判断内核符合条件，一个判断这一行符合条件（`proc2.rs`） | 内核没有表里的槽位，匹配规则也不一样（整个循环扫不到它）。拆开之后，行匹配函数是单纯的行内判断，可以一行一行测 |
| D3 | 终端哨兵值由调用的人传 | 直接用设备头文件的宏 | 匹配函数取"无终端"和"被收回"两个值做参数（`proc2.rs`） | 设备号的值归设备头文件管。16 已经论证过不固定端点相对的值，这里同理：逻辑值得测，值不值得固定 |
| D4 | 状态映射变成函数 | 按状态分支写两个字段（`:760-782`） | 状态映射函数（`proc2.rs`） | 五种映射里四种是直接对应，一种是正在退出显示成等收尸。显示成什么由函数定，调用的人不用再写一遍分支 |
| D5 | 标志组装变成函数 | 按位或散写（`:709-723`） | 扩展标志和进程标志两个组装函数（`proc2.rs`） | 每一位的条件是独立的判断，值得独立测。僵死先算终端（`:707`）是调用顺序，组装函数只管给定的是否值 |

替代方案及否决：输出结构的 C 语言内存排布直接复制——否决，和 17 同一个理由，字节排布归架构演进 A-4。内存用量拿不到就报错——否决，C 明确忽略失败（`:621`），改成报错是改语义。开机时间拿不到返回错误——否决，C 明确崩溃（`:700`）， Rust 侧崩溃点归要数据的代码，本模块不规定。

和别的操作系统对照着看：Linux 查进程列表没有过滤条件（`ps` 把全表读回去自己筛），NetBSD 把九种过滤做进系统调用。Minix 跟 NetBSD：过滤条件进内核侧，省一次全表拷贝。Redox 的进程方案用路径表示过滤（比如按用户查就是不同的路径），三种路子各有各的账：Linux 把复杂度推给用户态，Redox 推给路径解析，NetBSD 和 Minix 推给枚举分支。本篇保留 NetBSD 的枚举，因为过滤值（进程号、用户号）的含义调用的人和服务是一致的，不需要翻译。


### 4.3 不变量

| 不变量 | 谁保证 | 证据 |
|--------|------|------|
| 未知过滤进不来 | 解码函数回空，调用的人报参数错 | `:831-832` |
| 内核只在该出的查询里出现 | 内核匹配函数 | `:815-833` |
| 被收回的终端一行不出 | 行匹配函数先判收回 | `:871-872` |
| 僵死的终端按无设备算 | 调用的人先调终端函数 | `:707,873-875` |
| 正在退出显示成等收尸 | 映射函数 | `:777` |
| 单个进程号的估计不留位置 | 预留函数看是不是查单个 | `:909` |

### 4.4 和 C 不一样的地方

§2 有四节，§4 是一个模块：拿表、读时钟、问内存用量、问开机时间、拷贝循环按 §1.2 移交出去。设备哨兵值由调用的人传（D3），输出结构大小由调用的人传（字节数函数取参），合法输入下两边结果一样。类别：边界移交出去的，已经声明。
