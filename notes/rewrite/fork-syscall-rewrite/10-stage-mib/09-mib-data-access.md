# 09 — 系统信息库数据读写：先暂存再落盘，避免中途失败污染节点

> **分类**: 数据面 / 读写 verdict
> **源码**: `minix3/minix/servers/mib/tree.c:1098-1154`（`mib_getptr`/`mib_read`）、`:1160-1300`（`mib_write`）、`:1308-1325`（`mib_readwrite`）
> **说明**: 叶子结点字节的进出：哪条 lane、报多长、写多严、stage 哪、bool 怎么消毒、verify 怎么判。handler 们（13~20）复用 `mib_readwrite`，本篇是它们的公共地基。

## 1 概念

### 1.1 目标读者与前置知识

面向要读 handler（13~20）的人。前置知识：03（lane 语义）、06（钳制/精确/分页）、07（写门）。"stage"现用现讲：先拷到一边，验好了再落子。

### 1.2 本章不讲什么

- 函数驱动结点（handler 接管整棵子树）——那是 13~20 各自的事（本篇只管"常规数据叶"）。
- 分发怎么调到这里——那是 10 的事。
- 拷贝执行——06/transport。

### 1.3 先 stage，再落子

`mib_write` 的核心禁令是禁止在原地直接更新——用户数据拷贝可能中途失败，若已写一半则节点处于损坏状态（`:1171-1175` 注释）。所以流程是：判断尺寸是否合法 → 选择暂存区（若需暂存长度加一后仍能放入共享暂存区则用之，否则需有特权才允许在堆上分配）→ 拷贝入暂存区 → 调用校验回调 → 按类型写入节点 → 释放暂存区。**暂存区起"可回退"作用**：若校验不通过或拷贝失败，节点原值保持不变。读路径无此顾虑（读不改变节点），但读有个对称设计：无论是否能拷入用户缓冲区，都如实报告完整长度（01 §2.4），能否拷下是缓冲区大小的事。

字符串是全篇最绕的：写入时允许用户不带字符串结束符（提供长度不超过节点大小先放行，`:1203`），暂存区多留一字节以备补加结束符（`:1211-1214`），最终写入时自行补加（`:1286`）——但若整个槽已写满且仍无结束符则拒绝（已无空间可补，`:1274-1277`）。读取时报告长度为实际字符串长度加一（含结束符，`:1141`），缓冲区中结束符之后的无用数据永远不会被读出（`:1280-1285`）。**字符串的不变约束是"读取时必带结束符，写入时可不带由内核补加"，唯一的例外是"槽位已满且无结束符则拒绝写入"**。

布尔值消毒是 C99 的坑： `_Bool` 类型中存放 2 属于未定义行为（读取即未定义，`:1255-1264` 长注释），所以先经过单字节中转（取首字节非零即为真，`:1265`）再存。并附带编译期断言 `sizeof(bool)==1`（`:1163` 的数组技巧）——这是应用二进制接口的硬性约束，布尔值不是一字节则编译失败。

### 1.4 小结

读路径：确定数据所在位置 → 确定报告长度（字符串按实际长度加一）→ 按缓冲区大小截断拷贝 → 报告完整长度。写路径：判断尺寸 → 选择暂存区（共享暂存或堆，需特权）→ 拷贝入暂存区 → 校验回调 → 按类型写入（字符串补结束符、布尔值消毒）→ 释放暂存区。记住"可回退的暂存"与"字符串结束符的三条规则"，后续处理函数的读写复用就通了。

## 2 C 源码分析

### 2.1 确定数据所在位置（`mib_getptr`，`:1098-1124`）

| 节点类型 | 是否为立即值 | 数据所在位置 |
|------|-----------|------|
| 布尔/整数/64位整数 | 是 | 节点体内直接存放（取体内字段地址） |
| 布尔/整数/64位整数 | 否 | 外部指针指向的内存 |
| 字符串/结构体 | 是 | 返回空（不可能的组合，`:1116-1117`） |
| 字符串/结构体 | 否 | 外部指针指向的内存 |
| 其他类型 | — | 返回空（无对应存储） |

### 2.2 读（`mib_read`，`:1130-1154`）

无 lane → `EINVAL`（`:1137-1138`）；串量 live+1 否则报宽（`:1140-1143`）；超 `SSIZE_MAX` → `EINVAL`（`:1145-1146`，`ssize_t` 装不下）；有槽则拷（错码上浮，`:1149-1150`）；**永远报全长**（`:1153`）。

### 2.3 写（`mib_write`，`:1160-1300`）

| 步骤 | 位置 | 行为 |
|------|------|------|
| 空写 | `:1168-1169` | `newp==NULL` 直接 OK（读-only 调用无辜） |
| 取 lane | `:1184-1185` | 无 lane → `EINVAL` |
| 判尺寸 | `:1187-1208` | 非串精确等；串 `≤`；未知 `EINVAL` |
| 定 stage | `:1220-1242` | `newlen+1>scratch` → 非特权 `EPERM`；特权堆（败 `EINVAL` 非 ENOMEM，`:1235-1238`）；否则草稿 |
| 拷入 | `:1245` | `copyin`（零长亦拷，错码上浮） |
| verify | `:1247-1248` | 有回调且说不 → `EINVAL` |
| 落子 | `:1250-1292` | bool 消毒/整量 `memcpy`/串补终结+`strlcpy` |
| 释 stage | `:1294-1297` | 非草稿释放 + 对象计数-- |

### 2.4 合成（`mib_readwrite`，`:1308-1325`）

读（错即回）→ 写（错即回）→ 报读长。十六行，handler 复用的唯一入口（`:1303-1306` 注释：无函数叶走它，有函数 handler 也可借它）。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | lane 变枚举 | 返回指针/NULL（NULL 兼"无 lane"与"不可能"） | `PtrLane::{Immediate,External,Absent}`（`readwrite.rs:24`） | "串+立即"的不可能（`:1116-1117`）与"未知类型"（`:1119-1120`）在 C 里都是 NULL——枚举让"不可能"与"未知"同归 Absent，调用者只判一次 |
| D2 | stage 变枚举 | `src` 指针 + `!=scratch` 判断释放 | `Stage::{Scratch,Heap}` + `stage_for`（`readwrite.rs:97,106`） | "谁分配谁释放"（`:1294-1297` 配对）是释放遗漏的温床；枚举让"堆即需释"成为类型知识（arena 落地时 `Heap` 携带释放义务） |
| D3 | bool 消毒变函数 | `(bool)src[0]` 内联 + 编译期数组 trick | `sanitize_bool`（`readwrite.rs:138`）+ doc 链 UB 注释 | UB 规避值得名字 + 测试（`2→true`）；数组 trick（`:1163`）是 C 编译期断言，Rust 侧 `assert!(size_of::<bool>()==1)` 在测试钉（§5） |
| D4 | 合成变函数 | 16 行直写 | `readwrite_combine`（`readwrite.rs:159`） | 读错短路/写错替换/报读长三规则值得钉（handler 复用入口的语义，一行漂移全树漂移） |

替代方案及否决：stage 代持 RAII（`StageBuf` 持草稿引用或堆 Vec，Drop 释放）——否决，arena/分配器未定（A-3，no_std 全局分配器待定）；verdict 先行，RAII 在分配器落地时从 `Stage::Heap` 长出。

### 4.3 不变量

| 不变量 | 守卫 | 证据 |
|--------|------|------|
| 不在位更新 | stage 必经 | `:1171-1175` |
| 报数恒全长 | 合成报读长 | `:1324` + 01 §2.4 |
| 失败非 ENOMEM | 调用方（02 §2.7） | `:1235-1238` |
| bool 一字节 | 测试钉 `size_of` | `:1163` trick |
| 满槽无终结拒 | `finalize_string` | `:1274-1277` |

### 4.4 与 C 的差异说明（模式 72 CSSCM）

§2 四节 vs §4 一模块：指针追逐/拷贝/释放移交 arena+transport（§1.2）；verify 调用移交 handler（`apply_verify` 只判答案）；`SSIZE_MAX` 取 64 位（ARCH 加宽，§4.2 行注——无结点企及，parity 检查）。category：边界移交 + 允许演进。
