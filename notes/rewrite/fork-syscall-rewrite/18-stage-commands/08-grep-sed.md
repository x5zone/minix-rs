## 1. 概念：用一句话描述无数行

### 1.0 本章说明

本章讲正则表达式：一种"用短字符串描述行集合"的语言，以及 `grep`（找行）与 `sed`（改行）两个使用者。读完本章，读者应能读懂常用模式、理解两种拼写的区别、明白匹配引擎为什么不能是指数级回溯。

> **本章不讲什么**：
>
> - 各国字符集与本地化匹配（显式留白，见 3.5 节）
> - 补丁生成算法（见 `07` 篇边界）
> - `sed` 地址的执行（行号范围、多文件流，后续阶段）
>
> 本章只讲模式语言本身：语法、语义、引擎、两个工具的选项面。

### 1.1 正则解决什么问题：从枚举到描述

要在十万行日志里找"所有报错行"，枚举写法是把每个报错行号列出来——文件一变就作废。描述写法是"包含 `error` 后跟冒号的行"——文件怎么变都有效。正则表达式就是这套描述语言：字面字符表示自己（`error` 匹配连续五字节），点表示"任意单字节"，星号表示"前一个东西零个或多个"，方括号表示"其中之一"，行首符与行尾符表示"行首行尾"，竖杠表示"或"。

初学者最该建立的直觉是：正则描述的是"形状"，不是"内容"。`[0-9]+` 描述"一串数字"的形状，至于是电话还是金额，正则不关心——关心形状、忽略含义，正是它能复用的原因。

### 1.2 两种拼写：基础与扩展

历史原因，正则有两种拼写，C 工具用 `-G`（基础，默认）与 `-E`（扩展）切换：

| 写法 | 基础拼写 | 扩展拼写 |
|------|---------|---------|
| 重复零或多次 | `*` | `*` |
| 重复一或多次 | 无（用 `*` 组合） | `+` |
| 可选 | 无 | `?` |
| 或 | 无（字面竖杠） | `\|` |
| 分组 | `\(...\)` | `(...)` |
| 后向引用 | `\1` 到 `\9` | 无 |

基础拼写"默认字面、反斜杠启用魔法"，扩展拼写"默认魔法、反斜杠取消魔法"——助记口诀：基础保守（多写反斜杠才有功能），扩展大方（功能默认就有）。本库两种拼写各一个编译入口（`compile_basic` 与 `compile_extended`），行为差异逐项测试。

### 1.3 匹配语义：最左、最长、贪婪

找到匹配分三步走：先定起点（最左：文本中最早能开始的位置获胜），再定终点（最长：该起点出发能走多远走多远），重复算子默认贪婪（`a*` 先吞下所有 `a`，不够再吐出来）。`a|aa` 在 `aa` 上的匹配是 `aa`（不是 `a`）——起点相同比终点，这是 POSIX 偏好的语义，本库 `find` 返回的正是"最左起点、最长终点"。

贪婪有个著名陷阱：`.*` 会吞掉整行——初学者写 `<.*>` 想配一个标签，实际配出整行。理解"贪婪先吞、再吐"的两阶段，就理解了大半的正则调试。

### 1.4 引擎为什么不能是指数级回溯

朴素的回溯匹配器遇到 `(a*)*$` 这类模式会尝试天文数字种切分，输入稍长就卡死——这不是理论风险，是 2000 年代真实发生过的服务瘫痪事故类别。正确的做法是自动机：汤普森构造把模式编译成状态机，派克虚拟机逐字节推进活跃状态集，时间与"程序大小乘输入长度"成正比，输入再长也不爆炸。本库引擎正是这个结构（见第 3.1 节），测试 `test_pathological_pattern_is_fast` 用 200 字节输入证明实用输入秒回。

代价是模式内数字后向引用（`\1`）被显式拒绝——它不是正则的，硬上会把引擎拖回回溯。拒绝是响亮的（编译期错误），不是静默的（错配）。替换侧的 `\1`（读已捕获分组）完全支持——读存档与现场勘查是两回事。

### 1.5 `grep` 与 `sed` 分工：找行与改行

- **`grep`**：按行过滤。选项管三件事：模式怎么写（`-E`、`-G`、`-F` 固定串、`-e` 多模式、`-i` 忽略大小写）、选哪些行（`-v` 反选、`-x` 整行、`-w` 词边界）、怎么输出（`-c` 只计数、`-l` 只列文件名、`-n` 加行号、`-q` 静默）。退出码三值（第 505 行）：命中为 0、未命中为 1、文件出错为 2——脚本用它做分支，务必背熟。
- **`sed`**：按行改写。程序由"地址加命令"组成（地址：行号或模式，缺省为每行；命令：`s` 替换、`d` 删除、`p` 打印、`a`、`i`、`c` 增改、`y` 字符转写）。替换命令 `s/模式/替换/标志` 的分隔符可换（`s#...#...#` 合法，路径里全是斜杠时救命）、标志 `g` 全局、`p` 打印、第 N 个。下节源码分析展开。

地址解析从第 189 行开始：合法地址首字符集是"数字、斜杠、反斜杠、行尾符"（第 193 行宏定义），行号与模式地址各归一分支（`compile_addr` 第 76 行）。命令分派表第 122 行把 `s` 指向替换编译；第 339 行在地址解析完成后调用 `compile_subst`（定义第 480 行）。分隔符任意性、转义规则、标志解析（`g`、`p`、数字）都在这 100 行里——Rust 侧 `parse_subst` 与之逐项对应（见第 4.2 节）。

### 2.4 `process.c`：执行与空匹配推进（792 行）

## 3. Rust 设计决策

### 3.1 为什么是虚拟机而不是回溯器

见 1.4 节：线性时间是命令级基础设施的硬要求（`grep` 跑的是整个文件系统，卡死不可接受）。汤普森构造（每个语法节点对应一小段指令，空转移连接）加派克虚拟机（活跃线程集逐字节推进，优先级去重）是 60 年前的老办法，至今仍是正确性与性能的最佳平衡点。代价是代码量（编译器加虚拟机约 600 行）大于回溯器（约 200 行）——为"永不爆炸"付的 architectural 溢价是值得的。本阶段其他库的"接口加双实现"手法在这里体现为 `Matcher` 接口（固定串与正则两种策略，`grep -F` 跳过编译器）。

### 3.2 为什么拒绝模式内后向引用

后向引用让语言不再是正则的（需要记忆任意长捕获），虚拟机处理不了。三个选项：退回回溯（指数风险）、近似支持（错配风险）、响亮拒绝。本库选第三个：`\1` 到 `\9` 在模式里是编译期错误，文档、注释、测试三处写明。替换侧 `\1` 完全支持（读捕获是 O(1) 查表）。这个取舍参考了 RE2（同样不支持）与 PCRE（支持但可能爆炸）的分野：基础设施选 RE2 这边。

### 3.3 为什么退出码是纯函数

第 505 行的三值逻辑（命中、未命中、文件错、静默四变量压缩成 0/1/2）是 `grep` 与脚本世界的契约，错一位就断无数脚本。Rust 侧 `exit_code` 把它写成四行纯函数，测试用真值表六行情景钉死——契约代码值得这种"笨"写法：分支越直白，review 时越能逐行对照 C 源码。

### 3.4 为什么替换命令解析返回消耗长度

`sed` 程序是分号连接的多命令（`s/a/b/;s/c/d/`），解析完一条必须知道下一条从哪开始。`parse_subst` 返回（替换命令，消耗字节数），调用方据此续解析。这是编译器前端的通用手法（C 侧用指针推进，本库用长度返回——无分配约束下的等价表达）。

### 3.5 字节取向的架构注记

引擎按字节匹配（点匹配单字节、类匹配单字节、大小写只认 ASCII）。在 C 本地化环境下与 C 工具行为一致；多字节本地化是全阶段统一的后续升级（`cut -c`、`tr` 类、`grep -i` 共用一份升级计划，见各篇留白）。提前在这里声明，避免读者误以为"字符"与"字节"已被区分。

## 4. 实现详解

### 4.1 模块结构

`os/commands/usr-bin/regex`（库包名 `minix-regex`）共 5 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`RegexError`，22 对应模式非法与超限）与模块组织 |
| `pattern.rs` | `regcomp` 语义、`grep.h:66` 标志思想 | 两种拼写编译（`compile_basic`、`compile_extended`）与虚拟机匹配（`find`、`is_match`、`is_full_match`、`find_bytes`） |
| `matcher.rs` | `grep.c:67`（`-F`）、`:186`（词边界） | `Matcher` 接口、`SubstringMatcher` 与 `RegexMatcher`、`find_word` |
| `grep.rs` | `grep.c:67-86`（标志）、`:281-451`（选项）、`:505`（退出） | 选项模型（`GrepOptions`）、参数解析、退出码（`exit_code`） |
| `sed.rs` | `compile.c:122-480`（替换解析）、`process.c:403-432`（执行） | 替换解析（`parse_subst`）与应用（`apply`） |

### 4.2 关键类型与不变量

- **模式 `Pattern`**：指令表（上限 192）、字符类表（上限 16）、捕获上限 9 组。不变量：空模式非法；超限即错（不截断）；前导重复算子读作字面；未闭合类与组即错；模式内后向引用即错。
- **捕获 `Captures`**：11 槽位（整匹配加 9 组）。不变量：未参与组为缺席；重复组取末次迭代；整匹配由驱动层落定（起点与最长终点）。
- **匹配器 `Matcher`**：最左匹配。不变量：固定串无元字符；词匹配要求双侧非词字节；整行匹配要求全覆盖。
- **搜索选项 `GrepOptions`**：九开关。不变量：拼写三选一（后指定赢）；`-e` 可重复（上限 8，任一命中即选中）；双横杠结束选项。
- **替换 `Subst`**：模式文本、替换文本、范围、打印标志。不变量：分隔符任意单字节；转义分隔符不算结束；零序号非法；超长即错。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `compile_basic`/`compile_extended` | 模式文本 | 模式 | `regcomp` 两种标志语义 |
| `find`/`is_match`/`is_full_match` | 文本 | 跨度或真假 | `regexec` 行匹配语义 |
| `find_word` | 匹配器与行 | 词跨度 | `-w` 词边界语义 |
| `parse_grep_args` | 参数表 | 选项、模式串、文件操作数 | 选项处理语义 |
| `exit_code` | 命中、文件错、静默 | 退出码 | 第 505 行真值表 |
| `parse_subst` | 替换命令文本 | 替换命令与消耗长度 | `compile_subst` 语义 |
| `apply` | 模式、替换、行、缓冲 | 结果长度与是否替换 | `process.c` 执行语义 |
