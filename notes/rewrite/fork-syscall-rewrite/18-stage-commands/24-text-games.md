## 1. 概念：留住人的三件事

### 1.0 本章说明

文字游戏和动作游戏留住人的方式不同：动作游戏靠手感，文字游戏靠故事。讲故事需要三件事：听得懂人话（词汇查得到、走得动），讲得起规则（钱算得清、牌判得明），藏得住惊喜（格言抽得匀、随机够公平）。

> **本章不讲什么**：
>
> - 大文本数据文件的落地格式（架构演进决策，见 3.5 节）
> - 数据文件读取与玩家交互（各游戏二进制包）
> - 发牌洗牌与剧本细节（后续补齐）
>
> 本章只讲故事语言：词怎么查，路怎么走，钱怎么算，书怎么凑，签怎么抽。

### 1.1 探险：听懂方向，拿起东西

探险游戏的世界是房间加出口：每个房间列出哪些动作词通向哪个房间，玩家输入方向词，程序查表，查到就换房间，查不到就说走不通。词汇表分三种词：动作词、物品词、行为词，每词带一个数字含义。查词不分大小写，空词直接拒绝，未知词报查无而不是乱走。

物品分两类放：普通物品记房间号，固定物品记固定点，编号一百是分界线。拿起放下就是改这两张表。词汇上限五百一十二词，够装下整个山洞的说法，超了说明数据文件坏了。

### 1.2 垄断：钱与骰子

垄断游戏的钱只会算到零：付钱从余额扣，扣成负数就是破产，报错而不是记负数。收钱用饱和加，封顶不溢出。开局一千五百元是规则，不是实现细节。棋盘四十格，走子按步数加模回绕，经过起点算经过（至于是不是给钱归规则层，纯层只报告过没过）。

骰子两颗各一到六，双数再掷一次，连出三次进监狱是规则，纯层只管点数合法与是否双数。点数越界拒绝，超大金额报超范围。

### 1.3 格言与首字母：抽签与查表

格言库是条目数组，抽签用随机数对库长取余，余数均匀则抽签均匀。空库报查无。磁盘上的分隔符形状（百分号行）由切分函数处理：空段跳过，全空报查无，装不下报超范围。大格言文件随程序资源落地，测试用三行小表，形状一样。

首字母查询读 `词条：解释` 形状的行，两边去空，词条里不能有空白。查询不分大小写，首个命中获胜。命令行里的 `is` 词跳过（查 `wtf is LOL` 和查 `wtf LOL` 一样），这是用法约定不是数据。

### 1.4 钓鱼与随机：成书与分母

钓鱼纸牌十三点数，每种四张，四张凑成一本书，十三本书凑满游戏结束。要牌策略选有牌且没要过的最小点数，没得要就摸牌，摸牌与发牌归执行层。点数词认英文与数字两形，一和十四以上拒绝。

随机过滤器每行以分母倒数的概率打印：分母六就是六分之一。实现是抽一个分母之内的均匀数，抽中零就选中。种子混时钟、微秒、进程号三样，同样的三样在纯层可复现，执行层每次真随机。分母为零拒绝，抽数超界拒绝。

## 2. C 源码分析

### 2.1 探险：词汇上限与物品移动

词汇上限 `HTSIZE 512`（头文件第 78 行附近）是查表数组的长度，物品描述数组一百零一项（第 101 行附近），初始位置数组（第 116 行附近）管开局摆放。物品移动（第 72 行附近）按编号分界：小于等于一百记房间，大于一百记固定点。Rust 侧 `adventure.rs` 的词汇接口（切片表加空表）与查表语义对应，移动分界函数与移动语义逐项对应，出口跟随与房间语义对应。

### 2.2 钓鱼：点数与成书

点数常量十三（第 61 行附近）定死牌面种类，整副牌（第 64 行附近）是点数乘花色，四手牌数组（第 77 行到第 78 行附近）各记点数持有量。成书计数（第 83 行附近）数满四的点数，要牌提示（第 160 行附近）问玩家要什么。Rust 侧 `fish.rs` 的点数解析（英文与数字两形）与牌面语义对应，成书计数（满四成书、超四报错）与计数语义对应，要牌选择（有牌未问的最小点数）与策略语义对应。

### 2.3 格言：索引表定位

格言选择走索引表：先定位到表头（第 267 行附近），再按表项读偏移（第 980 行附近），最后定位读正文。数据文件在 `datfiles` 目录下，多个主题各一库。Rust 侧 `fortune.rs` 的格言库接口（切片库加空库）与选择语义对应，取余抽签与均匀语义对应，分隔符切分与磁盘形状对应。

### 2.4 首字母与随机：跳过词与分母选中

首字母脚本的两个文件标志管攻击性文件与额外库，`is` 词在术语之前跳过。随机工具播种混时钟微秒与进程号（第 107 行附近），选中条件是分母内抽中零（第 126 行附近），概率恰为分母倒数。Rust 侧 `acronym.rs` 的行解析与跳过词、`lottery.rs` 的分母解析与选中条件与这两处逐项对应。

## 3. Rust 设计决策

### 3.1 为什么词汇查表不分大小写，而不是要求玩家小写输入

玩家输入什么的都有，全大写、首字母大写、大小写混杂。要求玩家先转小写是把程序的方便转嫁给玩家，转嫁的代价是体验差。不分大小写比较只多一行折叠，成本忽略不计。空词单独拒绝，因为空词连查的意义都没有，而且空词往往意味着输入管线断了，早报错早定位。

### 3.2 为什么付钱破产用报错，而不是记负数继续玩

负数余额没有规则意义：规则里破产就是出局，继续玩下去后面的买地盖房全是错的。报错让调用方（游戏主循环）立刻结算出局，而不是带着负数跑完一局才发现账对不上。收钱用饱和加是另一面：钱再多也不能溢出回绕，溢出回绕会把首富变成负翁。两种不对称处理各有理由：付钱错是规则事件，收钱溢出是算术事故。

### 3.3 为什么格言抽签用取余，而不是拒绝超界抽数

抽数来自随机源，范围不可控，拒绝超界等于要求调用方先对好范围，多一层约定就多一处错位。取余把任何抽数映射到库内，调用方随便给，纯层永远有答案。均匀性要求转移到随机源身上：随机源均匀则抽签均匀，随机源偏则抽签偏，责任边界清晰。空库是唯一的真错误：没有格言可抽，报查无。

### 3.4 为什么纸牌点数认两形，而不是只认数字

玩家说 `king` 和说 `13` 应该等价，因为牌面上印的是字母不是数字。只认数字逼玩家做翻译，翻译错了还怪玩家。英文形与数字形在解析期统一成零起编号，下游只认编号。大小写不分与词汇表同理。一和十四以上拒绝，因为牌里没有。

### 3.5 与同类系统的对照：故事进数据，规则进类型

架构演进决策：大文本数据（探险地图描述、垄断卡片文字、格言库正文）进程序资源，不进代码表。理由是数据会长大、会改错别字、会加新条目，改数据不该重新编译逻辑。纯层只定形状（词条形状、分隔符形状、索引形状），形状稳定，数据流动。同类现代系统的文字游戏也是这个分法，只是资源格式不同，本篇的形状定义不依赖任何一种资源格式。

## 4. 实现详解

### 4.1 模块结构

`os/commands/games/text-games`（库包名 `minix-text-games`）共 7 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`TextGameError`，22 对应参数无效、2 对应查无、34 对应超范围）与模块组织 |
| `adventure.rs` | `hdr.h` 第 78 行与第 101 行与第 116 行附近 | 词汇接口（切片表加空表）、出口跟随、物品移动 |
| `monop.rs` | `monop.c` 棋盘语义 | 走子回绕、起点经过、付收钱、骰子 |
| `fortune.rs` | `fortune.c` 第 267 行与第 980 行附近 | 格言库接口（切片库加空库）、取余抽签、分隔符切分 |

| `acronym.rs` | `wtf` 脚本标志与跳过词 | 跳过词、行解析、首命中查询 |
| `lottery.rs` | `random.c` 第 107 行与第 126 行附近 | 分母解析、选中条件、种子混合 |

### 4.2 关键类型与不变量

- **词汇 `VocabEntry`**：词加种类加编号。不变量：查词不分大小写；空词即错；未知报查无；空表一切查无。
- **出口 `Exit`**：动作码加房间。不变量：无匹配动作报查无；房间号原样返回。
- **钱**：余额加金额。不变量：付成负数报超范围；收钱饱和；骰子一到六。
- **格言库 `QuipDb`**：索引加计数。不变量：空库一切查无；抽数取余恒有答案；空段跳过。
- **纸牌点数**：零到十二编号。不变量：英文数字两形等价；一与十四以上拒绝；每点零到四张。
- **首字母行**：词条加解释。不变量：词条无空白；两边去空；首命中获胜；`is` 跳过。
- **分母**：正整数。不变量：零拒绝；抽数超界拒绝；选中当且仅当抽中零。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `parse_word` | 表、词 | 词条 | 查词语义 |
| `follow_exit` | 出口表、动作 | 房间 | 移动语义 |
| `move_object` | 物品、房间 | 两表位置 | 摆放语义 |
| `advance_position` | 位置、步数 | 新位置 | 走子语义 |
| `pay` | 余额、金额 | 新余额 | 付钱语义 |
| `pick_quip` | 库、抽数 | 格言 | 抽签语义 |
| `count_books` | 手牌 | 书数 | 成书语义 |
| `choose_ask` | 持有、已问 | 点数 | 要牌语义 |
| `lookup_acronym` | 行表、词条 | 解释 | 查询语义 |
| `is_selected` | 抽数、分母 | 是否选中 | 过滤语义 |
