## 1. 概念：连通之后的三件事

### 1.0 本章说明

机器连上网之后，接下来有三件事。第一件是等人上门：有些服务平时不运行，有连接来了才启动，省内存，省管理，这就是超级服务器。第二件是记日志：系统里到处都在说话，内核、守护、应用都在产生消息，需要有人按类别和轻重分拣，写文件，发终端，转给远方，广播给所有人。第三件是替用户跑腿：取文件，传文件，登录远方，查名字，收邮件，打文件。

> **本章不讲什么**：
>
> - 传输协议的状态机（见网络阶段）
> - 进程如何创建与切换用户（待进程接口）
> - 邮件投递与打印渲染的后端（本篇只到队列语义）
>
> 本章只讲服务语言：服务表怎么写，日志怎么分拣，定位符怎么读，会话怎么准入。

### 1.1 超级服务器：平时睡觉，有客才起

为每个服务常驻一个进程太浪费：十几个服务里平时活跃的可能只有一两个。超级服务器替所有服务守着端口，有连接来了，按表查到对应的服务程序，启动它，把连接交过去，自己回去继续守。表的每一行写清服务名、套接字种类、传输协议、等待模式、运行用户、服务程序路径、启动参数。

等待模式区分两种服务：单线程的数据报服务自己抱着套接字慢慢处理，超级服务器等它处理完再收下一个；多进程的流服务每个连接 fork 一个新进程，超级服务器立刻回去接下一个。回显、丢弃、报时、字符发生四种服务简单到不需要外部程序，超级服务器自己就能回答，标成内置。

### 1.2 系统日志：按类别和轻重分拣每条消息

系统里每条日志消息都带一个优先级：类别部分说明谁发的（内核、用户、邮件、守护、认证、本地零到七），严重度部分说明多严重（调试、信息、注意、警告、出错、危急、报警、瘫痪）。没有类别的消息给缺省用户优先级，内核来源的给缺省内核优先级，保证每条消息都有归宿。

分拣规则写成选择符：类别点严重度表示该类别达到该严重度及以上的都要，星号表示所有类别，none 表示该类别排除。动作种类说明消息去哪：写普通文件，发终端，发控制台，转给远方机器，发给用户列表，广播给所有登录用户，管道给程序，写先进先出队列。重复消息抑制避免日志被刷屏：短时间内相同的消息只记一条加一个重复计数。

### 1.3 跑腿客户端：定位符、会话与队列

取文件命令读定位符：方案前缀说明用哪种传输（超文本还是文件传输），主机部分说明去哪，端口缺省按方案补，路径缺省为根。输出文件用选项指定，超时用选项指定，主机加文件加目录的老写法和定位符新写法都支持。

文件传输、终端、远 shell 三个守护共享同一套会话流程：先发欢迎横幅，再验用户名口令，再看策略文件允不允许登，文件传输还可能把会话关进更换根目录，登录记账写进登录记录。认证失败报查无而不是报口令错，避免向探测者透露用户名是否存在。策略拒绝报拒绝，和认证失败区分开，管理员排查时能分清是口令错了还是策略拦了。

邮件和打印是队列：发件先入队，投递慢慢来，打印先排队，假脱机逐个打。本篇只到队列语义，投递的路由和打印的渲染归各自后端。

## 2. C 源码分析

### 2.1 超级服务器：套接字上限与参数上限

最多服务的套接字数 `OPEN_MAX 64`（第 276 行附近）是超级服务器同时守的端口上限，超过就放不下。每个服务程序的参数上限 `MAXARGV 20`（第 306 行附近）含程序名本身，超长配置行在装载时就被拒绝，不会带病运行。内置服务的四个处理函数族（第 339 行到第 348 行附近）覆盖回显、丢弃、报时、字符发生，每种各有数据报版和流版：数据报版自己抱着套接字，流版每个连接一个进程。

Rust 侧 `inetd.rs` 的服务行结构与表的列逐项对应，内置服务表与这四个名字逐项对应，两个上限以同名常量逐项对应。

### 2.2 系统日志：动作表与优先级解码

动作种类从文件到先进先出队列共八种（第 130 行到第 137 行）：普通文件，终端，控制台，远方机器，用户列表，广播，管道，先进先出队列。优先级解码看掩码（第 1488 行附近）：低三位是严重度，其余是类别。无类别的消息给缺省用户优先级（第 1471 行附近），内核来源的无类别消息给缺省内核优先级（第 1528 行附近），两处缺省保证每条消息都有归宿。控制台动作的行在分发时有独立的忽略标记，终端与控制台在落盘判断里走同一分支。

Rust 侧 `syslog.rs` 的动作枚举与八种动作逐项对应，优先级解码与掩码划分逐项对应，选择符的通过判断（达到最低严重度即通过，排除即不通过）与分拣语义对应。

### 2.3 取文件与传输守护：用法行与命令表

取文件命令的用法行（第 859 行附近）列出输出文件、超时、主机、文件、目录选项与末尾的定位符：两种写法并存，老写法分字段给主机文件目录，新写法一个定位符全包。文件传输守护的命令表在 `cmds.c`，配置在 `conf.c`，主程序在 `ftpd.c`，登录记账分写登录记录与写登出记录两个小文件。终端守护管协商，远 shell 守护管执行，手指守护管查询，超文本守护管文档，各守一摊。

Rust 侧 `fetch.rs` 的定位符解析（方案、主机、端口、路径四段）与用法的定位符分支对应，`session.rs` 的准入决策（空名 malformed、验错报查无、策略拦报拒绝）与守护的登录语义对应。

## 3. Rust 设计决策

### 3.1 为什么服务表用借用切片而不是自有字符串

服务表在守护启动时装载一次，之后只读不写。借用切片零拷贝，行数固定，查询是线性扫描首次命中，行为和配置文件从上到下的顺序语义天然一致。自有字符串要分配堆，在无标准库环境下不可用，而且守护的热路径是查询不是修改，为修改付出的代价不划算。如果将来需要运行时增删服务，可以在执行层包一层可变表，纯判断层的借用表不需要动。

### 3.2 为什么严重度用枚举派生排序，而不是用数字比较

严重度的轻重顺序是语义，不是偶然的数字排列。用枚举把八个等级按从轻到重声明，派生排序后大于等于就是达到及以上，一行代码表达分拣规则。用数字比较要记住哪个数字对应哪个等级，读代码的人要翻表，而且数字写错一位就是静默错误。枚举写错名字会编译失败，错误在编译期暴露。解码时数字到枚举的映射集中在一处，映射错了测试立刻抓住。

### 3.3 为什么认证失败报查无，而不是报口令错

向未认证的对端透露用户名是否存在，是信息泄漏。探测者可以用不同的用户名反复试，从报错的差异里枚举出系统上有哪些用户，再针对真实用户做口令猜测。统一报查无把两种失败混在一起，探测者分不清是名错了还是口令错了，枚举的效率大减。策略拒绝单独报拒绝，因为那是管理员的明确意图，排查时需要分清。空名是 malformed，最先拒绝，连认证流程都不进。

### 3.4 为什么日志池只计数不存文本

纯判断层要回答的是路由对不对，不是把日志存下来。存文本需要堆或者大静态缓冲，容量规划困难，而且文本的归宿（文件、终端、远方）是执行层的事。计数器按动作分八格，每存一条对应格加一，测试可以断言分拣结果，内存占用恒定。空行拒绝，超长行拒绝， Grenze 明确。执行层在调用存储之前先问路由，路由说去哪才写哪，判断与执行不纠缠。

### 3.5 与同类系统的对照：守护只做分发，机制留在内核与库

本篇延续上一章的分层：命令和守护只做翻译与分发，真正的传输机制在网络阶段，真正的进程机制在进程阶段。超级服务器不实现任何应用协议，只负责查表和启动。日志守护不实现任何存储格式，只负责分拣和投递。同类现代系统也用同样的分法，只是启动机制不同，本篇的纯判断层不依赖任何一种启动实现。

## 4. 实现详解

### 4.1 模块结构

`os/commands/usr-sbin/netservices`（库包名 `minix-netservices`）共 5 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`ServiceError`，22 对应参数无效、2 对应查无、13 对应拒绝）与模块组织 |
| `inetd.rs` | `inetd.c` 第 276 行与第 306 行与第 339 行到第 348 行附近 | 套接字种类、等待模式、服务行、内置表、服务表接口 |
| `syslog.rs` | `syslogd.c` 第 130 行到第 137 行与第 1488 行附近 | 动作编解码、严重度解析、优先级解码、选择符、日志池接口 |
| `fetch.rs` | `fetch.c` 第 859 行附近 | 方案解析、定位符解析、端口解析 |
| `session.rs` | `ftpd.c` 与登录记账 | 会话记录与准入决策 |

### 4.2 关键类型与不变量

- **套接字种类 `SocketKind`**：流与数据报。不变量：未知词即错；内置服务两种都支持。
- **等待模式 `WaitMode`**：等待与不等。不变量：数据报单线程用等待，流多进程用不等；未知词即错。
- **服务行 `ServiceEntry`**：名字、套接字、协议、等待、用户、程序。不变量：名字与协议非空；首次命中获胜；空表一切查无。
- **日志动作 `LogAction`**：八种去向。不变量：编号一到八连续；零与九之外即错；往返编解码恒等。
- **严重度 `Severity`**：八级。不变量：声明顺序即轻重顺序；未知词即错；缩写与全称等价。
- **优先级 `Priority`**：类别加严重度。不变量：低三位恒为严重度；本地类别带序号；未知类别归用户类。
- **选择符 `Selector`**：类别加最低严重度。不变量：排除恒不通过；达到最低即通过；类别空表示全体。
- **定位符 `Locator`**：方案、主机、端口、路径。不变量：缺方案分隔符即错；主机空即错；路径恒以斜杠开头；缺端口按方案补。
- **会话 `SessionSetup`**：用户、横幅、更换根、认证结果。不变量：空名即错；验错报查无；策略拦报拒绝；更换根非空即受限。
