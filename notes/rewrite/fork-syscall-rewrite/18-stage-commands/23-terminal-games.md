## 1. 概念：在格子上动起来的三件事

### 1.0 本章说明

上一章的游戏只说话，这一章的游戏要动屏幕。动屏幕需要三件事：知道屏幕多大、能把光标送到指定格、能在格子里写字擦字。七个终端游戏共享这三件事，区别在玩法：方块往下掉，蛇往前爬，虫往前拱，雨往下落，地牢一间一间探。

> **本章不讲什么**：
>
> - 终端能力数据库的移植（架构演进决策，见 3.5 节）
> - 键盘逐键读取（各游戏二进制包）
> - 怪物、物品、计分规则（后续补齐）
>
> 本章只讲格子语言：屏幕多大，块怎么转，蛇怎么长，虫怎么拱，房间怎么摆。

### 1.1 屏幕：格子与转义序列

屏幕是宽乘高的格子，每个格子一个字符加一个高亮标志。纯层用内存屏幕：读写按坐标，越界报错，清屏全变空白。空屏幕是测试替身：写了就忘，读全是空白，尺寸读零。控制码是纯字符串：清屏一串，光标回家一串，光标定位按行列数组装。行列从一数，零拒绝，因为终端的行列从来没有零。

内存屏幕定容上限（宽 132、高 50）覆盖经典终端，超了报参数无效。定容即保护：游戏进程短命，不需要动态大屏，坏尺寸在到达绘制之前就被拦下。

### 1.2 方块：七种形状与消行

七种方块各四格，首格是转轴。旋转是坐标转置加取反，转四次回到原样，纯层的旋转测试钉死这个循环。吻合测试看四个格是否全落在空棋盘格里：出界不行，压住已有格不行。放置先吻合再填色，吻合不过报参数无效。消行从底行往上扫，满行清掉，上面的行整体下移，顶行补空，一次返回消掉的行数。计分按经典表：消一二三四行各得四十、一百、三百、一千二百分，别的行数不得分。

### 1.3 蛇与虫与雨：爬行动物的三种走法

蛇有朝向，朝向不能直接反转（往右时不能直接往左），反转拒绝。走一格分两种：普通走（头进新格、尾巴松开）与吃食走（头进新格、尾巴留下，身体长一格）。撞墙死，撞自己死（松开的尾巴格不算），身体满了再吃报满。虫更简单：头到哪，身体跟到哪，没有朝向概念，几条虫各爬各的。雨是竖直的虫：每帧下一格，到底回顶，延时选项一到九百九十九毫秒，超了拒绝。

三种走法的共性是头跟身体：新头先定，老身体依次跟进。纯层把跟进写成一段搬移，蛇、虫、雨滴都用它，区别只在规则（朝向、生长、回绕）。

### 1.4 地牢：房间与走廊

地牢每层最多九个房间，房间至少三乘三，贴边留一圈墙。两个房间算重叠的标准带一圈墙余量：挨着也算重叠，邻居永远不共墙。房间表校验三件事：个数不超，每间合法，两两不重叠。走廊先横后竖打直角，只把岩石变成通道，地板房门原样保留，所以走廊穿过房间不会把地板吃掉。怪物、物品、陷阱、计分是下一层故事，本篇只到地图几何。

## 3. Rust 设计决策

### 3.1 为什么屏幕用接口隔离，而不是直接操作转义序列

转义序列是输出格式，格子是游戏状态。游戏逻辑只关心格子（这格有没有蛇头），不关心序列（光标怎么过去）。接口隔离后，逻辑测试用内存屏幕跑，断言格子内容，完全不用解析转义字符串。空屏幕再进一步：连格子都不存，逻辑只验流程不验内容。如果逻辑直接拼转义序列，每个测试都要解析字符串找字符，测试写得又长又脆。

### 3.2 为什么旋转用坐标公式，而不是查旋转表

查表要存每个形状的四个朝向，二十八组坐标，手写易错，核对要逐格看。坐标公式一行：新横等于老纵，新纵等于负老横，转四次恒等，测试转四次即验。公式对七个形状通用，加新形状不用加表。查表唯一的优势是快，但旋转一秒最多几次，公式的速度绰绰有余。可读性与可扩展性压倒查表的微小速度。

### 3.3 为什么蛇的尾巴格在普通走时不算自撞

普通走是头进尾松同时发生：尾巴格在这一帧会空出来，头进去不算撞。如果把尾巴格算进去，蛇咬自己尾巴尖这种合法走位会被误判死，玩家会觉得游戏耍赖。吃食走保留尾巴，尾巴格照算，逻辑对称。两种走法的区别只在身体窗口是否含尾，测试用贴尾走位钉死。

### 3.4 为什么随机数用接口加两个确定源，而不是直接读系统随机

游戏逻辑测试不能 flake：食物位置、方块顺序、房间布局都要可复现。接口后面挂两个确定源：固定循环（按给定序列出数）与零源（永远出零，最倒霉的运气）。测试用固定循环摆出想要的局面，用零源测边界。系统真随机随执行层落地，逻辑层一个字不用改。如果逻辑直接读系统随机，测试只能断言统计性质，又慢又偶发失败。

### 3.5 与同类系统的对照：转义序列直发，不移植能力数据库

架构演进决策：终端能力数据库不移植。理由是目标终端单一（系统控制台与常见模拟器都懂基础转义序列），移植整套数据库与解析器是重武器打轻目标。纯层只发三类序列（清屏、回家、定位），都是三十年不变的基础序列。如果将来遇到不懂这些序列的终端，再在执行层加能力查询，纯层不动。同类极简系统也用同样的取舍。

## 4. 实现详解

### 4.1 模块结构

`os/commands/games/term-games`（库包名 `minix-term-games`）共 7 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |

### 4.2 关键类型与不变量

- **格子 `Cell`**：字符加高亮。不变量：越界读写即错；清屏全空白。
- **内存屏幕 `MemoryScreen`**：宽乘高。不变量：零尺寸与超限拒绝；索引恒等于行乘定宽加列。
- **方块 `Piece`**：四格加颜色。不变量：首格恒为转轴；七形状不多不少；转四次恒等。
- **棋盘 `Board`**：十乘二十占用表。不变量：吻合不过不写；消行从底往上；顶行补空。
- **朝向 `Heading`**：四向。不变量：反转拒绝；步进与朝向严格对应。
- **蛇 `Snake`**：头首尾末。不变量：普通走长度不变；吃食走长一格；尾巴格普通走不算撞；满格再吃报满。
- **爬行者 `Crawler`**：头首尾末。不变量：跟进搬移；长度不变；空长度拒绝。
- **房间 `Room`**：角加尺寸。不变量：三乘三起步；贴边留墙；重叠带一圈余量；全表不超九间。
- **随机源 `GameRandom`**：定界出数。不变量：零界拒绝；空序列拒绝；固定循环按序重放。
