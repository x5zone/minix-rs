## 1. 概念：切分、命名、格式化

### 1.0 本章说明

本章讲磁盘变卷的三步：切分（分区表）、命名（类型码）、格式化（建文件系统）。以及卷大小的说法（人类单位）。

> **本章不讲什么**：
>
> - 分区写入与格式化的执行（待块设备接口）
> - 各文件系统的内部结构（见 `15-stage-fs`）
> - 引导加载程序（见引导阶段）
>
> 本章只讲布局语言：表长什么样、类型码说什么、大小怎么说。

### 1.1 主引导记录：446 字节之后的世界

磁盘首扇区（512 字节）尾部藏着分区表：446 字节处起四项、每项 16 字节，510 字节处是魔数 `0xAA55`（小端存 `55 AA`）。每项 16 字节：激活标志（`0x80` 可引导）、起始几何三字节（历史遗产，仅供显示）、类型码、结束几何三字节、起始扇区号（小端 32 位）、扇区数（小端 32 位）。魔数不对即"此盘无表"（新盘、非分区盘、损坏盘三可能，命令必须区分报错与空表——"坏"与"无"是两回事）。

几何三字节（柱面磁头扇区）是 BIOS 时代的寻址文物：现代工具只显示不计算，真凭实据是 32 位起始扇区号。本库解析几何字节但不解释（存而不算），文档如实说明其"仅供显示"地位——不算的东西不假装懂。

### 1.2 类型码：一个字节的身份声明

类型码说"这个分区里是什么"：`0x81` Minix（`0x80` 是 1.4a 之前的老 Minix）、`0x83` Linux 原生、`0x82` Linux 交换、`0xA5` 386BSD、`0x07` NTFS、`0x0B` FAT32……全表在头文件第 279 到 328 行。本库只命名常见十七种，未知类型返回"无名"而非猜测——猜类型码是灾难之源（把交换分区当 Minix 格式化会丢数据）。

### 1.3 分区工具链：看、改、自动排

- `fdisk`（交互式分区）、`part`（读写分区表，含排序基准与起止换算）、`partition`（显示）、`autopart`（自动排布）、`repartition`（重排）：同一张表的五种操作面（交互、脚本、显示、自动、重布）。
- `format`（低级格式化）、`devsize`（报设备大小）：准备链的两端（ media 初始化与容量查询）。

### 1.4 格式化家族：新卷四格式加制像器

`newfs_ext2fs`、`newfs_msdos`、`newfs_udf`、`newfs_v7fs`（四种文件系统的新卷工具）加 `makefs`（从目录树制像）加 `mkfs`（统一入口）：参数面共享"卷大小说法"（本库 `size.rs`：`10M`、`512K`、`1G` 二进制单位，溢出报错）。大小算错是格式化领域最具破坏力的静默错误（多一位零就吞掉整盘），解析器用 checked 算术逐级验溢出——"算不出就报错"在这里是安全刚需。

### 1.5 阅读顺序说明：先用后备

计划列本篇前置为 `14`（挂载），但阅读顺序是 `14` 在前、`15` 在后：先看到"挂载的卷从哪来"的问题（`14` 的表行指向 `/dev` 下的分区设备），再学"分区设备怎么来"，动机最清楚。与 `07`/`08` 的编排同理（先用后学），不再重复论证。

## 2. C 源码分析

### 2.1 `bootblock.h`：布局的权威来源（第 150 到 746 行）

注释区（第 150 到 182 行）逐段标注首扇区用途（表在 446、魔数在 510），宏区定义偏移与魔数（`MBR_PART_OFFSET` 446、`MBR_MAGIC` `0xAA55`、`MBR_PART_COUNT` 4、激活标志 `0x80`），类型码区（第 279 到 328 行，Minix 对在 299 到 300 行），结构区（第 703 到 745 行：16 字节项、小端起止、魔数尾）。Rust 侧 `mbr.rs` 的常量（446、510、`0xAA55`、4、16、`0x80`）与之逐字对应——抄布局代码以"逐字"为荣。

### 2.2 `part.c`：读写两端

引导块数组（第 300 行 512 字节）、表拷贝三处（第 384 到 482 行：读出、写入、比对）、起止换算（第 550 到 551 行表头行、第 691 到 702 行三函数：基址、末址、大小）。`entry2last` 的"起加长减一"与本库 `last_sector` 同式（含空槽与溢出防护）；`sortbase` 的排序思想与 `14` 篇检查排序同源（表序有意义）。

### 2.3 `fdisk.c`：表指针定位

`part_entry` 指针落在 `secbuf + n_OFF` 处（表偏移的别名），槽位加一即下一项——指针算术即表结构，Rust 侧用切片索引（`TABLE_OFFSET + i * ENTRY_SIZE`）等价表达（无指针算术，但形状一致）。

### 2.4 新卷工具族：参数面职责级

四 `newfs` 加 `makefs` 加 `mkfs`：各守一格式，参数面共享"大小说法"（本库 `size.rs`）。卷内结构（超级块、位图、根目录）各归其文件系统阶段，本篇只定"多大"的语言。

## 3. Rust 设计决策

### 3.1 为什么几何字节存而不算

起始几何三字节的编码（柱面高低位拆分）是 BIOS 遗产，现代寻址只用 32 位起始扇区。解析保留（结构体诚实），语义不解释（无函数消费）——"存而不算"比"删了省事"好（删了就读不懂旧工具的显示），也比"算了充数"好（算了就是错）。三态（解析、解释、忽略）中取中间态，文档写明理由。

### 3.2 为什么未知类型返回无名

类型码表永远在长（新系统新类型），硬编码全表是追不上的游戏。十七常见命名加未知返回空——调用方（`part` 显示）对空显示原始十六进制数（信息无损），而不是编一个名字（信息造假）。"无名"不是缺失，是设计。

### 3.3 为什么大小解析用 checked 全程

`18446744073709551615G` 必须报错而不是回绕成小数字——回绕的 size 会格式化错误的卷。`checked_mul` 逐级（十进制累积、单位相乘）加 `x` 连乘，任一步溢出即错。测试 `test_overflow_rejected` 用最大 64 位数加单位触发溢出路径——溢出测试必须用真溢出值，不能用"看起来很大"的值，这是数值测试的铁律。

## 4. 实现详解

### 4.1 模块结构

`os/commands/sbin/diskfmt`（库包名 `minix-diskfmt`）共 3 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`DiskError`，22 对应参数无效、2 对应空槽）与模块组织 |
| `mbr.rs` | `bootblock.h` 布局 | 扇区解析（`parse_sector`）、项解析（`parse_entry`）、类型命名、`PartitionTable` 接口 |
| `size.rs` | 新卷参数面 | 人类单位解析（`parse_size`）与扇区换算（`sectors_for`） |

### 4.2 关键类型与不变量

- **分区项 `PartitionEntry`**：激活、类型、起止。不变量：标志只认零与 `0x80`；空槽（类型零）无末扇区；零长无末扇区；溢出无末扇区（`checked_add`）。
- **魔数**：小端 `0xAA55` 在 510。不变量：不对即错（坏与无在此不分——调用方结合上下文区分，解析层只报"非表"）。
- **类型命名**：十七常见。不变量：未知返回空（不猜）；空类型名"未用"。
- **人类单位**：十进制数加可选单位。不变量：空串错；纯单位错；未知后缀错；溢出全程检查；`x` 连乘左结合。
- **分区表 `PartitionTable`**：槽查询。不变量：空槽查无（不是错）；越界查无；空表零槽。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `parse_sector` | 512 字节 | 四项 | 表布局语义 |
| `parse_entry` | 16 字节 | 一项 | 项布局语义 |
| `type_name` | 类型码 | 名或无 | 类型码语义 |
| `parse_size`/`sectors_for` | 文本与扇区大小 | 字节与扇区数 | 大小说法语义 |
