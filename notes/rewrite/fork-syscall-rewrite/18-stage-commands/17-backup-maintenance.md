## 1. 概念：数据已经存好之后的三类担心

### 1.0 本章说明

想象你已经把文件系统挂上，把磁盘切好，把数据存进去。故事结束了吗？没有。真实世界里还有三类担心，每天都会找上门。

第一类担心是丢失：磁盘会坏，误删会发生，断电会丢掉刚写的数据。所以需要复制留底，需要知道哪些文件变了需要重新复制，需要把复制送到另一台机器。

第二类担心是堆积：临时目录越长越大，日志文件越写越长，旧的备份占满磁盘。所以需要定期清理过期文件，需要把日志按代轮转，需要一个看得见的进度条。

第三类担心是介质：还有磁带机这种顺序介质，一次只能向前或者向后走，不能随机跳。所以需要一套磁带动作语言，前进几个文件，后退几条记录，倒带，弹出，查看状态。

> **本章不讲什么**：
>
> - 文件系统内部如何遍历目录（见文件系统阶段）
> - 磁带驱动如何执行动作（见驱动阶段）
> - 终端如何重绘进度条（见终端阶段）
>
> 本章只讲判断语言：什么该复制，什么该删除，进度怎么算，磁带命令怎么说，日志怎么轮转。

### 1.1 复制留底：像制作工具一样只做增量

备份命令的核心想法可以用一句话讲清：目标目录是空的就全部复制，目标目录里有旧备份就只复制新增的和过期的。这个行为和制作工具非常像，只是制作工具依据规则文件判断过期，备份命令依据修改时间判断过期：源文件比目标文件新，或者目标文件根本不存在，就复制，否则跳过。

为什么只做增量？因为全量复制太慢。软盘时代一次备份要换好几张盘，只复制变化的部分才能让人坚持备份。这个取舍一直保留到今天：增量判断只需要比较两个修改时间，代价极小，收益极大。

十个选项字母各自回答一个实际问题。只备份顶层目录还是连散文件一起备份，垃圾名字要不要跳过，目标盘满了是报错还是换盘，对象文件和汇编文件要不要跳过，是备份还是恢复，目标时间要不要和源时间一致，要不要详细播报，要不要压缩。每个选项都是一次真实教训的沉淀，不是装饰。

### 1.2 同步到远方：两棵目录树如何达成一致

远程同步和目录树同步解决的是同一个问题：两台机器或者两个目录，如何变得一样。做法是各自列出自己的文件清单，逐个比较，缺的补上，旧的刷新，多的按策略处理。硬链接需要特别跟踪，因为同一个文件内容可能有多个名字，只复制内容不记录链接关系会把一份文件变成多份。

传输按固定大小的块进行，每次搬运固定字节数，大文件分多次搬完。这样慢速链路也不会因为一个大文件卡死整个同步，小块失败重传的代价也小。

### 1.3 清理过期：午夜对齐的保留窗口

临时目录清理的核心是一个时间换算：用户说保留若干天，程序把它换算成两个时间戳。先把当前时间取整到当天午夜，再往前倒退保留天数减一天，得到普通名字的过期线。隐藏名字用更长的窗口单独算一条过期线，而且隐藏名字的过期线永远不许跑到普通名字的过期线前面。早于过期线的文件删掉，新于过期线的文件留下。强制模式删掉一切，调试模式只说不删。

为什么取整到午夜？因为用户说的保留若干天指的是自然天，不是精确到秒的滑动窗口。午夜对齐让每天凌晨跑一次清理的结果稳定可预期，不会因为执行时刻差几分钟而多删或者少删一批文件。

### 1.4 进度和磁带：看得见的等待与顺序介质的语言

进度条解决的是等待焦虑：一次备份要跑很久，用户想知道还剩多少。程序从命令行读入总数，从标准输入逐行读入已经完成的名字，每读一行重绘一次：还剩多少个文件，方括号里用等号表示已完成份额，用竖线表示当前光标，用减号表示剩余份额。总数为零时不做除法，直接画空条，程序永远不该因为除零崩溃。

磁带机是顺序介质，不能像磁盘那样随机读写，只能向前走或者向后走。磁带控制命令就是这套动作的语言：写文件结束标记，前进几个文件，前进几条记录，后退几个文件，后退几条记录，走到介质末尾，倒带，离线，查看状态，收紧磁带，擦除，选择密度，选择块大小。每个动作对计数的要求不同：有些动作忽略计数，有些接受零和正数，有些要求严格为正。状态查询是唯一不需要驱动配合的动作，程序自己就能回答。

## 2. C 源码分析

### 2.1 备份命令：选项表与复制缓冲

备份命令的选项说明写在 `minix3/minix/commands/backup/backup.c` 的文件头注释里，十个字母的含义逐行列出：只备份顶层目录，跳过垃圾名字，盘满换盘，只备份散文件，跳过对象文件，恢复方向，跳过汇编文件，保持创建时间，详细播报，压缩传输。复制缓冲 `COPY_SIZE 4096`（第 52 行）决定每次读写搬运的字节数，每目录最多 `MAX_ENTRIES 512` 个条目（第 53 行）决定目录排序表的上限，每条路径最多 `MAX_PATH 256` 个字符（第 54 行）决定路径缓冲的长度。致命错误与非致命错误用 `FATAL` 和 `NONFATAL` 区分（第 55 行到第 56 行），压缩工具返回码 2 表示没有省出空间（第 57 行），空间耗尽用 `OUT_OF_SPACE` 表示（第 58 行）。

Rust 侧 `backup.rs` 的选项结构与这十个字母逐项对应，垃圾名字判断与注释里的后缀表逐项对应，复制决策（目标缺失则复制新增，源比目标新则复制过期，否则跳过）与制作工具式增量语义对应。

### 2.2 远程同步与目录树同步：三张记录表

远程同步用三张记录描述同步对象：路径记录（第 101 行附近）描述一条路径的完整形态，名字链表（第 177 行附近）把目录里的名字串起来，按文件记录（第 285 行附近）描述单个文件的模式与时间。硬链接跟踪用独立的小链表实现，相同设备号加相同索引号只存一次内容。用法函数（第 1472 行附近）拒绝互相冲突的选项组合。

目录树同步用固定大小的块搬运文件（`CHUNK 4096`，第 55 行），数字按固定字节数编码（`NUMBYTES`，第 54 行），目录条目记录（第 200 行附近）用三根指针描述树形（同级下一个、所属目录、子内容首个）。本篇到职责级为止，网络传输与文件遍历归执行层。

### 2.3 临时目录清理：一天的长度与隐藏名字的宽限

一天的长度 `SEC_DAY`（第 31 行）定义为 24 乘以 3600 秒，隐藏名字至少保留 `DOTDAYS 14` 天（第 32 行）。午夜取整函数 `days2time`（第 56 行附近）先把当前时间取整到当天午夜，再减去保留天数减一天得到普通名字的过期线，用隐藏名字的窗口单独算隐藏名字的过期线，并把隐藏名字的过期线钳在普通名字的过期线之前。强制开关（第 53 行附近）打开时跳过一切比较直接删除。

Rust 侧 `cleantmp.rs` 的保留窗口换算与这个函数逐项对应：午夜取整用除余丢掉当天已过秒数，时钟早于窗口时两条过期线都归零，隐藏名字的过期线永远不许跑到普通名字的过期线前面。

### 2.4 进度条：总宽固定为 77 列

进度绘制函数 `prettyprogress`（第 11 行附近）打印剩余文件数，方括号里按完成份额画等号，画一条竖线做光标，剩余部分画减号。总宽 `WIDTH 77`（第 34 行）是整行的列数上限。总文件数从命令行读入（第 56 行附近），每从标准输入读到一行就重绘一次，输入行显示前截断到 78 个可见字符。

Rust 侧 `progress.rs` 的绘制函数与这个版式逐项对应：前缀写剩余文件数，方括号里按份额画等号和减号，总数为零时直接画空条避免除零。

### 2.5 磁带控制：操作表与计数规则

磁带操作表（第 42 行附近）把每个命令词和驱动操作以及计数规则绑在一起：写文件结束标记的两个写法，前进文件，前进记录，后退文件，后退记录，走到介质末尾，倒带，离线的两个写法，状态查询，收紧磁带，擦除，选择密度，选择块大小的两个写法。计数规则分三档：忽略计数的动作，接受零和正数的动作，要求严格为正的动作。用法行 `mt [-f device] command [count]`（第 78 行）说明设备可以来自命令行也可以来自环境变量。设备状态分就绪、出错、遇到文件结束标记三种，感觉键表把驱动的感觉字节翻译成文字。

Rust 侧 `tape.rs` 的命令表与这个表格逐项对应，计数检查与三档规则逐项对应，状态解码与三种状态逐项对应。

### 2.6 日志轮转与差异修复：脚本与块命令

日志轮转脚本接受两个参数：日志路径和要保留的代数。先删掉最老的一代，中间各代依次上移一代，把当前日志压缩成第一代，再把当前日志截空。差异修复工具的输入行上限 `LINELEN 1024`（`fix.c` 第 38 行），差异块分追加、删除、替换三种，命令字母分别是增加、删除、替换（文件头注释第 11 行到第 14 行），应用前先拿原文逐行核对，冲突就报错而不是硬写。

Rust 侧 `rotate.rs` 的轮转计划与脚本的移动顺序逐项对应，差异命令字母解析与三种块类型逐项对应。

## 3. Rust 设计决策

### 3.1 为什么复制决策只依赖修改时间和名字，不过问文件内容

比较文件内容最准确，但要把两个文件都读一遍，代价太大。比较修改时间只需要两次状态查询，代价极小，而且日常场景下修改时间就是内容变化的可靠代理。如果有人刻意伪造时间戳，这个判断会被骗过，但备份工具的威胁模型里没有主动伪造时间的对手，只有磁盘故障和误删。把昂贵的精确比较留给校验工具，把廉价的近似比较留给备份工具，这是分层设计的取舍。如果将来需要内容校验，可以在复制之后加一道校验工序，而不是在决策时就读全文。

### 3.2 为什么保留窗口要对齐到午夜，而不是用滑动窗口

滑动窗口语义精确但不可预期：同样保留七天，凌晨一点跑和凌晨三点跑删掉的文件集不一样，管理员无法回答到底哪些文件会被删。午夜对齐把保留窗口变成自然天的概念，每天凌晨跑一次，结果稳定，管理员可以心算。代价是边界那一天的文件多留几个小时，这对临时目录完全可以接受。隐藏名字用更长的窗口，是因为隐藏名字往往是应用的状态而不是垃圾，误删的代价更高，所以多给宽限。

### 3.3 为什么进度绘制函数遇到总数为零时画空条而不是报错

总数为零意味着没有事情可做，这时候进度条应该安静地显示空，而不是崩溃或者报错。调用方可能是脚本，脚本传零不代表程序有错，只代表本次无事可做。纯函数里用分支处理零总数，比让调用方保证总数非零更健壮，因为调用方可能来自用户的命令行输入，输入什么都有可能。响亮失败留给真正的错误（比如写不下的缓冲），边界上的合法输入应该优雅处理。

### 3.4 为什么磁带命令表把状态查询标成解释执行

状态查询不需要驱动配合，程序自己读一份状态就能回答。如果把它和别的命令一样发给驱动，会多一次不必要的设备往返，而且在没有介质的时候反而问不出状态。把状态查询标成解释执行，执行层看到标记就知道走本地分支，不走驱动分支。这个标记是类型系统里的一位布尔值，不是注释里的提醒，写错分支会在测试里立刻暴露。

### 3.5 与同类系统的对照：轻量自研参数解析与静态链接

本阶段的命令都用轻量的手写参数解析，不引入通用的命令行解析依赖。理由是这些工具的参数形状非常简单（单字母聚集、固定位置参数），手写解析只有几十行，行为完全可控，而且和原始命令的用法行逐字对应。引入通用解析库会带来依赖体积和行为差异（比如双横线长选项的自动支持），对系统命令这种要求行为稳定的场景不划算。静态链接的取舍见全局概念文档：系统命令不经过动态链接器，所以列出依赖的命令语义相应变化（见第 20 篇）。

## 4. 实现详解

### 4.1 模块结构

`os/commands/sbin/maint`（库包名 `minix-maint`）共 6 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`MaintError`，22 对应参数无效、2 对应查无、28 对应空间耗尽、5 对应设备失败）与模块组织 |
| `backup.rs` | `backup.c` 文件头注释与第 52 行到第 58 行 | 选项解析、垃圾名字判断、复制决策、元数据源接口 |
| `cleantmp.rs` | `cleantmp.c` 第 31 行到第 73 行 | 保留窗口换算与删除决策 |
| `progress.rs` | `progressbar.c` 第 11 行与第 34 行 | 总数解析与进度行绘制 |
| `tape.rs` | `mt.c` 第 42 行附近与第 78 行 | 磁带命令表、计数检查、状态解码、磁带后端接口 |
| `rotate.rs` | `rotate.sh` 与 `fix.c` 第 38 行 | 轮转计划与差异命令字母解析 |

### 4.2 关键类型与不变量

- **备份选项 `BackupOptions`**：十个布尔值。不变量：只备份目录与只备份散文件互斥，同时出现即错；空标志词即错；未知字母即错。
- **复制决策 `CopyDecision`**：新增复制、过期刷新、已是最新则跳过、被选项过滤则跳过。不变量：过滤先于比较，被过滤的名字不看时间；时间相等算已是最新。
- **元数据源 `MetaSource`**：目录形状与修改时间。不变量：查无即错；内存表三片等长；空源一切查无。
- **保留窗口 `Retention`**：普通过期线与隐藏过期线。不变量：天数为零即错；时钟早于窗口时两线归零；隐藏过期线永不跑到普通过期线前面。
- **磁带命令 `TapeCommand`**：命令词、计数规则、是否解释执行。不变量：十六个命令词不多不少；别名共享规则；状态查询是唯一的解释执行命令。
- **计数规则 `CountRule`**：忽略、零和正数、严格为正。不变量：忽略档缺计数给缺省；零和正数档拒绝负数；严格为正档缺计数即错。
- **设备状态 `DeviceStatus`**：就绪、出错、文件结束。不变量：零一二之外即设备失败。
- **轮转移动 `RotationMove`**：源代数与目标代数。不变量：保留代数为零即错；移动数恒等于保留代数减一；目标恒等于源加一；最老一代的删除由计划隐含。

### 4.3 函数一览
