## 1. 概念：挂载是嫁接，检查是体检

### 1.0 本章说明

本章讲存物的两件事：把文件系统接进目录树（挂载），与定期给文件系统体检（检查）。前者是空间拼接，后者是结构验证。

> **本章不讲什么**：
>
> - 文件系统内部结构（索引节点、位图、目录项，见 `15-stage-fs`）
> - 块设备的驱动（见驱动阶段）
> - 检查遍的具体算法（后续文件系统阶段）
>
> 本章只讲命令面：挂载说什么、表怎么写、检查按什么顺序跑。

### 1.1 挂载：把存储嫁接到目录树

空目录树只有根，`mount 设备 挂载点 -t 类型 -o 选项` 即"把这个文件系统的根嫁接到这个目录上"。之后访问挂载点即访问该文件系统——用户看不到边界（`df` 能看到，日常使用看不到）。`umount` 摘除（忙则拒绝：有进程正在里面工作时硬摘会丢数据，这是保护不是刁难）。选项管嫁接的规矩：只读、禁执行、忽略特殊位、同步写、不更新访问时间、无设备文件——每个选项都是一条安全或语义契约，拼错必须大声失败（本库 `options.rs` 未知词报错的理由）。

### 1.2 文件系统表：六字段的静态婚约

表（`fstab`）是"开机自动挂载清单"：设备、挂载点、类型、选项、备份频率、检查序号六字段一行。备份频率今已多为零（转储工具退役），检查序号仍是活的（0 跳过、1 先查根、余下升序）。`newfstab.sh`（单参数、读 Minix 风格变量、必填检查）是"从安装问答生成此表"的脚本——表不是手写的，是安装程序算出来的，理解这点就理解为什么它的格式必须机器友好。

### 1.3 检查：按序号排队的体检

文件系统会坏（断电、崩溃、坏块），检查器（`fsck` 族：通用、`mfs` 专用、`ext2` 专用）负责"查结构、能修则修"。顺序 discipline：根先行（序号 1 且单独），余下按序号升序，同序号保表序（管理员的排列有意义：同盘 Webster 先查元数据盘）。序号 0 永不查（内存、网络、伪文件系统无盘上结构可查）。`preen` 模式是"无人值守自动修小病、大病叫人"的开机默认——体检报告分"自己吃药"与"叫医生"两档。

## 2. C 源码分析

### 2.1 `mount.c`：类型选项三参数

用法函数（第 17 与 168 行）与参数计数检查（第 60 行：非全部显示模式下必须恰三参数）框定形状：`mount [-t 类型] [-o 选项] 设备 挂载点`。`-t` 与 `-o` 各消费其后一词（第 41 到 47 行），余者不认（第 51 行默认分支即用法）。Rust 侧 `options.rs` 的严格词表与之同精神（未知词报错），`fstab.rs` 的六字段与表格式同形。

### 2.2 `fsck.c` 第 254 行：零号跳过

检查调度只看序号：一句话"序号零即跳过"。Rust 侧 `plan_checks` 的升序稳定排序加零过滤是这句话的完整实现（根首、升序、零跳过、表序保持四规则，测试 `test_root_first_then_ascending` 与 `test_pass_zero_skipped` 双钉）。

### 2.3 `newfstab.sh`：单参数脚本范本

参数计数检查（恰一参数否则用法退出）、读入变量文件、必填变量检查（根与用户设备缺一不可）——三段式是 shell 脚本的教科书结构。Rust 侧不解析 shell（那是 `05` 篇执行器的事），只消费它产出的表（`fstab.rs`）——生产者与消费者各归其位。

### 2.4 族群面貌：五实现一职责

通用检查器、Minix 检查器、第二扩展检查器各守一文件系统，外加预检查模式与进度显示——"一文件系统一检查器"是 Unix 的可扩展性设计（新文件系统带新检查器，老命令不动）。`sbin/mount` 目录的 `fattr.c`（属性工具）说明挂载命令族还有"调属性"的旁支。本篇到职责级为止，实现各归其文件系统阶段。

## 3. Rust 设计决策

### 3.1 为什么未知挂载选项必须报错

`noexce`（`noexec` 之误）若静默忽略，系统以"可执行"挂上本该禁执行的卷——安全契约无声降级。`parse_options` 对未知词、空词、空表一律报错。这是全阶段最硬的一条"响亮失败"规则（`02` 篇时间方言、`08` 篇后向引用同理），测试 `test_unknown_word_rejected` 用三形态钉死（拼错、空表、双逗号）。

### 3.2 为什么检查计划是稳定排序

同序号的检查谁先谁后？C 工具按表序（读到谁先查谁）。插入排序（16 行以内）天然稳定，代码即证明（无额外注释论证稳定性——算法本身保证）。管理员把"先查元数据卷"的心思排进表序，排序必须尊重——"输入顺序有意义"是需求，不是巧合。

### 3.3 为什么挂载表是接口

`EmptyMountTable`（全缺席）与 `SliceMountTable`（内存行表、首中获胜）配 `lookup_mount`（空点位报错、落空报查无）——与 `03` 篇用户库、`04` 篇查询表、`10` 篇手册库同一形状。本阶段第五次应用，不再论证，只记录：只读小库一律此形。

## 4. 实现详解

### 4.1 模块结构

`os/commands/sbin/mountinfo`（库包名 `minix-mountinfo`）共 4 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`MountError`，22 对应参数无效、2 对应查无）与模块组织 |
| `fstab.rs` | 表六字段格式 | 行解析（`parse_fstab_line`，六字段不多不少） |
| `options.rs` | `mount.c:47` 选项思想 | 选项词表（`parse_options`，七词严表） |
| `order.rs` | `fsck.c:254` 思想 | 检查计划（`plan_checks`）与 `MountTable` 接口 |

### 4.2 关键类型与不变量

- **表行 `FstabEntry`**：设备、挂载点、类型、选项原文、备份频率、检查序号。不变量：六字段不多不少；前三非空；尾两纯数字；选项原文不解释（`options.rs` 的事）。
- **挂载选项 `MountOptions`**：六位标志。不变量：未知词即错；空词即错；`rw` 为空操作（缺省即读写）；`ro` 与 `rw` 并存即只读（与 `mount.c` 第 143 到 147 行 `has_opt` 查存在语义一致：有 `ro` 即只读）。
- **检查任务 `CheckJob`**：表行。不变量：零号不入计划；升序；表序稳定；超 16 行即错。
- **挂载表 `MountTable`**：按点查询。不变量：空点位即错；落空报查无；首中获胜。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `parse_fstab_line` | 表行 | 条目或无 | 表行语义 |
| `parse_options` | 选项串 | 标志集 | 选项词语义 |
| `plan_checks` | 表行表 | 任务序列 | 检查顺序语义 |
| `lookup_mount` | 表与挂载点 | 条目或查无 | 查询语义 |
