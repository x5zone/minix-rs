## 1. 概念：观察系统的四种目光

### 1.0 本章说明

系统跑起来之后，管理员需要四种目光。第一种看身份：这是什么版本，根设备是哪块，硬件时钟是多少。第二种看时间：系统时钟和硬件时钟一致不一致，时区对不对。第三种看参数：内核和各服务的旋钮当前拧在什么位置，想改怎么改。第四种看构成：一个程序由哪些归档成员组成，性能热点在哪，基准跑分多少。

> **本章不讲什么**：
>
> - 驱动如何读写硬件（见驱动阶段）
> - 内核参数改了之后内部发生什么（见各服务阶段）
> - 音频如何采集播放（待音频驱动，本篇只到命令词）
>
> 本章只讲观察语言：选项怎么说，名字怎么写，根怎么找，归档怎么列。

### 1.1 身份与时钟：版本文件、根设备、硬件时钟

版本命令最简单：打开版本文件，打印内容，退出。简单但重要：报问题时第一句话就是版本，版本不对，后面一切诊断都可能走偏。

根设备发现的思路很朴素：对根目录做一次状态查询得到设备号，打开设备目录逐个做状态查询，第一个设备号相同的块设备就是根。字符设备不算，只有块设备能装根。找不到就报未知加失败状态，调用方（比如引导更新脚本）看到失败就停下来，而不是猜一个继续。

硬件时钟命令管两块钟的同步：硬件钟断电也走，系统钟跑得准。缺省方向是把硬件钟读进系统钟，写标志反转方向，预览标志只说不做，安静标志什么都不打印，寄存器访问标志打开直接寄存器读写，两千年兼容标志处理老硬件的年份断代。读取最多试十次，每次间隔五秒，读到合法时间就停，十次都非法就放弃报错，而不是拿一个非法时间把系统钟带歪。

### 1.2 限时执行：给命令套上中断与闹钟

限时执行命令解决一个实际问题：有些命令平时需要中断才能停，但在脚本里没有终端可按。把它包起来跑，前台模式把它带进前台并恢复默认信号处理，后台模式让它脱离会话、输入接空、输出接日志、回到根目录。闹钟选项给执行加上限，时间一到发闹钟信号，命令自己决定是收尾还是被杀。

### 1.3 参数树：点分名字与赋值

系统参数组织成树，点分名字是路径：第一段是子系统，后面逐级细化。查询给名字，赋值给名字等号值。名字检查拒绝空段、超长段、非法字符、过深嵌套，坏名字在到达内核之前就被拦下。内存参数表定容十六行，短命命令进程够用，满表再写即错，同名再写即替换。空表一切查询 miss，一切赋值拒绝，类型即文档。

### 1.4 归档清单：没有动态链接器的列依赖

架构演进点：本系统静态链接，没有动态链接器，所以列依赖的命令语义跟着变：不再列共享对象，改列静态归档的成员。工具同时接受三十二位和六十四位格式，靠文件头识别，不靠扩展名。显示行为每成员一行：成员名加大小。空名拒绝，过小缓冲拒绝，调用方按需分批列，不一次性装下整个归档。

## 2. C 源码分析

### 2.1 版本与根设备：一行脚本与一次目录扫描

版本脚本只有一行：打印版本文件的内容。根设备发现（第 45 行附近）对根目录做状态查询，打开设备目录（第 25 行附近），逐个比较设备号，只认块设备，命中即打印返回，扫完无命中打印未知加失败状态（第 55 行附近）。未知回退常量（第 27 行附近）保证失败时也有确定的输出，调用方可以字符串匹配。

Rust 侧 `rootdev.rs` 的发现函数与这个流程逐项对应：首个块匹配即中，字符设备永不中，扫完无中即回退。

### 2.2 硬件时钟：读写两调用与五个字母

读取调用（第 73 行附近）把硬件时间取回来，写入调用（第 122 行附近）把系统时间写进去。寄存器访问（第 55 行附近）置位后隐含写入，两千年兼容（第 59 行附近）处理年份断代。用法行（第 164 行附近）把五个字母收在一起：预览、写入、寄存器访问、两千年兼容、安静。读取循环最多十次，每次间隔五秒，合法即停。

Rust 侧 `clock.rs` 的选项结构与五个字母逐项对应，方向决策（写标志即系统到硬件）与命令分支对应，重试上限十次以同名常量对应。

### 2.3 限时执行：前台与后台两条路

后台开关（第 51 行附近）分叉两条路：前台路接管终端并恢复默认信号处理，后台路脱离会话、输入接空、输出接日志设备（第 19 行附近）、回到根目录。闹钟布防（第 140 行附近）在执行新程序之前完成，继承过执行边界，时间一到信号先到。命令词解析支持双横线结束选项，选项可聚集， deadline 可紧贴可分离。

Rust 侧 `intr.rs` 的选项解析与这两条路的开关逐项对应，缺省 deadline 允许缺席， deadline 解析拒绝非数字与溢出。

### 2.4 参数树与归档：节点类型与格式通吃

参数树的根带节点类型标记（第 252 行附近的根标志、第 520 行附近的节点分支），查询按类型分流，节点继续下钻，叶子打印值。归档工具对两种位宽的格式通吃（第 93 行附近），靠文件头识别。剖析工具与基准工具各守一摊：剖析采样、基准跑分、源码校验、时区转换，职责级覆盖。

Rust 侧 `sysctl.rs` 的名字检查与赋值拆分对应命令的参数面，`ldd.rs` 的成员表与静态归档语义对应。

## 3. Rust 设计决策

### 3.1 为什么时钟方向由写标志决定，而不是由位置参数决定

位置参数容易错位：多一个少一个，读写就反了，写硬件变成读硬件是 variances，读硬件变成写硬件是事故。用独立的写标志表达方向，缺省安全方向是读（只观察不改变），必须显式加写标志才改变硬件。寄存器访问隐含写入，因为打开寄存器不写没有意义，这个隐含关系写在解析里而不是写在文档里，测试钉死。预览标志最高优先级的直觉是错的：预览和写入可以同时出现，预览只管打印不管拦截，拦截是执行层的事，纯判断层只报告两个布尔值。

### 3.2 为什么根设备发现返回找到与否，而不是在找不到时报错

找不到根设备是调用方必须处理的正常情况（比如设备目录还没挂上），不是程序错误。返回回退名加是否找到的标记，调用方可以分支：引导脚本看到未找到就停，显示工具看到未找到就打印未知。抛错会逼调用方用异常做分支，逻辑反而乱。字符设备永不匹配是类型层面的保证，不是运行时的运气：比较前先看块标志，字符设备直接跳过。

### 3.3 为什么参数表定容十六行，而不是动态增长

系统参数命令一次处理几个名字就退出，不需要长期持有大表。定容数组无堆可用，满表报错是明确的背压信号：一次改二十个参数的调用本身就值得怀疑，分两次调用更清晰。同名替换保证幂等：同样的赋值跑两次结果一样，脚本重入安全。空表拒绝一切赋值而不是静默接受，因为空表意味着后端没接好，接受赋值会制造改了但没生效的幻觉。

### 3.4 为什么归档清单每成员一行，而不是表格对齐

每成员一行的输出最容易被脚本处理：逐行读，按固定前缀切，结果稳定。表格对齐要先知道最长成员名的宽度，意味着要么读两遍，要么先全装进内存，对大归档不友好。纯函数一次画一行，调用方循环调用，内存恒定。大小用十进制整数，不加千分位分隔符，机器可读优先。

### 3.5 与同类系统的对照：观察命令只读，改变动作显式且可预览

本篇的观察命令缺省只读：版本只打印，根发现只扫描，参数查询只显示，归档清单只列。改变动作（写时钟、改参数、限时杀）都要显式选项开启，而且时钟支持预览模式先算后做。同类现代系统也用同样的分法，只是参数树的深度不同，本篇的名字检查 independent 于任何一种树的实际内容。

## 4. 实现详解

### 4.1 模块结构

`os/commands/bin/sysinfo`（库包名 `minix-sysinfo`）共 6 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`SysinfoError`，22 对应参数无效、2 对应查无、1 对应无权限）与模块组织 |
| `clock.rs` | `readclock.c` 第 55 行与第 59 行与第 73 行与第 122 行与第 164 行附近 | 时钟选项解析、方向决策、重试策略 |
| `intr.rs` | `intr.c` 第 19 行与第 51 行与第 140 行附近 | 限时选项解析与 deadline 解析 |
| `rootdev.rs` | `printroot.c` 第 25 行与第 27 行与第 45 行附近 | 设备目录接口与根发现 |
| `sysctl.rs` | `sysctl.c` 第 252 行与第 520 行附近 | 参数名检查、赋值拆分、参数表接口 |
| `ldd.rs` | `ldd.c` 第 93 行附近 | 归档表接口与清单行绘制 |

### 4.2 关键类型与不变量

- **时钟选项 `ClockOptions`**：五个布尔值。不变量：空词即错；未知字母即错；大写寄存器访问恒隐含写入。
- **时钟方向 `ClockDirection`**：硬件到系统与系统到硬件。不变量：无写标志恒为读方向；有写标志恒为写方向。
- **限时选项 `IntrOptions`**：后台开关与 deadline。不变量： deadline 缺席表示不限； deadline 溢出即错；双横线后全是命令。
- **设备条目 `DeviceEntry`**：名字、设备号、是否块设备。不变量：字符设备永不中；首个块匹配即停；缓冲过小即错。
- **发现结果 `Discovery`**：名字加是否找到。不变量：找到恒为块匹配；未找到恒为回退名；回退名恒带设备目录前缀。
- **参数行 `SysctlRow`**：点分名加文本值。不变量：名空即错；段空即错；超深即错；同名后写覆盖。
- **归档成员 `ArchiveMember`**：名字加大小。不变量：空名即错；大小按十进制画；缓冲过小即错。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `parse_clock_options` | 选项词 | 选项结构 | 五个字母语义 |
| `clock_direction` | 选项 | 方向 | 读写分支语义 |
| `should_retry_read` | 已试次数、是否合法 | 是否再试 | 十次重试语义 |
| `parse_intr_options` | 词表 | 选项与命令起点 | 选项聚集语义 |
| `discover_root` | 目录、根设备号、缓冲 | 发现结果 | 目录扫描语义 |
