## 1. 概念：看护运行的三只眼睛

### 1.0 本章说明

本章讲管理员看护运行的三组工具：看进程、看会话、发信号，外加时间与锁。二十八个命令各有位置，互不重叠。

> **本章不讲什么**：
>
> - 进程调度算法（见调度阶段）
> - 内核进程表的读取实现（后续内核接口阶段）
> - 邮件系统本体（见 `19` 篇，`from` 只看信箱提示）
>
> 本章只讲"看与管"：列表、信号、会话、时间、锁。

### 1.1 看进程：`ps` 的列是可选的

`ps` 的本质是"进程表选列打印"：关键字表（`keyword.c` 的 `VAR3`、`VAR4`、`PID` 宏：别名、标题、对齐、字段）定义了全部可选列（进程号、父号、状态、命令、用户、时间……），用户点哪些印哪些。默认列集是"够定位问题"的最小集（谁在跑、占什么态），全列是调试时才开的显微镜。Minix 特有三件套（`ministat` 统计、`mtop` 顶消耗、`toproto` 协议流量）是"顶层视角"的补充：`ps` 看个体，它们看群体。

### 1.2 发信号：`kill` 的名字与号码

信号是"进程间的极简消息"（一个编号，无正文）：挂起、中断、退出、杀死、终止、停止、继续、子死、用户自定义……三十二种（编号 1 到 32，见信号表）。`kill` 做两件事：`-l` 列出名字（`sys_signame` 表的 Rust 版是 `SIGNALS` 常量表），按名或按号发（`signame_to_signum` 大小写不敏感、前缀可省：`TERM`、`term`、`SIGTERM` 同指 15）。默认发终止（15，可捕获可清理），`-9` 发杀死（9，不可捕获，核选项），挂起（1）常用于"重读配置"（守护进程约定俗成）。数字 0 有特殊含义（查存在不真发），本库拒收（越界检查含零值拒绝）。

### 1.3 看会话：登录记录是唯一的真相来源

谁在哪个终端、什么时候登的、从哪来——答案全在登录记录文件（`utmp`）：定宽记录（终端行 8、用户名 8、主机 16、时间 4，共 36 字节），空用户名即已退出。`who`（列表）、`w`（加干什么）、`last`（倒序翻档）、`users`（只名）、`finger`（详细信息）、`logname`（我是谁）、`tty`（这是哪）、`mesg`（允不允许别人写过来）、`wall`（广播）、`write`（单呼）——十个命令全是这 36 字节的不同读法。记录写坏（尾部不足一条）必须报错而非丢弃——丢一条就是丢一个会话的真相。

### 1.4 时间与锁：度量与互斥

- **时间**（`date` 看设、`sleep` 等、`time` 计时）：`time` 的输出（用户态、系统态、流逝）是性能分析的起点；时长打印 `[[天-]时:]分:秒` 四形态（本库 `ptime.rs`）。
- **优先级**（`nice` 降权启动、`renice` 改已跑、`nohup` 免疫挂起）："别让批量任务碍交互的事"的三件套，数值越大越客气。
- **锁**（`lock` 锁终端、`shlock` shell 锁文件）：防人碰与防重入各一。
- **进程间通信面**（`ipcs` 看、`ipcrm` 删：共享内存、信号量、消息队列）：System V 三件套的状态与清理。
- **日志与提醒**（`logger` 写系统日志、`leave` 定时提醒、`from` 看发件人提示）：各管一种"告诉人"的通道。

## 2. C 源码分析

### 2.1 `kill.c`：名字号码双通道（226 行）

默认信号赋值（第 83 行 `numsig = SIGTERM`）开宗明义；`-l` 分支（第 105 行）遍历系统名表打印；名字转号码（第 119 到 127 行两处调用，定义第 188 到 195 行：大小写不敏感比对 `sys_signame`）；挂起与终止的特殊处置在第 178 行（作业控制联动的钩子）。Rust 侧 `signal.rs` 的常量表（1 到 32 全数）、双向查询、单词解析与之逐项对应——信号编号逐字抄自 `signal.h` 第 52 到 84 行（挂起 1、中断 2……用户自定义 30 与 31、电源 32），抄表类代码以"逐字"为荣。

### 2.2 `ps` 列定义：`keyword.c` 的宏表

`VAR3`（别名三元）、`VAR4`（标题对齐四元）、`PID`（进程号专用）三宏在第 115 到 197 行登记全部列（`args`、`command`、`pid`、`ppid`、`stat`……）。读 `ps` 源码应该先读这张表（它即"能看什么"的全集），再读主程序（它只管"选了什么、怎么印"）。主程序的内核读取经 `kvm` 与 `sysctl`（第 89 到 92 行头文件）——执行层，后续阶段。

### 2.3 登录记录结构：`utmp.h` 的 36 字节

兼容头展示的结构（终端行、用户名、主机、32 位时间）是 `who` 系十命令的共同地基。定宽、空填、无换行——三个格式事实决定解析器的三个动作（按宽切分、去尾空、整除校验）。Rust 侧 `utmp.rs` 的宽度常量（8、8、16、4）与之一一对应，`walk_database` 的整除校验对应"撕裂写入必须报错"。

## 3. Rust 设计决策

### 3.1 为什么信号表是常量而非函数

32 个信号名号固定不变（ABI 冻结），查表是最忠实的表达：`SIGNALS` 常量即文档，`signame_to_signum` 即 `kill.c` 第 188 行的移植（大小写不敏感、前缀可省的语义逐项保留）。数字 0 与 33 以上拒绝（`kill.c` 的范围检查在解析层，本库同）。抄表代码的评审标准只有一条：与源逐字对（测试 `test_names_resolve` 抽七个锚点、`test_numbers_round_trip` 穷举 32 个往返）。

### 3.2 为什么缺席进程报 3 而不是 2

`kill` 报"无此进程"用的是"无此进程"专用码 3（`ESRCH`），不是通用的"无此文件" 2——调用方（脚本）靠它区分"名字打错"与"进程已退"。`ProcError::NotFound` 映射 3 而非 2，是领域正确压倒习惯（测试 `test_lookup_maps_miss` 把 3 钉死）。这是错误码映射"贴源不贴惯"的实例。

### 3.3 为什么时长打印四形态

`45s`、`12:34`、`3:12:34`、`2-04:00:00`——省略高位零是可读性工程（`time` 输出天天看，省一位是一位）。`ptime.rs` 按阈值四分支（60、3600、86400），分钟秒补零、小时天不补（与 C 工具格式一致）。边界测试八组（0、59、60、3599、3600、86399、86400）把四个阈值两侧全钉住——边界测试的密度与格式分支数成正比，这是测试设计的一条经验。

### 3.4 为什么进程表接口只给三个数

`ProcessRow` 只有进程号、父号、用户号——状态、命令、时间全是"列层"的事（`keyword.c` 的列有一大半）。接口给最小可用（定位进程够用），列层以后叠加。这是"接口最小化"的实例：多给的每个字段都是未来要维护的契约。

## 4. 实现详解

### 4.1 模块结构

`os/commands/bin/proctools`（库包名 `minix-proctools`）共 5 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`ProcError`，22 对应参数无效、3 对应查无）与模块组织 |
| `signal.rs` | `kill.c:83-195`、`signal.h:52-84` | 信号表（`SIGNALS`）、双向查询、单词解析 |
| `ptime.rs` | `time` 输出格式 | 时长四形态（`format_duration`） |
| `utmp.rs` | `utmp.h` 记录结构 | 记录解析（`parse_record`）与库遍历（`walk_database`） |
| `stable.rs` | `ps` 列表思想 | `ProcessTable` 接口、`EmptyTable` 与 `SliceTable` |

### 4.2 关键类型与不变量

- **信号表 `SIGNALS`**：32 对名号。不变量：编号 1 到 32 连续；`SIG` 前缀可省；裸 `SIG` 非法；大小写不敏感；数字 0 与 33 以上非法。
- **时长**：非负秒数。不变量：四形态阈值分明；分秒补零；小时天不补；缓冲不足即错。
- **登录记录 `UtmpEntry`**：行、名、机、时。不变量：定宽 36；去尾空零； interior 空保留；空名即退出；撕裂库即错。
- **进程表 `ProcessTable`**：列表与单查。不变量：空表全空；首中获胜；查无报 3；列表截断诚实计数。

### 4.3 函数一览

| 函数 | 输入 | 输出 | 对应 C 行为 |
|------|------|------|------------|
| `signame_to_signum`/`signum_to_signame` | 名或号 | 号或名 | 名字表语义 |
| `parse_signal` | 单词 | 信号号 | 信号参数语义 |
| `format_duration` | 秒数与缓冲 | 字节数 | 时长格式语义 |
| `parse_record`/`walk_database` | 记录与库 | 条目与计数 | 登录记录语义 |
| `list`/`find`/`lookup` | 表与进程号 | 行或查无 | 进程列表语义 |

## 5. 测试要点

`cargo test -p minix-proctools`：**16 个测试，全部通过**（截至 2026-09-06）。

重点行为与测试的对应（以下函数名均可用 `rg "fn 测试名" os/commands/bin/proctools` 复现）：

- **信号**（`signal.rs`，5 个）：`test_names_resolve`（七锚点名号）、`test_unknown_names_rejected`（未知名、裸前缀、空串）、`test_numbers_round_trip`（32 号穷举往返加越界）、`test_parse_signal_words`（数字、前缀名、零与超界）、`test_default_is_term`（默认 15）。
- **时长**（`ptime.rs`，2 个）：`test_four_shapes`（四形态）、`test_boundaries`（七边界）。
- **登录记录**（`utmp.rs`，5 个）：`test_fields_trimmed`（三字段去尾加时间）、`test_logged_out_empty_name`（空名即退出）、`test_short_record_rejected`（短记录）、`test_walk_counts_and_visits`（双记录遍历）、`test_torn_image_rejected`（撕裂库）。

尚未覆盖、随后续阶段补齐的：内核表读取（`ps` 执行层）、终端检查（`-t` 之类）、作业联动（挂起终止特判的执行侧）、邮件与网络会话（`from` 信箱、`write` 投递）。号码记录表格三层是全覆盖的，执行层是显式留白的。
