## 1. 概念：连通之前要回答的四个问题

### 1.0 本章说明

一台机器想和远方说话，在发送第一个字节之前，其实要先回答四个问题。网卡叫什么名字，地址配了没有，开关打开没有。去往目标的路是哪一条，走哪个网关，从哪个口出去。局域网里目标的链路地址是什么，地址解析表里有没有。名字怎么写，主机名对应哪个地址，服务名对应哪个端口。

本章讲的就是这四个问题的命令面：接口配置管第一个问题，路由管第二个问题，地址解析管第三个问题，名字数据库管第四个问题。回显探测和路径追踪是出问题时的两件诊断工具：前者回答通还是不通，后者回答断在哪一段。

> **本章不讲什么**：
>
> - 协议栈内部如何选路和转发（见网络阶段）
> - 网卡驱动如何收发（见驱动阶段）
> - 无线关联与串行拨号的硬件细节（本篇只到命令词）
>
> 本章只讲配置语言：标志词怎么说，路由动词怎么说，邻居条目长什么样，探测包怎么算校验。

### 1.1 接口：网卡的开关、名字与一次能装多少

每个网络接口都有名字、标志集合、地址、最大传输单元。标志集合里最重要的是管理开关：打开表示允许收发，关闭表示停止收发。运行标志是驱动报告的，只读，管理员改不了。混杂模式是抓包工具用的，打开后网卡把所有经过的帧都收下来。最大传输单元是一次能装多少字节，太小浪费头部开销，太大对端收不下，以太网风格的链路常用 1500。

配置命令的形状是名字加上一串词：接口名打头，后面跟开关词和键值对。最大传输单元用键值对的形式单独设置，缺值即错，超出合理范围即错。读标志和写标志是两套控制调用，读在前写在后，先读出来，改掉要改的位，再写回去，而不是盲写。

### 1.2 路由：去往目标走哪条路

路由表回答去往每个目标走哪条路：目标网段、下一跳网关、出接口。直连路由没有网关，内核直接送到链路上。缺省路由的目标是全部地址，当前面没有更具体的条目命中时兜底。路由动词有增加、删除、修改、查询、清空、监听六种：增加放新条目，删除拿掉旧条目，修改换下一跳，查询看一条，清空全删，监听看内核的实时通告。

地址解析表回答局域网里的下一个问题：已知对方的网络层地址，链路层地址是什么。条目由网络地址、链路地址、接口名、是否永久组成。链路地址是六组十六进制字节对，点分十进制地址是四组十进制数，每组零到 255。删除不存在的条目时内核报告查无，这是正常语义不是程序错误。

### 1.3 回显探测：通还是不通，以及慢了多少

回显探测是最简单的连通性测试：发一个回显请求，对方回一个回显应答，收到应答就是通，收不到就是不通，多次统计就是丢包率和时延分布。请求和应答靠类型号区分，靠标识符和序列号配对。校验和覆盖整个报文，发送方算好填入，接收方重算验证，算不对就丢掉。

校验算法是十六位反码求和：把报文按十六位一组累加，奇数字节结尾时把最后一个字节补在高位，累加时溢出的进位折回低十六位，最后取反。计算时校验字段本身先置零，填入之后整包再算一次应该得零。这个算法不加密，只防传输损坏，设计目标就是快。

路径追踪回答更细的问题：通，但慢，或者不通，断在哪一段。做法是从小到大逐个增加跳数上限，发探测包，看是哪个中间路由器先回超时消息。缺省用用户数据报做探测，缺省跳数上限从系统变量读。每个跳数发几个包，取往返时间的最小、平均、最大，星号表示超时无应答。

### 1.4 名字数据库：人写的字与机器要的数之间

人记名字，机器要数字。主机文件把主机名翻译成地址，服务文件把服务名加传输协议翻译成端口，协议文件把协议名翻译成协议号。查询顺序是首次命中获胜，文件里排在前面的先生效。注释行和空行跳过，地址格式不对的行是文件错误，应该响亮报错而不是静默跳过。

## 2. C 源码分析

### 2.1 接口配置：读标志、改标志、写标志

接口配置的标志读写分两步：先用读取调用把当前标志读出来（第 1050 行附近），改掉要改的位，再用写入调用把新标志写回去（第 1059 行附近）。开关词 `up` 置位管理开关，`down` 清除管理开关。最大传输单元用独立的写入调用设置（第 1173 行附近），失败只警告不退出，因为一张网卡配多个地址族时某个地址族失败不该中断整张卡的配置。

Rust 侧 `iface.rs` 的标志字解析与开关语义逐项对应，最大传输单元的上界下界检查与链路常识对应（过小无意义，过大需巨帧支持）。

### 2.2 路由与地址解析：同一套路由套接字，两种用途

路由命令和地址解析命令共用路由套接字，只是动词不同。地址解析的查询、新增、删除分别对应获取、增加、删除三个路由消息（第 315 行、第 350 行、第 434 行附近），版本号标记（第 642 行附近）保证内核和工具对消息格式的理解一致。删除不存在的条目时内核报告查无（第 690 行附近按查无且动词为删除时放行），工具把查无翻译成对用户友好的提示。

Rust 侧 `route.rs` 的六个动词与路由命令的动词表对应，`arp.rs` 的四个动词与地址解析命令的选项对应，查无错误沿用系统的查无错误号。

### 2.3 回显探测：校验函数与请求应答配对

校验函数 `in_cksum`（第 1266 行）是全篇算法核心：十六位累加、奇数字节补高位、进位折回、最后取反。请求构造（第 897 行附近）填类型号为回显请求，算好校验和再发送（第 909 行附近）。应答匹配（第 1029 行附近）检查类型号为回显应答，再核对标识符和序列号，防止把别人的应答算到自己头上。发送计数器 bound 整次运行的包数，发完即停，不设计数就一直发到被中断。

Rust 侧 `ping.rs` 的校验函数与这个算法逐字节对应，类型号与协议常量对应，计数与间隔解析与命令选项对应。

### 2.4 路径追踪与状态显示：跳数上限与显示选择

路径追踪缺省用用户数据报做探测（第 721 行附近），跳数上限通过存活时间套接字选项逐次抬高（第 1350 行附近），缺省上限从系统变量读（第 472 行附近）。状态显示的用法行（第 866 行附近）列出地址族过滤、数字显示、路由表、接口统计等选择，软中断队列显示是独立的小函数。网络配置脚本按顺序做地址配置、路由添加、名字服务指向，是安装问答的产物。

Rust 侧本篇覆盖到命令词与选项语义为止，套接字调用与系统变量读取归执行层。

## 3. Rust 设计决策

### 3.1 为什么标志字解析与控制调用分离

标志字的含义是稳定的，控制调用的编号是系统相关的。今天读标志用这个调用号，明天内核重构可能换号，但开关词的含义不变。把解析做成纯函数，把调用留在执行层，内核接口变化时只需要改执行层，测试也不需要打开套接字就能跑。如果解析和调用写在一起，每个测试都要模拟内核，测试成本大增，而且解析错误和调用失败混在一起，定位困难。

### 3.2 为什么路由表用定容数组而不是动态链表

命令进程是短命的，一次调用处理几条路由就退出，不需要支撑成千上万条目的长期存储。定容数组没有堆分配，在无标准库环境下直接可用，而且容量上限本身就是一种保护：输入失控时返回参数无效，而不是把内存吃光。原始工具用链表是因为要和内核的表结构对接，纯判断层不需要。执行层在把条目发给内核之前，先过一遍这张内存表做合法性检查，坏条目在到达内核之前就被拦下。

### 3.3 为什么校验函数按字节切片实现，而不是按十六位指针强转

按十六位指针强转在对齐和端序上有隐患：奇地址强转在某些架构上直接 fault，大端小端对同一块内存的切分结果不同。按字节切片每次取两个字节拼成一个十六位字，行为在所有架构上一致，而且奇数字节结尾自然落在分支里。性能损失微不足道：探测包每秒最多几个，校验的字节数最多几千，可读性和可移植性远比这点速度重要。

### 3.4 为什么名字查询把首次命中获胜写进类型，而不是写进注释

首次命中获胜是查询语义的核心，不是顺带的说明。如果只写在注释里，换一个实现者可能写成最后命中获胜，测试还都通过，因为测试只查了一个名字。把顺序语义写进查找函数的实现（从头扫描，遇到即返），测试用重复名字验证返回第一条，语义就被钉死了。空库是一个独立的类型而不是空切片，因为空切片还能插入，空库连插入都拒绝，类型即文档。

### 3.5 与同类系统的对照：命令只做翻译，机制留在内核

本篇的设计沿用经典分层：命令把用户的话翻译成内核听得懂的请求，内核做真正的选路和转发，命令再把内核的回答翻译成人看得懂的行。这种分法的好处是命令可以独立测试：给一组词，看翻出来的请求对不对，给一份回答，看画出来的行对不对，全程不需要网卡。同类现代系统也用同样的分法，只是传输机制不同，本篇的纯判断层不依赖任何一种传输实现。

## 4. 实现详解

### 4.1 模块结构

`os/commands/usr-sbin/netconfig`（库包名 `minix-netconfig`）共 6 个源文件：

| Rust 文件 | 对应 C 源码位置 | 职责 |
|-----------|----------------|------|
| `lib.rs` | — | 错误类型（`NetconfigError`，22 对应参数无效、3 对应查无、51 对应网络不可达）与模块组织 |
| `iface.rs` | `ifconfig.c` 第 1050 行与第 1059 行与第 1173 行附近 | 标志字解析、最大传输单元解析、接口请求组装 |
| `route.rs` | `route.c` 第 642 行附近 | 路由动词解析、内存路由表、空路由表 |
| `arp.rs` | `arp.c` 第 315 行与第 350 行与第 434 行附近 | 邻居动词解析、链路地址与点分地址检查 |
| `ping.rs` | `ping.c` 第 1266 行与第 897 行与第 1029 行附近 | 反码校验、类型号、计数与间隔解析、丢包统计 |
| `hosts.rs` | `etc/hosts` 与 `etc/services` | 主机行与端口解析、名字数据库接口 |

### 4.2 关键类型与不变量

- **接口标志 `InterfaceFlags`**：五位标志。不变量：管理开关可读写，运行状态只读；未知词即错；空名即错。
- **接口请求 `InterfaceRequest`**：名字、标志、最大传输单元。不变量：名字非空；最大传输单元缺省表示不变；在范围内才接受。
- **路由动词 `RouteVerb`**：增加、删除、修改、查询、清空、监听。不变量：未知词即错；缺省路由是合法目标。
- **路由条目 `RouteEntry`**：目标、网关、出接口。不变量：目标非空；直连路由网关为空；同目标插入即替换。
- **内存路由表 `MemoryRouteTable`**：定容十六条。不变量：满表再插即错；删除查无即错；删除用末尾搬移保持紧凑。
- **邻居动词 `ArpVerb`**：显示、增加、删除、设置。不变量：短横线形式与长单词形式等价；未知词即错。
- **回显类型 `EchoKind`**：请求与应答。不变量：请求类型号恒为八，应答恒为零；校验时校验字段先置零。
- **探测选项 `PingOptions`**：计数、间隔、载荷。不变量：计数缺省表示一直运行；计数为零即错；间隔按秒收按毫秒存。
- **名字数据库 `AddressDb`**：主机查询与服务查询。不变量：首次命中获胜；空名即错；查无报查无。
