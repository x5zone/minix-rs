# 22 — sdev：套接字长短问、挂起登记、取消交叉与复活分流

本文讲清套接字层如何在“短问钉线程、长问挂进程、选择发即返”的三态等待中，以驱动回答为唯一真相来源，把建字/绑定/读写/控制送到套接字驱动，并在取消与复活的交叉路口以“或部分成功、或穿越回复”收尾——字符对话谈完就走，套接字对话谈到一半会睡，睡醒了还要分三组善后。

前置阅读：`19-device-map.md`（smap 按域查人与驱散分类）、`02-fproc-struct.md`（`SdevCall/SdevAux` 挂起记录）、`21-cdev.md`（授权交叉与换码配对）。

> 本章不讲什么：
> - `asynsend3` 的传输执行—— 内核侧（本篇只给发送顺序）
> - `worker_wait/suspend` 的等待执行—— `08-worker-thread.md`
> - `resume_accept/recvfrom/recvmsg` 的上层续作执行—— `24-socket.md`
> - `select_sdev_reply1/2` 的多路复用执行—— `23-select.md`
> - 授权（grant）的内核侧实现—— `99-global-concepts.md`（本篇只给配给规则）
> - 套接字地址族与选项语义—— `24-socket.md`（本篇只给驱动对话层）

## 1 概念

### 1.1 为什么分长问短问

短问钉住线程等回答（建字、listen、简单的关），长问挂起进程等回答（绑定、接受、读写、控制），选择发完就返（回复走多路复用层）。分流的根因是等待的代价：线程是稀缺资源（9 个 worker），进程挂起是廉价状态——等得久的挂进程，等得短的钉线程，发完不等的直接走。

“非阻塞调用仍按长问处理”是关键细节（`sdev.c:15-16`）：`O_NONBLOCK` 改变的是驱动行为（快失败），不是 VFS 的等待形态——挂起登记照做，驱动回得快而已。等待形态看的是“回答什么时候来”，不是“调用者急不急”。

### 1.2 挂起的三授权

读写一次最多备三份授权：数据、控制、地址。各按需分配（缓冲为零即跳过），方向交叉（读配写、写配读，21 同源），撤销按序（复活时三权依次撤销，不问当初是哪一调用——“每次挂起三权全置”的不变式使无条件撤销成立）。

三授权是“先占后谈”的保证金：谈之前把用户缓冲的使用权押给驱动，谈完（无论成败）赎回。押与赎配对是本篇最容易漏的义务——漏赎即授权泄漏，驱动永久持有用户内存的访问权。

### 1.3 取消的交叉语义

取消不是“作废”，而是“发取消信，然后等原回答”。两种交叉：取消可能部分成功（原请求做了一半，回复是部分字节数），原回复可能穿越取消信（两信交错，先到的不是取消确认而是原回答）。驱动因此被要求：对不认识的取消请求**不回答**——回答了反而制造第三种语义，沉默是最好的协议。

套接字的取消没有字符设备的“自回复”特权（21 §1.6 的 `sdev_cancel` 自发回复）：取消信发出去后，线程挂起等原回答，原回答到了按正常复活走。统一即简单：取消与正常走同一条复活路，只是触发者不同。

### 1.4 接受的特事特办

接受成功要建新套接字，建新套接字要调阻塞调用（PFS 落子），阻塞调用不能在主线程做——于是主线程生一个工人线程专办接受回复。这是全 VFS 唯一的“为回复而生线程”，特事的代价是两道防线：查端点（驱动死了没）与查监听套接字（根死了没），双查全过才生，生出来还要防重（同一进程连中两元，第二封忽略）。

取消线程上的接受回复不生线程——已经在了，直接办。特事特办的是“场合”（主线程），不是“事情”（办接受），场合对了事情照旧。

### 1.5 复活的三组分流

复活按调用分三组：简单组（绑定/连接/写/发/控/关——回状态码即可）、接收组（读/收——回状态加长度标志）、接受组（失败才到此，成功走特办）。分组的依据是“回复长相”：三种回复类型（通用/接收/接受）各带不同的字段，解析一次分流一次。

关闭归一是分流中最务实的一行：关了就是关了（回 `OK`），除非驱动还在进行中（`EINPROGRESS` 原样）。关的语义是“描述符已死”，不是“驱动已停”——描述符之死立即可报，驱动之停慢慢再说。

### 1.6 死亡的统一口径

驱动死亡在三处报同一种 `EIO`：短问收尸（传输层回负错）、长问停尸（`sdev_stop` 标负类型）、复活验尸（端点查无此人）。统一口径的价值在上层：24 的续作只需处理 `EIO` 一种死因，不必分辨死在何处。分辨是本篇的事，善后是上层的事—— layers 之间只传结论，不传过程。

### 1.7 与其他 OS 的套接字下层对照

- **Linux** 以 `sockfs`（套接字 inode）+ `proto_ops`（协议操作表）实现同构分层：`sdev_sendrec` 的短问对应内核的同步 `sock_sendmsg` 等待，`sdev_suspend` 的长问对应 `sk_wait_event` 的进程挂起，`sdev_stop` 的 EIO 标记对应 `sk_error_report` 的死亡通知。
- **Redox** 的网络 scheme 以 `Socket` 状态机（`TcpScheme` 的读写队列 + 事件）对应长短问：非阻塞的 `EAGAIN` 快失败语义一致；Redox 以方案内 Waker 唤醒对应 `sdev_finish` 的复活分流。
- **seL4** 无套接字原语，网络栈是持有网卡能力的用户服务，直达即 IPC；VFS 的挂起账本在 seL4 中由客户端自持——状态服务器把等待做进服务里，无状态内核把它留给客户端。

### 1.8 小结

套接字对话是五段（短问→长问→取消→复活→驱散），三组开关（问型三态/授权三权/回复三组）决定走向，一条不变量贯穿始终：每句发出去的话都有着落——短问有状态，长问有挂起，取消有交叉语义，死亡有 `EIO`。没有悬空的对话，是本篇的全部要求。

## 2 C 源码分析

### 2.1 头注释契约（`sdev.c:1-43`）

长短问定义（`8-16`：短问钉线程、长问挂进程、非阻塞仍按长问）→ 回复总则（`22-27`：主线程唤醒用户进程，复杂转交上层）→ 取消语义（`29-35`：发取消信等原回答，或部分成功或穿越）→ 接受例外（`37-42`：成功需工人线程，非工人线程收到才生）。

### 2.2 `sdev_sendrec` 短问机（`sdev.c:58-77`）

异步发（`64-65`，失败 panic）→ 挂线程等复（`68-74`）→ 负类型直返类型码、余回 `OK`（`76`，死亡统一口径的源头）。

### 2.3 `sdev_suspend` 登记机（`sdev.c:82-111`）

### 2.4 `sdev_socket` 建字机（`sdev.c:118-172`）

### 2.5 `sdev_bindconn` 绑定机（`sdev.c:178-234`）

### 2.6 `sdev_simple` 三元机（`sdev.c:241-286`）

### 2.7 `sdev_accept/sdev_readwrite/sdev_ioctl` 长问机（`sdev.c:292-448`）

### 2.8 `set/get` 选项机（`sdev.c:453-586`）

### 2.9 `sdev_shutdown/sdev_close/sdev_select` 机（`sdev.c:591-668`）

### 2.11 `sdev_finish` 分流机（`sdev.c:758-905`）

### 2.12 `stop/cancel` 取消机（`sdev.c:911-980`）

`stop`：挂起断言（`916`）→ 清挂起（`918`）→ 标 `EIO` 负类型续办（`926-927`，统一口径）。`cancel`：挂起已清断言（`947`）→ 查表（`949`，无则标 `EIO`）→ 组包发取消（`951-966`，注释写明穿越与部分成功语义）→ 接受成功走迎新（`975-977`，已在工人线程不另生）→ 余走分流（`978-979`）。

### 2.13 `sdev_reply` 路由机（`sdev.c:988-1114`）

知名门（`998-1002`）→ 四回复取号（`1004-1016`）/选择直转 23（`1017-1028`）/未知丢弃（`1029-1033`）→ 端点复核（`1035-1039`）→ 工人投递（`1043-1052`，未阻塞断言）→ 非挂起或异主丢弃（`1053-1057`）→ 接受成功生线程（`1058-1108`：注释写明丢回复即泄漏，双查防线、`fp_u` 复用 TODO `1094-1107` 诚实保留、清挂起）→ 余清挂起续办（`1109-1112`）。

## 3 Rust 设计决策

Rust 改写不是照抄 `sdev.c` 的挂起循环，而是吸收 Linux/Redox 的套接字模型后做取舍。以下决策对应 `.design/22-design.v1.md` D1-D7。

### D1 问型三分类

- **C**：长短问知识散在头注释与各函数中（`sdev.c:8-16`）。
- **Rust**：`SdevOp` 十七值 + `ask_kind() -> AskKind::{RoundTrip, Suspend, FireAndForget}` 全映射（`os/servers/vfs/src/sdev.rs:99,162`）。
- **为什么**：等待语义是调用点最需要的一比特；全映射使十七操作无一漏网（测试全枚举锁定）。替代方案（布尔 `may_suspend`）被否决：即发即返是第三态，二值装不下。

### D2 通道 trait 化

- **C**：`sdev_sendrec` 短问往返 + 各函数 `asynsend3` 投递（`sdev.c:58-77,209-210`）。
- **Rust**：`SockChannel{roundtrip(expect), dispatch()}`（`ScriptedChannel` 按脚本应答 vs `SilentChannel` 常死亡）+ `ReplyKind` 四值（`os/servers/vfs/src/sdev.rs:221,198`）。
- **为什么**：传输是唯一的不可测点；双方法对应短问（要答案）与长问投递（只问发出）。替代方案（单方法 + 标志）被否决：两方法的失败语义不同（要答案的死 vs 发出的死），标志位抹平差异。

### D3 挂起记录校验

- **C**：三分支断言（`sdev.c:93-107`）。
- **Rust**：`suspend_aux(call: SdevCall, fd, buf) -> Result<SdevAux, SdevError>`，复用 02 结构（`os/servers/vfs/src/sdev.rs:292`）。
- **为什么**：断言→verdict 是 ARCH 加固；不断言改结构（模式 A 规避）。TODO 空页注记诚实保留为文档注记。

### D4 授权配给

- **C**：三授权按需分配 + 方向交叉（`sdev.c:355-384`）。
- **Rust**：`grant_trio(need×3, is_read) -> [(bool,bool);3]` + `grant_dir` 复用（`os/servers/vfs/src/sdev.rs:323,333`）。
- **为什么**：零跳过与方向交叉正交；数组使撤销计数可数。方向知识不定义两遍（21 同源）。

### D5 标志拼合

- **C**：`NONBLOCK→SDEV_NONBLOCK` 到处 + 写 `NOSIGPIPE→MSG_NOSIGNAL`（`sdev.c:205-206,399-402`）。
- **Rust**：`sdev_sflags(nonblock)` + `sock_msg_flags(nonblock, write_nosigpipe)`（`os/servers/vfs/src/sdev.rs:338,347`）。
- **为什么**：两处拼合是同一规则的两用；`NOSIGPIPE` 只在写时有效一测即知。位值 sync 树可验证。

### D6 复活分流

- **C**：三组 + 关闭归一 + 接受失败路（`sdev.c:785-892`）。
- **Rust**：`FinishGroup::{Simple, Recv, Accept, Unknown}` + `finish_kind` + `close_normalize` + `accept_fail_status`（`os/servers/vfs/src/sdev.rs:404,416,432,443`）。
- **为什么**：回复长相决定分流；关闭归一单列；未知 panic 收敛 `EIO`（ARCH 加固）。

### D7 回复路由

- **C**：选择直转/工人投递/挂起续办/接受生线程（`sdev.c:1004-1113`）+ 死亡标记（`926`）。
- **Rust**：`ReplyRoute::{Select, WorkerDeliver, BlockedFinish, AcceptSpawn, AcceptDirect, Ignore(DropReason)}` + `route_reply` 九参纯判定（`os/servers/vfs/src/sdev.rs:494,533`）。
- **为什么**：路由是“谁收信”的知识；生线程条件（成功 + 非取消线程）显式。`fp_u` 复用 TODO 诚实保留为文档注记。

### ARCH 决策总表

| ARCH | 落点 | 三处一致标注 |
|------|------|-------------|
| A-1 单线程事件循环（mthread→状态机） | 挂起/等待皆 verdict，执行留 08/09 | `sdev.rs:187,494` + 本文档 D1/D7 + 22 正文 §1.1 |
| 断言→verdict（挂起登记加固） | `suspend_aux` 非法形状报 `EINVAL` | `sdev.rs:292` + 本文档 D3 + 22 正文 §2.3 |

## 6 过渡

本篇在 19（域查人）之后、23（多路复用）之前，是“套接字对话”的归属层：19 只管查到驱动，本篇管查到之后怎么谈（长短问/挂起/取消/复活）；没有本篇，24 的套接字调用不知向谁发，23 的选择回复不知从哪来。

```
19-device-map: get_smap_by_domain → 驱动端点（查到谁）
   │
   └─► 本篇：ask_kind 定等待 → channel 对话 → suspend 登记 → finish 分流 → reply 路由
          │                        │                  │
          ├─► 24-socket：上层调用与续作执行（resume_* 的归属）
          ├─► 23-select：选择回复的执行（SEL1/SEL2 的终点）
          └─► 09-main-loop：IS_SDEV_RS 分流与挂起续办
```

阅读顺序提示：若关心“续作是谁执行的”，下一站 `24-socket.md`（`resume_accept/recvfrom/recvmsg` 的执行）；若关心“选择回复去哪”，下一站 `23-select.md`（`select_sdev_reply1/2` 的执行）。
