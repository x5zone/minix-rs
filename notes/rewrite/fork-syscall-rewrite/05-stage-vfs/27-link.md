# 27 — link：硬链接、删除、重命名与截断

本文讲清链接层如何处理目录项与 inode 的四类操作：硬链接（同一设备内多个目录项指向同一 inode，跨设备返回 `EXDEV`），删除（目录项计数减一，数据块回收由 FS 在最后一个链接删除时完成），重命名（同一设备内双目录权限与文件名长度检查通过后原子搬移目录项，inode 不动），截断（新旧长度相等且为常规文件时直接返回 `OK`，避免无意义的时间戳更新），以及符号链接的创建与读取（空路径与超长检查，末尾 NUL 不写入 FS）——目录项是名字，inode 是文件本体；删除最后一个名字后，文件数据才由 FS 回收。

前置阅读：`13-path-lookup.md`（路径解析）、`14-filedes.md`（fd 表，供 ftruncate 取 vnode）、`02-fproc-struct.md`（凭证）、`15-open-close.md`（O_TRUNC 同源语义）。

> 本章不讲什么：
> - 寻路的执行—— `13-path-lookup.md`（本篇只给路径解析的调用规格）
> - 权限检查的执行—— `29-protect.md`（本篇只给权限检查点）

## 1 概念

### 1.1 为什么目录项与 inode 分离

文件由两部分组成：目录项（文件名到 inode 号的映射）和 inode（文件元数据与数据块）。硬链接让多个目录项指向同一 inode，inode 上的链接计数记录引用数。删除目录项只把计数减一；只有计数归零时，FS 才会把数据块放回空闲池。分离的原因是共享成本不同——目录项创建便宜，inode 与数据块回收需要按引用计数处理。

### 1.2 硬链接的三项检查

创建硬链接有三项检查。双路径检查：源路径必须存在（解析并打开源 vnode 做类型检查），目标父目录必须存在（定位到父目录）。同一设备检查：源 inode 与目标目录必须在同一设备——跨设备返回 `EXDEV`（inode 号只在所属设备内有效）。目标目录权限检查：目标目录须同时可写可执行（`W|X`）——在目录中新增目录项属于写操作。检查全部通过后下发 FS 创建目录项，随后释放锁并归还 vnode 引用——借用的 vnode 用完即归还。

### 1.3 删除的计数语义

删除只把链接计数减一，不直接释放文件数据。`unlink` 与 `rmdir` 共用同一套流程、按调用号分流：同一套路径解析、同一套权限检查、同一套粘滞位检查，最后按调用号分别下发 `req_unlink`（文件）或 `req_rmdir`（目录）。删除前三项验证：父目录须是目录（否则 `ENOTDIR`）、父目录须可查找可写、粘滞位目录须做所有者检查（见 §1.4）。最后一个链接删除后数据块回收是 FS 的事——VFS 只删除目录项，不负责释放数据块。

### 1.4 粘滞位的保护规则

粘滞位（典型如 `/tmp`）的规则是：在此目录下，不能删除不属于自己的文件——只有文件所有者或 root 可以删除或改名（否则 `EPERM`）。判断所有者需要两次路径解析：先定位到父目录，再用 `advance` 取出被删文件的 vnode 并比对 uid——为了保护普通用户，多走一次解析是值得的。root 例外：只有 root（`SU_UID` 即 0）不受此限制。

### 1.5 重命名的约束

重命名把目录项从旧父目录移到新父目录，inode 本身不动。流程有四项检查：旧父目录必须存在（先定位旧父目录）；先做粘滞位检查（旧父目录含粘滞位时按 §1.4 规则检查）；缓存旧文件名（最后一个分量暂存到缓冲区，超长返回 `ENAMETOOLONG`）；新父目录必须存在（再定位新父目录，同一目录时断言新锁为空以避免自死锁）。两个父目录必须在同一设备（否则 `EXDEV`）、两个目录都必须有 `W|X` 权限（缺一不可）。最后获取互斥锁后下发 FS，一次完成搬移。

### 1.6 截断的长度相同优化

截断把文件调整到指定长度（负长度返回 `EINVAL`）。长度相同优化：新长度与当前长度相等且为常规文件时，不下发 FS，直接返回 `OK`（POSIX 要求保留文件时间戳，无实际修改时不应更新时间）。路径与 fd 双入口：按路径时解析路径并检查写权限，按 fd 时从 fd 取 vnode 并检查写模式（无写模式返回 `EBADF`）。公共函数 `truncate_vnode`：只允许常规文件与管道（其余返回 `EINVAL`），下发后同步新长度——注意：公共函数不做长度相同比较（open 的 `O_TRUNC` 即使长度相同也要更新时间戳，比较了反而错误）。

### 1.7 与其他 OS 的链接对照

- **Linux** 以 `vfs_link`/`vfs_unlink`/`vfs_rename` 实现同构检查：同一设备检查对应 `rename` 跨挂载点的 `EXDEV`，粘滞位检查对应 `may_delete` 的属主或能力检查，长度相同跳过对应 `truncate` 的 `ATTR_SIZE` 时间戳保留语义；`truncate_vnode` 的文件类型检查对应 `S_ISREG/S_ISFIFO` 的可截断集合。
- **Redox** 的名字空间以 rename/unlink 句柄对应重命名/删除；Redox 以方案内属主检查对应粘滞位保护。
- **seL4** 无名字空间，目录项管理是各服务的内部逻辑——有状态服务器把重命名做成多步检查流程（本篇的七类检查），无状态内核把它留给持有能力的客户端自行处理。

### 1.8 小结

链接层处理四类操作（创建硬链接→删除→重命名→截断），三组条件（设备是否相同/权限是否有/长度是否变化）决定流程走向，一条不变量贯穿始终：每次修改前必先检查——创建检查设备与权限，删除检查粘滞位，重命名检查双目录权限，截断检查长度与类型。每步都有检查覆盖，是本篇的核心要求。

## 2 C 源码分析

### 2.1 头注释契约（`link.c:1-12`）

最后一个链接删除后回收数据块（`1-3`：最后一个 unlink 把数据块放回空闲池）→ 七个入口（`5-12`：`do_unlink` 兼管 `rmdir`，其余各一个）。

### 2.2 `do_link` 流程（`link.c:29-86`）

`do_link`：取源路径与目标路径（`40-43`）→ 路径解析并配锁（`45-47`：源 vnode 全路径读锁）→ 打开源 vnode（`50-51`）→ 配置目标路径（`54-56`：父目录写锁）→ 取目标名并定位父目录（`57-60`，失败则释放源 vnode `62-67`）→ 同一设备检查（`70-71`）→ 新目录权限检查（`73`）→ 下发 FS 创建目录项（`75-77`）→ 释放锁并归还 vnode 引用（`79-84`）→ 返回（`85`）。

### 2.3 `do_unlink` 流程（`link.c:91-164`）

`do_unlink`：注释说明兼管（`93-97`：unlink 与 rmdir 共用流程，调用者按调用号区分）→ 复制路径（`104-105`）→ 配置路径解析（`107-109`：父目录写锁 + 保留符号链接尾）→ 定位父目录（`112`）→ 父目录类型检查（`115-120`，非目录返回 `ENOTDIR`）→ 双权限检查（`123-128`）→ 粘滞位检查（`132-152`：含粘滞位时二次解析并比对属主，属主或 root 以外返回 `EPERM`）→ 获取互斥锁（`154`）→ 按调用号下发（`156-159`）→ 释放并归还（`160-163`）。

### 2.4 `do_rename` 流程（`link.c:169-271`）

`do_rename`：取源路径与目标路径（`181-184`）→ 配置旧路径解析（`186-189`，注释说明先不取互斥锁以避免死锁 `187`）→ 定位旧父目录（`192-193`）→ 粘滞位检查（`197-217`，与删除共用逻辑）→ 缓存旧文件名（`220-226`，超长返回 `ENAMETOOLONG`）→ 配置新路径解析（`229-231`，读挂载表写 vnode）→ 定位新父目录（`232-233`）→ 同一目录断言（`240`，同一目录时新锁必为空）→ 失败则释放旧侧（`242-247`）→ 同一设备检查（`250`）→ 双目录权限检查（`253-254`，两个 `W|X` 缺一不可）→ 获取互斥锁后下发（`256-260`）→ 分别释放并归还（`262-268`，新锁存在则释放）→ 返回（`270`）。

### 2.5 `do_truncate` 流程（`link.c:276-322`）

`do_truncate`：注释说明公共函数（`278-282`）→ 取路径与目标长度（`292-299`）→ 负长度检查（`300`）→ 打开 vnode（`303-304`）→ 写权限检查（`307`）→ 长度相同跳过（`312-313`，常规文件且长度相同时直接 `OK`，保留时间戳语义）→ 下发 FS（`315`）→ 释放并归还（`318-320`）。

### 2.6 `do_ftruncate` 流程（`link.c:327-359`）

`do_ftruncate`：取 fd 与目标长度（`335-338`）→ 负长度检查（`338`）→ 按 fd 取 vnode（`341-342`）→ 写模式检查（`346-347`，无写模式返回 `EBADF`）→ 长度相同跳过（`348-353`）→ 下发 FS（`355`）→ 解锁（`357`）。

### 2.7 `truncate_vnode` 公共函数（`link.c:365-381`）

`truncate_vnode`：持锁断言（`371`）→ 文件类型检查（`372`，只允许常规文件与管道）→ 注释说明不比较长度（`374-377`，open 的 `O_TRUNC` 即使长度相同也要更新时间戳）→ 下发 FS（`378`）→ 成功后同步新长度（`379`）→ 返回（`380`）。

### 2.8 `do_slink` 流程（`link.c:387-424`）

`do_slink`：取目标内容与新路径（`402-405`）→ 空路径检查（`407`，长度 ≤1 返回 `ENOENT`）→ 超长检查（`408`，长度 ≥255 返回 `ENAMETOOLONG`）→ 定位父目录（`411-412`）→ 双权限检查（`413`）→ 下发 FS（`414-416`，长度减一，末尾 NUL 不写入，附发送者端点与有效 uid/gid）→ 释放并归还（`419-421`）。

### 2.9 `readlink` 流程（`link.c:430-508`）

`rdlink_direct`（`430-466`）：注释说明内部使用（`436`）→ 配置路径解析（`442-444`，读锁 + 保留符号链接尾）→ 暂存路径副本（`448-450`，原路径不动，末字节写零终止）→ 打开 vnode（`450`）→ 文件类型检查（`453-454`，非符号链接返回 `EINVAL`）→ 下发 FS（`456-457`，NONE 端点 + `PATH_MAX-1` + 标志 1）→ 零终止（`459`，正数即终止成功）→ 释放并归还（`461-463`）。`do_rdlink`（`471-508`）：取路径与缓冲（`483-486`）→ 缓冲长度检查（`487`）→ 配置路径解析（`489-491`）→ 打开 vnode（`494-495`）→ 文件类型检查（`498-499`）→ 下发 FS（`501`，请求者端点 + 标志 0）→ 释放并归还（`503-505`）。

## 3 Rust 设计决策

Rust 改写不是照抄 `link.c` 的路径解析与 FS 下发流程，而是吸收 Linux/Redox 的名字空间模型后做取舍。以下决策对应 `.design/27-design.v1.md` D1-D7。

### D1 调用枚举

- **C**：头注释七个入口，unlink 兼管 rmdir（`link.c:1-12,156-159`）。
- **Rust**：`LinkCall` 八个变体 + `ends_in_dir()`（`os/servers/vfs/src/link.rs:42,61`）。
- **为什么**：unlink 兼管 rmdir 是调用层面的事实，按调用号拆分为八个变体可使分流穷举。替代方案（七值 + 布尔）被否决：兼管是调用面的事实，八个变体更直接。

### D2 路径解析规格

- **C**：七个调用各有一套路径解析（锁组合 + 终止标志散见 `link.c:45-56,107-109,186-231,295-297,398-400,442-491`）。
- **Rust**：`LinkLookup` 九种 + `lookup_spec()` 纯函数表（`os/servers/vfs/src/link.rs:73,87,96,111,131`）。
- **为什么**：路径解析是"文件名对应哪个 vnode"的公共逻辑；锁意图与锁状态分离（锁状态归 05/06，本层只记录意图）。替代方案（各调用分散书写）被否决：锁组合错配会导致死锁或竞态，集中成一张表更易检查。

### D3 粘滞位检查

- **C**：两处共用逻辑（删除 `132-152`/重命名 `197-217`）。
- **Rust**：`sticky_check()`（`os/servers/vfs/src/link.rs:192`）。
- **为什么**：粘滞位保护规则在两处完全相同，收敛为一个函数。替代方案（两处各写一份）被否决：与 23-D5 同理，同一逻辑复制两份容易漂移。

### D4 截断检查

- **C**：负长度检查 + 长度相同跳过 + 文件类型检查 + 写模式检查（`link.c:300-372`）。
- **Rust**：`check_length()` + `same_size_skip()` + `truncate_type_ok()` + `write_mode_ok()`（`os/servers/vfs/src/link.rs:203,214,219,227`）。
- **为什么**：四个检查对应四种不同的错误返回；长度相同跳过单独列出——POSIX 时间戳保留语义最容易被"优化"掉。替代方案（合并为更少函数）被否决：四种错误各有 errno，合并后无法区分。

### D5 符号链接长度检查

- **C**：空路径检查 + 超长检查 + 下发长度减一（`link.c:407-416`）。
- **Rust**：`check_slink_len()` 返回下发长度（`os/servers/vfs/src/link.rs:238`）。
- **为什么**：三个检查保证符号链接内容合法；返回值即下发长度，使"末尾 NUL 不写入"可通过单测直接验证。替代方案（布尔检查 + 调用点减一）被否决：减一散落在调用点容易漏减。

### D6 readlink 检查

- **C**：缓冲长度检查 + 文件类型检查 + 内核/用户端点标志 + 零终止（`link.c:453-459,487-501`）。
- **Rust**：`check_rdlink_buf()` + `RdlinkSide` + `rdlink_channel()` + `terminate_ok()`（`os/servers/vfs/src/link.rs:249,258,270,278,292`）。
- **为什么**：内核内部读取与用户 readlink 请求的端点与标志必须配对，拆成独立参数容易错配。替代方案（两个布尔参数）被否决：配对关系分散成参数后容易传错。

### D7 设备与权限检查及 FS 对话

- **C**：两处 EXDEV 检查 + 双目录权限检查 + 旧文件名长度检查 + req_* 七个下发点（`link.c:70-77,220-259`）。
- **Rust**：`same_device()` + `old_name_fits()` + `FsLink{七个方法}`（`ScriptedLink` 按脚本应答 vs `RefusingLink` 固定拒绝）+ `link_then_read()` 契约探针（`os/servers/vfs/src/link.rs:298,307,319,338,394,396,421`）。
- **为什么**：设备一致性与权限检查是两个调用共用的前置条件；FS 是唯一的不可测点，一个 trait 七个方法即可覆盖。替代方案（七个 trait 分立）被否决：测试矩阵会膨胀七倍，而覆盖的是同一类逻辑。

## 6 过渡

本篇在 13（寻路）之后、28（stat）之前，是重命名与链接的归属层：13 只管路径解析到 vnode，26 只管进程终止转储之后，本篇管目录项变更（创建硬链接/删除/重命名/截断）；没有本篇，09 的主循环不知链接调用向谁分发，28 的 stat 不知文件名如何对应到文件属性。

```
13-path-lookup: eat_path/last_dir 寻路（路径解析到 vnode）
   │
26-coredump: 进程终止转储 ──────────┐
                                    ├─► 本篇：lookup_spec 路径解析 → sticky_check 粘滞位检查
14-filedes: get_filp 取 vnode ──────┘   → truncate 长度检查 → FsLink 下发 FS
           │                              │
           ├─► 28-stadir：stat 族的执行（文件名到属性的下一站）
           └─► 09-main-loop：VFS_LINK* 分发与回执的执行
```

阅读顺序提示：若关心"文件名如何对应到文件属性"，下一站 `28-stadir.md`（stat/chdir/statvfs 的执行）；若关心"路径如何解析到 vnode"，回看 `13-path-lookup.md`（寻路全程）。
