# 25 — exec：路径检查、脚本与动态链接处理及地址空间替换

本文讲清 `exec` 如何把"同一进程替换地址空间"拆成检查文件→释放旧空间→装载新程序→收尾四段：打开可执行文件并做三项检查（常规文件 REG 检查/X 执行权限检查/stat 属性可读检查），脚本解释器处理（`#!` 脚本需启动解释器并重写 `argv[0]`），动态链接（ELF `.interp` 需同时打开主文件与解释器，主文件 fd 保留供运行时读取，解释器作为新程序入口），装载或 `mmap` 直接映射或分段读取搬运，收尾关闭 CLOEXEC、按 `allow_setuid` 更新有效 uid/gid、写入新进程名——fork 是创建新进程（另起一个地址空间），exec 是替换当前进程地址空间（地址空间全换，fd 表独留）。

前置阅读：`10-pm-protocol.md`（`VFS_PM_EXEC` 入口）、`13-path-lookup.md`（打开文件所用的路径解析）、`02-fproc-struct.md`（凭证与进程名）、`04-filp-table.md`（检查所用的 filp）。

## 1 概念

### 1.1 为什么 exec 是地址空间替换

进程有两样东西：地址空间（含程序、栈）与保留的状态（fd 表、凭证、进程名）。fork 复制父进程状态创建新进程（新建一个地址空间）；exec 保留 fd 表、凭证、进程名，替换掉地址空间——fd 表原样留下（除了标了 CLOEXEC 的），地址空间整个释放重建，栈从用户手里重新拷贝，凭证看有效 uid/gid（sugid）再定，名字改成新文件名。exec 的顺序要求是：先把新文件的底细查清（打开文件并检查），再释放旧地址空间并装载新程序——先完成新文件检查再替换旧地址空间，否则两手空空。

exec 全程同步到底：从 PM 接到 `VFS_PM_EXEC` 起，到回执 `*pc`/`*newsp` 止，调用者一直等——没有续作，没有次波（与 22/23/24 的长问不同）。同步到底的前提是每一步都可判定：本篇的七个判定即七步的"放行条件"。

### 1.2 打开文件并做三项检查

打开文件即"把待执行文件解析并打开"。打开之前释放旧文件（有已打开的文件先解锁归还——换文件不止一次，脚本与动态链接都要换）。打开之后做三项检查：是常规文件吗（REG 检查，否则 `ENOEXEC`——目录不能执行）；可执行吗（X 执行权限检查，`forbidden` 说了算）；属性可读吗（stat 检查）。三项检查的顺序即优先级：文件类型→权限→属性，一关不过即返回，不往下走。

进程名附在打开文件里：取路径的 basename 记作文件名（`progname`）——ps 里看到的名字，此刻定下。

### 1.3 脚本解释器处理

文件首两字节是 `#!`，此文件是脚本——脚本自己运行不了，需启动解释器并重写 `argv[0]`。处理分三步：把脚本路径换成新 `argv[0]`（旧 argv0 腾位）；读文件首部一页，逆向切出解释器路径与参数，逐个插入栈；重新定位到解释器路径，再打开一个文件——这次打开文件时不应用 suid-sgid 提权规则（`sugid` 只用一次：脚本的有效 uid/gid 管脚本，解释器的不管——双重提权是祸根）。

`#!` 行必须有换行才算数（无换行即 `ENOEXEC`）；解释器路径必须切得出来（切不出即 `ENOEXEC`）——两处 `ENOEXEC` 检查的是"文件首部格式合法"。

### 1.4 动态链接处理

文件带解释器名（ELF 的 `.interp`），此文件是动态链接——需同时打开主文件与解释器：主文件打开一个 fd 保留（解释器运行时还要读它），解释器作为新程序入口。基址定在栈下 10MB（高得能 trap 空指针，低得能自重定位）。记名并切换文件：记住主文件名（`execname`，备栈留名用），切换到解释器路径再打开一个文件——同样不应用提权规则（标志表 1,1→1,0→0,0：首个文件应用，后续文件皆不应用）。

两个文件分工不同：主文件是"被读的"，解释器是"被运行的"——`is_dyn` 标记哪个是解释器，`elf_main_fd` 保留主文件的 fd。

### 1.5 装载的两条路径

新程序装载有两条路径。直接映射路径（`mmap`）：FS 支持 peek 且文件非内存设备 → 向 VM 借个 fd 直接映射（`vfs_memmap`，WRITE 转 WRITABLE，用即标 `vmfd_used`）。分段读取路径（`copymem`）：分段读取搬运（`read_seg`，LONG 检查防溢出、文件长度检查防越界、短读注记）。两条路径都是"把文件内容装入新地址空间"，只是直接映射请 VM 代劳，分段读取自己搬。装载表只认 ELF（`exec_loaders[]` 一表一哨兵）：首个 OK 即胜，全败即 `ENOEXEC`。

### 1.6 收尾三步

地址空间替换完了，收尾三步。关闭 fd：标了 CLOEXEC 的 fd 一律关闭（旧地址空间保留的 fd，新程序不继承）。更新有效 uid/gid：装载后仍允许提权（`allow_setuid`），此刻按 suid-sgid 规则更新有效 uid/gid（早改晚改皆错：早了被覆盖，晚了进程已跑）。写入进程名：文件名写入进程名（ps 显示新名）。终局清理：借用的 filp 解锁，否则旧文件解锁归还；闲置的 vmfd 关掉；VM 锁解开——按序清理借用的 filp、闲置 vmfd 与 VM 锁，一个不落。

### 1.7 与其他 OS 的执行对照

- **Linux** 以 `binfmt` 链实现同构语义：`binfmt_script` 嗅探 `#!` 并重写 `argv[0]`（对应 `is_script` + `patch_stack`），`binfmt_elf` 解析 `.interp` 并双映射（对应动态链接支路），`flush_old_exec` 关 CLOEXEC 并换凭证（对应收尾三步）；`exec_loaders[]` 的"首个 OK 即胜"即 `search_binary_handler` 的链式试探。
- **Redox** 的执行方案以验证（可读可执行）→映射（方案内分页）→更新进程名（改进程名）三段对应检查文件/装载/收尾；Redox 以方案内闭包续作对应 `run_loaders` 的表驱动。
- **seL4** 无执行原语，地址空间替换是持券者自助：新地址空间由用户组装，VFS 的打开文件三项检查在 seL4 中由各服务的准入检查分担——状态服务器把地址空间替换做成一站式，无状态内核把它拆成散件。

### 1.8 小结

exec 处理四段流程（检查文件→释放旧空间→装载新程序→收尾），三组条件（文件类型/地址空间状态/映射方式）决定流程走向，一条不变量贯穿始终：每次动手前必有检查——打开文件有三项检查，切换文件有三组标志，装载有两项长度检查，收尾按序清理。每步都有检查覆盖，是本篇的核心要求。

## 2 C 源码分析

### 2.1 头注释契约（`exec.c:1-15`）

十一步管线（`1-11`：验权→读首→取栈→配存→拷栈→读段→有效 uid/gid→修表→告内核→记 argc）→ 单入口 `pm_exec`（`13-15`）。

### 2.2 `vfs_exec_info` 结构（`exec.c:43-84`）

`vfs_exec_info` 十字段（`43-54`：装载参数/文件/挂载/属性/用户标志/动态链接标记/主文件 fd/全名/vmfd/使用标记）→ 前置声明（`56-65`）→ `PTRSIZE`（`67`）→ 装载表（`78-81`：ELF + 哨兵，装载钩 + 备栈钩）→ VM 锁宏（`83-84`）。

### 2.3 `get_read_vp` 流程（`exec.c:89-154`）

`get_read_vp`：释放旧文件（`105-109`，多次切换文件的设计）→ 记录进程名（`112-118`，basename + 终零）→ 打开文件（`121-122`）→ 解挂载锁（`124`）→ 三项检查（`126-134`：REG 检查 `ENOEXEC`/X 执行权限检查 `forbidden`/stat 检查）→ 有效 uid/gid 应用（`137-147`，sugid 下 SUID/SGID 各管各）→ 读首块（`149-151`）→ `OK`（`153`）。`FAILCHECK/Get_read_vp` 宏（`156-159`）：错即跳终局。

### 2.4 `vfs_memmap` 流程（`exec.c:161-180`）

`vfs_memmap`：取文件（`165-166`，经 `opaque` 回指）→ WRITE 转 WRITABLE（`170-171`）→ 下发 VM（`173-174`，九参直达）→ 成功则标已用（`175-177`）→ 返回（`179`）。

### 2.5 `pm_exec` 流程一：准备（`exec.c:185-247`）

`pm_exec` 签名（`185-186`：路径/路径长/帧/帧长/PC/栈指针/未用）→ 锁 VM（`209`）→ 清文件状态（`212-213`，`vmfd=-1`）→ 栈边界（`217-218`，用户栈顶 + 4MB）→ 检查路径（`220-223`，读锁对）→ 帧长度限制（`226-227`，超 `ARG_MAX` 即 `ENOMEM`）→ 取栈（`229-234`，替换旧地址空间前先保存栈）→ 定 vsp（`238`）→ 默认 UID（`241-242`，默认沿用旧值）→ 取路径名（`245-247`，三名同源）。

### 2.6 `pm_exec` 流程二：脚本与动态链接处理（`exec.c:249-314`）

首次打开文件（`254`，标志 1,1）→ 脚本支路（`260-271`：重取路径 `265` + 补栈 `266` + 二次打开文件 `270` 标志 1,0）→ 解释器分类（`278-281`，三值：负错/零静态/正动态）→ 动态链接支路（`283-314`：标动态 `285` + 打开主文件 `290-295` + 定基址 `301-302` + 记名 `305` + 切换文件 `311-313` 标志 0,0）。

### 2.7 `pm_exec` 流程三：装载准备（`exec.c:316-356`）

vmfd 取用（`317-335`：PEEK 检查 + 非 mem 检查 + 取 fd（`R_BIT`、`count=1`、挂载文件、`O_RDONLY`）+ 挂 memmap `332`）→ 回调挂钩（`338-344`：分段读/清进程/清存储/三配存 + 回指 + 端点/帧长/文件长度）→ 装载循环（`350-354`，首个 OK 即定备栈钩）→ 定局（`356`）。

### 2.8 `pm_exec` 流程四：收尾（`exec.c:358-402`）

通知 PM（`359`）→ 存 PC（`362`）→ 备栈（`365`）→ 拷贝栈（`368-369`，VFS→新地址空间）→ 交付栈指针（`372`）→ 收尾（`374-384`：关 CLOEXEC + 应用有效 uid/gid + 写入进程名）→ 终局清理（`386-401`：解锁序 + 关闲置 vmfd + 解 VM 锁）→ 返回（`401`）。

### 2.9 `stack_prepare_elf` 流程（`exec.c:404-517`）

`stack_prepare_elf`：非动态链接直接返回（`424-425`）→ 首块检查（`427-430`）→ 栈边界检查（`432-436`，`STACK_MIN_SZ` 公式 `406-411`）→ 定位（`439-441`）→ 边界双检查（`443-455`，首末 aux 越界即 `ENOEXEC`）→ 注释约定（`457-465`：libc 预留位之约）→ 七个辅向量（`480-514`：基址/入口/fd/双 id/页数 + 进程名 + 封口，满则跳末 `473-477`）→ `OK`（`516`）。

### 2.10 `is_script` 与 `patch_stack` 流程（`exec.c:519-602`）

`is_script`（`522-529`）：断言有首块（`525`）→ 双字节 `#!` + 长度足二（`527-528`）。`patch_stack`（`534-602`）：换 argv0（`553`，失败即 `ENOMEM`）→ 读页（`558-561`）→ 取长度（`563-565`，页为界）→ 长度检查（`566`，不足二即 `ENOEXEC`）→ 跳过 `#!`（`568-570`，`PATH_MAX` 封顶）→ 拷贝行（`573`）→ 换行检查（`575-576`）→ 逆向分词（`579-593`，空格跳尾、零封、回溯、逐个插入，失败即 `ENOMEM`）→ 定解释器（`595-599`，无解释器/解释器异位各一 `ENOEXEC`）→ `OK`（`601`）。

### 2.11 `insert_arg` 流程（`exec.c:604-683`）

`insert_arg`：注记布局（`610-618`）→ 取旧长度（`621`）→ 取参数长（`623`）→ 定 a0（`626`）→ 边界检查（`629-632`，越界即假）→ 差量（`634-642`：添为串加指针、换为长度差）→ 对齐（`645`）→ 限高（`648-652`，超 `ARG_MAX` 即假）→ 搬串（`655`）→ 摆参数（`658`）→ 添指针（`660-666`，数加一，仅添）→ 指零（`669`）→ 移指针（`672`）→ 修 ps（`675-680`，argv/env 重算）→ 真（`682`）。

### 2.12 `read_seg` 流程（`exec.c:685-715`）

`read_seg`：注记短读之源（`690-694`）→ LONG 检查（`701`，溢出即 `EIO`）→ 长度检查（`702`，超文件即 `EIO`）→ 下发读取（`704-709`，直达进程地址）→ 短读注记（`711-712`）→ 返回（`714`）。

### 2.13 `clo_exec` 与 `map_header` 流程（`exec.c:717-763`）

`clo_exec`（`721-731`）：逐 fd 查 CLOEXEC 位图（`728-729`）→ 关闭（`730`，不挂起）。`map_header`（`736-763`）：注记对齐之猜（`741-745`，8 字节于 ELF 皆宜）→ 取小（`751`，文件与缓冲之小）→ 首块读（`754-756`，经 FS 向 VFS）→ 失败注记（`757-760`）→ `OK`（`762`）。

## 3 Rust 设计决策

Rust 改写不是照抄 `exec.c` 的打开文件与装载流程，而是吸收 Linux/Redox 的执行模型后做取舍。以下决策对应 `.design/25-design.v1.md` D1-D7。

### D1 管线枚举

- **C**：头注释十一步 + `FAILCHECK` 跳终局（`exec.c:1-11,156,386-401`）。
- **Rust**：`ExecPhase` 十一段 + `?` 早返 + `CleanupPlan`（`os/servers/vfs/src/exec.rs:54,518,526`）。
- **为什么**：管线是"执行到哪一步"的知识；枚举使断点可名状。替代方案（布尔组）被否决：十一段非布尔可表。

### D2 打开文件的三项检查

- **C**：`get_read_vp` 释放旧文件/记录进程名/打开文件/三项检查/有效 uid-gid/读首块（`exec.c:89-154`）。
- **Rust**：`IdCheck` 三值 + `check_identity()` + `SuidHonor` + `honor_suid()`（`os/servers/vfs/src/exec.rs:81,91,106,120`）。
- **为什么**：三项检查顺序即优先级；有效 uid/gid 应用的 sugid 条件使"谁的有效 id"一算可知。替代方案（三布尔返回）被否决：三错各有 errno，枚举即分流。

### D3 脚本解释器处理

- **C**：`is_script` 双字节 + `patch_stack` 补栈 + `insert_arg` 算术（`exec.c:522-529,534-602,607-683`）。
- **Rust**：`is_script()` + `PatchPlan::{Direct, ViaInterpreter}` + `OffsetCalc` + `calc_insert()`（`os/servers/vfs/src/exec.rs:144,150,159,169,186`）。
- **为什么**：插参算术是全篇最微妙的纯计算；C 对齐公式的"已对齐再进一字" quirks 被逐算符镜像并注记。替代方案（指针直算）被否决：usize 算术配显式边界检查更安全。

### D4 动态链接处理

- **C**：解释器分类三值 + 动态链接支路（打开主文件/定基址/记名并切换文件，`exec.c:278-314`）。
- **Rust**：`classify_interpreter()`（负值直通）+ `loader_base()` + `VP_SWITCHES` 标志表（`os/servers/vfs/src/exec.rs:222,233,246,257,265`）。
- **为什么**：三值非二值，枚举消灭"负数即动态"的误读；切换文件标志表使 1,1→1,0→0,0 一表可查。替代方案（布尔动静）被否决：错/静态/动态三态非二值。

### D5 装载双路径

- **C**：`read_seg` 双检查 + `vfs_memmap` 标志转换 + `exec_loaders[]` 表 + vmfd 取用条件（`exec.c:688-715,161-180,78-81,320-321`）。
- **Rust**：`check_seg()` + `mmap_flags()` + `ImageLoader{load, setup_stack}`（`ScriptedLoader` 按脚本应答 vs `NullLoader` 恒 `ENOEXEC`，即哨兵）+ `vmfd_gate()`（`os/servers/vfs/src/exec.rs:284,293,299,305,315,324,347,359`）。
- **为什么**：装载表是"先试 ELF，不行即无"的知识；哨兵即第二实现，表驱动天然穷举。替代方案（函数指针表直译）被否决：trait 双钩对应装载/备栈，可测试。

### D6 辅向量准备

- **C**：`stack_prepare_elf` 七个辅向量封口 + `map_header` 取小首读（`exec.c:413-517,736-763`）。
- **Rust**：`AuxKind` 七名（数值归 ELF ABI，判定层只记名）+ `plan_aux()`（容名/溢名皆封口）+ `HeaderReader`（`ScriptedHeader` 定长应答 vs `ZeroHeader` 空文件）+ `HeaderInfo`（`os/servers/vfs/src/exec.rs:375,396,411,445,454,461,477`）。
- **为什么**：辅向量表是"动态链接续命七件事"的知识；数值不入判定层避 P0-fact 风险（ABI 数值归执行层）。替代方案（数值硬编码）被否决：记错一位即 P0。

### D7 收尾步骤

- **C**：`clo_exec` + 有效 uid/gid 应用 + 写入进程名 + 终局清理（`exec.c:721-731,376-384,386-401`）。
- **Rust**：`frame_gate()` + `stack_start()` + `settle_ids()` + `plan_cleanup()`（`os/servers/vfs/src/exec.rs:486,494,502,518,526`）。
- **为什么**：收尾是"旧地址空间退场、新进程名生效"的知识；关→改→名→理的顺序即步骤，错序即泄漏或错付。替代方案（散写）被否决：顺序知识集中才不丢步。

## 6 过渡

本篇在 10（PM 协议入口）之后、26（core dump）之前，是 exec 的归属层：10 只管 `VFS_PM_EXEC` 到达本层，13 只管打开文件所用的寻路，本篇管检查完成之后怎么办（释放旧空间/装载/收尾）；没有本篇，09 的主循环不知执行调用向谁登记，26 的转储不知地址空间何时建成。

```
10-pm-protocol: VFS_PM_EXEC 到达（exec 请求入口）
   │
13-path-lookup: eat_path 寻路 ───────┐
29-protect: forbidden X 执行权限检查 ┼─► 本篇：check_identity 检查文件 → classify_interpreter 分类
12-request: req_stat/首块/分段读 ────┘   → run_loaders 装载 → plan_aux 准备辅向量
           │                              │ → settle_ids 更新 id → plan_cleanup 清理
           ├─► 26-coredump：地址空间建成后的转储（pm_dumpcore 的归属）
           ├─► ../02-stage-vm/20-vm-mmap.md：mmap 装载的执行
           └─► ../04-stage-pm/17-exec.md：新生通告的执行
```

阅读顺序提示：若关心"进程终止后如何转储"，下一站 `26-coredump.md`（`pm_dumpcore` 的执行）；若关心"装载由谁执行"，外站 `../02-stage-vm/20-vm-mmap.md`（VM 侧 mmap）。
