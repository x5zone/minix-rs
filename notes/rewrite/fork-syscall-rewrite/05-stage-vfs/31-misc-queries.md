# 31 — misc-queries：杂项查询：statvfs批量、sync、fcntl复用与utimens

本文讲清杂项八类操作如何处理：批量查询需 root 检查与长度检查（getsysinfo 整表复制）、sync 与 fsync 广播无返回值（落盘同步全卷与定点单卷）、fcntl 复用需 fd 检查（按 fd 查询：peek 检查与常规块检查）、ioctl 三类请求与异步处理（上游请求的 fd 查询与关闭、读写，非预期来源拒绝，异步恢复）、sysctl 的 verbose 与统计下发（sysctl 开关设置与获取）、utimens 按 fd 与按路径双入口与 NOW-OMIT-显值三态（时间戳更新）、参数探针五项检查（标签查询与分发）、废弃调用固定返回（getrusage 恒返 OK）——杂项虽分散但每项都有明确检查，各有前置条件。

前置阅读：`09-main-loop.md`（调用分发与 `ReplyIntent`）、`06-vmnt-table.md`（挂载表结构）、`12-request-wrappers.md`（FS 信封）、`29-protect.md`（判权与只读挂载检查）。

## 1 概念

### 1.0 引言与前置

三类问题：系统状态如何批量查询（getsysinfo 整表复制）、数据何时落盘同步（sync 全卷与 fsync 定点）、上游请求与参数如何处理（VM 请求、sysctl 开关、时间戳更新、参数探针、废弃调用）。三类问题答完，前置条件（root 检查、属主检查、只读挂载检查）一过，数据形状（表、卷、fd）一定，返回结果即出。本章假设读者已知挂载卷（vmnt）与 fd 为何物（见 06/14），只讲"常规文件操作之外的杂项查询与控制"。

### 1.1 为什么杂项要成篇

杂项不是杂物：八个调用分三类——状态查询类（getsysinfo 批量查询）、落盘同步类（sync/fsync 落盘同步）、请求应答类（dupvm 按 fd 查询、vm_call 上游请求、svrctl 的 sysctl 开关、utimens 时间戳更新、gcov 参数探针、getrusage 废弃调用）。每类各有前置条件。无此篇，阶段叙事缺收束：14~30 管"操作挂载卷"，本篇管"挂载卷操作之外的一切查询与应答"。

### 1.2 批量查询：整表复制

批量查询（getsysinfo）是整表复制：调用者要全表，VFS 把整表拷贝到用户缓冲——复制不问用途（不问调用者为何要表）。复制有三张表（进程表、设备映射、轻量进程表）加一项（调用统计，编译开关常闭）；检查有两项（root 检查先行：复制会泄露系统状态，非 root 不复制；长度检查后置：表长度须等于传入长度，不等即 `EINVAL`）。轻量进程表是现场填写的：阻塞在字符设备者直接填写其设备号，阻塞在套接字者查表填写，其余填写"无属主"——填写复制是"阻塞状态翻译为任务类型"的知识。

### 1.3 落盘同步：广播与定点

落盘同步（sync）是广播：逐个挂载卷询问"是否需要落盘"，有设备号（FS 在）有根 vnode（卷已挂载）者下发 FS，下发结果不收集——广播无返回值（`req_sync` 返回 void，结果也无处返回）。加锁失败则停止：卷锁不上，广播即止，错误直接返回。定点（fsync）是广播的收窄：先按 fd 定位卷（fd 转卷，fd 无效即直接返回 `err_code`），再对同卷按同样的三条件（有设备号、有 FS、有根 vnode）下发。广播与定点流程相同，区别在"先定位卷"。

### 1.4 按 fd 查询：VM 的反向查询

按 fd 查询（dupvm）是反向查询：平日进程向 VFS 申请 fd（open），此处 VM 向 VFS 查询他人已打开的 fd（mmap 需要读取他人所在卷）。查询有两项检查：peek 检查（FS 无 peek 方法不允许查询——查询即读取，无读取方法不允许）加常规块检查（非常规块文件不允许——映射只支持常规块文件）。检查通过则共享借位（VM 表置位加 `filp_count++`）：借位分配是 14 章表操作，计数共享是 04 章语义，本篇只做两项检查。诊断打印归调用者：错误作返回值，日志在外层。

### 1.5 上游请求：VM 的三种请求

上游请求（vm_call）是 VM 发来的请求，有三种：fd 查询（FDLOOKUP：按 fd 查询并返回设备号、inode 号、页数）、fd 关闭（FDCLOSE：关闭借来的 fd）、读写（FDIO：定位加直接读）。请求必有来源检查：非 VM 发来的请求即拒绝（`ENOSYS`，"你不是 VM，不处理"）。fd 查询的应答分两支：块设备走一支（返回对端设备号加无 inode 号加无界页数）、常规文件走另一支（返回本卷加 inode 号加折算页数）。回复必须异步（VM 收不到同步回复）加结果恒挂起——上游请求无即时回复，回复都是后续补发。

### 1.6 sysctl 开关：F 族设置与获取

sysctl 开关（svrctl）是 F 族两个操作：设置（SET）与获取（GET），分组检查先行（非 F 族不处理）。设置只有 verbose 一个键：键长度两项检查（键名长度在 `(0,64)`、键值长度在 `(0,64)`，区间一开一闭）加值域五档（0-4，越界即拒绝）。获取有三个键：堆栈回溯（转储线程栈，由宿主转储——无线程则无转储，A-1）、select 统计（倒出 select 记账，由宿主倒出）、活动线程数（`NR_WTHREADS - 空闲数`，可计算）。键不同事情不同：四个键名各有后续处理，不可混用。

### 1.7 时间戳更新：路径方式与 fd 方式

时间戳更新（utimens）有两种方式：路径方式（UTIMENS：路径解析后处理）与 fd 方式（FUTIMENS：持有 fd 直接处理）。路径方式有标志检查（只有 NOFOLLOW 可附带，其余标志即拒绝；相对 fd 的路径名不支持——注释明言）；fd 方式也有标志检查（无标志才处理）。属主检查分两段：文件属主与 root 直接通过；其余用户只有 NOW 全量更新（两个时间戳都是 NOW）且有写权限，才通过——"NOW 全量更新"是第二条件（touch 的本意：时间戳全部更新为当前时间时可用写权限代替属主检查）。只读挂载检查在最后：只读挂载上，root 也不允许修改。时间戳三态：NOW 取时钟（涉 NOW 或 OMIT 则读取时钟 `clock_time`）、OMIT 保留原值（秒从时钟取值、纳秒保留，老 FS 也兼容）、显值检查纳秒（纳秒超十亿即 `EINVAL`，负值也拒绝——无符号比较下无负数）。

### 1.8 参数探针与废弃调用

参数探针（gcov_flush）是按标签分发，五项检查：root 检查（覆盖率数据敏感，非 root 不处理）→ 标签长度检查（16 字节以内，含终止符；空标签也拒绝——空则 `label[-1]` 越界，见 §2.7）→ 端点查询（DS 按标签翻译为端点）→ INIT 拒绝（init 是唯一有标签的非系统进程，覆盖率不出系统进程）→ 授权检查（临时授权，失败即 `ENOMEM`）。分发后按目标分流：自身（VFS）本地刷新、他人发送任务消息；事后释放授权（临时授权必释放）。废弃调用（getrusage）固定返回：PM 接管已成定局，VFS 侧恒返 OK——废弃也有前置条件（删除前保持兼容，兼容即 OK）。异常钩子（panic_hook）无判定：只打印，不设判定层。

### 1.9 与其他 OS 的杂项对照

- **Linux** 以同构调用对应七类操作：`sync_filesystems` 全卷广播对应落盘同步广播（逐 superblock 下发）；`sysinfo` 整表复制对应批量查询；`utimensat` 的 NOW/OMIT/显值三态对应时间戳更新三态（POSIX 同源）；`sysctl` 开关对应 F 族设置与获取；gcov 内核覆盖率对应标签参数探针；`getrusage` 留用对应废弃调用的差异（Linux 保留、VFS 归 PM——职责归属不同）。
- **Redox** 的杂项以持有即操作对应广播：Redox 持卷句柄者自行刷盘（无全卷广播——广播是 Minix3 多 FS 服务的结构）；Redox 以方案读取状态对应整表复制（读取状态不复制整表）；Redox sysctl 开关以环境方案调参对应 F 族键名。
- **seL4** 无杂项接口：批量查询与落盘同步都由能力持有者直接执行——广播复制在 seL4 中由能力分发替代：有能力者各自执行，无需中央杂项层。

### 1.10 小结

批量查询有三表两项检查（root 检查加长度检查），落盘同步有广播与定点（选卷是纯判定），按 fd 查询有两项检查（peek 检查加常规块检查），上游请求有三种（fd 查询、关闭、读写，非预期来源拒绝，恒挂起），sysctl 开关有设置获取两个操作四个键名（verbose 0-4 加堆栈回溯、select 统计、活动线程数），时间戳更新有两种方式三态（路径方式与 fd 方式加 NOW/OMIT/显值），参数探针有五项检查（root 检查、长度检查、端点查询、INIT 拒绝、授权检查），废弃调用固定返回。八类操作同一写法：前置条件通过则执行，各有明确处理——检查逻辑都在杂项层。

## 2 C 源码分析

### 2.1 `do_getsysinfo` 流程（`misc.c:52-112`）

`do_getsysinfo`：取参数（`61-63`：哪张表、何处、多长）→ root 检查（`70`，泄露系统状态非 root 不复制）→ 三表分流（`73-97`：整表复制 `73-76` + 设备映射 `77-80` + 轻量表填写 `81-97`：逐进程复制 tty 与阻塞状态，字符设备直接填设备号 `87-88`、套接字查表填写 `89-91`、其余填无属主 `92-93`）→ 统计分支（`98-103`，编译开关内）→ 未知表拒绝（`104-105`）→ 长度检查（`108`）→ 拷贝到用户（`111`）。

### 2.2 落盘同步流程（`misc.c:276-326`）

### 2.3 `dupvm` 流程（`misc.c:328-375`）

`dupvm`：准备空位（`334`）→ 按 fd 取 vnode（`336-339`：失败即 `EBADF` + 打印）→ peek 检查（`341-347`：无 peek 即 `EINVAL`）→ 断言有卷与只读挂载引用（`349-350`）→ 常规块检查（`352-357`：非常规块即 `EINVAL` + 打印）→ VM 表分配空位（`360-364`：VM 表取空位，失败直接返回 + 打印）→ 计数共享（`368-370`：`filp_count++` + 置位）→ 返回卷（`372`）→ 返回（`374`）。

## 3 Rust 设计决策

Rust 改写不是照抄 `misc.c` 的开关与指针表，而是吸收 Linux/Redox 的杂项模型后做取舍。以下决策对应 `.design/31-design.v1.md` D1-D7。

### D1 调用面复用

- **C**：八注册（`table.c:34,50,55,56,60-62,66`）+ 八号（`callnr.h:88,104,109,110,114-116,120`）。
- **Rust**：复用 `VfsCallNum::{Sync, Fsync, Utimens, Vmcall, Getrusage, Svrctl, GcovFlush, Getsysinfo}`（`os/servers/vfs/src/call_table.rs:45,61,66,67,71-73,77`）；本篇另附八偏移常量（`os/servers/vfs/src/misc.rs:46,48,50,52,54,56,58,60`）供调用面一处览。
- **为什么**：八调用各为独立 VFS 消息，09 已类型化；另设枚举即两处真源。替代方案（本篇另设 MiscCall 八值）被否决：与 09 同值枚举是重复定义（模式 A 反例）。

### D2 批量查询检查

- **C**：root 检查（`70`）+ 三表分流（`73-97`）+ 统计分支（`98-103`，编译开关）+ 长度检查（`108`）。
- **Rust**：`SysinfoWhat::{ProcTab, DmapTab, ProcLightTab}` + `from_raw()`（`misc.rs:73,85`，`2/3/13`；`9` 无表返 `None`）+ `sysinfo_root_gate()`（`96`）+ `sysinfo_len_gate()`（`104`）+ `BlockKind/LightTask` + `light_task()`（`114,125,136`，smap 查询结果以 `Option` 传入）。
- **为什么**：复制不问用途（批量查询只管拷贝）；统计分支是编译期开关，常闭即无物，Rust 以文档声明代 cfg（A-9 同款）；轻量表填写是"阻塞状态翻译为任务类型"的知识，查表执行归 19 故参数化。替代方案（本模块复刻 calls_stats 表）被否决：表是编译开关产物，常闭即无物。

### D3 落盘同步选卷

- **C**：全卷扫描（`281-291`）+ 按 fd 定位卷（`305-311`）+ 同卷扫描（`313-323`）；下发结果不收集（`req_sync` 返回 void）。
- **Rust**：`MntSync{has_dev, has_fs, has_root, fs, dev}` + `sync_targets()`（`misc.rs:153,172`）+ `fsync_targets()`（`181`，卷相同 + 三条件）；加锁失败与下发 FS 归调用者。
- **为什么**：选卷是纯判定，加锁与下发是执行；下发结果不收集故 `sync_fs` 返回 `()`（忠实）。替代方案（trait 内锁表）被否决：表归 06（A-4 聚合在 VfsState）。

### D4 按 fd 查询检查

- **C**：按 fd 取 vnode（`336-339`）+ peek 检查（`341-347`）+ 常规块检查（`352-357`）+ VM 表分配（`360-364`）+ 计数共享（`368-370`）+ 打印三处（`338/353/362`）。
- **Rust**：`dupvm_fd_gate()`（`misc.rs:192`，fd 无效拒绝）+ `dupvm_gate()`（`misc.rs:204`，peek 检查 + 常规块检查两项；`FileType` 复用 15）+ `LookupAnswer{dev, ino, size_pages}`（`227`）+ `size_pages()`（`239`，`div_ceil` 无溢出）+ `BLK_PAGES_UNBOUNDED`（`223`，32 位 `LONG_MAX` 线值 pin，A-8）。
- **为什么**：分配与计数归 14 章；与 25 `vmfd_gate` 同 peek 不同次序检查（25 查卷性质、此处查文件类型，不合并）；打印归调用者（错误作返回值，日志在外层）；`div_ceil` 替 C 加除式（防溢出是目的，加法式是形式）。替代方案（合并两项检查）被否决：检查分属不同域。

### D5 VM 上游请求

- **C**：非预期来源拒绝（`402-403`）+ 槽位查询（`405-406`）+ 三种请求（`414-477`，未知请求 panic `475`）+ 异步恢复（`492-494`）+ 恒挂起（`497`）。
- **Rust**：`VmVfsReq::{FdLookup, FdClose, FdIo}` + `from_raw()`（`misc.rs:262,274`，`101/102/103`；未知请求返 `None`——C 的 panic 转拒绝，SUSPEND 语义下调用者应答错误）+ `vm_call_source_ok()`（`285`）+ `vm_lookup_gate()`（`297`，无属主拒绝）+ `lookup_answer()`（`244`，块与常规分流）+ `VM_VFS_REPLY`（`305`，`0xC1E`）+ `MiscVerdict::Suspend`（`688`，恒挂起，A-5）。
- **为什么**：请求必有来源检查；未知请求 panic 在单线程事件循环无宿主可崩——转拒绝是"崩不如拒"的知识（崩溃用于调试器，拒绝用于协议）；三种请求同归挂起故一个 verdict。替代方案（三种请求各一个 verdict）被否决：`497` 无分支。

### D6 sysctl 开关与时间戳更新

- **C**：分组检查（`805`）+ 设置获取分流（`808-809`）+ 键长度检查（`822-829`）+ verbose 值域（`848`）+ 三键应答（`860-876`）/ 路径方式与 fd 方式（`time.c:59-85`）+ 标志检查（`61-62/80-81`）+ 属主检查两段（`89-92`）+ 只读挂载检查（`93`）+ 三态处理（`105-138`）。
- **Rust**：`SVRCTL_GROUP` + `svrctl_group()`（`misc.rs:308,324`，`IOCGROUP` 式，方向位复用 19）+ `SvrctlCmd::{SetParam, GetParam}` + `from_raw()`（`338,347`，线值 const fn 合成，A-8）+ `SvrctlKey` 四值 + `from_key/settable`（`358,373,384`）+ `verbose_gate()`（`391`，`0-4`）+ `sysgetenv_len_gate()`（`402`，值域同归区间一开一闭）+ `HostAction` 四值（`417`，执行下发）/ `UtimensStyle` + `utimens_flag_gate()`（`430,441`）+ `utimens_owner_gate()`（`461`，两段）+ `NsecSpec/Timespec` + `resolve_nsec()`（`494,505,520`）+ `utimens_readonly_gate()`（`539`，复用 29）。
- **为什么**：键名不同事情不同；长度检查区间一开一闭、值域同归是"长度检查"的知识；属主检查两段顺序不可换（属主通过→NOW 全量更新的写权限）；三态是 POSIX 语义；只读复用 29 不另判（同源一处）。替代方案（verbose 布尔化/另判只读）被否决：五档是线值事实；另判是重复定义。

### D7 杂项三则与 FS 对话

- **C**：gcov 五项检查（`31/39/46/50/54`）+ 本地远端分流（`59-68`）+ 释放授权（`70`）/ getrusage 废弃调用固定返回（`1000-1005`）/ panic_hook 打印（`989-993`）/ `req_sync` 下发不等待 + `req_utime` 问答。
- **Rust**：`gcov_label_gate()`（`misc.rs:555`，空标签拒绝——MINIX3 BUG 修复，见下）+ `gcov_endpt_ok()`（`566`）+ `gcov_grant_outcome()`（`575`）+ `GcovTarget/gcov_target()`（`585,593`）+ `getrusage_verdict()`（`605`，恒 `OK`）+ panic_hook 无符号 + `MiscFs{sync_fs, utime}`（`614`，`ScriptedMisc` 记录调用应答 vs `RefusingMisc` 固定拒绝）+ `MiscVerdict::{Done, Suspend}`（`688`）+ `MiscError` 九变体（`701`）。
- **为什么**：废弃也有前置条件（删除前保持兼容）；下发不等待是 D3 同源；空标签拒绝是**内存安全修复**：C `39` 放行空标签致 `44` 之 `label[len-1]` 越界（MINIX3 BUG 标注，模式 78）；gcov 全 trait 化（grant/taskcall/revoke）被否决：授权与释放是外层执行，判定层只做检查与分流。

## 6 过渡

本篇在 30（锁）之后、99（全局）之前，是"杂项"的归属层：30 管操作挂载卷时上锁，本篇管挂载卷操作之外一切查询与应答；没有本篇，09 的分发不知杂项何往，99 的常量不知杂项何用。

```
30-fcntl-lock: lock_op_decision 判争（操作挂载卷时上锁）
   │
09-main-loop: 八调用分发 ────────────┐
                                    ├─► 本篇：批量查询复制 → 落盘同步广播 → 按 fd 查询应答
06-vmnt-table: 挂载表 ──────────────┘   → MiscFs 下发 FS → MiscVerdict 异步挂起
           │                              │
           └─► 99-global-concepts：常量术语收束（杂项何用的下一站）
```

阅读顺序提示：若关心"杂项何用的下文"，下一站 `99-global-concepts.md`（常量、全局状态、术语收尾）；若回看调用分发，见 `09-main-loop.md`（八调用的来处）。
