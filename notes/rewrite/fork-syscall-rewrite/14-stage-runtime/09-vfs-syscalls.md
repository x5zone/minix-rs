## 1 概念：为什么读写是最大的一组

进程管理管的是进程表，一张表，几十个操作。文件系统管的是所有文件和目录：打开关闭读写挪位，建删改查，目录 mounting，元数据，几十个调用号从 256 排到 294，是用户态调用最多的一组。但数量多不等于形状多，全部调用只用四种形状，学会四个就等于学会全部。

第一种是读写形：描述符、长度、缓冲地址、预留计数，四字段，读和写共用。回复类型是实际传输的字节数，可能比要的少（读到文件尾、管道没货），调用者按实际数处理，不能假设要多少给多少。第二种是开关形：打开按标志分两条路，关闭带描述符加不阻塞标志。第三种是定位形：描述符、偏移、起点三字段，回复体里捎回新位置，和等孩子的回抄是一个思想。第四种是散列形：调用者手里是离散的小块，协议只要连续的一段，中间需要一次拼装：先校验各段合法，再决定拼还是不拼。

### 1.1 读写形状的心智模型

记住一句话：四字段去，一数字回。去的时候描述符指哪开的文件，长度说要多少，地址说往哪放（读）或从哪拿（写），计数永远填零留给未来。回来的时候类型字段就是实际数，负数就是错误号。读写的 C 源码除了调用号不一样，其余一字不差，这种重复不是偷懒，是有意让两条路行为一致。

### 1.2 打开分派的心智模型

记住另一句话：创建位是道岔，扳过去走创建布局，不过走路径布局。创建布局带名字、长度、标志、模式，因为新建文件要定权限；路径布局带名字、长度、标志、内联副本，因为打开老文件要传路径。模式只在创建时有意义，打开老文件时模式字段是零，服务不看它。道岔判断只看一位，其他标志位原样进消息，服务自己解读。

### 1.3 散列拼装的心智模型

记住第三句话：先验段数，再验总长，再验空针，零总长直接回家。段数超一千直接拒绝，加法回绕直接拒绝，非空段配空地址直接报坏地址，三关都过算出总长。总长为零说明没事可做，直接返回成功，连临时缓冲都不申请。总长非零才申请一块连续内存，写操作先抄进去再调读写的形状，读操作调完再散回去。拼装层只管拼，不管读写，读写只管连续，不管离散。

## 2 C 语言源码分析：调用组里的每个文件在做什么

本章按读写、开关、定位、散列的顺序讲解代表性 C 语言文件。组内几十个文件共享四种形状，这里讲透形状，清单列全。

### 2.1 读和写：同一个模子

打开 `minix3/minix/lib/libc/sys/read.c` 和 `write.c`，两个文件除了名字和调用号一字不差：清零消息，填描述符、长度、缓冲地址，预留计数填零，调协议，返回回复类型。写操作的计数旁注明留给未来用，读操作没有这句注，但行为一致：发零，服务不看。载荷布局在 `minix3/minix/include/minix/ipc.h` 的第 795 行到第 803 行：描述符、缓冲地址、长度、累计计数。注意顺序是地址在前长度在后，和源码里的赋值顺序（长度先写）不一样：赋值顺序不重要，布局顺序才决定字节位置，Rust 实现按布局顺序排字段，测试逐字节核对。

### 2.2 打开：标志决定布局和调用号

打开 `minix3/minix/lib/libc/sys/open.c`，函数用变长参数取模式（只有创建时才取）。分支看创建标志位：有，走创建布局（名字长度、标志、模式、名字地址）加创建调用号；无，走路径打包（名字、长度、内联副本见第 05 篇）加标志字段，再加打开调用号。创建标志位的值在 `minix3/sys/sys/fcntl.h` 文件的第 99 行：十六进制 200。调用号在调用号头文件的第 75、76 行：打开是基址加 3，创建是基址加 4。基址本身在第 68 行：十六进制 100。

### 2.3 关闭与复制：小函数大复用

关闭函数 `close.c` 只有三行有效内容：清零，填描述符，不阻塞标志填零，调协议。复制函数 `dup.c` 更短：全文就是调文件控制函数，命令是固定复制，参数是零，意思是复制到最小的空闲描述符。文件控制命令固定复制的值在 `minix3/sys/sys/fcntl.h` 文件的第 178 行：0。这种小函数复用大函数的写法是组合面的典型：不新增调用号，不新增消息布局，老路新用。

### 2.4 定位：请求加回读

打开 `minix3/minix/lib/libc/sys/lseek.c`，清零，填描述符、偏移、起点，调协议，失败返回负一，成功从回复体读回新位置并返回。载荷布局在通信头文件的第 726 行到第 734 行，顺序罕见：偏移第一，描述符第二，起点第三。和读写载荷的描述符第一不一样，抄字段时不能凭感觉，必须看定义。回复的读取位置是载荷零偏移的八字节，类型是 64 位偏移，符号保留。

### 2.5 散列读写：校验加拼装

打开 `minix3/minix/lib/libc/sys/vectorio.c`，前半段是三关校验：段数负数或超一千直接参数错误；累加时用最大值减已累加比较下一段，包不住就参数错误；非空段配空地址报坏地址。三关的错误号不一样：前两关参数错误，第三关坏地址，调用者能分清是段表写错了还是地址写错了。总长为零直接存空指针返回零，不申请内存。申请到临时缓冲后，写操作先把各段抄进去再调读写的形状，读操作调完再把结果散回各段。散列层从不碰调用号，碰的是读写函数，层次分明。

### 2.6 调用号清单

调用号集中在调用号头文件的第 68 行起：基址十六进制 100，读加 0，写加 1，定位加 2，打开加 3，创建加 4，关闭加 5，文件控制加 25，目录列举加 29，选择等待加 30。目标端点在 `minix3/minix/include/minix/com.h` 文件的第 60 行：文件系统是 1 号端点。本组其余调用（元数据、目录、挂载、截断等）同形，清单见阶段计划。套接字族排除在外，归网络阶段，边界在计划排除表里写明。

## 3 Rust 设计决策：为什么是四种载荷加一个校验函数

本章解释 `os/libs/minix-sys/src/vfs.rs` 文件里的每一个设计选择。先说 C 语言做法带来的问题，再说 Rust 做法如何解决问题，最后说否决掉的替代方案。

### 3.1 用布局结构体锁定字节顺序

C 语言的字段赋值顺序和布局顺序是两回事，抄写的人容易按赋值顺序排 Rust 字段，导致字节错位。Rust 实现给每种形状一个布局结构体，字段按 C 定义顺序排，尺寸断言锁 56，顺序测试逐字节核对。读写载荷的地址在前长度在后，定位载荷的偏移第一，这两处反直觉的顺序都有测试锁死，凭感觉写的人会被测试拦下来。

替代方案是直接用消息联合体的通用槽位，理由是少定义类型。这个方案被否决了，理由是通用槽位的名字不表达含义，读者看到第三个整数不知道它是长度还是地址，而布局结构体的字段名就是文档。

### 3.2 用分派枚举说出打开的两条路

C 语言的打开分支藏在条件语句里，两种布局的差异散落在分支两侧。Rust 实现用分派枚举说出两条路：创建带模式，既有走路径。分派函数是纯的，测试覆盖四种标志组合：纯创建位、有杂质的创建位、纯零、纯杂质。创建路完整实现，路径布局路如实报告未就绪：64 位地址下 40 字节内联缓冲放不进 56 字节载荷，布局决策权在第 99 篇，本组不擅自改分界，不发送畸形消息。未就绪不是占位疏漏，是有归属的已知缺口，注释写明去向，测试断言不跑路（零次往返）。

### 3.3 用纯函数承载散列校验

C 语言的散列校验和拼装、调用混在一个函数里，测试校验逻辑必须进堆分配。Rust 实现把校验抽成纯函数：段数、总长、空针三关，返回总长或错误。调用者拿总长决定拼还是不拼，拼装和调用在上层。测试覆盖总量、空表、空针无害、空针有害、回绕五种情形。最大值用 64 位上限表达 32 位时代的最大可表示字节数，注释写明换算，不烧新常量。

## 4 错误处理：调用组的失败及其错误号

| Rust 情形 | 处理 | 对应的 Minix 错误号 | 选择理由 |
|-----------|------|---------------------|----------|
| 服务回复负数 | 取反为类型化错误 | 回复的绝对值 | 协议本身，不是映射 |
| 段数超限或总长回绕 | 直接参数错误 | `EINVAL`（值 22） | C 版本前两关同样参数错误 |
| 非空段配空地址 | 直接坏地址错误 | `EFAULT`（值 14） | C 版本第三关同样坏地址 |
| 路径布局未定 | 明确报告未就绪 | `ENOSYS`（值 78） | 有归属的缺口，不是无声失败 |

坏地址错误号复用共享类型库的现有值，无自创。布局待定错误只出现在布局未定的一条路上，调用者一看便知去第 99 篇找下文。

## 6 过渡：从管文件到管内存与杂项

文件系统解决的是字节流的问题：读多少，写多少，位置在哪，目录里有什么。从下一篇开始，视角转向地址空间：程序要扩内存找谁，映射文件到内存怎么讲，共享内存怎么算。形状还是同一个：清零消息，填字段，调协议，看正负，只是目标换成虚拟内存服务。

请继续阅读第 10 篇 `10-vm-syscalls.md`（待改写），它讲解堆调整、映射解除映射两族调用的封装。路径布局的 64 位决策在第 99 篇落定后，本篇的打开既有路会补全，届时以第 99 篇为准。
