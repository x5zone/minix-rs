# 04 — DS 槽位分配与查找：六个原语管两张表

> **分类**: 存储原语 / 分配与查找
> **源码**: `minix3/minix/servers/ds/store.c:11-107`
> **说明**: 两张定长表需要六个原语：两个分配、一个释放、三个查找，外加一个"空"判定。本文讲清每个原语的语义、为什么分配是"从 0 往上找第一个空位"，以及 Rust 为什么用编号（slot）代替指针。

---

## 1 概念

### 1.1 目标读者与前置知识

面向要调用或实现表操作的读者。前置知识：03 的两张表（知道槽里有什么），`IN_USE` 标志。线性扫描的时间复杂度概念（O(n)）用到时现场解释。

### 1.2 本章不讲什么

- 条目和订阅长什么样——那是 03 的事。
- 名字和权限怎么判定——那是 05 的事（本篇的查找只管"按什么条件比"，不管"名字从哪来"）。
- handler 怎么调这些原语——那是 07~11 的事。

### 1.3 六个原语一览

| 原语 | C 函数 | 表 | 做什么 | 满了/找不到 |
|------|--------|----|--------|-------------|
| 分配条目槽 | `alloc_data_slot`（`:11-22`） | 条目表（128） | 从 0 起找第一个无旗槽 | 回 `NULL` |
| 分配订阅槽 | `alloc_sub_slot`（`:27-38`） | 订阅表（256） | 同上 | 回 `NULL` |
| 释放订阅槽 | `free_sub_slot`（`:43-52`） | 订阅表 | 断言有旗 → 释正则 → 清零 → 清旗 | 空槽释放直接 `assert` 崩（调用方 bug，不容忍） |
| 按名+类型查 | `lookup_entry`（`:57-70`） | 条目表 | 有旗 → 类型相交 → 名字相等 | 回 `NULL` |
| 按端点查标签 | `lookup_label_entry`（`:75-88`） | 条目表 | 有旗 → 是 label 臂 → 端点值相等 | 回 `NULL` |
| 按订阅者查 | `lookup_sub`（`:93-105`） | 订阅表 | 有旗 → 订阅者名相等 | 回 `NULL` |

三个查找有个共同点：**先看旗，再比内容**。空槽里可能还残留着旧名字的字节（释放时 `owner` 没清），但无旗即无——旗是门，门不开，后面的字节再像也不算数。

### 1.4 为什么分配是"从 0 找第一个空位"

三种常见做法：升序首适应（本篇）、空闲链表（LIFO 复用）、哈希按名直达。DS 选第一种，两个理由：

1. **顺序即契约**：11 的镜像是原样拷表，IS 按下标读。分配顺序决定条目在表里的位置，位置决定镜像里第几个 192 字节是谁。如果改成 LIFO 复用（释放的槽下次优先），同一组条目的先后就会变，IS 的显示就悄悄错位——错还没有错误码。分配顺序必须稳定，而"从 0 找第一个空"是最稳定的确定性顺序。
2. **表太小，不值得**：128/256 个槽，线性扫最多比 256 次——常数成本。空闲链表要多维护一个表外状态，哈希要多维护桶，都属于"为小表付大复杂度"。

对照：Linux 的 IDR 用基数树分配 ID（号空间 32 位，必须动态结构）；seL4 的 capability 槽也是定长线性（和 DS 同构）；Redox 的 slab 分配定长对象（同构，但槽里直接放对象，DS 的槽和堆是分离的）。表定长 + 镜像直拷 → 首适应是最诚实的选择。

### 1.5 指针 vs 编号：Rust 为什么不回指针

C 的六个原语进出都是指针（`struct data_store *`）。Rust 改成编号（`EntrySlot` / `SubSlot`，两个类型，互不混用）：

- **借用过不了 IPC 点**：handler 拿着 `&mut` 表项去调 IPC（发通知），借用就和表的可变借用冲突——单线程也一样，这是借用规则，不是线程问题。编号是数字，随便复制，随便传。
- **编号可测序**：释放后重分配"最低位优先"（`test_free_reopens_lowest`）是可测行为；指针地址不可测、不可断言。
- **两表分币**：条目的编号进不了订阅表的函数（类型不同，编译不过），C 里传错指针只能靠小心。

### 1.6 小结

分配首适应（序即契约），释放断言+清旗（空槽释放是 bug），查找三式（门先判后），进出用编号（两表分币）。下一站 05 讲"名字从哪来、谁能碰谁的条目"。

## 2 C 源码分析

### 2.1 两个分配（`store.c:11-38`）

`alloc_data_slot`（`:11-22`）：`for (i = 0; ...)` 自 0 起，`!(flags & IN_USE)` 即空（`:17`），首空即返（`:18`），全满返 `NULL`（`:21`）。`alloc_sub_slot`（`:27-38`）同式，宽表 256。两函数除表和界外逐行对应——同式异表，各立一个，不做"通用分配器"（通用参数会把"界"这个 03 的事掺进"动"里）。

### 2.2 一个释放（`store.c:43-52`）

`free_sub_slot`：`assert(flags & IN_USE)`（`:46`，有旗方释）→ `regfree(&regex)`（`:48`，释正则）→ `memset` 清正则（`:49`）→ `flags = 0`（`:51`）。注意 `owner` 和 `old_subs` **没清**——残留但不可读（查找先问旗，§1.3）。"不清残留"不是 bug，是"门即全部"的设计：清旗就够了。

### 2.3 三个查找（`store.c:57-105`）

- `lookup_entry`（`:57-70`）：门（`:63` 有旗）→ 类型（`:64` `flags & type` 交非空——**相交**，不是相等；相等会让"多类型条目"不可表达）→ 名（`:65` `!strcmp`，NUL 止）→ 中即返（`:66`），无则空手（`:69`）。
- `lookup_label_entry`（`:75-88`）：门（`:81`）→ label 臂（`:82` `TYPE_LABEL`）→ 数值（`:83` `u.u32 == num`）→ 中即返。找的是"端点值"，不是"名字"——label 寄数字道（03 §2.4）的直接应用。
- `lookup_sub`（`:93-105`）：门（`:99`）→ 订阅者名（`:100` `strcmp(owner)`）→ 中即返。一人一席：重订阅先释旧席（10 细讲），所以结果至多一个。

### 2.4 空判定三用（`IN_USE` 一门三用）

取问空（`:17`/`:33`）、查问门（`:63`/`:81`/`:99`）、放问断言（`:46`）——同一个位，三个位置。合在一起讲比分开讲好，因为改一位三处同动。

## 3 Rust 设计决策

| # | 决策 | C 做法 | Rust 做法 | 为什么 |
|---|------|--------|-----------|--------|
| D1 | 编号代指针 | 进出皆指针 | `EntrySlot` / `SubSlot`（`slots.rs`，私域序号 + `from_index` 守门 + `get` 取体） | 除借用险、守表序、防错表（§1.5）；回 `&mut` 会卡住 IPC 点，裸 `usize` 会串表 |
| D2 | 满即 `None` | 满回 `NULL` | `alloc_*` 回 `Option<Slot>` | 满是状态（释了可再取），不是错误——状态进 `Option`，错误进 `Result`；满进 `Result` 会诱使调用方 `?` 直接返回，把"态"当"错"断 |
| D3 | 首适应保留 | 升序扫描 | `position` 自 0 起，顺序与 C 一致 | 序即契约（11 镜像），改序则 IS 误读；空闲链（LIFO 改影）和哈希（影无序）都否决 |
| D4 | 名比 NUL 止 | `strcmp` | `key_eq`（双侧遇 NUL 止后比） | 残尾不参判：80 字节全比会把旧名残尾算进去，而调用方 grant 拷的尾字节是不定的；`&str` 比会引入借用（03 D1 已否决） |
| D5 | 释放全清 | 式释 + 旗清（名图残留） | `free_sub_slot` 置 `None` + `assert!` 保留 + A-2 接点注释 | 订阅表不进镜像（镜像只拷条目表），超集清零无外部差；半清（只清旗留体）会留下"有体无门"的怪态，不如无体 |
| D6 | 类型用相交判 | `flags & type` 非零即中 | `intersects(ty)` | 与 C 逐字同义；调用方恒传单比特（07~11），单比特下相交与包含同果；`contains` 在多比特查询下会变"全有"，无体能全有——约当容后问 |
