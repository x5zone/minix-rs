## 1. 概念：控制面只传消息，不传内部指针

### 1.0 本章的读者与阅读方法

本章假设读者已经理解第 19 篇的前缀假设，知道掩码可以用前缀长度表达。本章不需要读者记住路由消息的全部类型，只需要带着三个问题来读：消息版本在什么时机检查，发送与接收的尺寸边界各是多少，为什么其它模块不得引用路由消息头与协议栈地址类型。读完本章，读者应当能够说出版本 4 的含义，发送上限 512 与接收区间 0 到 65536 的含义，以及隔离规则的内容，即使遮住所有函数名字也不影响理解。

### 1.1 版本检查在类型分发之前

路由消息头的版本字段必须为 4，否则在类型分发之前直接拒绝。这种前置检查的意义在于兼容：不同版本的消息布局不同，先确认版本再解析类型，避免按错误布局解读后续字节。源文件第 535 行的分支顺序印证了这一点：版本判断先于获取、添加、删除、修改、锁定等类型分支。Linux 内核同样在路由套接字入口先检查版本，Redox 系统在控制消息入口先检查魔数，思路一致：先认版本，再谈内容。

### 1.2 发送上限 512 是有意取小

路由发送缓冲区的最大值为 512，没有最小值与默认值，因为发送都是单条消息，不需要分档。预发送检查拒绝超过 512 的消息，发送主体用 512 字节的对齐数组做栈上缓冲。这种取小的意义在于控制面消息都很短：地址数组压缩后通常不足 512，过长的消息一定是调用者构造错误，早拒绝比截断更诚实。接收区间为 0 到 65536，默认值 16384 在创建时装入。接收下限 0 表示允许只关心发送而不接收的用法，上限 65536 与数据报接收上限同值，便于统一管理。

### 1.3 地址结构隔离是模块边界的硬性规定

源文件第 26 行附近的注释明确规定：路由消息头与协议栈地址类型是本模块独有的，其它模块不得引用。其它模块需要地址时走通用地址结构，由本模块负责压缩与展开。这种隔离的意义在于解耦：地址的内部表示变化时，只需要改本模块的压缩展开，不需要改全系统的调用点。违反隔离的代价是连锁修改，这正是注释用独有措辞强调的原因。

### 1.4 本章小结

路由套接字解决三件事：版本 4 的前置检查，发送 512 与接收 0 到 65536 的边界，地址结构的隔离规则。下一章进入 C 语言源码的逐项验证，确认每个数字都有源码依据。

## 3. Rust 设计决策

> 本章解释每个设计选择的原因，先给出依据，再列出考虑过的替代方案与放弃理由。

### 3.1 发送只保留上限（依据：第 1.2 节、第 2.2 节）

发送没有最小与默认，只有上限 512。替代方案是照搬接收的三档。放弃的理由是源文件注释明确说明不定最小与默认，照搬会虚构不存在的语义。

### 3.2 接收保留三档（依据：第 1.2 节、第 2.2 节）

最小 0，默认 16384，最大 65536。替代方案是只保留上限。放弃的理由是创建时装入默认值的行为需要默认值常量表达，否则无法测试创建语义。

### 3.3 版本采用常量加判断（依据：第 1.1 节、第 2.2 节）

版本 5 用常量记录，判断为相等。替代方案是调用者手写数字。放弃的理由是手写数字无法区分 5 是版本还是其它含义，重构时容易改错。

### 3.4 设计决策汇总

| 决策 | 依据章节 | 考虑过的替代方案 | 放弃理由 |
|------|----------|------------------|----------|
| 发送只留上限 | 第 1.2 节、第 2.2 节 | 照搬三档 | 虚构不存在语义 |
| 接收保留三档 | 第 1.2 节、第 2.2 节 | 只留上限 | 无法表达创建语义 |
| 版本常量判断 | 第 1.1 节、第 2.2 节 | 手写数字 | 含义不清，重构易错 |
