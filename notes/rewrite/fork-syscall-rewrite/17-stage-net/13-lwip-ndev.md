## 1. 概念：使用方只定边界，不碰硬件

### 1.0 本章的读者与阅读方法

本章假设读者已经理解第 03 篇的主循环分发，知道网络设备回复走独立分支进入消费侧。本章不需要读者了解网卡硬件，只需要带着三个问题来读：最多同时支持几个网卡驱动，每个驱动的发送与接收队列至少保证多深，什么情况下一个槽位算已经可用。读完本章，读者应当能够说出 8、2、2、8、40 五个数字的含义，以及活动判断的唯一条件，即使遮住所有函数名字也不影响理解。

### 1.1 槽位上限 8 是编译时确定的数组大小

消费侧用固定数组保存 8 个设备槽位，标识为 0 到 7 的整数。标识超出范围的请求不会被处理。固定数组的意义在于可预测：内存占用在编译时已知，不需要动态分配，驱动上下线只改变槽位状态，不改变内存布局。Linux 内核同样用固定上限加动态链表管理网络设备，Redox 系统把设备数量实现为启动时枚举的结果加显式上限，思路一致：数量有界，行为可测。

### 1.2 每个方向保证 2 个请求深度，外加 8 个备用

每个设备保证发送队列深度 2 与接收队列深度 2，超出保证的发送请求会被拒绝，接收请求不受此限。请求对象总数为两个方向之和乘以设备数再加 8 个备用，即 40 个。备用的意义在于初始化阶段：驱动尚未报告队列深度时，初始化请求需要占用备用对象，备用耗尽则初始化排队等待。这种分层保证的意义在于隔离：一个驱动的突发流量最多占用自己的保证深度加共享备用，不会饿死其它驱动。

### 1.3 活动判断只看发送队列是否公布深度

槽位是否可用只看一个条件：发送队列的最大深度是否大于 0。驱动初始化回复到达并报告队列深度后，槽位变为活动，此后才能附加接口对象。在此之前，槽位处于跟踪状态：初始化请求已经发出但回复尚未到达，消费侧记录驱动端点与标签，但不创建接口。这种两阶段的意义在于时序：驱动进程可能先于协议栈就绪，也可能晚于协议栈就绪，跟踪状态保证无论哪种时序都不会丢失驱动。

### 1.4 配置请求的空标志有明确含义

配置请求允许不带任何设置标志，这种请求不是空操作，而是一次显式的无更改确认，用于探测驱动是否存活。发送队列满时配置请求同样排队，队列管理函数保证非接收请求的入队检查与出队检查使用同一阈值，避免入队时允许、出队时又拒绝的不一致。接收数量超过保证时钳制到保证值，防止驱动报告的过大数字撑满服务内存。

### 1.5 本章小结

消费侧解决三件事：槽位上限 8 与请求总数 40 的容量规划，每个方向深度 2 的隔离保证，活动判断只看发送队列是否公布深度。下一章进入 C 语言源码的逐项验证，确认每个数字与每个分支都有源码依据。

## 3. Rust 设计决策

> 本章解释每个设计选择的原因，先给出依据，再列出考虑过的替代方案与放弃理由。

### 3.1 上限与保证采用具名常量，总数用公式表达（依据：第 1.1 节、第 1.2 节、第 2.2 节）

8、2、2、8 各有一个名字，总数 40 用公式算出，而不是手写 40。替代方案是五处手写数字。放弃的理由是手写数字无法表达总数等于两方向之和乘以设备数加备用的关系，一处改动会漏掉另一处，而公式让编译器保证一致。

与 Redox 的对比：Redox 的设备上限同样用具名常量加公式，而不是裸数字。与 Linux 的对比：Linux 用配置宏表达队列深度，本文的常量是同一思路的纯函数形式。

### 3.2 活动判断采用单条件函数（依据：第 1.3 节、第 2.2 节）

发送队列最大值大于 0 即活动。替代方案是检查多个字段。放弃的理由是源文件用宏明确定义了唯一条件，增加条件会改变语义，违反外部行为不变原则。

### 3.3 容量判断区分接收与非接收（依据：第 1.2 节、第 2.3 节）

接收请求永远允许排队，非接收请求受保证深度限制。替代方案是不区分类型统一限制。放弃的理由是统一限制会误拒接收请求，改变源文件的行为。

### 3.4 钳制采用取小函数（依据：第 1.4 节、第 2.4 节）

驱动报告值与保证值取较小者。替代方案是直接信任驱动报告。放弃的理由是恶意或故障驱动可能报告巨大数字，直接信任会撑满服务内存。

### 3.5 设计决策汇总

| 决策 | 依据章节 | 考虑过的替代方案 | 放弃理由 |
|------|----------|------------------|----------|
| 常量加公式 | 第 1.1 节、第 2.2 节 | 五处手写数字 | 无法表达加和关系 |
| 活动单条件 | 第 1.3 节、第 2.2 节 | 检查多个字段 | 改变原始语义 |
| 容量区分类型 | 第 1.2 节、第 2.3 节 | 统一限制 | 误拒接收请求 |
| 钳制取小 | 第 1.4 节、第 2.4 节 | 信任驱动报告 | 故障驱动撑满内存 |

## 4. 错误处理

| 场景 | C 语言行为 | Rust 表达 | 说明 |
|------|------------|-----------|------|
| 设备标识达到 8 | 请求不处理 | 标识函数返回假 | 槽位外不接受 |
| 非接收队列已达保证深度 | 拒绝入队 | 容量函数返回假 | 超出保证不排队 |
| 驱动报告接收最大值过大 | 钳制到保证 2 | 钳制函数返回保证值 | 过大不信任 |
| 槽位尚未活动 | 配置断言失败 | 活动函数返回假，调用者不得下发配置 | 未活动不配置 |
