## 1. 概念：胶水加补丁等于可用的第三方栈

### 1.0 本章的读者与阅读方法

本章假设读者知道第三方代码需要胶水才能融入构建，不需要了解协议算法。本章只需要带着四个问题来读：编译子集有多大，关键选项是哪几个，服务向栈提供哪 4 个钩子，应用了哪 4 个补丁。读完本章，读者应当能够说出 68、58232、1460、16384、11 倍四个数字的含义，4 个钩子的名称，以及 4 个补丁的主题，即使遮住所有文件名字也不影响理解。

### 1.1 编译子集只取核心、网际协议与网络接口三组

第三方目录按原样引入，编译时只取核心、版本 4、版本 6、网络接口 4 组共 68 个文件 58232 行。套接字、网络连接、邮箱、线程、同步、保护等上层支撑一律不用，定时器由协议栈自己管理。这种只取核心的裁剪意义在于依赖最小：服务自己实现套接字层，只借协议与接口层的算法，不引入线程模型，避免两套并发原语打架。Linux 内核同样按需裁剪第三方代码，Redox 系统引入第三方协议栈时同样只取无操作系统依赖的核心，思路一致。

### 1.2 关键选项决定内存模型与缓冲尺寸

单线程无系统层、轻量保护关闭、池分配器尺寸 0（改用定制内存池）、缓冲池切片 512、最大分段 1460、接收窗口 16384、发送缓冲 11 倍分段。这些选项的意义逐条可查：无系统层保证不引入线程，池尺寸 0 保证不走通用分配，窗口与发送缓冲决定吞吐与内存占用的折中。发送缓冲 11 倍分段的注释用一整段推导了队列长度公式，说明 11 不是随意取值，而是按最大分段报文的头部加链式缓冲算出的。重写后的 Rust 栈必须守住这些数字：窗口 16384 与发送 11 倍分段已经出现在第 08 篇的边界常量中，改动此处必须同步改动彼处。

### 1.3 服务向栈提供 4 个钩子

序列号生成、版本 4 路由覆盖、版本 6 路由覆盖、网关查询（含地址解析与邻居发现共用一项）。钩子是栈留给服务的影响点：栈在需要序列号、选路、网关时回调服务，服务用自己的表回答。这种反向依赖的意义在于策略集中：算法在栈，策略在服务，换栈时只要新栈提供同样的钩子点，服务侧不用改。测试逐个断言 4 个钩子俱全，缺一即暴露。

### 1.4 补丁 4 个，主题分别是弱符号、转发开关、路由通告忽略、大分配避免

弱符号补丁把若干函数标记为弱符号，服务才能覆盖选路。转发开关补丁把转发判断改成运行时可调。路由通告忽略补丁让服务决定是否接受路由通告。大分配避免补丁禁止超过固定长度的连续分配，配合定制内存池的链式缓冲模型。补丁按目录顺序列出，名字即主题，重写后不再需要补丁，但需要保留等价行为：弱符号对应 Rust 的特征覆盖，转发开关对应运行配置，大分配避免对应链式分配不变式。

### 1.5 替代裁决：smoltcp 一族的 Rust 栈加自研语义垫片（2026-09-17）

[ARCH N-1]：本节把"候选中"推进为裁决。三条候选路线的完整对比是本节的核心，先给结论再给依据。

**裁决**：选成熟 Rust 栈（smoltcp 一族，0.14 版，2026 年 8 月发布）加自研语义垫片。服务到栈之间立一道墙——`os/net/lwip/src/lwip_port.rs` 的 `Stack` 与 `StackHooks` 两个 trait——服务代码只依赖这道墙，墙后换任何栈（含回退 FFI 路线）服务侧零改动。

三条路线的对比：

| 路线 | 行为正确性的来源 | 必付的代价 | 判定 |
|------|------------------|-----------|------|
| 外层保留 C，FFI 绑定 liblwip 逐层替换 | 被执行的代码即行为真值 | 构建链要在 cargo 里复刻 `Makefile.inc` 的选文件逻辑；4 个补丁改写为构建期变换；C 回调 Rust 需要蹦床；58232 行 C 以"临时"名义长期在树——逐层替换路线在内核史上极少走完 | 否决：代价确定且永久，收益局限于协议细节 |
| **成熟 Rust 栈加语义垫片（裁决）** | wire 行为取 RFC 级一致（smoltcp 自带测试套件，embassy-net 与 Redox smolnetd 是操作系统级部署先例）；socket 行为本来就写在我们自己的 sock 模块里 | 语义垫片是真实工作量：Redox 的经验是端口分配、accept 语义、SO_* 选项全部自己写（redox-os/netstack 的 `port_set.rs` 与 SettingFile 先例）；MINIX 特有面两条路线都得自研（见下表） | 裁决 |
| 自研精简栈 | 无 | 58232 行行为契约需要在合理轮次内逐条重推导与复验，逐字翻译风险全场最高 | 否决：负价值的重复发明 |

裁决成立的关键证据是**偏差面比直觉小**。逐特性面对照（C 侧事实全部来自 `lwipopts.h` 与 `lwiphooks.h`，已 grep 实证）：

| MINIX3 特性面 | C 侧事实 | smoltcp 0.14 现状 | 落位 |
|---------------|----------|-------------------|------|
| tcp/udp/raw/icmp 四族 socket | `NETCONN=0`/`SOCKET=0`（lwipopts.h:401-402），服务走 pcb 级回调 | 四族原生 socket | 语义垫片：窗口 16384 与发送 11 倍分段在构造期定容 |
| 组播 | `LWIP_IGMP=1`（lwipopts.h:201）；64+64 全局上限与每 socket 8 个在 mcast.c | 原生 IGMP 加入/离开；上限由我们强制 | mcast.c 语义原样保留 |
| DHCP | `LWIP_DHCP=0`（lwipopts.h:189），DHCP 在用户态跑 | 有 DHCPv4 但我们不用 | 无 |
| keepalive | `LWIP_TCP_KEEPALIVE=1`（lwipopts.h:404） | 原生可配置 | 垫片 |
| SACK、时间戳、紧急指针 | lwIP 没有 SACK；时间戳与紧急未配置，且 `tcpsock.c`/`lwip.h`/libc 头 grep 零引用 | 同样没有 | **零偏差**：直觉以为的差异并不存在 |
| pktsock、bpfdev、rtsock、ifconf | 服务自有 `.c`（链路帧直收发、BPF 解释器、路由变更广播、ioctl 面） | 全部无对应 | 两条路线都自研——不是选型差异项 |
| IPv6（scope、4 地址、转发） | `LWIP_IPV6=1` 加 `IPV6_FORWARD=1`（lwipopts.h:446/:479） | 原生 IPv6/NDP/SLAAC；转发在我们设备层做（补丁 0002 的等价物） | 垫片 |
| ISN 注入点 | `lwip_hook_tcp_isn`（minix3/minix/lib/liblwip/lib/lwiphooks.h:lwip_hook_tcp_isn），服务持有随机源 | smoltcp 内部生成，不可注入 | **唯一实现差异**：ISN 具体值不是行为契约（每次连接本就不同），不可预测性由栈内熵承担；墙保留钩子位，服务随机源随时可回接 |
| 路由与网关 | 路由覆盖钩子的契约是"被调用即 panic"（minix3/minix/lib/liblwip/lib/lwiphooks.h:LWIP_HOOK_TCP_ISN（L15，工具生成） 与 :31）——路由真相在服务的 route.c | smoltcp 有内部路由表 | 架构关键：服务表仍是唯一权威，适配层在路由变更时向栈同步；墙上只留网关解析钩子 |

墙的职责用三句话固定：路由决策、时间源（毫秒，对齐 `sys_now`）、设备都在服务侧；帧只沿"接口进来、接口出去"一个方向穿越；错误一律返回 `util.rs` 的 `STACK_*` 线上值（N-14 双射表的栈侧半边）。本裁决是内部实现选择，外部行为保持 MINIX3 等价；若评审倾向先 FFI 保真，在墙后插一个 C 适配器即可，服务代码零改动——这是把"否决点"留给人评审而不是写死在代码里。

### 1.6 本章小结

移植面解决五件事：68 个文件 58232 行的子集规模，关键选项的数字与含义，4 个钩子的清单，4 个补丁的主题，外加替代栈的裁决与那道把裁决变成可回退结构的墙。下一章进入 C 语言源码的逐项验证，确认每个数字都有源码依据。

## 3. Rust 设计决策

> 本章解释每个设计选择的原因，先给出依据，再列出考虑过的替代方案与放弃理由。

### 3.1 规模用常量记录（依据：第 1.1 节、第 2.1 节）

68 个文件 58232 行用常量记录。替代方案是不记录规模。放弃的理由是不记录时子集漂移无人发现，替换进度无法衡量。

### 3.2 选项用常量映射（依据：第 1.2 节、第 2.2 节）

6 个关键选项各有一个常量。替代方案是只在文档写数字。放弃的理由是文档数字无法被测试，代码常量可以被断言，漂移立即暴露。

### 3.3 钩子用四变体枚举（依据：第 1.3 节、第 2.1 节）

4 个钩子各为一个变体。替代方案是用字符串。放弃的理由是字符串无穷举检查，新增钩子时编译器不会提醒。

### 3.4 栈墙用 trait 而不是具体类型（依据：第 1.5 节）

`Stack` 与 `StackHooks` 两个 trait 构成服务唯一依赖的栈面。替代方案一是服务直接依赖具体栈类型——放弃的理由是裁决从"候选"变"定案"靠的是证据而非教条，保留可回退结构让证据变化时代价最小；替代方案二是墙后先留空、等实现落地再抽 trait——放弃的理由是服务代码（第 03 篇的分发路、第 08 篇往后的各 sock 模块）马上就要开工，先立墙才不会有代码越墙。骨架期的墙只含 pump、就绪与最小生命周期，逐家族操作与数据面随缓冲轮次补齐，签名上标注了这一点。

### 3.5 设计决策汇总

| 决策 | 依据章节 | 考虑过的替代方案 | 放弃理由 |
|------|----------|------------------|----------|
| 规模常量 | 第 1.1 节、第 2.1 节 | 不记录规模 | 漂移无人发现 |
| 选项常量映射 | 第 1.2 节、第 2.2 节 | 只在文档写数字 | 无法被测试 |
| 钩子枚举 | 第 1.3 节、第 2.1 节 | 字符串 | 无穷举检查 |
| 栈墙 trait | 第 1.5 节 | 直接依赖具体栈；后置抽墙 | 证据变化时代价大；服务开工前必须有墙 |
