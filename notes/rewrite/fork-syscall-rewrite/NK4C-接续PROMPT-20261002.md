## 一、这个项目在做什么，你要达成什么（三终目标）
`minix-rs` 是把 Minix3 微内核用 Rust（x86_64 / aarch64 / riscv64 三架构，`#![no_std]`）做的**语义重写**：
保持对外行为一致，内部用 Rust 类型系统。三条最终目标：

1. **三架构启动标记**：x86_64 / aarch64 / riscv64 各自从串口打印出
   `minix-rs rc: minimal boot script marker` 这一行，算作「跑到了最小启动脚本」。
   现状：x86_64 ✅、aarch64 ✅、**riscv64 ❌，只差一个叫 (A) 的缺陷**。
2. **18-stage 命令面**：echo / ls / cat 走真实 VFS 的 IPC 全跑通。现状：仅 x86_64 核心 ✅。
3. **586 个 minix3 的 C 测试上机跑通**：把原 Minix3 的 C 语言测试真正在我们的 OS 上运行。
   现状：已能从零搭到「一批测试能链成可加载的 riscv64 ELF」，但还没真正跑起来（依赖 (A) 解除）。

**(A) 是目标① riscv 标记 和 目标③ riscv 上机 的共同关键路径**，所以 (A) 是最高优先。

## 三、(A) 到底是什么，现在推进到哪
**症状**：riscv64 启动过程中，VM（虚拟内存服务器进程，用户态）在遍历页表时崩溃——串口打
`pagefault for VM sepc 0x3abec stval 0x10bd28cb2c`，随后内核在
`os/kernel/src/trap_dispatch.rs:1991` 的 `panic!("pagefault in VM")` 停机。这一崩在同一个二进制上
**确定复现**（不需要 gdb 也会崩），是 riscv 到不了 marker 的唯一阻塞。

**已用零扰动手段钉死的事实**（本会话 §续-238/239）：
- 崩溃指令是 `os/arch/src/riscv64/paging.rs` 里 `walk_read` 遍历 Sv39 三级页表时读一级表项的那条
  `ld`（`paging.rs:326`，反汇地址 0x3abec）。
- 真正被写坏的是**上一级（L2）页表项本身**：子进程（进程号 0x800c，即 exec 出来的 /etc/rc 那个）
  页表根 `0x9dc37000` 里、第 `i2 = 255` 项那个 8 字节槽。它被写成了一个**数据字**而不是合法页表项，
  所以 `walk_read` 把它当页表基址解出来后算出一个越界的调试底图虚拟地址去读，触发缺页。
- 关键判据：崩溃地址的页内偏移 `off = 0xb2c` 不是 8 的倍数。合法页表项解出的表基址必然 4K 对齐、
  槽偏移必然是 8 的倍数；出现非 8 对齐，说明那个槽里装的是被当作数据的值——即**同一个物理帧既被当
  页表用、又被旧数据引用方写踩**（帧级 页表/数据 双别名）。
- 被写坏的槽**不在 VM 自己的页表根**里（`0x82000000`，之前 §续-195 用 512MB 内存快照从它 breadth-first
  遍历 22 张级联表全部干净），**只在子进程 0x800c 的根**（`0x9dc37000`，§续-229 探针实测）。

**⇒ 要抓真凶，唯一的物理地址靶 = `0x9DC377F8`**（= 子根 `0x9dc37000` + 255×8）。对它设**硬件写
观察点（watchpoint）**，程序第一次把这个数据字写进该槽时就会停，停下来时的 PC 就是写者、回栈就是来源。
静态分析和内存快照都抓不到这个「写入瞬间的瞬态值」，所以硬件写观察点是剩下的唯一能定谳的手段。

## 五、已经排除的死路（千万不要重走，否则浪费一整轮）
- ❌ 「页表帧分配器双重发放 / refcount 漏计」：gh72/gh73 真机的可信检测器
  （`ptalloc-DUP=0`、`alloc-reuse-PT=0`、`dblfree=0`、`OOR/BADPFN=0`）全为 0，静态审计对照 C 真源
  （`minix3` 的 pagetable.c / alloc.c / cache.c）也一致 ⇒ 在 `alloc_pfn_reclaiming`/`vm_pt_alloc` 里加
  「拒发 live 帧」是**空修/幻影**，勿做。
- ❌ 「崩溃寄存器里的 `0x00fffffffffff000` 是寄存器被破坏」：那其实是 `query` 正常算出的
  `PTE_PPN_MASK<<2` 掩码，不是破坏。
- ❌ 「纯算术 bug」：`walk_read` 的算术完全正确，它只是如实解码了一个已经被写坏的上级页表项。
- ❌ 「resume-Fault / 自填 / 走错根」整族（§续-139~190 追的链）：gh61 正证据判死，是幻影。
- ❌ 「paging.rs 里的 U 态 SBI ecall」：那是**另一个真 P0**，但**已经修掉了**（commit `f90416cc9`），
  现在 (A) 才是裸露出来的原始缺陷。
- ⚠️ 「歧义检测器 reuse-DATA」命中很多，但它因 VM 堆旁路 `DATA_SEEN` 而系统性假阳，**不能单独定谳**
  （记忆：调试陷阱 reuse-DATA 不可作定谳依据）。它只是提示了 页表/数据 同帧的方向。
- ⚠️ 「纯文本探针定帧（a2d）」：实测加探针会扰动时序反而让 (A) 本轮不复现（Heisenbug），已回滚。
