# 06 — 信号量原子操作：要么全做，要么全不等

> **状态**: 已改写（2026-09-05，依据 plan.md 阶段 3 操作语义边界从零写作）
> **定位**: 阶段 3 信号量之操作语义（查表分发命中 `IPC_SEMOP` 时发生什么；主循环挂起后由重试与进程事件恢复）
> **源码**: `minix3/minix/servers/ipc/sem.c` 第 6 行到第 14 行（等待槽位表）、第 163 行到第 250 行（挂起计数与完成）、第 294 行到第 429 行（试执行与重试）、第 654 行到第 779 行（操作入口）、第 866 行到第 888 行（进程事件取消）
> **Rust 模块**: `os/servers/ipc-server/src/sem/op.rs`（试执行、重试、入口校验）、`os/servers/ipc-server/src/sem/waiter.rs`（等待记录与完成）
> **说明**: 一次信号量操作包含多个子操作，语义要求"要么全部生效、要么一个都不生效"；条件不满足时调用者挂起等待，以后被叫醒。本篇讲原子性怎么做、挂起后住在哪里、三种叫醒路径。集合表的事情是 05 的，订阅机制是 09 的，本篇只讲操作。

## 1 概念

### 1.1 目标读者与前置知识

面向已经读过 04 与 05 篇的读者。前置知识：04 篇的操作掩码，05 篇的集合表与删除四幕。原子性是什么不需要预习——可以把它理解成"一组动作不可分割：中途任何一步走不下去，前面走过的全部作废"。挂起是什么不需要预习——"条件不满足时先睡，等条件可能满足时再试"。

### 1.2 本篇不讲什么

- 集合的创建、查找、删除、控制命令——那是 05 的事情（本篇假设集合已经在表里）。
- 权限判断的内部规则——那是 04 的事情（本篇只引用掩码结论）。
- 订阅开关的执行——那是 09 的事情（本篇只讲等待记录的取消，不讲订阅的建立）。
- 撤销语义——Minix3 明确不支持（遇到撤销标志直接回参数错误，plan A-7 契约）。

### 1.3 为什么原子性值得单独成篇

一个刚接触实现的读者最容易犯的错误，是把"原子执行"理解成"加一把锁"。其实这里的原子性不用锁——单线程事件循环同一时刻只做一件事，天然没有并发穿插。真正的难点是"乐观执行加失败回滚"：按数组顺序一个个试做，中途卡住就把前面做的全部撤销，记住卡在哪一步，然后挂起。以后每次值变化（设值命令、别的操作成功、删除）都把等待队列从头到尾重试一遍，直到某一轮无人被叫醒。

把操作语义单独抽出来有两个好处。第一，05 篇的表管理可以完全不提挂起，两篇各做一件事。第二，挂起的三条唤醒路径（值变重试、删除叫醒、进程事件取消）一次讲清，09 篇的进程事件处理只需引用本篇的取消函数。Redox 操作系统的阻塞系统调用也是这个形状：调用者在条件上睡眠，条件生产者负责叫醒——睡眠与叫醒分属两端，中间是显式的等待记录。

### 1.4 一次操作进门的完整旅程（以条件暂不满足为例）

```
1. 用户进程：发起操作请求（集合标识符、操作数组地址、个数）
  → 2. 入口校验：集合存在、个数非零且不超一百、数组拷贝成功、
     权限掩码通过、序号不越界、无撤销标志（任一步不过即回错误码）
  → 3. 试执行：按数组顺序乐观试做，卡在某一步（值不够或非零）
  → 4. 挂起：把数组、进程身份、卡住位置存入该进程的等待槽位，
     挂到集合的等待队列尾，进出计数加一，主循环不回信（挂起标记）
  → 5. 以后：某次设值或别的操作成功触发重试，本操作重跑通过，
     出队、计数减一、释放数组、补发成功回信
```

注意第 4 步里面的"进出计数"：每个信号量记着"多少人在等它变零、多少人在等它增长"，`ipcs` 命令能看到这两个数（05 篇的取值命令读它们）。挂起时加、叫醒或取消时减——计数与队列成员严格对应，这是本篇的不变量之一。

### 1.5 小结

操作语义由六部分组成：入口校验七步、试执行与回滚、等待槽位表、重试循环、完成与回信、进程事件取消。记住这六部分，09 篇的事件处理与 05 篇的设值唤醒都只是调用本篇的函数。

## 2 C 源码分析

### 2.1 等待槽位表逐项核对（`sem.c` 第 6 行到第 14 行）

| 字段 | C 类型 | 含义 |
|------|--------|------|
| `ip_sem` | 集合指针（可空） | 挂起在哪一个集合上；空表示该槽位闲置（单挂起不变量：非空即挂起中） |
| `ip_sops` | 操作数组指针（堆分配） | 挂起的操作数组副本（入口处拷贝，完成后释放） |
| `ip_nsops` | 无符号整数 | 数组元素个数 |
| `ip_blkop` | 数组内指针 | 卡住的那一步（重试时若卡点变化则迁移计数） |
| `ip_endpt` | 端点 | 等待进程的端点（回信用） |
| `ip_pid` | 进程标识 | 等待进程的标识（试执行成功时写入各信号量） |
| `ip_next` | 队列链接 | 挂在集合等待队列里的前后链 |

表长等于进程上限（`iproc[NR_PROCS]`），槽位下标等于端点的槽位号（第 751 行断言下标合法）。一个进程同时只能挂起一个操作（第 755 行断言槽位闲置）——**单挂起不变量**，plan A-2 记为类型系统表达点。

等待队列是每集合一条的双向尾队列（第 23 行到第 38 行注释讲透选型：先进先出保公平、尾部插入、双向链为常数时间删除；按集合分队列而非按单个信号量分，因为等待者数量不值得更细的复杂度）。

### 2.2 入口校验七步逐项核对（`do_semop`，第 654 行到第 779 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 找集合 | 第 667 行到第 668 行 | 按标识符查找，找不到回参数错误 |
| 个数检查 | 第 670 行到第 673 行 | 个数为零直接回成功（无事可做）；超过一百回单次太多 |
| 拷贝数组 | 第 676 行到第 682 行 | 堆分配加内核拷贝；分配失败回内存不足；拷贝失败释放后回错误码 |
| 权限掩码 | 第 697 行到第 706 行 | 组装掩码（有非零操作则写位，否则读位），不过回访问拒绝；注释写明只查一次（挂起期间改权限不重查，规范本身没讲清，两可，C 选一次） |
| 序号越界 | 第 709 行到第 712 行 | 任一序号超集合大小回序号太大 |
| 撤销排除 | 第 730 行到第 739 行 | 任一标志带撤销则回参数错误（测试集魔数除外，见下） |
| 试执行与分流 | 第 742 行到第 778 行 | 试执行；挂起则入队（2.5 节）；成功则顺带重试队列；失败释放后回错误码 |

撤销检查里的测试集魔数（第 733 行）：标志恰好等于短整数最大值时不打印警告——测试套件的探针值，只认不吵。行为一致：照样回参数错误。

内存分配失败（第 677 行到第 678 行）在 Rust 侧无直接对应（分配器模型不同），行为契约记入 99（plan A-4 依赖面）。

### 2.3 试执行与回滚逐项核对（`try_semop`，第 294 行到第 373 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 正操作 | 第 318 行到第 323 行 | 加后超 32767 则回超范围；否则累加 |
| 负操作 | 第 324 行到第 334 行 | 值不够减则按标志回（非阻塞回暂不可用，否则挂起）；够则累减。与正操作不同，负操作不做超范围预检——注释写明是故意的：进程可以用负最大值把自己永久卡住，这是它的自由 |
| 零操作 | 第 335 行到第 341 行 | 值非零则按标志回（同上）；为零则无事发生 |
| 回滚 | 第 350 行到第 360 行 | 未走完则交出卡点、逐个减回已做增量、回错误或挂起 |
| 落定 | 第 367 行到第 372 行 | 走完则各信号量记最后进程、刷新操作时间，回成功 |

三个细节值得记住：第一，数组顺序有语义（注释第 302 行到第 311 行）：同一信号量出现多次时，前面的增量后面的减法看得见——"原子增加若零"这类组合靠它实现，所以不能乱序执行。第二，负操作允许下溢（注释第 325 行到第 328 行）：进程想用负数把自己卡死是它的自由。第三，回滚用减法逆运算（第 356 行）——加法与减法互逆，所以"撤销"就是"反向再做一遍"，这是乐观执行可行的数学基础。

### 2.4 重试循环逐项核对（`check_set`，第 381 行到第 423 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 外层驱动 | 第 393 行到第 422 行 | 只要上一轮叫醒过至少一人就再扫一轮（有人进展就可能有连锁进展） |
| 逐个重试 | 第 396 行到第 421 行 | 按队列顺序把每个等待者的整组操作重跑一遍（原子地） |
| 成功或失败 | 第 401 行到第 407 行 | 非挂起则完成（成功才算进展）；失败不改任何值（试执行的回滚保证） |
| 卡点迁移 | 第 408 行到第 420 行 | 仍挂起但卡点变了：旧信号量计数减一、新信号量计数加一、更新卡点 |

重试的触发者：设值两命令成功后（05 篇 2.5 节）、别的操作成功后（本篇 2.2 节收尾）、删除时不走重试（直接全叫醒，05 篇 2.4 节）。重试本身不产生新挂起（重跑卡住就地留下），只减少等待者。

### 2.5 挂起计数与完成逐项核对（第 163 行到第 244 行）

| 函数 | 位置 | 行为 |
|------|------|------|
| 加计数 | 第 163 行到第 178 行 | 按卡点操作是否为零加等零或等增长计数（上限断言） |
| 减计数 | 第 185 行到第 200 行 | 对应减一（非零断言） |
| 发信 | 第 207 行到第 215 行 | 清零消息、填回信码、非阻塞发送（失败不处理） |
| 完成 | 第 223 行到第 244 行 | 出队、减计数、释放数组、清槽位；回信码非抑制标记则发信 |

发信失败不处理（第 214 行无视返回值）——叫醒信发不出去多半是对端已消失，计数的账已经结清，不值得重试。抑制标记（`EDONTREPLY`，数值 203）用于进程退出场景：进程都没了，回信无意义（2.6 节）。

### 2.6 进程事件取消逐项核对（`sem_process_event`，第 866 行到第 888 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 定位槽位 | 第 871 行到第 874 行 | 端点槽位号取槽；断言合法 |
| 未挂起则返 | 第 877 行到第 878 行 | 槽位空闲说明没在等，直接返回 |
| 身份核对 | 第 880 行 | 槽位端点必须等于事件端点（断言） |
| 取消 | 第 887 行 | 已退出则抑制回信（进程已死），被信号打断则回中断 |

退出与信号的差异：退出（进程已死）用抑制标记（不发信），信号打断（进程还活着）回中断（进程的等待调用以中断错误返回）。09 篇的订阅机制把事件送到这里，本篇只管取消。

## 3 Rust 设计决策

| 编号 | 决策 | C 做法 | Rust 做法 | 为什么这样做 |
|---|------|--------|-----------|--------|
| D1 | 等待槽位变 Option | 空指针表闲置（`ip_sem == NULL` 散写断言） | `slots: [Option<Waiter>; 256]`，下标由端点槽位号算（`waiter.rs`） | 单挂起不变量变类型（plan A-2）：闲置不可表达成"有等待"，`assert` 变构造；槽位数复用 `NR_PROCS` 常量 |
| D2 | 试执行变草稿提交 | 原地乐观改加失败回滚（第 312 行到第 360 行） | 草稿数组上试做，成功才整体提交（`op.rs`） | 可观察行为一致（要么全做要么全不做），但无中间态可错：回滚逻辑（逆运算）整段消失，少一类"回滚不彻底"缺陷；加减互逆的数学基础写进注释 |
| D3 | 试结果变枚举 | 整数码加输出参数（`blkop` 指针输出） | `TryOutcome::{Done, Suspend{blocked_on}, Failed(SemError)}`（`op.rs`） | 三种出口各有名字；卡点是下标不是指针（数组重分配不悬空）；调用者匹配分支，漏分支编译不过 |
| D4 | 唤醒名单变返回值 | 完成函数内直接发信（第 242 行） | `complete` 返回 `Wake { endpoint, code }` 或空（抑制时）（`waiter.rs`） | 发信是传输效应；05 的删除产出的名单与本篇同构（同为端点加回信码）；抑制标记变空值（02 篇的"不回信"语义延续） |
| D5 | 入口校验变管道 | 七步散写一函数（第 667 行到第 778 行） | `validate(entry) -> Result<ValidatedOp, SemError>` 纯函数（`op.rs`） | 每步的错误码独立可测（个数、掩码、越界、撤销各一测）；拷贝与分配留边界（D6）；只查一次权限的注释变文档 |
| D6 | 拷贝分配留边界 | 入口内堆分配加内核拷贝（第 676 行到第 682 行） | 操作数组由调用者备好传入（`Vec<SemOp>` 参数） | 传输与分配是边界效应；内存不足在 Rust 分配器模型下另议（99 契约）；逻辑可单测 |
| D7 | 重试变纯循环 | 队列就地改加计数回调（第 393 行到第 422 行） | `retry(set, waiters) -> Vec<Wake>`（`op.rs`） | 输入输出皆值：测试可构造"两人在等，一人能走"的场景断言名单；卡点迁移的计数调整在值上表达 |

微内核对照（类比，不是移植依据）：Redox 的阻塞读同样把等待者挂在显式队列上、由数据生产者叫醒——睡眠端与叫醒端通过等待记录解耦，与本篇 D1/D4 同构。seL4 的通知位图是另一种形状（不等队列、只记"有人叫过"），不适合这里（信号量等待要按序重试整组操作，必须留数组）。

替代方案及否决：保留原地改加回滚的直译——否决，因为回滚的正确性依赖"每步可逆"的隐含前提（正操作溢出检查先行、负操作下溢允许都是为可逆服务的），直译会把三处 subtle 前提一起搬过来；草稿提交把前提从"代码小心"变成"结构保证"。

## 4 实现详解

### 4.1 模块结构

```
os/servers/ipc-server/src/sem/
  op.rs           — 操作项、试执行、重试、入口校验（本篇 D2、D3、D5、D7 的落地）
  waiter.rs       — 等待记录、槽位表、完成与取消（本篇 D1、D4 的落地）
```

05 的 `table.rs` 持有集合数据与等待队列成员关系，06 的 `waiter.rs` 持有槽位表——两表在服务层会合（05 的删除产出名单，本篇的完成消费记录）。

### 4.2 关键类型与函数

**操作与试执行**（`op.rs`）：

- `SemOp { num: u16, op: i16, flag: u16 }`：对应 C 的 `sembuf`（序号、操作、标志）。
- `TryOutcome` 枚举：`Done`（全做完）、`Suspend { blocked_on: usize }`（卡点下标）、`Failed(SemError)`。
- `try_ops(values: &mut [u16], ops: &[SemOp], pid: i32, now: u64, times) -> TryOutcome`：2.3 节的逐行对应（正操作超范围、负操作不足、零操作非零、落定记进程与时间），草稿语义由调用者保证（函数内先拷草稿再提交，或调用者给草稿）。
- `validate(count, ops, perm, identity) -> Result<(), SemError>`：2.2 节七步中的纯判断部分（个数、掩码、越界、撤销）。
- `retry(set, queue) -> Vec<Wake>`：2.4 节的外层驱动加逐个重试加卡点迁移。

**等待与完成**（`waiter.rs`）：

- `Waiter { endpoint, pid, ops: Vec<SemOp>, blocked_on: usize }`：对应 C 的 `iproc` 槽内容（去队列链，队列用 `VecDeque<usize>` 存槽号）。
- `WaiterTable { slots: [Option<Waiter>; 256] }`：对应 `iproc` 数组；`park`（入队，断言闲置）、`cancel(endpoint, exited) -> Option<Wake>`（2.6 节：退出抑制、信号回中断）。
- `complete(slot) -> Option<Wake>`：2.5 节的出队、减计数（计数由集合侧维护，见 4.3）、释放、发信名单。
- `Wake { endpoint, code }`：与 05 的唤醒名单同构。

### 4.3 关键不变量

- 单挂起：每槽至多一个等待（`park` 前断言闲置，`Option` 表达）。
- 计数与队列对应：等零与等增长计数之和等于队列成员数（测试构造场景断言）。
- 卡点恒指数组内：迁移时下标合法（测试非法下标拒绝）。
- 抑制不发信：退出取消产出空（测试断言名单为空）。
