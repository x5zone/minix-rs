> **定位**: 阶段 3 信号量之表管理（查表分发命中 `IPC_SEMGET` 与 `IPC_SEMCTL` 时发生什么）

## 1 概念

### 1.1 目标读者与前置知识

面向已经读过 02 与 04 篇的读者。前置知识：02 篇的信号量三组消息字段，04 篇的权限掩码表。信号量是什么不需要预习——可以把它理解成"进程之间用来互斥与同步的计数器"，集合就是"一组放在一起管理的计数器"。标识符编码（高十六位序号、低十六位下标）在用到时用一句话解释，完整规则在 99。

### 1.2 本篇不讲什么

- 信号量操作怎么原子执行、挂起后谁唤醒——那是 06 的事情。
- 进程事件的订阅机制——那是 09 的事情（本篇只讲"第一个集合诞生时打开订阅、最后一个集合消失时关闭订阅"这两个调用点）。
- 管理信息库子树的结构——那是 03 的事情（本篇只讲组装函数往分发点交什么数据）。
- 权限判断的内部规则——那是 04 的事情（本篇只引用掩码结论）。

### 1.3 为什么表值得单独成篇

一个刚接触实现的读者最容易犯的错误，是把"创建集合"理解成一句话"分配一块内存"。其实集合的生命史有五幕：找空槽、填身份、定序号、挂等待队列、登记订阅。删除也有四幕：唤醒等待者、清分配位、收缩高水位、可能关闭订阅。查找有两种（按键、按标识符），信息查询有两种（概要、明细），控制命令有十三个。

把表管理单独抽出来有两个好处。第一，06 篇的操作语义可以假设"集合已经在表里、标识符已经验过"，只关心值怎么变、什么时候挂起——两篇各做一件事，读者可独立阅读。第二，表的容量上限（十个集合、每集合六十个信号量）与序号防重用机制是全篇的隐含前提，一次讲清，后面不再重复。Redox 操作系统的资源表也是这个形状：固定槽位数加占用位加序号防重用——有限表加序号是微内核管理有数对象的通用做法，不是 Minix3 的特殊癖好。

### 1.4 一个集合的完整生命史（以创建、使用、删除为例）

```
1. 创建：用户进程发起创建请求（键、数量、标志）
  → 按键查找：键非私有且已存在则走"已存在"分支（存在性检查、权限检查、数量检查）
  → 否则走"新建"分支：数量合法性、找空槽（满则回空间不足）、填身份与模式、
     序号加一、初始化等待队列、可能打开事件订阅
  → 回标识符（下标加序号编码）
2. 使用：取值、设值、操作（05 管前两种，06 管第三种）
3. 删除：用户进程发起删除命令
  → 唤醒全部等待者（每人一封"标识符已删除"回信，06 的完成函数干这事）
  → 清分配位、收缩高水位、可能关闭事件订阅
```

注意第 1 步里面的序号加一：删掉的槽位会被重用，但序号每次加一（只保留低十五位），标识符里带着序号——上次删除前拿到的旧标识符在槽位重用后对不上序号，查找直接拒绝。这是"序号防重用"：**槽位可以重用，身份不能冒充**。实现订阅开关的那两句（第一个集合诞生时打开、最后一个消失时关闭）在 09 篇展开，本篇只认调用点。

### 1.5 小结

表管理由六部分组成：表结构（十个槽位加高水位）、两种查找、创建两分支、删除四幕、十三个控制命令、两类信息组装。记住这六部分，06 篇的操作语义就可以假设表的事情已经办妥，只讲值与等待。

## 2 C 源码分析

### 2.1 表结构逐项核对（`sem.c` 第 39 行到第 46 行）

| 符号 | 位置 | 内容 |
|------|------|------|
| `sem_struct` | 第 39 行到第 43 行 | 描述符（含权限、数量、时间）加信号量数组（最多六十个）加等待队列头 |
| `sem_list` | 第 45 行（十个槽位） | 集合上限十个（`SEMMNI`，`sem.h:164`）；槽位状态看模式里的分配位 |
| `sem_list_nr` | 第 46 行 | 高水位：最高在用槽号加一；查找只扫到这里，删除时收缩 |

单个信号量（`semaphore`，第 16 行到第 21 行）四个字段：值、等零人数、等增长人数、最后操作进程标识。等零与等增长两个计数是给 `ipcs` 命令看的（06 篇维护它们），取值命令直接读（本篇 2.5 节）。

每集合信号量上限六十个（`SEMMSL`，`sem.h:181`，值等于系统总数上限 `SEMMNS` 六十），单次操作上限一百个（`SEMOPM`，`sem.h:184`），信号量最大值 32767（`SEMVMX`，`sem.h:93`）。

### 2.2 两种查找逐项核对（第 53 行到第 87 行）

| 函数 | 位置 | 输入 | 行为 |
|------|------|------|------|
| `sem_find_key` | 第 53 行到第 65 行 | 键（调用者保证非私有） | 只扫到高水位；跳过未分配槽；键相等即命中 |
| `sem_find_id` | 第 72 行到第 87 行 | 标识符 | 取低十六位作下标（越界直接空）；未分配则空；序号对不上则空 |

按键查找不验序号（键是用户给的长期名字），按标识符查找三重验（下标、分配位、序号）。私有键（零）永远走新建分支——调用者在调查找前就分流了（2.3 节）。

### 2.3 创建两分支逐项核对（`do_semget`，第 93 行到第 156 行）

**已存在分支**（第 104 行到第 111 行）：键非私有且按 key 找到集合。注意一个反直觉的细节：权限检查拿创建标志原样比对，而判断函数的收尾要求"想要的位非空"——所以标志里一个权限位都不带（零标志）打开已存在集合会直接吃访问拒绝，哪怕你是所有者。想要打开，至少带一个读位。

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 独占冲突 | 第 105 行到第 106 行 | 新建标志加独占标志同时出现则回已存在 |
| 权限检查 | 第 107 行 | 按创建标志原样做权限判断（04 篇掩码表），不过回访问拒绝 |
| 数量检查 | 第 109 行到第 110 行 | 要的数量超过集合实际数量则回参数错误 |

**新建分支**（第 112 行到第 152 行）：键私有，或键非私有但找不到且带新建标志。

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 缺新建标志 | 第 113 行到第 114 行 | 非私有键又无新建标志则回无此键 |
| 数量合法性 | 第 115 行到第 116 行 | 数量小于等于零或超过六十则回参数错误 |
| 找空槽 | 第 119 行到第 123 行 | 全表无空槽则回空间不足 |
| 填身份 | 第 127 行到第 135 行 | 保留旧序号加一（只留低十五位）；清零；填键、创建者与所有者（调用者身份）、模式（分配位加标志里的低九位）；数量；创建时间（当前时间） |
| 挂等待队列 | 第 139 行 | 初始化空等待队列 |
| 订阅与水位 | 第 141 行到第 151 行 | 若是追加到末尾且表原先为空则打开事件订阅（09）；高水位推进 |

收尾（第 154 行到第 155 行）：回标识符（下标与序号编码），成功。

序号只留低十五位的意思：序号到 32767 后绕回零——绕回后旧标识符可能误中（序号重合），是已知的小概率复用风险，C 接受它（ NetBSD 同款做法），Rust 侧保持同样行为（行为契约，非演进）。

### 2.4 删除四幕逐项核对（`remove_set`，第 251 行到第 281 行）

| 步骤 | C 位置 | 行为 |
|---|------|--------|
| 唤醒等待者 | 第 259 行到第 263 行 | 队列里每个人一封"标识符已删除"回信（06 的排空函数先运行，本函数随后清槽），直到队列空 |
| 清分配位 | 第 266 行 | 模式去掉分配位（槽位即空闲） |
| 收缩水位 | 第 272 行到第 274 行 | 从尾部去掉连续空闲槽，高水位回落 |
| 关闭订阅 | 第 279 行到第 280 行 | 高水位归零（表空）则关闭事件订阅（09） |

删除由控制命令的删除分支触发（2.5 节），不直接对外。注意第一幕调用的是 06 的完成函数——05 与 06 在这里握手：05 负责"决定删"，06 负责"一个个叫醒"。

### 2.5 十三个控制命令逐项核对（`do_semctl`，第 469 行到第 648 行）

先找集合（第 491 行到第 507 行）：信息查询两命令无集合；状态查询按槽下标直接取（越界或未分配回参数错误）；其余按标识符查找（找不到回参数错误）。再查权限（第 516 行到第 538 行）：设值两命令要写位；删除与改属性比所有者身份（否则回操作不许可）；信息查询放行；其余要读位（04 篇掩码表）。

| 命令 | 值 | 行为 |
|------|------|------|
| `IPC_STAT` | 2 | 把描述符拷贝给调用者（内核拷贝） |
| `SEM_STAT` | 18 | 同上（按槽下标找集合），另回标识符 |
| `IPC_SET` | 1 | 从调用者拷回描述符草稿，只收所有者、组、模式低九位，刷新改属性时间 |
| `IPC_RMID` | 0 | 调删除（2.4 节） |
| `IPC_INFO` | 500 | 填概要信息（2.6 节）并拷贝，另回最高在用槽号（空表回零） |
| `SEM_INFO` | 19 | 填明细信息（2.6 节）并拷贝，另回最高在用槽号 |
| `GETVAL` | 5 | 回序号对应信号量的值（序号越界回参数错误） |
| `GETPID` | 4 | 回最后操作进程标识 |
| `GETNCNT` | 3 | 回等增长人数 |
| `GETZCNT` | 7 | 回等零人数 |
| `GETALL` | 6 | 把全部信号量的值拷贝给调用者（经临时缓冲） |
| `SETVAL` | 8 | 设单个值（零到 32767，超限回超范围），刷新时间，唤醒等待者（06 的重试） |
| `SETALL` | 9 | 设全部值（逐个超范围检查，调试宏已排除），刷新时间，唤醒等待者 |

取值四命令（`GETVAL`/`GETPID`/`GETNCNT`/`GETZCNT`）都要先验序号越界；设值两命令设完都调 06 的重试（值变了，被卡住的人可能能走了）；其他命令走默认回参数错误（第 643 行到第 644 行）。调试打印宏（`DEBUG_SEM`）三处已按 plan 排除，不实现。

### 2.6 两类信息组装逐项核对

**概要与明细填充**（`fill_seminfo`，第 430 行到第 463 行）：十个字段，固定值（集合上限十、每集六十、单次一百、最大 32767）与两档差异——概要命令的在用集数与已分配信号量总数填零（撤销支持缺席，plan A-7 契约），明细命令填真实计数（在用集数等于高水位、总数累加各集数量）。

**管理信息库组装**（`get_sem_mib_info`，第 787 行到第 848 行）：先填概要；若调用者只要概要大小则只回概要；否则按集合上限十个逐个输出（在用槽交真实快照：权限拷贝用 04 的搬运函数、数量与时间；空槽交清零项）。`ipcs` 命令指望数组长度恒等于上限（注释第 807 行到第 812 行写明：给小了它会越界读），所以空槽也要占位输出——**数组长度恒定是契约**，03 篇的分发点把查询交到这里。

**空表判断**（`is_sem_nil`，第 854 行到第 858 行）：高水位为零即空（10 篇的退出判定用）。

## 3 Rust 设计决策

| 编号 | 决策 | C 做法 | Rust 做法 | 为什么这样做 |
|---|------|--------|-----------|--------|
| D1 | 槽位状态变类型 | 分配位藏在模式整数里（`mode & SEM_ALLOC` 散写各处） | `SemSlot::{Free, Used(SemSet)}` 枚举（`table.rs`） | 空槽不可表达成"有数据的集合"： occupancy 与数据同体，找空槽、跳空槽、清槽都变成匹配分支；与 Redox 的资源槽位（占用位加数据同体）同款 |
| D2 | 序号绕回显式化 | `(seq + 1) & 0x7fff` 内联（第 135 行） | `next_seq(seq: u16) -> u16` 纯函数（`table.rs`） | 绕回是行为契约（旧标识符小概率误中），值得一个名字加测试；掩码常量 `0x7fff` 具名 |
| D3 | 副作用变返回值 | 订阅开关直接调（第 148 行/第 280 行） | 创建与删除返回 `TableEffect::{SubscribeEvents, UnsubscribeEvents, None}`（`table.rs`） | 表模块不直接调 09 的订阅函数（跨模块调用变返回）；调用者（服务层）执行效应；测试不断言全局状态，只断言返回值 |
| D4 | 唤醒名单变返回值 | 删除时逐个调完成函数发信（第 259 行到第 263 行） | 排空由 06 的 `drain_set` 产出名单（端点加删除码，`waiter.rs`），删除本体只回订阅效应 | 发信是传输效应；名单顺序即唤醒顺序（队列头到尾），测试可断言 |
| D5 | 控制命令变枚举 | 裸整数 `switch`（第 491 行/第 516 行/第 540 行） | `SemctlCommand` 枚举加 `from_raw`（`ctl.rs`） | 未知命令不可表达；三处 `switch`（找集合、查权限、执行）的分支一致性由编译器监督；加命令时三处同改 |
| D6 | 拷贝边界外移 | 处理函数内调内核拷贝（各 `sys_datacopy`） | 控制函数收发已拷贝好的缓冲（`ctl.rs`：调用者给字节，函数给字节） | 拷贝是传输效应；纯逻辑可单测；服务层做搬运（与 02 篇"信里装指针"呼应：指针解引用只发生在边界） |
| D7 | 信息组装纯化 | 组装与拷贝交织（第 824 行到第 845 行） | `assemble_mib_info(&Table) -> (SemInfo, Vec<SemIdView>)` 纯函数（`ctl.rs`） | 数组长度恒定（十个）在类型层面表达（`Vec` 长度断言）；拷贝留给 03 的库调用 |

微内核对照（类比，不是移植依据）：Redox 的方案服务同样用固定槽位表管理打开的文件描述符（占用位、序号防重用、删除时叫醒等待者）——有限表加序号是通用做法。本篇的效应返回值（D3/D4）对应 Redox 把"发通知"排队到调用者执行的习惯：数据模块不直接做跨模块调用。

替代方案及否决：把等待队列与重试逻辑也搬进本篇——否决，因为等待涉及挂起语义（SUSPEND、序号越界、撤销排除），属 06 的语义单元；本篇的删除只产出唤醒名单，叫醒的细节（计数调整、内存释放、不回复抑制）由 06 的完成函数实现，两篇在 `Wakeup` 类型上握手。

## 4 实现详解

### 4.1 模块结构

```
os/servers/ipc-server/src/sem/
  mod.rs          — 模块声明与重导出、错误类型（05 与 06 共用）
  table.rs        — 集合表、槽位、创建两分支、删除四幕（本篇 D1 到 D4 的落地）
  ctl.rs          — 控制命令枚举与执行、信息组装（本篇 D5 到 D7 的落地）
  op.rs           — 原子执行与重试（06 的落地，本篇只引用唤醒类型）
  waiter.rs       — 等待记录与完成（06 的落地，本篇只引用完成语义）
```

### 4.2 关键类型与函数

**表与集合**（`table.rs`）：

- `Semaphore { value: u16, zero_waiters: u16, raise_waiters: u16, last_pid: i32 }`：对应 C 的 `semaphore`。
- `SemSet { key, uid, gid, creator_uid, creator_gid, mode, seq, times..., values }`：对应 C 的 `sem_struct`（权限复用 04 的 `IpcPerm`，等待队列由 06 的结构挂载）。
- `SemSlot::{Free, Used(SemSet)}`：十个槽位的数组 `slots: [SemSlot; 10]` 加 `high_water: usize`。
- `find_key(key) -> Option<usize>` / `find_id(id) -> Option<usize>`：2.2 节的逐行对应（含序号校验）。
- `create(key, count, flag, identity, now) -> Result<(id, TableEffect), SemError>`：2.3 节两分支（含独占冲突、空槽、序号、订阅效应）。
- `remove(index) -> TableEffect`：2.4 节的槽位清空、水位收缩、订阅效应。排空等待队列另有专人（06 的 `drain_set` 在本函数之前运行，一人一封删除回信），本函数只管集合数据之死。

**控制**（`ctl.rs`）：

- `SemctlCommand` 枚举：十三个变体，`from_raw(u32) -> Option`。
- `apply(table, cmd, args, identity) -> Result<CtlReply, SemError>`：2.5 节的找集合、查权限（调 04 决策）、执行三段。
- `fill_info(cmd) -> SemInfo`：2.6 节的概要与明细差异。
- `assemble_mib_info(table) -> (SemInfo, Vec<SemIdView>)`：2.6 节的恒定十项数组。

**错误**（`mod.rs`）：`SemError` 枚举（参数错误、访问拒绝、操作不许可、已存在、无此键、空间不足、超范围、单次太多、序号太大、标识符已删除、中断），`to_errno()` 映射 Minix3 错误码（02 篇 99 收口对照）。

### 4.3 关键不变量

- 高水位语义：恒等于最高在用槽号加一（创建追加、删除收缩，测试双向钉住）。
- 序号单调绕回：只增不减（十五位掩码），测试绕回点。
- 唤醒名单顺序：队列头到尾（与 C 的 `while` 取头一致），测试断言顺序。
- 信息数组恒定十项：空槽占位输出（`ipcs` 契约），测试断言长度。

## 6 过渡

本篇讲完了集合住在哪里、怎么生、怎么做控制、怎么死。但是最难的部分还没讲：一次信号量操作怎么保证"要么全做、要么全不做"，条件不满足时调用者挂在哪里、谁来叫醒（06 回答）。下一篇进入阶段 3 的第二块：原子操作与等待队列。

在启动时序里面的位置：本篇是阶段 3 的表管理，是 06 的前置依赖（06 的重试与完成操作本篇表里的数据）。01 的主循环查表命中创建与控制命令时，进的是本篇的函数。
